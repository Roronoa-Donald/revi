Chapitre 3 — Cycle de vie et ressources des VM

Module 3 ≈ 2 h 30 de travail Réservé B2 et plus
Mise en situation

Une VM se crée, vit et meurt comme un service. Sans cycle de vie clair, elle devient un risque : ressources mal dimensionnées, sauvegardes oubliées, dépendances invisibles. Le cycle de vie est le cadre qui garde le contrôle.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. définir VM, template, clone et snapshot ;
  2. décrire les quatre phases du cycle de vie ;
  3. allouer vCPU, RAM et disque selon la charge ;
  4. distinguer clone complet et clone lié.

1. Concepts essentiels

  • VM : unité d’exécution isolée avec ses ressources.
  • Template : modèle standardisé pour uniformiser les déploiements.
  • Clone : duplication d’un état existant.
  • Snapshot : point de retour temporel.

Ces notions se combinent pour accélérer la création sans perdre le contrôle : on part d’un template, on clone, on prend un snapshot avant modification.

2. Les quatre phases du cycle de vie

  1. Conception : objectifs, charges, criticité.
  2. Provisioning : ressources, stockage, réseau.
  3. Exploitation : supervision, mises à jour, sauvegarde.
  4. Retrait : archivage, nettoyage, traçabilité.

Une VM sans cycle de vie clair devient vite un risque : personne ne sait ce qu’elle fait, ni si on peut l’éteindre.

Tracer pour pouvoir retirer

La phase de retrait est la plus souvent oubliée. Archiver les données utiles, libérer les ressources et consigner la suppression évitent de laisser traîner des VM « zombies » qui consomment sans servir.

3. Allocation de ressources

  • vCPU : partage temporel du CPU physique — allouer plus que nécessaire crée de l’attente.
  • RAM : ressource non élastique, à dimensionner finement.
  • Disque : thin pour la souplesse, thick pour la performance garantie.

Principe : dimensionner selon la charge réelle et la priorité du service, pas selon le « au cas où ».

La surallocation de vCPU

Quand le total de vCPU dépasse les cœurs physiques, les VM attendent leur tour : le CPU Ready Time s’allonge et toutes les performances baissent. La surallocation doit rester maîtrisée et proportionnée aux charges réelles.

4. Réseau, snapshots et clones

Le réseau donne une identité et un périmètre à la VM : le bridge relie virtuel et physique, le VLAN isole logiquement les flux, l’adressage assure lisibilité et gouvernance.

Un snapshot fige l’état d’une VM à un instant T : utile pour revenir en arrière après un changement, il ne remplace pas une sauvegarde externe.

Un clone complet est indépendant mais plus lourd ; un clone lié est rapide mais dépend de sa base (souvent un template). La stratégie template → clone garantit cohérence et rapidité.

Standardiser puis décliner

Un template fige la qualité ; les clones la diffusent sans réinventer. C’est la même logique qu’une recette de cuisine : on maîtrise la base, puis on la duplique.

6. QCM — niveau examen

Que duplique un clone ?

Le clone copie une VM ou un template.

Première phase du cycle de vie ?

On définit les besoins avant de provisionner.

Que fait la phase de provisioning ?

On attribue CPU, RAM, stockage, réseau.

Quelle ressource est non élastique ?

La RAM ne se partage pas dynamiquement.

Disque thin : avantage ?

L’espace est alloué selon l’usage réel.

Un snapshot remplace-t-il une sauvegarde ?

Il vit sur le même stockage et reste temporaire.

Clone lié : faiblesse ?

Si la base disparaît, le clone lié ne fonctionne plus.

Que garantit un template ?

Un modèle standardise les déploiements.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Utiliser un snapshot comme sauvegarde durable.
  • Surallouer les vCPU et dégrader toutes les VM.
  • Allouer la RAM « au cas où », sans dimensionnement fin.
  • Oublier la phase de retrait (VM zombies).
  • Supprimer la base d’un clone lié, qui cesse de fonctionner.

8. Méthodologie de résolution

Cycler une VM proprement
  1. Concevoir : objectifs, charges, criticité.
  2. Provisionner à partir d’un template (cohérence).
  3. Exploiter : superviser, mettre à jour, sauvegarder.
  4. Protéger par snapshots (court terme) et sauvegardes (long terme).
  5. Retirer : archiver, nettoyer, tracer.

9. Révision active

Résumé essentiel
  • VM, template, clone et snapshot se combinent pour créer vite et bien.
  • Cycle de vie : conception, provisioning, exploitation, retrait.
  • vCPU (partage temporel), RAM (non élastique), disque thin/thick.
  • Bridge pour le lien réseau, VLAN pour l’isolation.
  • Snapshot = retour rapide ; backup = résilience.

Checklist de maîtrise

  • Je définis VM, template, clone, snapshot.
  • Je décris les quatre phases du cycle de vie.
  • Je dimensionne vCPU, RAM et disque.
  • Je distingue clone complet et clone lié.
