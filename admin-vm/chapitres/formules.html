Mémo VM

Hyperviseurs, cycle de vie, stockage, réseau, clusters et sauvegarde sur une page. À garder ouvert pendant les exercices et l’atelier.

Virtualisation

  • Type 1 (bare-metal : Proxmox, ESXi) → production ; type 2 (Workstation, VirtualBox) → tests.
  • Types : serveur, poste (VDI), stockage, réseau.
  • Vocabulaire : host, guest, vCPU, snapshot, template, cluster.

Prérequis & architecture

  • Prérequis : extensions CPU (VT-x / AMD-V), RAM, I/O, réseau.
  • Pile KVM : noyau (CPU), QEMU (VM), libvirt (pilotage).
  • Plan de données (exécution) et plan de gestion (gouvernance).
  • Nested : pédagogique et plus lent.

Cycle de vie & ressources

  • Phases : conception, provisioning, exploitation, retrait.
  • vCPU : partage temporel ; RAM : non élastique ; disque thin/thick.
  • Template → clone : standardiser puis décliner.
  • Snapshot (retour rapide) ≠ sauvegarde (résilience).

Stockage

  • LVM : PV (disque), VG (pool), LV (disque de VM).
  • Types : Directory, LVM-thin, ZFS, Ceph.
  • Protocoles : NFS (fichier), iSCSI (disque réseau).
  • Sauvegarde GFS : quotidien 7 j, hebdo 4 sem., mensuel 6 à 12 mois.
  • Règle d’or : 3 copies, 2 supports, 1 hors site.

Réseau

  • Bridge (switch virtuel), NAT (Internet), VLAN (segmentation), pare-feu (filtrage).
  • VLAN 10 utilisateurs, 20 serveurs, 30 DMZ.
  • DMZ : services exposés — jamais la base de données.
  • Diagnostic : connectivité, chemin, filtrage, segmentation.

Administration avancée

  • Réservation (minimum), limite (plafond), shares (priorité).
  • Cluster : quorum (décision), fencing (isolement), failover (redémarrage).
  • Migration dépend du stockage partagé, du réseau et de la charge.
  • Sauvegarde avancée : déduplication, chiffrement, restauration granulaire.
  • Un hyperviseur non patché expose toutes ses VM.

Erreurs fréquentes à éviter

  • Confondre hyperviseur de type 1 et OS hôte.
  • Utiliser la virtualisation imbriquée en production.
  • Prendre un snapshot pour une sauvegarde durable.
  • Surallouer les vCPU et dégrader toutes les VM.
  • Exposer une base de données en DMZ.
  • Négliger le quorum ou le durcissement de l’hôte.
