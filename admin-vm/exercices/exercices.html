Projet intégrateur — « plan de dimensionnement »

Cahier des charges

On te confie un script de dimensionnement. Le script lit la RAM de l’hôte (Go), la RAM réservée au système (Go), la RAM par VM (Go), puis le nombre total de vCPU alloués et le nombre de cœurs physiques. Il affiche la capacité de VM, détecte une surallocation de vCPU, et conclut : plateforme : valide si aucune surallocation, sinon plateforme : a revoir.

Fonctionnalités attendues
  1. Lire les cinq valeurs dans l’ordre indiqué.
  2. Calculer la capacité de VM (mémoire utile / RAM par VM).
  3. Détecter la surallocation (vCPU > cœurs).
  4. Afficher capacite : X puis surallocation : oui/non.
  5. Conclure : plateforme : valide ou plateforme : a revoir.
  6. Gérer les cas limites (mémoire utile nulle).

Contraintes : divisions entières avec [math]::Floor, comparaisons avec -gt.

Grille d’auto-évaluation du projet (sur 100)
< 50 % — Lecture ordonnée des cinq valeurs 20
50–69 % — Capacité de VM correcte 20
70–94 % — Sortie au bon format 20
≥ 95 % — Lisibilité et cohérence 20

Objectif : ≥ 95/100 avant de considérer le projet terminé.

Voir une solution de référence (après avoir essayé !) 
$ramHote = [int][Console]::In.ReadLine()
$ramSysteme = [int][Console]::In.ReadLine()
$ramVm = [int][Console]::In.ReadLine()
$vcpu = [int][Console]::In.ReadLine()
$coeurs = [int][Console]::In.ReadLine()

$utile = $ramHote - $ramSysteme
if ($utile -lt 0) { $utile = 0 }
$capacite = [int]([math]::Floor($utile / $ramVm))
Write-Output ("capacite : " + $capacite)

if ($vcpu -gt $coeurs) {
    Write-Output "surallocation : oui"
    Write-Output "plateforme : a revoir"
} else {
    Write-Output "surallocation : non"
    Write-Output "plateforme : valide"
}
Cette solution combine lecture ordonnée, calcul de capacité, détection de surallocation et verdict — l’essentiel des chapitres 2 et 3 en un seul script.
