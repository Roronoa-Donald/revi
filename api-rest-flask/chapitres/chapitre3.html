Chapitre 3 — Démarrage avec Flask & Routage

Module 3 ≈ 3 h 00 de travail Réservé B2 et plus
Mise en situation

Après avoir modélisé les ressources et les routes théoriques, il est temps de leur donner vie en Python. Flask est un micro-framework minimaliste, rapide et flexible qui permet de déployer une API web en quelques lignes de code sans imposer une structure de projet lourde.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. installer et initialiser une application Flask avec Flask(__name__) ;
  2. déclarer des routes avec le décorateur @app.route et spécifier les verbes acceptés ;
  3. capturer et convertir des paramètres dynamiques d’URL (<int:id>, <string:slug>) ;
  4. exploiter l’objet global contextuel request (query string, headers, corps JSON) ;
  5. exécuter et tester le serveur localement avec le CLI Flask ou en script Python.

1. Introduction à Flask et installation

Créé par Armin Ronacher en 2010, Flask est qualifié de micro-framework car il fournit uniquement le cœur indispensable : le routage HTTP (via Werkzeug) et le moteur de gabarits (Jinja2). Contrairement à des frameworks complets comme Django, Flask ne force aucun ORM ni structure de base de données prédéfinie.

L’installation s’effectue simplement dans un environnement virtuel Python dédié :

python3 -m venv .venv
source .venv/bin/activate
pip install flask
L’application Flask minimale
from flask import Flask

app = Flask(__name__)

@app.route("/")
def accueil():
    return {"message": "Bienvenue sur l'API REST"}

if __name__ == "__main__":
    app.run(debug=True, port=5000)

2. Le système de routage et les convertisseurs de variables

Le routage associe une URL à une fonction Python dite fonction vue (view function) à l’aide du décorateur @app.route('/chemin').

Flask permet d’extraire des portions dynamiques de l’URL en utilisant des balises typées :

ConvertisseurSyntaxeComportement
string (défaut)<nom> ou <string:nom>Accepte n’importe quelle chaîne sans slash.
int<int:id>Accepte uniquement des entiers positifs et convertit la valeur en int Python.
float<float:val>Convertit les nombres décimaux à virgule en float.
path<path:chemin>Accepte une chaîne textuelle pouvant contenir des slashes.
uuid<uuid:identifiant>Valide et convertit un identifiant UUID v4.
Rejet automatique 404 sur type invalide

Si une route attend <int:article_id> et qu’un client appelle /articles/abc, Flask rejette automatiquement la requête avec une erreur 404 Not Found sans même exécuter le corps de votre fonction.

3. Filtrer les méthodes HTTP avec le paramètre methods

Par défaut, une route Flask ne répond qu’aux requêtes GET. Pour autoriser des verbes supplémentaires comme POST, PUT ou DELETE, on renseigne le paramètre methods du décorateur :

@app.route("/articles", methods=["GET", "POST"])
def gerer_articles():
    if request.method == "POST":
        # Création d’un nouvel article
        donnees = request.get_json()
        return {"statut": "cree", "titre": donnees.get("titre")}, 201
    # Sinon, retour de la liste (GET)
    return {"articles": []}, 200

Si un client effectue une requête avec un verbe non listé (par exemple DELETE sur cette route), Flask interrompt l’échange avec le code d’état 405 Method Not Allowed.

4. Inspecter les données avec l’objet request

Flask met à disposition l’objet global contextuel request (importé depuis flask). Cet objet encapsule toutes les informations envoyées par le client pour la requête en cours de traitement :

  • request.method : chaîne contenant la méthode HTTP (ex. "GET", "POST").
  • request.args : dictionnaire immuable (MultiDict) contenant les paramètres de la Query String. Ex. : page = request.args.get("page", 1, type=int).
  • request.headers : dictionnaire insensible à la casse des en-têtes HTTP (ex. request.headers.get("Authorization")).
  • request.get_json() : désérialise le corps de la requête en dictionnaire ou liste Python. Renvoie None si le Content-Type n’est pas application/json.

Exercice 1 — Convertisseurs de route Flask

Python Niveau 1 — Acquisition

Objectif : Déterminer le type de convertisseur Flask adapté à une valeur reçue.

Dans Flask, les variables de routes acceptent des convertisseurs pour typer les paramètres :
- int pour les entiers positifs (ex: 42)
- float pour les nombres décimaux à virgule (ex: 19.99)
- path pour les chaînes contenant au moins un slash / (ex: docs/api/v1)
- string pour toute autre chaîne de caractères standard sans slash.

Lit une valeur textuelle et le nom de variable souhaité (deux lignes en entrée). Affiche la syntaxe de route Flask correspondante sous la forme <type:nom_variable>.

Entrée du programme
42
user_id
Sortie attendue
<int:user_id>

42 est un entier.

Deux indices, rédigés en mots
  1. Vérifie d’abord si la chaîne contient un slash avec "/" in valeur.
  2. Pour tester un entier : valeur.isdigit().
  3. Pour tester un float : essaye de convertir avec float() dans un bloc try/except.

Exercice 2 — Simulateur de dispatch de route

Python Niveau 2 — Application

Objectif : Vérifier la correspondance entre une URL demandée et un modèle de route avec paramètre.

Flask associe chaque requête entrante au pattern de route correspondant. Par exemple, la route /livres/<int:id> doit capturer /livres/15 et extraire id=15.

Le programme reçoit deux lignes :
1. Le modèle de route avec une variable au format <type:nom> (ex: /articles/<int:id>)
2. L’URL demandée (ex: /articles/73)
Si l’URL correspond au modèle et que le type est valide (par exemple int ne contient que des chiffres), affiche Match: <nom>=<valeur>.
Sinon, affiche 404 Not Found.

Entrée du programme
/articles/<int:id>
/articles/73
Sortie attendue
Match: id=73

Correspondance exacte et valeur 73 entière.

Deux indices, rédigés en mots
  1. Découpe le modèle et l’URL en segments avec .split("/").
  2. Compare le nombre de segments : s’ils diffèrent, c’est 404 Not Found.
  3. Repère le segment contenant "<" et ">", extrais le type et le nom, puis valide la valeur reçue.

Exercice 3 — Filtrage de méthodes HTTP Flask

Python Niveau 3 — Raisonnement

Objectif : Simuler le contrôle des méthodes autorisées sur un endpoint Flask (@app.route(..., methods=[...])).

Par défaut, une route Flask n’accepte que la méthode GET. Pour autoriser d’autres verbes, on fournit le paramètre methods=['GET', 'POST']. Si un client sollicite l’endpoint avec une méthode non autorisée, Flask renvoie automatiquement le code d’état 405 Method Not Allowed.

Lit deux lignes sur l’entrée standard :
1. La liste des méthodes autorisées séparées par des virgules (ex: GET,POST)
2. La méthode utilisée par la requête entrante (ex: DELETE)
Si la méthode est autorisée, affiche 200 OK: Traitement <METHODE>.
Sinon, affiche 405 Method Not Allowed: Verbes autorises: <liste triee separee par des virgules>.

Entrée du programme
GET,POST
DELETE
Sortie attendue
405 Method Not Allowed: Verbes autorises: GET,POST

DELETE non autorisé sur cette route.

Deux indices, rédigés en mots
  1. Nettoie et passe toutes les méthodes en majuscules avec [m.strip().upper() for m in autorisees].
  2. Si methode in autorisees, le code est 200.
  3. Sinon, trie la liste des verbes autorisés avec sorted() et joins-les avec ",".

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de spécifier methods=["POST"] et recevoir une erreur 405 Method Not Allowed.
  • Appeler request.get_json() sans vérifier si le retour est None (absence de corps ou Content-Type invalide).
  • Tenter de convertir un paramètre request.args.get() en int sans valeur de repli ni gestion d’exception.
  • Confondre request.args (paramètres d’URL ?page=2) et les variables de route dynamiques (/utilisateurs/<int:id>).
  • Laisser le mode debug=True actif en environnement de production (faille de sécurité critique avec console interactive).

8. Méthodologie de résolution

Déclarer un point d’entrée REST avec Flask
  1. Définir l’URI et la méthode : choisir l’URI canonique et la liste methods=[...].
  2. Déclarer le décorateur : placer @app.route("/...", methods=[...]) au-dessus de la fonction vue.
  3. Typer les variables dynamiques : utiliser les convertisseurs appropriés (<int:id>).
  4. Extraire les données : lire request.args pour les filtres et request.get_json() pour le body.
  5. Renvoyer la réponse : retourner un dictionnaire et le code de statut HTTP adapté.
