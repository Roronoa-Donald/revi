Chapitre 5 — Validation des données & gestion d’erreurs

Module 5 ≈ 3 h 00 de travail Réservé B2 et plus
Mise en situation

Faire aveuglément confiance aux données transmises par le client expose l’API aux injections, aux corruptions de base et aux plantages inattendus. Une API professionnelle valide chaque entrée, intercepte les anomalies via des gestionnaires globaux et dispose d’une suite de tests automatisés.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. valider rigoureusement la présence et le type des données reçues dans le body JSON ;
  2. interrompre proprement une requête avec la fonction abort() de Flask ;
  3. centraliser la gestion des erreurs HTTP avec le décorateur @app.errorhandler ;
  4. protéger l’API contre le Mass Assignment via une liste blanche d’attributs ;
  5. tester et valider les endpoints avec cURL et le client de test natif de Flask (test_client).

1. Validation défensive des données entrantes

Tout corps JSON reçu via request.get_json() doit être rigoureusement audité avant traitement. Trois vérifications successives s’imposent :

  1. Présence du payload : vérifier que le corps n’est pas None ou vide.
  2. Champs obligatoires : s’assurer que les attributs clés (ex. titre, prix) figurent dans le dictionnaire.
  3. Conformité des types et plages : s’assurer qu’un prix est un nombre positif, qu’une chaîne n’est pas vide.
data = request.get_json()
if not data:
    return jsonify({"erreur": "Corps JSON manquant"}), 400

champs_requis = ["titre", "prix"]
manquants = [c for c in champs_requis if c not in data]
if manquants:
    return jsonify({"erreur": f"Champs obligatoires manquants: {', '.join(manquants)}"}), 400
Danger : Le Mass Assignment

Ne jamais insérer directement request.get_json() dans votre base de données sans filtrage. Un attaquant pourrait injecter {"is_admin": true, "solde": 999999}. Définissez toujours une liste blanche (whitelisting) des attributs modifiables par l’utilisateur.

2. Interruption contrôlée avec abort() et erreurs personnalisées

Flask fournit la fonction utilitaire abort(code, description=...) pour interrompre immédiatement le flux d’exécution et déclencher une réponse d’erreur HTTP standardisée :

from flask import abort

@app.route("/articles/<int:id>")
def detail_article(id):
    article = trouver_article(id)
    if article is None:
        abort(404, description=f"Aucun article trouvé avec l'ID {id}")
    return jsonify(article)

Par défaut, abort() renvoie une page d’erreur HTML générique. Dans une API REST, il est indispensable de capturer ces exceptions pour renvoyer exclusivement du JSON.

3. Centralisation avec @app.errorhandler

Le décorateur @app.errorhandler(code_ou_exception) intercepte les erreurs pour l’ensemble de l’application et unifie le format de réponse JSON :

@app.errorhandler(404)
def introuvable(erreur):
    return jsonify({
        "code": 404,
        "error": "Not Found",
        "message": getattr(erreur, "description", "Ressource introuvable")
    }), 404

@app.errorhandler(500)
def erreur_serveur(erreur):
    return jsonify({
        "code": 500,
        "error": "Internal Server Error",
        "message": "Une anomalie imprévue est survenue côté serveur."
    }), 500
Bénéfice de la centralisation

Cette approche évite la duplication de code d’erreur dans chaque route : toute levée de 404 ou 400 dans l’application passera automatiquement par cette fonction uniforme.

4. Tester son API : cURL et test_client natif

Pour valider le bon fonctionnement des endpoints, deux approches complémentaires existent :

1. L’outil en ligne de commande cURL :

# Requête GET
curl -i http://localhost:5000/api/v1/articles

# Requête POST avec en-têtes et JSON
curl -i -X POST http://localhost:5000/api/v1/articles \
     -H "Content-Type: application/json" \
     -d '{"titre": "Guide Flask", "prix": 29.9}'

2. Le client de test automatisé Flask :

def test_creation_article():
    client = app.test_client()
    reponse = client.post("/api/v1/articles", json={"titre": "Test", "prix": 10})
    assert reponse.status_code == 201
    assert reponse.get_json()["titre"] == "Test"

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Validation des champs obligatoires

Python Niveau 1 — Acquisition

Objectif : Vérifier la présence de tous les champs obligatoires dans un payload JSON.

Avant de traiter une création ou une modification, l’API doit s’assurer que les attributs requis sont présents dans le corps JSON.

Lit deux lignes sur l’entrée standard :
1. La liste des champs obligatoires séparés par des virgules (ex: titre,prix,auteur)
2. Le payload JSON brut reçu (ex: {"titre": "Guide", "prix": 25})
Si tous les champs requis sont présents dans l’objet JSON, affiche :
200 OK: Payload valide
Sinon, affiche les champs manquants triés alphabétiquement au format :
400 Bad Request: Champs manquants: <champs séparés par des virgules>.

Entrée du programme
titre,prix,auteur
{"titre": "Guide", "prix": 25}
Sortie attendue
400 Bad Request: Champs manquants: auteur

Le champ auteur est manquant.

Deux indices, rédigés en mots
  1. Identifie les clés manquantes avec [c for c in requis if c not in payload].
  2. Trie la liste des clés manquantes avec sorted() avant de la joindre avec ",".

Exercice 2 — Validation des types JSON

Python Niveau 2 — Application

Objectif : Vérifier la conformité des types de données reçus face à un schéma typé.

Une API robuste ne se contente pas de vérifier la présence des champs : elle contrôle leur type de données (par exemple int, str, bool ou float).

Lit deux lignes sur l’entrée standard :
1. Les spécifications de schéma séparées par des virgules (ex: nom:str,age:int,actif:bool)
2. Le payload JSON reçu (ex: {"nom": "Alice", "age": "vingt", "actif": true})
Vérifie chaque champ spécifié. Si le type correspond exactement (en Python, attention : bool dérive de int, donc vérifier isinstance(val, bool) en premier pour bool, et type(val) is int pour int).
Si un champ a un type erroné, affiche la première erreur rencontrée (selon l’ordre du schéma) :
Erreur type: champ <nom> attendu <type>.
Si tous les types sont valides, affiche : Validation reussie.

Entrée du programme
nom:str,age:int,actif:bool
{"nom": "Alice", "age": "vingt", "actif": true}
Sortie attendue
Erreur type: champ age attendu int

age est une chaîne au lieu d’un entier.

Deux indices, rédigés en mots
  1. Pour str : type(v) is str.
  2. Pour bool : type(v) is bool.
  3. Pour int : type(v) is int (et pas bool).
  4. Pour float : type(v) in (float, int) (ou type(v) is float).

Exercice 3 — Filtrage de propriétés (Whitelisting)

Python Niveau 3 — Raisonnement

Objectif : Supprimer d’un objet JSON toute propriété qui ne figure pas dans la liste blanche autorisée.

La vulnérabilité de Mass Assignment survient lorsqu’une API accepte sans filtrage des champs sensibles soumis par le client (ex: is_admin: true, role: superuser).

Lit deux lignes sur l’entrée standard :
1. La liste blanche des clés autorisées séparées par des virgules (ex: titre,description,prix)
2. Le payload JSON reçu pouvant contenir des clés non autorisées.
Ne conserve dans le résultat que les clés autorisées qui sont présentes dans le payload. Affiche le dictionnaire assaini sérialisé en JSON avec les clés triées (json.dumps(..., sort_keys=True)).

Entrée du programme
titre,prix
{"titre": "Livre Flask", "prix": 29, "is_admin": true, "role": "root"}
Sortie attendue
{"prix": 29, "titre": "Livre Flask"}

Les champs is_admin et role ont été éliminés.

Deux indices, rédigés en mots
  1. Construis un nouveau dictionnaire : {k: payload[k] for k in autorisees if k in payload}.
  2. Utilise json.dumps(..., sort_keys=True) pour l’affichage.

6. QCM — niveau examen

Quel code de statut doit être renvoyé si un champ obligatoire est absent du corps ?

400 Bad Request signale que la charge utile soumise par le client est incomplète ou malformée.

À quoi sert la fonction abort() dans Flask ?

abort() lève une exception HTTPException interrompant instantanément la vue courante.

Quel décorateur intercepte globalement une erreur pour formater sa réponse ?

@app.errorhandler(code) enregistre un gestionnaire d’erreur global pour le code spécifié.

Qu’est-ce que la vulnérabilité de Mass Assignment ?

Le Mass Assignment survient lorsqu’une application persiste sans filtre les données d’un objet JSON.

Quelle option de cURL permet d’afficher les en-têtes HTTP de la réponse ?

L’option -i affiche la ligne de statut et les en-têtes de réponse avant le corps.

Comment instancie-t-on un client de test unitaire dans Flask ?

app.test_client() permet de simuler des requêtes HTTP sans démarrer de serveur réel.

Comment passer un payload JSON avec le test_client de Flask ?

Le paramètre json={...} sérialise automatiquement l’objet et positionne le Content-Type.

Que contient l’attribut description d’une exception levée par abort(404, description="...") ?

description transporte le message explicatif passé lors de l’appel à abort().

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Négliger la validation des types (ex. accepter une chaîne de caractères à la place d’un prix numérique).
  • Conserver les pages d’erreur HTML par défaut au lieu de renvoyer du JSON uniforme.
  • Ne pas filtrer les clés du JSON reçu (vulnérabilité au Mass Assignment).
  • Faire des tests uniquement avec le navigateur (qui n’envoie que des requêtes GET facilement).
  • Oublier le drapeau -H "Content-Type: application/json" lors de tests avec cURL.

8. Méthodologie de résolution

Sécuriser et valider un point d’entrée POST/PUT
  1. Récupérer le payload : extraire les données avec data = request.get_json().
  2. Contrôler la non-vacuité : vérifier que data est un dictionnaire non nul.
  3. Valider les champs requis : vérifier la présence de chaque attribut obligatoire.
  4. Valider les types : s’assurer que chaque valeur respecte son type attendu (int, str, bool).
  5. Filtrer les champs (whitelisting) : ne retenir que les clés explicitement autorisées.

9. Révision active

Résumé essentiel
  • La validation rigoureuse des entrées est le premier rempart de sécurité d’une API REST.
  • La fonction abort() permet d’interrompre proprement le flux d’une requête invalide.
  • @app.errorhandler() centralise la réponse d’erreur JSON pour toute l’application.
  • Le Mass Assignment se neutralise par une liste blanche stricte des attributs autorisés.
  • test_client et cURL permettent d’automatiser et de valider les contrats d’API.

Checklist de maîtrise

  • Je sais vérifier la présence d’un corps JSON et des champs obligatoires.
  • Je maîtrise l’utilisation de la fonction abort() pour les erreurs 400 et 404.
  • Je sais unifier les réponses d’erreur en JSON avec @app.errorhandler.
  • Je sais me prémunir du Mass Assignment par filtrage de propriétés.
  • Je sais tester un point d’entrée avec cURL et app.test_client().
