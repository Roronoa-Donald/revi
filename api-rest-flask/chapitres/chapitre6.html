Chapitre 6 — Mini API complète & persistance

Module 6 ≈ 3 h 15 de travail Réservé B2 et plus
Mise en situation

Passer de fragments de code isolés à une architecture logicielle robuste et maintenable exige de structurer les modules avec soin. Ce dernier chapitre synthétise l’ensemble des notions pour concevoir un CRUD complet, organiser les routes avec les Blueprints et préparer l’application à la production.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. concevoir et assembler un CRUD complet (Create, Read, Update, Delete) conforme REST ;
  2. gérer un modèle de persistance en mémoire ou connecté à une base relationnelle ;
  3. modulariser une application Flask volumineuse à l’aide des Blueprints ;
  4. documenter les contrats d’API selon la spécification OpenAPI / Swagger ;
  5. comprendre les prérequis de mise en production avec un serveur WSGI (Gunicorn).

1. Synthèse d’un CRUD RESTful complet

Un point d’accès CRUD complet met en œuvre l’intégralité des principes abordés :

from flask import Flask, request, jsonify, abort

app = Flask(__name__)

# Base de données en mémoire pour illustration
ETUDIANTS = [
    {"id": 1, "nom": "Amina", "filiere": "Informatique"},
    {"id": 2, "nom": "Lucas", "filiere": "Réseaux"}
]

# 1. READ (Collection) avec filtrage optionnel
@app.route("/etudiants", methods=["GET"])
def lister_etudiants():
    filiere = request.args.get("filiere")
    if filiere:
        resultats = [e for e in ETUDIANTS if e["filiere"].lower() == filiere.lower()]
        return jsonify(resultats), 200
    return jsonify(ETUDIANTS), 200

# 2. READ (Élément)
@app.route("/etudiants/<int:id>", methods=["GET"])
def obtenir_etudiant(id):
    etudiant = next((e for e in ETUDIANTS if e["id"] == id), None)
    if not etudiant:
        abort(404, description="Étudiant introuvable")
    return jsonify(etudiant), 200

# 3. CREATE
@app.route("/etudiants", methods=["POST"])
def creer_etudiant():
    data = request.get_json()
    if not data or "nom" not in data or "filiere" not in data:
        abort(400, description="Les champs nom et filiere sont requis")
    nouvel_id = max((e["id"] for e in ETUDIANTS), default=0) + 1
    etudiant = {"id": nouvel_id, "nom": data["nom"], "filiere": data["filiere"]}
    ETUDIANTS.append(etudiant)
    return jsonify(etudiant), 201

# 4. UPDATE (PATCH)
@app.route("/etudiants/<int:id>", methods=["PATCH"])
def modifier_etudiant(id):
    etudiant = next((e for e in ETUDIANTS if e["id"] == id), None)
    if not etudiant:
        abort(404, description="Étudiant introuvable")
    data = request.get_json() or {}
    for champ in ("nom", "filiere"):
        if champ in data:
            etudiant[champ] = data[champ]
    return jsonify(etudiant), 200

# 5. DELETE
@app.route("/etudiants/<int:id>", methods=["DELETE"])
def supprimer_etudiant(id):
    global ETUDIANTS
    etudiant = next((e for e in ETUDIANTS if e["id"] == id), None)
    if not etudiant:
        abort(404, description="Étudiant introuvable")
    ETUDIANTS = [e for e in ETUDIANTS if e["id"] != id]
    return "", 204

2. Modulariser avec les Blueprints Flask

Lorsque le projet prend de l’ampleur, regrouper toutes les routes dans un fichier app.py unique devient ingérable. Flask propose le patron architectural des Blueprints pour découper l’application en modules fonctionnels indépendants :

# routes/etudiants.py
from flask import Blueprint, jsonify

etudiants_bp = Blueprint("etudiants", __name__, url_prefix="/api/v1/etudiants")

@etudiants_bp.route("/", methods=["GET"])
def lister():
    return jsonify([])

# app.py
from flask import Flask
from routes.etudiants import etudiants_bp

app = Flask(__name__)
app.register_blueprint(etudiants_bp)
Avantages du préfixe d’URL

Le paramètre url_prefix="/api/v1/etudiants" factorise l’arborescence : toutes les routes du Blueprint bénéficient automatiquement de ce préfixe sans répétition.

3. Persistance avec SQLAlchemy

Pour dépasser le stockage volatil en mémoire, on utilise généralement l’extension Flask-SQLAlchemy qui fait le pont entre Python et une base SQL (PostgreSQL, SQLite, MySQL) :

from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy(app)

class Etudiant(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    nom = db.Column(db.String(100), nullable=False)
    filiere = db.Column(db.String(50), nullable=False)

    def to_dict(self):
        return {"id": self.id, "nom": self.nom, "filiere": self.filiere}

L’écriture d’une méthode to_dict() ou l’usage de bibliothèques comme Marshmallow garantit une sérialisation JSON propre et contrôlée.

4. Documentation OpenAPI et Déploiement en production

Pour qu’une API soit facilement exploitable par des tiers, documenter ses endpoints est indispensable. Le standard OpenAPI (anciennement Swagger) permet de générer une interface interactive où les consommateurs peuvent tester les appels en direct.

En production, le serveur de développement intégré de Flask (app.run()) ne doit jamais être utilisé : il n’est ni sécurisé ni dimensionné pour la concurrence. On déploie l’application derrière un serveur WSGI robuste tel que Gunicorn ou uWSGI, orchestré par un reverse proxy comme Nginx :

gunicorn -w 4 -b 0.0.0.0:8000 "app:app"
Règle de sécurité absolue

Ne jamais lancer app.run(debug=True) sur un serveur public accessible : le debugger interactif de Werkzeug permet l’exécution arbitraire de code Python sur la machine hôte !

Exercice 1 — Filtrage de collection en mémoire

Python Niveau 1 — Acquisition

Objectif : Filtrer une liste d’objets JSON selon un critère d’égalité (clé=valeur).

Une requête GET /ressources?critere=valeur extrait uniquement les éléments correspondants.

Lit deux lignes sur l’entrée standard :
1. La collection JSON initiale (tableau d’objets, ex: [{"id": 1, "role": "admin"}, ...])
2. Le critère au format cle=valeur (ex: role=admin)
Filtre les objets dont l’attribut correspond à la valeur (convertis en chaîne pour la comparaison).
Affiche d’abord : Trouves: <nombre>.
Puis affiche le tableau JSON des éléments filtrés avec json.dumps(..., sort_keys=True).

Entrée du programme
[{"id": 1, "nom": "Alice", "role": "admin"}, {"id": 2, "nom": "Bob", "role": "user"}]
role=admin
Sortie attendue
Trouves: 1
[{"id": 1, "nom": "Alice", "role": "admin"}]

Seule Alice possède le rôle admin.

Deux indices, rédigés en mots
  1. Sépare le critère avec cle, val = critere.split("=", 1).
  2. Compare str(elem.get(cle)) == val.
  3. Affiche len(resultats) puis le JSON.

Exercice 2 — Création avec ID auto-incrémenté

Python Niveau 2 — Application

Objectif : Insérer un nouvel objet dans un store mémoire en lui attribuant un identifiant unique (max + 1).

Lors d’une requête POST, le serveur génère l’identifiant unique de la ressource créée avant de la stocker et de renvoyer le code 201 Created avec l’objet complet.

Lit deux lignes sur l’entrée standard :
1. La collection actuelle (tableau JSON d’objets ayant chacun un champ entier "id", peut être vide [])
2. Le nouvel objet reçu sans champ "id" (ex: {"nom": "Bob", "ville": "Nantes"})
Calcule le nouvel ID : s’il n’y a aucun élément, l’ID vaut 1 ; sinon, il vaut max(id) + 1.
Attribue cet id au nouvel objet et affiche :
201 Created: <objet_json_avec_id_trie>.

Entrée du programme
[{"id": 10, "nom": "Alice"}]
{"nom": "Bob"}
Sortie attendue
201 Created: {"id": 11, "nom": "Bob"}

Le nouvel id généré est 11.

Deux indices, rédigés en mots
  1. Si collection est vide, nouvel_id = 1.
  2. Sinon, nouvel_id = max(item["id"] for item in collection) + 1.
  3. Ajoute item["id"] = nouvel_id et affiche avec json.dumps(..., sort_keys=True).

Exercice 3 — Gestion des mutations (UPDATE & DELETE)

Python Niveau 3 — Raisonnement

Objectif : Traiter une modification partielle (PATCH) ou une suppression (DELETE) sur un store mémoire.

Dans un store mémoire, une opération DELETE retire l’élément et répond 204 No Content. Une opération UPDATE fusionne les nouveaux attributs et répond 200 OK. Si l’identifiant n’existe pas, le serveur répond 404 Not Found.

Lit deux lignes sur l’entrée standard :
1. La collection actuelle (tableau JSON d’objets avec un entier "id")
2. La commande à exécuter :
- soit DELETE <id> (ex: DELETE 42)
- soit UPDATE <id> <json_modifs> (ex: UPDATE 42 {"prix": 35})
Affiche :
- Si l’ID est introuvable : 404 Not Found: Ressource <id> inexistante
- Si DELETE réussi : 204 No Content: Ressource <id> supprimee
- Si UPDATE réussi : 200 OK: <objet_mis_a_jour_trie>.

Entrée du programme
[{"id": 42, "nom": "Alice", "score": 10}]
DELETE 42
Sortie attendue
204 No Content: Ressource 42 supprimee

Suppression réussie.

Deux indices, rédigés en mots
  1. Trouve l’index ou l’élément avec item["id"] == cible_id.
  2. Pour UPDATE, charge le fragment JSON avec json.loads() et mets à jour avec item.update(modifs).
  3. Assure-toi que l’id cible est converti en entier int(cible_id).

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Regrouper des dizaines d’endpoints hétérogènes dans un unique fichier monolithique.
  • Exécuter app.run() en production au lieu d’utiliser un gestionnaire de processus WSGI (Gunicorn).
  • Oublier de documenter les contrats de requêtes et de réponses avec OpenAPI.
  • Ne pas gérer les suppressions d’enregistrements dépendants (problème d’intégrité référentielle).
  • Renvoyer des modèles de base de données bruts sans les sérialiser en dictionnaire ou DTO propre.

8. Méthodologie de résolution

Structurer une API Flask prête pour la production
  1. Découper par domaine : créer un Blueprint par ressource principale (ex. auth, articles, utilisateurs).
  2. Implémenter le cycle CRUD : mapper rigoureusement GET, POST, PUT/PATCH et DELETE.
  3. Isoler la couche de données : définir des modèles clairs avec méthodes to_dict() pour la sérialisation.
  4. Documenter les contrats : décrire chaque schéma et code retour dans la spécification OpenAPI.
  5. Configurer le serveur WSGI : tester le démarrage avec Gunicorn en environnement de pré-production.

9. Révision active

Résumé essentiel
  • Un CRUD complet applique l’ensemble des standards REST (verbes, codes de statut, formats JSON).

  • En production, l’application doit être servie par un serveur WSGI dédié comme Gunicorn.
