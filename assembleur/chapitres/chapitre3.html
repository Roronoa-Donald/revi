Chapitre 3 — Mémoires, Bus & Architectures (Von Neumann vs Harvard, AVR / x86)

Module 3 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Un électronicien conçoit un système embarqué communicant avec un serveur PC. Sur le microcontrôleur AVR (ATmega328P), le programme est figé en mémoire Flash tandis que les variables volatiles résident en SRAM, avec des bus d’adresses totalement séparés (architecture Harvard). Sur le PC x86 hôte, code et données se partagent la même mémoire vive (Von Neumann). Lorsque le serveur transmet l’entier 32 bits 0x12345678 par le port série, pourquoi les octets arrivent-ils inversés si les deux machines n’appliquent pas les mêmes conventions d’endianness ? Ce module détaille l’organisation physique de la mémoire et les interactions avec les bus matériels.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. distinguer avec rigueur l’architecture de Von Neumann (bus partagé) de l’architecture Harvard (bus code/données séparés) ;
  2. comprendre les caractéristiques et les rôles des mémoires Flash (programme), SRAM (variables, pile) et EEPROM (persistance non volatile) ;
  3. configurer sans erreur les registres de ports numériques GPIO sur microcontrôleur : DDRx, PORTx et PINx ;
  4. ordonner et reconstruire les mots multi-octets selon les formats Little-Endian et Big-Endian ;
  5. calculer les adresses physiques réelles en mode segmenté x86 (formule Segment × 16 + Offset).

1. Von Neumann vs Harvard & le goulot d’étranglement mémoire

L’organisation des flux de données et d’instructions divise le monde des processeurs en deux grandes écoles d’architecture :

CritèreArchitecture de Von Neumann (PC, Serveurs, x86)Architecture Harvard (AVR, Microcontrôleurs, DSP)
Organisation mémoireEspace d’adressage unifié : le code et les données se partagent la même RAM.Espaces d’adressage strictement séparés : une mémoire Flash pour le code, une SRAM pour les données.
Bus physiquesUn seul bus d’adresses et un seul bus de données partagés.Deux jeux de bus indépendants (bus instruction et bus données).
PerformancesSujette au goulot d’étranglement de Von Neumann (on ne peut pas lire une donnée et une instruction simultanément).Accès simultané en un seul cycle d’horloge à l’instruction suivante et à une variable en SRAM.
Sécurité matérielleVulnérable aux attaques par injection de code (le processeur peut exécuter des octets situés dans la pile ou le tas).Immunité matérielle naturelle contre l’exécution de données (le processeur ne peut pas exécuter la SRAM).

2. Les trois mémoires du microcontrôleur AVR (ATmega328P)

Un microcontrôleur intègre sur une seule puce de silicium le processeur, les horloges, les périphériques et trois technologies de mémoire distinctes :

Cartographie des mémoires de l’ATmega328P (Arduino Uno)
  • Mémoire Flash (32 Ko) : mémoire non volatile où réside le code compilé du programme. Elle est programmée via le bootloader ou un programmateur ISP et ne peut pas être modifiée à la volée comme de la RAM classique.
  • SRAM (Static RAM, 2 Ko) : mémoire volatile ultra-rapide hébergeant les 32 registres généraux ($R0..R31$), les registres d’E/S, les variables globales, le tas (heap) et la pile d’exécution (stack). Tout s’efface lors d’une coupure d’alimentation.
  • EEPROM (1 Ko) : mémoire non volatile modifiable octet par octet. Idéale pour stocker des paramètres de configuration persistants (identifiants réseau, compteurs d’allumage, seuils de calibration).

3. Contrôle des broches matérielles GPIO (DDR, PORT, PIN)

Pour interagir avec le monde extérieur (allumer une LED, lire un capteur, commander un relais), le microcontrôleur dispose de ports d’entrées/sorties généralistes (GPIO). Chaque port (ex. Port B) est piloté par 3 registres 8 bits :

// Les 3 registres de pilotage du Port B (broches PB0 à PB7) :

1. DDRB (Data Direction Register B) :
   - Bit = 1 → la broche correspondante est configurée en SORTIE (Output)
   - Bit = 0 → la broche correspondante est configurée en ENTRÉE (Input)

2. PORTB (Data Register B) :
   - Si la broche est en SORTIE : 1 = état HAUT (5V), 0 = état BAS (0V)
   - Si la broche est en ENTRÉE : 1 = active la résistance de rappel (Pull-up interne), 0 = haute impédance

3. PINB (Input Pins Address B) :
   - Registre en lecture seule reflétant le niveau logique physique présent sur la broche (0 ou 1)
   - Astuce AVR : écrire un 1 dans PINB bascule (toggle) l’état de la broche de sortie !

4. Little-Endian vs Big-Endian & Mode Segmenté x86

Lorsqu’une donnée s’étend sur plusieurs octets (ex. entier 32 bits 0x12345678), l’architecture choisit dans quel ordre placer les octets en mémoire :

FormatAdresse $A$Adresse $A+1$Adresse $A+2$Adresse $A+3$Architectures typiques
Little-Endian (octet faible d’abord)0x780x560x340x12x86, x86_64, ARM (par défaut), AVR
Big-Endian (octet fort d’abord)0x120x340x560x78Mainframes IBM, SPARC, Protocoles réseau IP
Le calcul d’adresse en mode réel x86 (Segment:Offset)

Le processeur Intel 8086 ne disposait que de registres 16 bits mais d’un bus d’adresses 20 bits ($2^{20} = 1\text{ Mo}$). Il combine deux registres selon la formule universelle :

Adresse_Physique = (Segment × 16) + Offset = (Segment << 4) + Offset

Exemple : pour le segment 0x07C0 et l’offset 0x0000, l’adresse physique vaut :
$0\text{x07C0} \times 16 + 0 = 0\text{x07C00}$ (l’adresse standard de démarrage du MBR).

Exercice 1 — Configuration des broches GPIO AVR (DDRB & PORTB)

Python Niveau 1 — Acquisition

Objectif : Déterminer l’état électrique d’une broche de microcontrôleur AVR selon les registres DDR et PORT.

Sur un microcontrôleur d’architecture Harvard tel que l’ATmega328P (Arduino), la configuration d’une broche d’E/S dépend de deux registres 8 bits :

  • DDRx (Data Direction Register) : bit à 1 = broche en SORTIE, bit à 0 = broche en ENTRÉE ;
  • Si la broche est en SORTIE : bit PORTx à 1 = SORTIE_HAUT, bit PORTx à 0 = SORTIE_BAS ;
  • Si la broche est en ENTRÉE : bit PORTx à 1 = ENTREE_PULLUP (résistance de rappel interne active), bit PORTx à 0 = ENTREE_FLOTTANTE (haute impédance).

Lit sur l’entrée standard DDRB_HEX;PORTB_HEX;BROCHE (broche de 0 à 7). Affiche :
BROCHE=X MODE=<SORTIE_HAUT|SORTIE_BAS|ENTREE_PULLUP|ENTREE_FLOTTANTE>.

Entrée du programme
0xFF;0x20;5
Sortie attendue
BROCHE=5 MODE=SORTIE_HAUT

DDRB=0xFF (toutes broches en sortie). Sur broche 5, 0x20 a le bit 5 à 1 -> SORTIE_HAUT.

Deux indices, rédigés en mots
  1. Isole le bit de la broche k avec : bit_ddr = (ddr >> k) & 1, bit_port = (port >> k) & 1.
  2. Si bit_ddr == 1 : SORTIE_HAUT si bit_port == 1 sinon SORTIE_BAS.
  3. Si bit_ddr == 0 : ENTREE_PULLUP si bit_port == 1 sinon ENTREE_FLOTTANTE.

Exercice 2 — Gestion de l’Endianness (Little-Endian vs Big-Endian)

Python Niveau 1 — Acquisition

Objectif : Comprendre l’ordonnancement des octets en mémoire vive selon l’architecture matérielle.

L’architecture x86 utilise l’ordre Little-Endian (l’octet de poids faible est placé à l’adresse la plus basse en mémoire), tandis que les protocoles réseau et certains processeurs RISC utilisent le Big-Endian.

Lit sur l’entrée standard une valeur 32 bits et le format demandé : VAL_HEX32;FORMAT où :

  • VAL_HEX32 est une valeur 32 bits (ex. 0x12345678) ;
  • FORMAT est LITTLE ou BIG.

Affiche la séquence des 4 octets en mémoire au format :
FORMAT=<LITTLE|BIG> OCTETS=<XX XX XX XX>.

Entrée du programme
0x12345678;LITTLE
Sortie attendue
FORMAT=LITTLE OCTETS=78 56 34 12

En Little-Endian, l’octet de poids faible 0x78 est stocké en premier.

Deux indices, rédigés en mots
  1. Un entier 32 bits 0x12345678 contient les octets b0=0x78 (faible), b1=0x56, b2=0x34, b3=0x12 (fort).
  2. En LITTLE-ENDIAN : b0, b1, b2, b3 (78 56 34 12).
  3. En BIG-ENDIAN : b3, b2, b1, b0 (12 34 56 78).

Exercice 3 — Calcul d’adresse physique en mode réel x86 (Segment:Offset)

Python Niveau 2 — Application

Objectif : Calculer l’adresse physique 20 bits à partir d’une paire Segment:Offset en mode réel x86.

En mode réel (processeur 8086 et phase d’amorçage du BIOS PC), le processeur accède à 1 Mo de mémoire sur un bus 20 bits en combinant deux registres 16 bits :

Adresse_Physique = (Segment << 4) + Offset

Lit sur l’entrée standard SEGMENT;OFFSET (en hexadécimal 16 bits, ex. 0x07C0;0x0000). Affiche l’adresse physique 20 bits en hexadécimal et en décimal au format :
PHY=0xXXXXX DEC=<valeur> (où XXXXX est formaté sur 5 chiffres hexadécimaux majuscules).

Entrée du programme
0x07C0;0x0000
Sortie attendue
PHY=0x07C00 DEC=31744

0x07C0 * 16 + 0x0000 = 0x07C00 (adresse standard de chargement du secteur d’amorce MBR).

Deux indices, rédigés en mots
  1. Multiplie le segment par 16 (équivalent à segment << 4), puis ajoute l’offset.
  2. Formate avec f"PHY=0x{phy:05X} DEC={phy}".

6. QCM — niveau examen

Quelle est la caractéristique fondamentale de l’architecture Harvard par rapport à celle de Von Neumann ?

Harvard sépare physiquement le code et les données, permettant un chargement simultané sans goulot d’étranglement.

Dans un microcontrôleur ATmega328P, où le code exécutable du programme est-il stocké de façon permanente ?

La mémoire Flash est non volatile et conserve le firmware même hors tension.

Sur microcontrôleur AVR, comment configure-t-on la broche PB5 en SORTIE ?

DDR (Data Direction Register) : 1 = Sortie, 0 = Entrée.

Dans une architecture Little-Endian (comme x86), où l’octet de poids faible (LSB) est-il stocké ?

Little-Endian (« petit bout d’abord ») stocke l’octet le moins significatif à la première adresse mémoire.

Soit la valeur 32 bits 0x12345678 stockée à l’adresse 0x1000 en Little-Endian. Quel octet se trouve à l’adresse 0x1000 ?

L’octet de poids faible est 0x78 : en Little-Endian, il est situé à l’adresse de base 0x1000.

En mode réel x86, quelle est l’adresse physique 20 bits correspondant à Segment = 0x1000 et Offset = 0x0250 ?

Adresse = (Segment << 4) + Offset = 0x10000 + 0x0250 = 0x10250.

À quoi sert le registre PINx sur microcontrôleur AVR ?

PIN (Port Input Pins) est le registre en lecture seule qui reflète la tension réelle appliquée sur les broches.

Quelle est la taille maximale de l’espace mémoire adressable directement par un bus d’adresses 20 bits ?

2^20 octets = 1 048 576 octets = exactement 1 Mo.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre le registre DDR (direction : entrée ou sortie) et le registre PORT (valeur : haut ou bas).
  • Inverser l’ordre des octets lors de la lecture d’une trame réseau (Big-Endian) sur une machine x86 (Little-Endian).
  • Croire que la SRAM conserve ses données après une coupure d’alimentation : seule l’EEPROM ou la Flash est non volatile.
  • Oublier de décaler le segment de 4 bits vers la gauche (multiplier par 16) dans la formule de calcul en mode réel 8086.
  • Tenter d’écrire dynamiquement dans la mémoire Flash comme si c’était de la RAM pendant l’exécution normale du code.

8. Méthodologie de résolution

Protocole en 4 étapes pour cartographier un accès mémoire bas niveau
  1. Identifier l’architecture du processeur : Von Neumann (espace unique) ou Harvard (code et données séparés).
  2. Déterminer le type de mémoire cible : Flash (statique/lecture), SRAM (volatile/lecture-écriture) ou EEPROM.
  3. Vérifier la convention d’Endianness du système : Little-Endian pour x86/AVR, Big-Endian pour le réseau et certains RISC.
  4. Calculer l’adresse effective : appliquer le décalage de segment (mode réel) ou l’offset de structure avant d’émettre la requête sur le bus.

9. Révision active

Résumé essentiel
  • Von Neumann partage le bus code et données ; Harvard sépare physiquement la Flash (programme) et la SRAM (données).
  • L’ATmega328P dispose de 32 Ko de Flash, 2 Ko de SRAM volatile et 1 Ko d’EEPROM non volatile.
  • Les broches GPIO sont pilotées par DDR (direction 1=sortie, 0=entrée), PORT (état haut/bas/pull-up) et PIN (lecture physique).
  • Little-Endian stocke l’octet de poids faible à l’adresse basse ; Big-Endian stocke l’octet de poids fort en premier.
  • En mode réel x86 20 bits : $\text{Adresse Physique} = (\text{Segment} \times 16) + \text{Offset}$.
