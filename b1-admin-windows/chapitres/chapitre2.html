Chapitre 2 — Windows Server 2012 R2 : éditions et installation

Module 2 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le stage commence : on te confie une machine nue et une image de Windows Server 2012 R2. Avant de cliquer sur « suivant », il faut savoir ce qu’on installe : quelle édition correspond à quel besoin, quelle option d’installation (avec ou sans interface graphique), et si la machine tient la configuration requise. Ce chapitre suit le support pas à pas, jusqu’à la première ouverture de session.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. situer Windows Server dans l’histoire des systèmes Microsoft ;
  2. choisir l’édition adaptée : Foundation, Essential, Standard, Datacenter ;
  3. distinguer l’installation Core de l’installation complète (GUI) ;
  4. vérifier la configuration requise et réussir la première ouverture de session.

1. Un peu de contexte : de Windows 1.0 à Windows Server 2022

Windows Server est le système d’exploitation serveur de Microsoft — en quelque sorte une version améliorée du Windows « utilisateur », orientée services : fournir des services à de nombreux autres équipements, pas seulement à l’utilisateur qui est devant l’écran.

Repères du support : en 1985, Windows 1.0 introduit le système de fenêtres pour simplifier un ordinateur alors piloté par un shell en ligne de commande (chez Microsoft, le DOS). Dans les années 1990, pour concurrencer les systèmes serveurs de l’époque, Microsoft conçoit un système orienté services : la lignée NT. La popularité de Windows NT en entreprise pousse Microsoft à continuer : en 2003 arrive la première version de Windows Server, massivement adoptée. Se suivent ensuite 2008, 2012, 2016, 2019 et 2022.

Retenir la chronologie

1985 Windows 1.0 (fenêtres), années 90 lignée NT (orientée services), 2003 premier Windows Server, puis 2008 → 2012 → 2016 → 2019 → 2022. Les TP du module se font sur 2012 R2.

2. Les quatre éditions de Windows Server 2012

Un même produit, quatre éditions aux cibles différentes :

ÉditionLimites
FoundationTPE ; 15 utilisateurs max ; pas de virtualisation ; 1 processeur ; machine physique
Essential25 utilisateurs max ; pas de virtualisation ; 2 processeurs ; physique ou virtuelle
Standardtoutes les fonctionnalités ; licence couvrant 2 machines virtuelles ; jusqu’à 64 sockets et 4 To de RAM
Datacenterusage intensif de machines virtuelles ; VM illimitées par licence (2 processeurs)

Standard et Datacenter offrent les mêmes fonctionnalités : ils se distinguent par le nombre de machines virtuelles couvertes par la licence — deux pour Standard, illimité pour Datacenter.

Piège — Standard contre Datacenter

Les deux éditions supportent 64 sockets et 4 To de RAM. La seule question à se poser : combien de VM la licence doit-elle couvrir ? Deux → Standard ; illimité → Datacenter.

3. Options d’installation : Core ou interface graphique ?

Lors de l’installation, deux options :

  • Installation minimale (Server Core) : sans interface graphique ; moins d’espace disque, surface exposée aux attaques réduite, tâches de maintenance considérablement réduites ;
  • Serveur avec interface graphique (équivalent de l’installation complète de 2008 R2) : confort de la console graphique, pour l’apprentissage et l’administration assistée.

Depuis Windows Server 2012, les options sont intégrées : un administrateur peut installer ou désinstaller ces fonctionnalités pour basculer entre Core et complet — dans un sens avec PowerShell, dans l’autre avec l’outil DISM.EXE (gestion et maintenance des images de déploiement) après avoir repéré le numéro d’index de l’image dans install.wim.

Quand choisir Core ?

Core est le choix de la production : moins de composants installés = moins de correctifs à appliquer = moins de portes d’entrée pour un attaquant. L’interface graphique se justifie en formation et pour certains rôles d’administration.

4. Configuration requise et ouverture de session

La configuration requise de Windows Server 2012 R2 :

ComposantMinimum
Processeur3,1 GHz 64 bits recommandé
Mémoire vive2 Go (8 Go recommandés)
Espace disque60 Go
Carte réseauGigabit Ethernet (10/100/1000base-T)

Pour la première connexion, la syntaxe de session dépend du contexte :

  • base SAM locale (Security Account Manager, la base de données des comptes locaux, composant du registre qui contient les mots de passe locaux) : taper nom_machine\utilisateur ;
  • machine membre d’un domaine : Nom_NETBIOS\login ou login@nom_dns_domaine.
Retenir deux écritures

Deux formes pour le domaine : l’une avec antislash (NETBIOS\login), l’autre avec arobase (login@domaine). La forme locale ne s’applique qu’à la SAM de la machine.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Les quatre éditions de Windows Server 2012

Bash Niveau 1 — Acquisition

Objectif : Associer chaque édition à sa limite : utilisateurs ou machines virtuelles.

Le script lit n lignes « edition limite » : limite est un code parmi u15, u25, vm2 ou vmillimite. Éditions du support : Foundation (15 utilisateurs, pas de virtualisation) → u15 ; Essential (25 utilisateurs) → u25 ; Standard (2 machines virtuelles couvertes) → vm2 ; Datacenter (machines virtuelles illimitées) → vmillimite. Pour chaque ligne il affiche edition : OK ou edition : ERREUR, puis correctes : X/n.

Entrée du programme
3
foundation u15
essential u25
datacenter vmillimite
Sortie attendue
foundation : OK
essential : OK
datacenter : OK
correctes : 3/3
Deux indices, rédigés en mots
  1. Un case sur l’édition : foundation → u15, essential → u25, standard → vm2, datacenter → vmillimite.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Configuration requise : installable ou pas ?

Bash Niveau 2 — Application

Objectif : Vérifier la configuration requise de Windows Server 2012 R2 machine par machine.

Configuration requise du support : 2 Go de RAM minimum (8 recommandés), 60 Go d’espace disque. Le script lit n lignes « poste ram disque » (ram et disque en Go). Pour chaque poste il affiche poste : installable si les deux minimums sont atteints, sinon poste : a renforcer (motif) avec motif = ram, disque ou les-deux (dans cet ordre de priorité), puis installables : X/n.

Entrée du programme
3
A 8 60
B 1 100
C 4 30
Sortie attendue
A : installable
B : a renforcer (ram)
C : a renforcer (disque)
installables : 1/3
Deux indices, rédigés en mots
  1. Test ram d’abord : ram -lt 2 → a renforcer (ram) ou (les-deux) selon le disque.
  2. Puis disque : disque -lt 60 → a renforcer (disque) ; sinon installable, compteur incrémenté.

Exercice 3 — SAM et ouverture de session

Bash Niveau 3 — Raisonnement

Objectif : Former la bonne syntaxe de session selon le contexte du support.

Le script lit n lignes « contexte identite machine » où machine est le nom utilisé dans la syntaxe. Contextes du support : session locale (base SAM locale) → machine\utilisateur ; session domaine-netbios → NETBIOS\identite ; session domaine-upn → identite@machine. Pour chaque ligne il affiche la syntaxe formée contexte : syntaxe, puis sessions : n.

Entrée du programme
3
locale admin SRV2012
domaine-netbios admin CDP
domaine-upn admin cdp.org
Sortie attendue
locale : SRV2012\admin
domaine-netbios : CDP\admin
domaine-upn : admin@cdp.org
sessions : 3
Deux indices, rédigés en mots
  1. Locale et domaine-netbios utilisent l’antislash : machine\utilisateur, machine\identite.
  2. Domaine-upn utilise l’arobase : identite@machine (forme adresse e-mail).

6. QCM — niveau examen

La première version de Windows Server sort en…

Windows Server 2003, massivement adopté en entreprise.

Foundation : TPE, 15 utilisateurs, pas de virtualisation, 1 processeur, machine physique.

L’édition qui couvre 2 VM par licence est…

Standard couvre 2 machines virtuelles ; Datacenter les couvre sans limite.

L’installation Core présente l’avantage…

Moins d’espace disque, surface d’attaque réduite, maintenance allégée.

Security Account Manager : composant du registre contenant les comptes et mots de passe locaux.

Pour se connecter au domaine, on tape…

Deux formes domaine : antislash avec le nom NETBIOS, ou arobase avec le nom DNS.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Choisir Standard ou Datacenter sans se poser la question du nombre de VM couvertes par la licence.
  • Confondre Essential et Foundation : 25 utilisateurs et 2 processeurs contre 15 utilisateurs et 1 processeur.
  • Oublier que Foundation impose une machine physique et refuse la virtualisation.
  • Se connecter au domaine avec la forme machine\utilisateur : c’est la forme locale (SAM).

8. Méthodologie de résolution

Bien installer 2012 R2
  1. Dimensionner : combien d’utilisateurs ? combien de VM prévues ? → l’édition se déduit.
  2. Décider Core ou GUI : production sécurisée contre confort d’administration.
  3. Vérifier la configuration requise avant l’installation, pas après un échec.

9. Révision active

Résumé essentiel
  • De Windows 1.0 (1985) à la lignée NT puis Windows Server 2003 : un système devenu orienté services.
  • Quatre éditions en 2012 : Foundation (15 u), Essential (25 u), Standard (2 VM), Datacenter (VM illimitées).
  • Core réduit la surface d’attaque et la maintenance ; le basculement Core et interface graphique reste possible.
  • La SAM gère les comptes locaux ; le domaine s’écrit NETBIOS\login ou login@domaine.

Checklist de maîtrise

  • Je place Windows 1.0, NT, 2003 et 2012 R2 sur la frise.
  • Je fais le lien édition → limite d’utilisateurs ou de VM sans tableau.
  • Je sais argumenter le choix Core contre interface graphique.
  • Je formule les trois syntaxes de session (locale, NETBIOS, UPN).

10. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — relis le tableau des éditions, c’est le cœur des questions d’examen.
50–69 % — rejoue l’exercice des limites par édition.
70–89 % — solide : entraîne-toi à justifier un choix d’édition à l’oral.
≥ 95 % — maîtrise : passe à la configuration initiale.
