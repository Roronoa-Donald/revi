Chapitre 3 — Configuration initiale du serveur

Module 3 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Le serveur vient d’être installé : il n’a pas encore de nom sérieux, pas d’adresse IP fixe, son pare-feu bloque tout et il n’est pas activé. Un serveur mal configuré à la naissance provoque des pannes incompréhensibles des semaines plus tard. Ce chapitre déroule la liste des réglages de première main, graphiquement et en ligne de commande, comme aux TP.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. se repérer dans le Gestionnaire de serveur (tableau de bord, serveur local, outils, notifications) ;
  2. gérer le pare-feu sur ses trois profils : domaine, privé, public ;
  3. renommer le serveur et configurer une adresse IP statique (GUI et PowerShell) ;
  4. activer Windows et la communication à distance.

1. Le Gestionnaire de serveur : point central d’administration

Le Gestionnaire de serveur est un composant majeur de Windows Server : point central d’administration, il affiche les informations de configuration et de sécurité, permet d’ajouter des rôles et fonctionnalités, de lancer des commandes PowerShell et de créer des tâches de configuration.

  • Tableau de bord : ajouter des rôles et fonctionnalités (IIS, DHCP, AD DS, DNS…), ajouter d’autres serveurs à gérer, créer des groupes de serveurs (ex. « Serveur Paris », « Serveur Stockage ») ;
  • Serveur local : propriétés de la machine — nom, domaine ou groupe de travail, pare-feu, bureau à distance, cartes réseau, fuseau horaire ;
  • menus Gérer (rôles et fonctionnalités, groupes de serveurs) et Outils (toutes les consoles d’administration) ;
  • Centre de notifications : erreurs et actions à suivre après l’installation d’un rôle.
Le réflexe notifications

Après toute installation de rôle, le centre de notifications indique les actions restantes (ex. « promouvoir ce serveur en contrôleur de domaine » au chapitre 5). L’ignorer, c’est laisser un rôle à moitié configuré.

2. Pare-feu : trois profils à maîtriser

Par défaut, le pare-feu est activé — et l’on oublie généralement sa présence. Beaucoup de « pannes » de réplication ou de service viennent de lui : le réflexe est de vérifier si le problème ne provient pas du pare-feu avant de chercher plus loin.

Trois profils existent : domaine, privé et public. Toute manipulation doit cibler les trois. Trois façons de faire :

Console : Pare-feu Windows avec fonctions avancées
  → Propriétés du pare-feu → État : Désactivé (par profil)
Invite de commande :
  netsh advfirewall set allprofiles state off
  (réactiver : state on)
PowerShell :
  Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
Piège — désactiver un seul profil

Le support est formel : « il faut bien penser à désactiver le pare-feu pour les 3 profils ». Un profil oublié = un service qui tombe selon le réseau de connexion de l’utilisateur. En production, on crée des règles précises plutôt que d’éteindre le pare-feu.

3. Renommer la machine et fixer l’adresse IP

Renommer le serveur — graphiquement : serveur local → cliquer sur le nom actuel → Modifier → nouveau nom → redémarrer. En ligne de commande :

netdom renamecomputer NOMACTUEL /NewName:NOUVEAUNOM
shutdown /r /t 0 /c "changement de nom"

Adresse IP statique — graphiquement : serveur local → Ethernet → Propriétés → Protocole internet version 4 → adresse, masque, passerelle, DNS. En PowerShell, on reparte de l’index d’interface (ifIndex) obtenu par Get-NetAdapter ou Get-NetIPInterface :

New-NetIPAddress -InterfaceIndex 12 -IPAddress 192.168.1.203 `
  -PrefixLength 24 -DefaultGateway 192.168.1.1
Remove-NetIPAddress -InterfaceIndex 12 -IPAddress 10.10.10.10   # ancienne
Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 8.8.8.8
ipconfig /all                                                    # vérification

Deux précisions du support : ajouter une adresse sur une carte en DHCP désactive le DHCP ; l’ActiveStore applique l’adresse immédiatement, le PersistentStore la sauvegarde pour après redémarrage (au démarrage, le contenu du PersistentStore est recopié dans l’ActiveStore).

Modifier le mot de passe administrateur

En invite de commande : net user administrateur * — saisir puis confirmer le nouveau mot de passe. Réflexe de première configuration.

4. Activer Windows et la communication à distance

Activer Windows — graphiquement : Panneau de configuration → Système et sécurité → Système → « Modifier la clé de produit » (activation par Internet ; configurer le proxy si besoin). En ligne de commande, deux procédures :

slmgr.vbs /ipk XXXXX-XXXXX-XXXXX-XXXXX-XXXXX   # installer la clé
slmgr.vbs /ato                                 # activer en ligne
sconfig → 11 (Activation) → 2 (Activer Windows) # équivalent sconfig

Communication à distance — graphiquement : serveur local → Bureau à distance → Activer. En PowerShell, Enable-PSRemoting -Force active l’exécution de commandes PowerShell depuis un autre ordinateur ; l’utilitaire sconfig propose aussi le menu 7 (Bureau à distance : désactivé par défaut → saisir 7, puis A pour activer, puis le niveau de sécurité). Le test se fait depuis une autre machine avec l’outil « Connexion Bureau à distance ».

La check-list de première main

Nom net, IP statique vérifiée par ipconfig /all, DNS renseigné, pare-feu maîtrisé sur les trois profils, Windows activé, accès distant testé depuis une autre machine. Six points — aucun serveur ne doit passer en production sans eux.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Le Gestionnaire de serveur : qui fait quoi ?

Bash Niveau 1 — Acquisition

Objectif : Rattacher chaque action à l’onglet du Gestionnaire de serveur.

Le script lit n lignes « action onglet » : onglet est un code parmi tableaudebord, serveurlocal, notifications ou outils. Actions du support : ajouter des rôles et fonctionnalités, créer un groupe de serveurs → tableaudebord ; renommer la machine, configurer la carte réseau, activer le bureau à distance → serveurlocal ; lire les messages d’erreur après l’installation d’un rôle → notifications ; ouvrir la console Pare-feu avec fonctions avancées → outils. Pour chaque ligne il affiche action : OK ou action : ERREUR, puis correctes : X/n.

Entrée du programme
3
roles tableaudebord
renommer serveurlocal
parefeu outils
Sortie attendue
roles : OK
renommer : OK
parefeu : OK
correctes : 3/3
Deux indices, rédigés en mots
  1. Un case sur l’action : roles/groupes → tableaudebord, renommer/carte/bureau → serveurlocal, erreurs → notifications, parefeu → outils.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Pare-feu : les trois profils

Bash Niveau 2 — Application

Objectif : Vérifier que les trois profils du pare-feu sont traités comme l’exige le support.

Le support est formel : « il faut bien penser à désactiver le pare-feu pour les 3 profils » (domaine, privé, public). Le script lit 3 lignes « profil etat » dans cet ordre (domaine, prive, public) ; etat vaut actif ou inactif. Pour chaque profil il affiche profil : a desactiver s’il est actif, sinon profil : ok, puis a desactiver : X/3 — et si les trois profils sont inactifs, une dernière ligne pare-feu pret.

Entrée du programme
domaine actif
prive inactif
public actif
Sortie attendue
domaine : a desactiver
prive : ok
public : a desactiver
a desactiver : 2/3
Deux indices, rédigés en mots
  1. etat = actif → « a desactiver » et compteur incrémenté ; sinon « ok ».
  2. Après la boucle : si ok = 0, afficher « pare-feu pret ».

Exercice 3 — Adresse IP statique : valider avant d’appliquer

Bash Niveau 3 — Raisonnement

Objectif : Contrôler les adresses IPv4 et préfixes avant la commande New-NetIPAddress.

Le script lit n lignes « index ip prefixe » : index est le numéro d’interface (ifIndex), ip une adresse IPv4 à quatre octets séparés par des points, prefixe la longueur du masque (0 à 32). Une adresse est valide si ses quatre octets sont numériques et compris entre 0 et 255, et si le préfixe est entre 0 et 32. Pour chaque ligne il affiche index : valide ou index : refusee, puis adresses : X/n.

Entrée du programme
3
12 192.168.1.203 24
13 192.168.999.1 24
14 10.10.10.10 40
Sortie attendue
12 : valide
13 : refusee
14 : refusee
adresses : 1/3
Deux indices, rédigés en mots
  1. Découpage : IFS="." read -r o1 o2 o3 o4 <<< "$ip" ; chaque octet doit matcher 0-9+ et valoir au plus 255.
  2. Une valeur non numérique ou > 255, un préfixe hors 0-32 : refusee.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier un profil du pare-feu : le service tombe seulement sur ce profil, panne intermittente garantie.
  • Ajouter une seconde IP sans supprimer l’ancienne : Remove-NetIPAddress est obligatoire pour remplacer.
  • Confondre ActiveStore et PersistentStore : l’un applique maintenant, l’autre retient après reboot.
  • Oublier de redémarrer après un changement de nom : le nouveau nom n’est pas encore actif.

8. Méthodologie de résolution

Configurer un serveur de première main
  1. Ouvrir le Gestionnaire de serveur et passer en revue serveur local + notifications.
  2. Traiter pare-feu (3 profils), nom, IP statique, DNS — dans cet ordre, avec vérification ipconfig /all.
  3. Terminer par l’activation et l’accès à distance, testés depuis une autre machine.

9. Révision active

Résumé essentiel
  • Le Gestionnaire de serveur concentre tableau de bord, serveur local, outils et notifications.
  • Le pare-feu a trois profils (domaine, privé, public) : netsh, PowerShell ou console pour les traiter.
  • Nom et IP se changent graphiquement ou en commande (netdom, New-NetIPAddress avec l’ifIndex).
  • Activation (slmgr, sconfig) et accès à distance (bureau à distance, Enable-PSRemoting) closent la configuration.

Checklist de maîtrise

  • Je situe chaque action dans le bon onglet du Gestionnaire de serveur.
  • Je connais trois façons de traiter le pare-feu et ses trois profils.
  • Je sais fixer une IP statique en PowerShell et la vérifier.
  • Je distingue slmgr /ipk, slmgr /ato et le menu 11 de sconfig.
