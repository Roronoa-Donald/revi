Chapitre 3 — Configuration initiale du serveur

Mise en situation

Le serveur vient d’être installé : il n’a pas encore de nom sérieux, pas d’adresse IP fixe, son pare-feu bloque tout et il n’est pas activé. Un serveur mal configuré à la naissance provoque des pannes incompréhensibles des semaines plus tard. Ce chapitre déroule la liste des réglages de première main, graphiquement et en ligne de commande, comme aux TP.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. se repérer dans le Gestionnaire de serveur (tableau de bord, serveur local, outils, notifications) ;
  2. gérer le pare-feu sur ses trois profils : domaine, privé, public ;
  3. renommer le serveur et configurer une adresse IP statique (GUI et PowerShell) ;
  4. activer Windows et la communication à distance.

1. Le Gestionnaire de serveur : point central d’administration

Le Gestionnaire de serveur est un composant majeur de Windows Server : point central d’administration, il affiche les informations de configuration et de sécurité, permet d’ajouter des rôles et fonctionnalités, de lancer des commandes PowerShell et de créer des tâches de configuration.

  • Tableau de bord : ajouter des rôles et fonctionnalités (IIS, DHCP, AD DS, DNS…), ajouter d’autres serveurs à gérer, créer des groupes de serveurs (ex. « Serveur Paris », « Serveur Stockage ») ;
  • Serveur local : propriétés de la machine — nom, domaine ou groupe de travail, pare-feu, bureau à distance, cartes réseau, fuseau horaire ;
  • menus Gérer (rôles et fonctionnalités, groupes de serveurs) et Outils (toutes les consoles d’administration) ;
  • Centre de notifications : erreurs et actions à suivre après l’installation d’un rôle.
Le réflexe notifications

Après toute installation de rôle, le centre de notifications indique les actions restantes (ex. « promouvoir ce serveur en contrôleur de domaine » au chapitre 5). L’ignorer, c’est laisser un rôle à moitié configuré.

2. Pare-feu : trois profils à maîtriser

Par défaut, le pare-feu est activé — et l’on oublie généralement sa présence. Beaucoup de « pannes » de réplication ou de service viennent de lui : le réflexe est de vérifier si le problème ne provient pas du pare-feu avant de chercher plus loin.

Trois profils existent : domaine, privé et public. Toute manipulation doit cibler les trois. Trois façons de faire :

Console : Pare-feu Windows avec fonctions avancées
  → Propriétés du pare-feu → État : Désactivé (par profil)
Invite de commande :
  netsh advfirewall set allprofiles state off
  (réactiver : state on)
PowerShell :
  Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False
Piège — désactiver un seul profil

Le support est formel : « il faut bien penser à désactiver le pare-feu pour les 3 profils ». Un profil oublié = un service qui tombe selon le réseau de connexion de l’utilisateur. En production, on crée des règles précises plutôt que d’éteindre le pare-feu.

3. Renommer la machine et fixer l’adresse IP

Renommer le serveur — graphiquement : serveur local → cliquer sur le nom actuel → Modifier → nouveau nom → redémarrer. En ligne de commande :

netdom renamecomputer NOMACTUEL /NewName:NOUVEAUNOM
shutdown /r /t 0 /c "changement de nom"

Adresse IP statique — graphiquement : serveur local → Ethernet → Propriétés → Protocole internet version 4 → adresse, masque, passerelle, DNS. En PowerShell, on reparte de l’index d’interface (ifIndex) obtenu par Get-NetAdapter ou Get-NetIPInterface :

New-NetIPAddress -InterfaceIndex 12 -IPAddress 192.168.1.203 `
  -PrefixLength 24 -DefaultGateway 192.168.1.1
Remove-NetIPAddress -InterfaceIndex 12 -IPAddress 10.10.10.10   # ancienne
Set-DnsClientServerAddress -InterfaceIndex 12 -ServerAddresses 8.8.8.8
ipconfig /all                                                    # vérification

Deux précisions du support : ajouter une adresse sur une carte en DHCP désactive le DHCP ; l’ActiveStore applique l’adresse immédiatement, le PersistentStore la sauvegarde pour après redémarrage (au démarrage, le contenu du PersistentStore est recopié dans l’ActiveStore).

Modifier le mot de passe administrateur

En invite de commande : net user administrateur * — saisir puis confirmer le nouveau mot de passe. Réflexe de première configuration.

4. Activer Windows et la communication à distance

Activer Windows — graphiquement : Panneau de configuration → Système et sécurité → Système → « Modifier la clé de produit » (activation par Internet ; configurer le proxy si besoin). En ligne de commande, deux procédures :

slmgr.vbs /ipk XXXXX-XXXXX-XXXXX-XXXXX-XXXXX   # installer la clé
slmgr.vbs /ato                                 # activer en ligne
sconfig → 11 (Activation) → 2 (Activer Windows) # équivalent sconfig

Communication à distance — graphiquement : serveur local → Bureau à distance → Activer. En PowerShell, Enable-PSRemoting -Force active l’exécution de commandes PowerShell depuis un autre ordinateur ; l’utilitaire sconfig propose aussi le menu 7 (Bureau à distance : désactivé par défaut → saisir 7, puis A pour activer, puis le niveau de sécurité). Le test se fait depuis une autre machine avec l’outil « Connexion Bureau à distance ».

La check-list de première main

Nom net, IP statique vérifiée par ipconfig /all, DNS renseigné, pare-feu maîtrisé sur les trois profils, Windows activé, accès distant testé depuis une autre machine. Six points — aucun serveur ne doit passer en production sans eux.

5. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

La validation compare vos réponses aux attendus des cas affichés ; elle ne vérifie pas votre capacité à traiter toutes les situations.

Exercice 1 — Premier tour du Gestionnaire de serveur chez BâtirPlus

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Situer chaque action de configuration dans la bonne zone du Gestionnaire de serveur.

Énoncé. La PME de BTP BâtirPlus vient d'installer Windows Server 2012 R2 sur son serveur SRV-BTP. Le nouvel administrateur découvre le Gestionnaire de serveur, point central d'administration de Windows Server. Le cours décrit ses zones : le tableau de bord (ajouter des rôles et fonctionnalités, ajouter d'autres serveurs à gérer, créer des groupes de serveurs), serveur local (propriétés de la machine : nom, domaine ou groupe de travail, pare-feu, bureau à distance, cartes réseau, fuseau horaire), les menus Gérer et Outils (toutes les consoles d'administration), et le centre de notifications (erreurs et actions à suivre après l'installation d'un rôle).

Le premier matin, cinq actions sont à réaliser :

N°Action à réaliser
1Renommer la machine SRV-BTP.
2Ajouter le rôle Impression au serveur.
3Après l'installation du rôle, lire les messages d'erreur et les actions à suivre.
4Ouvrir la console « Pare-feu Windows avec fonctions avancées ».
5Activer le bureau à distance sur le serveur.

Répondez par un seul mot ou une expression très courte à chaque question.

  1. Dans quelle zone du Gestionnaire de serveur réaliser l'action n° 1 ?
  2. Dans quelle zone réaliser l'action n° 2 ?
  3. Dans quelle zone réaliser l'action n° 3 ?
  4. Dans quelle zone réaliser l'action n° 4 ?
  5. Comment s'appelle le composant de Windows Server décrit comme le « point central d'administration » ?
Cas d’exemple
Une agence prend en main son serveur : « configurer la carte réseau », puis « ajouter le rôle DHCP », puis « consulter les erreurs après l'installation du rôle ».

1) Configurer la carte réseau : serveur local.
2) Ajouter le rôle DHCP : tableau de bord.
3) Consulter les erreurs : notifications.
Trois indices, rédigés en mots
  1. Quatre zones à connaître : tableau de bord (rôles, serveurs, groupes de serveurs), serveur local (propriétés de la machine), outils (consoles d'administration), centre de notifications (messages après installation d'un rôle).
  2. Demandez-vous si l'action modifie la machine elle-même, ajoute un service, consulte un message, ou ouvre une console existante.
  3. Contrôle : deux actions touchent les propriétés de la machine elle-même ; une ajoute un service ; une consulte un message ; une ouvre une console.

Exercice 2 — Le pare-feu à trois profils du serveur du ComptoirNiger

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Traiter le pare-feu Windows sur ses trois profils (domaine, privé, public) et écrire les commandes netsh et PowerShell du cours.

Énoncé. Au ComptoirNiger, le serveur de fichiers devient inaccessible par intermittence : le partage fonctionne au siège mais pas depuis l'ordinateur portable du dirigeant connecté en déplacement. Le support du cours rappelle que le pare-feu Windows possède trois profils — domaine, privé et public — et que toute manipulation doit cibler les trois (« il faut bien penser à désactiver le pare-feu pour les 3 profils » en laboratoire). L'état actuel du pare-feu du serveur :

ProfilÉtat actuel
DomaineDésactivé
PrivéActivé
PublicDésactivé

Rappel du cours, trois façons de traiter le pare-feu : la console « Pare-feu Windows avec fonctions avancées » ; la commande netsh advfirewall set allprofiles state off (réactiver avec state on) ; la cmdlet PowerShell Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False.

  1. Citez les trois profils du pare-feu (un mot chacun, séparés par des espaces).
  2. D'après le tableau, quel profil encore activé explique la panne intermittente du dirigeant en déplacement ?
  3. Écrivez la commande netsh qui désactive le pare-feu pour TOUS les profils.
  4. Écrivez la cmdlet PowerShell équivalente (profils, puis état).
  5. À l'installation de Windows Server, le pare-feu est-il activé ou désactivé par défaut ? (un seul mot)
Cas d’exemple
Le formateur prépare un serveur de TP : profil domaine inactif, profil public actif, profil privé inactif. Il veut tout désactiver pour le laboratoire, puis pouvoir réactiver.

1) Le profil encore actif : public.
2) La commande netsh : netsh advfirewall set allprofiles state off.
3) Pour réactiver : netsh advfirewall set allprofiles state on.
Trois indices, rédigés en mots
  1. Trois profils, un par contexte de connexion : le domaine de l'entreprise, les réseaux privés, les réseaux publics.
  2. La panne n'apparaît que dans certaines situations : cherchez le profil qui correspond au réseau du moment du dirigeant, et regardez s'il est encore activé dans le tableau.
  3. Pour les commandes, recopiez la syntaxe exacte du cours : netsh traite tous les profils d'un coup ; la cmdlet PowerShell enchaîne le paramètre des profils puis l'état False.

Exercice 3 — Une identité fixe pour le serveur de la scierie ForêtVert

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Renommer le serveur (netdom) et fixer son adresse IP statique (Get-NetAdapter, New-NetIPAddress, Remove-NetIPAddress, DNS) comme au TP du cours.

Énoncé. La scierie ForêtVert vient d'installer Windows Server 2012 R2 sur un serveur livré sous le nom WIN-SRV1. L'administrateur doit lui donner une identité sérieuse avant d'y installer AD DS :

  • nouveau nom du serveur : SRV-BOIS ;
  • carte réseau d'index ifIndex 12, repérée avec Get-NetAdapter ;
  • adresse IP fixe : 172.16.5.10, préfixe 24, passerelle 172.16.5.1 ;
  • l'ancienne adresse 10.10.10.10, obtenue par DHCP, doit disparaître ;
  • serveur DNS à définir sur la même carte : 172.16.5.10.

Rappel du cours : netdom renamecomputer NOMACTUEL /NewName:NOUVEAUNOM puis shutdown /r ; New-NetIPAddress -InterfaceIndex 12 -IPAddress … -PrefixLength 24 -DefaultGateway … ; Remove-NetIPAddress pour supprimer l'ancienne adresse ; Set-DnsClientServerAddress pour le DNS ; l'ActiveStore applique l'adresse immédiatement, le PersistentStore la sauvegarde pour après redémarrage (au démarrage, le PersistentStore est recopié dans l'ActiveStore).

  1. Quelle cmdlet liste les cartes réseau et leur ifIndex ?
  2. Écrivez la commande netdom complète qui renomme le serveur (sans le redémarrage).
  3. Quelle cmdlet ajoute la nouvelle adresse IP fixe ?
  4. Quelle cmdlet supprime l'ancienne adresse 10.10.10.10 ?
  5. Quelle cmdlet définit le serveur DNS de la carte ?
  6. Quel magasin sauvegarde l'adresse pour qu'elle survive au redémarrage : ActiveStore ou PersistentStore ?
Cas d’exemple
Une école configure son serveur WIN-TST, à renommer SRV-TEST : carte d'ifIndex 14, IP fixe 192.168.50.5/24, ancienne IP 172.20.1.5.

1) Repérer la carte : Get-NetAdapter.
2) Renommer : netdom renamecomputer WIN-TST /NewName:SRV-TEST.
3) Ajouter l'IP fixe : New-NetIPAddress -InterfaceIndex 14 -IPAddress 192.168.50.5 -PrefixLength 24.
Trois indices, rédigés en mots
  1. Le cours enchaîne les gestes dans l'ordre : repérer l'interface (ifIndex), renommer la machine, fixer la nouvelle IP, retirer l'ancienne, définir le DNS.
  2. Pour la question 2, la commande netdom attend l'ancien nom puis le paramètre du nouveau nom, séparés par un espace ; le redémarrage est une commande à part (shutdown /r).
  3. Contrôle final : ipconfig /all doit montrer le nouveau nom, l'adresse fixe et le DNS ; pour la question 6, relisez ce que fait chaque magasin au moment du redémarrage.

La commande PowerShell qui éteint le pare-feu sur tous les profils…

Pour renommer le serveur en ligne de commande…

Puis redémarrer (shutdown /r) pour appliquer.

Le numéro d’interface d’une carte s’obtient par…

Get-NetAdapter ou Get-NetIPInterface ; l’ifIndex sert aux commandes de configuration.

L’ActiveStore…

Le PersistentStore sauvegarde pour le redémarrage ; au boot, PersistentStore recopie dans ActiveStore.

L’activation en ligne se lance par…

/ipk installe la clé, /ato tente l’activation en ligne ; sconfig menu 11 exécute la même commande.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier un profil du pare-feu : le service tombe seulement sur ce profil, panne intermittente garantie.
  • Ajouter une seconde IP sans supprimer l’ancienne : Remove-NetIPAddress est obligatoire pour remplacer.
  • Confondre ActiveStore et PersistentStore : l’un applique maintenant, l’autre retient après reboot.
  • Oublier de redémarrer après un changement de nom : le nouveau nom n’est pas encore actif.

8. Méthodologie de résolution

Configurer un serveur de première main
  1. Ouvrir le Gestionnaire de serveur et passer en revue serveur local + notifications.
  2. Traiter pare-feu (3 profils), nom, IP statique, DNS — dans cet ordre, avec vérification ipconfig /all.
  3. Terminer par l’activation et l’accès à distance, testés depuis une autre machine.

9. Révision active

Résumé essentiel
  • Le Gestionnaire de serveur concentre tableau de bord, serveur local, outils et notifications.
  • Le pare-feu a trois profils (domaine, privé, public) : netsh, PowerShell ou console pour les traiter.
  • Nom et IP se changent graphiquement ou en commande (netdom, New-NetIPAddress avec l’ifIndex).
  • Activation (slmgr, sconfig) et accès à distance (bureau à distance, Enable-PSRemoting) closent la configuration.

Checklist de maîtrise

  • Je situe chaque action dans le bon onglet du Gestionnaire de serveur.
  • Je connais trois façons de traiter le pare-feu et ses trois profils.
  • Je sais fixer une IP statique en PowerShell et la vérifier.
  • Je distingue slmgr /ipk, slmgr /ato et le menu 11 de sconfig.
