Chapitre 4 — Active Directory : domaine, arbre, forêt

Module 4 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

L’entreprise grandit : des comptes éparpillés sur chaque machine ne suffisent plus. Il faut un annuaire central qui connaisse utilisateurs, ordinateurs et droits — et qui tienne dans une hiérarchie claire quand il y a plusieurs sites. Ce chapitre construit le vocabulaire exact de cet annuaire : domaine, arbre, forêt, sous-domaine.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. définir Active Directory (AD DS) et son organisation hiérarchique ;
  2. décrire le domaine : entité logique qui héberge objets et stratégies ;
  3. construire un arbre (espace de nom contigu) et une forêt (regroupement d’arbres) ;
  4. nommer des sous-domaines de succursales (domaines enfants).

1. La notion d’Active Directory

Une infrastructure Active Directory fonctionne selon une hiérarchie : cette hiérarchie forme une arborescence composée de domaines, d’arbres et de forêt.

Un domaine est une entité logique (administrative) Active Directory au sein de laquelle des fonctionnalités et caractéristiques sont partagées. Un domaine héberge des utilisateurs, des ordinateurs, dans lequel des paramètres de stratégies sont définis.

Au sein du domaine, on retrouve un ensemble d’unités d’organisation (UO) remplies d’objets de différentes classes : utilisateurs, ordinateurs, groupes, contrôleurs de domaine…

L’annuaire de l’entreprise

Active Directory est l’annuaire central : un seul endroit où sont décrits les comptes, les machines et les droits. Un utilisateur change de poste ? Son compte suit, il ne se recrée pas machine par machine.

2. Succursales et sous-domaines

De nombreuses entreprises ont plusieurs succursales — donc plusieurs sites sur différents emplacements géographiques. Selon l’importance de ces sites, on pourra créer un sous-domaine au domaine principal, voire plusieurs sous-domaines.

Exemple du support : on part du domaine de base cdp.org, auquel on ajoute deux sous-domaines — paris.cdp.org et lome.cdp.org — pour les deux succursales de Paris et de Lomé. Ces domaines sont les domaines enfants du domaine racine cdp.org.

Piège — renommer un domaine après coup

Le support insiste : le nom du domaine est très important, il faut saisir un nom de domaine réel. Le renommage d’un domaine AD DS est possible, mais l’impact technique est très conséquent — pour les PC, les utilisateurs, les services et les logiciels.

3. Arbre et forêt

Lorsqu’un domaine principal contient plusieurs sous-domaines, on parle d’arbre : chaque sous-domaine représente une branche. Un arbre est un regroupement hiérarchique de plusieurs domaines ; les domaines d’un même arbre partagent un espace de nom contigu et hiérarchique — comme cdp.org, paris.cdp.org, lome.cdp.org.

Si une forêt est un ensemble d’arbres, alors la forêt est un regroupement d’une ou de plusieurs arborescences de domaine. Ces arborescences sont indépendantes et distinctes bien qu’elles soient dans la même forêt.

Le support l’illustre : si l’on rachète « college-paris » et que l’on crée un domaine racine college-paris.local avec ses sous-domaines paris.college-paris.local, cameroun.college-paris.local et dev.cameroun.college-paris.local, on obtient un second arbre — racine college-paris.local — dans la même forêt qui en contenait déjà un (cdp.org).

Mnémotechnique — trois mots, trois tailles

Domaine = l’entité (objets + stratégies). Arbre = des domaines à nom contigu (cdp.org et ses enfants). Forêt = des arbres indépendants réunis. Du plus petit au plus grand : domaine ⊂ arbre ⊂ forêt.

4. Ce qu’il faut retenir avant d’installer

Ce vocabulaire n’est pas décoratif : chaque choix d’installation du chapitre suivant s’exprime en ses termes. « Ajouter une nouvelle forêt » = créer un domaine racine ; choisir le niveau fonctionnel = les services disponibles pour le domaine ; le nom NetBIOS = le préfixe du domaine saisi.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Domaine, arbre, forêt : le vocabulaire

Bash Niveau 1 — Acquisition

Objectif : Associer chaque notion AD DS à sa définition du support.

Le script lit n lignes « notion definition » : definition est un code parmi entite, contigu, arbres ou enfant. Notions du support : le domaine est l’entité logique (administrative) qui héberge utilisateurs, ordinateurs et stratégies → entite ; un arbre regroupe des domaines partageant un espace de nom contigu → contigu ; une forêt est un regroupement d’arbres → arbres ; un sous-domaine dépend du domaine racine (domaine enfant) → enfant. Pour chaque ligne il affiche notion : OK ou notion : ERREUR, puis correctes : X/n.

Entrée du programme
3
domaine entite
arbre contigu
foret arbres
Sortie attendue
domaine : OK
arbre : OK
foret : OK
correctes : 3/3
Deux indices, rédigés en mots
  1. Un case sur la notion : domaine → entite, arbre → contigu, foret → arbres, sousdomaine → enfant.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — L’arborescence des succursales

Bash Niveau 2 — Application

Objectif : Classer racine et domaines enfants dans l’arborescence d’entreprise.

Le support construit cdp.org avec les sous-domaines paris.cdp.org et lome.cdp.org. Le script lit n lignes « domaine parent » : parent vaut - si le domaine est racine, sinon le nom de son parent. Pour chaque domaine il affiche domaine : racine ou domaine : enfant de parent, puis racines : X et enfants : Y.

Entrée du programme
3
cdp.org -
paris.cdp.org cdp.org
lome.cdp.org cdp.org
Sortie attendue
cdp.org : racine
paris.cdp.org : enfant de cdp.org
lome.cdp.org : enfant de cdp.org
racines : 1
enfants : 2
Deux indices, rédigés en mots
  1. parent = "-" → racine (r incrémenté) ; sinon « enfant de $parent » (e incrémenté).
  2. Les deux bilans sortent une seule fois, après la boucle.

Exercice 3 — Les objets par unité d’organisation

Bash Niveau 3 — Raisonnement

Objectif : Compter les objets AD DS logés dans chaque unité d’organisation.

Le support décrit des unités d’organisation « remplies d’objets de différentes classes : utilisateurs, ordinateurs, groupes, contrôleurs de domaine ». Le script lit n lignes « objet uo » et affiche d’abord chaque ligne objet : uo, puis pour chaque unité d’organisation, dans l’ordre de première apparition, uo : X objets, et enfin uos : Y.

Entrée du programme
3
iziti TRI
poste1 TRI
groupe-ventes VENTES
Sortie attendue
iziti : TRI
poste1 : TRI
groupe-ventes : VENTES
TRI : 2 objets
VENTES : 1 objets
uos : 2
Deux indices, rédigés en mots
  1. Nouvelle UO : [ -z "${compte[$uo]+x}" ] → ordre[$g]=$uo et g=$((g+1)).
  2. Les bilans sortent après la boucle : UO dans l’ordre du tableau ordre, puis g.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre arbre et forêt : l’arbre exige un nom contigu, la forêt réunit des arbres indépendants.
  • Choisir un nom de domaine à la légère : son renommage coûte très cher techniquement.
  • Placer les objets directement à la racine du domaine sans structure d’UO.
  • Croire qu’une forêt ne peut contenir qu’un arbre : le support montre le cas du rachat avec deux arbres.

8. Méthodologie de résolution

Dessiner une arborescence AD
  1. Partir du métier : un site ou plusieurs ? une filiale rachetée ?
  2. Nommer le domaine racine (nom réel, réfléchi), puis les enfants par succursale.
  3. Vérifier la contiguïté : si les noms sont contigus, c’est un arbre ; sinon, une forêt à plusieurs arbres.

9. Révision active

Résumé essentiel
  • Active Directory est un annuaire hiérarchique : domaine, arbre, forêt.
  • Le domaine héberge les objets (utilisateurs, ordinateurs, groupes) et les stratégies.
  • Les sous-domaines servent les succursales : paris.cdp.org, lome.cdp.org.
  • Un arbre = noms contigus ; une forêt = arbres indépendants réunis.

Checklist de maîtrise

  • Je définis domaine, arbre et forêt en une phrase chacun.
  • Je construis l’arborescence d’une entreprise à deux succursales.
  • Je sais expliquer le risque du renommage d’un domaine.
  • Je range les objets par classes dans des unités d’organisation.
