Chapitre 5 — Installer un contrôleur de domaine

Mise en situation

Le serveur est configuré (chapitre 3) : il ne manque que le cœur du réseau d’entreprise. Installer AD DS se fait en deux temps — le rôle, puis la promotion en contrôleur de domaine — et demande cinq informations exactes. Ce chapitre suit l’assistant pas à pas, puis rejoue l’installation en PowerShell.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. installer le rôle AD DS et ses fonctionnalités associées ;
  2. promouvoir le serveur en contrôleur de domaine (nouvelle forêt) ;
  3. fixer nom DNS, nom NetBIOS, niveaux fonctionnels et mot de passe de restauration ;
  4. situer les dossiers de la base (NTDS.DIT), des journaux et de SYSVOL.

1. Installer le rôle AD DS

Pour ajouter le rôle : Gestionnaire de serveur → Gérer → Ajouter des rôles et des fonctionnalités. On choisit « Installation basée sur un rôle ou une fonctionnalité » (un nouveau rôle, pas une fonctionnalité complémentaire), puis le serveur cible — ici le seul serveur du TP.

Pour un réseau d’entreprise simple, on sélectionne uniquement Services AD DS (AD DS). Quand la case est cochée, des fonctionnalités complémentaires sont automatiquement sélectionnées : il est impératif de les avoir toutes pour gérer efficacement le serveur AD.

À la fin de l’installation initiale, les binaires AD DS sont installés — mais AD DS n’est pas encore configuré. Un message du Gestionnaire de serveur propose le lien « Promouvoir ce serveur en contrôleur de domaine » : c’est l’assistant de configuration, passage obligatoire.

Piège — s’arrêter après l’installation du rôle

Installer les binaires ne configure rien : sans la promotion, il n’y a ni domaine ni contrôleur. Le bandeau jaune du Gestionnaire de serveur le rappelle tant que la configuration est incomplète.

2. Les informations à réunir avant la configuration

Il existe différents types de configuration selon le besoin de l’entreprise. Avant d’exécuter la configuration de l’AD DS, vous devez disposer de :

  • le nom DNS pour le domaine AD DS ;
  • le nom NetBIOS ;
  • le fait que le contrôleur de domaine doit (ou non) prendre en charge les versions antérieures ;
  • le fait que le contrôleur de domaine sera également DNS ;
  • l’emplacement de la base de données NTDS.DIT et de SYSVOL (+ le mot de passe de restauration).
Cinq questions avant de cliquer

Nom DNS du domaine ? Nom NetBIOS (préfixe du domaine) ? Compatibilité ancienne ? DNS sur le même serveur ? Où stocker la base ? Cinq réponses écrites à l’avance = une installation sans retour en arrière.

3. Ajouter une nouvelle forêt

La procédure actuelle étant la création d’un nouveau domaine, on sélectionne « Ajouter une nouvelle forêt » et on entre le nom du domaine — un nom réel et réfléchi (chapitre 4).

Le niveau fonctionnel d’un domaine correspond aux services disponibles pour ce domaine : plus il est élevé, plus les fonctionnalités sont nombreuses. Le support conseille d’utiliser le niveau le plus haut — Windows Server 2012 R2.

Seconde étape obligatoire : le mot de passe de restauration (DSRM). Il sera utilisé uniquement si l’AD DS se retrouve corrompu et inaccessible : c’est le sésame de la restauration. Il doit donc être solide et… mémorisé.

Un message d’avertissement apparaît ensuite : le rôle AD DS nécessite le rôle DNS. Si vous installez le DNS en même temps que l’AD DS (ou sans configuration spécifique), la configuration se fera quasi-automatiquement ; sinon (serveur DNS séparé, par exemple Linux), vous devrez créer les zones DNS vous-même.

Pourquoi DNS est inseparable d’AD

Les clients localisent le domaine par son nom DNS : sans zone DNS correcte, personne ne trouve le contrôleur de domaine. C’est pourquoi l’assistant propose de l’installer en même temps.

4. Emplacements des données et vérification

L’étape « emplacement des données » propose trois dossiers :

  • Base de données : tous les fichiers du fonctionnement interne de l’Active Directory — fichiers temporaires, fichiers d’échanges, la base NTDS.DIT ;
  • Fichiers journaux : les logs, lus par l’Observateur d’événements ;
  • SYSVOL : les scripts de connexion des utilisateurs, les GPO (stratégies de groupe) et les fichiers nécessaires à la réplication AD et aux partages publics.

Par défaut ces dossiers vivent sous C:\Windows ; on peut les déplacer — simple question d’organisation interne. Un récapitulatif complet s’affiche, puis vient la vérification : Windows Server dit si les paramètres sont corrects pour un domaine AD. Quand tous les prérequis sont validés, le serveur doit être obligatoirement redémarré.

En PowerShell, le même résultat : récupérer le nom du serveur, installer le rôle (Install-WindowsFeature), puis configurer la nouvelle forêt avec Install-ADDSForest — nom de domaine, niveaux fonctionnels et options incluant la création du DNS.

Trois dossiers à retenir

NTDS.DIT = la base AD. Journaux = les logs. SYSVOL = scripts de connexion, GPO, réplication. Une question d’examen classique : « où sont stockés les GPO ? » → SYSVOL.

Exercice 1 — Le premier contrôleur de domaine de la Menuiserie Bois d'Or

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Dérouler les deux temps de l'installation : le rôle AD DS, puis la promotion du serveur en contrôleur de domaine d'une nouvelle forêt.

Énoncé. La Menuiserie Bois d'Or a configuré son serveur SRV-OR (nom, adresse IP fixe, pare-feu, activation) : place maintenant à l'annuaire d'entreprise. L'administrateur veut créer le domaine boisdor.local. Le cours déroule l'installation en deux temps : d'abord le rôle AD DS (Gestionnaire de serveur, Gérer, Ajouter des rôles et des fonctionnalités : on coche « Services AD DS » et les fonctionnalités complémentaires) ; à la fin de cette installation, les binaires sont installés mais AD DS n'est pas encore configuré ; le Gestionnaire de serveur propose alors le lien « Promouvoir ce serveur en contrôleur de domaine ». Dans l'assistant, la création d'un premier domaine racine passe par « Ajouter une nouvelle forêt ». En PowerShell : Install-WindowsFeature pour le rôle, puis Install-ADDSForest pour la forêt. Après la vérification des prérequis, le serveur doit obligatoirement redémarrer.

Répondez par un sigle, un mot ou un nom de cmdlet.

  1. Quel rôle faut-il installer pour bâtir un contrôleur de domaine ? (sigle)
  2. Après l'installation des binaires, le serveur est-il déjà un contrôleur de domaine ? (oui/non)
  3. Comment s'appelle l'opération, proposée par le bandeau du Gestionnaire de serveur, qui achève la configuration ?
  4. Pour créer un tout premier domaine racine, l'assistant propose d'ajouter une nouvelle… ? (un mot)
  5. Quelle cmdlet PowerShell crée la nouvelle forêt ?
Cas d’exemple
Une librairie installe son premier contrôleur de domaine pour le domaine librairie.local.

1) Le rôle à installer : AD DS.
2) L'assistant propose : Ajouter une nouvelle forêt.
3) La cmdlet PowerShell : Install-ADDSForest.
Trois indices, rédigés en mots
  1. Deux temps bien distincts : l'installation du rôle pose les binaires ; la configuration du serveur vient ensuite, par le lien du bandeau jaune.
  2. Tant que la configuration n'est pas faite, le domaine n'existe pas : un rôle à moitié configuré n'est pas un contrôleur.
  3. Pour la question 4, un premier domaine racine fonde une structure complète : le mot du cours désigne l'ensemble des arbres.

Exercice 2 — La fiche de préparation d'ImprimaLocal

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Réunir avant l'assistant les informations exigées : nom DNS, nom NetBIOS, niveau fonctionnel, NTDS.DIT, SYSVOL et mot de passe DSRM.

Énoncé. L'imprimerie ImprimaLocal (45 salariés) promeut son serveur SRV-IMP en contrôleur de domaine. Le cours exige de disposer, AVANT de lancer la configuration de l'AD DS, de : le nom DNS du domaine, le nom NetBIOS, la prise en charge (ou non) des versions antérieures, le fait que le contrôleur sera également DNS, et l'emplacement de la base NTDS.DIT et de SYSVOL (plus le mot de passe de restauration). La fiche de préparation validée par la direction :

RubriqueValeur retenue
Nom DNS du domaineimprimerie.local
Nom NetBIOSIMPRIM
Niveau fonctionnelle plus haut conseillé par le support

Rappel du cours : le niveau fonctionnel d'un domaine correspond aux services disponibles pour ce domaine — plus il est élevé, plus les fonctionnalités sont nombreuses ; la base de données de l'Active Directory s'appelle NTDS.DIT ; SYSVOL contient les scripts de connexion des utilisateurs, les GPO (stratégies de groupe) et les fichiers nécessaires à la réplication ; le mot de passe de restauration (DSRM) sera utilisé uniquement si l'AD DS se retrouve corrompu et inaccessible.

Répondez par un nom, un sigle ou un niveau exact.

  1. Quel est le nom DNS complet du domaine à créer ?
  2. Quel est le nom NetBIOS retenu ?
  3. Quel niveau fonctionnel la direction retient-elle ? (le plus haut disponible)
  4. Quel est le nom du fichier de la base de données de l'Active Directory ?
  5. Dans quel dossier sont stockés les scripts de connexion et les GPO ?
  6. Quel est le sigle du mot de passe de restauration ?
Cas d’exemple
Un cabinet d'architectes prépare son contrôleur de domaine : domaine cabinets-archi.local, nom NetBIOS ARCHI, niveau fonctionnel le plus haut (Windows Server 2012 R2).

1) Nom DNS : cabinets-archi.local.
2) NetBIOS : ARCHI.
3) Niveau fonctionnel : Windows Server 2012 R2.
Trois indices, rédigés en mots
  1. Cinq questions avant de cliquer : nom DNS, nom NetBIOS, compatibilité anciennes versions, DNS sur le contrôleur, emplacements de la base et de SYSVOL.
  2. Le nom NetBIOS est le préfixe court de la fiche ; le nom DNS porte le suffixe complet du domaine.
  3. Contrôle : la base est un fichier au nom bien connu ; le dossier des stratégies est un dossier système ; le mot de passe de secours s'abrège en quatre lettres.

Exercice 3 — Remettre l'assistant AD DS en ordre chez VulcanMéca

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Ordonner les étapes de l'installation d'un contrôleur de domaine et situer le rôle DNS, les GPO et les dossiers par défaut.

Énoncé. Chez VulcanMéca (mécanique industrielle), un stagiaire a mélangé ses notes sur l'installation du contrôleur de domaine du serveur SRV-VUL. Ses cinq étapes, dans le désordre :

LettreÉtape notée par le stagiaire
APromouvoir le serveur en contrôleur de domaine (nouvelle forêt, nom du domaine)
BInstaller le rôle AD DS avec ses fonctionnalités complémentaires
CRedémarrer le serveur après la vérification des prérequis
DChoisir le niveau fonctionnel et définir le mot de passe de restauration
EChoisir les emplacements de la base NTDS.DIT, des journaux et de SYSVOL

Rappel du cours : l'ordre de l'assistant est rôle, puis promotion (nouvelle forêt), puis niveau fonctionnel et mot de passe DSRM, puis DNS, puis dossiers, puis récapitulatif, vérification des prérequis et redémarrage obligatoire ; l'avertissement de l'assistant signale que le rôle AD DS nécessite le rôle DNS ; SYSVOL contient les scripts de connexion, les GPO et les fichiers nécessaires à la réplication ; par défaut, les dossiers de la base, des journaux et de SYSVOL vivent sous C:\Windows.

Aux questions 1 à 3, répondez par la lettre seule de l'étape.

  1. Quelle étape vient en premier ?
  2. Quelle étape suit immédiatement l'installation du rôle ?
  3. Quelle étape clôt la procédure ?
  4. L'avertissement de l'assistant rappelle que le rôle AD DS nécessite quel autre rôle ?
  5. SYSVOL contient les scripts de connexion, les fichiers de réplication et quelles stratégies ? (sigle)
  6. Par défaut, sous quel dossier de Windows les dossiers de l'AD sont-ils créés ?
Cas d’exemple
Un garagiste note ses étapes en désordre : « X. définir le mot de passe DSRM », « Y. installer le rôle AD DS », « Z. promouvoir le serveur (nouvelle forêt) ».

1) La première étape : Y.
2) La deuxième : Z.
3) La troisième : X.
Trois indices, rédigés en mots
  1. L'ordre du cours : les binaires d'abord, la promotion ensuite, puis les choix de configuration — le redémarrage clôt toujours la vérification des prérequis.
  2. Repérez l'étape qui ne peut avoir aucun prérequis (la toute première) et celle qui n'a de sens qu'une fois tout vérifié (la toute dernière).
  3. Contrôle : votre ordre doit commencer par l'étape qui installe et finir par celle qui redémarre ; entre les deux, la configuration précède la vérification.

6. QCM — niveau examen

Après l’installation initiale du rôle AD DS…

AD DS n’est pas encore configuré : il faut promouvoir le serveur en contrôleur de domaine.

Pour créer un domaine racine, l’assistant propose…

La création d’un nouveau domaine racine passe par « Ajouter une nouvelle forêt ».

Le niveau fonctionnel du domaine définit…

Plus le niveau est élevé, plus les fonctionnalités sont nombreuses : viser 2012 R2.

Le mot de passe de restauration sert…

DSRM : utilisé uniquement si l’AD devient inaccessible — d’où sa solidité.

L’avertissement à l’installation d’AD DS concerne…

AD DS nécessite un serveur DNS ; installé en même temps, il se configure quasi-automatiquement.

La base de l’Active Directory s’appelle…

NTDS.DIT dans le dossier « base de données » ; SYSVOL porte scripts et GPO.

Le dossier SYSVOL contient…

Les fichiers journaux sont dans le second dossier ; SYSVOL est le dossier des stratégies.

Quand la vérification des prérequis est passée…

Le redémarrage est obligatoire pour finaliser la promotion.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • S’arrêter après l’installation du rôle : sans promotion, pas de contrôleur de domaine.
  • Saisir un nom de domaine irréel : son renommage ultérieur est très coûteux (chapitre 4).
  • Bâcler le mot de passe de restauration : c’est la seule clé de secours d’un AD inaccessible.
  • Oublier le redémarrage final : la promotion ne s’achève pas sans lui.

8. Méthodologie de résolution

Installer AD DS sans faux pas
  1. Écrire les cinq informations avant l’assistant : DNS, NetBIOS, anciennes versions, DNS local, emplacements.
  2. Suivre l’ordre : rôle → promotion (nouvelle forêt) → niveaux → DSRM → DNS → dossiers.
  3. Lire le récapitulatif, attendre la vérification des prérequis, redémarrer, puis vérifier le domaine.

9. Révision active

Résumé essentiel
  • Deux temps : installer le rôle AD DS, puis promouvoir le serveur en contrôleur de domaine.
  • « Ajouter une nouvelle forêt » crée le domaine racine ; le nom doit être réel et réfléchi.
  • Niveau fonctionnel le plus haut conseillé (2012 R2) ; mot de passe DSRM solide obligatoire.
  • AD DS exige le DNS ; la base NTDS.DIT, les journaux et SYSVOL ont chacun leur dossier ; redémarrage final.

Checklist de maîtrise

  • Je distingue NTDS.DIT, journaux et SYSVOL.
  • Je connais l’équivalent PowerShell (Install-WindowsFeature, Install-ADDSForest).
