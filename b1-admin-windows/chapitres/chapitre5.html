Chapitre 5 — Installer un contrôleur de domaine

Module 5 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Le serveur est configuré (chapitre 3) : il ne manque que le cœur du réseau d’entreprise. Installer AD DS se fait en deux temps — le rôle, puis la promotion en contrôleur de domaine — et demande cinq informations exactes. Ce chapitre suit l’assistant pas à pas, puis rejoue l’installation en PowerShell.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. installer le rôle AD DS et ses fonctionnalités associées ;
  2. promouvoir le serveur en contrôleur de domaine (nouvelle forêt) ;
  3. fixer nom DNS, nom NetBIOS, niveaux fonctionnels et mot de passe de restauration ;
  4. situer les dossiers de la base (NTDS.DIT), des journaux et de SYSVOL.

1. Installer le rôle AD DS

Pour ajouter le rôle : Gestionnaire de serveur → Gérer → Ajouter des rôles et des fonctionnalités. On choisit « Installation basée sur un rôle ou une fonctionnalité » (un nouveau rôle, pas une fonctionnalité complémentaire), puis le serveur cible — ici le seul serveur du TP.

Pour un réseau d’entreprise simple, on sélectionne uniquement Services AD DS (AD DS). Quand la case est cochée, des fonctionnalités complémentaires sont automatiquement sélectionnées : il est impératif de les avoir toutes pour gérer efficacement le serveur AD.

À la fin de l’installation initiale, les binaires AD DS sont installés — mais AD DS n’est pas encore configuré. Un message du Gestionnaire de serveur propose le lien « Promouvoir ce serveur en contrôleur de domaine » : c’est l’assistant de configuration, passage obligatoire.

Piège — s’arrêter après l’installation du rôle

Installer les binaires ne configure rien : sans la promotion, il n’y a ni domaine ni contrôleur. Le bandeau jaune du Gestionnaire de serveur le rappelle tant que la configuration est incomplète.

2. Les informations à réunir avant la configuration

Il existe différents types de configuration selon le besoin de l’entreprise. Avant d’exécuter la configuration de l’AD DS, vous devez disposer de :

  • le nom DNS pour le domaine AD DS ;
  • le nom NetBIOS ;
  • le fait que le contrôleur de domaine doit (ou non) prendre en charge les versions antérieures ;
  • le fait que le contrôleur de domaine sera également DNS ;
  • l’emplacement de la base de données NTDS.DIT et de SYSVOL (+ le mot de passe de restauration).
Cinq questions avant de cliquer

Nom DNS du domaine ? Nom NetBIOS (préfixe du domaine) ? Compatibilité ancienne ? DNS sur le même serveur ? Où stocker la base ? Cinq réponses écrites à l’avance = une installation sans retour en arrière.

3. Ajouter une nouvelle forêt

La procédure actuelle étant la création d’un nouveau domaine, on sélectionne « Ajouter une nouvelle forêt » et on entre le nom du domaine — un nom réel et réfléchi (chapitre 4).

Le niveau fonctionnel d’un domaine correspond aux services disponibles pour ce domaine : plus il est élevé, plus les fonctionnalités sont nombreuses. Le support conseille d’utiliser le niveau le plus haut — Windows Server 2012 R2.

Seconde étape obligatoire : le mot de passe de restauration (DSRM). Il sera utilisé uniquement si l’AD DS se retrouve corrompu et inaccessible : c’est le sésame de la restauration. Il doit donc être solide et… mémorisé.

Un message d’avertissement apparaît ensuite : le rôle AD DS nécessite le rôle DNS. Si vous installez le DNS en même temps que l’AD DS (ou sans configuration spécifique), la configuration se fera quasi-automatiquement ; sinon (serveur DNS séparé, par exemple Linux), vous devrez créer les zones DNS vous-même.

Pourquoi DNS est inseparable d’AD

Les clients localisent le domaine par son nom DNS : sans zone DNS correcte, personne ne trouve le contrôleur de domaine. C’est pourquoi l’assistant propose de l’installer en même temps.

4. Emplacements des données et vérification

L’étape « emplacement des données » propose trois dossiers :

  • Base de données : tous les fichiers du fonctionnement interne de l’Active Directory — fichiers temporaires, fichiers d’échanges, la base NTDS.DIT ;
  • Fichiers journaux : les logs, lus par l’Observateur d’événements ;
  • SYSVOL : les scripts de connexion des utilisateurs, les GPO (stratégies de groupe) et les fichiers nécessaires à la réplication AD et aux partages publics.

Par défaut ces dossiers vivent sous C:\Windows ; on peut les déplacer — simple question d’organisation interne. Un récapitulatif complet s’affiche, puis vient la vérification : Windows Server dit si les paramètres sont corrects pour un domaine AD. Quand tous les prérequis sont validés, le serveur doit être obligatoirement redémarré.

En PowerShell, le même résultat : récupérer le nom du serveur, installer le rôle (Install-WindowsFeature), puis configurer la nouvelle forêt avec Install-ADDSForest — nom de domaine, niveaux fonctionnels et options incluant la création du DNS.

Trois dossiers à retenir

NTDS.DIT = la base AD. Journaux = les logs. SYSVOL = scripts de connexion, GPO, réplication. Une question d’examen classique : « où sont stockés les GPO ? » → SYSVOL.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Le chemin d’un contrôleur de domaine

Bash Niveau 1 — Acquisition

Objectif : Rattacher chaque jalon à sa phase : installation, configuration, vérification.

Le script lit n lignes « jalon phase » : phase est un code parmi installation, configuration, verification ou finalisation. Jalons du support : rôle AD DS et fonctionnalités ajoutés → installation ; promotion en contrôleur de domaine (nouvelle forêt, niveaux, mots de passe) → configuration ; vérification des prérequis → verification ; redémarrage obligatoire du serveur → finalisation. Pour chaque ligne il affiche jalon : OK ou jalon : ERREUR, puis correctes : X/n.

Entrée du programme
3
role installation
promotion configuration
redemarrage finalisation
Sortie attendue
role : OK
promotion : OK
redemarrage : OK
correctes : 3/3
Deux indices, rédigés en mots
  1. Un case sur le jalon : role → installation, promotion → configuration, prerequis → verification, redemarrage → finalisation.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Les informations à réunir avant la configuration

Bash Niveau 2 — Application

Objectif : Distinguer les informations requises de celles qu’on ignore.

Avant de configurer AD DS, le support exige : le nom DNS du domaine, le nom NetBIOS, le niveau fonctionnel, le fait que le contrôleur sera aussi DNS, et l’emplacement de la base NTDS.DIT et de SYSVOL (+ le mot de passe de restauration). Le script lit n lignes « info statut » où statut vaut fourni ou manquant. Pour chaque info requise manquante il affiche info : bloquante, pour chaque info requise fournie info : prete, et pour toute autre ligne info : ignoree — puis bloquantes : X et, si X vaut 0, configuration possible.

Entrée du programme
4
dns fourni
netbios manquant
fondEcran fourni
ntds fourni
Sortie attendue
dns : prete
netbios : bloquante
fondEcran : ignoree
ntds : prete
bloquantes : 1
Deux indices, rédigés en mots
  1. Infos requises : dns, netbios, niveau, dnsrole, ntds, sysvol, restauration — tout le reste est ignoré.
  2. Requise + manquante → bloquante (compteur) ; requise + fournie → prete ; verdict final si 0 bloquante.

Exercice 3 — Niveau fonctionnel et mot de passe de restauration

Bash Niveau 3 — Raisonnement

Objectif : Contrôler le niveau fonctionnel choisi et la robustesse du mot de passe DSRM.

Le support conseille « le niveau fonctionnel le plus haut » (2012 R2) et un mot de passe de restauration solide, utilisé seulement si l’AD DS devient inaccessible. Le script lit n lignes « domaine niveau longueur » : niveau est le niveau fonctionnel choisi, longueur la taille du mot de passe de restauration. Le domaine est conforme si le niveau vaut 2012R2 ET la longueur est au moins 12. Pour chaque ligne il affiche domaine : conforme ou domaine : a revoir (motif) avec motif = niveau, mdp ou les-deux (dans cet ordre de priorité), puis conformes : X/n.

Entrée du programme
3
cdp.org 2012R2 16
filiere 2008 20
stage 2012R2 8
Sortie attendue
cdp.org : conforme
filiere : a revoir (niveau)
stage : a revoir (mdp)
conformes : 1/3
Deux indices, rédigés en mots
  1. Niveau d’abord : niveau != 2012R2 → a revoir (niveau) ou (les-deux) selon la longueur.
  2. Puis longueur : longueur -lt 12 → a revoir (mdp) ; sinon conforme, compteur incrémenté.

6. QCM — niveau examen

Après l’installation initiale du rôle AD DS…

AD DS n’est pas encore configuré : il faut promouvoir le serveur en contrôleur de domaine.

Pour créer un domaine racine, l’assistant propose…

La création d’un nouveau domaine racine passe par « Ajouter une nouvelle forêt ».

Le niveau fonctionnel du domaine définit…

Plus le niveau est élevé, plus les fonctionnalités sont nombreuses : viser 2012 R2.

Le mot de passe de restauration sert…

DSRM : utilisé uniquement si l’AD devient inaccessible — d’où sa solidité.

L’avertissement à l’installation d’AD DS concerne…

AD DS nécessite un serveur DNS ; installé en même temps, il se configure quasi-automatiquement.

La base de l’Active Directory s’appelle…

NTDS.DIT dans le dossier « base de données » ; SYSVOL porte scripts et GPO.

Le dossier SYSVOL contient…

Les fichiers journaux sont dans le second dossier ; SYSVOL est le dossier des stratégies.

Quand la vérification des prérequis est passée…

Le redémarrage est obligatoire pour finaliser la promotion.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • S’arrêter après l’installation du rôle : sans promotion, pas de contrôleur de domaine.
  • Saisir un nom de domaine irréel : son renommage ultérieur est très coûteux (chapitre 4).
  • Bâcler le mot de passe de restauration : c’est la seule clé de secours d’un AD inaccessible.
  • Oublier le redémarrage final : la promotion ne s’achève pas sans lui.

8. Méthodologie de résolution

Installer AD DS sans faux pas
  1. Écrire les cinq informations avant l’assistant : DNS, NetBIOS, anciennes versions, DNS local, emplacements.
  2. Suivre l’ordre : rôle → promotion (nouvelle forêt) → niveaux → DSRM → DNS → dossiers.
  3. Lire le récapitulatif, attendre la vérification des prérequis, redémarrer, puis vérifier le domaine.

9. Révision active

Résumé essentiel
  • Deux temps : installer le rôle AD DS, puis promouvoir le serveur en contrôleur de domaine.
  • « Ajouter une nouvelle forêt » crée le domaine racine ; le nom doit être réel et réfléchi.
  • Niveau fonctionnel le plus haut conseillé (2012 R2) ; mot de passe DSRM solide obligatoire.
  • AD DS exige le DNS ; la base NTDS.DIT, les journaux et SYSVOL ont chacun leur dossier ; redémarrage final.

Checklist de maîtrise

  • Je sais dérouler l’assistant de bout en bout dans l’ordre.
  • Je liste les cinq informations à préparer sans regarder le cours.
  • Je distingue NTDS.DIT, journaux et SYSVOL.
  • Je connais l’équivalent PowerShell (Install-WindowsFeature, Install-ADDSForest).
