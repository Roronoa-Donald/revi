Chapitre 6 — Gérer les objets AD DS

Module 6 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le domaine existe : il est vide. Maintenant il faut le peupler — des unités d’organisation pour ranger, des utilisateurs pour se connecter, des groupes pour distribuer les droits. Ce chapitre suit la console « Utilisateurs et ordinateurs Active Directory » du support, avec les exemples réels (unité TRI, utilisateur iziti), jusqu’à la jointure du poste client au domaine.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. peupler l’Active Directory depuis la console Utilisateurs et ordinateurs ;
  2. créer des unités d’organisation et y créer des utilisateurs ;
  3. paramétrer un compte : UPN, changement de mot de passe, horaires, propriétés ;
  4. créer des groupes (sécurité ou distribution) et joindre un poste au domaine.

1. La console et les unités d’organisation

Pour peupler l’Active Directory, on lance la console Utilisateurs et ordinateurs Active Directory. La première brique est l’unité d’organisation (UO) : un conteneur qui range les objets par service, par site ou par projet — comme l’unité « TRI » du support, dans laquelle on crée ensuite l’utilisateur.

Créer une UO : clic droit sur le domaine ou sur une UO existante → Nouveau → Unité d’organisation. Bien pensée, la structure d’UO rend visibles les règles d’administration : une UO par service, des sous-UO pour les postes, les groupes, les comptes de service.

Piège — tout mettre à la racine

Un domaine sans UO devient un tiroir géant : impossible d’appliquer des stratégies fines ni de s’y retrouver. L’UO est le premier geste d’administration, pas une option décorative.

2. Créer et paramétrer des utilisateurs

Pour créer un utilisateur dans l’unité « TRI » : clic droit sur l’unité → Nouveau → Utilisateur. On remplit le formulaire (nom, prénom, nom d’ouverture de session), puis le mot de passe et ses options.

Deux moyens d’ouvrir une session (chapitre 2) : le UPN, forme d’adresse e-mail — iziti@ntic.ma — et la forme DOMAINE\login. L’option « l’utilisateur doit changer le mot de passe à la prochaine ouverture de session » force ce changement à la première connexion : réflexe de sécurité pour tout compte neuf.

Les propriétés de l’utilisateur (clic droit → Propriétés) offrent bien plus : dans l’onglet Compte se trouvent la partie liée à l’ouverture de session et les horaires d’accès (restriction des horaires de connexion). Le tout existe aussi en PowerShell (New-ADUser, Set-ADUser, Get-ADUser) — chaque geste de la console a son équivalent de commande.

Le cycle d’un compte neuf

Créer (formulaire) → mot de passe + « doit changer » → propriétés (horaires, compte) → test de connexion. Quatre gestes, dans cet ordre, pour chaque utilisateur.

3. Les groupes : droits, types et étendues

Les groupes sont créés pour donner des droits sur des fichiers, imprimantes, bases de données, etc. Il existe deux types de groupes : les groupes de sécurité, qui reçoivent des droits, et les groupes de distribution, utiles seulement à la diffusion (listes de diffusion).

Créer un groupe : sélectionner l’unité, clic droit → Nouveau → Groupe, choisir le type et l’étendue. Dans le cas d’un groupe d’utilisateurs du support, on choisit l’étendue Globale — le choix courant pour regrouper des utilisateurs du même domaine.

Droits aux groupes, pas aux utilisateurs

On donne le droit au groupe et on ajoute l’utilisateur au groupe : c’est la règle d’or. Les comptes restent propres, les droits se retirent en une suppression de membre, et l’audit se lit sur les groupes.

4. Joindre un poste au domaine et profils itinérants

Pour joindre un poste client au domaine, on commence par s’assurer que le client reçoit en serveur DNS celui du domaine Active Directory — sans DNS, personne ne trouve le contrôleur. Puis on change l’appartenance de la machine (Système → Modifier les paramètres → Domaine) avec un compte autorisé, et on redémarre : la connexion se fait alors en DOMAINE\login ou en UPN.

Le support présente enfin les profils itinérants : synchroniser le profil d’un utilisateur sur le serveur pour rendre ses données accessibles depuis n’importe quel poste du domaine. Un profil itinérant bien configuré suit l’utilisateur de machine en machine.

Le PowerShell d’AD en un clin d’œil

Le support illustre chaque geste de la console par sa commande : New-ADUser pour créer, Get-ADUser pour afficher les propriétés, les cmdlets groupes pour l’appartenance. Réfléchir console + PowerShell, toujours.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Les classes d’objets AD DS

Bash Niveau 1 — Acquisition

Objectif : Classer chaque objet dans sa classe : utilisateur, ordinateur, groupe, contrôleur.

Le script lit n lignes « objet classe » : classe est un code parmi utilisateur, ordinateur, groupe ou controleur. Objets du support : iziti, ilham → utilisateur ; poste-compta, portable-dir → ordinateur ; grp-ventes, grp-info → groupe ; SRV-DC1, SRV-DC2 → controleur. Pour chaque ligne il affiche objet : OK ou objet : ERREUR, puis correctes : X/n.

Entrée du programme
3
iziti utilisateur
poste-compta ordinateur
grp-ventes groupe
Sortie attendue
iziti : OK
poste-compta : OK
grp-ventes : OK
correctes : 3/3
Deux indices, rédigés en mots
  1. Un case sur l’objet : iziti/ilham → utilisateur, poste/portable → ordinateur, grp → groupe, SRV-DC → controleur.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Créer les utilisateurs : UPN et options de compte

Bash Niveau 2 — Application

Objectif : Valider l’UPN de chaque utilisateur et signaler l’option de mot de passe.

Le support crée les utilisateurs dans l’unité puis distingue les deux formes de session : UPN (forme adresse e-mail, contient une arobase) et DOMAINE\login. Le script lit n lignes « utilisateur upn changement » : upn est l’identifiant saisi, changement vaut oui (doit changer son mot de passe à la prochaine ouverture) ou non. Pour chaque utilisateur il affiche utilisateur : upn-valide si l’UPN contient une arobase, sinon utilisateur : forme-domaine ; et il note utilisateur : init-mdp en plus si changement vaut oui. Enfin upn : X/n et a-initialiser : Y.

Entrée du programme
3
iziti iziti@ntic.ma oui
ilham NTIC\\ilham non
demo demo@ntic.ma non
Sortie attendue
iziti : upn-valide
iziti : init-mdp
ilham : forme-domaine
demo : upn-valide
upn : 2/3
a-initialiser : 1
Deux indices, rédigés en mots
  1. L’arobase dans une variable : case "$identifiant" in *@*) forme UPN ;; *) forme domaine ;;
  2. changement = oui → ligne init-mdp en plus et compteur ; les deux bilans après la boucle.

Exercice 3 — Groupes : droits, type et étendue

Bash Niveau 3 — Raisonnement

Objectif : Décider quels groupes peuvent recevoir des droits et compter les jointures au domaine.

Le script lit d’abord g lignes « groupe type etendue » : type vaut securite (peut recevoir des droits sur fichiers, imprimantes, bases) ou distribution (diffusion seulement) ; etendue vaut globale, locale ou universelle. Puis il lit n lignes « poste dns » pour les jointures au domaine : un poste rejoint le domaine si son serveur DNS est celui du domaine (ad-dns). Il affiche pour chaque groupe groupe : droits ou groupe : diffusion, pour chaque poste poste : joint ou poste : dns a corriger, puis groupes-droits : X et jointures : Y/n.

Entrée du programme
2
grp-ventes securite globale
liste-clients distribution globale
2
pc1 ad-dns
pc2 8.8.8.8
Sortie attendue
grp-ventes : droits
liste-clients : diffusion
pc1 : joint
pc2 : dns a corriger
groupes-droits : 1
jointures : 1/2
Deux indices, rédigés en mots
  1. type = securite → « droits » et compteur ; distribution → « diffusion ».
  2. dns = ad-dns → « joint » et compteur ; sinon « dns a corriger » ; bilans après les deux boucles.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Créer les utilisateurs avant les UO : rien pour les ranger, structure à refaire.
  • Donner des droits à des utilisateurs isolés : passer par des groupes de sécurité.
  • Confondre groupe de sécurité (droits) et groupe de distribution (diffusion).
  • Joindre un poste au domaine sans corriger son DNS : le domaine reste introuvable.

8. Méthodologie de résolution

Peupler un domaine proprement
  1. Dessiner les UO (services, sites), puis créer les groupes de sécurité.
  2. Créer les comptes : UPN propre, « doit changer » activé, horaires si besoin.
  3. Joindre les postes : DNS d’abord, appartenance au domaine ensuite, test de connexion enfin.

9. Révision active

Résumé essentiel
  • La console Utilisateurs et ordinateurs AD peuple le domaine : UO d’abord.
  • Utilisateur = formulaire + UPN (iziti@ntic.ma) + « doit changer » + propriétés (horaires).
  • Groupes de sécurité pour les droits, de distribution pour la diffusion ; étendue Globale courante.
  • Jointure au domaine : DNS du client vers le domaine, puis changement d’appartenance ; profils itinérants pour suivre les utilisateurs.

Checklist de maîtrise

  • Je crée UO, utilisateur et groupe dans le bon ordre.
  • Je distingue les deux formes de session et l’option de premier changement.
  • Je choisis le type de groupe selon le besoin (droits ou diffusion).
  • Je connais les prérequis de la jointure au domaine et le rôle des profils itinérants.
