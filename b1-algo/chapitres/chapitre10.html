Chapitre 10 — Du pseudo-code au programme

Module 10 ≈ 3 h de travail Synthèse B1
Mise en situation

Le jour de l'examen, l'énoncé donne un pseudo-code et demande : « que calcule-t-il ? », « corrigez l'erreur », ou « traduisez-le en Pascal ». Ce chapitre ferme la boucle : tout ce que vous avez appris — variables, conditions, boucles, tableaux, fonctions — sert désormais à lire, corriger et écrire des algorithmes complets.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. traduire fidèlement un pseudo-code en Pascal et en Python ;
  2. exécuter un algorithme à la main grâce à une table de trace ;
  3. débusquer une erreur de logique (condition, seuil, ordre des tests) ;
  4. assembler un programme complet à partir de fonctions simples.

1. Traduire un pseudo-code

Définition. Le pseudo-code décrit l'algorithme sans syntaxe de langage. Le traduire est une opération mécanique si l'on connaît la table d'équivalence des structures — c'est la même pour tous les exercices.

La traduction est fidèle parce que chaque ligne du pseudo-code devient une ligne du programme, dans le même ordre, avec les mêmes variables. Résister à l'envie de « réécrire plus malin » : l'examen note la fidélité.

Intuition

Le pseudo-code est un plan d'architecte, le programme est la maison. On ne modifie pas le plan en construisant : chaque mur a sa place. Si vous pouvez nommer la structure (séquence, Si, TantQue, Pour) à chaque ligne, la traduction se fait toute seule.

2. Exécuter un algorithme à la main : la table de trace

Définition. Une table de trace note, après chaque instruction, la valeur de toutes les variables et éventuellement l'affichage. C'est l'unique méthode fiable pour répondre à « que vaut S à la fin ? ».

Pour le pseudo-code ci-dessus avec n = 6 :

Touri (au début)i mod 2 = 0 ?S aprèsi après
11non02
22oui23
33non24
44oui65
55non66
66oui127

i vaut 7 à la sortie : la condition i ≤ n devient fausse et le programme affiche 12. Une colonne oubliée (l'état du compteur, par exemple) fausse toute la trace.

La règle des trois points

Chaque boucle TantQue doit garantir : une initialisation avant la boucle, une progression vers l'arrêt dans le corps, une condition qui finit par être fausse. À la relecture d'un pseudo-code, vérifie les trois points avant de chercher plus loin : la plupart des erreurs sont là.

3. Corriger un algorithme existant

Les erreurs de logique les plus fréquentes ont des visages connus :

ErreurSymptômeRemède
Ordre des tests d'une cascadeLe cas général attrape toutTester du plus exigeant au plus général
Borne d'inégalitéUn cas limite décalé de 1Relire « au-delà de » et « à partir de » ; tester la borne
Initialisation dans la boucleAccumulateur remis à zéro à chaque tourDéplacer l'initialisation avant la boucle
Progression oubliéeBoucle infinieRègle des trois points
Échange sans temporaireUne valeur écrasée avant d'être déplacéeCase temporaire ou affectation simultanée

Exemple : une facturation avec remise dégressive où la remise de 10 % s'applique toujours. Le symptôme se voit sur le premier cas de l'énoncé (petite quantité : le prix baisse quand il ne devrait pas). Le remède : une cascade ordonnée, seuil élevé d'abord.

if quantite > 50:
    total = total - (total * 10) // 100
elif quantite > 10:
    total = total - (total * 5) // 100
# sinon : aucune remise
Piège — corriger sans d'abord observer

Ne « répare » jamais un algorithme à l'aveugle. D'abord la table de trace sur un cas où le résultat attendu est connu ; ensuite, comparer valeur attendue et valeur calculée à chaque ligne pour localiser la première divergence. C'est elle qui désigne l'erreur, pas l'intuition.

4. Assembler un programme complet

Un problème d'examen type combine tout : lecture, calcul par fonctions, affichage. La file d'attente en est l'archétype : n personnes arrivent avec des durées de traitement ; chaque personne attend la somme des durées des précédentes.

def attente_totale(durees):
    total = 0
    ecoule = 0
    for duree in durees:
        total += ecoule        # ce qui s'est passe avant moi
        ecoule += duree        # puis je passe, ma duree s'ecoule
    return total

def temps_moyen(durees):
    if not durees:
        return 0.0
    return attente_totale(durees) / len(durees)

Pour les durées 5, 10, 2 : les attentes valent 0, 5 et 15, soit un total de 20 et une moyenne de 6,67 minutes. Le programme principal se réduit à la lecture, deux appels et deux affichages — c'est le signe d'un bon découpage.

Mnémotechnique

« Lire, calculer, afficher » : trois responsabilités, jamais mélangées. La lecture et l'affichage restent dans le programme principal ; chaque calcul devient une fonction qui reçoit ses données en paramètres et renvoie son résultat.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Objectif : Débusquer une erreur de logique dans un algorithme existant.

Cet algorithme est censé calculer le montant d’une facture avec remise dégressive (5 % au-delà de 10 articles, 10 % au-delà de 50), mais il applique toujours la même remise. Corrigez la logique. Le programme reçoit le prix unitaire (entier) et la quantité ; affichez le total final (entier, après remise entière).

Deux indices, rédigés en mots

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Traduction « améliorée » : remplacer le TantQue par autre chose alors que la fidélité est notée.
  • Table de trace incomplète : une variable oubliée fausse le résultat final.
  • Cascade mal ordonnée : le seuil bas attrape tous les cas.
  • Borne exclusive : confondre « jusqu'à n » (inclus) et « strictement avant n ».
  • Compteur incrémenté avant le calcul : le premier tour travaille sur la mauvaise valeur.

8. Méthodologie de résolution

Face à un pseudo-code inconnu
  1. Identifier les variables et ce que chacune représente.
  2. Repérer les structures : surligner chaque Si, Pour, TantQue et son corps.
  3. Choisir un petit cas d'entrée (n = 3 ou 4) et dresser la table de trace complète.
  4. Nommer le résultat : savoir ce que calcule l'algorithme avant de le modifier.
  5. Corriger ou traduire structure par structure, puis retracer pour confirmer.

9. Révision active

Résumé essentiel
  • Traduction fidèle : mêmes structures, même ordre, mêmes variables.
  • Table de trace : toutes les variables, tour par tour, affichage compris.
  • La première divergence entre attendu et calculé désigne l'erreur.
  • Cascades de seuils : du plus exigeant au plus général.
  • Programme complet : lire, calculer (fonctions), afficher.

Checklist de maîtrise

  • Je traduis un pseudo-code en Pascal et en Python sans changer sa logique.
  • Je dresse une table de trace complète sur un petit cas.
  • Je localise une erreur de logique par divergence, pas par intuition.
  • Je découpe un problème complet en fonctions à responsabilité unique.
