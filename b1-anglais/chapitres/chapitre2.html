Chapitre 2 — Professional email writing

Module 2 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Zoe écrit « hey guys, the server thing is late lol. thx. » — et toute l'équipe reçoit son « reply all » courroucé. Clients et managers jugent par les emails : un mauvais email, c'est de la confusion, des retards, un chef en colère. Le chapitre structure l'email professionnel de la ligne d'objet à la signature.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. identifier les cinq composantes d'un email professionnel ;
  2. écrire une ligne d'objet informative (subject line make or break) ;
  3. appliquer la méthode CLEAR au corps du message ;
  4. adapter le ton au destinataire et éviter les erreurs classiques.

1. Les cinq parties et la ligne d'objet

Un email professionnel se compose de cinq parties : subject line, salutation (greeting), body, closing, signature. La subject line est make or break : « Hello », « Problem » ou un objet vide ruinent le message. Le format gagnant : Q3 Budget Update – Action Needed by Friday — sujet + action + échéance.

La salutation dépend du destinataire : formel (nouveau client, direction) → Dear Mr. Smith, ; semi-formel (collègue, client régulier) → Hello Sarah, / Hi John, ; jamais Hey dude, ni Yo,. Le closing suit la même logique : Best regards, (standard), Kind regards, (amical), Sincerely, (formel), jamais « Cheers, » ni « XOXO ».

La signature est votre carte de visite numérique : nom, job title, company, téléphone en option — jamais de citations, d'emojis ni d'images géantes.

Mnémotechnique — « S-S-B-C-S : de l'objet à la signature »

Subject, Salutation, Body, Closing, Signature : cinq cases, dans cet ordre. Un email qui saute une case se lit comme un formulaire incomplet.

2. La méthode CLEAR et les catastrophes

Le corps du message suit la méthode CLEAR : Context (why are you writing ?), Logistics (what, when, where ?), Expectation (what do you need ?), Action (what should they do ?), Respect (thank you). L'email modèle du support — budget approval for a server upgrade — coche les cinq lettres dans l'ordre.

Le ton s'adapte : au patron « Could you please review the attached report ? » ; au collègue « Can you check the attachment ? » ; au client « I would appreciate it if you could… ». Les réductions (gonna, gotta) restent dehors.

Les trois disaster emails du support : l'objet vide (« Hey, there's a problem. Call me. » → réécriture : « Server Issue – Please Call When Available ») ; le reply all à 200 personnes (« Reply all is a weapon. Use carefully. ») ; l'email trop casual (« Yo team, gonna need that thing by tomorrow. k thx. » → « Dear team, the deadline for the report is tomorrow. Thank you for your efforts. »).

Confusions d'examen
  • Objet vide ou « Hello » : le destinataire ne sait ni quoi, ni quand, ni pourquoi.
  • Reply all en colère : le destinataire humilie 200 collègues d'un coup — arme, pas outil.
  • Confondre Expectation (ce que j'attends) et Action (ce que le lecteur doit faire) : l'un énonce, l'autre ordonne poliment.
  • Emojis et citations dans la signature : jamais dans un cadre professionnel.

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — The CLEAR method

Bash Niveau 1 — Acquisition

Objectif : Classer les phrases d'un email selon la méthode CLEAR : Context, Logistics, Expectation, Action, Respect.

Le script lit n lignes « phrase partie » : partie vaut C, L, E, A ou R. Pour chaque ligne il affiche phrase : nom_complet, où nom_complet vaut context, logistics, expectation, action ou respect. Il termine par emails complets : ok si les cinq parties sont présentes au moins une fois, emails complets : manquant sinon.

Entrée du programme
5
p1 C
p2 L
p3 E
p4 A
p5 R
Sortie attendue
p1 : context
p2 : logistics
p3 : expectation
p4 : action
p5 : respect
emails complets : ok
Deux indices, rédigés en mots
  1. Un case traduit la lettre en nom complet ; un tableau vues[partie]=1 marque le passage.
  2. Le verdict final vérifie les cinq clés : C, L, E, A, R.

Exercice 2 — Formal or semi-formal

Bash Niveau 2 — Application

Objectif : Choisir le ton de l'email selon le destinataire : formel (nouveau client, direction), semi-formel (collègue), jamais familier.

Le script lit n lignes « destinataire audience » : audience vaut formal (nouveau client, direction), semi (collègue, client régulier) ou casual (jamais en entreprise). Pour chaque ligne il affiche destinataire : salutation, où salutation vaut Dear Mr Smith (formal), Hello Sarah (semi) ou jamais en entreprise (casual). Il termine par emails formels : X/n.

Entrée du programme
3
CEO formal
Sarah semi
Mike casual
Sortie attendue
CEO : Dear Mr Smith
Sarah : Hello Sarah
Mike : jamais en entreprise
emails formels : 1/3
Deux indices, rédigés en mots
  1. Un case à trois audiences, trois salutations.
  2. Comptez seulement les salutations formelles.

Exercice 3 — The reply all disaster

Bash Niveau 3 — Raisonnement

Objectif : Simuler la catastrophe du Reply All : suivre les destinataires, éviter la tempête d'emails.

Le script lit n lignes « action boite » : action vaut envoi (nouvel email à la boite), replyall (réponse à tous) ou desabonne (retirer la boite de la liste). La liste commence avec 0 boites ; chaque envoi ou replyall ajoute toutes les boites manquantes présentes sur la ligne (une seule boite par ligne). Les réponses à tous multiplient le trafic : chaque replyall sur une liste de X boites produit X messages. Affichage ligne par ligne : action boite : trafic total T. Final : boites : X et trafic total : T.

Entrée du programme
4
envoi a
envoi b
replyall a
desabonne b
Sortie attendue
envoi a : trafic total 1
envoi b : trafic total 2
replyall a : trafic total 4
desabonne b : trafic total 4
boites : 1
trafic total : 4
Deux indices, rédigés en mots
  1. liste[boite]=1 marque la présence ; un envoi sur une boite absente l'ajoute (trafic +1) ; sur une boite présente, rien.
  2. Un replyall sur une boite déjà présente éclate : trafic += nombre de boites dans la liste.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Envoyer un email sans subject line : il est ignoré, ou pire, lu comme du spam.
  • Répondre à tous en colère : la « reply all disaster » du support est un cas réel.
  • Mettre des réductions (gonna, k thx) dans un email formel.
  • Oublier la partie Action : le lecteur ne sait pas quoi faire.

6. Méthodologie de résolution

Méthode — rédiger un email en cinq gestes
  1. Objet informatif : sujet + action + échéance.
  2. Salutation adaptée : Dear (formel), Hello/Hi (semi-formel), jamais Yo.
  3. Corps CLEAR : Context, Logistics, Expectation, Action, Respect.
  4. Closing et signature sobres : Best regards, puis nom et titre.

7. Révision active

Résumé essentiel
  • Cinq parties : subject line, salutation, body, closing, signature.
  • Subject line make or break : sujet + action + échéance.
  • Méthode CLEAR : Context, Logistics, Expectation, Action, Respect.
  • Ton : formal (Dear), semi-formal (Hello), jamais casual en entreprise.

Checklist de maîtrise

  • Je sais étiqueter les cinq parties d'un email donné.
  • Je sais réécrire trois mauvais subject lines.
  • Je sais placer les cinq lettres CLEAR sur un email modèle.
  • Je sais corriger un disaster email (objet, ton, signature).

Les 8 notions à connaître absolument

  1. Subject line : objet informatif, make or break.
  2. Salutation : Dear (formel) / Hello (semi-formel).
  3. CLEAR : Context, Logistics, Expectation, Action, Respect.
  4. Closing : Best regards, Kind regards, Sincerely.
  5. Signature : nom, titre, société — sobre.
  6. Formal vs semi-formal : selon le destinataire.
  7. Reply all : réponse à tous, à manier avec précaution.
  8. Disaster email : objet vide, ton casual, réponse massive.

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — reprends les cinq parties et la méthode CLEAR.
