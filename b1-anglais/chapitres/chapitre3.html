Chapitre 3 — Oral presentations in a business context

Module 3 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Leo doit présenter la mise à jour du serveur à M. Tanaka en cinq minutes. Il commence par « So, like, basically, the thing is, um… » — et perd son auditoire. Le chapitre donne la structure « tell them, tell them, tell them », les transitions, et la règle d'or : si votre grand-mère ne comprend pas, simplifiez.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. structurer une présentation de 2 à 3 minutes : opening, body, closing ;
  2. commencer par un hook et annoncer une roadmap ;
  3. expliquer un problème technique à un public non technique (Grandma Rule) ;
  4. utiliser les phrases de transition et répondre poliment aux questions.

1. La structure en trois parties

La règle du support : « Tell them, tell them, tell them ». Opening (30 s) : dire ce qu'on va dire — un hook (question, fait, histoire courte : « Have you ever lost an hour of work because of a crash ? ») suivi d'une roadmap (« Today I'll explain the problem, the solution, and the result »). Body (1,5 à 2 min) : le dire. Closing (30 s) : dire ce qu'on a dit — résumé + call to action (« To sum up, we had a crash, we fixed it, and now everything works. Please restart your computers tonight. »).

Jamais finir sur « That's it », « I'm done », « Yeah… » : le closing est un résumé + un appel à l'action précis.

Les transitions structurent le body : démarrer « First… », « To begin with… » ; avancer « Next… », « Now let's look at… » ; conclure « Finally… », « In conclusion… », « To summarize… ». Elles guident l'auditeur et masquent l'hésitation — exit les « um » et « like ».

Mnémotechnique — « 30 s / 2 min / 30 s »

Opening 30 secondes (hook + roadmap), body 1,5 à 2 minutes (transitions), closing 30 secondes (summarize + call to action). Trois tempos, un seul message.

2. La Grandma Rule et les questions

Expliquer la technique aux non-techniciens : the Grandma Rule — « if your grandma can't understand it, simplify it ». Le support démonte « The API endpoint returned a 500 error due to a null pointer exception » en « The server stopped talking to our app », puis de plus en plus simple, jusqu'au niveau grand-mère : « The computer system got confused and couldn't finish the job ».

Le traducteur du support : deployment → software release ; failed → did not work ; CI/CD pipeline → automatic delivery system ; configuration mismatch → settings problem. Les clients ne se soucient pas du code : ils se soucient des solutions.

Les questions se traitent avec politesse et assurance : « That's a good question », « Let me clarify », puis une réponse courte. Le contact visuel et le langage du corps complètent : ne pas lire ses notes, regarder la salle.

Confusions d'examen
  • Ouvrir sans hook : l'auditeur décroche avant la première transition.
  • Terminer sur « I'm done » : le closing demande résumé + call to action.
  • Garder le jargon devant un client : CI/CD, null pointer — traduire en mots simples.
  • Répondre « je ne sais pas » sec : « Let me check and get back to you » est la forme polie.

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — The three-part structure

Bash Niveau 1 — Acquisition

Objectif : Vérifier la structure Opening / Body / Closing d'une présentation : dire, dire, dire.

Le script lit n lignes « minute partie » : partie vaut open (0-30 s), body (1,5-2 min) ou close (30 s). La présentation est valide si les parties arrivent dans l'ordre open, puis body, puis close (body peut apparaître plusieurs fois). Pour chaque ligne il affiche partie : ok ou partie : hors structure. Final : presentation : valide ou presentation : a revoir.

Entrée du programme
4
1 open
2 body
3 body
4 close
Sortie attendue
open : ok
body : ok
body : ok
close : ok
presentation : valide
Deux indices, rédigés en mots
  1. Trois étapes numérotées : open avance à 1, body avance à 2 (ou reste 2), close avance à 3.
  2. Un drapeau rompu : toute sortie d'ordre casse la présentation pour la suite.

Exercice 2 — The Grandma Rule

Bash Niveau 2 — Application

Objectif : Simplifier le jargon technique pour un public non technique : compter les termes complexes restants.

Le script lit n lignes « mot famille » : famille vaut tech (jargon) ou simple. Chaque terme tech porte une pénalité de 2 points, chaque mot simple 0 point. Affichage ligne par ligne : mot : penalite P. Final : score clarte : S/10 où S = 10 − somme des pénalités (jamais en dessous de 0), et grandma : comprend si S ≥ 6, grandma : perdu sinon.

Entrée du programme
4
deployment tech
release simple
settings simple
failure tech
Sortie attendue
deployment : penalite 2
release : penalite 0
settings : penalite 0
failure : penalite 2
score clarte : 6/10
grandma : comprend
Deux indices, rédigés en mots
  1. tech = 2 points de pénalité, simple = 0 : un if suffit.
  2. Le score est borné : si 10 − pénalités est négatif, on affiche 0.

Exercice 3 — Transition phrases

Bash Niveau 3 — Raisonnement

Objectif : Compter les transitions et vérifier qu'aucune ne manque : First, Next, Then, Finally, To summarize.

Le script lit n lignes « position transition » : transition vaut first, next, then, finally ou summary. Pour chaque ligne il affiche position : transition. Final : une ligne par transition attendue, dans l'ordre First, Next, Then, Finally, Summary : Transition : presente ou Transition : absente. Puis transitions : X/5.

Entrée du programme
5
1 first
2 next
3 then
4 finally
5 summary
Sortie attendue
1 : first
2 : next
3 : then
4 : finally
5 : summary
First : presente
Next : presente
Then : presente
Finally : presente
Summary : presente
transitions : 5/5
Deux indices, rédigés en mots
  1. Un tableau vues[transition]=1 marque le passage ; la liste d'audit est fixe.
  2. L'audit parcourt les cinq transitions dans l'ordre demandé et compte les présentes.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Commencer par « So, like, basically, um » : le hook remplace les tics.
  • Finir sur « That's it » : résumé + call to action obligatoires.
  • Débit continu sans transitions : l'auditeur perd le fil.
  • Jargon devant un non-technicien : traduire ou perdre la salle.

6. Méthodologie de résolution

Méthode — bâtir une présentation en quatre gestes
  1. Écrire le hook : une question, un fait ou une histoire courte.
  2. Annoncer la roadmap : X, puis Y, enfin Z.
  3. Parser le body avec les transitions : First, Next, Finally.
  4. Fermer : To sum up + call to action précis.

7. Révision active

Résumé essentiel
  • Structure : opening (30 s), body (1,5-2 min), closing (30 s) — tell them, tell them, tell them.
  • Hook + roadmap à l'ouverture ; summarize + call to action au closing.
  • Grandma Rule : traduire le jargon (deployment → software release).
  • Transitions : First, Next, Finally ; questions traitées avec politesse.

Checklist de maîtrise

  • Je sais chronométrer les trois parties d'une présentation de 2 minutes.
  • Je sais écrire un hook et une roadmap sur un sujet IT.
  • Je sais traduire quatre termes techniques en mots simples.
  • Je sais répondre à trois questions avec les formules polies.

Les 8 notions à connaître absolument

  1. Opening : hook + roadmap, 30 secondes.
  2. Hook : question, fait ou histoire qui accroche.
  3. Roadmap : annonce du plan (X, Y, Z).
  4. Closing : summarize + call to action.
  5. Grandma Rule : simplifier pour le non-technicien.
  6. Transitions : First, Next, Finally, To summarize.
  7. Call to action : ce que l'auditeur doit faire ensuite.
  8. Q&A : That's a good question / Let me clarify.

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — reprends la structure en trois parties.
50–69 % — réécris trois phrases techniques en langage simple.
70–89 % — bon niveau, cible les transitions et le Q&A.
≥ 95 % — niveau de maîtrise recherché.
