Chapitre 5 — Register, reductions and fluency

Module 5 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

En pause café, « I'm gonna send that email » passe très bien. En présentation client, la même phrase coûte la crédibilité. Le registre n'est pas une règle scolaire : c'est un choix contextuel — et il s'entraîne comme la prononciation.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. remplacer les réductions familières par leur forme formelle en contexte professionnel ;
  2. choisir l'intonation montante ou descendante selon la phrase ;
  3. distinguer reductions acceptables (casual) et interdites (formal) ;
  4. suivre sa progression de fluidité semaine par semaine.

1. Reductions : quand, comment

Le support classe les reductions : gonna (going to), wanna (want to), gotta (got to). Elles sont ok en parole casual entre collègues : « I'm gonna send that email ». Elles sont interdites en contexte formel : devant un client, « We're going to deploy on Friday ».

Exercice de passage au formel : « I gotta go » → « I have to go » ; « Wanna meet ? » → « Would you like to meet ? » ; « Gonna start now » → « We are going to start now ». Le registre se corrige phrase par phrase, comme une faute de frappe.

Le lien avec le chapitre 2 : le registre de l'email (subject line, salutation, signature) et le registre oral suivent la même règle — le destinataire décide. Collègue de toujours : casual toléré. Client, direction, présentation : formel intégral.

Mnémotechnique — « casual chez soi, formel en clientèle »

Gonna/wanna/gotta vivent au café et meurent au boardroom. La question à se poser : « qui m'entend ? » — et le registre se choisit tout seul.

2. Intonation et suivi de fluidité

L'intonation se travaille par paires : « You're done ? ↗ » (surprise) contre « You're done. ↘ » (constat). Les listes descendent item par item et remontent à l'av dernier élément. Un mauvais patron d'intonation rend une phrase correcte incompréhensible.

La fluency vs perfection du support : « You don't need a perfect accent. You need to be understood. » Les natifs font des erreurs aussi ; l'objectif est l'intelligibilité, pas l'accent parfait. « You are already fluent enough. Today is about polishing, not perfection. »

Le suivi : enregistrer un message d'une minute chaque jour, s'écouter, compter les défauts (H perdus, pauses manquées, accent faux), puis comparer jour après jour. La fluidité est une habitude, pas une destination : le graphique des défauts qui baisse vaut mieux que l'auto-satisfaction.

Confusions d'examen
  • Gonna en présentation client : remplacez par going to, sans exception.
  • Intonation descendante sur une question oui/non : l'interlocuteur croit entendre une déclaration.
  • Chasser l'accent parfait : l'objectif est d'être compris, pas imité.
  • Corriger sans enregistrer : l'oreille se forme en s'écoutant, pas en lisant des règles.

3. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

En cas d’hésitation, le bouton Expliquer mon erreur sollicite le tuteur pédagogique pour vous guider dans l’application de la méthodologie sans donner directement la solution.

Exercice 1 — Gonna, wanna, gotta

Étude de cas Niveau 1 — Acquisition

Objectif : Remplacer les réductions familières par leur forme formelle, et compter les corrections.

Pour chaque situation proposée : registre vaut form (déjà formel) ou reduce (réduction familière). Pour chaque situation, indiquez mot : forme, où forme vaut formel (form) ou correction : going to (reduce). Concluez par corrections : X/n.

Cas d’exemple
4
form deploy
reduce gonna
form send
reduce wanna
Résolution attendue
deploy : formel
gonna : correction : going to
send : formel
wanna : correction : want to
corrections : 2/4
Deux indices, rédigés en mots
  1. Un if sur le registre suffit : form et reduce sont les deux seules valeurs.
  2. Le compteur suit exactement les lignes « correction ».

Exercice 2 — Intonation rising or falling

Étude de cas Niveau 2 — Application

Objectif : Choisir l'intonation : montante (questions oui/non), descendante (déclarations, questions WH).

Pour chaque situation proposée : type vaut yesno (question oui/non), wh (question WH) ou statement (déclaration). Pour chaque situation, indiquez phrase : intonation, où intonation vaut montante (yesno) ou descendante (wh et statement). Concluez par questions montantes : X/n.

Cas d’exemple
3
q1 yesno
q2 wh
s1 statement
Résolution attendue
q1 : montante
q2 : descendante
s1 : descendante
questions montantes : 1/3
Deux indices, rédigés en mots
  1. Seules les questions oui/non montent : wh et statement descendent.
  2. Le compteur suit exactement les intonations montantes.

Exercice 3 — The fluency tracker

Étude de cas Niveau 3 — Raisonnement

Objectif : Suivre une semaine d'entraînement : enregistrer, écouter, corriger — et décider si la fluidité progresse.

Pour chaque situation proposée : defauts X. Le cas compte ensuite les jours d'amélioration (moins de défauts que le jour précédent) et affiche ameliorations : X/n-1 (0 si n = 1), puis verdict : progresse si les améliorations sont majoritaires, verdict : stagne sinon.

Cas d’exemple
4
lun 8
mar 6
mer 7
jeu 5
Résolution attendue
lun : defauts 8
mar : defauts 6
mer : defauts 7
jeu : defauts 5
ameliorations : 2/3
verdict : progresse
Deux indices, rédigés en mots
  1. Retenez la valeur du jour précédent ; comparez seulement quand elle existe.
  2. Le décompte des comparaisons est n - 1 ; le verdict est un test de majorité.

4. QCM — niveau examen

« I'm gonna send that email » est…

Casual speech OK avec des collègues ; formel exige going to.

Devant un client, on dit…

Formal : pas de reductions.

« Gotta » signifie…

Gonna = going to ; wanna = want to ; gotta = got to.

« You're done ? » avec intonation montante exprime…

Rising = question ; falling = déclaration.

La position du support sur l'accent :

« You need to be understood » — fluency vs perfection.

Suivre sa fluidité demande de…

Recording lab : un message par jour, s'écouter, compter les défauts.

Une liste d'items prend une intonation…

Les listes descendent, l'intonation remonte à l'av-dernier ou dernier item selon l'ouverture suivante.

Wanna meet ? au formel devient…

La forme polie remplace la réduction : Would you like to…

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Garder gonna/wanna dans un email ou une présentation formels.
  • Descendre en fin de question oui/non : le sens bascule en déclaration.
  • Viser l'accent parfait au lieu de l'intelligibilité.
  • S'améliorer sans mesurer : sans recording lab, pas de progression visible.

6. Méthodologie de résolution

Méthode — passer un passage au registre formel
  1. Repérer les reductions : gonna, wanna, gotta, y a-t-il un cas ?
  2. Remplacer : going to / want to / have to — ou reformuler poliment (Would you like to…).
  3. Vérifier l'intonation : question oui/non ↗, déclaration et WH ↘.
  4. S'enregistrer, écouter, compter les défauts — et rejouer.

7. Révision active

Résumé essentiel
  • Reductions : gonna/wanna/gotta ok en casual, interdites en formel.
  • Corrections : going to, want to, got to (ou have to) ; Would you like to… pour inviter.
  • Intonation : ↗ questions oui/non, ↘ déclarations et questions WH.
  • Fluency vs perfection : être compris prime ; s'enregistrer pour progresser.

Checklist de maîtrise

  • Je sais corriger cinq réductions en formes formelles.
  • Je sais choisir l'intonation de huit phrases variées.
  • Je sais expliquer pourquoi l'accent parfait n'est pas l'objectif.
  • Je sais mettre en place un recording lab hebdomadaire.

Les 8 notions à connaître absolument

  1. Gonna : going to, casual seulement.
  2. Wanna : want to, casual seulement.
  3. Gotta : got to / have to, casual seulement.
  4. Register : casual vs formal selon le destinataire.
  5. Rising intonation : questions oui/non.
  6. Falling intonation : déclarations et WH-questions.
  7. Recording lab : s'enregistrer, s'écouter, se corriger.
  8. Fluency : être compris, pas être parfait.

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — reprenez les trois reductions et leurs formes formelles.
50–69 % — refaites l'exercice intonation du support.
70–89 % — bon niveau, ciblez le suivi de fluidité.
≥ 95 % — niveau de maîtrise recherché.
