Exercices supplémentaires & projet intégrateur

De la pratique graduée pour consolider chaque session, puis un projet final qui outille l'équipe entière. Les scripts sont en Bash, comme à l'atelier.

Entraînement rapide (acquisition)

Échauffement
  1. Lit n mots « type mot » (b/c) et affiche professionnel ou familier, puis les deux compteurs.
  2. Lit n personnes « nom relation » (long/once) et affiche client ou customer, puis les fidèles.
  3. Lit n verbes « verbe son » (t/d/id) et affiche la prononciation du -ed, puis les trois compteurs.
  4. Lit n phrases « phrase type » (yesno/wh/statement) et affiche montante ou descendante.
Corrections
read -r n
b=0 ; c=0
for ((k=0; k<n; k++)); do
  read -r type mot
  if [ "$type" = "b" ]; then echo "$mot : professionnel" ; b=$((b + 1))
  else echo "$mot : familier" ; c=$((c + 1)); fi
done
echo "business : $b / casual : $c"

read -r n
fideles=0
for ((k=0; k<n; k++)); do
  read -r nom relation
  if [ "$relation" = "long" ]; then echo "$nom : client" ; fideles=$((fideles + 1))
  else echo "$nom : customer"; fi
done
echo "fideles : $fideles"

read -r n
t=0 ; d=0 ; id=0
for ((k=0; k<n; k++)); do
  read -r verbe son
  case "$son" in
    t) echo "$verbe : /t/" ; t=$((t + 1)) ;;
    d) echo "$verbe : /d/" ; d=$((d + 1)) ;;
    id) echo "$verbe : /ɪd/" ; id=$((id + 1)) ;;
  esac
done
echo "t : $t / d : $d / ɪd : $id"

read -r n
montantes=0
for ((k=0; k<n; k++)); do
  read -r phrase type
  if [ "$type" = "yesno" ]; then echo "$phrase : montante" ; montantes=$((montantes + 1))
  else echo "$phrase : descendante"; fi
done
echo "montantes : $montantes"

Application

Application
  1. Audit d'email : lit n lignes « partie lettre » (C/L/E/A/R) et signale les parties manquantes au format du kit.
  2. Réécriture de subject lines : lit n lignes « mauvaise bonne » et valide que la nouvelle contient action et échéance (mots cle et by).
  3. Score CLEAR : lit « seuil n » puis n occurrences de parties et calcule le taux de complétude, verdict prêt ou a completer.
  4. Registre d'équipe : lit n messages « auteur registre » (form/reduce) et compte les corrections par auteur avec declare -A.
Corrections
read -r n
declare -A vues
for ((k=0; k<n; k++)); do
  read -r partie lettre
  vues[$lettre]=1
done
for lettre in C L E A R; do
  if [ -z "${vues[$lettre]:-}" ]; then echo "$lettre : manquante" ; fi
done

read -r n
valides=0
for ((k=0; k<n; k++)); do
  read -r mauvaise bonne action echeance
  if [ "$action" != "-" ] && [ "$echeance" = "by" ]; then
    echo "subject line valide"
    valides=$((valides + 1))
  else
    echo "subject line incomplet"
  fi
done
echo "valides : $valides/$n"

read -r seuil
read -r n
complet=0
for ((k=0; k<n; k++)); do
  read -r phrase partie
  complet=$((complet + 1))
done
taux=$((complet * 5 / n))
if [ "$taux" -ge "$seuil" ]; then echo "pret" ; else echo "a completer"; fi

read -r n
declare -A corrections
for ((k=0; k<n; k++)); do
  read -r auteur registre
  if [ "$registre" = "reduce" ]; then
    corrections[$auteur]=$(( ${corrections[$auteur]:-0} + 1 ))
  fi
done
for auteur in "${!corrections[@]}"; do
  echo "$auteur : ${corrections[$auteur]} corrections"
done

Raisonnement

Raisonnement
  1. Structure de présentation : lit n lignes « minute partie » (open/body/close) et valide l'ordre avec drapeau de rupture.
  2. Grandma Rule : lit n mots « mot famille » (tech/simple) et calcule le score de clarté /10 avec pénalités de 2.
  3. Thought groups : lit n positions (run/pause) et compte les séquences robot de plus de 4 mots.
  4. Suivi de fluidité : lit n jours « jour defauts » et compte les améliorations, puis le verdict progresse/stagne.
Corrections
read -r n
etape=0 ; rompu=0
for ((k=0; k<n; k++)); do
  read -r minute partie
  if [ "$rompu" = "0" ]; then
    if [ "$partie" = "open" ] && [ "$etape" = "0" ]; then etape=1 ; echo "ok"
    elif [ "$partie" = "body" ] && [ "$etape" = "1" -o "$etape" = "2" ]; then etape=2 ; echo "ok"
    elif [ "$partie" = "close" ] && [ "$etape" = "2" ]; then etape=3 ; echo "ok"
    else rompu=1 ; echo "hors structure"; fi
  else echo "hors structure"; fi
done

read -r n
penalite=0
for ((k=0; k<n; k++)); do
  read -r mot famille
  if [ "$famille" = "tech" ]; then penalite=$((penalite + 2)) ; fi
done
score=$((10 - penalite))
[ "$score" -lt 0 ] && score=0
echo "score : $score/10"

read -r n
courant=0 ; robots=0
for ((k=0; k<n; k++)); do
  read -r position groupe
  if [ "$groupe" = "run" ]; then courant=$((courant + 1))
  else
    [ "$courant" -gt 4 ] && robots=$((robots + 1))
    courant=0
  fi
done
[ "$courant" -gt 4 ] && robots=$((robots + 1))
echo "sequences robot : $robots"

read -r n
precedent="" ; ameliorations=0
for ((k=0; k<n; k++)); do
  read -r jour defauts
  if [ -n "$precedent" ] && [ "$defauts" -lt "$precedent" ]; then
    ameliorations=$((ameliorations + 1))
  fi
  precedent=$defauts
done
echo "ameliorations : $ameliorations"

Projet intégrateur — « correcteur de courriels de l'équipe »

Cahier des charges

Le script reçoit le journal d'envoi d'une équipe : d'abord n_emails emails au format auteur parties où parties est une suite de lettres CLEAR (par exemple CLAR — cinq lettres = email complet), puis n_mots mots au format mot registre (form/reduce). Il produit le rapport qualité : pour chaque auteur, nombre d'emails complets et incomplets ; puis les corrections de registre à appliquer ; enfin le verdict global : « equipe prete » si tous les emails sont complets et zéro reduction, « formation requise » sinon.

Fonctionnalités attendues
  1. Lire les deux blocs sans mélanger emails et mots.
  2. Analyser chaque suite CLEAR : complète si C, L, E, A, R tous présents.
  3. Agréger
    4.  par auteur avec des tableaux associatifs.
  4. Compter les reductions et citer leur forme formelle.
  5. Verdict final au format exact du cahier des charges.

Contraintes : parsing lettre à lettre des suites CLEAR, declare -A par auteur, bilan après lecture complète.

Grille d'auto-évaluation du projet (sur 100)
Lecture des deux blocs et parsing CLEAR 20
Agrégation par auteur correcte 20
Corrections de registre avec formes cibles 20
Verdict global conforme 20
Rapport lisible et formats exacts 20

Objectif : ≥ 95/100 avant de considérer le projet terminé.

Voir une solution de référence (après avoir essayé !) 
read -r n_emails
declare -A complets
declare -A incomplets
tout_complets=1
for ((k=0; k<n_emails; k++)); do
  read -r auteur parties
  declare -A vues
  for ((j=0; j<${#parties}; j++)); do
    vues[${parties:$j:1}]=1
  done
  if [ -n "${vues[C]:-}" ] && [ -n "${vues[L]:-}" ] && [ -n "${vues[E]:-}" ] &&
     [ -n "${vues[A]:-}" ] && [ -n "${vues[R]:-}" ]; then
    complets[$auteur]=$(( ${complets[$auteur]:-0} + 1 ))
  else
    incomplets[$auteur]=$(( ${incomplets[$auteur]:-0} + 1 ))
    tout_complets=0
  fi
  unset vues
done
read -r n_mots
reductions=0
for ((k=0; k<n_mots; k++)); do
  read -r mot registre
  if [ "$registre" = "reduce" ]; then
    echo "correction : $mot"
    reductions=$((reductions + 1))
  fi
done
for auteur in "${!complets[@]}"; do
  echo "$auteur : ${complets[$auteur]} complets / ${incomplets[$auteur]:-0} incomplets"
done
if [ "$tout_complets" = "1" ] && [ "$reductions" = "0" ]; then
  echo "verdict : equipe prete"
else
  echo "verdict : formation requise"
fi
Cette solution combine parsing lettre à lettre, agrégation par auteur, corrections de registre et verdict global — les chapitres 1, 2 et 5 en un seul script.
