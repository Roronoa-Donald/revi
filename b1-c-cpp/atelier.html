Atelier de code

Un éditeur dans la page, un vrai compilateur derrière. Écrivez un programme, donnez-lui son entrée, compilez-le et lisez ce qu’il affiche. C’est ici qu’on transforme la théorie en réflexe.

Comment fonctionne l’atelier
  • Exécuter compile et lance votre code tel quel, puis affiche sa sortie, ses erreurs et son code de sortie.
  • Langage permet de basculer entre C et C++ depuis la même zone.
  • Entrée du programme contient ce que scanf ou cin lira, une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le programme sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours : vous le retrouvez à la prochaine visite.

Écrire un programme qui lit son entrée

Un programme d’examen ne se contente pas d’afficher une valeur calculée à l’avance : il lit ce qu’on lui donne. En C, scanf remplit une variable par l’intermédiaire de son adresse ; en C++, cin remplit directement la variable. Dans les deux cas, l’ordre des lectures doit correspondre à l’ordre des lignes fournies.

Les trois erreurs que l’atelier révèle immédiatement
  • Oublier le & devant une variable scalaire de scanf : le programme plante à l’exécution (sauf pour une chaîne, qui est déjà une adresse).
  • Confondre int et float : une division entre entiers tronque silencieusement la partie décimale.
  • Oublier le point-virgule : le compilateur s’arrête, mais le programme n’est jamais produit.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution sandboxé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. Exécuter à chaque frappe épuiserait ce quota : l’atelier n’exécute que sur un clic.
