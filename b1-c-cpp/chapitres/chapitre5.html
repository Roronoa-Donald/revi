Chapitre 5 — Fonctions

Module 5 ≈ 3 h de travail B1 et plus
Mise en situation

Dans un programme qui calcule des moyennes, la même formule revient dix fois. La recopier, c'est se condamner à corriger dix endroits le jour où elle change. La fonction isole ce calcul une fois pour toutes et lui donne un nom : c'est la brique de base de tout programme lisible.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. Déclarer un prototype et définir une fonction ;
  2. comprendre le passage par valeur ;
  3. distinguer une fonction void d'une fonction qui renvoie une valeur ;
  4. expliquer la portée des variables locales et globales ;
  5. décomposer un problème en fonctions réutilisables.

1. Définir et appeler une fonction

Définition. Une fonction regroupe un bloc d'instructions sous un nom. Elle reçoit des paramètres et renvoie une valeur d'un type donné (ou void si elle ne renvoie rien).

int carre(int n);                /* prototype : annonce la signature */

int carre(int n) {               /* définition */
    return n * n;
}

void affiche_ligne(int n) {      /* ne renvoie rien */
    for (int i = 0; i < n; i++) printf("-");
    printf("\n");
}

int main(void) {
    printf("%d\n", carre(5));    /* appel */
    affiche_ligne(10);
    return 0;
}
PartieRôle
Type de retourCe que la fonction renvoie (int, double, void…).
NomIdentifiant explicite, en minuscules.
ParamètresLes entrées, avec leur type.
returnRenvoie la valeur à l'appelant et termine la fonction.
Niveau 1 — Intuition

Une fonction est une machine à sous : tu y mets des valeurs (les paramètres), tu tires le levier (l'appel), et il en sort une valeur (le retour). Ce qui se passe à l'intérieur ne regarde pas l'extérieur — c'est le principe d'encapsulation.

Niveau 2 — Technique

Le prototype (ou déclaration) annonce la signature avant l'usage. Sans lui, le compilateur ne connaît pas le type de retour au moment de l'appel et suppose un entier par défaut : c'est un avertissement fréquent. La définition, elle, contient le corps.

2. Le passage par valeur

Définition. En C, les arguments sont passés par valeur : la fonction reçoit une copie. Modifier un paramètre ne change donc pas la variable de l'appelant.

void doubler(int n) {
    n = n * 2;        /* modifie la copie locale */
}

int main(void) {
    int x = 5;
    doubler(x);
    printf("%d\n", x);  /* affiche 5 : x n'a pas changé */
    return 0;
}
Piège — « ma fonction ne modifie rien »

C'est le comportement normal du passage par valeur. Pour qu'une fonction modifie une variable de l'appelant, il faut lui passer son adresse (chapitre 6). C'est ce mécanisme qui permet d'écrire scanf("%d", &x).

3. Plusieurs valeurs en retour

Une fonction ne renvoie qu'une seule valeur. Pour en renvoyer plusieurs, deux solutions : les empaqueter dans une structure (chapitre 7), ou les écrire dans des variables de l'appelant par leurs adresses (chapitre 6).

int min_de_deux(int a, int b) {
    if (a < b) return a;
    return b;
}

4. Portée des variables

Définition. La portée est la région du programme où un nom est visible. Une variable déclarée dans un bloc n'existe que dans ce bloc.

TypePortée
LocaleDu point de déclaration à la fin du bloc.
ParamètreComme une locale de la fonction.
GlobaleDéclarée hors fonction : visible partout, à éviter.
Piège — la variable globale

Une variable globale introduit une dépendance cachée entre les fonctions et rend le programme difficile à tester. Préférer passer les valeurs en paramètres.

5. Décomposer un problème

Un bon programme est une suite de fonctions ayant chacune une seule responsabilité. Exemple : calculer la moyenne d'un tableau et afficher un rapport.

int somme(int t[], int n) {
    int total = 0;
    for (int i = 0; i < n; i++) total += t[i];
    return total;
}

double moyenne(int t[], int n) {
    if (n == 0) return 0.0;
    return (double)somme(t, n) / n;
}

6. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Une fonction qui renvoie une valeur

C Niveau 3 — Raisonnement

Objectif : Écrire une fonction avec paramètre et valeur de retour.

Complétez la fonction carre pour qu’elle renvoie le carré de son argument, puis affichez son résultat sous la forme Carre : <valeur>.

Entrée du programme
7
Sortie attendue
Carre : 49

7² = 49.

Deux indices, rédigés en mots
  1. Une fonction déclarée pour renvoyer un entier doit se terminer par l’instruction qui transmet cette valeur à l’appelant.
  2. Le mot-clé de retour est suivi de l’expression à renvoyer, et non d’un affichage.

Exercice 2 — Fonction de test booléenne

C Niveau 3 — Raisonnement

Objectif : Faire renvoyer à une fonction un résultat de type vrai/faux.

Complétez la fonction est_pair pour qu’elle renvoie vrai si son argument est pair, faux sinon. Le programme affiche Pair ou Impair.

Entrée du programme
10
Sortie attendue
Pair

10 est pair.

Deux indices, rédigés en mots
  1. En C, il n’existe pas de type booléen d’origine : un entier nul vaut faux, tout entier non nul vaut vrai.
  2. La parité se teste avec le reste de la division par deux : un reste nul signifie que le nombre est pair.

Exercice 3 — Factorielle d’un entier

C Niveau 4 — Examen

Objectif : Écrire une fonction qui accumule dans une boucle.

Complétez la fonction factorielle qui renvoie le produit 1 × 2 × … × n, avec la convention 1 pour n = 0. Affichez le résultat sous la forme Factorielle : <valeur>.

Entrée du programme
5
Sortie attendue
Factorielle : 120

1 × 2 × 3 × 4 × 5 = 120.

Deux indices, rédigés en mots
  1. Un produit s’accumule comme une somme, mais l’élément neutre n’est pas zéro : multiplier par zéro effacerait tout le résultat.
  2. Pour n = 0, la boucle ne s’exécute pas : la valeur initiale de l’accumulateur est donc déjà le bon résultat.

7. QCM — niveau examen

Que fait le return d'une fonction ?

La valeur devient le résultat de l'appel.

Que renvoie une fonction void ?

void signifie « aucune valeur de retour ».

Que fait doubler(x) si la fonction modifie son paramètre ?

Le passage par valeur copie l'argument.

À quoi sert un prototype ?

Le compilateur connaît ainsi le type de retour à l'appel.

Où une variable locale est-elle visible ?

Sa portée est limitée au bloc.

Combien de valeurs une fonction peut-elle renvoyer directement ?

Pour plusieurs valeurs, on utilise une structure ou des paramètres pointeurs.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier return : la valeur renvoyée est indéterminée.
  • Type de retour incohérent avec la valeur renvoyée.
  • Prototype absent : avertissement « implicit declaration ».
  • Croire qu'un paramètre modifie l'appelant (passage par valeur).
  • Variable globale là où un paramètre suffirait.

9. Méthodologie de résolution

Concevoir une fonction
  1. Nommer par un verbe d'action : calculer_moyenne, est_pair.
  2. Lister les entrées : ce sont les paramètres, avec leur type.
  3. Déterminer la sortie : type de retour, ou void.
  4. Écrire le corps avec une seule responsabilité.
  5. Appeler depuis main et tester.

10. Révision active

Résumé essentiel
  • Signature : type de retour, nom, paramètres typés.
  • return renvoie une valeur unique et termine la fonction.
  • void = aucune valeur de retour.
  • Passage par valeur : la fonction reçoit une copie.
  • Portée locale : une variable n'existe que dans son bloc.

Checklist de maîtrise

  • J'écris un prototype avant usage quand c'est nécessaire.
  • J'explique le passage par valeur sans hésiter.
  • Je distingue void d'une fonction à retour.
  • Je limite la portée de mes variables.
  • Je découpe un problème en fonctions à responsabilité unique.
