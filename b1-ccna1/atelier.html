Atelier d’analyse & Bac à sable

Un éditeur dans la page, un vrai interpréteur Bash derrière. Écris un script, exécute-le et lis ce qu'il affiche : c'est ici qu'une règle de brochage devient un contrôle automatisé.

Comment fonctionne l'atelier
  • Valider vérifie la conformité de vos réponses dans la grille d’analyse.
  • Données du cas contient les paramètres soumis à l’étude.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n'écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l'éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Zone libre

Zone libre — validateur de liaisons Ethernet

Bash

Objectif : expérimenter sans conséquence. Prends un mécanisme du cours (couches OSI, étapes du routage, modes de la CLI, sécurisation), programme-le et teste-le sur des cas limites.

Le script proposé juge chaque liaison selon la règle « droit entre différents, croisé entre copains ». Transforme-le : ajoute les liaisons gigabit, vérifie les catégories de câbles, ou remplace tout le script par le mécanisme que tu veux vérifier.

Dans une vraie baie de brassage, ce contrôle se fera à l'étiquetage : la structure du script — lire, décider, rapporter — reste exactement la même.

Cas d’exemple
3
pc-switch droit
switch-switch droit
pc-pc croise
Résolution attendue
pc-switch : conforme
switch-switch : a revoir
pc-pc : conforme
conformes : 2/3

Trois lignes attendues : déplie « Entrée du programme » et saisis-les avant d’exécuter.

De la page au vrai commutateur

La simulation a une limite assumée : aucun câble n'est broché et aucun commutateur Cisco n'est configuré ici — le réseau reste du texte structuré. Elle a une force : toute la logique se vérifie sans risque — on peut rejouer une escalade de modes ou une configuration SSH autant de fois que nécessaire. Quand le script reproduit les bons réflexes — lire, décider, rapporter — le passage à la vraie CLI est mécanique.

Les trois erreurs que l'atelier révèle immédiatement
  • Case incomplet : la liaison r1-r2 tombe dans le défaut silencieux et sort « a revoir » à tort.
  • Compteur dans la boucle : le bilan s'affiche à chaque ligne au lieu d'une seule fois, après.
  • Ordre des lectures inversé : le script lit le brochage avant la liaison, et tout décale.
Ce que fait l'atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d'exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n'est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d'exécutions est limité par jour, pour tout le monde. L'atelier n'exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois études de cas corrigées automatiquement dans la page. Une fois l'atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme est vraiment acquis.
