Chapitre 2 — Les modèles TCP/IP et OSI

Module 2 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Impossible de faire communiquer des machines de fabricants différents sans un accord : l'ISO a bâti le modèle OSI en sept couches, référentiel de toutes les discussions. Mais c'est le TCP/IP — à 4 couches, ou à 5 couches « modèle d'actualité » — qui fait tourner les réseaux réels.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. ranger les protocoles dans les 4 couches TCP/IP : accès réseau, internet, transport, application ;
  2. expliquer le modèle à 5 couches : la couche physique est séparée de l'accès réseau ;
  3. réciter les 7 couches OSI avec leur rôle et leur unité de données ;
  4. associer équipements et couches : hub (1), switch (2), routeur (3).

1. TCP/IP : 4 puis 5 couches

Le modèle TCP/IP à 4 couches : accès réseau (Ethernet, câbles), internet (IP, routage), transport (TCP, UDP), application. Le modèle à 5 couches — « le modèle d'actualité » selon le support — sépare la couche physique de la couche accès réseau : physique, liaison de données, réseau, transport, application.

Ce découpage hérite d'OSI : les couches hautes fusionnent en « application », la couche réseau devient « internet », et les deux basses se partagent entre « liaison de données » et « physique ».

Mnémotechnique — « TCP/IP 4 : AITA ; OSI 7 : PLR-TSPA »

Accès, Internet, Transport, Application pour TCP/IP ; Physique, Liaison, Réseau, Transport, Session, Présentation, Application pour OSI.

2. OSI : les sept couches

7-Application : point d'accès aux services réseau (messagerie, transfert de fichiers) — le lien entre l'utilisateur et la machine. 6-Présentation : codage et décodage des données (ASCII, Unicode, HTML), représentation commune. 5-Session : ouvre, gère et ferme les sessions, synchronise le dialogue (RPC, NetBIOS). 4-Transport : découpe en segments, fiabilité (renvoi des données manquantes), contrôle de flux, ports. 3-Réseau : adressage logique (IP), acheminements de réseau en réseau par routeurs — chaque segment devient un paquet. 2-Liaison de données : méthodes de transmission dans un même LAN, détection d'erreurs, Ethernet — chaque paquet devient une trame (en-tête + queue ajoutés). 1-Physique : transmission des bits sur les supports (cuivre, fibre, ondes) — le hub vit ici.

Confusions d'examen
  • La couche 6 code (ASCII) ; la couche 7 parle à l'utilisateur : deux rôles distincts.
  • Segment (4), paquet (3), trame (2), bits (1) : l'unité trahit la couche.
  • Le modèle d'actualité est TCP/IP à 5 couches, pas à 4.
  • Le hub est de couche 1 : il ne lit ni MAC ni IP.

3. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

En cas d’hésitation, le bouton Expliquer mon erreur sollicite le tuteur pédagogique pour vous guider dans l’application de la méthodologie sans donner directement la solution.

Exercice 1 — Couches TCP/IP à 4 ou 5

Étude de cas Niveau 1 — Acquisition

Objectif : Classer les éléments dans le modèle TCP/IP à 4 couches puis à 5 couches (modèle d'actualité).

Analysez chaque ligne proposée « element modele couche » : modele est un code parmi tcp4 ou tcp5. Dans le modèle à 4 couches, les couches sont acces, internet, transport et application ; dans le modèle à 5 couches (d'actualité), la couche physique est séparée de l'accès réseau. Pour chaque ligne il Indiquez element : OK si la couche existe dans ce modèle, sinon element : ABSENT (physique est absent du modèle 4 couches). Il termine par conformes : X/n.

Cas d’exemple
3
cable tcp5 physique
cable tcp4 physique
ip tcp4 internet
Résolution attendue
cable : OK
cable : ABSENT
ip : OK
conformes : 2/3
Deux indices, rédigés en mots
  1. Le modèle 4 couches n'a pas de couche physique : seule la 5 couches l'a.
  2. Le verdict porte sur la couche, pas sur l'élément.

Exercice 2 — Les sept couches OSI

Étude de cas Niveau 1 — Acquisition

Objectif : Placer chaque unité de données dans sa couche OSI, du bit (1) à la donnée applicative (7).

Analysez chaque ligne proposée « unite couche » : couche est un numéro de 1 à 7. Correspondances du support : bits (1), trame (2), paquet (3), segment (4), donnée de session (5), donnée codée (6), donnée applicative (7). Pour chaque ligne il Indiquez unite : couche N — ou unite : NON quand l'unité ne correspond pas à la couche annoncée — puis justes : X/n.

Cas d’exemple
3
bits 1
trame 3
paquet 3
Résolution attendue
bits : couche 1
trame : NON
paquet : couche 3
justes : 2/3
Deux indices, rédigés en mots
  1. bits=1, trame=2, paquet=3, segment=4, session=5, codage=6, appli=7.
  2. Le numéro affiché est celui de la couche attendue.

Exercice 3 — Qui fait quoi entre OSI et TCP/IP

Étude de cas Niveau 2 — Application

Objectif : Relier chaque tâche au modèle qui la porte : OSI 7 couches (référentiel) ou TCP/IP 5 couches (actualité).

Analysez chaque ligne proposée « tache modele » : modele est un code parmi osi ou tcp5. Tâches du référentiel OSI : codage (couche 6), session (couche 5). Tâches du modèle d'actualité TCP/IP 5 couches : routage (internet), ports (transport), cables (physique). Pour chaque ligne il Indiquez tache : conforme ou tache : a revoir, puis conformes : X/n.

Cas d’exemple
2
codage osi
routage osi
Résolution attendue
codage : conforme
routage : a revoir
conformes : 1/2
Deux indices, rédigés en mots
  1. codage et session → OSI ; routage, ports, cables → TCP/IP 5 couches.
  2. Le bilan sort après la boucle.

4. QCM — niveau examen

Le modèle TCP/IP d'actualité compte…

Le support : « le modèle TCP/IP à 5 couches est le modèle d'actualité ».

La couche présentation OSI gère…

Couche 6 : codage/décodage, représentation commune.

La couche session s'occupe…

RPC et NetBIOS vivent en couche 5.

La couche transport découpe les données en…

Segments en 4 ; paquets en 3 ; trames en 2.

Chaque paquet devient une trame en couche…

Liaison de données : en-tête + queue de trame ajoutés.

Le hub travaille en couche…

Il transmet sans cibler MAC ni IP.

L'adressage logique (IP) est de la couche…

Réseau : routeurs et protocoles de routage.

La couche application OSI est…

Couche 7 : messagerie, transfert de fichiers, pages web.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Mettre « physique » dans le modèle TCP/IP à 4 couches : il n'y est pas.
  • Confondre segment (4) et paquet (3) : l'unité suit la couche.
  • Chercher le codage ASCII en couche 7 : c'est la couche 6.
  • Réciter OSI de haut en bas sans les numéros : l'examen demande les deux sens.

6. Méthodologie de résolution

Méthode — classer une tâche en trois gestes
  1. Identifier l'unité : bits, trame, paquet, segment, donnée — elle nomme la couche.
  2. Regarder le périmètre : même LAN (2), entre réseaux (3), bout en bout (4).
  3. Choisir le modèle : OSI 7 pour décrire, TCP/IP 5 pour pratiquer.

7. Révision active

Résumé essentiel
  • TCP/IP 4 couches : accès réseau, internet, transport, application.
  • TCP/IP 5 couches (actualité) : la physique est séparée.
  • OSI 7 : application, présentation, session, transport, réseau, liaison, physique.
  • Unités : bits, trame, paquet, segment — du câble vers l'utilisateur.

Checklist de maîtrise

  • Je sais réciter les deux modèles dans les deux sens.
  • Je sais associer unité de données et couche.
  • Je sais expliquer le rôle de chaque couche OSI.
  • Je sais dire pourquoi TCP/IP 5 est le modèle d'actualité.

Les 8 notions à connaître absolument

  1. TCP/IP 4 : accès réseau, internet, transport, application.
  2. TCP/IP 5 : le modèle d'actualité — physique séparée.
  3. Couche 6 : présentation — codage ASCII, Unicode.
  4. Couche 5 : session — RPC, NetBIOS, synchronisation.
  5. Couche 3 : réseau — IP, routeurs, paquets.
  6. Couche 2 : liaison — Ethernet, trames, switch.
  7. Couche 1 : physique — bits, câbles, hub.
  8. Segment / paquet / trame : les unités des couches 4/3/2.

Comment t'auto-évaluer
