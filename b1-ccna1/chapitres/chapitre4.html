Chapitre 4 — Fondamentaux des WAN et du routage IP

Module 4 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le WAN est l'interconnexion de plusieurs LAN — par ligne louée (HDLC, PPP) ou par Ethernet WAN (EoMPLS). Le routage IP y achemine les paquets de bout en bout : chaque routeur désencapsule, consulte sa table, réencapsule — tandis que l'en-tête IP reste inchangé.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. décrire le WAN de lignes louées et le WAN Ethernet (EoMPLS) ;
  2. dérouler les quatre étapes du routage interne d'un routeur ;
  3. appliquer les deux règles d'or des sous-réseaux (routeur entre les adresses ou non) ;
  4. expliquer l'en-tête IPv4 de 20 octets (adresses source et destination 32 bits) ;
  5. décrire l'apprentissage des routes par protocole de routage (connectées, annonces, métrique).

1. Les WAN : lignes louées et Ethernet

Le WAN de lignes louées : une liaison permanente louée à un opérateur, dont les détails de liaison de données utilisent HDLC (ou PPP). Le routeur y encapsule le paquet IP dans une trame HDLC. L'Ethernet WAN (EoMPLS — Ethernet over MPLS) est « plus d'actualité » : le WAN se comporte comme un gigantesque switch Ethernet entre les sites.

La logique de routage interne, pour chaque trame qui arrive sur une interface : 1. vérifier le FCS de la trame (erreur → jeter) ; 2. supprimer l'ancien en-tête et la fin de liaison de données, laissant le paquet IP ; 3. comparer l'IP de destination à la table de routage (meilleure route → interface sortante et saut suivant) ; 4. encapsuler le paquet dans un nouvel en-tête approprié à l'interface sortante et transmettre.

Mnémotechnique — « l'en-tête IP voyage intact, l'en-tête de liaison change à chaque saut »

Les MAC et en-têtes de trame se renouvellent à chaque routeur ; les adresses IP de bout en bout restent les mêmes.

2. Sous-réseaux, en-tête IP et protocoles de routage

Les règles d'or des groupes d'adresses : deux adresses non séparées par un routeur appartiennent au même groupe (sous-réseau) ; deux adresses séparées par au moins un routeur appartiennent à des groupes différents. L'analogie du support : le sous-réseau est le code postal des adresses IP. L'en-tête IPv4 fait 20 octets, avec les adresses source et destination de 32 bits — inchangées par le routage.

Les protocoles de routage apprennent les routes en trois étapes : chaque routeur ajoute d'abord ses routes connectées ; chaque protocole annonce les routes de sa table à ses voisins (mises à jour de routage) ; après apprentissage, la meilleure route — selon une métrique — entre dans la table. Les hôtes, eux, connaissent leur routeur par défaut : destination de tout paquet hors du sous-réseau local. ARP apprend dynamiquement la MAC de liaison de données d'un hôte IP du LAN.

Confusions d'examen
  • Le FCS est vérifié AVANT la désencapsulation : trame fautive = trame jetée.
  • Adresses séparées par un routeur = sous-réseaux différents : la règle inverse piège.
  • L'en-tête IP reste inchangé de bout en bout : ce sont les en-têtes de liaison qui changent.
  • EoMPLS est un WAN Ethernet : plus d'actualité que HDLC.

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Même sous-réseau ou routé

Bash Niveau 1 — Acquisition

Objectif : Appliquer les deux règles d'or du sous-réseautage : séparés par un routeur ou non.

Le script lit n lignes « couple verdict » : couple est un code de liaison et verdict un code parmi memegroupe ou groupesdifferents. Règles du support : deux adresses non séparées par un routeur appartiennent au même groupe (sous-réseau) ; deux adresses séparées par au moins un routeur appartiennent à des groupes différents. Couples du support : mmelAN et mmelRouteur (même LAN, avec ou sans routeur entre les deux). Pour chaque ligne il affiche couple : conforme ou couple : a revoir, puis conformes : X/n.

Entrée du programme
2
mmelAN memegroupe
mmelAN groupesdifferents
Sortie attendue
mmelAN : conforme
mmelAN : a revoir
conformes : 1/2
Deux indices, rédigés en mots
  1. mmelAN → memegroupe ; mmelRouteur → groupesdifferents.
  2. Un case par couple donne le verdict attendu.

Exercice 2 — Les quatre étapes du routage

Bash Niveau 2 — Application

Objectif : Dérouler la logique interne du routeur : FCS, désencapsulation, table de routage, réencapsulation.

Le script lit n lignes « etape action » : etape est un numéro de 1 à 4 et action un code parmi fcs, desencapsule, table ou encapsule. Les quatre étapes du support : 1 vérifier le FCS (jeter si erreur), 2 supprimer l'ancien en-tête de liaison de données, 3 chercher la meilleure route pour l'IP de destination, 4 encapsuler dans un nouvel en-tête et transmettre. Pour chaque ligne il affiche etape N : OUI quand le couple est juste, sinon etape N : NON, puis justes : X/n.

Entrée du programme
3
1 fcs
2 desencapsule
4 encapsule
Sortie attendue
etape 1 : OUI
etape 2 : OUI
etape 4 : OUI
justes : 3/3
Deux indices, rédigés en mots
  1. 1-fcs, 2-desencapsule, 3-table, 4-encapsule : l'ordre du support.
  2. Le numéro affiché est celui de l'étape.

Exercice 3 — Les trois protocoles de routage apprennent

Bash Niveau 3 — Raisonnement

Objectif : Simuler l'apprentissage des routes par protocole de routage : connexes, annonces, métrique.

Le script lit d'abord n (nombre de routeurs R1..Rn), puis n lignes « routeur sousreseau » annoncés dans l'ordre de propagation (le dernier routeur est connecté au sous-réseau, les annonces remontent vers le premier). Le protocole de routage suit trois étapes du support : chaque routeur ajoute d'abord ses routes connectées, les voisins s'annoncent leurs routes, la meilleure route (métrique) entre dans la table. Le script affiche pour chaque routeur (du dernier vers le premier) routeur : apprend sousreseau, puis routes apprises : n.

Entrée du programme
3
R1 150.150.4.0
R2 150.150.4.0
R3 150.150.4.0
Sortie attendue
R3 : apprend 150.150.4.0
R2 : apprend 150.150.4.0
R1 : apprend 150.150.4.0
routes apprises : 3
Deux indices, rédigés en mots
  1. Les annonces remontent du routeur connecté (dernier lu) vers le premier.
  2. Chaque routeur du chemin apprend exactement une route.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Chercher la route avant de vérifier le FCS.
  • Encapsuler sans désencapsuler : le vieux cabeau de liaison doit partir.
  • Placer deux adresses séparées par un routeur dans le même sous-réseau.
  • Confondre route connectée (apprentissage automatique) et route apprise (annonce).

6. Méthodologie de résolution

Méthode — suivre un paquet en trois gestes
  1. Repérer le sous-réseau de destination : même groupe ou saut vers le routeur par défaut.
  2. À chaque routeur : FCS, désencapsulation, table, réencapsulation.
  3. Vérifier au bout : les adresses IP sont intactes, les en-têtes de liaison ont changé à chaque saut.

7. Révision active

Résumé essentiel
  • WAN : lignes louées (HDLC, PPP) ou Ethernet WAN (EoMPLS).
  • Routage interne : FCS → désencapsulation → table → réencapsulation.
  • Sous-réseaux : routeur entre les adresses = groupes différents.
  • Protocoles de routage : routes connectées, annonces aux voisins, métrique.

Checklist de maîtrise

  • Je sais dérouler les quatre étapes du routage dans l'ordre.
  • Je sais appliquer les deux règles des sous-réseaux.
  • Je sais expliquer l'en-tête IPv4 et sa stabilité.
  • Je sais décrire l'apprentissage d'une route par protocole de routage.

Les 8 notions à connaître absolument

  1. HDLC : protocole de liaison des lignes louées.
  2. EoMPLS : Ethernet WAN, le plus d'actualité.
  3. Table de routage : sous-réseau → interface sortante + saut suivant.
  4. Métrique : critère de choix de la meilleure route.
  5. Route connectée : ajoutée sans protocole de routage.
  6. En-tête IPv4 : 20 octets, adresses 32 bits inchangées.
  7. Routeur par défaut : destination des paquets hors du sous-réseau.
  8. ARP : apprend la MAC d'un hôte IP du LAN.
