Chapitre 5 — L'interface en ligne de commande

Module 5 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Sur un commutateur Cisco Catalyst, tout passe par la CLI (interface en ligne de commande) d'IOS : on tape une commande, on appuie sur Entrée, le commutateur fait et parfois répond. Trois accès, trois modes, quatre mémoires, deux fichiers de configuration — la grammaire complète du réseau Cisco.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. accéder à la CLI : câble console (physique), Telnet (clair), SSH (chiffré) ;
  2. escalader les modes : user EXEC, enable (privilégié), configuration globale et sous-modes ;
  3. placer les fichiers : running-config (RAM), startup-config (NVRAM), IOS (flash), bootstrap (ROM) ;
  4. sauvegarder avec copy running-config startup-config et effacer avec erase startup-config.

1. Accès et modes

Trois méthodes d'accès : la console — port physique dédié (RJ-45 ou USB mini-B), exigeant une connexion physique et un émulateur de terminal (Putty) ; Telnet et SSH — clients qui traversent le réseau IP existant. Telnet transmet en clair (mots de passe compris) : bien en laboratoire, dangereux en production. SSH chiffre tout, y compris les mots de passe : l'option sérieuse.

Les modes s'escaladent : user EXEC (regarder sans rien casser — mais la commande reload y est refusée), enable ou mode privilégié (commandes puissantes comme reload, accessibles après la commande enable), puis mode de configuration (configure terminal) — le seul qui modifie le commutateur, avec application immédiate à chaque Entrée. Les sous-modes s'ouvrent par commandes de contexte : line console 0, interface FastEthernet 0/1… et exit redescend d'un cran.

Mnémotechnique — « user regarde, enable ose, configure change »

Trois degrés d'audace : consulter, exécuter des commandes puissantes, modifier la configuration — et exit pour redescendre.

2. Mémoires et fichiers de configuration

Quatre mémoires : la RAM (DRAM) — stockage de travail, perd son contenu à l'extinction ; la flash — stocke les images IOS, emplacement par défaut du démarrage ; la ROM — programme d'amorçage (bootstrap) qui trouve et charge IOS ; la NVRAM — RAM non volatile qui conserve la configuration de démarrage.

Deux fichiers de configuration : running-config (active, en RAM, modifiée dynamiquement en mode configuration) et startup-config (initiale, en NVRAM, utilisée à chaque recharge). Le réflexe : copy running-config startup-config sauvegarde la configuration — sinon une coupure d'alimentation la perd. Pour repartir de zéro en laboratoire : erase startup-config (ou write erase, ou erase nvram:), puis recharger. IOS n'a pas de commande qui efface la running-config : on efface la startup puis on recharge.

Confusions d'examen
  • SSH chiffre ; Telnet transmet en clair : la question tombe à chaque examen.
  • reload est refusée en mode user : le support le démontre explicitement.
  • startup-config vit en NVRAM, pas en flash (qui stocke IOS).
  • Une commande de configuration s'applique immédiatement à l'Entrée : prudence.

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Les trois modes de la CLI

Bash Niveau 1 — Acquisition

Objectif : Valider l'escalade des modes Cisco : user, enable, configuration — et le retour avec exit.

Le script lit n lignes « commande modeattendu » : commande est un code parmi enable, configure, exit ou showversion ; modeattendu est un code parmi user, enable ou config. Règles du support : enable fait passer de user à enable ; configure (terminal) fait passer d'enable à config ; exit redescend d'un mode ; showversion s'exécute en user (non perturbant). Pour chaque ligne il affiche commande : OK si le mode annoncé est cohérent, sinon commande : REFUSE, puis valides : X/n.

Entrée du programme
3
enable enable
configure config
showversion enable
Sortie attendue
enable : OK
configure : OK
showversion : REFUSE
valides : 2/3
Deux indices, rédigés en mots
  1. enable→enable (depuis user), configure→config, exit→tous les modes (redescend), showversion→user.
  2. Un case par commande donne le mode attendu.

Exercice 2 — Console, Telnet ou SSH

Bash Niveau 1 — Acquisition

Objectif : Comparer les trois accès à la CLI : câble console (physique), Telnet (clair), SSH (chiffré).

Le script lit n lignes « acces propriete » : acces est un code parmi console, telnet ou ssh et propriete un code parmi physique, clair ou chiffre. Couples du support : la console exige une connexion physique ; Telnet transmet en clair (y compris les mots de passe) ; SSH chiffre toutes les données. Pour chaque ligne il affiche acces : OUI quand le couple est juste, sinon acces : NON, puis justes : X/n.

Entrée du programme
3
console physique
telnet clair
ssh clair
Sortie attendue
console : OUI
telnet : OUI
ssh : NON
justes : 2/3
Deux indices, rédigés en mots
  1. Les trois couples : console-physique, telnet-clair, ssh-chiffre.
  2. SSH est le seul accès chiffré ; Telnet le seul en clair.

Exercice 3 — RAM, NVRAM, flash et ROM

Bash Niveau 2 — Application

Objectif : Placer les fichiers et programmes du commutateur dans les quatre mémoires Cisco.

Le script lit n lignes « fichier memoire » : memoire est un code parmi ram, nvram, flash ou rom. Placements du support : running-config vit en RAM (perdue à l'extinction), startup-config en NVRAM (conservée), l'IOS en flash, le bootstrap (programme d'amorçage) en ROM. Pour chaque ligne il affiche fichier : OK quand le placement est juste, sinon fichier : KO (attendu X), puis placements justes : X/n.

Entrée du programme
3
running-config ram
startup-config ram
ios flash
Sortie attendue
running-config : OK
startup-config : KO (attendu nvram)
ios : OK
placements justes : 2/3
Deux indices, rédigés en mots
  1. running-config → ram ; startup-config → nvram ; ios → flash ; bootstrap → rom.
  2. En cas d'erreur, affiche la mémoire attendue entre parenthèses.

4. QCM — niveau examen

L'accès CLI qui exige une connexion physique :

Câble console vers le port dédié (RJ-45 ou USB mini-B).

Telnet transmet les données…

Mots de passe compris : dangereux en production.

La commande qui fait passer du mode user au mode enable :

enable ; configure terminal monte ensuite vers la configuration.

La commande reload en mode user est…

Reload est puissante : réservée au mode enable.

La running-config est stockée en…

RAM : active, dynamique, volatile.

La startup-config est stockée en…

NVRAM : configuration initiale, utilisée à la recharge.

IOS est chargé depuis…

La flash stocke les images IOS ; la ROM n'a que le bootstrap.

Pour tout effacer et repartir de zéro :

Trois commandes possibles (write erase, erase startup-config, erase nvram:), puis recharge.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Utiliser Telnet en production : texte clair, mots de passe capturables.
  • Modifier la configuration sans copier : perdu à la prochaine coupure.
  • Placer la startup-config en flash : c'est la NVRAM.
  • Chercher une commande qui vide la running-config : elle n'existe pas.

6. Méthodologie de résolution

Méthode — prendre la main sur un commutateur en trois gestes
  1. Se connecter : console (physique) ou SSH (chiffré) — jamais Telnet en production.
  2. Escalader : user → enable → configure terminal → sous-mode (line, interface).
  3. Conclure par copy running-config startup-config avant de quitter.

7. Révision active

Résumé essentiel
  • Trois accès : console (physique), Telnet (clair), SSH (chiffré).
  • Modes : user EXEC → enable (privilégié) → configuration → sous-modes ; exit redescend.
  • RAM : running-config ; NVRAM : startup-config ; flash : IOS ; ROM : bootstrap.
  • copy running-config startup-config sauvegarde ; erase startup-config repart de zéro.

Checklist de maîtrise

  • Je sais choisir l'accès adapté et justifier.
  • Je sais dérouler l'escalade des modes.
  • Je sais placer les quatre mémoires et les deux fichiers.
  • Je sais sauvegarder et effacer proprement.

Les 8 notions à connaître absolument

  1. CLI : interface textuelle d'IOS — commande + Entrée.
  2. Console : accès physique dédié (RJ-45 bleu ou USB mini-B).
  3. SSH : accès distant chiffré, l'option de production.
  4. Mode enable : mode privilégié — reload y est acceptée.
  5. configure terminal : passage au mode de configuration.
  6. running-config : configuration active, en RAM.
  7. startup-config : configuration initiale, en NVRAM.
  8. Bootstrap : programme d'amorçage en ROM.

Comment t'auto-évaluer

< 50 % — relis les trois accès et les quatre mémoires.

≥ 95 % — niveau de maîtrise recherché.
