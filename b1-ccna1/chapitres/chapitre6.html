Chapitre 6 — Configuration de base du commutateur

Module 6 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Par défaut, un commutateur Catalyst n'exige aucun mot de passe sur la console et n'accepte aucun accès distant. Pour gérer un réseau, il faut sécuriser (console, enable, SSH) et donner une adresse IP de gestion au commutateur — via son interface virtuelle VLAN (SVI).

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. sécuriser la console et les lignes vty : password + login, ou login local ;
  2. protéger le mode enable avec enable secret ;
  3. déployer SSH : hostname, ip domain-name, crypto key generate rsa, transport input ssh ;
  4. configurer l'IPv4 de gestion : interface vlan 1, ip address, no shutdown, ip default-gateway ;
  5. conforter la console : logging synchronous, exec-timeout, no ip domain-lookup.

1. Sécuriser la CLI

Les mots de passe simples : en mode de ligne, password + login — pour la console (line con 0) et pour Telnet (line vty 0 15, le mot de passe vty). Le mode enable se protège par la commande de configuration globale enable secret — obligatoire dès qu'on gère à distance, car depuis le mode enable un attaquant rechargerait le commutateur ou modifierait la configuration.

Les utilisateurs locaux : créer les couples avec username nom secret motdepasse, puis activer avec login local (et nettoyer avec no password). Pour SSH — le seul accès chiffré, qui exige un couple utilisateur/mot de passe : hostname + ip domain-name (le FQDN sert à générer la clé), puis crypto key generate rsa (au moins 768 bits pour SSHv2), ip ssh version 2, et transport input ssh en vty pour interdire Telnet.

Mnémotechnique — « secret pour enable, local pour user, crypto pour SSH »

Trois protections, trois commandes-clés : enable secret, login local, crypto key generate rsa.

2. IPv4 de gestion et confort de console

L'adresse IP du commutateur ne concerne pas la commutation des trames — elle sert au trafic de gestion (Telnet, SSH, SNMP). Elle se pose sur l'interface virtuelle (SVI) : interface vlan 1 (tous les ports y sont par défaut), ip address adresse masque, no shutdown, puis ip default-gateway en configuration globale — indispensable pour parler hors du sous-réseau, comme pour un hôte. Alternative : ip address dhcp pour apprendre les paramètres dynamiquement.

Trois commandes de confort : logging synchronous — les messages syslog attendent la fin de la commande en cours au lieu de s'inviter en pleine saisie ; exec-timeout minutes secondes — délai de déconnexion d'inactivité (5 min par défaut, 0 0 = jamais, pour le laboratoire) ; no ip domain-lookup — plus d'attente d'une minute après une commande mal tapée qu'IOS essaie de résoudre en nom d'hôte.

Confusions d'examen
  • SSH ne fonctionne pas avec un simple mot de passe : il exige un couple utilisateur/mot de passe.
  • Le crypto key a besoin du FQDN : hostname + ip domain-name avant.
  • Sans ip default-gateway, le commutateur ne parle pas hors de son sous-réseau.
  • exec-timeout 0 0 = jamais déconnecté : pour le labo, pas la production.

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Sécuriser les accès

Bash Niveau 1 — Acquisition

Objectif : Associer chaque protection de la CLI à sa commande de configuration.

Le script lit n lignes « protection commande » : commande est un code parmi passwordlogin (mot de passe simple + login), loginlocal (noms d'utilisateurs locaux), enablesecret ou transportinput. Protections du support : passwordlogin protège console et vty avec un mot de passe partagé ; loginlocal exige un couple utilisateur/mot de passe local ; enablesecret protège le mode enable ; transportinput choisit les protocoles vty (ssh, telnet, all). Pour chaque ligne il affiche protection : OK ou protection : ERREUR, puis conformes : X/n.

Entrée du programme
2
passwordlogin passwordlogin
transportinput enablesecret
Sortie attendue
passwordlogin : OK
transportinput : ERREUR
conformes : 1/2
Deux indices, rédigés en mots
  1. passwordlogin → password + login ; loginlocal → login local ; enablesecret → enable secret ; transportinput → transport input.
  2. Le bilan sort après la boucle.

Exercice 2 — IPv4 sur le commutateur

Bash Niveau 2 — Application

Objectif : Dérouler la configuration IPv4 de gestion : SVI, adresse/masque, no shutdown, passerelle.

Le script lit n lignes « etape commande » : etape est un numéro de 1 à 5 et commande un code parmi svi, ipaddress, noshutdown, gateway ou nameserver. Étapes du support : 1 interface vlan 1 (la SVI), 2 ip address (adresse + masque), 3 no shutdown, 4 ip default-gateway (obligatoire pour parler hors du sous-réseau), 5 ip name-server (facultatif, DNS). Pour chaque ligne il affiche etape N : OK ou etape N : NON, puis justes : X/n.

Entrée du programme
3
1 svi
2 ipaddress
4 gateway
Sortie attendue
etape 1 : OK
etape 2 : OK
etape 4 : OK
justes : 3/3
Deux indices, rédigés en mots
  1. 1-svi, 2-ipaddress, 3-noshutdown, 4-gateway, 5-nameserver : l'ordre du support.
  2. L'étape 5 est facultative mais garde sa place dans l'ordre.

Exercice 3 — Le confort du laboratoire

Bash Niveau 3 — Raisonnement

Objectif : Simuler les trois commandes de confort : logging synchronous, exec-timeout, no ip domain-lookup.

Le script lit d'abord n (nombre de sessions console), puis n lignes « session reglages » où reglages est une suite de codes sans espace : s = logging synchronous activé, t = exec-timeout à 0 (jamais déconnecté), d = no ip domain-lookup, le tiret - = aucun réglage. Effets du support : sans s, les messages syslog s'invitent en pleine saisie ; sans t, la session expire après 5 minutes ; sans d, une commande mal tapée bloque une minute sur une résolution DNS. Pour chaque session il affiche session : fluide si les trois réglages sont présents, sinon session : gene (motif X) où X vaut syslog, timeout ou dns (premier motif manquant dans l'ordre s, t, d). Il termine par sessions fluides : X/n.

Entrée du programme
3
s1 std
s2 st
s3 -
Sortie attendue
s1 : fluide
s2 : gene (motif dns)
s3 : gene (motif syslog)
sessions fluides : 1/3
Deux indices, rédigés en mots
  1. Parcours la suite caractère par caractère : s, t, d dans cet ordre.
  2. Signale le PREMIER réglage manquant ; le tiret vaut absence de tout réglage.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Activer SSH sans crypto key generate rsa : pas de clés, pas de SSH.
  • Oublier ip default-gateway après l'ip address : gestion locale seulement.
  • Laisser transport input all en production : Telnet en clair reste ouvert.
  • Mettre exec-timeout 0 0 en production : sessions jamais expirées.

6. Méthodologie de résolution

Méthode — sécuriser et connecter un switch en trois gestes
  1. Sécuriser : enable secret, puis console/vty (password + login ou login local).
  2. Ouvrir SSH : hostname, ip domain-name, crypto key generate rsa, transport input ssh.
  3. Donner une IP de gestion : interface vlan 1, ip address, no shutdown, ip default-gateway.

7. Révision active

Résumé essentiel
  • Défaut : console libre, distant fermé — tout se configure.
  • enable secret protège le mode enable ; login local remplace les mots de passe simples.
  • SSH : hostname + ip domain-name + crypto key generate rsa + transport input ssh.
  • IP de gestion sur la SVI : ip address, no shutdown, ip default-gateway.

Checklist de maîtrise

  • Je sais poser les trois types de protections.
  • Je sais dérouler la configuration SSH complète.
  • Je sais configurer l'IPv4 de gestion en cinq étapes.
  • Je sais rendre la console confortable en laboratoire.

Les 8 notions à connaître absolument

  1. line con 0 : contexte de configuration de la console.
  2. line vty 0 15 : contexte des lignes distantes (Telnet/SSH).
  3. enable secret : mot de passe du mode enable, en global.
  4. username nom secret motdepasse : création d'un utilisateur local.
  5. crypto key generate rsa : génération des clés SSH.
  6. transport input ssh : SSH seul sur les lignes vty.
  7. SVI / interface vlan 1 : interface virtuelle de gestion.
  8. exec-timeout 0 0 : jamais déconnecté (laboratoire).

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — relis la sécurisation et les cinq étapes IPv4.
50–69 % — refais la configuration SSH étape par étape.
70–89 % — bon niveau, cible SVI et default-gateway.
≥ 95 % — niveau de maîtrise recherché.
