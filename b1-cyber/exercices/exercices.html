Exercices supplémentaires & projet intégrateur

De la pratique graduée pour consolider chaque module, puis un projet final qui outille le poste de travail d'un analyste. Les scripts sont en Bash, comme à l'atelier.

Entraînement rapide (acquisition)

Échauffement
  1. Lit n niveaux de risque (sommes de 2 à 6) et affiche le libellé : Faible (2-3), Moyenne (4-5), Critique (6).
  2. Lit n lettres C, I ou D et affiche le nom complet de la composante, puis le compteur de chaque lettre.
  3. Lit n mots de passe et affiche ok si la longueur atteint 12, court sinon.
  4. Lit n liens et affiche https pour ceux qui commencent par https://, suspect sinon.
Corrections
read -r n
for ((i=0; i<n; i++)); do
  read -r somme
  if [ "$somme" -le 3 ]; then echo "Faible"
  elif [ "$somme" -le 5 ]; then echo "Moyenne"
  else echo "Critique"; fi
done

read -r n
c=0 ; i=0 ; d=0
for ((k=0; k<n; k++)); do
  read -r lettre
  case "$lettre" in
    C) echo "confidentialité" ; c=$((c + 1)) ;;
    I) echo "intégrité" ; i=$((i + 1)) ;;
    D) echo "disponibilité" ; d=$((d + 1)) ;;
  esac
done
echo "C : $c"
echo "I : $i"
echo "D : $d"

read -r n
for ((k=0; k<n; k++)); do
  read -r mot
  if [ "${#mot}" -ge 12 ]; then echo "ok" ; else echo "court"; fi
done

read -r n
for ((k=0; k<n; k++)); do
  read -r lien
  case "$lien" in
    https://*) echo "https" ;;
    *) echo "suspect" ;;
  esac
done

Application

Application
  1. Verrouillage de compte : lit n événements « reussite » ou « echec » et affiche BLOQUE au 3e échec consécutif, sinon ok.
  2. Politique de mots de passe : liste noire (3 mots interdits), longueur au moins 10, aucune répétition du mot précédent.
  3. Confinement : lit n alertes mineure/majeure et affiche l'action (journaliser, isoler) puis le total d'alertes majeures.
  4. Guichet 3-2-1 : lit n lignes « copies supports hors_site » et affiche conforme ou la règle manquante.

Raisonnement

Raisonnement
  1. Corrélation d'alertes : lit n alertes horodatées et regroupe par actif, puis signale l'actif avec le plus d'alertes.
  2. Chaîne d'attaque : lit n étapes reconnaissance/exploitation/exfiltration et affiche la première étape atteinte et la dernière.
  3. Comparateur de politiques : lit deux politiques (longueur, renouvellement en jours) et affiche celle qui est la plus stricte.
  4. Résumé d'incident : lit n événements horodatés et calcule la durée entre détection et confinement (fin - début).

debut=""
fin=0

  read -r heure evenement
  if [ "$evenement" = "detection" ] && [ -z "$debut" ]; then debut="$heure"; fi

Projet intégrateur — « poste de l'analyste »

Cahier des charges

Le script reçoit n événements au format heure evenement detail — heure croissante en minutes (0 à 1439), evenement parmi echec (detail : IP), reussite (detail : IP), malware (detail : poste), correctif (detail : poste). Il applique les règles du cours : seuil de 3 échecs par IP avant tout succès, verrouillage de l'IP fautive, isolement immédiat d'un poste infecté, obligation de correctif sur un poste touché dans les 90 jours. Le rapport final affiche les verrouillages, les isolements, les correctifs exigés et le bilan.

Fonctionnalités attendues
  1. Lire les événements dans l'ordre chronologique, sans en sauter.
  2. Compter les échecs par IP avec un tableau associatif, et verrouiller au seuil.
  3. Isoler un poste à la première détection de malware, une seule fois par poste.
  4. Exiger le correctif sur chaque poste isolé, même s'il arrive après l'alerte.
  5. Bilan : totaux par catégorie, après la boucle, formats exacts.

Contraintes : declare -A pour les compteurs par IP et par poste, drapeaux de verrouillage/isolement, aucun affichage de bilan dans la boucle.

Grille d'auto-évaluation du projet (sur 100)
Lecture chronologique et découpage des champs 20
Comptage par IP et verrouillage au seuil 20
Isolement unique des postes infectés 20
Exigence de correctifs conforme 20
Bilan final lisible et complet 20

Objectif : ≥ 95/100 avant de considérer le projet terminé.

Voir une solution de référence (après avoir essayé !) 
read -r n
declare -A echecs
declare -A verrouille
declare -A isole
declares_verrouillages=0
declares_isolements=0
declares_correctifs=0
for ((k=0; k<n; k++)); do
  read -r heure evenement detail
  if [ "$evenement" = "echec" ]; then
    if [ "${verrouille[$detail]:-0}" = "1" ]; then continue ; fi
    echecs["$detail"]=$(( ${echecs[$detail]:-0} + 1 ))
    if [ "${echecs[$detail]}" -ge 3 ]; then
      verrouille[$detail]=1
      echo "verrouillage : $detail"
      declares_verrouillages=$((declares_verrouillages + 1))
    fi
  elif [ "$evenement" = "malware" ]; then
    if [ "${isole[$detail]:-0}" = "0" ]; then
      isole[$detail]=1
      echo "isolement : $detail"
      declares_isolements=$((declares_isolements + 1))
    fi
  elif [ "$evenement" = "correctif" ] && [ "${isole[$detail]:-0}" = "1" ]; then
    echo "correctif exigé : $detail"
    declares_correctifs=$((declares_correctifs + 1))
  fi
done
echo "verrouillages : $declares_verrouillages"
echo "isolements : $declares_isolements"
echo "correctifs : $declares_correctifs"
Cette solution combine lecture chronologique, comptage associatif, drapeaux d'état et bilan final — les chapitres 4 et 5 en un seul script.
