Atelier de scripts

Un éditeur dans la page, un vrai interpréteur Bash derrière. Écrivez un script, exécutez-le et lisez ce qu'il affiche : c'est ici qu'une commande Git devient un programme.

Comment fonctionne l'atelier
  • Exécuter fait tourner votre script Bash tel quel et affiche sa sortie, ses erreurs et son code de sortie.
  • Entrée du programme contient ce que read lira, une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n'écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l'éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Zone libre

Zone libre — journal de commits

Bash

Objectif : expérimenter sans conséquence. Prenez un mécanisme de Git (index, branches, push refusé, stash), programmez-le et testez-le sur des cas limites.

Le script proposé numérote des commits et sait annuler. Ajoutez des branches, un compteur de push refusés, ou remplace tout le script par le mécanisme que vous voulez vérifier.

Dans un vrai terminal, ce sera git log --oneline et git revert : la structure du script — lire, décider, rapporter — reste exactement la même.

De la page au vrai terminal

La simulation a une limite assumée : aucun dépôt réel n'est écrit sur disque. Elle a une force : toute la logique se vérifie sans risque — on peut casser un dépôt simulé autant de fois que nécessaire. Quand le script reproduit les bons trajets entre copie, index, dépôt et distant, le passage aux vraies commandes est mécanique.

Les trois erreurs que l'atelier révèle immédiatement
  • Ordre des lectures inversé : le script lit un argument avant n, ou déstructure mal « operation message ».
  • Compteur réinitialisé dans la boucle : le numéro de commit repart à 1 à chaque ligne.
  • Bilan dans la boucle : l'état des trois espaces s'affiche à chaque opération au lieu d'une seule fois, après.
Ce que fait l'atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d'exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n'est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d'exécutions est limité par jour, pour tout le monde. L'atelier n'exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices Bash corrigés automatiquement dans la page. Une fois l'atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme Git est vraiment acquis.
