Module 2 — Index et commits : add, reset, commit

QuestionOptions de git add : -A vs -u ?
Réponse-A : nouveaux, modifiés, détruits. -u : modifications et destructions des fichiers déjà suivis seulement.
QuestionRetirer du suivi un fichier déjà commité ?
Réponsegit rm --cached fichier (il reste sur disque), puis commit. Le .gitignore seul ne suffit pas.
Questionreset HEAD vs rm --cached ?
Réponsereset HEAD retire de l'index (le fichier reste suivi) ; rm --cached retire aussi le suivi.
QuestionQue se passe-t-il après git commit ?
RéponseL'index est transféré au dépôt (une entrée SHA-1 + message) et l'index se vide.
QuestionQuand commit --amend ?
RéponsePour corriger le dernier commit avant tout push : il crée un nouveau SHA-1.
QuestionQu’est-ce que « git reset HEAD » (Ch. 2) ?
Réponseretirer un fichier de l'index avec git reset HEAD et git rm --cached ;

Module 3 — Historique et annulations : log, reset, revert

QuestionLes trois options de git reset ?
Réponse--soft : commits remontés dans l'index ; --mixed (défaut) : index vidé, copie gardée ; --hard : tout aligné sur le commit cible.
Questionreset vs revert ?
Réponsereset réécrit l'historique (local, avant push) ; revert ajoute un commit d'annulation (dépôts partagés).
Questiongit diff --cached montre quoi ?
RéponseLes différences entre l'index et le dépôt local — ce qui partira au prochain commit.
QuestionQue montre git log --follow ?
RéponseL'historique d'un fichier, renommages compris.

Module 4 — Branches : isoler, fusionner, supprimer

QuestionCréer une branche et s'y placer ?
Réponsegit checkout -b nom (équivaut à git branch nom puis git checkout nom).
QuestionQu'est-ce qu'un fast-forward ?
RéponseUne fusion qui avance simplement le pointeur de main : aucun commit de fusion, plus de trace de la branche.
QuestionPourquoi --no-ff ?
RéponsePour créer un commit de fusion même quand ff est possible : la branche de fonctionnalité reste visible dans l'historique.
QuestionLes marqueurs de conflit ?
Réponse<<<<<<< HEAD (version courante), =======, >>>>>>> branche (version fusionnée) : à éditer puis add + commit.

Module 5 — Dépôt distant : clone, push, pull, fetch

QuestionLier un dépôt local au distant ?
Réponsegit remote add origin URL, puis git push -u origin main ; vérification avec git remote -v.
QuestionPourquoi un push est-il rejeté ?
RéponseLe distant contient des commits absents du local : il faut pull (fetch + merge) puis repousser.
Questionfetch vs pull ?
Réponsefetch actualise les références distantes sans fusionner ; pull = fetch + merge, il avance aussi la branche courante.
QuestionQue fait push -u origin main ?
RéponseIl pousse main et la lie (upstream) à origin/main pour les échanges futurs.
QuestionQu’est-ce que « dépôt distant » (Ch. 5) ?
Réponselier un dépôt local à un dépôt distant avec git remote add origin ;

QuestionLe trio stash ?
Réponsestash remise (copie propre), pop reprend la dernière (et la retire), drop la détruit ; list montre la pile.
Question.gitignore minimal d'un projet Python ?
Réponse__pycache__/ (cache), *.pyc (compilés), venv/ (environnement virtuel).
QuestionRetirer du suivi un fichier déjà commité (Ch. 6) ?

QuestionQue fait git archive --format=tar --prefix=d/ HEAD ?
