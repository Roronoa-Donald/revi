Chapitre 6 — Stash, gitignore et publication

Module 6 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Dernier tour d'outils du semestre : remiser un travail en cours pour changer de branche sans perdre une ligne, tenir un .gitignore qui protège vraiment l'historique, livrer une archive propre, et publier une page d'accueil avec GitHub Pages — le TP4 dans son intégralité.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. remiser et reprendre des modifications avec stash, pop et list ;
  2. construire un .gitignore effectif pour un projet réel ;
  3. produire une archive de version avec git archive ;
  4. publier une page via GitHub Pages (README, index.html, Settings).

1. stash : remiser sans committer

La copie de travail est modifiée, et Git bloque toute opération qui changerait son contenu : changer de branche, rapatrier un commit. Deux solutions : commiter (mais cela laisse une trace dans l'historique) ou remiser temporairement :

git stash            remise : la copie redevient propre, les modifications patientent
git stash pop        reprend la remise la plus récente et la supprime de la pile
git stash list       liste les remises en attente
git stash drop       supprime la remise la plus récente

Après un stash, on se retrouve dans le même état qu'après un reset --hard — mais les modifications ne sont pas perdues : elles dorment dans la pile des remises. C'est la solution honnête avant un checkout -f ou un reset --hard.

Mnémotechnique — « la panière du artisan »

stash est une panière : on y dépose le chantier en cours pour libérer la table, on le ressort avec pop. La panière empile : dernier déposé, premier ressorti.

2. .gitignore en conditions réelles

Le chapitre 2 a posé la syntaxe ; ici, le contenu d'un vrai projet Python (celui du TP1) :

__pycache__/
*.pyc
venv/

Chaque motif cible une pollution : __pycache__/ le cache d'exécution, *.pyc les fichiers compilés, venv/ l'environnement virtuel. Règle de maintien : le .gitignore se met à jour dès qu'un fichier parasite apparaît dans git status — et pour les fichiers déjà suivis, rappel du chapitre 2, git rm --cached d'abord.

La commande git ls-files --other --ignored --exclude-standard liste tous les fichiers exclus du suivi dans le projet : le moyen de vérifier que le .gitignore fait son travail.

Piège — plusieurs .gitignore

Plusieurs .gitignore répartis dans les sous-dossiers se cumulent, mais la pratique est fortement déconseillée : les motifs peuvent s'annuler les uns les autres. Un .gitignore à la racine, sauf besoin très particulier.

3. git archive : livrer sans .git

Pour avoir une archive de la version de votre dépôt sans les fichiers inutiles tel le dossier .git :

cd depot
git archive --format=tar --prefix=dossier/ HEAD | gzip > v1.4.0.tar.gz

L'archive v1.4.0.tar.gz contient la dernière version de la branche courante. Décompressée, elle crée un dossier portant le préfixe demandé avec tous les fichiers du dépôt — et rien d'autre : ni historique, ni fichiers ignorés.

Le réflexe qualité

Une livraison propre = git archive depuis un historique propre = un .gitignore tenu à jour. Les trois outils du semestre se rejoignent : ce qui n'est pas suivi ne part pas dans l'archive.

4. Publier : README et GitHub Pages

Le TP4 publie le projet sur GitHub avec une vraie page d'accueil. Les étapes :

1. créer le dépôt sur GitHub (public)
2. lier : git remote add origin ... ; git push -u origin main
3. rédiger un README.md structuré : titre, description, fonctionnalités,
   installation (git clone + lancement), auteur
4. créer une page d'accueil index.html minimaliste
5. Settings → Pages → Source : branch main, dossier /root
6. l'URL https://<user>.github.io/gestion_taches/ sert la page

Le README professionnel du TP4 suit un plan fixe : # Titre, ## Description, ## Fonctionnalités (une liste), ## Installation (un bloc de code), auteur. Chaque modification passe par le cycle du chapitre 2 : add, commit avec message net, push.

Bash Niveau 1 — Acquisition

Objectif : Simuler git stash / stash pop : les modifications partent en attente puis reviennent.

Le script lit n opérations : modifie (une modification de plus sur la copie), stash (empile toute la copie : elle devient propre), pop (dépile : les modifications remises reviennent ; si la pile est vide, affiche rien à reprendre), ou etat (affiche copie : K et remises : K).

Deux indices, rédigés en mots
  1. stash transfère tout le compteur de copie dans la pile : la copie repart à zéro.
  2. pop rend ce qui était remisé : copie + remise dépilée.

Exercice 2 — gitignore : filtrer les adds

Bash Niveau 2 — Application

Objectif : Appliquer les motifs .gitignore aux fichiers ajoutés à l’index.

Le script lit d’abord g motifs (un par ligne : un nom exact comme build/ filtre le dossier build ; un suffixe comme *.log filtre tout fichier finissant par .log). Puis n opérations : add fichier ou index. Un add d’un fichier filtré est refusé avec ignoré ; l’index affiche ses fichiers, un par ligne, dans l’ordre.

Entrée du programme
2
*.log
build/
3
add main.py
add debug.log
index
Sortie attendue
ignoré
main.py

debug.log tombe sous le coup de *.log : l'add est refusé.

Deux indices, rédigés en mots
  1. Deux familles de motifs : ceux qui finissent par / (dossier : le fichier commence par ce nom) et ceux qui commencent par * (suffixe).
  2. Un motif exact sans * ni / filtre le fichier de ce nom exact.

Exercice 3 — archive : le rapport de version

Bash Niveau 3 — Raisonnement

Objectif : Produire le récapitulatif d’une version : fichiers versionnés, ignorés exclus, taille totale.

Le script lit n lignes taille nom (taille en Ko, nom de fichier). Il affiche un rapport : fichiers : K, taille : T (somme des tailles, T en Ko), plus gros : NOM (premier fichier de taille maximale), puis la liste des fichiers de taille strictement supérieure à la moyenne entière (somme ÷ nombre, division entière), un par ligne, dans l’ordre d’entrée — ou rien si aucun.

Deux indices, rédigés en mots
  1. La moyenne entière se calcule après la boucle : division entière de la somme par n.
  2. Un tableau parallèle noms/tailles permet un second passage pour la liste.

6. QCM — niveau examen

Que fait git stash ?

stash empile les modifications de la copie : elle redevient propre, rien ne se perd.

git stash pop fait quoi ?

pop dépile : les modifications remises reviennent dans la copie de travail.

pop sur une pile vide…

Sans remise en attente, pop n'a rien à rendre — l'atelier reproduit ce cas.

Quel .gitignore pour un projet Python du TP1 ?

Cache d'exécution, fichiers compilés et environnement virtuel : les trois pollutions du TP1.

Comment vérifier ce que le .gitignore exclut ?

Cette commande liste tous les fichiers exclus du suivi dans le projet.

Que produit git archive ?

archive livre la branche courante en tar/tar.gz, préfixe de dossier au choix.

Où active-t-on GitHub Pages ?

Le service se règle dans Settings → Pages : il sert l'URL user.github.io/depot.

Stash ou commit avant de changer de branche ?

stash remise sans polluer l'historique : idéal pour un chantier inachevé.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Commit de chantier par flemme de stash : l'historique se remplit de traces inutiles.
  • drop au lieu de pop : la remise la plus récente est détruite au lieu d'être reprise.
  • .gitignore multi-niveaux : les motifs se cumulent et peuvent s'annuler.
  • Archive d'un historique pollué : les fichiers ignorés manquent, les suivis encombrants partent.
  • README sans plan : sans titre, description, installation, la page d'accueil ne raconte rien.

8. Méthodologie de résolution

Livrer une version propre
  1. Nettoyer la copie : status, puis stash ou commit des chantiers.
  2. Vérifier les exclusions : ls-files --other --ignored pour auditer le .gitignore.
  3. Archiver : git archive avec préfixe et version nommée.
  4. Documenter : README au plan fixe, mis à jour à chaque fonctionnalité.
  5. Publier : push, puis Pages pour la page d'accueil.

9. Révision active

Résumé essentiel
  • stash remise la copie (propre immédiatement) ; pop reprend, list liste, drop détruit.
  • Un .gitignore Python tient en trois lignes : __pycache__/, *.pyc, venv/.
  • Les fichiers déjà suivis sortent du suivi par rm --cached, pas par .gitignore.
  • git archive livre la version courante en tar.gz, sans .git ni fichiers ignorés.
  • GitHub Pages sert l'URL du projet depuis la branche main, dossier /root.
