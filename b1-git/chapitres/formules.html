Mémo Git

Les commandes du cours sur une page, dans l'ordre des trajets. À garder ouvert pendant les exercices et l'atelier.

Les trois espaces

copie de travail   fichiers du développeur

index              zone de transit (ce qui partira au commit)

dépôt local (HEAD) historique des versions



copie ──add──→ index ──commit──→ dépôt

copie ←──reset HEAD── index ←──checkout── dépôt

status observe sans rien déplacer ; diff compare deux espaces.

Créer et configurer

git init [projet]        crée .git (le dépôt local)

git clone url            télécharge projet + historique + origin

git config --global user.name "Nom"

git config --global user.email "mail"   (ou sans --global : par projet)

git config --list        vérifier

Sans identité, le commit est refusé ou signé faux : configurer avant tout.

Index et commits

git add fichier | dossier | .    dépose dans l'index

git add -A    nouveaux + modifiés + détruits

git add -u    modifiés + détruits des fichiers suivis seulement

git reset HEAD fichier    sort de l'index (reste suivi)

git rm fichier            copie + index | --cached : index seul

git commit -m "Message"   archive l'index (SHA-1)

git commit --amend -m     réécrit le dernier commit (avant push)

Le commit archive l'état de l'index au moment du add : modifier après = re-add.

.gitignore

fichier      un nom exact

dossier/     un dossier entier

*.pyc        un suffixe (* = tout ce qui finit par)



__pycache__/   *.pyc   venv/          (projet Python du TP1)



git ls-files --other --ignored --exclude-standard   auditer les exclus

git rm --cached fichier    dé-suivre un fichier déjà commité

Le .gitignore ne s'applique qu'aux fichiers pas encore suivis.

Historique et annulations

git log --oneline [--graph --all]      l'historique lisible

git show SHA                le contenu d'un commit

git diff [--cached | --staged]        copie↔index | index↔dépôt

git diff brancheA..brancheB           deux branches



git reset --soft HEAD~n    commits remontés dans l'index

git reset --mixed HEAD~n   (défaut) index vidé, copie gardée

git reset --hard HEAD~n    tout effacé après le commit cible

git revert HEAD^           annule EN AJOUTANT un commit (partagé)

reset réécrit le passé (local) ; revert écrit l'inverse (partagé).

Branches et fusion

git branch nom             crée | -v : locales | -r : distantes | -d : supprime

git checkout nom           bascule | -b nom : crée + bascule | -f : force (perd)

git checkout main && git merge feature    fusionne dans main

git merge --abort          annule un merge en cours

fast-forward               avance le pointeur, plus de trace de la branche

--no-ff                    crée un commit de fusion (branche visible)

Conflit = même zone, deux versions : lire, décider, add, commit.

Distant, stash, archive

git remote add origin url    lie le distant | -v : vérifie

git push [-u origin main]    envoie | rejeté = pull d'abord

git fetch origin             actualise les références, sans fusionner

git pull                     fetch + merge



git stash | pop | list | drop    remise / reprise / pile / destruction



git archive --format=tar --prefix=d/ HEAD | gzip > v1.tar.gz

GitHub Pages : Settings → Pages → branch main, /root

Rejet et conflit sont des protections : on les résout, jamais on ne les contourne.

Erreurs fréquentes à éviter

  • Committer sans user.name/user.email configurés.
  • Croire que .gitignore dé-suivra un fichier déjà commité.
  • reset --hard sur un dépôt partagé (ou sans stash au préalable).
  • Amend après push : le SHA change pour tout le monde.
  • Forcer un push au lieu de pull et résoudre.
  • Committer des marqueurs de conflit <<<<<<< par add aveugle.
