Examen blanc n°1

Sujet type TP noté — premier dépôt, index, historique.

Exercice 1/5 — Premier dépôt

Écrire la séquence complète du TP1 : créer le projet gestion_taches, initialiser le dépôt, configurer l'identité globalement, vérifier, ajouter les fichiers et réaliser le premier commit. Que se passe-t-il si l'identité n'est pas posée ?

Corrigé
mkdir gestion_taches ; cd gestion_taches ; touch main.py taches.py utils.py README.md ; git init ; git config --global user.name "Nom" ; git config --global user.email "mail" ; git config --list ; git status ; git add . ; git commit -m "Initialisation du projet gestion_taches".
Sans identité : le commit peut être refusé ou signé d'une identité incorrecte.
Exercice 2/5 — Index

Vous avez modifié main.py et créé debug.log, venv/ et __pycache__. Écrire le .gitignore adapté et la séquence qui n'indexe que les modifications de fichiers suivis. Quelle option de git add fait cela ?

Corrigé
.gitignore : __pycache__/, *.pyc, venv/ (debug.log peut s'ajouter : *.log).
Sélection des suivis seuls : git add -u — il indexe modifications et destructions des fichiers déjà suivis, sans ramasser les nouveaux.
Exercice 3/5 — Annulations

Trois commits ont été faits localement (a1, a2, a3). Décrire l'état des trois espaces après git reset --soft HEAD~1, puis --mixed, puis --hard. Quel choix si les commits ont été poussés ?

Corrigé
--soft : HEAD sur a2, index contient les modifications de a3, copie intacte. --mixed (défaut) : HEAD sur a2, index vidé, les modifications restent dans la copie. --hard : HEAD sur a2, index vide, copie effacée.
Commits poussés → git revert : il ajoute un commit d'annulation sans réécrire l'historique partagé.
Exercice 4/5 — Lecture

Expliquer la différence entre git diff, git diff --cached et git status. Que ne montre jamais git diff ?

Corrigé
git diff : copie de travail ↔ index. --cached : index ↔ dépôt local (ce qui partira au prochain commit). status : l'état des lieux, catégories comprises.
diff ne montre jamais les fichiers non suivis — ils restent dans status.

Examen blanc n°2 — variante

Sujet orienté branches, collaboration et publication.

Exercice 1/5 — Branches

Dérouler le workflow du TP3 : créer feature-ajout-tache depuis main, deux commits atomiques, fusion, envoi, analyse, suppression de la branche. Que constate-t-on sur git log --graph si la fusion est fast-forward ?

Corrigé
git checkout main ; git checkout -b feature-ajout-tache ; deux couples add+commit ; git checkout main ; git merge feature-ajout-tache ; git push origin main ; git log --oneline --graph --all ; git branch -d feature-ajout-tache.
En fast-forward, l'historique reste droit : plus aucune trace de la branche (contre un commit de fusion avec --no-ff).
Exercice 2/5 — Conflit

Deux branches modifient la même ligne de main.py. Décrire les marqueurs de conflit, identifier chaque section, et donner la séquence de validation après résolution.

Corrigé
« <<<<<<< HEAD » ouvre la version de la branche courante, « ======= » sépare, « >>>>>>> branche » ferme la version fusionnée.
Résolution : éditer (garder/combiner), plus aucun marqueur, puis git add main.py et git commit -m "Résolution du conflit".
Exercice 3/5 — Distant

Rejouer le TP2 : l'étudiant A pousse, B committe puis push. Que se passe-t-il et pourquoi ? Quelle séquence débloque la situation ? Que vaut un push --force ici ?

Corrigé
Le push de B est rejeté : le distant contient des commits (de A) que B n'a pas. Déblocage : git pull origin main (fetch + merge, conflit possible), résolution, puis push.
--force écraserait le travail de A : à proscrire sur un dépôt partagé.
Exercice 4/5 — Publication

Décrire les étapes du TP4 pour publier le projet : lien distant, README structuré, page d'accueil, activation GitHub Pages. Où s'active la page et quelle URL en résulte ?

Corrigé
remote add origin + push -u origin main ; README au plan # Titre / ## Description / ## Fonctionnalités / ## Installation / auteur ; index.html minimal ; Settings → Pages → Source : main, /root.
URL : https://<user>.github.io/gestion_taches/.

QCM final — toutes notions

git init crée…

Tout le dépôt local vit dans .git.

git add -u sélectionne…

-u ignore les nouveaux : uniquement modifications et destructions des fichiers suivis.

Un fichier suivi ajouté au .gitignore…

Il faut git rm --cached pour dé-suivre.

reset --hard fait quoi de la copie ?

hard aligne les trois espaces : modifications locales perdues.

Sur un dépôt partagé, annuler avec…

revert ajoute un commit d'annulation : l'historique partagé reste cohérent.

En fast-forward, la branche fusionnée…

Les commits s'enchaînent comme sur main ; --no-ff grave un commit de fusion.

Un push rejeté signifie…

Pull (fetch + merge) d'abord, puis repousser.

git fetch…

fetch écoute ; pull = fetch + merge.

git stash puis git stash pop : la copie…

stash empile, pop dépile : rien ne se perd.

GitHub Pages s'active dans…

Source : branch main, dossier /root → URL user.github.io/depot.
