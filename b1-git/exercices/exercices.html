Exercices supplémentaires & projet intégrateur

De la pratique graduée pour consolider chaque module, puis un projet final qui gère la collaboration complète d'un dépôt versionné. Les scripts sont en Bash, comme à l'atelier.

Entraînement rapide (acquisition)

Échauffement
  1. Lit n puis n commandes « commande » et affiche ok pour chaque commande connue (init, add, commit, push, pull).
  2. Lit n commits et affiche le nombre total, la tête HEAD (dernier numéro) et le premier numéro.
  3. Lit n opérations add/commit et affiche combien de fichiers sont restés en index à la fin.
  4. Lit un SHA abrégé (comme a1b2) et affiche sa longueur et son premier caractère.
Corrections

connues="init add commit push pull"

    *) echo "inconnue" ;;
  esac
done

  read -r mot

read -r n
index=0
for ((i=0; i<n; i++)); do
  read -r op
  if [ "$op" = "add" ]; then index=$((index + 1)); fi
  if [ "$op" = "commit" ]; then index=0; fi
done
echo "en index : $index"

read -r sha
echo "longueur : ${#sha}"
echo "premier : ${sha:0:1}"

Application

Application
  1. Simule git stash : lit n opérations modifie/stash/pop et affiche l'état final (copie, remises).
  2. Valide des messages de commit : majuscule, 50 caractères max, sans point final.
  3. Lit n fichiers « nom taille » et affiche les trois plus gros dans l'ordre (tri simple).
  4. Simule un .gitignore à un motif (*.ext) : refuse les adds filtrés, liste l'index.
Corrections
read -r n
copie=0
remises=0
for ((i=0; i<n; i++)); do
  read -r op
  if [ "$op" = "modifie" ]; then copie=$((copie + 1)); fi
  if [ "$op" = "stash" ]; then remises=$((remises + 1)); copie=0; fi
  if [ "$op" = "pop" ] && [ "$remises" -gt 0 ]; then remises=$((remises - 1)); fi
done
echo "copie : $copie"
echo "remises : $remises"

read -r n
for ((i=0; i<n; i++)); do
  read -r message
  premiere="${message:0:1}"
  if [ "$premiere" != "${premiere^^}" ]; then echo "majuscule"
  elif [ "${#message}" -gt 50 ]; then echo "longueur"
  elif [ "${message: -1}" = "." ]; then echo "point final"
  else echo "ok"; fi
done

read -r n
noms=()
tailles=()
for ((i=0; i<n; i++)); do
  read -r nom taille
  noms+=("$nom")
  tailles+=("$taille")
done
for ((i=0; i<3 && i<n; i++)); do
  max=-1
  idx=-1
  for k in "${!tailles[@]}"; do
    [ "${tailles[$k]}" -gt "$max" ] && { max="${tailles[$k]}"; idx=$k; }
  done
  echo "${noms[$idx]} ${tailles[$idx]}"
  unset "noms[$idx]"
  unset "tailles[$idx]"
  noms=("${noms[@]}")
  tailles=("${tailles[@]}")
done

read -r motif
read -r n
suffixe="${motif:1}"
for ((i=0; i<n; i++)); do
  read -r op fichier
  if [ "$op" = "add" ]; then
    if [ "${fichier: -${#suffixe}}" = "$suffixe" ]; then echo "ignoré"
    else index+=("$fichier"); fi
  else for f in "${index[@]}"; do echo "$f"; done; fi
done

Raisonnement

Raisonnement
  1. Simule deux branches avec commits parallèles puis une fusion : affiche l'historique combiné.
  2. Décompose pull : lit les opérations tierce/fetch/merge et affiche local, origin/main et copie.
  3. Décode un conflit : lit un fichier avec marqueurs et affiche les deux versions côte à côte.
  4. Compte les trajets : pour n opérations, affiche combien de fichiers ont traversé copie→index→dépôt.
Corrections
read -r n
main=()
feature=()
num_main=0
num_feature=0
for ((i=0; i<n; i++)); do
  read -r branche message
  if [ "$branche" = "main" ]; then num_main=$((num_main + 1)); main+=("m$num_main $message")
  else num_feature=$((num_feature + 1)); feature+=("f$num_feature $message"); fi
done
echo "--- main ---"
for ligne in "${main[@]}"; do echo "$ligne"; done
echo "--- feature ---"
for ligne in "${feature[@]}"; do echo "$ligne"; done

read -r n
local=0
origin=0
for ((i=0; i<n; i++)); do
  read -r op
  if [ "$op" = "commit" ]; then local=$((local + 1)); fi
  if [ "$op" = "tierce" ]; then origin=$((origin + 1)); fi
  if [ "$op" = "fetch" ]; then echo "fetch : origin/main = $origin (copie inchangée)"; fi
  if [ "$op" = "merge" ] && [ "$origin" -gt "$local" ]; then local=$origin; echo "merge : avance à $local"; fi
done
echo "local : $local"
echo "origin/main : $origin"

read -r n
dans_conflit=0
for ((i=0; i<n; i++)); do
  read -r ligne
  case "$ligne" in
    "<<<<<<<"*) dans_conflit=1 ;;
    "=======") echo "-- vs --" ;;
    ">>>>>>>"*) dans_conflit=0 ;;
    *) [ "$dans_conflit" = "1" ] && echo "$ligne" ;;
  esac
done

read -r n
trajet_complet=0
etape=0
for ((i=0; i<n; i++)); do
  read -r op
  if [ "$op" = "add" ]; then etape=1; fi
  if [ "$op" = "commit" ] && [ "$etape" = "1" ]; then trajet_complet=$((trajet_complet + 1)); etape=0; fi
done
echo "copie→index→dépôt : $trajet_complet"

Projet intégrateur — « dépôt de binôme »

Cahier des charges

Deux développeurs travaillent sur le projet gestion_taches. Le script lit n opérations au format acteur operation [argument] — acteur vaut A ou B, operation parmi commit (message), push, pull. Le dépôt distant rejette un push si l'autre acteur a poussé depuis le dernier pull de cet acteur. Le rapport final affiche le nombre de push réussis, refusés, les conflits détectés (push refusé suivi direct d'un push sans pull entre les deux) et l'état final des deux copies.

Fonctionnalités attendues
  1. Lire les opérations dans l'ordre, acteur par acteur, sans mélanger.
  2. Suivre par acteur : commits locaux en attente et fraîcheur (pull vu).
  3. Arbitrer : le distant avance à chaque push réussi.
  4. Compter : pushs réussis, rejetés, pulls effectués.
  5. Recommander : « pull recommandé pour X » si X tente un push avec un distant en avance.
  6. Formater : libellés exacts, un compte par ligne.

Contraintes : deux structures parallèles (une par acteur), pas de variable globale de copie, bilan après la boucle.

Grille d'auto-évaluation du projet (sur 100)
Lecture et séparation par acteur 20
Suivi des états par acteur correct 20
Arbitrage du distant conforme 20
Comptes et recommandations exacts 20
Lisibilité, noms, formats 20

Objectif : ≥ 95/100 avant de considérer le projet terminé.

Voir une solution de référence (après avoir essayé !) 
read -r n
commits_a=0 ; commits_b=0
frais_a=1 ; frais_b=1
distant=0
ok_push=0 ; ko_push=0 ; pulls=0
for ((i=0; i<n; i++)); do
  read -r acteur operation reste
  if [ "$operation" = "commit" ]; then
    if [ "$acteur" = "A" ]; then commits_a=$((commits_a + 1)); else commits_b=$((commits_b + 1)); fi
  elif [ "$operation" = "pull" ]; then
    if [ "$acteur" = "A" ]; then frais_a=1 ; [ "$distant" -gt "$commits_a" ] && commits_a=$distant
    else frais_b=1 ; [ "$distant" -gt "$commits_b" ] && commits_b=$distant; fi
    pulls=$((pulls + 1))
  elif [ "$operation" = "push" ]; then
    if [ "$acteur" = "A" ]; then locaux=$commits_a ; frais=$frais_a
    else locaux=$commits_b ; frais=$frais_b; fi
    if [ "$locaux" -gt "$distant" ] && [ "$frais" = "1" ]; then
      distant=$locaux
      if [ "$acteur" = "A" ]; then frais_b=0; else frais_a=0; fi
      ok_push=$((ok_push + 1))
    else
      ko_push=$((ko_push + 1))
      echo "pull recommandé pour $acteur"
    fi
  fi
done
echo "push réussis : $ok_push"
echo "push refusés : $ko_push"
echo "pulls : $pulls"
echo "commits A : $commits_a"
echo "commits B : $commits_b"
echo "distant : $distant"
Cette solution combine lecture par acteur, suivi d'états parallèles, arbitrage du distant et rapport final — les chapitres 1, 2 et 5 en un seul script.
