Chapitre 2 — Arborescence et système de fichiers

Module 2 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Sous Windows, chaque disque a sa lettre : C:, D:. Sous Linux, il n’y a qu’un seul arbre qui part de une racine unique, et tout — documents, périphériques, processus — y prend place comme fichier. Avant de taper la moindre commande, il faut savoir lire cette carte : où vivent les configurations, les répertoires personnels, les fichiers temporaires, les journaux.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. décrire l’arborescence hiérarchique issue de la racine ;
  2. associer chaque répertoire standard (/etc, /home, /var, /tmp…) à son rôle ;
  3. expliquer « tout est fichier » et le rôle des inodes et métadonnées ;
  4. distinguer partition principale, étendue et logique, et monter un système de fichiers.

1. Un arbre unique, une racine

Le système de fichiers de Linux est hiérarchique : une arborescence de répertoires et de sous-répertoires qui part d’un élément de base noté / — la racine (root directory). Tout chemin absolu commence par ce slash : /etc/passwd, /home/alice/notes.txt.

/                      la racine : origine de tout
├── boot               noyau et ressources de démarrage
├── dev                fichiers des périphériques (devices)
├── etc                fichiers de configuration du système et des démons
├── home               répertoires personnels des utilisateurs
├── proc               arborescence virtuelle du noyau (lecture seule, sauf /proc/sys)
├── root               répertoire personnel du super-utilisateur
├── tmp                fichiers temporaires, pouvant être supprimés selon la politique locale
├── usr                applications, documentation, manuels, librairies
│   └── local          installation des logiciels supplémentaires
├── var                fichiers variables : journaux des démons, spools (mail, impression, cron)
├── bin   et   sbin    binaires indispensables au démarrage et commandes d’administration
└── lib   et   usr/lib librairies nécessaires à ces commandes
Mnémotechnique — « etc = étagère de config »

Retenez par contrastes : /etc est l’étagère de configuration (à sauvegarder pour restaurer la configuration, avec les données sauvegardées séparément), /home les maisons des utilisateurs, /tmp la table temporaire qui peut être débarrassée, /var les journaux qui varient, /root la maison de root — qui n’est pas dans /home.

2. Tout est fichier

Dans les systèmes Linux, tout est fichier : contrairement à Windows, un fichier Linux peut être un fichier de données, un périphérique, une partition, un programme en cours d’exécution ou un répertoire. C’est pourquoi les disques vivent dans /dev (devices) : sda pour un disque SCSI, hda pour un disque IDE.

Un fichier est décrit par des propriétés appelées métadonnées : sous Linux, l’inode. Les données, elles, sont placées dans d’autres blocs du support de stockage. Droits, propriétaire et taille figurent dans l’inode. Le nom est une entrée de répertoire associée à un inode : deux liens physiques de noms différents peuvent partager le même inode et désigner ainsi le même fichier.

Piège — /root n’est pas /

La racine de l’arbre est / ; /root est le répertoire personnel du super-utilisateur. Les deux se prononcent presque pareil et se confondent en examen : la racine n’a pas de nom, /root a un habitant.

3. Systèmes de fichiers : ext et compagnie

Un système de fichiers (File System, FS) définit l’organisation des données sur un support de stockage : comment sont gérés et organisés les fichiers par l’OS. Les principaux sous Linux :

FSÀ retenir
ext2le FS historique de Linux, aux normes Unix, non journalisé
ext3successeur d’ext2 (1999), journalisé, convertible depuis ext2 en quelques secondes
ext4évolution d’ext3, optimisations et rétrocompatibilité
reiserfspremier FS intégré à Linux, indexation des répertoires, petits fichiers
xfsjournalisation performante, snapshots, défragmentation en ligne (1993)
vfatFAT de Windows avec noms longs (255 caractères) ; clefs USB et supports amovibles

La journalisation est le critère qui revient toujours : avant d’écrire, le FS note ce qu’il va faire dans un journal ; après une coupure de courant, il reprend proprement. ext2 ne l’a pas, ext3/ext4/xfs l’ont.

4. Partitions, montage et occupation

À l’installation, un disque n’est ni partitionné ni formaté : partitionner, c’est définir un ou plusieurs espaces sur le disque ; formater, c’est préparer une partition à recevoir des données avec un système de fichiers défini.

Avec une table de partitions MBR, il existe quatre entrées au maximum. L’une d’elles peut désigner une partition étendue contenant des partitions logiques :

TypeRègle
principaleoccupe une entrée de la table MBR
étendueoccupe une entrée et contient des partitions logiques ; ne reçoit pas de FS directement
logiquecontenue dans l’étendue ; son nombre dépend des limites du système

GPT utilise une autre organisation : la limite de quatre entrées MBR ne s’applique pas, et le nombre de partitions dépend de la table et du système utilisés.

La commande fdisk configure une partition (ex. fdisk /dev/hda pour le premier disque IDE). Pour être utilisé, un système de fichiers doit être monté sur un point de l’arborescence : mount /dev/sda1 /mnt/flashdisk, démonter avec umount. Enfin df -h affiche l’occupation des partitions montées et du -ks /usr/local l’espace occupé par une arborescence.

Les descripteurs de disques

Dans /dev, les disques se nomment hdX (IDE) ou sdX (SCSI), X étant une lettre pour le périphérique : hda = maître du contrôleur primaire, hdd = esclave du secondaire. Un chiffre suit pour la partition : sda1 est la première partition de sda.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Lire une ligne ls -l

Bash Niveau 1 — Acquisition

Objectif : Décoder les neuf caractères de droits d'une ligne ls -l en classes utilisateur/groupe/autres.

Le script lit n lignes au format ls -l réduit : DROITS NOM (ex. -rw-r--r-- notes.txt). Le premier caractère est le type (- fichier, d répertoire) ; les neuf suivants sont les droits. Pour chaque ligne il affiche : NOM : TYPE, u=DROITSu, g=DROITSg, o=DROITSo où DROITSu/g/o sont les triplets (ex. rw-).

Entrée du programme
2
-rw-r--r-- notes.txt
drwxr-x--- dossier
Sortie attendue
notes.txt : fichier, u=rw-, g=r--, o=r--
dossier : repertoire, u=rwx, g=r-x, o=---

Un fichier et un répertoire classiques.

Deux indices, rédigés en mots
  1. Les triplets se découpent par positions : ${droits:1:3}, ${droits:4:3}, ${droits:7:3}.
  2. Le type est ${droits:0:1} : traduire - en « fichier » et d en « repertoire ».

Exercice 2 — Compter les permissions

Bash Niveau 2 — Application

Objectif : Convertir chaque triplet symbolique en valeur octale et produire les trois chiffres de chmod.

Le script lit n lignes DROITS NOM comme au format ls -l (-rw-r--r-- notes.txt). Pour chacune il calcule la valeur octale des droits (r = 4, w = 2, x = 1, par triplet) et affiche NOM : octal — par exemple rw-r--r-- donne 644.

Entrée du programme
3
-rw-rw-r-- liste
drwx------ prive
-r-xr-x--- vue
Sortie attendue
liste : 664
prive : 700
vue : 550

rw- = 6, rw- = 6, r-- = 4 ; rwx = 7 ; r-x = 5.

Deux indices, rédigés en mots
  1. Pour un triplet, additionner : 4 si le premier caractère est r, 2 si le second est w, 1 si le troisième est x.
  2. Boucler sur les trois positions du triplet avec une coupe ${triplet:i:1}, et construire la chaîne octale chiffre par chiffre.

Exercice 3 — Liens symboliques simulés

Bash Niveau 3 — Raisonnement

Objectif : Suivre une chaîne de liens symboliques vers un fichier, une destination absente ou un cycle.

Le script lit d'abord n, puis n lignes lien destination décrivant des liens : ln -s destination lien crée un lien qui pointe vers sa destination. Il lit ensuite m, puis m lignes contenant chacune le nom d'un fichier existant, et enfin le point de départ. Les noms sont des mots non vides sans espace ; les noms des liens sont distincts et ne figurent pas parmi les fichiers existants. Ces tables simulent le système de fichiers.

Suivre les liens et afficher le nom du fichier final s'il existe dans la liste. Si le nom final, y compris le point de départ, n'est ni un lien ni un fichier existant, afficher casse. Si un nom de lien est rencontré à nouveau, afficher boucle.

Entrée du programme
3
texte texte.txt
texte.txt fichier
doc texte
1
fichier
doc
Sortie attendue
fichier

doc → texte → texte.txt → fichier ; fichier figure dans la liste des fichiers existants.

Trois indices, rédigés en mots
  1. Tant que le nom courant est une clé de liens[${entree}], avancer vers sa destination.
  2. Mémoriser les noms de liens déjà visités : une répétition signale un cycle. Sinon, vérifier si le nom final figure dans fichiers.
  3. Pour afficher le nom final, printf évite que echo interprète un nom comme -n comme une option.

6. QCM — niveau examen

Comment note-t-on la racine de l’arborescence Linux ?

Un seul arbre part de la racine notée / ; C:\ est la convention Windows.

Quel répertoire contient les fichiers de configuration du système ?

/etc concentre les configurations système et des démons : il est à inclure dans un plan avec les données.

Que contient /tmp, et quelle est sa particularité ?

La conservation des fichiers de /tmp n’est pas garantie ; leur suppression au démarrage est possible, mais pas obligatoire.

Où se trouve le répertoire personnel de root ?

/root est la maison du super-utilisateur, hors de /home.

Que signifie « tout est fichier » sous Linux ?

Fichiers, périphériques, partitions, programmes en cours, répertoires : tout prend la forme d’un fichier.

Quel est le rôle de l’inode ?

L’inode porte les métadonnées (droits, propriétaire, taille…) ; le nom est associé à l’inode dans une entrée de répertoire.

Quelle est la principale différence entre ext2 et ext3 ?

ext3 est la version journalisée d’ext2 ; les deux partagent commandes et manipulations.

Combien de partitions principales au maximum dans une table MBR ?

MBR possède quatre entrées au maximum ; une partition étendue occupe l’une d’elles. GPT suit d’autres limites.

Que fait mount /dev/sda1 /mnt/flashdisk ?

Monter rend le contenu accessible comme un simple répertoire de l’arborescence.

Quelle commande affiche l’espace occupé par une arborescence ?

du (disk usage) avec -k (kilo-octets) et -s (total) ; df liste, elle, les partitions montées.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre / et /root : la racine n’a pas de nom ; /root est la maison de root.
  • Mettre les journaux dans /etc : les journaux variables vivent dans /var ; /etc est la configuration.
  • Supposer /tmp persistant : des fichiers peuvent y être supprimés selon la politique locale.
  • Ext2 dit journalisé : c’est ext3 qui apporte le journal ; ext2 est le FS historique.
  • Confondre MBR et GPT : le plafond de quatre entrées concerne MBR ; une étendue en occupe une.

8. Méthodologie de résolution

Lire une arborescence sans se perdre
  1. Partir de la racine et demander pour chaque répertoire : qui y vit et pourquoi.
  2. Classer par nature : config (/etc), personnel (/home), variable (/var), éphémère (/tmp).
  3. Vérifier un chemin absolu : il commence toujours par /.
  4. Associer disque et descripteur : sdX/hdX pour le disque, chiffre pour la partition.
  5. Se représenter le montage : un FS se greffe sur un répertoire, comme un volume sur un point.

9. Révision active

Résumé essentiel
  • Un seul arbre part de / ; chaque répertoire standard a un rôle précis et opposable en examen.
  • /etc : configuration (à sauvegarder) ; /home : utilisateurs ; /tmp : temporaire sans garantie de conservation ; /var : journaux et spools.
  • Tout est fichier : périphériques et partitions vivent dans /dev sous les noms hdX/sdX.
  • L’inode porte les métadonnées, le répertoire associe un nom à l’inode ; ext2 non journalisé, ext3 journalisé, ext4 optimisé.
  • MBR : quatre entrées au maximum, dont l’éventuelle étendue ; GPT a d’autres limites. mount/umount gèrent le montage.
