Chapitre 3 — Commandes de base : trouver, manipuler, chercher

Module 3 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Le terminal est ouvert, l’invite attend. Tout passe par une ligne de commande : se repérer, lister, créer, copier, déplacer, chercher. Ce chapitre installe la boîte à outils du TP — pwd, cd, ls, mkdir, cp, mv, rm, cat, echo, ln, find — et l’habitude de lire une commande comme une phrase : COMMANDE OPTIONS ARGUMENTS.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. écrire une commande avec sa syntaxe COMMANDE OPTIONS ARGUMENTS ;
  2. naviguer et manipuler fichiers et répertoires avec les commandes de base ;
  3. créer et interpréter un lien symbolique avec ln -s ;
  4. filtrer une recherche avec find et ses critères -name, -type, -size, -user.

1. La syntaxe d’une commande

Chaque utilisateur connecté dirige la machine en exécutant des commandes dans un terminal. La syntaxe est immuable :

COMMANDE OPTIONS ARGUMENTS
ls      -a      /home
│        │        │
│        │        └── objet(s) sur lesquels la commande agit (facultatif)
│        └── modifie le comportement (facultatif) : -a inclut les fichiers cachés
└── la commande elle-même : lister les fichiers

Options et arguments sont tous deux facultatifs : ls seul liste le répertoire courant. Les commandes utiles pour se repérer : pwd affiche l’emplacement courant, cd change de répertoire courant, ls liste les fichiers.

Mnémotechnique — « le verbe, le ton, la cible »

Lire une commande comme une phrase : le verbe (la commande), le ton (les options, avec un tiret), la cible (les arguments). pwd = « où suis-je ? », cd = « va à », ls = « montre-moi ».

2. Créer, copier, déplacer, supprimer

La panoplie de manipulation :

CommandeRôle
mkdircréer un répertoire
rmdirsupprimer un répertoire
touchchanger la date de modification d’un fichier — et créer un fichier vide
cpcopier un fichier ou un répertoire
mvrenommer ou déplacer un fichier/repertoire en une seule opération
rmsupprimer un fichier ou un répertoire
catafficher le contenu d’un fichier
echoafficher une ligne — et écrire dans un fichier avec > ou >>

echo "texte" > fichier écrase le contenu ; echo "texte" >> fichier suffixe (ajoute à la fin). Et un avertissement du cours qui ne se négocie pas : rm avec -f ou -rf peut endommager, voire supprimer tout le système de fichiers, de manière irréversible.

Piège — le > et le >>

Un seul chevron > écrase tout le fichier ; deux chevrons >> ajoutent à la fin. Confondre les deux, c’est perdre un fichier de configuration en une commande. En cas de doute, relire la ligne avant de valider.

Lire un gros fichier : man, more, head, tail

man commande affiche le manuel de n’importe quelle commande (essayer man ls). more montre un fichier page à page, head en montre le début (10 premières lignes par défaut), tail la fin (10 dernières lignes par défaut).

3. Les liens symboliques

La commande ln crée un lien matériel ou symbolique (raccourci) vers un fichier ou un répertoire. L’option -s (voir man ln) crée le lien symbolique :

echo "contenu" > fichiersource
ln -s fichiersource fichiercible
cat fichiercible          → contenu
echo "contenu2" >> fichiersource
cat fichiercible          → contenu
                            contenu2

fichiercible n’est pas un fichier stocké physiquement sur le disque : c’est juste un lien vers fichiersource. Toute modification de la source se lit à travers la cible — c’est exactement ce que simule l’exercice « liens symboliques » de l’atelier, en suivant la chaîne de liens jusqu’au fichier réel.

4. find : chercher selon tous les critères

La commande find cherche un fichier sous Linux. Sa syntaxe :

find répertoire critères

Le répertoire est le chemin où la recherche s’exécute ; les critères affinent la recherche. Les options les plus utilisées :

CritèreFiltre
-namepar rapport au nom du fichier
-typepar rapport au type du fichier
-sizepar rapport à la taille du fichier
-ctime / -atime / -mtimecréation / dernier accès / dernière modification
-user / -grouppropriétaire / groupe du fichier
-permpermissions du fichier

Les exercices du cours de TP s’y entraînent : créer fichier1, fichier2 et testfichier1 dans /tmp puis trouver ceux qui commencent par « fich » (find /tmp -name "fich*"), trouver ceux qui commencent par « fich » ou « test », trouver tous les fichiers (find /tmp -type f). À la maison, l’atelier rejoue ces filtres en Bash sur une arborescence simulée.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — find -name simulé

Bash Niveau 1 — Acquisition

Objectif : Filtrer des chemins par motif de nom : commencent par, finissent par, contiennent.

Le script lit n chemins (une ligne chacun), puis un motif : prefixe:X (noms de base commençant par X), suffixe:X (finissant par X) ou contient:X. Il affiche les chemins retenus, dans l'ordre d'entrée, puis la dernière ligne trouves : K. Le motif porte sur le nom de base (après le dernier /), jamais sur les répertoires parents.

Entrée du programme
4
/tmp/fichier1
/tmp/fichier2
/home/testfichier1
/etc/passwd
prefixe:fichier
Sortie attendue
/tmp/fichier1
/tmp/fichier2
trouves : 2

Le /home/testfichier1 a « test » devant : pas de correspondance de préfixe.

Deux indices, rédigés en mots
  1. Le nom de base s'obtient avec ${chemin##*/} : tout supprimer jusqu'au dernier /.
  2. Trois formes de motif : ${base#"$X"} != "$base" (commence), ${base%"$X"} != "$base" (finit), ou un test de sous-chaîne.

Exercice 2 — find par taille

Bash Niveau 2 — Application

Objectif : Convertir des tailles en octets, filtrer par seuil et trier le résultat.

Le script lit n lignes NOM TAILLE où TAILLE s'écrit 123 (octets), 45K (kilo-octets) ou 2M (méga-octets). Puis il lit un seuil au même format. Il affiche les fichiers dont la taille est strictement supérieure au seuil, convertis en octets sous la forme NOM OCTETS, triés de la plus grosse taille à la plus petite (tailles égales : ordre d'entrée). La dernière ligne : total : K fichier(s).

Entrée du programme
1M
4
gros.txt 3M
moyen.log 500K
petit.txt 100
image.png 2M
Sortie attendue
gros.txt 3145728
image.png 2097152
total : 2 fichier(s)

3M et 2M dépassent 1M ; 500K et 100 octets restent sous le seuil.

Deux indices, rédigés en mots
  1. Le seuil arrive en première ligne : le lire avant n, sinon la boucle le prend pour un fichier.
  2. Conversion : si la valeur finit par K, multiplier par 1024 ; par M, par 1024 × 1024 ; sinon octets bruts.
  3. Un tri simple à la main : boucler en prenant à chaque tour le maximum restant, ou trier le tableau par insertion.

Exercice 3 — Squelette de /etc/passwd

Bash Niveau 3 — Raisonnement

Objectif : Analyser le format login:x:UID:GID:... du fichier passwd : filtrer, compter, retrouver.

Le script lit n lignes au format /etc/passwd réduit : login:UID:GID:shell (quatre champs séparés par :). Il affiche trois lignes : utilisateurs : K (total), systeme : S (UID < 1000) et humains : H (UID ≥ 1000), puis la liste des logins humains, un par ligne, dans l'ordre d'entrée.

Entrée du programme
4
root:0:0:/bin/bash
sys:99:99:/usr/sbin/nologin
alice:1000:1000:/bin/bash
bob:1001:1001:/bin/sh
Sortie attendue
utilisateurs : 4
systeme : 2
humains : 2
alice
bob

UID 0 et 99 sont système ; 1000 et 1001 sont humains.

Deux indices, rédigés en mots
  1. Découper par deux-points : IFS=":" read -r login uid gid shell <<< "$ligne".
  2. Un test arithmétique [ "$uid" -lt 1000 ] sépare comptes système et comptes humains.

6. QCM — niveau examen

Quelle est la syntaxe générale d’une commande ?

La commande, puis les options (facultatives), puis les arguments (facultatifs) : ls -a /home.

Que fait pwd ?

pwd (print working directory) affiche l’emplacement où l’on se situe dans la hiérarchie.

Quelle commande crée un fichier vide ?

touch change la date de modification d’un fichier — et le crée vide s’il n’existe pas.

echo "x" > f et echo "x" >> f : quelle différence ?

Un chevron écrase le contenu, deux chevrons suffisent au fichier.

Que fait mv fichier3 /home/fichier4 ?

mv renomme ou déplace : renommer est un déplacement dans le même répertoire.

Pourquoi rm -rf est-elle dangereuse ?

Le cours l’avertit : avec -f ou -rf, rm peut endommager voire détruire le système de fichiers sans retour.

Quelle option de ln crée un lien symbolique ?

ln -s crée un lien symbolique (raccourci) au lieu d’un lien physique ; c’est documenté dans man ln.

Après modification de la source, que voit-on via le lien symbolique ?

La cible n’est pas un fichier stocké : elle pointe vers la source et reflète son contenu courant.

Que fait find /tmp -type f ?

-type f filtre sur les fichiers ordinaires ; sans critère, find listerait tout.

Quel critère de find filtre par propriétaire ?

-user filtre par propriétaire (-group par groupe, -perm par permissions).

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre cd et pwd : l’un déplace, l’autre affiche.
  • Chevron unique par habitude : > écrase un fichier existant sans avertissement.
  • Supprimer avec rm sans réfléchir : -f / -rf sont irréversibles.
  • Ln sans -s attendu symbolique : sans option, ln crée un lien physique.
  • find sans répertoire : la syntaxe demande le chemin où chercher, puis les critères.

8. Méthodologie de résolution

Construire une ligne de commande fiable
  1. Nommer l’intention : chercher, créer, copier, déplacer, supprimer, afficher.
  2. Choisir le verbe (la commande) avant les options : find, touch, cp, mv, rm, cat.
  3. Ajouter les options qui affinent : -a pour les cachés, -s pour un lien symbolique.
  4. Cibler précisément : chemin absolu quand le contexte change, relatif sinon.
  5. Relire avant de valider — surtout si la ligne contient rm ou >.

9. Révision active

Résumé essentiel
  • COMMANDE OPTIONS ARGUMENTS : ls -a /home — verbe, ton, cible.
  • pwd affiche, cd déplace, ls liste ; mkdir/rmdir et touch gèrent répertoires et fichiers vides.
  • cp copie, mv renomme/déplace, rm supprime — -f/-rf sont irréversibles.
  • echo avec > écrase, avec >> il ajoute ; cat, more, head, tail lisent ; man documente tout.
  • ln -s crée un lien symbolique qui reflète la source ; find répertoire critères cherche par -name, -type, -size, -user, -perm.

Checklist de maîtrise

  • Je crée, copie, déplace, supprime sans ambiguïté (touch, cp, mv, rm).
  • Je crée un lien symbolique et j’explique ce qu’il reflète.
  • Je construis une recherche find avec les critères -name, -type, -size, -user.
