Chapitre 4 — Installer Debian 12

Module 4 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

La théorie est posée : un arbre, des partitions, des montages. Place à la pratique du TP — installer une vraie distribution, Debian 12, sur une machine ou une machine virtuelle. C’est au cours de cette installation que le chapitre 2 devient concret : les partitions que l’on définit deviennent les points de montage de l’arborescence.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. préparer le support d’installation : image ISO, clé USB amorçable, machine virtuelle ;
  2. dérouler l’installateur Debian : langue, réseau, comptes, partitionnement ;
  3. justifier un schéma de partitionnement avec ses points de montage ;
  4. configurer les dépôts via /etc/apt/sources.list et mettre le système à jour.

1. Préparer le support d’installation

Debian 12 (nom de code Bookworm) se distribue sous forme d’image ISO à télécharger depuis le site officiel. Trois terrains de jeu possibles :

SupportQuand le choisir
clé USB amorçableinstallation réelle sur un ordinateur dédié
machine virtuelleTP en salle : sans risque pour la machine hôte
graveur de DVDmatériel ancien sans amorçage USB

L’image netinst est la plus légère : elle installe un système de base puis va chercher les paquets restants sur les dépôts en ligne. Une clé USB s’amorce après copie de l’ISO avec un outil dédié ; en VM, il suffit de monter l’ISO dans le lecteur virtuel et de démarrer.

Mnémotechnique — « netinst = système minimum + réseau »

netinst installe le net minimum et tire le reste du réseau. D’où l’importance de la configuration réseau pendant l’installation : sans elle, pas de paquets.

2. Dérouler l’installateur

L’installateur Debian pose les mêmes questions, dans le même ordre :

1. langue, pays, clavier
2. nom de machine (hostname) et domaine
3. comptes : mot de passe root, puis un utilisateur ordinaire
4. horloge et fuseau horaire
5. partitionnement du disque
6. sélection des logiciels (tasksel) et environnement de bureau
7. installateur d’amorçage GRUB
8. redémarrage sur le nouveau système

Deux comptes se créent à cette étape et ils n’ont pas le même rôle : root, le super-utilisateur qui a tous les droits (sa maison est /root), et un utilisateur ordinaire pour le travail quotidien (sa maison est /home/login). Travailler en root en permanence est une faute d’administration : chaque faute de frappe devient une faute système.

Piège — mot de passe root et utilisateur

Retenir lequel des deux mots de passe sert à su (devenir root) et lequel sert à la connexion graphique. Les confondre est la première panne de TP ; l’exercice « audit des comptes » de l’atelier reproduit exactement ce genre de diagnostic.

3. Partitionner pour Debian

Le partitionnement est l’étape où le chapitre 2 s’applique. L’installateur propose : disque entier, disque entier avec LVM, ou manuel. Un schéma pédagogique courant pour un TP :

partition   taille        point de montage
/dev/sda1   ~30 Go        /          (racine, ext4)
/dev/sda2   ~2× la RAM    swap       (échange mémoire)
/dev/sda3   le reste      /home      (données personnelles)

Chaque partition reçoit un système de fichiers (ext4 en pratique : journalisé et optimisé) et un point de montage. Séparer /home permet de réinstaller le système sans perdre les données personnelles ; le swap (échange) est l’espace disque où le noyau déborde quand la mémoire vive sature.

Après l’installation : vérifier le montage

df -h liste les partitions montées et leur occupation ; lsblk montre l’arbre des disques et partitions. Si une partition attendue n’y figure pas, c’est qu’elle n’est pas montée — revérifier /etc/fstab.

4. Dépôts, sources.list et mise à jour

Les paquets viennent de dépôts (repositories) décrits dans /etc/apt/sources.list — encore lui, le répertoire de configuration. Une ligne de sources liste une adresse de dépôt, la version (bookworm) et les composantes (main, contrib, non-free) ; il peut être utile de la modifier pour qu’elle pointe vers le dépôt backports ou un miroir proche.

apt update      rafraîchit la liste des paquets disponibles
apt upgrade     installe les mises à jour des paquets installés
apt install X   installe le paquet X et ses dépendances

Après installation, le rituel est immuable : apt update puis apt upgrade. C’est aussi le moment d’installer les outils du cours (vim, git, curl…). La gestion des utilisateurs et des groupes — le sujet du chapitre suivant — se fait alors sur un système à jour, en root ou avec sudo.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — chmod octal → symbolique

Bash Niveau 2 — Application

Objectif : Traduire les trois chiffres octaux de chmod en droits symboliques type ls -l.

Le script lit n lignes OCTAL NOM (ex. 644 notes.txt). Pour chacune il affiche la chaîne de droits complète type ls -l : le caractère de type - (fichiers uniquement ici), puis les neuf caractères. 644 donne rw-r--r--. La sortie est NOM : -DROITS.

Entrée du programme
2
644 notes.txt
755 run.sh
Sortie attendue
notes.txt : -rw-r--r--
run.sh : -rwxr-xr-x

6 = rw-, 4 = r--, 5 = r-x.

Deux indices, rédigés en mots
  1. Pour un chiffre : le 4 vaut r, le 2 vaut w, le 1 vaut x — construire le triplet caractère par caractère.
  2. Isoler chaque chiffre avec ${octal:0:1}, ${octal:1:1}, ${octal:2:1} et une petite fonction ou trois tests.

Exercice 2 — chmod symbolique simple

Bash Niveau 2 — Application

Objectif : Appliquer une modification symbolique (u/g/o suivi de + ou - et de rwx) à des droits existants.

Le script lit n lignes DROITS MODIF où DROITS est une chaîne de neuf caractères (sans le type) et MODIF s'écrit classe action lettres — classe vaut u, g, o ou a (toutes), action vaut + ou -, lettres valent une à trois lettres parmi r, w, x (ex. o-r, ug+x). Il applique la modification et affiche les neuf nouveaux caractères.

Entrée du programme
2
rw-r--r-- o-r
rwxr-xr-x go+w
Sortie attendue
rw-r-----
rwxrwxrwx

o-r retire la lecture des autres ; go+w ajoute écriture au groupe et aux autres.

Deux indices, rédigés en mots
  1. Positions des classes : u = 0-2, g = 3-5, o = 6-8. Construire un masque des positions touchées.
  2. Pour + : poser la lettre si la position correspond ; pour - : la remplacer par -. Parcourir les lettres demandées une à une.

Exercice 3 — Droits et accès : qui peut quoi

Bash Niveau 3 — Raisonnement

Objectif : Décider, pour chaque demande d'accès (r, w ou x) par un propriétaire, un groupe ou un autre, si elle est accordée.

Le script lit d'abord une ligne de droits (neuf caractères, ex. rw-r-x---), puis m demandes : classe lettre (classe = u, g ou o ; lettre = r, w ou x). Pour chaque demande il affiche accordé ou refusé. Rappel : pour la classe u ce sont les caractères 0-2, g les 3-5, o les 6-8 ; r en première position du triplet, w en deuxième, x en troisième.

Entrée du programme
rw-r-x---
4
u w
g x
o r
g w
Sortie attendue
accordé
accordé
refusé
refusé

Le groupe a r-x : exécution accordée, écriture refusée ; les autres n'ont rien.

Deux indices, rédigés en mots
  1. Décaler la base selon la classe : u → 0, g → 3, o → 6 ; puis r → +0, w → +1, x → +2 dans le triplet.
  2. Un seul test suffit : le caractère à la position calculée vaut-il la lettre demandée ?

6. QCM — niveau examen

Qu’est-ce que l’image netinst ?

netinst installe un système de base puis télécharge le reste depuis les dépôts.

Quel répertoire décrit les dépôts de paquets ?

/etc/apt/sources.list liste les dépôts : adresse, version, composantes.

Quels comptes crée l’installateur ?

Root pour l’administration (maison /root) et un utilisateur ordinaire pour le quotidien (/home/login).

Où place-t-on traditionnellement la partition /home ?

Séparer /home permet de réinstaller le système sans toucher aux données personnelles.

À quoi sert le swap ?

Le swap (typiquement deux fois la RAM) est l’espace où le noyau déborde de la mémoire vive.

Que fait apt update ?

update actualise la liste ; upgrade applique les mises à jour des paquets installés.

Que signifie le nom de code Bookworm ?

Chaque version stable de Debian porte un nom de code ; Debian 12 est Bookworm.

Pourquoi ne faut-il pas travailler en root en permanence ?

Root a tous les droits : la moindre commande mal ciblée est irréversible ; on travaille en utilisateur ordinaire et on passe root ponctuellement.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Choisir un ISO complet hors ligne sans le comprendre : netinst tire du réseau — sans réseau, pas de paquets.
  • Confondre les deux mots de passe : celui de root sert à su, celui de l’utilisateur à la connexion.
  • Swap oublié : sans espace d’échange, la saturation mémoire gèle la machine.
  • Points de montage non vérifiés : df -h après installation est un réflexe, pas une option.
  • apt upgrade sans apt update : la liste des paquets périmée, les mises à jour passent à côté.

8. Méthodologie de résolution

Installer Debian sans mauvaise surprise
  1. Préparer : ISO vérifiée, support amorçable ou VM configurée, sauvegarde faite.
  2. Lire chaque écran avant de valider — surtout le partitionnement.
  3. Noter hostname, mot de passe root et utilisateur au fil de l’eau.
  4. Justifier le schéma de partitions : /, swap, /home avec les tailles.
  5. Terminer par le rituel : apt update, apt upgrade, vérification df -h.

9. Révision active

Résumé essentiel
  • Debian 12 « Bookworm » s’installe depuis une ISO netinst, sur clé USB ou en machine virtuelle.
  • L’installateur crée root (maison /root) et un utilisateur ordinaire (maison /home/login).
  • Le partitionnement associe à chaque partition un FS (ext4) et un point de montage : /, swap, /home.
  • Séparer /home survit à une réinstallation ; le swap est l’échange mémoire-disque.
  • Les dépôts se déclarent dans /etc/apt/sources.list ; le rituel est apt update puis apt upgrade.

Checklist de maîtrise

  • Je déroule l’installateur en citant chaque étape dans l’ordre.
  • Je justifie un schéma de partitionnement complet avec tailles et points de montage.
  • Je distingue les comptes root et utilisateur ordinaire et leurs maisons.
  • J’explique sources.list et le couple apt update / apt upgrade.
