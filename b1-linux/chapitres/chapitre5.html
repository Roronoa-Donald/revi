Chapitre 5 — Utilisateurs, groupes et fichiers de comptes

Module 5 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Un serveur héberge plusieurs personnes et chaque personne n’a pas les mêmes droits. Linux gère cela avec des comptes et des groupes, décrits dans trois fichiers texte lisibles : /etc/passwd, /etc/shadow, /etc/group. Savoir lire ces lignes — et les produire, comme le font les commandes d’administration — est le cœur de ce chapitre.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. décomposer une ligne de /etc/passwd champ par champ et interpréter le champ mot-de-passe ;
  2. expliquer le rôle de /etc/shadow et /etc/group avec leurs formats ;
  3. créer, modifier et supprimer comptes et groupes (useradd, usermod, userdel, groupadd, groupdel) ;
  4. gérer les mots de passe avec passwd et distinguer UID système et UID humain.

1. Le fichier /etc/passwd

Le fichier /etc/passwd contient les informations relatives à tous les utilisateurs du système : chaque ligne concerne un utilisateur, les champs sont séparés par le signe deux-points :

login:mot-de-passe:UID:GID:info-utilisateur:répertoire-principal:shell

alice:x:1000:1000:Alice Diallo:/home/alice:/bin/bash
  │    │    │    │        │                  │           │
  │    │    │    │        │                  │           └ interpréteur lancé après connexion
  │    │    │    │        │                  └ maison de l’utilisateur (généralement /home/toto)
  │    │    │    │        └ nom complet, numéro de poste… (séparés par des virgules)
  │    │    │    └ GID : identifiant du groupe principal
  │    │    └ UID : identifiant numérique unique ; root = 0
  │    └ mot de passe (voir ci-dessous)
  └ identifiant de connexion

Le champ mot-de-passe prend plusieurs significations :

ValeurSignification
*impossible de s’authentifier avec ce compte
!!compte désactivé
x ou !le mot de passe est dans /etc/shadow
champ videpas de mot de passe pour ce compte

Les UID inférieurs à 1000 sont réservés aux comptes système ; root possède l’UID 0. C’est exactement le seuil que l’exercice « squelette de /etc/passwd » de l’atelier fait manier : compter, filtrer, lister selon l’UID.

Piège — pourquoi passwd est lisible par tous

/etc/passwd est accessible à tout le monde car certaines commandes ont besoin de la liste des utilisateurs ou de la correspondance login/UID. Les mots de passe chiffrés, eux, ont déménagé dans /etc/shadow — c’est le x du champ.

2. /etc/shadow et /etc/group

Le fichier /etc/shadow stocke les mots de passe chiffrés ; il ne peut être lu que par l’administrateur. Cette séparation permet à /etc/passwd de rester lisible tout en protégeant les empreintes.

Le fichier /etc/group décrit les groupes. La syntaxe d’une ligne :

groupe:*:GID:utilisateurs

dev:*:1010:alice,bob
  │  │   │      │
  │  │   │      └ liste des membres, séparés par des virgules
  │  │   └ identifiant numérique unique du groupe
  │  └ champ historique, vide ou * ou x
  └ nom du groupe
Mnémotechnique — « passwd décrit, shadow protège, group regroupe »

Trois fichiers, trois verbes : décrit (passwd, lisible par tous), protège (shadow, réservé à l’administrateur), regroupe (group, la liste des membres par groupe).

3. Créer, modifier, supprimer des comptes

Les commandes d’administration (en root) :

ActionCommandeDétail
ajouter un utilisateuruseradd options loginex. useradd toto crée toto
supprimer un utilisateuruserdel options loginle répertoire n’est pas supprimé ; ajouter -r pour tout retirer
modifier un compteusermod options loginmêmes options que useradd
changer un mot de passepasswd options loginex. passwd toto ; sans login, c’est l’utilisateur courant

Exemples de usermod du cours : usermod -d /home/toto -m tutu change le répertoire personnel de tutu en /home/toto en recopiant le contenu de l’ancien dossier et en ajustant les droits ; usermod -l toto tutu renomme l’utilisateur tutu en toto — ce qui suppose que tutu n’est pas connecté au moment de la commande. Pour être effectives, les modifications imposent à l’utilisateur de se déloguer puis reloguer.

Côté consultation : whoami affiche l’identité de l’utilisateur courant ; who, users et w listent les utilisateurs connectés sur la machine. L’administrateur peut changer n’importe quel mot de passe ; un utilisateur normal ne peut changer que le sien (l’ancien lui est alors demandé).

4. Créer et gérer des groupes

Créer un groupe : groupadd option groupe — ex. groupadd modem. Le supprimer : groupdel groupe (ou groupdel GID), avec une contrainte importante : on ne peut pas supprimer un groupe qui est le groupe principal d’un utilisateur.

Rattacher un utilisateur à un groupe passe par usermod, et le fichier /etc/group montre alors le login dans la liste des membres. L’atelier simule toute cette chaîne : créer des groupes, y rattacher des utilisateurs, répondre aux requêtes d’appartenance dans l’ordre de création des groupes — le même travail que les commandes réelles, sur une arborescence de texte.

Le cycle complet en une séance

useradd tpsysteme puis useradd userVoisin, vérifier dans /etc/passwd, créer le groupe de projet avec groupadd, y rattacher les deux comptes avec usermod, contrôler dans /etc/group. Ce cycle est exactement celui du TP noté.

Exercice 1 — useradd et /etc/passwd simulés

Bash Niveau 2 — Application

Objectif : Générer les lignes /etc/passwd à partir d'opérations useradd/userdel, avec UID automatique.

Le script simule la gestion des comptes. Il lit n opérations : useradd login (crée le compte avec le prochain UID libre à partir de 1000, GID = UID), userdel login (supprime), ou ls. À chaque ls, il affiche les lignes passwd des comptes courants, dans l'ordre de création : login:x:UID:GID:/home/login:/bin/bash. Un useradd d'un login existant affiche existe ; un userdel d'un login absent affiche inconnu.

Entrée du programme
6
useradd alice
useradd bob
ls
userdel alice
ls
useradd carol
Sortie attendue
alice:x:1000:1000:/home/alice:/bin/bash
bob:x:1001:1001:/home/bob:/bin/bash
bob:x:1001:1001:/home/bob:/bin/bash

Après suppression d'alice, seul bob reste ; carol est créée après le dernier ls.

Deux indices, rédigés en mots
  1. Un tableau des logins créés + un compteur d'UID : le prochain UID est 1000 + le nombre de créations réussies.
  2. Pour userdel, chercher la position du login dans le tableau et retirer l'élément ; pour ls, rejouer le tableau.

Exercice 2 — groupadd et appartenance

Bash Niveau 3 — Raisonnement

Objectif : Gérer des groupes simulés : créer, ajouter des membres, répondre aux requêtes d'appartenance.

Le script lit n opérations : groupadd groupe, usermod groupe login (ajoute login au groupe), ou groups login. À chaque groups login il affiche, séparés par des virgules, les groupes dont login est membre, dans l'ordre de création des groupes — ou aucun si l'utilisateur n'appartient à rien. Un usermod vers un groupe inexistant affiche groupe inconnu ; ajouter deux fois le même membre ne duplique pas.

Entrée du programme
6
groupadd etudiants
groupadd profs
usermod etudiants alice
usermod profs alice
groups alice
groups bob
Sortie attendue
etudiants,profs
aucun

alice est dans les deux groupes, bob dans aucun.

Deux indices, rédigés en mots
  1. Un tableau associatif groupe → liste de membres (séparés par des espaces) garde l'ordre des groupes.
  2. Pour groups, parcourir les groupes dans l'ordre de création et tester la présence du login dans la liste.

Exercice 3 — Audit des comptes

Bash Niveau 4 — Examen

Objectif : Confronter /etc/passwd et /etc/shadow simulés pour signaler les comptes à risque.

Le script lit n lignes login:champ-mdp représentant la vue passwd/shadow fusionnée. Les valeurs du champ : x (mot de passe géré, compte normal), * (authentification impossible), !! (compte désactivé), vide (aucun mot de passe). Il affiche un audit : total : K, desactives : D (* et !!), risque : R (champ vide), puis les logins à risque, un par ligne, dans l'ordre — ou aucun si R vaut 0.

Entrée du programme
4
root:x
sys:*
ancien:!!
vide:
Sortie attendue
total : 4
desactives : 2
risque : 1
vide

Le compte sans mot de passe est le seul signalé.

Deux indices, rédigés en mots
  1. Couper au premier deux-points : login="${ligne%%:*}", champ="${ligne#*:}".
  2. Trois catégories se déduisent du champ : * et !! désactivent, le vide est le seul cas à risque.

6. QCM — niveau examen

Combien de champs dans une ligne /etc/passwd ?

Sept champs : login, mot-de-passe, UID, GID, info, répertoire principal, shell.

Que signifie le champ x dans /etc/passwd ?

x ou ! renvoient à /etc/shadow ; !! signifie compte désactivé, * interdit l’authentification.

Quel UID possède root ?

root = UID 0 ; les UID inférieurs à 1000 sont réservés aux comptes système.

Quel fichier stocke les mots de passe chiffrés ?

/etc/shadow, lisible uniquement par l’administrateur.

Que fait usermod -d /home/toto -m tutu ?

-d fixe la nouvelle maison et -m y recopie le contenu de l’ancienne en ajustant les droits.

Que fait userdel toto, et que faut-il pour supprimer sa maison ?

userdel ne supprime pas le répertoire personnel ; l’option -r l’ajoute à la suppression.

Quelle commande crée un groupe ?

groupadd groupe (ex. groupadd modem) ; suppression avec groupdel.

Quand groupdel échoue-t-il ?

On ne peut pas supprimer un groupe qui sert de groupe principal à un utilisateur.

Quelle commande affiche l’utilisateur courant ?

whoami affiche l’identité de l’utilisateur courant ; who, users et w listent les connectés.

Format d’une ligne /etc/group ?

Nom, champ historique, GID numérique, liste des membres séparés par des virgules.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Sept champs pas huit : recompter sur une vraie ligne passwd — login, mdp, UID, GID, info, maison, shell.
  • UID 1000 dit système : c’est la frontière ; les comptes système sont en dessous (root = 0).
  • userdel -r oublié : sans -r, la maison reste sur le disque.
  • Renommer un utilisateur connecté : usermod -l exige qu’il soit délogué.
  • Confondre whoami et who : l’un dit qui je suis, l’autre qui est connecté.

8. Méthodologie de résolution

Lire et manipuler un compte
  1. Découper la ligne passwd par les deux-points et nommer les sept champs.
  2. Interpréter le champ mot-de-passe : *, !!, x/!, vide.
  3. Classer par UID : système si < 1000, humain sinon, root = 0.
  4. Choisir la commande d’administration : useradd, usermod, userdel, passwd, groupadd, groupdel.
  5. Vérifier dans les fichiers : passwd, shadow, group — après chaque opération.

9. Révision active

Résumé essentiel
  • /etc/passwd : login:mot-de-passe:UID:GID:info:maison:shell — lisible par tous, car les commandes en ont besoin.
  • Champ mot-de-passe : * (authentification impossible), !! (désactivé), x/! (dans shadow), vide (sans mot de passe).
  • UID < 1000 = comptes système, root = 0 ; /etc/shadow garde les empreintes, /etc/group les membres.
  • useradd/userdel -r/usermod/passwd gèrent les comptes ; les modifications imposent déloguer-reloguer.
  • groupadd/groupdel créent et suppriment ; impossible de supprimer un groupe principal d’un utilisateur.

Checklist de maîtrise

  • Je décompose une ligne /etc/passwd et je nomme les sept champs.
  • J’interprète les quatre états du champ mot-de-passe.
  • Je choisis la bonne commande pour créer, modifier, supprimer un compte ou un groupe.
  • Je vérifie le résultat dans /etc/passwd, /etc/shadow et /etc/group.
