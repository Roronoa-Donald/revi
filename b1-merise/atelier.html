Atelier d’analyse & Bac à sable

Un éditeur interactif dans la page pour résoudre les études de cas. Complétez la grille d’analyse, validez-la et observez le résultat : c'est ici qu'une règle de gestion devient un programme.

Comment fonctionne l'atelier
  • Valider vérifie la conformité de vos réponses dans la grille d’analyse.
  • Données du cas contient les paramètres soumis à l’étude.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n'écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l'éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Grille d’analyse

Objectif : expérimenter sans conséquence. Prenez un mécanisme de MERISE (cardinalités, règles de passage, formes normales), programmez-le et testez-le sur des cas limites.

Le script proposé classe les associations : réflexive, hiérarchique (sans données) ou porteuse, puis compte les tables à créer au MLD. Ajoutez les cardinalités, une vérification d'identifiant, ou remplace tout le script par le mécanisme que vous voulez vérifier.

Dans l'outil AnalyseSI, ce seront des rectangles et des patates : la structure du script — lire, décider, rapporter — reste exactement la même.

De la page au vrai outil

La simulation a une limite assumée : aucun schéma graphique n'est dessiné — le MCD reste du texte structuré. Elle a une force : toute la logique se vérifie sans risque — on peut rejouer une analyse autant de fois que nécessaire. Quand le script reproduit les bons trajets — lire la règle de gestion, la traduire en dépendance ou en cardinalité, rapporter — le passage à l'outil de dessin est mécanique.

Les trois erreurs que l'atelier révèle immédiatement
  • Compteur dans la boucle : le bilan des tables s'affiche à chaque ligne au lieu d'une seule fois, après.
  • Cas partiels : le test ne couvre qu'un type d'association et juge les autres par un défaut silencieux.
  • Clé oubliée : le tableau associatif est utilisé sans declare -A, et les cumuls s'écrasent.
Ce que fait l'atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d'exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n'est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d'exécutions est limité par jour, pour tout le monde. L'atelier n'exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois études de cas corrigées automatiquement dans la page. Une fois l'atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme de modélisation est vraiment acquis.
