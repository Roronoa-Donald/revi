Chapitre 3 — Dictionnaire de données et dépendances fonctionnelles

Module 3 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le client raconte son activité en vrac : factures, clients, remises, catégories. Avant tout schéma, l'analyste recense les propriétés une à une (le dictionnaire de données) et écrit ce qui détermine quoi (les dépendances fonctionnelles). Ces deux documents préparent le MCD — et évitent les propriétés fantômes inventées plus tard.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. classer une propriété en élémentaire, composée ou calculée ;
  2. constituer un dictionnaire de données propre (types, formats, remarques) ;
  3. formuler une dépendance fonctionnelle « source détermine cible » à partir d'une règle de gestion ;
  4. construire la matrice des dépendances et en déduire l'identifiant d'une entité.

1. Le dictionnaire de données

Le dictionnaire de données recense et décrit l'ensemble des propriétés qui serviront à élaborer le MCD : nom, type (texte, nombre, date), format, nature, remarques. Une propriété est :

  • élémentaire : elle ne se déduit d'aucune autre ;
  • composée : sa valeur résulte d'une règle de construction sur d'autres informations (une adresse = numéro, rue, ville) ;
  • calculée : elle se déduit d'une autre propriété par une règle de calcul (le TTC depuis le HT et la TVA).

Les propriétés calculées ne s'enregistrent pas : elles se recalculent. Le dictionnaire les note, mais le MCD les écarte. Le recueil se fait en interviewant les acteurs et en étudiant les documents existants (factures, bons de livraison, registres) : chaque rubrique d'un document est une propriété candidate.

Mnémotechnique — « E-C-C : élémentaire, composée, calculée »

Élémentaire = irremplaçable. Composée = assemblée (décomposable). Calculée = déductible. Seules les deux premières entrent dans le MCD ; la calculée retourne aux traitements.

2. Dépendances fonctionnelles et matrice

Une dépendance fonctionnelle (DF) relie deux propriétés : « connaître la valeur de A suffit à connaître celle de B ». On écrit A → B : A détermine B. Exemple : NumClt → NomClt (le numéro de client détermine son nom) ; NumCde → DateCde.

Les DF se tirent des règles de gestion énoncées par le client (« une facture concerne un et un seul client ») et se contrôlent sur les documents : une même source qui détermine deux cibles contradictoires révèle une erreur d'analyse ou une propriété mal décomposée.

La matrice des dépendances croise toutes les propriétés : pour chaque couple (ligne source, colonne cible), une croix si la DF existe. On y lit : les identifiants candidats (les sources qui déterminent le plus de propriétés), les propriétés élémentaires, et les associations éventuelles entre entités (une source qui détermine l'identifiant d'un autre groupe de propriétés signale une CIF, contrainte d'intégrité fonctionnelle). Des symboles complètent la légende : association réflexive, DF élémentaire et directe, CIF.

Confusions d'examen
  • Le TTC est calculé, donc écarter du dictionnaire des propriétés à modéliser.
  • Une DF se vérifie sur des exemples : NumClt → VilleClt est suspecte si deux clients d'une même ville… si, ça marche — mais VilleClt → NumClt est fausse.
  • Le sens de la flèche compte : A → B ne dit rien de B → A.
  • Une règle de gestion qui ne donne aucune DF est soit mal comprise, soit un simple commentaire.

3. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

En cas d’hésitation, le bouton Expliquer mon erreur sollicite le tuteur pédagogique pour vous guider dans l’application de la méthodologie sans donner directement la solution.

Exercice 1 — Le dictionnaire de données

Étude de cas Niveau 1 — Acquisition

Objectif : Construire un dictionnaire de données : filtrer les propriétés élémentaires et repérer les calculées.

Analysez chaque ligne proposée « nom type » : type vaut el (élémentaire), co (composée) ou ca (calculée). Le dictionnaire ne retient que les propriétés élémentaires et composées. Pour chaque ligne retenue il Indiquez nom : conservee, pour les autres nom : ecartee. Il termine par dictionnaire : X proprietes, X étant le nombre de propriétés retenues.

Cas d’exemple
4
NumClt el
NomClt el
AdresseClt co
MontantTTC ca
Résolution attendue
NumClt : conservee
NomClt : conservee
AdresseClt : conservee
MontantTTC : ecartee
dictionnaire : 3 proprietes
Deux indices, rédigés en mots
  1. Seul le type « ca » écarte une propriété : les deux autres passent.
  2. Le compteur suit exactement les lignes affichées « conservee ».

Exercice 2 — Les règles de gestion

Étude de cas Niveau 2 — Application

Objectif : Extraire les dépendances fonctionnelles des règles de gestion et éliminer les règles redondantes.

Analysez chaque ligne proposée « source cible » décrivant une règle de gestion « source détermine cible ». Pour chaque ligne il Indiquez source → cible si le couple n'a jamais été énoncé, sinon source → cible : redondante (règle répétée). Il termine par df elementaires : X/n, X étant le nombre de couples distincts.

Cas d’exemple
4
NumClt NomClt
NumClt AdrClt
NumCde DateCde
NumClt NomClt
Résolution attendue
NumClt → NomClt
NumClt → AdrClt
NumCde → DateCde
NumClt → NomClt : redondante
df elementaires : 3/4
Deux indices, rédigés en mots
  1. La clé du tableau associatif est le couple complet : vues[source|cible].
  2. Un couple nouveau s'affiche et se compte ; un couple déjà vu s'affiche « : redondante » et ne se compte pas.

Exercice 3 — La matrice des dépendances

Étude de cas Niveau 3 — Raisonnement

Objectif : Construire la matrice des dépendances fonctionnelles et déduire l'identifiant de l'entité.

Analysez chaque ligne proposée « source cible » (DF élémentaires, sans doublon de couple). Il dénombre pour chaque source le nombre de cibles qu'elle détermine, puis désigne l'identifiant candidat : la source qui détermine le plus de propriétés (une seule gagnante garantie par les données). Affichage : une ligne source : X cibles par source distincte, triée par ordre d'apparition, puis identifiant candidat : source et propriete : cible pour chaque cible de l'identifiant, dans l'ordre d'apparition.

Cas d’exemple
4
NumClt NomClt
NumClt AdrClt
NumClt TelClt
NumCde NumClt
Résolution attendue
NumClt : 3 cibles
NumCde : 1 cibles
identifiant candidat : NumClt
propriete : NomClt
propriete : AdrClt
propriete : TelClt
Deux indices, rédigés en mots
  1. Deux structures : un compteur par source et, par source, la liste des cibles (concaténées avec un séparateur).
  2. Un second passage sur les sources distinctes (tableau des clés) trouve le maximum ; l'ordre d'apparition se conserve avec un tableau indexé des sources à leur première apparition.

4. QCM — niveau examen

Le MontantTTC d'une facture est une propriété…

Il se déduit du HT et de la TVA par une règle de calcul : le MCD ne le mémorise pas.

« Adresse = numéro, rue, ville » : Adresse est…

Sa valeur est obtenue par une règle de construction sur d'autres informations.

NumClt → NomClt se lit…

A → B : connaître A suffit pour connaître B.

Le dictionnaire de données sert à…

Il recense et décrit l'ensemble des propriétés utilisées pour élaborer le MCD.

La matrice des dépendances sert à…

Croisement sources × cibles : on y lit identifiants candidats, propriétés élémentaires et CIF.

NumCde → NumClt (numéro de commande détermine le client) est…

Une DF vers l'identifiant d'un autre groupe de propriétés est une contrainte d'intégrité fonctionnelle.

Une propriété calculée dans une table…

Elle risque de contredire le recalcul ; on la calcule au moment du traitement.

À quoi reconnaît-on l'identifiant dans la matrice ?

L'identifiant détermine toutes les propriétés de son entité.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Mémoriser une propriété calculée : le TTC se recalcule, il ne s'enregistre pas.
  • Inverser le sens d'une DF dans la matrice : la source détermine la cible, jamais l'inverse.
  • Oublier de décomposer une adresse (numéro, rue, ville) : la propriété composée masque des attributs utiles.
  • Écrire des DF sans règle de gestion derrière : une DF se justifie par un énoncé ou un document.

6. Méthodologie de résolution

Méthode — du document au dictionnaire
  1. Lister les rubriques de chaque document de l'entreprise (facture, bon, registre).
  2. Pour chaque propriété : élémentaire, composée ou calculée ? Calculée = écartée.
  3. Énoncer les règles de gestion et les traduire en DF (source → cible).
  4. Construire la matrice, lire les identifiants candidats et les CIF.

7. Révision active

Résumé essentiel
  • Le dictionnaire de données recense toutes les propriétés : nom, type, format, nature.
  • Trois natures : élémentaire (à garder), composée (à décomposer), calculée (à écarter).
  • Une DF « A → B » : connaître A suffit à connaître B ; elle se justifie par une règle de gestion.
  • La matrice des dépendances révèle identifiants candidats et contraintes d'intégrité fonctionnelle.

Checklist de maîtrise

  • Je sais trier douze propriétés en élémentaires, composées et calculées.
  • Je sais écrire cinq DF à partir de règles de gestion.
  • Je sais lire une matrice des dépendances et proposer un identifiant.
  • Je sais expliquer pourquoi le TTC ne s'enregistre pas.

Les 8 notions à connaître absolument

  1. Propriété : plus petit élément d'information manipulable.
  2. Élémentaire : non déductible d'autres propriétés.
  3. Composée : assemblée par une règle de construction.
  4. Calculée : déduite par une règle de calcul (à écarter).
  5. Dépendance fonctionnelle : A → B, connaître A suffit pour B.
  6. Dictionnaire de données : inventaire descriptif des propriétés.
  7. Matrice des dépendances : croisement sources × cibles des DF.
  8. CIF : contrainte d'intégrité fonctionnelle entre deux entités.

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — reprends les trois natures de propriété.
50–69 % — refais le dictionnaire d'un document (facture, bon de livraison).
70–89 % — bon niveau, cible la matrice des DF.
≥ 95 % — niveau de maîtrise recherché.
