Chapitre 3 — Dictionnaire de données et dépendances fonctionnelles

Mise en situation

Le client raconte son activité en vrac : factures, clients, remises, catégories. Avant tout schéma, l'analyste recense les propriétés une à une (le dictionnaire de données) et écrit ce qui détermine quoi (les dépendances fonctionnelles). Ces deux documents préparent le MCD — et évitent les propriétés fantômes inventées plus tard.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. classer une propriété en élémentaire, composée ou calculée ;
  2. constituer un dictionnaire de données propre (types, formats, remarques) ;
  3. formuler une dépendance fonctionnelle « source détermine cible » à partir d'une règle de gestion ;
  4. construire la matrice des dépendances et en déduire l'identifiant d'une entité.

1. Le dictionnaire de données

Le dictionnaire de données recense et décrit l'ensemble des propriétés qui serviront à élaborer le MCD : nom, type (texte, nombre, date), format, nature, remarques. Une propriété est :

  • élémentaire : elle ne se déduit d'aucune autre ;
  • composée : sa valeur résulte d'une règle de construction sur d'autres informations (une adresse = numéro, rue, ville) ;
  • calculée : elle se déduit d'une autre propriété par une règle de calcul (le TTC depuis le HT et la TVA).

Les propriétés calculées ne s'enregistrent pas : elles se recalculent. Le dictionnaire les note, mais le MCD les écarte. Le recueil se fait en interviewant les acteurs et en étudiant les documents existants (factures, bons de livraison, registres) : chaque rubrique d'un document est une propriété candidate.

Mnémotechnique — « E-C-C : élémentaire, composée, calculée »

Élémentaire = irremplaçable. Composée = assemblée (décomposable). Calculée = déductible. Seules les deux premières entrent dans le MCD ; la calculée retourne aux traitements.

2. Dépendances fonctionnelles et matrice

Une dépendance fonctionnelle (DF) relie deux propriétés : « connaître la valeur de A suffit à connaître celle de B ». On écrit A → B : A détermine B. Exemple : NumClt → NomClt (le numéro de client détermine son nom) ; NumCde → DateCde.

Les DF se tirent des règles de gestion énoncées par le client (« une facture concerne un et un seul client ») et se contrôlent sur les documents : une même source qui détermine deux cibles contradictoires révèle une erreur d'analyse ou une propriété mal décomposée.

La matrice des dépendances croise toutes les propriétés : pour chaque couple (ligne source, colonne cible), une croix si la DF existe. On y lit : les identifiants candidats (les sources qui déterminent le plus de propriétés), les propriétés élémentaires, et les associations éventuelles entre entités (une source qui détermine l'identifiant d'un autre groupe de propriétés signale une CIF, contrainte d'intégrité fonctionnelle). Des symboles complètent la légende : association réflexive, DF élémentaire et directe, CIF.

Confusions d'examen
  • Le TTC est calculé, donc écarter du dictionnaire des propriétés à modéliser.
  • Une DF se vérifie sur des exemples : NumClt → VilleClt est suspecte si deux clients d'une même ville… si, ça marche — mais VilleClt → NumClt est fausse.
  • Le sens de la flèche compte : A → B ne dit rien de B → A.
  • Une règle de gestion qui ne donne aucune DF est soit mal comprise, soit un simple commentaire.

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

Exercice 1 — Le dictionnaire de données du camping Les Pins Bleus

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Compléter un dictionnaire de données : type, longueur et nature (élémentaire, composée, calculée) de chaque rubrique.

Énoncé. Le camping Les Pins Bleus prépare l'informatisation de ses réservations. L'analyste a étudié les documents existants (fiche d'accueil, carnet de réservations) et obtient le dictionnaire de données suivant, partiellement rempli :

RubriqueTypeLongueurNature
NumResaNombre4élémentaire
DateDebut…—élémentaire
NbPersonnesNombre2élémentaire
NomCampeur…30élémentaire
AdresseCampeurTexte60…
MontantSejourNombre8…

Précisions de gestion : DateDebut est la date d'arrivée au camping ; NomCampeur est le nom du campeur ; AdresseCampeur assemble numéro, rue et ville (par exemple « 12 rue des Palmiers, Lomé ») ; MontantSejour s'obtient en multipliant le nombre de nuitées par le tarif de l'emplacement.

Rappel du cours : les types sont texte, nombre et date ; les natures sont élémentaire (non déductible), composée (assemblée par une règle de construction) et calculée (déduite par une règle de calcul). Les propriétés calculées ne s'enregistrent pas : elles se recalculent.

Répondez par un seul mot, sauf la question 5 (un nombre).

  1. Quel est le type de la rubrique DateDebut ?
  2. Quel est le type de la rubrique NomCampeur ?
  3. Quelle est la nature de la rubrique AdresseCampeur ?
  4. Quelle est la nature de la rubrique MontantSejour ?
  5. Quelle est la longueur prévue pour la rubrique NomCampeur ? (un nombre)
  6. La rubrique MontantSejour doit-elle être enregistrée dans une table du futur modèle ? (oui/non)
Cas d’exemple
Le salon de coiffure Éclat dresse son dictionnaire : NumVisite (Nombre, longueur 5, élémentaire), DateCoupe (—, élémentaire), NomClient (—, longueur 25, élémentaire), AdresseClient (Texte, 50, …), MontantTotal (Nombre, 6, …). L'adresse assemble numéro, rue et ville ; le montant total vaut nombre de prestations × tarif.

1) Type de DateCoupe : date.
2) Type de NomClient : texte.
3) Nature de AdresseClient : composee.
4) Nature de MontantTotal : calculee.
5) Longueur de NomClient : 25.
6) MontantTotal enregistrée dans le modèle ? non.
Trois indices, rédigés en mots
  1. Les types du cours : texte, nombre, date. Les natures : élémentaire (rien ne la déduit), composée (assemblée à partir d'autres informations), calculée (déduite par un calcul).
  2. Pour chaque case vide, relisez la précision de gestion : une date d'arrivée, un nom de campeur, une adresse qui assemble numéro, rue et ville, un montant obtenu par une multiplication.
  3. Le montant du séjour se recalcule à chaque tarif : le cours dit précisément ce qu'il faut faire des propriétés calculées avant de construire le modèle.

Exercice 2 — Les règles de gestion du vidéoclub CinéPalmes

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Traduire des règles de gestion en dépendances fonctionnelles et contrôler le sens de la flèche.

Énoncé. Le vidéoclub CinéPalmes gère encore ses emprunts sur fichier papier. L'analyste relève avec Awa, la gérante, les règles de gestion suivantes :

  • chaque client reçoit un numéro unique (NumClient) et possède un nom (NomClient) et un téléphone (TelClient) ;
  • deux clients peuvent porter le même nom ;
  • chaque film reçoit un numéro unique (NumFilm), un titre (TitreFilm) et un support (SupportFilm) ;
  • chaque emprunt reçoit un numéro unique (NumEmprunt) et se fait à une date donnée (DateEmprunt) ;
  • plusieurs emprunts peuvent avoir lieu le même jour, pour des clients différents.

Rappel du cours : une dépendance fonctionnelle A → B signifie que connaître la valeur de A suffit à connaître celle de B ; le sens de la flèche compte, A → B ne dit rien de B → A.

Répondez par oui ou non aux questions 1 à 4.

  1. La dépendance NumClient → NomClient est-elle fonctionnelle ?
  2. La dépendance NomClient → NumClient est-elle fonctionnelle ?
  3. La dépendance NumEmprunt → DateEmprunt est-elle fonctionnelle ?
  4. La dépendance DateEmprunt → NumClient est-elle fonctionnelle ?
  5. La règle « le numéro de film détermine le titre du film » se traduit par une dépendance fonctionnelle : quel est le nom de la rubrique source ? (nom exact)
  6. Dans la dépendance NumClient → TelClient, quel est le nom de la rubrique cible ? (nom exact)
Cas d’exemple
Un loueur de vélos : chaque vélo reçoit un numéro unique (NumVelo), un type (TypeVelo) ; deux vélos peuvent être du même type ; chaque location reçoit un numéro unique (NumLocation), une date (DateLocation) et un montant (MontantLocation) ; plusieurs locations ont lieu le même jour.

1) NumVelo → TypeVelo : oui.
2) TypeVelo → NumVelo : non.
3) NumLocation → DateLocation : oui.
4) DateLocation → NumVelo : non.
5) Source de « le numéro de vélo détermine le type du vélo » : NumVelo.
6) Cible de NumLocation → MontantLocation : MontantLocation.
Trois indices, rédigés en mots
  1. Une DF A → B : connaître A suffit pour connaître B. Le sens de la flèche compte, et l'inverse n'est pas automatique.
  2. Testez chaque flèche avec des exemples : deux clients homonymes, plusieurs emprunts le même jour, un numéro unique d'emprunt.
  3. Dans la question 5, remplacez mentalement « détermine » par une flèche : la source est la rubrique qui détermine, la cible celle qui est déterminée.

Exercice 3 — La matrice des dépendances de la pharmacie du Marché

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Lire une matrice des dépendances pour trouver un identifiant, une source de DF et une CIF.

Énoncé. La pharmacie du Marché prépare son futur système de gestion des médicaments. Les propriétés recensées : NumMedicament, NomMedicament, PrixUnitaire, CodeFamille, NomFamille, NumFournisseur, NomFournisseur. Le groupe de propriétés de la famille est identifié par CodeFamille, celui du fournisseur par NumFournisseur. L'analyste dresse la matrice des dépendances :

Source ↓ / Cible →NomMedicamentPrixUnitaireCodeFamilleNomFamilleNumFournisseurNomFournisseur
NumMedicament××××
CodeFamille×
NumFournisseur×

Précisions de gestion : chaque famille de médicaments a un code et un seul nom ; deux conditionnements différents d'un même principe actif (boîte de 10 et boîte de 20) portent le même NomMedicament mais des prix différents.

Rappel du cours : dans la matrice, une croix à l'intersection (ligne source, colonne cible) signale une DF. La source qui détermine le plus de propriétés est un identifiant candidat ; une DF vers l'identifiant d'un autre groupe de propriétés signale une CIF (contrainte d'intégrité fonctionnelle).

  1. Quelle rubrique détermine toutes les propriétés du groupe médicament et sert d'identifiant à l'entité MEDICAMENT ? (nom exact)
  2. La dépendance NumMedicament → NumFournisseur relie MEDICAMENT à l'identifiant du groupe fournisseur : quel sigle de trois lettres nomme ce type de contrainte ?
  3. Quelle est la rubrique source de la dépendance qui détermine NomFamille ? (nom exact)
  4. La dépendance NomMedicament → PrixUnitaire est-elle fonctionnelle ? (oui/non)
  5. Combien de croix compte la ligne NumMedicament de la matrice ? (un nombre)
Cas d’exemple
Un magasin de pièces auto : NumPiece → NomPiece, PrixPiece, CodeRayon ; CodeRayon → NomRayon. Deux conditionnements d'une même pièce portent le même nom mais des prix différents ; le groupe rayon est identifié par CodeRayon.

1) Identifiant du groupe pièce : NumPiece.
2) NumPiece → CodeRayon (identifiant du groupe rayon) : c'est une CIF.
3) Source de la DF vers NomRayon : CodeRayon.
4) NomPiece → PrixPiece : non.
5) Croix sur la ligne NumPiece : 3.
Trois indices, rédigés en mots
  1. Dans la matrice, chaque croix se lit « la rubrique de la ligne détermine la rubrique de la colonne ».
  2. L'identifiant d'un groupe est la source qui détermine toutes les autres propriétés de ce groupe ; comptez les croix de chaque ligne.
  3. Pour la question 4, servez-vous de la règle des boîtes de 10 et de 20 : à un même nom, combien de prix possibles ?

4. QCM — niveau examen

Le MontantTTC d'une facture est une propriété…

Il se déduit du HT et de la TVA par une règle de calcul : le MCD ne le mémorise pas.

« Adresse = numéro, rue, ville » : Adresse est…

Sa valeur est obtenue par une règle de construction sur d'autres informations.

NumClt → NomClt se lit…

A → B : connaître A suffit pour connaître B.

Le dictionnaire de données sert à…

Il recense et décrit l'ensemble des propriétés utilisées pour élaborer le MCD.

La matrice des dépendances sert à…

Croisement sources × cibles : on y lit identifiants candidats, propriétés élémentaires et CIF.

NumCde → NumClt (numéro de commande détermine le client) est…

Une DF vers l'identifiant d'un autre groupe de propriétés est une contrainte d'intégrité fonctionnelle.

Une propriété calculée dans une table…

Elle risque de contredire le recalcul ; on la calcule au moment du traitement.

À quoi reconnaît-on l'identifiant dans la matrice ?

L'identifiant détermine toutes les propriétés de son entité.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Mémoriser une propriété calculée : le TTC se recalcule, il ne s'enregistre pas.
  • Inverser le sens d'une DF dans la matrice : la source détermine la cible, jamais l'inverse.
  • Oublier de décomposer une adresse (numéro, rue, ville) : la propriété composée masque des attributs utiles.
  • Écrire des DF sans règle de gestion derrière : une DF se justifie par un énoncé ou un document.

6. Méthodologie de résolution

Méthode — du document au dictionnaire
  1. Lister les rubriques de chaque document de l'entreprise (facture, bon, registre).
  2. Pour chaque propriété : élémentaire, composée ou calculée ? Calculée = écartée.
  3. Énoncer les règles de gestion et les traduire en DF (source → cible).
  4. Construire la matrice, lire les identifiants candidats et les CIF.

7. Révision active

Résumé essentiel
  • Le dictionnaire de données recense toutes les propriétés : nom, type, format, nature.
  • Trois natures : élémentaire (à garder), composée (à décomposer), calculée (à écarter).
  • Une DF « A → B » : connaître A suffit à connaître B ; elle se justifie par une règle de gestion.
  • La matrice des dépendances révèle identifiants candidats et contraintes d'intégrité fonctionnelle.

Checklist de maîtrise

  • Je sais trier douze propriétés en élémentaires, composées et calculées.
  • Je sais écrire cinq DF à partir de règles de gestion.
  • Je sais lire une matrice des dépendances et proposer un identifiant.
  • Je sais expliquer pourquoi le TTC ne s'enregistre pas.

Les 8 notions à connaître absolument

  1. Propriété : plus petit élément d'information manipulable.
  2. Élémentaire : non déductible d'autres propriétés.
  3. Composée : assemblée par une règle de construction.
  4. Calculée : déduite par une règle de calcul (à écarter).
  5. Dépendance fonctionnelle : A → B, connaître A suffit pour B.
  6. Dictionnaire de données : inventaire descriptif des propriétés.
  7. Matrice des dépendances : croisement sources × cibles des DF.
  8. CIF : contrainte d'intégrité fonctionnelle entre deux entités.

8. Test de maîtrise

Comment vous auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lisez votre pourcentage :

< 50 % — reprenez les trois natures de propriété.
50–69 % — refaites le dictionnaire d'un document (facture, bon de livraison).
70–94 % — bon niveau, ciblez la matrice des DF.
≥ 95 % — niveau de maîtrise recherché.
