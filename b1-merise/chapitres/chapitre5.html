Chapitre 5 — Le modèle logique des données (MLD relationnel)

Module 5 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le MCD est validé par le métier, mais l'ordinateur ne comprend pas les bulles et les patates. Le MLD traduit : chaque entité devient une table, chaque association porteuse aussi, et les cardinalités deviennent des clés primaires et étrangères. C'est la forme machinale du modèle — celle que le SGBD exécutera.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. définir attribut, table (relation), clé primaire et clé étrangère ;
  2. appliquer les règles de passage du MCD au MLD ;
  3. écrire un schéma relationnel en notation textuelle avec les # ;
  4. expliquer les contraintes d'intégrité de domaine, de relation et référentielle.

1. Tables, clés et règles de passage

Le MLD est la forme machinale du MCD : il s'appuie sur le modèle relationnel. L'attribut est le plus petit élément d'information manipulable ; la table (ou relation) est un ensemble d'attributs significativement associés ; chaque ligne (tuple) est distinguée par une clé.

Deux types de clés : la clé primaire (simple ou composée) identifie chaque ligne ; la clé étrangère est un attribut qui est clé primaire d'une autre table — elle porte les liens du système d'information et se note avec un # :

CLIENT (NumClt, NomClt, AdrClt)

COMMANDE (NumCde, DateCde, #NumClt)

LIGNE_CDE (#NumCde, #RefPdt, Quantite)

Les règles de passage du MCD au MLD :

  • Règle 1 : toute entité devient une table ; son identifiant devient clé primaire, ses propriétés deviennent des attributs.
  • Règle 2 : toute association non hiérarchique (porteuse, max = n) devient une table ; sa clé primaire est la concaténation des identifiants des entités participantes.
  • Règle 3 : toute association hiérarchique avec une cardinalité (0,1) ou (1,1) migre sa clé comme étrangère dans la table côté (0,1)/(1,1) — pas de table nouvelle.
Mnémotechnique — « entité = table, porteuse = table, (x,1) = # »

Deux règles créent des tables (entité, association porteuse) ; la troisième déplace une clé. Un # dans le schéma = un lien vers une autre table, donc une intégrité à surveiller.

2. Les trois intégrités

Les contraintes d'intégrité contrôlent les valeurs prises par les attributs :

  • Intégrité de domaine : chaque attribut respecte son domaine de valeurs (une quantité est un entier positif).
  • Intégrité de relation : la clé primaire est unique et non nulle — deux clients ne peuvent porter le même numéro, aucun client ne va sans numéro.
  • Intégrité référentielle : une clé étrangère doit référencer une clé primaire existante — pas de NumClt 25 dans COMMANDE si les clients vont de 1 à 15.

Le MLD peut ensuite être transformé en fichiers et en base de données (MPD) : choix du SGBD, des types SQL, des index. Le schéma relationnel textuel est le document de passage entre l'analyse et l'implémentation — celui que le développeur SQL lit.

Confusions d'examen
  • Oublier le # sur une clé étrangère : le lien disparaît du schéma.
  • Créer une table pour une association hiérarchique (x,1) : sa clé migre comme étrangère, point.
  • Confondre intégrité de relation (clé unique) et référentielle (fk existe dans la table référencée).
  • MLD ≠ MPD : le MLD est logique (tables), le MPD est physique (SGBD, index, fichiers).

3. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Les règles de passage MCD vers MLD

Bash Niveau 1 — Acquisition

Objectif : Appliquer les règles de passage : entités et associations porteuses deviennent des tables.

Le script lit n lignes « nom nature » : nature vaut entite ou assoc (association). Une association avec des données portées (toute ligne assoc de ce sujet) devient une table ; une association sans données portées (nature assoc0) n'en devient pas. Pour chaque ligne il affiche nom : table ou nom : ignoree. Il termine par MLD : X tables.

Entrée du programme
4
CLIENT entite
PRODUIT entite
FOURNIR assoc
APPARTENIR assoc0
Sortie attendue
CLIENT : table
PRODUIT : table
FOURNIR : table
APPARTENIR : ignoree
MLD : 3 tables
Deux indices, rédigés en mots
  1. Trois natures, trois comportements : entite et assoc créent une table, assoc0 non.
  2. Incrémentez le compteur dans chaque branche qui crée une table.

Exercice 2 — La clé primaire et les étrangères

Bash Niveau 2 — Application

Objectif : Valider les clés : unicité des primaires, références des étrangères (intégrité référentielle).

Le script lit n lignes « table cle type » : type vaut pk (clé primaire à déclarer) ou fk:REF (clé étrangère référençant la table REF). Pour chaque ligne il affiche table : cle ok, ou table : doublon si la même clé primaire est déclarée deux fois, ou table : REF inconnue si la table référencée n'a pas (encore ou jamais) de clé primaire déclarée. Il termine par lignes valides : X/n.

Entrée du programme
4
CLIENT NumClt pk
COMMANDE NumCde pk
COMMANDE NumClt fk:CLIENT
LIVRAISON NumClt fk:FOURNISSEUR
Sortie attendue
CLIENT : NumClt ok
COMMANDE : NumCde ok
COMMANDE : NumClt ok
LIVRAISON : FOURNISSEUR inconnue
lignes valides : 3/4
Deux indices, rédigés en mots
  1. Un tableau associatif primaires[REF] est rempli par les lignes pk ; les fk consultent ce même tableau.
  2. L'ordre compte : une fk qui référence une table dont la pk arrive plus tard est « inconnue » à cette ligne.

Exercice 3 — Le schéma relationnel complet

Bash Niveau 3 — Raisonnement

Objectif : Assembler un schéma relationnel : table (cle, attributs..., fk#) vérifiée champ par champ.

Le script lit d'abord n_tables puis déclare chaque table par une ligne table cle. Puis il lit n_attrs lignes « table champ » où champ est soit la clé de la table (il devient #pk dans l'affichage), soit une clé étrangère référençant une table déclarée (affichée champ#), soit un attribut simple (affiché tel quel). Chaque champ connu est affiché table : champ_role où role vaut pk, fk ou attr. Un champ appartenant à une table non déclarée produit champ : table inconnue.

Entrée du programme
2
CLIENT NumClt
COMMANDE NumCde
4
CLIENT NomClt
COMMANDE NumCde
COMMANDE NumClt
COMMANDE DateCde
Sortie attendue
CLIENT : NomClt attr
COMMANDE : NumCde pk
COMMANDE : NumClt fk
COMMANDE : DateCde attr
Deux indices, rédigés en mots
  1. Premier test : la table est-elle déclarée ? Deuxième : le champ est-il la clé de sa table ? Troisième : le champ est-il la clé d'une autre table (donc fk) ? Sinon attribut.
  2. Parcourez le tableau des clés déclarées pour savoir si le champ en est une.

L'identifiant devient clé primaire, les propriétés deviennent attributs.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Écrire le schéma sans les # : les liens sont invisibles pour le lecteur.
  • Donner une clé primaire composée à une table qui n'en a pas besoin (ou l'inverse).
  • Créer une table pour chaque association, même hiérarchique : les règles de passage existent.
  • Confondre MLD et MPD : logique ≠ physique.

6. Méthodologie de résolution

Méthode — du MCD au schéma
  1. Une table par entité (règle 1) : clé primaire = identifiant.
  2. Une table par association porteuse (règle 2) : clé = concaténation des identifiants.
  3. Les associations (0,1)/(1,1) migrent leur clé en # (règle 3).
  4. Vérifier les trois intégrités sur le schéma final.

7. Révision active

Résumé essentiel
  • MLD = forme machinale du MCD, en tables relationnelles.
  • Clé primaire (simple ou composée) identifie chaque ligne ; clé étrangère (#) porte le lien.
  • Règles de passage : entité → table ; association porteuse → table (clé concaténée) ; (0,1)/(1,1) → #.
  • Trois intégrités : de domaine, de relation (pk unique non nulle), référentielle (fk → pk existante).

Checklist de maîtrise

  • Je sais écrire CLIENT (NumClt, NomClt) et COMMANDE (NumCde, #NumClt).
  • Je sais appliquer les trois règles de passage sur un MCD à trois entités.
  • Je sais citer et illustrer les trois intégrités.
  • Je sais dire ce qui distingue MLD et MPD.

Les 8 notions à connaître absolument

  1. Attribut : plus petit élément d'information manipulable.
  2. Table (relation) : ensemble d'attributs significativement associés.
  3. Clé primaire : identifie chaque ligne, simple ou composée.
  4. Clé étrangère : pk d'une autre table, notée #.
  5. Règle 1 : entité → table.
  6. Règle 2 : association porteuse → table, clé concaténée.
  7. Intégrité de relation : pk unique et non nulle.
  8. Intégrité référentielle : fk référence une pk existante.

8. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — reprends clés primaire/étrangère et les règles de passage.
50–69 % — refais le passage MCD → MLD de la facture.
70–89 % — bon niveau, cible les trois intégrités.
≥ 95 % — niveau de maîtrise recherché.
