Chapitre 5 — Le modèle logique des données (MLD relationnel)

Module 5 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le MCD est validé par le métier, mais l'ordinateur ne comprend pas les bulles et les patates. Le MLD traduit : chaque entité devient une table, une association n–n une table de liaison, et les cardinalités deviennent des clés primaires et étrangères. C'est la forme machinale du modèle — celle que le SGBD exécutera.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. définir attribut, table (relation), clé primaire et clé étrangère ;
  2. appliquer les règles de passage du MCD au MLD ;
  3. écrire un schéma relationnel en notation textuelle avec les # ;
  4. expliquer les contraintes d'intégrité de domaine, de relation et référentielle.

1. Tables, clés et règles de passage

Le MLD est la forme machinale du MCD : il s'appuie sur le modèle relationnel. L'attribut est le plus petit élément d'information manipulable ; la table (ou relation) est un ensemble d'attributs significativement associés ; chaque ligne (tuple) est distinguée par une clé.

Deux types de clés : la clé primaire (simple ou composée) identifie chaque ligne ; la clé étrangère est un ou plusieurs attributs qui référencent une clé primaire ou unique de la table cible, éventuellement la même table. Elle porte un lien et se note avec un # :

CLIENT (NumClt, NomClt, AdrClt)

COMMANDE (NumCde, DateCde, #NumClt)

LIGNE_CDE (#NumCde, #RefPdt, Quantite)

Les règles de passage du MCD au MLD :

  • Règle 1 : toute entité devient une table ; son identifiant devient clé primaire, ses propriétés deviennent des attributs.
  • Règle 2 : une association binaire n–n devient une table de liaison, même sans propriété ; si chaque couple est unique, les deux identifiants forment sa clé composée.
  • Règle 3 : pour une association 1–n, la clé migre dans la table du côté de maximum 1, avec les éventuelles propriétés de l’association. Pour 1–1, choisir le côté selon les contraintes et ajouter l’unicité nécessaire.
Mnémotechnique — « entité = table, n–n = liaison, 1–n = # »

Ce sont les cardinalités, et non la seule présence de propriétés, qui guident la traduction. Un # indique un lien dont l’intégrité reste à contrôler.

2. Les trois intégrités

Les contraintes d'intégrité contrôlent les valeurs prises par les attributs :

  • Intégrité de domaine : chaque attribut respecte son domaine de valeurs (une quantité est un entier positif).
  • Intégrité de relation : la clé primaire est unique et non nulle — deux clients ne peuvent porter le même numéro, aucun client ne va sans numéro.
  • Intégrité référentielle : une clé étrangère référence une clé primaire ou unique existante, sous réserve des règles propres à NULL — pas de NumClt 25 dans COMMANDE si les clients vont de 1 à 15.

Le MLD peut ensuite être transformé en fichiers et en base de données (MPD) : choix du SGBD, des types SQL, des index. Le schéma relationnel textuel est le document de passage entre l'analyse et l'implémentation — celui que le développeur SQL lit.

Confusions d'examen
  • Oublier le # sur une clé étrangère : le lien disparaît du schéma.
  • Oublier une table de liaison n–n parce que l’association ne porte aucune donnée.
  • Confondre intégrité de relation (clé unique) et référentielle (fk existe dans la table référencée).
  • MLD ≠ MPD : le MLD est logique (tables), le MPD est physique (SGBD, index, fichiers).

3. Pour aller plus loin : Lire et comprendre les mots-clés SQL du MLD (CREATE TABLE, PRIMARY KEY, REFERENCES)

Comprendre la traduction SQL sans attendre le cours de SQL

Exemples de mots-clés SQL (approfondis dans le cours SQL B1) :

  • CREATE TABLE NomTable (...) : crée une table ;
  • PRIMARY KEY : désigne la clé primaire ;
  • FOREIGN KEY (col) REFERENCES AutreTable(code) : référence une clé primaire ou une clé unique admissible de la table cible. Une clé étrangère peut comporter plusieurs colonnes.

Exercice 1 — Les règles de passage MCD vers MLD

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Déterminer une traduction du MCD à partir des cardinalités, même sans attribut porté.

Chaque ligne décrit soit nom entite, soit nom assoc maxA maxB attributs, où maxA et maxB sont les maximums des cardinalités, chacun vaut 1 ou n, et attributs vaut oui ou non. Pour chaque ligne, écrivez nom : TABLE pour une entité, nom : TABLE_LIAISON pour une association n–n, nom : CLE_MIGREE pour une association 1–n, ou nom : CHOIX_1_1 pour 1–1. Une association n–n demande une table de liaison même sans attribut ; en 1–n ses éventuels attributs accompagnent la clé dans la table du côté de maximum 1. En 1–1, le choix du côté et les contraintes exigent une analyse complémentaire. Le modèle ne traite que des associations binaires et leurs maximums ; les minimums et autres contraintes sont à examiner à part.

Cas d’exemple
CLIENT entite
FACTURE entite
EMETTRE assoc n 1 non
Deux indices, rédigés en mots
  1. Deux maximums n demandent une liaison, que l’association porte ou non des propriétés.
  2. Avec un seul maximum 1, la clé migre du côté qui porte ce maximum ; avec deux, discutez le choix.

Exercice 2 — La clé primaire et les étrangères

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Valider les clés : unicité des primaires, références des étrangères (intégrité référentielle).

Analysez chaque ligne proposée « table cle type » : type vaut pk (clé primaire à déclarer) ou fk:REF (clé étrangère référençant la table REF). Pour chaque ligne, indiquez table : cle ok, ou table : doublon si la même clé primaire est déclarée deux fois, ou table : REF inconnue si la table référencée n'a pas (encore ou jamais) de clé primaire déclarée. Terminez par lignes valides : X/n.

Cas d’exemple
4
CLIENT NumClt pk
COMMANDE NumCde pk
COMMANDE NumClt fk:CLIENT
LIVRAISON NumClt fk:FOURNISSEUR
Deux indices, rédigés en mots
  1. Un tableau associatif primaires[REF] est rempli par les lignes pk ; les fk consultent ce même tableau.
  2. L'ordre compte : une fk qui référence une table dont la pk arrive plus tard est « inconnue » à cette ligne.

Exercice 3 — Le schéma relationnel complet

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Assembler un schéma relationnel : table (cle, attributs..., fk#) vérifiée champ par champ.

Analysez les données fournies pour chaque cas. Puis il lit n_attrs lignes « table champ » où champ est soit la clé de la table (il devient #pk dans l'affichage), soit une clé étrangère référençant une table déclarée (affichée champ#), soit un attribut simple (affiché tel quel). Chaque champ connu est affiché table : champ_role où role vaut pk, fk ou attr. Un champ appartenant à une table non déclarée produit champ : table inconnue.

Cas d’exemple
2
CLIENT NumClt
COMMANDE NumCde
4
CLIENT NomClt
COMMANDE NumCde
COMMANDE NumClt
COMMANDE DateCde
Deux indices, rédigés en mots
  1. Premier test : la table est-elle déclarée ? Deuxième : le champ est-il la clé de sa table ? Troisième : le champ est-il la clé d'une autre table (donc fk) ? Sinon attribut.
  2. Parcourez le tableau des clés déclarées pour savoir si le champ en est une.

5. QCM — niveau examen

Le MLD est…

Le MCD n'est pas compréhensible par l'ordinateur ; le MLD est sa forme machinale (relationnelle).

Une clé étrangère est…

Elle référence une clé primaire ou unique admissible, dans la même table ou une autre ; elle peut être simple ou composée.

Le symbole # marque…

COMMANDE (NumCde, DateCde, #NumClt) : NumClt référence CLIENT.

Règle 1 du passage MCD → MLD :

L'identifiant devient clé primaire, les propriétés deviennent attributs.

Une association binaire n–n sans propriété devient…

La table de liaison est nécessaire même sans propriété portée ; le couple d’identifiants peut être sa clé.

Pour une association 1–n, où migre la clé étrangère ?

La clé de l’autre entité migre côté maximum 1 avec les éventuelles propriétés de l’association.

L'intégrité référentielle impose…

Pas de NumClt 25 si les clients s'arrêtent à 15 ; une clé unique admissible peut aussi être référencée.

L'intégrité de relation impose…

Pas de doublon de clé, pas de ligne sans clé.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Écrire le schéma sans les # : les liens sont invisibles pour le lecteur.
  • Donner une clé primaire composée à une table qui n'en a pas besoin (ou l'inverse).
  • Créer une table pour chaque association, même hiérarchique : les règles de passage existent.
  • Confondre MLD et MPD : logique ≠ physique.

7. Méthodologie de résolution

Méthode — du MCD au schéma
  1. Une table par entité (règle 1) : clé primaire = identifiant.
  2. Une table de liaison par association binaire n–n, même sans propriété.
  3. En 1–n, migrer la clé et les propriétés côté maximum 1 ; en 1–1, choisir le côté et imposer l’unicité.
  4. Vérifier les trois intégrités sur le schéma final.

8. Révision active

Résumé essentiel
  • MLD = forme machinale du MCD, en tables relationnelles.
  • Clé primaire (simple ou composée) identifie chaque ligne ; clé étrangère (#) porte le lien.
  • Règles de passage : entité → table ; n–n → liaison ; 1–n → clé étrangère côté maximum 1.
  • Trois intégrités : de domaine, de relation (pk unique non nulle), référentielle (fk → clé admissible existante, sous réserve de NULL).

Checklist de maîtrise

  • Je sais écrire CLIENT (NumClt, NomClt) et COMMANDE (NumCde, #NumClt).
  • Je sais appliquer les trois règles de passage sur un MCD à trois entités.
  • Je sais citer et illustrer les trois intégrités.
  • Je sais dire ce qui distingue MLD et MPD.

Les 8 notions à connaître absolument

  1. Attribut : plus petit élément d'information manipulable.
  2. Table (relation) : ensemble d'attributs significativement associés.
  3. Clé primaire : identifie chaque ligne, simple ou composée.
  4. Clé étrangère : un ou plusieurs attributs référençant une clé primaire ou unique admissible, notés #.
  5. Règle 1 : entité → table.
  6. Règle 2 : association binaire n–n → table de liaison, même sans propriété.
  7. Intégrité de relation : pk unique et non nulle.
  8. Intégrité référentielle : fk référence une clé admissible existante, sous réserve des règles NULL.

9. Test de maîtrise

Comment vous auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lisez votre pourcentage :

< 50 % — reprenez clés primaire/étrangère et les règles de passage.
50–69 % — refaites le passage MCD → MLD de la facture.
70–94 % — bon niveau, ciblez les trois intégrités.
≥ 95 % — niveau de maîtrise recherché.
