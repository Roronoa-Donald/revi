Chapitre 3 — Conditions

Module 3 ≈ 3 h de travail B1 et plus
Mise en situation

Un site de vente applique la livraison offerte à partir de 50 EUR, refuse les mots de passe trop courts et classe les étudiants par mention. Dans les trois cas, le programme choisit : il compare des valeurs et exécute la branche correspondante. C'est le test alternatif — la première structure de contrôle d'un programme.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. écrire un test simple et un test double (if / else) ;
  2. construire une cascade if / elseif / else dans le bon ordre ;
  3. combiner des conditions avec && et || ;
  4. choisir entre == et ===, et éviter le piège de = dans un test.

1. Test simple et test double

Définition. Le test alternatif exécute un bloc d'instructions seulement si une condition est vraie. La version double ajoute une branche par défaut, exécutée quand la condition est fausse.

// test simple
if ($note >= 10) {
    echo "Admis\n";
}

// test double
if ($note >= 10) {
    echo "Admis\n";
} else {
    echo "Ajourne\n";
}

La condition est une expression booléenne : le résultat d'une comparaison. Les opérateurs de comparaison : == (égal), != (différent), <, <=, >, >=. Attention : en PHP, l'égalité de valeur s'écrit avec deux signes == — un seul = est une affectation.

Piège — = au lieu de ==

if ($nom = "admin") affecte "admin" à $nom puis évalue le résultat (une chaîne non vide : toujours vrai). La branche s'exécute donc à chaque fois, et la variable est écrasée. Le test voulu est if ($nom === "admin"). PHP ne le signale pas : c'est au lecteur de le repérer.

2. La cascade if / elseif / else

Quand plusieurs cas s'excluent mutuellement, on enchaîne : if, puis autant de elseif que nécessaire, puis un else final. Le mot est unique : elseif.

if ($note >= 16) {
    echo "Tres bien\n";
} elseif ($note >= 14) {
    echo "Bien\n";
} elseif ($note >= 10) {
    echo "Passable\n";
} else {
    echo "Ajourne\n";
}
Intuition : la première vraie gagne

PHP évalue les conditions de haut en bas ; dès qu'une est vraie, il exécute son bloc et saute tout le reste. D'où la règle d'or : ordonner du cas le plus exigeant au plus général. Si la cascade commence par $note >= 10, la note 17 est attrapée par cette branche et ne voit jamais « Tres bien ».

3. Combiner des conditions

LogiquePHPVrai si…
ET&&les deux conditions sont vraies
OU||au moins une est vraie
NON!la condition est fausse
// gratuit : moins de 12 ans OU 65 ans et plus
if ($age < 12 || $age >= 65) {
    echo "Gratuit\n";
}

// réduit : entre 12 et 17 inclus
if ($age >= 12 && $age <= 17) {
    echo "Reduit\n";
}

Les parenthèses du if délimitent la condition entière ; à l'intérieur, && est évalué avant ||. Ajouter des parenthèses explicites rend la lecture sûre quand les deux se mélangent.

4. == ou === ?

PHP compare de deux façons :

OpérateurComparaisonExemple
==Valeurs, après conversion de type"42" == 42 → vrai
===Valeurs et types"42" === 42 → faux

La version stricte évite les surprises de conversion (0 == "texte" valait vrai dans d'anciennes versions, par exemple). La règle du cours : utiliser === et !== par défaut, et réserver == aux cas où la conversion est voulue.

La ternaire : un if d'expression

echo ($note >= 10 ? "Admis" : "Ajourne") . "\n"; — la condition ternaire renvoie l'une des deux valeurs selon le test. Pratique pour choisir un texte ou une valeur ; à éviter pour des blocs d'instructions longs.

6. QCM — niveau examen

Que fait if ($x = 5) ?

Un seul = est une affectation ; le test d'égalité s'écrit == ou ===.

Dans une cascade if / elseif / else, quelle branche s'exécute ?

Dès qu'une condition est satisfaite, les suivantes sont ignorées.

Comment écrire « âge entre 12 et 17 inclus » ?

Les deux bornes doivent être vraies ensemble : ET logique.

Que vaut "42" === 42 ?

=== exige même valeur et même type.

Une cascade de mentions doit commencer par…

La première condition vraie gagne : le général attraperait tout.

Le mot correct pour enchaîner un second test en PHP ?

elseif s'écrit en un mot ; elif est du Python.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • = au lieu de == : affectation silencieuse, branche toujours exécutée.
  • Cascade mal ordonnée : le cas général attrape les cas particuliers.
  • || là où && est voulu : « entre 12 et 17 » avec OU est toujours vrai.
  • elseif écrit elif : erreur de syntaxe.
  • Borne oubliée : tester le seuil exact (≥ 10 avec 10, pas 9).

8. Méthodologie de résolution

Construire une cascade fiable
  1. Lister les cas de l'énoncé avec leurs bornes exactes.
  2. Ordonner du plus exigeant au plus général.
  3. Écrire les conditions avec les bons opérateurs (&& pour un intervalle).
  4. Prévoir le else final : le cas « tout le reste ».
  5. Tester les bornes : une valeur sur chaque seuil, une au-dessus, une en dessous.

9. Révision active

Résumé essentiel
  • if / else : exécuter selon une condition ; comparaisons avec <, >=, ===…
  • Cascade if / elseif / else : la première condition vraie gagne.
  • Ordre de la cascade : du plus exigeant au plus général.
  • && exige les deux, || en suffit une, ! inverse.
  • === compare valeur et type ; = affecte et n'est jamais un test.

Checklist de maîtrise

  • J'écris une cascade de mentions dans le bon ordre.
  • Je combine ET et OU sans ambiguïté.
  • Je repère le piège = / === dans un code lu.
  • Je teste chaque borne de mes conditions.
