Chapitre 8 — Formulaires, sessions et PDO

Module 8 ≈ 4 h de travail Synthèse B1
Mise en situation

Voici la chaîne complète d'un site dynamique : un visiteur soumet un formulaire, PHP reçoit et valide les données, les enregistre dans MySQL, puis affiche les pages en reprenant les données de la session. Ce chapitre assemble tout le cours autour de trois outils : $_POST, $_SESSION et PDO.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. lire et valider des données de formulaire ;
  2. mémoriser des informations entre deux pages avec la session ;
  3. se connecter à MySQL avec PDO en mode exceptions ;
  4. exécuter SELECT et INSERT avec des requêtes préparées et parcourir les résultats.

1. Recevoir un formulaire : $_POST

Définition. Quand un formulaire HTML est soumis en méthode POST, PHP range chaque champ dans le tableau superglobal $_POST, indexé par le nom du champ. La donnée arrive brute : la validation est le travail du script.

// le formulaire a envoyé les champs "email" et "mdp"
$email = $_POST['email'] ?? '';      // ?? évite le champ absent
$mdp = $_POST['mdp'] ?? '';

if (str_contains($email, '@') && strlen($mdp) >= 6) {
    // données acceptables : suite du traitement
} else {
    echo "Formulaire invalide\n";
}

Deux réflexes : l'opérateur ?? fournit une valeur par défaut quand le champ manque (« Undefined array key » évité), et chaque règle de validation se traduit en condition — arobase présente, longueur minimale, intervalle numérique.

Piège — ne jamais afficher une donnée brute

Une donnée venue de l'extérieur peut contenir du HTML ou du JavaScript. L'afficher telle quelle ouvre la porte à l'injection XSS. Toujours passer par htmlspecialchars($valeur) au moment d'afficher : les chevrons sont neutralisés, la donnée reste du texte.

2. La session : se souvenir d'un visiteur

HTTP oublie tout entre deux requêtes. La session donne au site une mémoire par visiteur : le panier, le login, le compteur de pages vues. Tout passe par le tableau $_SESSION, disponible après session_start().

session_start();

if (!isset($_SESSION['visites'])) {
    $_SESSION['visites'] = 0;
}
$_SESSION['visites']++;

echo "Visites : " . $_SESSION['visites'] . "\n";

Même réflexe que les tableaux associatifs du chapitre 7 : tester avec isset avant de lire ou d'incrémenter. La session vit côté serveur ; le navigateur ne porte qu'un identifiant.

3. Connexion à MySQL avec PDO

Définition. PDO (PHP Data Objects) est l'interface standard d'accès aux bases de données. On construit un objet PDO avec le DSN (type de base, hôte, nom, encodage), un utilisateur et un mot de passe.

try {
    $pdo = new PDO(
        'mysql:host=localhost;dbname=boutique;charset=utf8mb4',
        'utilisateur',
        'motdepasse',
        [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
    );
} catch (PDOException $e) {
    echo "Connexion impossible : " . $e->getMessage() . "\n";
}

ERRMODE_EXCEPTION demande à PDO de lever une exception en cas d'erreur SQL — le bloc catch l'attrape et affiche le message proprement. C'est le réglage par défaut de tout nouveau code.

4. La requête préparée : SELECT et INSERT

Une donnée externe ne s'insère jamais directement dans le texte SQL : on prépare la requête avec un emplacement ?, puis on exécute en passant les valeurs. La donnée ne peut plus modifier la requête — les injections SQL sont bloquées.

// SELECT : parcourir les résultats
$stmt = $pdo->prepare('SELECT nom, note FROM etudiants WHERE promotion = ?');
$stmt->execute(['B1']);

foreach ($stmt as $ligne) {
    // $ligne est un tableau associatif colonne => valeur
    echo $ligne['nom'] . " : " . $ligne['note'] . "\n";
}

// INSERT : enregistrer une ligne
$stmt = $pdo->prepare('INSERT INTO etudiants (nom, note) VALUES (?, ?)');
$stmt->execute([$nom, $note]);

Chaque ligne de résultat arrive sous la forme d'un tableau associatif (chapitre 7) : le foreach clé → valeur que vous maîtrisez déjà visite les colonnes. La boucle de lecture d'un jeu de résultats et la boucle d'un inventaire sont le même code.

La chaîne complète en résumé

Valider les entrées (conditions du module 3) → préparer la requête (PDO) → exécuter avec les valeurs → parcourir les résultats (foreach du module 7) → afficher protégé (htmlspecialchars). Chaque maillon a été appris séparément ; ici, ils s'enchaînent.

Intuition : pourquoi le ? change tout

Avec une concaténation, la donnée devient du code SQL : une valeur saisie « ' ; DROP TABLE ... » exécute quelque chose. Avec ?, la donnée reste une donnée : le moteur l'envoie séparément de la requête, et aucun caractère saisi ne peut en changer le sens. Une règle, jamais d'exception.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Valider un formulaire

PHP Niveau 3 — Raisonnement

Objectif : Vérifier des données saisies avant de les accepter.

Le programme reçoit deux lignes : un email et un mot de passe. Affichez OK si l’email contient une arobase ET le mot de passe compte au moins 6 caractères ; sinon affichez Refuse.

Entrée du programme
alice@ex.fr
motdepasse
Sortie attendue
OK

Arobase présente, mot de passe assez long.

Deux indices, rédigés en mots
  1. str_contains teste la présence d’une sous-chaîne, strlen la longueur d’une chaîne.
  2. Les deux règles doivent être vraies en même temps : c’est le ET logique qui les combine.

Exercice 2 — Parcourir des résultats comme PDO

PHP Niveau 4 — Examen

Objectif : Manipuler des lignes nom → valeur, comme les résultats d’une requête.

Le programme reçoit un entier n, puis n lignes de la forme nom age (un mot, une espace, un entier), comme autant de lignes renvoyées par une requête. Affichez le nom et l’âge de la personne la plus âgée, séparés par une espace.

Entrée du programme
2
Ines 19
Paul 22
Sortie attendue
Paul 22

Paul est le plus âgé des deux.

Deux indices, rédigés en mots
  1. Un tableau associatif nom → âge joue le rôle du jeu de résultats : un foreach visite chaque ligne.
  2. Gardez le meilleur candidat vu jusqu’ici : nom et âge avancent ensemble quand un âge supérieur apparaît.

Exercice 3 — Contrôler les données avant l’INSERT

PHP Niveau 5 — Challenge

Objectif : Valider un lot de données avant de l’envoyer à la base.

Le programme reçoit un entier n, puis n lignes de la forme nom note (un mot, une espace, un entier) destinées à une table. Avant tout INSERT, contrôlez : affichez Valide si toutes les notes sont comprises entre 0 et 20 inclus, sinon Invalide.

Entrée du programme
2
Lea 15
Adam 18
Sortie attendue
Valide

Deux notes dans l’intervalle autorisé.

Deux indices, rédigés en mots
  1. Une seule note hors bornes rend tout le lot refusable : le verdict se construit pendant le parcours.
  2. Un drapeau booléen démarre à true et passe à false dès qu’une valeur sort de l’intervalle autorisé.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Lire $_POST sans ?? ni isset : « Undefined array key » à chaque champ absent.
  • Confiance aveugle dans les données reçues : valider longueur, format, intervalle.
  • Afficher une donnée externe sans htmlspecialchars : faille XSS.
  • SQL concaténé avec une variable : faille d'injection, jamais accepté.
  • session_start() oubliée : $_SESSION vide, « Undefined variable ».

8. Méthodologie de résolution

Écrire un script PHP + MySQL
  1. Lire les entrées ($_POST ou STDIN) avec valeurs par défaut.
  2. Valider chaque règle de l'énoncé en conditions explicites.
  3. Se connecter en try/catch avec ERRMODE_EXCEPTION.
  4. Préparer chaque requête avec ?, puis exécuter avec un tableau de valeurs.
  5. Parcourir et afficher les résultats, protégés à l'affichage.

9. Révision active

Résumé essentiel
  • $_POST reçoit les champs du formulaire ; ?? fournit le défaut.
  • Valider avant d'utiliser ; htmlspecialchars au moment d'afficher.
  • session_start() puis $_SESSION : mémoire par visiteur, réflexes isset.
  • PDO + ERRMODE_EXCEPTION en try/catch pour la connexion MySQL.
  • Requêtes préparées (?) pour tout SELECT ou INSERT paramétré ; lignes = tableaux associatifs.

Checklist de maîtrise

  • Je décris la chaîne complète formulaire → validation → base → affichage.
