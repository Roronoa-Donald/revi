Chapitre 4 — CSS : sélecteurs, cascade et modèle de boîte

Module 4 ≈ 3 h de travail Réservé B1 et plus
Mise en situation

Vous écrivez une règle, la page ignore votre style. Ce n’est presque jamais un bug de navigateur : c’est une règle concurrente qui gagne. CSS applique ses décisions selon des règles précises — spécificité, ordre d’apparition, héritage — et savoir prédire laquelle gagne évite de tout réécrire à l’aveugle.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. écrire une règle CSS et choisir le bon sélecteur ;
  2. calculer la spécificité d’un sélecteur et l’utiliser pour résoudre un conflit ;
  3. expliquer l’ordre dans lequel CSS applique ses règles ;
  4. calculer la largeur réelle d’un élément avec le modèle de boîte ;
  5. choisir des unités adaptées et prévisibles.

1. Une règle, une feuille de style

Une feuille de style CSS est une suite de règles. Chaque règle a un sélecteur (ce qui est visé) et un bloc de déclarations (ce qui est appliqué), sous la forme propriété: valeur;.

/* sélecteur   bloc de déclarations */
h1 {
  font-size: 2rem;
  color: #1c1917;
  margin-bottom: 0.5rem;
}

Trois façons d’appliquer du CSS, dans l’ordre de préférence :

MéthodeOùQuand
feuille externe<link rel="stylesheet" href="styles.css">presque toujours : mise en cache, réutilisable
bloc interne<style> dans le headcas isolé d’une seule page
attribut en ligne<p style="color:red">à éviter : non réutilisable et difficile à surcharger
Piège — le <link> oublié

Un chemin de feuille de style faux ne produit aucune erreur visible : la page s’affiche sans style, et l’onglet Réseau montre une requête en 404. C’est la première chose à vérifier quand « le CSS ne marche pas ».

2. Les sélecteurs

Choisir le sélecteur, c’est exprimer une intention. Les plus utiles :

SélecteurCe qu’il cibleExemple
typetoutes les balises d’un nomp
classeles éléments portant class="…".badge
identifiantl’élément portant id="…"#sommaire
descendantun élément contenu dans un autrenav a
enfant directun enfant immédiatul > li
attributun élément selon ses attributsa[target="_blank"]
pseudo-classeun état de l’élémenta:hover, li:nth-child(2)
pseudo-élémentune partie engendréep::first-line

La classe est le sélecteur du quotidien : elle est réutilisable, explicite et de faible spécificité. Réserver l’id au ciblage unique (ancre de navigation, élément isolé) laisse les styles faciles à surcharger.

Mnémotechnique — « classe pour styler, id pour viser »

Une classe décrit à quoi ressemble un élément ; un id désigne un élément précis. Styler par id revient à écrire une exception dans le CSS : ça marche, mais ça se paie au deuxième élément.

3. Cascade, spécificité et héritage

Quand plusieurs règles visent le même élément, elles ne s’appliquent pas « dans l’ordre du fichier » mais selon une hiérarchie :

  1. Origine : styles du navigateur, puis de l’auteur, puis !important.
  2. Spécificité : un sélecteur plus précis l’emporte.
  3. Ordre d’apparition : à spécificité égale, la dernière règle gagne.

La spécificité se calcule en trois compteurs, lus de gauche à droite : le nombre d’identifiants, puis de classes (et d’attributs et de pseudo-classes), puis de types (et de pseudo-éléments). On ne compare jamais les totaux : on compare compteur par compteur, comme des nombres écrits à côté.

SélecteurIdentifiantsClassesTypes
p001
.item010
div#main.item p112
#app section h2102

L’héritage complète le tableau : certaines propriétés (couleur du texte, police, interlignage) descendent des parents vers les enfants, d’autres non (marges, bordures, position). C’est pourquoi body { color: … } colore toute la page, tandis que body { margin: 0 } ne retire rien aux paragraphes.

Piège — !important comme rustine

!important casse la hiérarchie naturelle : la règle suivante devra elle-même être !important, et le fichier devient ingérable. Un style qui n’est pas appliqué s’explique presque toujours par une spécificité, pas par un manque d’autorité.

4. Le modèle de boîte

Chaque élément est une boîte rectangulaire composée de quatre couches, de l’intérieur vers l’extérieur : le contenu, le padding (marge intérieure), la bordure, puis la marge (extérieure, qui ne se voit pas mais écarte les voisins).

.carte {
  width: 200px;      /* largeur du contenu par défaut */
  padding: 10px;     /* 2 × 10px autour du contenu */
  border: 2px solid #1c1917;   /* 2 × 2px */
  margin: 5px;       /* 2 × 5px autour de la boîte */
}

/* largeur occupée par le contenu : 200 + 20 + 4 = 224px  (box-sizing: content-box) */
/* place totale occupée :          224 + 10     = 234px  (avec les marges)        */

Par défaut, width ne désigne que le contenu : ajouter un padding agrandit la boîte. La règle box-sizing: border-box change tout — la largeur déclarée englobe alors padding et bordure, ce qui rend les calculs de mise en page prévisibles. C’est pour cette raison que la plupart des feuilles de style commencent par :

*, *::before, *::after { box-sizing: border-box; }
Mnémotechnique — « border-box : la promesse est tenue »

En border-box, une boîte déclarée à 300 px occupe au plus 300 px de contenu, padding et bordure compris. C’est ce que tout le monde attend en lisant width: 300px.

5. Unités, couleurs et fonctions

Une valeur sans unité adaptée produit un résultat qui « marche » sur un écran et pas sur un autre. Les unités à connaître :

UnitéRelative àUsage typique
pxrien : valeur absoluebordures, ombres, détails
remla taille de police de la racine (html)tailles de texte, espacements
emla taille de police de l’élément parentpadding dépendant du texte
%l’élément parentlargeurs fluides
vw / vhla fenêtresections plein écran

Les couleurs s’écrivent en hexadécimal (#047857), en fonction (rgb(4,120,87), hsl(160 93% 24%)) ou par mot-clé. Deux règles de lisibilité : le contraste texte/fond doit dépasser 4,5:1 pour un texte courant, et la couleur ne doit jamais être le seul moyen de transmettre une information.

Pourquoi rem plutôt que px

rem suit la taille de base choisie par l’utilisateur dans son navigateur. Un texte exprimé en rem grossit pour ceux qui en ont besoin ; exprimé en px, il reste figé. C’est un point d’accessibilité, pas une préférence esthétique.

6. Déboguer le CSS

Les outils de développement affichent, pour l’élément sélectionné, toutes les déclarations reçues et celles qui ont été barrées : une déclaration barrée est une déclaration perdante. La cause apparaît alors en clair.

SymptômeCause la plus fréquenteVérification
le style ne s’applique passélecteur qui ne correspond à riencompter les éléments sélectionnés
le style est barréune règle plus spécifique gagnecomparer les triplet de spécificité
aucun style du toutfeuille non chargéeonglet Réseau : 404 ?
une boîte dépassecontent-box avec paddingmesurer avec l’inspecteur
Méthode de résolution

Devant un style qui n’arrive pas : vérifie d’abord que le sélecteur cible bien quelque chose, puis cherche la règle gagnante dans l’inspecteur, et seulement en dernier ressort augmente la spécificité. Ajouter !important avant d’avoir compris est le meilleur moyen de créer un problème plus difficile à défaire.

7. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Spécificité d’un sélecteur

JavaScript Niveau 3 — Raisonnement

Objectif : Calculer le triplet (identifiants, classes, types) qui décide du style gagnant.

Le programme reçoit un sélecteur CSS sur une seule ligne (sans virgule, combinateurs par espaces). Affichez ses trois compteurs sur une ligne : nombre d’identifiants (#…), nombre de classes (.…, y compris plusieurs sur un même élément) et nombre de types (noms de balises). Le sélecteur universel * ne compte pas.

Entrée du programme
div#main.item p
Sortie attendue
1 1 2

Un identifiant, une classe, deux types.

Deux indices, rédigés en mots
  1. Découpez sur les espaces pour obtenir les éléments du sélecteur : chacun se juge séparément.
  2. Un élément qui commence par . peut porter plusieurs classes : compte les points, pas les éléments.

Exercice 2 — Modèle de boîte : content-box ou border-box

JavaScript Niveau 3 — Raisonnement

Objectif : Voir par le calcul ce que change box-sizing sur la largeur réellement occupée.

Le programme reçoit une ligne largeur padding border margin (quatre nombres de pixels). Affichez trois lignes : la largeur de la boîte avec box-sizing: content-box (largeur de contenu + 2·padding + 2·border) ; la place totale occupée avec les marges, dans tous les cas (largeur déclarée + 2·margin) ; enfin la largeur de contenu restante avec box-sizing: border-box (largeur déclarée − 2·padding − 2·border).

Entrée du programme
200 10 2 5
Sortie attendue
224
210
176

200 + 20 + 4 = 224 ; 200 + 10 = 210 ; 200 − 20 − 4 = 176.

Deux indices, rédigés en mots
  1. En content-box, la largeur déclarée ne concerne que le contenu : les marges internes et la bordure s’ajoutent.
  2. En border-box, la largeur déclarée englobe padding et bordure ; le contenu rétrécit d’autant.

Exercice 3 — Convertir rem, em et px

JavaScript Niveau 3 — Raisonnement

Objectif : Maîtriser les unités relatives, qui font toute la différence en responsive.

Le programme reçoit une taille de référence en pixels, puis un entier n, puis n déclarations de la forme valeur unité, où l’unité vaut px, rem (1 rem = taille de référence) ou em (l’élément parent a ici la taille de référence). Affichez chaque valeur convertie en pixels, deux décimales, une par ligne.

Entrée du programme
16
3
1.5 rem
2 em
10 px
Sortie attendue
24.00

16 × 1,5 = 24 ; 16 × 2 = 32 ; 10 px reste 10.

Deux indices, rédigés en mots

  2. px se recopie tel quel ; rem et em multiplient par la taille de référence.

8. QCM — niveau examen

Quel sélecteur cible toutes les cartes portant la classe « item » ?

Le point introduit une classe ; # introduit un identifiant.

Quelle est la spécificité de « div#main.item p » ?

#main donne un identifiant, .item une classe, div et p deux types.

Deux règles de même spécificité se contredisent. Laquelle gagne ?

À spécificité égale, l’ordre d’apparition tranche : la dernière gagne.

Avec box-sizing: border-box, width: 300px désigne…

border-box englobe padding et bordure ; les marges restent extérieures.

Quelle unité suit la taille de base du navigateur ?

rem est relative à la taille de police de la racine : elle respecte les préférences du lecteur.

À quoi sert !important ?

C’est une exception qui casse la hiérarchie naturelle : à utiliser le moins possible.

9. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Styler par id : la spécificité monte et les surcharges deviennent impossibles.
  • Oublier box-sizing: border-box : une boîte à 100 % de large plus un padding déborde.
  • Ajouter !important sans comprendre : le conflit suivant sera plus dur encore.
  • Mélanger px et rem sans intention : le texte ne suit plus les préférences du lecteur.
  • Croire qu’un style absent est un bug du navigateur : c’est presque toujours un sélecteur qui ne correspond à rien.

10. Méthodologie de résolution

Résoudre un conflit de style
  1. Vérifiez que la feuille est chargée (onglet Réseau) avant tout le reste.
  2. Contrôle le sélecteur : combien d’éléments correspondent vraiment ?
  3. Calculez les triplets de spécificité des deux règles concurrentes.
  4. Corrige la cause : un sélecteur plus juste, pas une autorité plus forte.
  5. Contrôle enfin la boîte : padding, bordure et box-sizing expliquent la plupart des débordements.

11. Révision active

Résumé essentiel
  • Une règle CSS = un sélecteur + un bloc de déclarations propriété: valeur;.
  • La feuille externe (link) est la méthode à privilégier ; l’attribut style se réserve aux cas isolés.
  • Spécificité : identifiants, puis classes (et attributs, pseudo-classes), puis types — comparés compteur par compteur.
  • À spécificité égale, la dernière règle écrite gagne ; !important passe avant tout, au prix de la lisibilité.
  • Modèle de boîte : contenu, padding, bordure, marge ; border-box englobe padding et bordure dans width.
  • rem suit les préférences du lecteur ; px reste une valeur absolue.

Checklist de maîtrise

  • Je choisis un sélecteur adapté et je justifie mon choix.
  • Je calcule la spécificité de deux sélecteurs et je prédis le gagnant.
  • Je calcule la largeur réelle d’une boîte avec et sans border-box.
  • Je choisis mes unités en fonction de l’usage, pas de l’habitude.
