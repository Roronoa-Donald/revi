Chapitre 6 — JavaScript : le DOM et les événements

Module 6 ≈ 3 h 30 de travail Réservé B1 et plus
Mise en situation

La page est chargée, l’utilisateur clic sur un bouton, et rien ne bouge. Le JavaScript est le seul langage de la page qui puisse réagir après l’affichage : il lit le document, le modifie, écoute les événements. Encore faut-il qu’il s’exécute au bon moment, qu’il trouve les éléments qu’il cherche et qu’il n’écrase pas le travail du navigateur.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. placer et charger un script sans bloquer la page ;
  2. écrire des variables, conditions et fonctions lisibles ;
  3. transformer un tableau de données avec map, filter et sort ;
  4. sélectionner et modifier des éléments du DOM ;
  5. écouter un événement et y répondre correctement, sans faille de sûreté.

1. Où et quand un script s’exécute

Un <script> s’exécute là où le navigateur le rencontre. Placer une balise en haut du body revient à demander à un script de manipuler des éléments qui n’existent pas encore.

<!-- à éviter : le script s’exécute avant que le titre existe -->
<script src="app.js"></script>
<h1 id="titre">Mes notes</h1>

<!-- préférable : le script attend la fin de l’analyse du document -->
<script src="app.js" defer></script>

<!-- ou : placé en fin de body -->
<h1 id="titre">Mes notes</h1>
<script src="app.js"></script>

defer télécharge le script en parallèle du HTML et l’exécute une fois le document analysé, dans l’ordre des balises. C’est l’attribut à retenir par défaut. async, lui, exécute le script dès qu’il est téléchargé, sans garantie d’ordre : il se réserve aux scripts indépendants.

Vérifier que le script est bien chargé

Dans la console du navigateur, écris le nom d’une fonction de ton script : si elle n’est pas définie, le fichier n’a pas été chargé (chemin faux) ou a produit une erreur avant sa déclaration. L’onglet Console affiche cette erreur en rouge, avec sa ligne.

2. Variables, types et fonctions

Deux déclarations suffisent au quotidien : const pour une valeur qu’on ne réassigne pas, let pour une variable qui change. var appartient au JavaScript d’avant 2015 : on ne l’utilise plus.

const titre = "Mes notes";          // chaîne
let note = 16;                     // nombre
const admis = true;                // booléen
const eleves = ["Ada", "Linus"];   // tableau
const fiche = { nom: "Ada", note: 18 };   // objet

function moyenne(valeurs) {
  const total = valeurs.reduce((somme, v) => somme + v, 0);
  return valeurs.length ? total / valeurs.length : 0;
}

const double = x => x * 2;   // fonction fléchée

Quelques réflexes : préférer const par défaut, comparer avec === (égalité stricte, sans conversion de type), et tester les longueurs (length) plutôt que la vérité d’un tableau vide.

Piège — = et ==, la confusion classique

= affecte, == compare en convertissant les types, === compare sans convertir. "10" == 10 est vrai (surprise), "10" === 10 est faux (attendu). On écrit toujours ===.

3. Tableaux : transformer plutôt que boucler

Trois méthodes couvrent la majorité des traitements de données, et chacune renvoie un nouveau tableau sans modifier l’original.

MéthodeCe qu’elle faitRenvoie
maptransforme chaque élémentun tableau de même longueur
filtergarde les éléments qui passent un testun tableau plus court
sorttrie sur place selon une comparaisonle tableau trié (attention : il modifie l’original)
const eleves = [
  { nom: "Ada", note: 18 },
  { nom: "Linus", note: 15 },
  { nom: "Bob", note: 8 }
];

const admis = eleves
  .filter(e => e.note >= 10)
  .sort((a, b) => b.note - a.note);

console.log(admis.map(e => e.nom));   // ["Ada", "Linus"]

La fonction de comparaison de sort renvoie un nombre négatif si le premier élément doit passer avant le second. Il faut donc connaître deux réflexes : a - b trie du plus petit au plus grand, b - a l’inverse, et localeCompare compare deux textes en respectant la langue et les accents.

Intuition — le tri se paie en prévisibilité

sort modifie le tableau d’origine, contrairement à map et filter. Sur des données affichées ailleurs dans la page, une copie ([...eleves].sort(...)) évite d’altérer l’ordre des autres affichages.

4. Le DOM : sélectionner et modifier

Le DOM est la représentation de la page sous forme d’arbre d’objets. On y accède par des sélecteurs identiques à ceux du CSS.

MéthodeRenvoieUsage
document.querySelector("…")le premier élément correspondant, ou nullcibler un élément connu
document.querySelectorAll("…")une liste de tous les correspondantsparcourir un ensemble
const titre = document.querySelector("#titre");
titre.textContent = "Mes notes du semestre 1";
titre.classList.add("titre--note");

const liste = document.querySelector("#notes");
liste.innerHTML = "";                    // on vide proprement

for (const ligne of lignes) {
  const item = document.createElement("li");
  item.textContent = ligne.nom + " : " + ligne.note;
  liste.append(item);
}

Créer un élément puis renseigner son textContent est la méthode sûre : le contenu est traité comme du texte, jamais comme du balisage. classList ajoute ou retire des classes sans toucher au reste de l’attribut.

Piège — null n’a pas de propriétés

document.querySelector("#titrre") renvoie null si le sélecteur ne correspond à rien. La ligne suivante échoue alors avec « Cannot read properties of null ». C’est le message d’erreur le plus fréquent du JavaScript de navigation : il signifie presque toujours « votre sélecteur ne cible rien » ou « le script tourne trop tôt ».

5. Les événements

Un événement est un signal : clic, frappe au clavier, envoi de formulaire, chargement. On y répond en attachant une fonction écouteuse.

const bouton = document.querySelector("#calcul");

bouton.addEventListener("click", () => {
  const note = Number(document.querySelector("#note").value);
  if (Number.isNaN(note)) {
    document.querySelector("#message").textContent = "Notez attendue : un nombre.";
    return;
  }
  document.querySelector("#message").textContent = note >= 10 ? "Admis" : "Non admis";
});

const formulaire = document.querySelector("form");
formulaire.addEventListener("submit", evenement => {
  evenement.preventDefault();      // le navigateur ne recharge pas la page
  // … traitement, puis envoi décidé par le script
});

Deux précautions rendent le code robuste. D’abord, un champ de saisie renvoie toujours une chaîne : convertir avec Number() avant de calculer, et tester Number.isNaN(). Ensuite, pour beaucoup d’éléments, il vaut mieux écouter une seule fois sur le conteneur : c’est la délégation.

// délégation : un seul écouteur pour toute la liste
document.querySelector("#notes").addEventListener("click", evenement => {
  if (evenement.target.matches("li")) {
    evenement.target.classList.toggle("est-selectionne");
  }
});
Mnémotechnique — « un écouteur sur le parent, pas dix sur les enfants »

Les éléments créés après le chargement n’existent pas encore quand on attache les écouteurs. Déléguer au parent réglé le problème une fois pour toutes, et le code reste juste même si la liste change.

6. Écrire du JavaScript sûr

Le JavaScript de page manipule des données qui viennent de l’extérieur : du texte saisi, un fichier JSON, une réponse de serveur. Trois règles suffisent à écarter les accidents les plus fréquents.

  1. Texte ou balisage. textContent pour une donnée venue de l’utilisateur ; innerHTML réservé au balisage que vous écrivez vous-même.
  2. Types. Ce qui sort d’un champ de formulaire est une chaîne : convertis, puis valide avant de calculer.
  3. Valeurs absentes. Un sélecteur qui ne trouve rien renvoie null : teste le résultat avant de vous en servir.
ÉcritureCe qui se passe
zone.textContent = saisie;la saisie est affichée telle quelle, en texte
zone.innerHTML = saisie;la saisie est interprétée comme du HTML — faille d’injection
Number("12") + 113 : la conversion est faite explicitement
"12" + 1"121" : concaténation involontaire
Méthode d’écriture d’un comportement

Écrivez toujours dans le même ordre : sélectionner les éléments (et tester qu’ils existent), écouter l’événement, lire et convertir les données, valider, puis afficher avec textContent. Un comportement qui suit cet ordre est presque toujours correct du premier coup.

7. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Construire une liste HTML depuis des données

JavaScript Niveau 2 — Application

Objectif : Produire le balisage que l’on injecterait dans le DOM, à partir d’un tableau.

Le programme reçoit un entier n, puis n lignes nom note. Affichez une liste HTML : la ligne <ul>, puis une ligne <li>nom : note</li> par étudiant dans l’ordre reçu, puis la ligne </ul>.

Entrée du programme
2
Ada 18
Linus 15
Sortie attendue
<ul>
<li>Ada : 18</li>
<li>Linus : 15</li>
</ul>

Deux élèves, deux lignes de liste.

Deux indices, rédigés en mots
  1. Un tableau de morceaux rejoint avec join("\n") produit du HTML lisible.
  2. Le format exact demandé est « nom : note » avec un espace avant et après les deux-points.

Exercice 2 — Filtrer et trier un tableau

JavaScript Niveau 3 — Raisonnement

Objectif : Enchaîner filter() et sort() : le geste le plus fréquent du JavaScript de données.

Le programme reçoit un entier n, puis n lignes nom note. Affichez les noms des étudiants ayant au moins 10, triés par note décroissante, puis par ordre alphabétique en cas d’égalité, un nom par ligne.

Entrée du programme
3
Ada 18
Bob 8
Chloe 15
Sortie attendue
Ada
Chloe

Bob est éliminé avec 8.

Deux indices, rédigés en mots
  1. sort() prend une fonction de comparaison ; elle renvoie un nombre négatif pour placer a avant b.
  2. En cas d’égalité de notes, compare les noms avec localeCompare().

Exercice 3 — Simuler un gestionnaire d’événements

JavaScript Niveau 3 — Raisonnement

Objectif : Faire l’état des lieux d’un compteur avant de l’écrire dans le DOM.

Un bouton déclenche un JavaScript qui gère deux événements : click incrémente un compteur, reset le remet à zéro. Le programme reçoit un entier n, puis n noms d’événements (un par ligne). Affichez sur la première ligne le nombre total de click reçus, puis sur la seconde la valeur finale du compteur.

Entrée du programme
4
click
click
reset
click
Sortie attendue
3
1

Trois clics au total, mais un seul après la remise à zéro.

Deux indices, rédigés en mots
  1. Ce sont deux informations différentes : un clic suivi d’une remise à zéro compte 1 clic mais laisse 0.
  2. deux variables : une qui ne fait que croître, une qui peut revenir à zéro.

8. QCM — niveau examen

Pourquoi placer un script avec defer plutôt qu’en haut de page ?

defer attend la fin de l’analyse : les éléments visés existent alors.

Quelle déclaration pour une valeur jamais réassignée ?

const exprime une intention : la valeur ne changera pas.

Quelle méthode transforme chaque élément d’un tableau ?

map renvoie un tableau de même longueur avec chaque élément transformé.

Que renvoie querySelector si rien ne correspond ?

null : c’est ce qui produit ensuite l’erreur « Cannot read properties of null ».

Que fait evenement.preventDefault() dans un submit ?

Il empêche le comportement par défaut du navigateur et laisse le script décider.

Comment afficher une saisie utilisateur sans risque ?

textContent traite la valeur comme du texte : aucune injection possible.

9. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Sélecteur qui ne cible rien : null.textContent échoue ; vérifie l’orthographe de l’id.
  • Script exécuté avant le DOM : utilise defer ou place le script en fin de body.
  • Oublier de convertir : "12" + 1 donne "121", pas 13.
  • Écouter chaque enfant au lieu du parent : le code casse dès qu’un élément est ajouté dynamiquement.
  • Utiliser innerHTML avec une donnée utilisateur : la donnée devient du code exécutable.

10. Méthodologie de résolution

Écrire un comportement, du début à la fin
  1. Sélectionne les éléments par querySelector et vérifie qu’ils existent.
  2. Charge le script avec defer pour qu’ils soient présents.
  3. Écoute l’événement, au bon niveau (parent pour les listes).
  4. Lisez, convertissez puis validez les données avant tout calcul.
  5. Affichez avec textContent ou en créant les éléments par createElement.

11. Révision active

Résumé essentiel
  • defer exécute le script après l’analyse du HTML ; c’est le choix par défaut.
  • const par défaut, let si la valeur change, === pour comparer.
  • map transforme, filter sélectionne, sort trie — et modifie le tableau d’origine.
  • Le DOM se sélectionne avec querySelector / querySelectorAll, qui renvoient null ou une liste.
  • Un événement s’écoute avec addEventListener ; preventDefault() annule le comportement du navigateur.
  • Une donnée d’origine extérieure s’affiche en textContent, jamais en innerHTML.

Checklist de maîtrise

  • Je charge un script sans bloquer l’analyse du document.
  • Je transforme un tableau de données avec map, filter et sort.
  • Je sélectionne, crée et modifie des éléments du DOM.
  • Je branche un écouteur d’événement et traite l’événement sans faille de sûreté.
