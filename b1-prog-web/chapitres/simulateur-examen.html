Examen blanc n°1

Sujet type — lecture du Web, HTML et CSS, d’après les évaluations B1.

Exercice 1/4 — URL et HTTP

Décomposez l’URL https://campus.exemple.fr:8443/cours/index.html?module=css&page=3#quiz en protocole, hôte, port, chemin, requête et fragment, puis précisez ce qui est réellement transmis au serveur.

Corrigé
protocole : https — hôte : campus.exemple.fr — port : 8443 — chemin : /cours/index.html — requête : module=css&page=3 — fragment : quiz. Le fragment ne part jamais au serveur : il reste dans le navigateur. Tout le reste (hôte, port, chemin, requête) fait partie de la demande.
Exercice 2/5 — Structure HTML

Écrivez le squelette d’une page de relevé de notes : en-tête avec un titre et une navigation, contenu principal contenant deux sections titrées, puis un pied de page. La page doit être correctement encodée, en français, et utilisable sur téléphone.

Corrigé
<!DOCTYPE html> puis <html lang="fr"> ; dans le head : charset="UTF-8", viewport et un title. Le corps contient <header> (avec h1 et nav), <main> avec deux <section> portant chacune un h2 (et non h3 : on descend d’un niveau à la fois), puis <footer>. Un seul h1 dans toute la page.
Exercice 3/6 — Spécificité CSS

Trois règles visent le même paragraphe : p { color: blue }, .note p { color: green } et #bloc p { color: red }. Le paragraphe est dans <div id="bloc" class="note">. Quelle couleur l’emporte, et pourquoi ?

Corrigé
Spécificités : p → 0 0 1 ; .note p → 0 1 1 ; #bloc p → 1 0 1. La comparaison se fait compteur par compteur, en partant de la gauche : les identifiants l’emportent avant même de regarder les classes. Le texte est donc en rouge. L’ordre d’apparition ne joue pas ici : la spécificité tranche d’abord.
Exercice 4/5 — Modèle de boîte

Une carte porte width: 300px; padding: 20px; border: 5px; margin: 8px;. Donnez la largeur occupée avec content-box, la place totale avec les marges, et la largeur du contenu si l’on passe en border-box.

Corrigé
content-box : 300 + 2×20 + 2×5 = 350 px. Place totale : 350 + 2×8 = 366 px (les marges sont toujours extérieures). border-box : le contenu dispose de 300 − 40 − 10 = 250 px. Conclusion : la même déclaration produit deux mises en page très différentes selon box-sizing.

Examen blanc n°2 — variante

Sujet orienté formulaires, mise en page responsive et JavaScript.

Exercice 1/5 — Formulaire

Écrivez le champ d’un formulaire qui collecte une note sur 20, bornée, obligatoire, avec une étiquette reliée. Indiquez ensuite où doit être vérifiée la valeur, et pourquoi.

Corrigé
<label for="note">Note sur 20</label> puis <input id="note" name="note" type="number" min="0" max="20" step="0.5" required>. Le name est indispensable pour que la valeur soit transmise. La vérification doit exister côté serveur : les attributs HTML aident l’utilisateur mais se contournent en désactivant le JavaScript ou en envoyant une requête directe.
Exercice 2/5 — Étiquettes

Pourquoi un placeholder ne remplace-t-il pas une <label> ? Donnez deux arguments.

Corrigé
1) Le texte du placeholder disparaît dès la première frappe : l’information n’est plus disponible au moment où l’on relit sa saisie. 2) Il n’est pas toujours lu par les lecteurs d’écran, et il ne décrit pas le champ à un lecteur qui arrive dessus au clavier. Une étiquette visible et reliée par for/id rend en plus tout le texte cliquable, ce qui agrandit la cible sur téléphone.
Exercice 3/5 — Grille responsive

Écrivez une galerie qui affiche une colonne sur téléphone, deux sur tablette (≥ 600 px) et trois sur bureau (≥ 900 px), en utilisant la méthode mobile first.

Corrigé
.galerie { display: grid; gap: 16px; grid-template-columns: 1fr; } puis @media (min-width: 600px) { .galerie { grid-template-columns: repeat(2, 1fr); } } et @media (min-width: 900px) { .galerie { grid-template-columns: repeat(3, 1fr); } } Mobile first : la règle de base décrit le plus petit écran, chaque palier ajoute une possibilité. Ne pas oublier la balise viewport dans le head, sinon les paliers ne se déclenchent pas comme prévu.
Exercice 4/5 — DOM et événements

Un formulaire contient un champ #note et un bouton #calcul. Écrivez le JavaScript qui affiche « Admis » si la note vaut au moins 10, « Non admis » sinon, dans l’élément #message — sans faille de sûreté.

Corrigé
Sélectionner (querySelector), écouter (addEventListener("click", …)), lire la valeur (.value, toujours une chaîne), convertir (Number()), valider avec Number.isNaN(), puis afficher : message.textContent = note >= 10 ? "Admis" : "Non admis"; Le nombre se vérifie avec >= 10 sur un nombre : comparer directement la chaîne fonctionne par conversion implicite, mais c’est une source d’erreur à éviter.

QCM final — toutes notions

Quelle partie d’une URL ne part jamais au serveur ?

Le fragment reste dans le navigateur.

Quelle méthode HTTP est idempotente ?

DELETE, GET, PUT, HEAD, OPTIONS et TRACE le sont.

Que signifie un statut 503 ?

5xx : erreur du serveur ; 503 signale une indisponibilité.

Quelle balise introduit le contenu principal ?

main est unique par page et délimite le contenu principal.

Quel attribut permet à un champ d’être transmis ?

Le couple name/valeur est ce qui voyage dans la requête.

Quelle spécificité pour « #bloc p » ?

Un identifiant, aucune classe, un type.

Avec border-box, width englobe…

Les marges restent extérieures à la boîte.

Quel outil pour organiser deux dimensions à la fois ?

La grille place des cellules en lignes et colonnes.

Que fait evenement.preventDefault() dans un submit ?

Il annule le comportement par défaut du navigateur.

Comment afficher une saisie utilisateur sans risque ?

textContent traite la valeur comme du texte.
