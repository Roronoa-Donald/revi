Chapitre 1 — Cadrage du projet

Module 1 ≈ 1 h 30 de travail Accès libre
Mise en situation

Le projet tutoré court : livrer une application complète de gestion de stock en Python, avec interface graphique Tkinter et base PostgreSQL. Un projet qui se réussit à 80 % avant la première ligne de code : objectifs clairs, environnement vérifié, structure de dossiers posée.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. présenter le projet : application de gestion de stock Python, Tkinter, PostgreSQL ;
  2. relier chaque objectif pédagogique à son concept Python (POO, Tkinter, CRUD, exceptions) ;
  3. vérifier les prérequis : Python 3.7+, Tkinter, PostgreSQL ;
  4. installer l'environnement : python3-pip, postgresql, psycopg2-binary, python3-tk ;
  5. poser la structure : main.py, database.py, requirements.txt, README.md.

1. Présentation et objectifs

Le tutoriel guide la création d'une application complète de gestion de stock en Python : la programmation orientée objet structure le code (classes Database et ApplicationGestionStock), Tkinter fournit l'interface graphique, PostgreSQL conserve les données, et les opérations CRUD — Create, Read, Update, Delete — les font vivre.

\n

Cinq objectifs pédagogiques : créer une interface intuitive, connecter l'application à la base, implémenter les opérations de base, gérer les erreurs et les exceptions, organiser le code en modules réutilisables. Prérequis : bases de Python, notions de POO, compréhension des bases de données relationnelles, Python 3.7 ou supérieur.

\n
Mnémotechnique — « une classe pour la base, une classe pour l'écran »

Deux classes, deux mondes : Database parle SQL, ApplicationGestionStock parle à l'utilisateur. main.py les fait se rencontrer.

2. Installer l'environnement

Vérifier Python : python3 --version — sinon sudo apt install python3 python3-pip. PostgreSQL : sudo apt install postgresql postgresql-contrib puis sudo service postgresql start. Tkinter : sudo apt install python3-tk — vérifiable avec python3 -m tkinter. Configuration de la base : sudo -u postgres psql, ALTER USER postgres WITH PASSWORD 'postgres', puis CREATE DATABASE gestion_stock.

\n

La dépendance Python tient en une ligne dans requirements.txt : psycopg2-binary==2.9.9, installée par pip install -r requirements.txt. Un requirements.txt versionné, c'est un projet que n'importe qui peut installer.

\n
Confusions d'examen
    \n
  • psycopg2 est le PONT Python-PostgreSQL ; Tkinter ne parle pas SQL.
    • \n
  • La version minimale est 3.7 : 3.6 refuse, 3.10 passe.
    • \n
  • La base se nomme gestion_stock : créer la base AVANT de lancer l'application.
    • \n
  • Le README fait partie du livrable : un projet sans documentation est incomplet.
    • \n

3. La structure du projet

Quatre fichiers, quatre rôles : main.py — l'interface principale (fenêtre, formulaire, tableau) ; database.py — la classe Database qui encapsule toute la gestion PostgreSQL ; requirements.txt — les dépendances ; README.md — la documentation. Cette séparation n'est pas décorative : on peut changer d'interface sans toucher à la base, et tester la base sans ouvrir la fenêtre.

\n

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Coder l'interface et le SQL dans le même fichier : séparer main.py et database.py.
  • Oublier d'installer python3-tk : l'import tkinter échoue.
  • Lancer l'application avant de créer la base gestion_stock.
  • Omettre requirements.txt : le projet ne s'installe plus ailleurs.

7. Méthodologie de résolution

Méthode — démarrer le projet en trois gestes
  1. Vérifier : python3 --version, python3 -m tkinter, service postgresql status.
  2. Installer : python3-pip, postgresql-contrib, psycopg2-binary ; créer la base gestion_stock.
  3. Poser la structure : main.py, database.py, requirements.txt, README.md.
