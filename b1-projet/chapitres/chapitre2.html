Chapitre 2 — La base de données

Mise en situation

La classe Database est le pont vers PostgreSQL : elle se connecte, crée la table produits si elle n'existe pas, et offre quatre méthodes CRUD. Chaque méthode vit dans un try/except — parce qu'un serveur éteint, un mot de passe faux ou une requête maladroite ne demandent qu'à arriver.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. décrire la table produits : id SERIAL, nom et categorie VARCHAR, quantite INTEGER, prix DECIMAL(10,2) ;
  2. expliquer la connexion : psycopg2.connect, cursor, gestion des erreurs par try/except ;
  3. utiliser CREATE TABLE IF NOT EXISTS et comprendre commit ;
  4. relier chaque opération CRUD à sa requête : INSERT, SELECT, UPDATE, DELETE ;
  5. fermer proprement : cursor.close, connection.close.

1. Prérequis intégré : Initiation pas à pas aux classes Python (class, __init__, self)

Niveau 1 — Intuition : Regrouper données et actions dans un même objet

Le cours de Python B1 s’arrêtait aux fonctions et aux fichiers. Pour structurer proprement notre application de gestion de stock, nous regroupons la connexion à la base et ses opérations dans une classe (un plan de construction) :

  • class Database: définit le plan de construction d’un objet ;
  • def __init__(self, fichier): est le constructeur appelé automatiquement à la création de l’objet (db = Database("stock.db")) ;
  • self désigne l’objet lui-même et permet de stocker ses attributs (ex. self.conn) pour les réutiliser dans toutes les méthodes de la classe.

2. La table produits

Cinq colonnes : id — identifiant unique, clé primaire auto-incrémentée (SERIAL PRIMARY KEY) ; nom — VARCHAR(100) NOT NULL ; categorie — VARCHAR(50) ; quantite — INTEGER NOT NULL ; prix — DECIMAL(10,2) NOT NULL. Le CREATE TABLE IF NOT EXISTS rend le premier lancement idempotent : la table ne se recrée pas à chaque démarrage.

Pourquoi DECIMAL et non FLOAT pour le prix : DECIMAL(10,2) stocke exactement deux décimales — 2500.50 reste 2500.50, sans arrondi binaire. La précision monétaire n'est pas négociable.

Mnémotechnique — « SERIAL compte, VARCHAR écrit, INTEGER compte en stock, DECIMAL coûte »

Cinq colonnes, cinq types : la grille attendue à l'examen.

3. Connexion et gestion des erreurs

La méthode connecter() appelle psycopg2.connect(host, database, user, password), récupère un cursor, affiche le succès et renvoie True ; en cas d'Error, elle affiche le problème et renvoie False. Ce pattern try/except recommence dans chaque méthode : le programme ne plante jamais, il rapporte.

Après toute écriture (INSERT, UPDATE, DELETE), la méthode appelle self.connection.commit() : sans commit, PostgreSQL annule la modification à la déconnexion. La deconnecter() ferme le cursor puis la connexion — dans cet ordre.

Confusions d'examen
  • SELECT lit : fetchall ; INSERT/UPDATE/DELETE écrivent : commit.
  • Sans commit, la modification est perdue à la fermeture : piège classique.
  • Le try/except renvoie False : l'application continue, elle ne s'arrête pas.
  • CREATE TABLE IF NOT EXISTS : le second lancement ne duplique rien.

4. Les quatre requêtes CRUD

Create — INSERT INTO produits (nom, categorie, quantite, prix) VALUES (%s, %s, %s, %s) avec les valeurs passées en paramètre ; Read — SELECT * FROM produits ORDER BY id puis fetchall() ; Update — UPDATE produits SET nom=%s, categorie=%s, quantite=%s, prix=%s WHERE id=%s ; Delete — DELETE FROM produits WHERE id=%s.

Les %s sont des requêtes paramétrées : psycopg2 échappe les valeurs. Concaténer du SQL à la main ouvre la porte à l'injection — le paramétrage n'est pas une option, c'est la seule façon.

Vérifier dans l’atelier
  • Le schéma : id → serial, nom/categorie → varchar, quantite → integer, prix → decimal.
  • La connexion : serveur/mdp/base dans l'ordre, sortie au premier ko.
  • Le cycle CRUD : create→insert, read→select, update→update, delete→delete.

5. Du besoin au SQL : MCD, MLD, script

La démarche de conception relie trois niveaux. Le MCD (modèle conceptuel) décrit le monde réel : l’entité PRODUIT a un identifiant, un nom, une catégorie, une quantité et un prix. Le MLD (modèle logique) la traduit en relation : produits(id, nom, categorie, quantite, prix), la clé primaire étant soulignée. Le script SQL (modèle physique) donne les types :

CREATE TABLE IF NOT EXISTS produits (
    id        SERIAL PRIMARY KEY,
    nom       VARCHAR(100) NOT NULL,
    categorie VARCHAR(50),
    quantite  INTEGER NOT NULL CHECK (quantite >= 0),
    prix      DECIMAL(10,2) NOT NULL
);

Piste d’évolution : si la catégorie devient une entité à part entière (CATEGORIE), le MLD gagne une clé étrangère produits.categorie_id vers categories(id). Chaque association se traduit toujours de la même façon : la clé primaire du côté « un » devient clé étrangère du côté « plusieurs ».

Exercice 1 — La table produits de la librairie

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Décrire la table produits : nommer ses colonnes, leurs types, sa clé primaire, et dire si elle porte une clé étrangère.

Énoncé. Deuxième étape : la base de données. Kofi crée la base gestion_stock, puis la table produits, la seule table du projet. Sa structure compte cinq colonnes :

ColonneTypeRôle
idSERIAL PRIMARY KEYidentifiant unique, auto-incrémenté
nomVARCHAR(100) NOT NULLnom du produit
categorieVARCHAR(50)rayon du produit
quantiteINTEGER NOT NULLnombre d'unités en stock
prixDECIMAL(10,2) NOT NULLprix unitaire, deux décimales exactes

Pour vérifier la table, Kofi y insère les quatre premiers produits de la librairie :

idnomcategoriequantiteprix (FCFA)
1Cahier 200 pagesPapeterie40500,00
2Roman policierLivres124500,00
3Stylo bleuPapeterie150350,00
4CalculatriceFournitures88500,00
  1. Combien de colonnes compte la table produits ?
  2. Quel type auto-incrémenté porte la colonne id ? (un seul mot)
  3. Quel type stocke le prix avec exactement deux décimales ? (un seul mot)
  4. Quelle colonne sert de clé primaire ?
  5. La table produits contient-elle une clé étrangère ? Répondez par oui ou non.
  6. Combien de produits l'extrait contient-il ?
Cas d’exemple
Une quincaillerie crée sa table articles :
id SERIAL PRIMARY KEY — designation VARCHAR(80) — rayon VARCHAR(40) —
stock INTEGER — tarif DECIMAL(10,2).

1) La table compte 5 colonnes.
2) id est un SERIAL, auto-incrémenté par PostgreSQL.
3) Le tarif est un DECIMAL : deux décimales exactes pour l'argent.
4) La clé primaire est id.
5) Le stock est un INTEGER : des unités entières.
Trois indices, rédigés en mots
  1. La structure d'une table se lit colonne par colonne : le premier tableau donne le type exact de chaque colonne.
  2. Deux types numériques se distinguent : celui qui compte les unités en stock, et celui qui garde l'argent exact à deux décimales.
  3. La clé primaire est la colonne qui identifie chaque ligne de façon unique ; une clé étrangère relie deux tables — comptez les tables de cette base.

Exercice 2 — Connexion, commit et bonne fermeture

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Appliquer les règles de la classe Database : commit après écriture, fetchall après lecture, try/except et ordre de fermeture.

Énoncé. La classe Database de Kofi suit des règles strictes, répétées dans chaque méthode : la connexion passe par psycopg2.connect() puis un cursor ; chaque requête vit dans un bloc try / except ; en cas d'erreur, la méthode affiche le problème et renvoie False — l'application ne plante jamais. Kofi résume les règles dans son carnet :

SituationRègle à appliquer
Après un INSERT, un UPDATE ou un DELETEappeler la méthode qui valide l'écriture
Après un SELECTrécupérer les lignes avec la méthode du cursor
Une requête échouel'exception est attrapée par le bloc ...
Fermeture de la basefermer ... en premier, puis la connexion
  1. Quelle méthode valide une écriture dans la base ? (un seul mot)
  2. Quelle méthode récupère toutes les lignes d'un SELECT ? (un seul mot)
  3. Que renvoie connecter() quand le serveur PostgreSQL est éteint : True ou False ?
  4. Quel objet exécute les requêtes SQL et lit les résultats ? (un seul mot)
  5. Quel mot-clé du try/except attrape l'erreur ? (un seul mot anglais)
  6. À la fermeture, quel objet ferme-t-on en premier ? (un seul mot)
Cas d’exemple
La pizzeria du coin tient sa table pizzas.
- INSERT de la pizza « 4 fromages » : la méthode appelle commit(), sinon la ligne disparaît à la déconnexion.
- SELECT des pizzas : le cursor rend les lignes avec fetchall().
- Serveur éteint : psycopg2 lève une erreur, le except l'attrape, la méthode renvoie False.
- Fermeture : cursor.close() puis connection.close().

1) Validation d'une écriture : commit.
2) Lecture des lignes : fetchall.
3) Échec de connexion : la méthode renvoie False, sans planter.
4) Ordre de fermeture : le cursor, puis la connexion.
Trois indices, rédigés en mots
  1. Deux familles de requêtes : les lectures rapportent des lignes, les écritures demandent une validation.
  2. Sans validation, PostgreSQL annule la modification à la déconnexion : la ligne n'est jamais vraiment écrite.
  3. À la fermeture, on démonte dans l'ordre inverse du montage : l'outil qui exécute les requêtes d'abord, la connexion ensuite.

Exercice 3 — Les premières requêtes de la vendeuse

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Lire des requêtes SQL simples (SELECT, INSERT, DELETE) et prévoir leur effet sur un petit tableau de données.

Énoncé. Pour former la vendeuse, Kofi branche un petit outil SQL sur la base et lui fait lire le catalogue du matin :

idnomcategoriequantiteprix (FCFA)
1Cahier 200 pagesPapeterie40500
2Roman policierLivres64500
3Stylo rougePapeterie0350
4Atlas scolaireLivres96500
5GommePapeterie25200

Il lui enseigne quatre requêtes : SELECT * FROM produits (tout lire), SELECT * FROM produits WHERE categorie = 'Papeterie' (filtrer), INSERT INTO produits ... (ajouter une ligne), DELETE FROM produits WHERE id = 3 (retirer une ligne). La vendeuse s'entraîne :

  1. Quelle clause SQL filtre les lignes d'une requête ? (un mot anglais)
  2. Combien de lignes renvoie « SELECT * FROM produits » sur le catalogue du matin ?
  3. Combien de lignes renvoie « SELECT * FROM produits WHERE categorie = 'Papeterie' » ?
  4. Quelle requête ajoute une nouvelle ligne : SELECT, INSERT, UPDATE ou DELETE ?
  5. Combien de lignes supprime « DELETE FROM produits WHERE id = 3 » ?
  6. Quelle colonne sert à cibler une seule ligne dans un UPDATE ou un DELETE ?
Cas d’exemple
Catalogue d'une quincaillerie :
id 1 Clous (Bois, 500 unités), id 2 Scie (Bois, 3 unités),
id 3 Peinture blanche (Peinture, 12 unités), id 4 Pinceau (Peinture, 30 unités).

1) SELECT * FROM articles : 4 lignes.
2) SELECT * FROM articles WHERE rayon = 'Peinture' : 2 lignes (peinture, pinceau).
3) DELETE FROM articles WHERE id = 2 : 1 ligne retirée (la scie).
4) La clause de filtrage : WHERE.
Trois indices, rédigés en mots
  1. Lisez le tableau ligne par ligne : chaque requête n'agit que sur les lignes qui vérifient sa condition.
  2. La clause de filtrage suit immédiatement le nom de la table dans la requête ; sans elle, toutes les lignes répondent.
  3. Pour cibler une seule ligne, on appelle la colonne qui ne se répète jamais dans la table.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Concaténer les valeurs dans le SQL : requêtes paramétrées obligatoires.
  • Oublier commit après INSERT : la ligne n'est pas vraiment écrite.
  • Mettre FLOAT pour le prix : DECIMAL(10,2) est exact, FLOAT arrondit.
  • Supprimer sans WHERE : la table entière disparaît.

9. Méthodologie de résolution

Méthode — écrire une méthode Database en trois gestes
  1. Ouvrir un try : exécuter la requête paramétrée avec le cursor.
  2. Commit si écriture, fetchall si lecture ; renvoyer le résultat ou True.
  3. Except Error : afficher le problème, renvoyer False ou [] — jamais de crash.

Résumé essentiel

Les 8 notions à connaître absolument

  1. SERIAL : entier auto-incrémenté de PostgreSQL.
  2. DECIMAL(10,2) : décimal exact à deux décimales.
  3. cursor : objet qui exécute les requêtes et lit les résultats.
  4. commit : validation des écritures sur la connexion.
  5. fetchall : récupère toutes les lignes d'un SELECT.
  6. Requête paramétrée : %s passés séparément, échappés par psycopg2.
  7. CREATE TABLE IF NOT EXISTS : création idempotente.
  8. Error (psycopg2) : exception attrapée par chaque try/except.
