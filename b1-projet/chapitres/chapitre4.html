Chapitre 4 — Cycle de vie d'un produit

Module 4 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le produit entre, change, sort : le trio ajouter / modifier / supprimer est le cœur du projet. Chaque action suit le même chemin — valider, appeler la base, rafraîchir l'écran — et la suppression ne passe jamais sans confirmation. Les mouvements de stock transforment la table statique en véritable gestion.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. ajouter un produit : validation des champs puis INSERT via la classe Database ;
  2. modifier : sélection dans le Treeview, remplissage du formulaire, UPDATE WHERE id ;
  3. supprimer : askyesno de confirmation, DELETE WHERE id, refus motivé si introuvable ;
  4. simuler des mouvements : entrées qui augmentent, sorties contrôlées qui ne rendent jamais le stock négatif.

1. Ajouter et modifier

Ajouter : lire les quatre champs, valider (obligatoires non vides, quantite entière et prix numérique), puis db.ajouter_produit(nom, categorie, quantite, prix). Succès → showinfo, effacer_champs(), actualiser_tableau(). Échec → showerror. Modifier : exiger une sélection dans le Treeview (sinon showwarning), remplir le formulaire au clic, puis db.modifier_produit(id, …) qui exécute UPDATE … WHERE id=%s.

Mnémotechnique — « valider, appeler, rafraîchir »

Trois verbes, les trois mêmes à chaque action : c'est le squelette de toutes les méthodes d'action du tutoriel.

2. Supprimer avec confirmation

Supprimer : sélection obligatoire, puis messagebox.askyesno("Confirmation", "Voulez-vous vraiment supprimer '…' ?"). Oui → db.supprimer_produit(id) (DELETE WHERE id), showinfo, rafraîchir. Non → rien. Cette double garde — sélection puis confirmation — sépare la suppression réfléchie du clic malheureux. Si le produit n'existe plus en base (supprimé par ailleurs), l'opération se rapporte : introuvable n'est pas supprimé.

Confusions d'examen
  • Modifier et supprimer exigent une sélection : sinon showwarning, pas d'appel SQL.
  • askyesno renvoie True/False : la suppression vit dans le if.
  • Après chaque action : effacer_champs puis actualiser_tableau.
  • DELETE sans WHERE vide la table entière : le WHERE id=%s est vital.

3. Mouvements de stock

Un mouvement est une entrée (+) ou une sortie (−) sur un produit. La règle métier : une sortie supérieure au stock disponible est refusée — le stock ne devient jamais négatif. En SQL, le mouvement se traduit par UPDATE produits SET quantite = quantite + X WHERE id = %s (ou − X après vérification). L'atelier rejoue ces mouvements : entrées cumulées, sorties contrôlées, refus explicites « stock insuffisant ».

Vérifier en Bash
  • L'ajout : quantité vide ou non positive → refuse, compteur d'ajouts à la fin.
  • Le mouvement : un tableau associatif par produit, sortie refusée si stock < quantité.
  • La suppression : trois motifs (confirme/annule/absent), deux compteurs de bilan.

4. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Ajout au stock

Bash Niveau 1 — Acquisition

Objectif : Simuler l'ajout de produits et compter les insertions réussies.

Le script lit n lignes « produit quantite » : quantite est le stock initial (nombre positif ; - = champ vide, insertion refusée comme dans le tutoriel). Pour chaque ligne il affiche produit : ajoute si la quantité est un entier positif, sinon produit : refuse, puis ajouts : X/n.

Entrée du programme
3
clavier 10
ecran -
souris 3
Sortie attendue
clavier : ajoute
ecran : refuse
souris : ajoute
ajouts : 2/3
Deux indices, rédigés en mots
  1. Refuse si quantite vaut - ou n'est pas un entier positif (test *[!0-9]* puis -gt 0).
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Mouvement de stock

Bash Niveau 2 — Application

Objectif : Appliquer entrées et sorties au stock existant, comme UPDATE quantite.

Le script lit n lignes « produit mouvement » où mouvement est un entier positif pour une entrée (le stock augmente) et préfixé de moins pour une sortie (le stock diminue). Le stock de départ de chaque produit est son entrée précédente : le premier mouvement d'un produit part de 0. Une sortie qui rendrait le stock négatif est refusée (produit : stock insuffisant, mouvement ignoré) ; sinon le script affiche le nouveau stock (produit : stock=X). Bilan final : mouvements : n.

Entrée du programme
4
clavier 10
clavier -4
souris 5
souris -9
Sortie attendue
clavier : stock=10
clavier : stock=6
souris : stock=5
souris : stock insuffisant
mouvements : 4
Deux indices, rédigés en mots
  1. Un mouvement qui commence par - est une sortie : quantite = valeur sans le signe.
  2. Sortie refusée si stock[produit] < quantite ; sinon stock += mouvement (entrée) ou -= (sortie).

Exercice 3 — Suppression protégée

Bash Niveau 3 — Raisonnement

Objectif : Traiter les demandes de suppression avec confirmation et refus motivés.

Le script lit n lignes « produit motif » : motif est un code parmi confirme, annule ou absent. Logique du tutoriel : askyesno confirme avant de supprimer — confirme → produit : supprime ; annule → produit : conserve ; absent (produit déjà parti de la table) → produit : introuvable et compté à part. Bilan : suppressions : X puis introuvables : Y (dans cet ordre, sur deux lignes).

Entrée du programme
3
clavier confirme
ecran annule
souris absent
Sortie attendue
clavier : supprime
ecran : conserve
souris : introuvable
suppressions : 1
introuvables : 1
Deux indices, rédigés en mots
  1. Trois verdicts : confirme → supprime (suppr+1), annule → conserve, absent → introuvable (abs+1).
  2. Deux lignes de bilan à la fin : suppressions : X puis introuvables : Y.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Exécuter UPDATE ou DELETE sans sélection préalable.
  • Confirmer la suppression par showinfo : c'est askyesno qui demande.
  • Laisser passer une sortie qui rend le stock négatif.
  • Oublier actualiser_tableau : l'écran continue d'afficher l'ancien état.

7. Méthodologie de résolution

Méthode — coder un mouvement en trois gestes
  1. Lire le stock actuel du produit (0 au départ).
  2. Entrée : ajouter ; sortie : refuser si le disponible est insuffisant.
  3. Afficher le nouveau stock et poursuivre la boucle sans planter.

8. Révision active

Résumé essentiel
  • Ajout : validation → INSERT → showinfo → champs et tableau rafraîchis.
  • Modification : sélection obligatoire → UPDATE WHERE id.
  • Suppression : askyesno → DELETE WHERE id ; introuvable rapporté à part.
  • Mouvements : entrées cumulées, sorties refusées si stock insuffisant.

Checklist de maîtrise

  • Je déroule le trio valider, appeler, rafraîchir.
  • J'explique la double garde de la suppression.
  • J'écris UPDATE et DELETE ciblés par id.
  • Je contrôle des entrées/sorties sans stock négatif.

Les 8 notions à connaître absolument

  1. Sélection Treeview : prérequis de toute modification.
  2. askyesno : dialogue oui/non avant suppression.
  3. UPDATE WHERE id : modification ciblée d'une ligne.
  4. DELETE WHERE id : suppression ciblée, jamais sans WHERE.
  5. Mouvement : entrée (+) ou sortie (−) de stock.
  6. Stock insuffisant : sortie refusée, mouvement ignoré.
  7. effacer_champs : formulaire vidé après action.
  8. actualiser_tableau : rechargement depuis la base.

9. Test de maîtrise

Comment t'auto-évaluer

Le QCM ci-dessus est un test de maîtrise. Lis ton pourcentage :

< 50 % — relis les trois actions du CRUD côté interface.
50–69 % — refais la suppression confirmée.
70–89 % — cible les mouvements et leur refus.
≥ 95 % — niveau de maîtrise recherché.
