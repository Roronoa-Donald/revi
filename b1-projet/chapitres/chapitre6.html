Chapitre 6 — Fiabiliser et livrer

Module 6 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le projet tourne, il reste à le livrer : anticiper les quatre pannes classiques, exporter les données pour preuve, cartographier les améliorations pour le rapport — et préparer le tableau de bord qui fera la soutenance : total, alertes, produit en vitrine.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. diagnostiquer les quatre problèmes courants du tutoriel et leur solution ;
  2. exporter le catalogue en CSV (en-tête, point-virgule, bilan) ;
  3. présenter les améliorations possibles et leurs exercices ;
  4. produire un tableau de bord : lignes, total, alertes, produit en vitrine.

1. Le dépannage du tutoriel

Quatre symptômes, quatre remèdes : « impossible de se connecter » → vérifier le service (sudo service postgresql status), le mot de passe, l'existence de la base ; « No module named psycopg2 » → pip install psycopg2-binary ; « No module named tkinter » → sudo apt install python3-tk ; « SyntaxError: Non-ASCII character » → en-tête # -*- coding: utf-8 -*- en première ligne. La démarche vaut plus que la liste : lire le symptôme, isoler la couche (service, module, encodage), appliquer le remède.

\n
Mnémotechnique — « service, module, module, encodage »

Les quatre pannes couvrent les quatre couches : serveur, dépendance Python, bibliothèque graphique, fichier source.

2. Exporter et améliorer

L'export CSV (amélioration 3) : une ligne par produit au format nom;categorie;quantite;prix — point-virgule par convention francophone — précédée de l'en-tête, suivie du bilan « lignes exportees ». L'en-tête se génère AVANT la boucle : il sort même pour un catalogue vide, et le bilan dit 0.

\n

Le tutoriel liste les améliorations : recherche et filtrage, alertes de stock et valeur totale (faites au chapitre 5), export CSV et rapports (fait ici), statistiques graphiques avec matplotlib, authentification et droits. Cinq exercices pratiques clôturent : champ date d'ajout, recherche par nom, bouton export, validation avant insertion, fenêtre de statistiques — autant de pistes à citer dans le rapport.

\n
Confusions d'examen
    \n
  • psycopg2 manquant se règle par pip ; tkinter par apt : les deux remèdes ne s'échangent pas.
    • \n
  • L'en-tête CSV sort avant la boucle : même pour 0 ligne.
    • \n
  • Le bilan « lignes exportees » compte les produits, pas l'en-tête.
    • \n
  • La vitrine se choisit sur la valeur de ligne, pas sur le prix unitaire.
    • \n

3. Le tableau de bord de soutenance

Le livrable final : pour chaque produit stock=X valeur=V, puis le total en FCFA, le nombre d'alertes, et la vitrine — le produit de plus grande valeur de ligne. Quatre lignes de synthèse qui résument le projet : la base est cohérente (stocks), elle vaut quelque chose (total), elle réclame des commandes (alertes), et elle a une vitrine (maximum). C'est exactement le récit d'une soutenance.

\n
Vérifier en Bash
    \n
  • Le diagnostic : connexion → service, psycopg2 → pip, tkinter → apt, ascii → utf8.
    • \n
  • Le CSV : en-tête avant la boucle, une ligne par produit, bilan après.
    • \n
  • Le tableau de bord : total + alertes + maximum, trois accumulateurs hors boucle.
    • \n

4. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Diagnostic d'erreur

Bash Niveau 1 — Acquisition

Objectif : Associer chaque symptôme de dépannage à sa solution du tutoriel.

Le script lit n lignes « symptome solution » : solution est un code parmi service, pip, apt ou utf8. Dépannage du tutoriel : « impossible de se connecter » → vérifier le service PostgreSQL (service) ; « ModuleNotFoundError psycopg2 » → pip install psycopg2-binary (pip) ; « ModuleNotFoundError tkinter » → sudo apt install python3-tk (apt) ; « SyntaxError Non-ASCII » → en-tête coding utf-8 (utf8). Pour chaque ligne il affiche symptome : OK ou symptome : ERREUR, puis diagnostics : X/n.

Entrée du programme
3
connexion service
psycopg2 pip
tkinter apt
Sortie attendue
connexion : OK
psycopg2 : OK
tkinter : OK
diagnostics : 3/3
Deux indices, rédigés en mots
  1. Un case sur le symptôme : connexion → service, psycopg2 → pip, tkinter → apt, ascii → utf8.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Export CSV

Bash Niveau 2 — Application

Objectif : Produire une ligne CSV valide par produit, comme l'amélioration 3 du tutoriel.

Le script lit n lignes « produit categorie quantite prix » et écrit une ligne CSV par produit au format produit;categorie;quantite;prix ; la première ligne de l'export est l'en-tête nom;categorie;quantite;prix. Après les lignes, il affiche le bilan lignes exportees : n. (Le séparateur du tutoriel est le point-virgule.)

Entrée du programme
2
clavier Periph 10 5000
souris Periph 30 2500
Sortie attendue
nom;categorie;quantite;prix
clavier;Periph;10;5000
souris;Periph;30;2500
lignes exportees : 2
Deux indices, rédigés en mots
  1. La ligne : "$produit;$categorie;$quantite;$prix".
  2. Le bilan sort une seule fois, après la boucle.

Exercice 3 — Tableau de bord de soutenance

Bash Niveau 3 — Raisonnement

Objectif : Produire le résumé complet du stock : lignes, alertes, valeur, produit le plus cher.

Le script lit n lignes « produit quantite prix seuil » et affiche le tableau de bord : une ligne par produit produit : stock=X valeur=V (V = quantite × prix) ; puis total : T FCFA (somme des valeurs) ; alertes : A (produits avec stock strictement inférieur au seuil) ; vitrine : P (V FCFA) (produit de plus grande valeur de ligne, premier rencontré en cas d'égalité).

Entrée du programme
3
clavier 10 5000 4
souris 5 2500 8
ecran 2 45000 1
Sortie attendue
clavier : stock=10 valeur=50000
souris : stock=5 valeur=12500
ecran : stock=2 valeur=90000
total : 152500 FCFA
alertes : 1
vitrine : ecran (90000 FCFA)
Deux indices, rédigés en mots
  1. V = quantite * prix ; total += V ; alerte si quantite -lt seuil.
  2. Le maximum : si V -gt vitrine_val OU vitrine = -, mettre à jour les deux.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Régler tkinter par pip : c'est un paquet système, apt.
  • Générer l'en-tête CSV dans la boucle : il se répéterait.
  • Choisir la vitrine sur le prix unitaire : un article unique très cher peut perdre.
  • Livrer sans tableau de bord : la soutenance perd son récit.

7. Méthodologie de résolution

Méthode — préparer la soutenance en trois gestes
  1. Dérouler les quatre pannes et leurs remèdes : service, pip, apt, utf-8.
  2. Produire l'export CSV : en-tête, lignes, bilan — la preuve des données.
  3. Afficher le tableau de bord : total, alertes, vitrine — le récit du projet.

8. Révision active

Résumé essentiel
  • Quatre pannes : service PostgreSQL, pip psycopg2, apt tkinter, utf-8.
  • Export CSV : en-tête avant boucle, lignes produit, bilan final.
  • Améliorations restantes : statistiques matplotlib, authentification.
  • Tableau de bord : total FCFA, alertes, vitrine par valeur de ligne.

Checklist de maîtrise

  • Je diagnostique les quatre problèmes courants.
  • Je produis un CSV complet, en-tête comprise.
  • Je cite les améliorations faites et celles qui restent.
  • Je génère le tableau de bord de soutenance.

Les 8 notions à connaître absolument

  1. systemctl status : premier réflexe de diagnostic du service.
  2. psycopg2-binary : l'installation pip qui manque.
  3. python3-tk : le paquet apt qui manque.
  4. coding utf-8 : en-tête contre le Non-ASCII.
  5. CSV : export lignes par point-virgules avec en-tête.
  6. Bilan d'export : lignes exportees, en-tête non comptée.
  7. Tableau de bord : total, alertes, vitrine.
  8. Vitrine : produit de plus grande valeur de ligne.
