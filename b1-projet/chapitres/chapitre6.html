Chapitre 6 — Fiabiliser et livrer

Mise en situation

Le projet tourne, il reste à le livrer : anticiper les quatre pannes classiques, exporter les données pour preuve, cartographier les améliorations pour le rapport — et préparer le tableau de bord qui fera la soutenance : total, alertes, produit en vitrine.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. diagnostiquer les quatre problèmes courants du tutoriel et leur solution ;
  2. exporter le catalogue en CSV (en-tête, point-virgule, bilan) ;
  3. présenter les améliorations possibles et leurs exercices ;
  4. produire un tableau de bord : lignes, total, alertes, produit en vitrine.

1. Le dépannage du tutoriel

Quatre symptômes, quatre remèdes : « impossible de se connecter » → vérifier le service (sudo service postgresql status), le mot de passe, l'existence de la base ; « No module named psycopg2 » → pip install psycopg2-binary ; « No module named tkinter » → sudo apt install python3-tk ; « SyntaxError: Non-ASCII character » → en-tête # -*- coding: utf-8 -*- en première ligne. La démarche vaut plus que la liste : lire le symptôme, isoler la couche (service, module, encodage), appliquer le remède.

Mnémotechnique — « service, module, module, encodage »

Les quatre pannes couvrent les quatre couches : serveur, dépendance Python, bibliothèque graphique, fichier source.

2. Exporter et améliorer

L'export CSV (amélioration 3) : une ligne par produit au format nom;categorie;quantite;prix — point-virgule par convention francophone — précédée de l'en-tête, suivie du bilan « lignes exportees ». L'en-tête se génère AVANT la boucle : il sort même pour un catalogue vide, et le bilan dit 0.

Le tutoriel liste les améliorations : recherche et filtrage, alertes de stock et valeur totale (faites au chapitre 5), export CSV et rapports (fait ici), statistiques graphiques avec matplotlib, authentification et droits. Cinq exercices pratiques clôturent : champ date d'ajout, recherche par nom, bouton export, validation avant insertion, fenêtre de statistiques — autant de pistes à citer dans le rapport.

Confusions d'examen
  • psycopg2 manquant se règle par pip ; tkinter par apt : les deux remèdes ne s'échangent pas.
  • L'en-tête CSV sort avant la boucle : même pour 0 ligne.
  • Le bilan « lignes exportees » compte les produits, pas l'en-tête.
  • La vitrine se choisit sur la valeur de ligne, pas sur le prix unitaire.

3. Le tableau de bord de soutenance

Le livrable final : pour chaque produit stock=X valeur=V, puis le total en FCFA, le nombre d'alertes, et la vitrine — le produit de plus grande valeur de ligne. Quatre lignes de synthèse qui résument le projet : la base est cohérente (stocks), elle vaut quelque chose (total), elle réclame des commandes (alertes), et elle a une vitrine (maximum). C'est exactement le récit d'une soutenance.

Vérifier dans l’atelier
  • Le diagnostic : connexion → service, psycopg2 → pip, tkinter → apt, ascii → utf8.
  • Le CSV : en-tête avant la boucle, une ligne par produit, bilan après.
  • Le tableau de bord : total + alertes + maximum, trois accumulateurs hors boucle.

4. Préparer la soutenance

La soutenance dure une dizaine de minutes. Un plan efficace suit le fil du projet, pas le fil du code :

  1. Le besoin (1 min) : le problème du commerçant et le cahier des charges ;
  2. La conception (2 min) : le MCD, le MLD et la table produits ;
  3. L’architecture (2 min) : database.py (modèle), Tkinter (vue), fonctions des boutons (contrôleur) ;
  4. La démonstration (3 min) : ajouter un produit, déclencher une alerte de seuil, exporter le CSV ;
  5. Le bilan (2 min) : difficultés rencontrées, historique Git, pistes d’amélioration (authentification, statistiques).

Préparez la démonstration sur une base de données propre, avec un jeu d’essai connu, et gardez une capture d’écran de secours. Le jury pose presque toujours une question sur la séparation des couches et une sur la gestion des erreurs : sachez montrer où se trouve le try/except.

5. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

La validation compare vos réponses aux attendus des cas affichés ; elle ne vérifie pas votre capacité à traiter toutes les situations.

En cas d’hésitation, le bouton Obtenir une aide formative générale fournit un conseil identique pour toutes les grilles, sans transmettre de réponse attendue ni utiliser le tuteur IA.

Exercice 1 — Les quatre pannes du premier lancement

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Diagnostiquer les quatre pannes classiques du projet et choisir le bon remède (service, pip, apt, utf-8), puis nommer le test unitaire.

Énoncé. Dernière ligne droite : livrer. Au premier lancement chez la librairie, Kofi affronte les quatre pannes classiques du tutoriel :

Symptôme à l'écranCouche en causeRemède
« impossible de se connecter »serveurvérifier le service PostgreSQL, le mot de passe, l'existence de la base
« No module named psycopg2 »dépendance Pythonpip install psycopg2-binary
« No module named tkinter »bibliothèque systèmesudo apt install python3-tk
« SyntaxError: Non-ASCII character »encodage du fichieren-tête # -*- coding: utf-8 -*- en première ligne

Avant de livrer, Kofi écrit aussi de petits tests unitaires : des fonctions qui vérifient automatiquement un comportement attendu (par exemple : une sortie supérieure au stock est bien refusée).

  1. Quand PostgreSQL refuse la connexion, que vérifie-t-on en premier : le service, le CSV ou le prix ?
  2. Pour « No module named psycopg2 », quel outil installe le remède : pip ou apt ?
  3. Pour « No module named tkinter », quel outil : pip ou apt ?
  4. Quel encodage déclare l'en-tête qui répare « Non-ASCII character » ?
  5. Combien de pannes classiques le tableau répertorie-t-il ?
  6. Comment s'appelle la vérification automatique d'un comportement attendu ? (un seul mot)
Cas d’exemple
L'application de la boulangerie plante au lancement :
1) « impossible de se connecter » : le service PostgreSQL était éteint — démarré, tout rentre.
2) « No module named flask » : paquet Python manquant — pip install flask.
3) « SyntaxError: Non-ASCII » : en-tête # -*- coding: utf-8 -*- ajoutée en première ligne.

1) Connexion : vérifier le service.
2) Module Python manquant : pip.
3) Encodage : utf-8.
Trois indices, rédigés en mots
  1. Chaque panne touche une couche différente : le serveur, une dépendance Python, une bibliothèque système, le fichier source.
  2. Le message « No module named X » nomme un module manquant : le remède dépend de la nature du module — paquet Python ou paquet système.
  3. Le message Non-ASCII signale des caractères non déclarés : l'en-tête de codage se place en première ligne du fichier.

Exercice 2 — L'export CSV pour le comptable

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Produire un export CSV conforme : en-tête avant la boucle, point-virgule, une ligne par produit, bilan des lignes exportées.

Énoncé. Pour son comptable, Mme Adjovi demande un export du catalogue. Le format du tutoriel : une ligne d'en-tête nom;categorie;quantite;prix générée avant la boucle (elle sort même pour un catalogue vide), puis une ligne par produit, les champs séparés par des points-virgules (convention francophone), et le bilan « lignes exportees » qui compte les produits, pas l'en-tête. Catalogue à exporter :

idnomcategoriequantiteprix (FCFA)
1Cahier 200 pagesPapeterie40500
2Stylo bleuPapeterie60350
3Roman policierLivres64500
4Atlas scolaireLivres96500
5GommePapeterie25200
  1. Quel caractère sépare les champs d'une ligne du CSV ?
  2. Combien de lignes de données l'export contient-il (sans l'en-tête) ?
  3. En comptant l'en-tête, combien de lignes compte le fichier CSV ?
  4. L'en-tête est-elle générée avant ou après la boucle d'export ?
  5. Le bilan « lignes exportees » compte-t-il l'en-tête ? Répondez par oui ou non.
  6. Si le catalogue était vide, l'en-tête apparaîtrait-elle quand même ? Répondez par oui ou non.
Cas d’exemple
Export d'une quincaillerie de 3 articles (clous, vis, marteau).
Ligne 1 (en-tête) : designation;rayon;quantite;tarif
Lignes 2 à 4 : les trois articles.
Bilan : lignes exportees : 3.

1) Séparateur : le point-virgule.
2) Lignes de données : 3.
3) Lignes du fichier en tout : 4.
4) Le bilan compte 3 : l'en-tête n'est pas comptée.
Trois indices, rédigés en mots
  1. Le CSV du tutoriel suit la convention francophone pour le séparateur de champs.
  2. Comptez les lignes de produits du tableau, puis ajoutez la ligne d'en-tête : une seule pour tout le fichier.
  3. L'en-tête est générée hors de la boucle : elle apparaît une seule fois, même si aucune ligne de données ne suit.

Exercice 3 — Le tableau de bord de la soutenance

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Construire le tableau de bord final : valeur totale, nombre d'alertes et vitrine (plus grande valeur de ligne).

Énoncé. Pour la soutenance, Inès prépare le tableau de bord final : pour chaque produit, son stock et sa valeur ; puis le total en FCFA, le nombre d'alertes (seuil 10 : alerte si 0 < stock < 10, rupture si stock 0) et la vitrine — le produit de plus grande valeur de ligne (quantite × prix). État du catalogue le jour de la soutenance :

idProduitQuantitéPrix unitaire (FCFA)
1Cahier 200 pages40500
2Atlas scolaire96500
3Stylo bleu60350
4Roman policier64500
5Agrafeuse102500
  1. Que vaut la ligne « Atlas scolaire » (quantité × prix) ?
  2. Quelle est la valeur totale du catalogue ?
  3. Combien de produits sont en alerte (strictement sous le seuil de 10) ?
  4. L'agrafeuse (stock 10, égal au seuil) compte-t-elle en alerte ? Répondez par oui ou non.
  5. Quel produit va en vitrine (plus grande valeur de ligne) ?
  6. La vitrine se choisit sur le prix unitaire ou sur la valeur de ligne ?

Montants en FCFA, nombres sans espace : 58500.

Cas d’exemple
Tableau de bord d'une épicerie (seuil 5) :
- riz : 20 sacs à 5000 FCFA → 100000, ok ;
- huile : 4 bouteilles à 1500 → 6000, alerte ;
- sucre : 12 kg à 800 → 9600, ok ;
- sel : 0 unité à 400 → 0, rupture.
Total : 100000 + 6000 + 9600 + 0 = 115600 FCFA.
Alertes : 1 (l'huile). Vitrine : le riz (100000).
Trois indices, rédigés en mots
  1. Le tableau de bord combine les acquis : valeur de ligne pour chaque produit, cascade du seuil pour les alertes, maximum pour la vitrine.
  2. Comparez chaque stock au seuil en pensant au cas limite : égal au seuil n'alerte pas, et le zéro est une rupture.
  3. Pour la vitrine, multipliez avant de comparer : un article rare et cher peut perdre contre un article modeste et nombreux.

6. QCM — niveau examen

« No module named psycopg2 » se corrige par…

psycopg2-binary est une dépendance Python : elle s'installe par pip ; apt installe le serveur PostgreSQL, pas la bibliothèque cliente.

« No module named tkinter » se corrige par…

tkinter est une bibliothèque système livrée par le paquet python3-tk : elle s'installe par apt, jamais par pip.

« SyntaxError: Non-ASCII character » exige…

Première ligne du fichier : # -*- coding: utf-8 -*-.

Impossible de se connecter : vérifier d'abord…

Service, mot de passe, existence de la base.

L'en-tête CSV est généré…

L'en-tête nom;categorie;quantite;prix sort avant la boucle : il apparaît une seule fois, même si le catalogue est vide.

Le séparateur CSV du tutoriel :

Convention francophone : nom;categorie;quantite;prix.

La vitrine du tableau de bord se choisit sur…

La vitrine est la plus grande valeur de ligne, quantite × prix ; retenir le prix unitaire seul ignorerait les quantités.

L'améliorations qui reste ouverte (non traitée dans le cours) :

Alertes, valeur et export sont faites ; auth et statistiques restent des pistes.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Régler tkinter par pip : c'est un paquet système, apt.
  • Générer l'en-tête CSV dans la boucle : il se répéterait.
  • Choisir la vitrine sur le prix unitaire : un article unique très cher peut perdre.
  • Livrer sans tableau de bord : la soutenance perd son récit.

8. Méthodologie de résolution

Méthode — préparer la soutenance en trois gestes
  1. Dérouler les quatre pannes et leurs remèdes : service, pip, apt, utf-8.
  2. Produire l'export CSV : en-tête, lignes, bilan — la preuve des données.
  3. Afficher le tableau de bord : total, alertes, vitrine — le récit du projet.

Les 8 notions à connaître absolument

  1. systemctl status : premier réflexe de diagnostic du service.
  2. psycopg2-binary : l'installation pip qui manque.
  3. python3-tk : le paquet apt qui manque.
  4. coding utf-8 : en-tête contre le Non-ASCII.
  5. CSV : export lignes par point-virgules avec en-tête.
  6. Bilan d'export : lignes exportees, en-tête non comptée.
  7. Tableau de bord : total, alertes, vitrine.
  8. Vitrine : produit de plus grande valeur de ligne.

Comment vous auto-évaluer
