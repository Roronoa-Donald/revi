Mémo Projet tutoré

Les règles du projet sur une page, dans l'ordre de la construction. À garder ouvert pendant les exercices et l'atelier.

Cadrage et environnement

objectifs : interface Tkinter / connexion PostgreSQL /

  operations CRUD / exceptions / modules reutilisables



prerequis : Python >= 3.7 / tkinter / postgresql

  notions POO + bases de donnees relationnelles



installation : python3-pip, postgresql-contrib,

  python3-tk, pip install psycopg2-binary

base : CREATE DATABASE gestion_stock ;



structure :

  main.py           interface principale

  database.py       classe Database (SQL)

  requirements.txt  psycopg2-binary==2.9.9

  README.md         documentation

Deux classes, deux mondes : Database parle SQL, l'application parle à l'écran.

La table produits et la connexion

CREATE TABLE IF NOT EXISTS produits (

  id        SERIAL PRIMARY KEY,

  nom       VARCHAR(100) NOT NULL,

  categorie VARCHAR(50),

  quantite  INTEGER NOT NULL,

  prix      DECIMAL(10,2) NOT NULL

)



connecter : psycopg2.connect(host, database, user,

  password) -> cursor ; try/except -> True/False

ecriture : execute puis connection.commit()

lecture   : execute puis cursor.fetchall()

fermer    : cursor.close() puis connection.close()

Sans commit, l'écriture est perdue à la déconnexion.

Les requêtes CRUD

Create : INSERT INTO produits (nom, categorie,

  quantite, prix) VALUES (%s, %s, %s, %s)

Read   : SELECT * FROM produits ORDER BY id

Update : UPDATE produits SET nom=%s, categorie=%s,

  quantite=%s, prix=%s WHERE id=%s

Delete : DELETE FROM produits WHERE id=%s



mouvement : UPDATE SET quantite = quantite + X

  (ou - X apres controle) WHERE id=%s



%s = requetes parametrees : psycopg2 echappe,

  protection contre l'injection SQL

DELETE et UPDATE toujours avec WHERE id : sinon toute la table.

Interface Tkinter et validation

ecran 1 : connexion (host, database, user, password)

  succes -> creer_table, destroy, ecran principal

ecran 2 : formulaire, boutons, Treeview



widgets : Label, Entry, Button (command=),

  Frame/LabelFrame, ttk.Treeview, Scrollbar

layout : pack (empile) / grid (lignes-colonnes)

bind("") : clic -> formulaire



boites : showinfo (succes) / showwarning (attention)

  / showerror (echec) / askyesno (confirmation)



validation avant INSERT : champs non vides,

  int(quantite), float(prix) dans un try

fermeture : db.deconnecter() puis root.destroy()

La base ne reçoit jamais de donnée absurde : valider d'abord.

Logique métier et livraison

etats de stock : stock = 0 -> rupture /

  stock < seuil -> alerte / stock >= seuil -> ok

valeur ligne = quantite x prix

total : accumulateur a 0, affiche apres la boucle

maximum : meilleur + valeur, test STRICT,

  premier rencontre gagne a egalite



export CSV : en-tete AVANT la boucle, une ligne par

  produit nom;categorie;quantite;prix, bilan apres



depannage : connexion -> service / psycopg2 -> pip /

  tkinter -> apt / Non-ASCII -> coding utf-8



tableau de bord : total FCFA / alertes /

  vitrine (plus grande valeur de ligne)

Trois accumulateurs hors boucle, bilans après : le récit de la soutenance.

Erreurs fréquentes à éviter

  • Lancer l'application sans créer la base gestion_stock.
  • Oublier commit après INSERT, UPDATE ou DELETE.
  • Concaténer les valeurs dans le SQL : requêtes paramétrées obligatoires.
  • Mettre FLOAT pour le prix : DECIMAL(10,2) est exact.
  • Supprimer sans askyesno ni sélection préalable.
  • Laisser passer une sortie de stock supérieure au disponible.
  • Compter en alerte un stock égal au seuil : le test est strict.
  • Afficher le total dans la boucle : sous-totaux, pas total.
  • Initialiser le maximum à un produit existant : biais du premier.
  • Générer l'en-tête CSV dans la boucle : il se répéterait.
