Chapitre 6 — Débogage et bonnes pratiques

Module 6 ≈ 2 h 30 Contenu protégé
Mise en situation

Votre script plante au pire moment : ZeroDivisionError devant le client. Vous ne pouvez pas simplement « ne plus diviser par zéro » : il faut anticiper l'erreur et garder le programme vivant. Le métier ne consiste pas à écrire du code qui marche une fois, mais du code qui résiste. Ce chapitre vous apprend à lire une erreur, à la reproduire, à la corriger, et à écrire du code lisible — exactement ce que l'examen évalue (exercice 4 : gestion d'exceptions et bonnes pratiques).

Objectifs pédagogiques
  1. Distinguer erreur de syntaxe, d'exécution et de logique ;
  2. lire une traceback et localiser la ligne fautive ;
  3. utiliser try/except/else/finally correctement ;
  4. lever une erreur volontairement avec raise ;
  5. importer et utiliser une bibliothèque ;
  6. écrire une docstring et appliquer les règles de lisibilité (PEP 8).

1. Les trois types d'erreurs

TypeQuand ?ExempleException
SyntaxeAvant l'exécutionif x = 3:SyntaxError
ExécutionPendant l'exécution10 / 0ZeroDivisionError
LogiqueAucune erreur… mais mauvais résultatmoyenne = somme au lieu de somme/nAucune (le plus dangereux)
Niveau 1 — Intuition

La syntaxe, c'est une faute de grammaire : Python refuse d'exécuter. L'exécution, c'est une action impossible (diviser par zéro) : Python s'arrête au moment du crash. La logique, c'est un raisonnement faux qui donne un résultat plausible — le pire, car rien ne prévient.

2. Lire une traceback

def moyenne(notes):
    return sum(notes) / len(notes)

print(moyenne([]))
Traceback (most recent call last): File "essai.py", line 4, in <module> print(moyenne([])) File "essai.py", line 2, in moyenne return sum(notes) / len(notes) ZeroDivisionError: division by zero
Lire une traceback dans le bon sens

Lisez la dernière ligne d'abord : c'est le type et le message de l'erreur. Puis remonte : la trace te montre le chemin d'appel jusqu'à la ligne fautive (return sum(notes) / len(notes), car len([]) vaut 0).

3. Gérer les exceptions : try / except

def division(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("Erreur : division par zéro impossible.")
        return None

print(division(10, 0))
print(division(10, 2))
Erreur : division par zéro impossible. None 5.0
ClauseQuand s'exécute-t-elle ?
tryLe code surveillé.
except Type:Si une exception de ce type est levée.
elseSi aucune exception — code de succès.
finallyToujours, succès ou échec (nettoyage).
Le piège du except trop large

except: ou except Exception: attrape tout, y compris vos propres bugs, et masque la cause. Capture le type précis (ZeroDivisionError, ValueError, FileNotFoundError) — sinon vous cachez l'erreur au lieu de la gérer.

raise — signaler un problème

Pour refuser une valeur invalide, on lève soi-même une erreur : if n < 0: raise ValueError("n doit être positif"). C'est ainsi qu'on protège une fonction d'entrées impossibles.

4. Techniques de débogage de base

  • Reproduire l'erreur avec le plus petit exemple possible.
  • print ciblés : afficher les valeurs intermédiaires aux endroits suspects.
  • Débogueur de l'IDE : point d'arrêt (breakpoint), exécution pas à pas, inspection des variables.
  • Isoler : tester une fonction seule, hors du grand programme.
  • Lire le message : Python donne souvent le type exact et la ligne.
Utilité IT

En production, une erreur non gérée fait tomber le service. Les try/except et la journalisation (logging) sont la base de la fiabilité. Un développeur qui sait lire une traceback résout en minutes ce qui prend des heures à d'autres.

5. Bibliothèques, docstrings, PEP 8

import statistics

def moyenne(notes):

6. Exemples travaillés

Exemple ATrès simple

Identifier le type d'erreur : print(5 + "a")

Réponse
TypeError (exécution) : on ne peut pas additionner un int et un str.
Exemple BIntermédiaire

Énoncé (sujet type). Le programme def division(a,b): return a/b puis print(division(10, 0)) plante. Identifiez l'erreur et corrige-la.

def division(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return "Erreur : division par zéro."

Analyse. L'erreur est ZeroDivisionError (exécution). Le try/except cible le bon type et fournit un message personnalisé.

Exemple CDifficile

Énoncé. Fonction robuste qui convertit une saisie en entier, en gérant un texte invalide.

def lire_entier(prompt):
    while True:
        saisie = input(prompt)
        try:
            return int(saisie)
        except ValueError:
            print("Valeur invalide, réessaie.")

Pourquoi boucler ? Une saisie invalide n'est pas exceptionnelle : on redemande plutôt que de planter. C'est le motif « valider jusqu'à obtenir une valeur correcte ».

def lire_note():
    while True:
        try:
            n = float(input("Note (0-20) ? "))
            if not 0 <= n <= 20:

10. Erreurs classiques

À reconnaître en examen
  • except: nu qui masque les bugs.
  • Confondre erreur de logique et erreur d'exécution.
  • Ne pas relancer le programme après correction (l'erreur « disparaît » dans l'IDE).
  • Croire qu'une traceback indique la dernière ligne exécutée : elle indique la ligne fautive en dernier.
  • Oublier raise pour signaler une entrée invalide.

11. Méthodologie de résolution

Corriger une erreur — boucle en 5 temps
  1. Lire la dernière ligne de la traceback (type + message).
  2. Remonter à la ligne fautive.
  3. Reproduire avec le plus petit exemple.
  4. Corriger (typage, gestion, logique).
  5. Re-tester et vérifier la gestion du cas limite (0, vide, None).
