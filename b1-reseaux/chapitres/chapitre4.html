Chapitre 4 — Le modèle TCP/IP

Mise en situation

Le modèle TCP/IP est celui qui fait tourner Internet : quatre couches, une poignée de protocoles, et une règle d'or — TCP établit la connexion avant de parler, UDP envoie sans demander. Le chapitre explique les deux modèles et détaille le three-way handshake, séquence d'ouverture de toute connexion TCP.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. ranger les protocoles dans les quatre couches TCP/IP : accès réseau, internet, transport, application ;
  2. relier les couches TCP/IP aux couches OSI ;
  3. dérouler le three-way handshake : SYN, SYN-ACK, ACK ;
  4. choisir TCP ou UDP selon l'exigence de fiabilité.

1. Quatre couches, un modèle réel

Le modèle TCP/IP regroupe les sept couches OSI en quatre : accès réseau (physique + liaison : Ethernet, câbles), internet (réseau : IP, routage), transport (TCP, UDP, ports) et application (session + présentation + application : HTTP, messagerie, FTP). C'est le modèle des produits réels — OSI reste le référentiel de discussion.

Le support rappelle les normes IEEE : 802.3 définit Ethernet. Sur un support partagé en half-duplex, CSMA/CD détecte les collisions ; en full-duplex, la détection de collisions est désactivée. 802.11 (avec CSMA/CA) définit les réseaux locaux sans fil, de la couche physique à la sous-couche MAC.

Source : documentation Cisco sur les modes duplex Ethernet, consultée le 30 octobre 2026.

Mnémotechnique — « Accès, Internet, Transport, Application : AITA »

Les trois couches hautes d'OSI fusionnent en une seule « application » ; les deux basses fusionnent en « accès réseau ». Le transport reste seul : c'est lui qui choisit TCP ou UDP.

2. Le three-way handshake et TCP contre UDP

TCP ouvre toute connexion en trois étapes : 1. SYN — le client envoie un paquet SYN (synchronized) portant un numéro de séquence aléatoire A ; 2. SYN-ACK — le serveur répond avec un ACK valant A + 1 et son propre numéro de séquence aléatoire B ; 3. ACK — le client accuse réception avec B + 1. Les étapes 1-2 définissent la séquence client vers serveur, les étapes 2-3 la séquence inverse : la communication full-duplex est établie.

TCP convient aux transferts exigeant la fiabilité — courriels, pages web, transferts de fichiers : accusés de réception, réémission des pertes. UDP convient aux flux temps réel — voix, DNS, vidéo : plus rapide, sans accusé, tolérant aux pertes. Le professionnel choisit selon l'exigence : un mot manquant dans un contrat est grave, une micro-coupure dans un appel ne l'est pas.

Confusions d'examen
  • Le SYN-ACK porte deux numéros : l'acquittement (A + 1) et une nouvelle séquence (B).
  • Sans les trois étapes, pas de connexion TCP : SYN, SYN-ACK, ACK dans l'ordre.
  • UDP n'est pas « pire » que TCP : il est adapté aux flux temps réel.
  • CSMA/CD concerne Ethernet half-duplex ; le full-duplex ne détecte pas de collision.

Exercice 1 — Les quatre couches TCP/IP

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Ranger chaque élément dans les quatre couches du modèle TCP/IP : accès réseau, internet, transport, application.

Associez chaque protocole ou mécanisme réseau à sa couche du modèle TCP/IP : objet : acces-reseau, objet : internet, objet : transport ou objet : application. Terminez par transport : X/n.

Cas d’exemple
4
ethernet (trames MAC)
ip (adressage et routage)
tcp (segments fiables sur port 443)
http (pages Web)
Trois indices, rédigés en mots
  1. Situez le rôle : média/MAC (acces-reseau), adressage/routage IP (internet), ports/fiabilité de bout en bout (transport) ou service utilisateur (application).
  2. Le compteur final ne retient que les éléments de couche transport.
  3. Écrivez exactement « objet : acces-reseau | internet | transport | application » puis « transport : X/n ».

Exercice 2 — Le three-way handshake de la banque en ligne

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Dérouler le three-way handshake de TCP avec les numéros de séquence et d'acquittement.

Énoncé. Le navigateur de Marc ouvre une connexion TCP vers le serveur de sa banque en ligne. Le three-way handshake commence : le navigateur envoie un premier paquet portant le numéro de séquence aléatoire A = 500. Le serveur répond par un SYN-ACK : il accuse la séquence du client et propose la sienne, B = 800. Le navigateur conclut par un ACK.

Questions 1 et 5 : un seul mot. Questions 2, 3 et 4 : le nombre seul.

  1. Comment s'appelle le premier paquet envoyé par le navigateur ?
  2. Dans son SYN-ACK, le serveur accuse la séquence du client : quel numéro envoie-t-il (A + 1) ?
  3. Le navigateur conclut par un ACK : quel numéro envoie-t-il pour acquitter la séquence B du serveur ?
  4. Combien d'étapes compte le three-way handshake ?
  5. Une fois le handshake terminé, la communication établie est-elle half-duplex ou full-duplex ?
Cas d’exemple
Un photographe ouvre une connexion FTP vers son studio. Le client envoie SYN avec la séquence A = 2000 ; le serveur répond SYN-ACK avec sa séquence B = 300 ; le client conclut par ACK.

1) Premier paquet : SYN.
2) Acquittement du SYN-ACK : 2001.
3) Acquittement de l'ACK final : 301.
4) Le handshake compte 3 étapes.
5) La communication est full-duplex.
Trois indices, rédigés en mots
  1. L'ouverture TCP se déroule en trois temps : SYN (séquence A), SYN-ACK (acquittement A + 1 et séquence B), ACK (B + 1).
  2. Chaque numéro d'acquittement vaut la séquence reçue augmentée de un : le serveur accuse la séquence du client, puis le client accuse celle du serveur.
  3. Les étapes 1 et 2 fixent la séquence dans un sens, les étapes 2 et 3 dans l'autre : une fois les trois échanges passés, le dialogue est établi dans les deux sens.

Exercice 3 — TCP contre UDP

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Choisir entre TCP (fiable, accusés de réception, full-duplex) et UDP (rapide, sans accusé).

Évaluez la priorité de chaque flux réseau : intégrité garantie avec accusés de réception (flux : fiable, via TCP) ou latence minimale en temps réel sans retransmission (flux : rapide, via UDP). Terminez par fiables : X/n.

Cas d’exemple
3
courriel (pièce jointe SMTP complète)
dns (résolution simple sans session)
transfert (sauvegarde binaire critique)
Trois indices, rédigés en mots
  1. Un transfert de fichier, une page web ou une transaction ne tolèrent aucune perte (« fiable ») ; la voix/vidéo directe ou un ping/DNS simple privilégient la vitesse (« rapide »).
  2. Le compteur « fiables : X/n » totalise les flux devant reposer sur TCP.
  3. Indiquez « flux : fiable » ou « flux : rapide » pour chaque ligne, puis « fiables : X/n ».

4. QCM — niveau examen

Les couches du modèle TCP/IP sont…

TCP/IP empile quatre couches — accès réseau, internet, transport, application (AITA) — quand OSI en décrit sept ; la réponse à trois couches confond accès réseau et internet.

La couche internet de TCP/IP correspond à OSI…

La couche internet assume le routage des paquets : elle correspond à la couche 3 OSI, réseau, celle des adresses IP et des routeurs.

La première étape du handshake est…

SYN avec numéro de séquence aléatoire A.

Le SYN-ACK porte…

Acquittement A + 1, nouveau numéro de séquence B.

Après le handshake, la communication est…

Le three-way handshake fixe des numéros de séquence dans les deux sens : la communication devient full-duplex, chaque partie émettant et recevant simultanément.

La voix sur IP utilise plutôt…

La voix en direct privilégie la rapidité : UDP transmet sans acquittement, une perte occasionnelle étant préférable à un délai ; TCP réémettrait trop lentement.

Un courriel voyage en…

Un courriel exige l'intégrité : TCP, avec ses accusés de réception et ses réémissions, garantit un message complet ; ICMP ne transporte que des messages de contrôle.

En Ethernet full-duplex, que devient CSMA/CD ?

CSMA/CD s’applique au half-duplex partagé ; le full-duplex ne nécessite pas la détection de collisions.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre les couches TCP/IP et OSI : 4 contre 7, les fusions se font en haut et en bas.
  • Démarrer un handshake par SYN-ACK : l'ordre est SYN, SYN-ACK, ACK.
  • Choisir TCP pour la voix : le retard de réémission dégrade l'appel.
  • Oublier que UDP sert aussi au DNS : rapide ne veut pas dire jouet.

6. Méthodologie de résolution

Méthode — choisir le transport en trois gestes
  1. Évaluer le coût d'une perte : contrat manquant (TCP) ou micro-coupure (UDP).
  2. Vérifier l'exigence de temps réel : flux vivant, UDP ; fichier exact, TCP.
  3. Dérouler le handshake si TCP : SYN (A), SYN-ACK (A+1, B), ACK (B+1).

7. Révision active

Résumé essentiel
  • Quatre couches : accès réseau, internet, transport, application.
  • Ethernet half-duplex : CSMA/CD ; full-duplex : sans détection de collisions ; Wi-Fi : CSMA/CA.
  • Handshake TCP : SYN (A), SYN-ACK (A+1, B), ACK (B+1) — full-duplex.
  • TCP = fiable (courriels, web) ; UDP = rapide (voix, DNS).

Checklist de maîtrise

  • Je sais ranger dix protocoles dans les quatre couches.
  • Je sais relier chaque couche TCP/IP à ses couches OSI.
  • Je sais dérouler le three-way handshake avec les numéros.
  • Je sais justifier TCP ou UDP pour cinq services donnés.

Les 8 notions à connaître absolument

  1. Accès réseau : physique + liaison — Ethernet, 802.3.
  2. Internet : couche réseau — IP, routage.
  3. Transport : TCP et UDP, ports.
  4. Application : HTTP, messagerie, FTP — fusion des couches 5-7.
  5. SYN : premier paquet, séquence aléatoire A.
  6. SYN-ACK : ACK = A + 1, séquence B.
  7. CSMA/CD : détection de collisions en Ethernet half-duplex partagé.
  8. CSMA/CA : contrôle d'accès Wi-Fi (802.11).
