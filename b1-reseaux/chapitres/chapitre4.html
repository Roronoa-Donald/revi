Chapitre 4 — Le modèle TCP/IP

Module 4 ≈ 2 h de travail Réservé B1 et plus
Mise en situation

Le modèle TCP/IP est celui qui fait tourner Internet : quatre couches, une poignée de protocoles, et une règle d'or — TCP établit la connexion avant de parler, UDP envoie sans demander. Le chapitre explique les deux modèles et détaille le three-way handshake, séquence d'ouverture de toute connexion TCP.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. ranger les protocoles dans les quatre couches TCP/IP : accès réseau, internet, transport, application ;
  2. relier les couches TCP/IP aux couches OSI ;
  3. dérouler le three-way handshake : SYN, SYN-ACK, ACK ;
  4. choisir TCP ou UDP selon l'exigence de fiabilité.

1. Quatre couches, un modèle réel

Le modèle TCP/IP regroupe les sept couches OSI en quatre : accès réseau (physique + liaison : Ethernet, câbles), internet (réseau : IP, routage), transport (TCP, UDP, ports) et application (session + présentation + application : HTTP, messagerie, FTP). C'est le modèle des produits réels — OSI reste le référentiel de discussion.

Le support rappelle les normes IEEE : 802.3 définit le contrôle d'accès au support (MAC) de l'Ethernet filaire — CSMA/CD — employé dans les réseaux locaux et certaines applications WAN ; 802.11 (avec CSMA/CA) définit les réseaux locaux sans fil, de la couche physique à la sous-couche MAC.

Mnémotechnique — « Accès, Internet, Transport, Application : AITA »

Les trois couches hautes d'OSI fusionnent en une seule « application » ; les deux basses fusionnent en « accès réseau ». Le transport reste seul : c'est lui qui choisit TCP ou UDP.

2. Le three-way handshake et TCP contre UDP

TCP ouvre toute connexion en trois étapes : 1. SYN — le client envoie un paquet SYN (synchronized) portant un numéro de séquence aléatoire A ; 2. SYN-ACK — le serveur répond avec un ACK valant A + 1 et son propre numéro de séquence aléatoire B ; 3. ACK — le client accuse réception avec B + 1. Les étapes 1-2 définissent la séquence client vers serveur, les étapes 2-3 la séquence inverse : la communication full-duplex est établie.

TCP convient aux transferts exigeant la fiabilité — courriels, pages web, transferts de fichiers : accusés de réception, réémission des pertes. UDP convient aux flux temps réel — voix, DNS, vidéo : plus rapide, sans accusé, tolérant aux pertes. Le professionnel choisit selon l'exigence : un mot manquant dans un contrat est grave, une micro-coupure dans un appel ne l'est pas.

Confusions d'examen
  • Le SYN-ACK porte deux numéros : l'acquittement (A + 1) et une nouvelle séquence (B).
  • Sans les trois étapes, pas de connexion TCP : SYN, SYN-ACK, ACK dans l'ordre.
  • UDP n'est pas « pire » que TCP : il est adapté aux flux temps réel.
  • CSMA/CD (Ethernet filaire, 802.3) et CSMA/CA (Wi-Fi, 802.11) ne sont pas interchangeables.

Exercice 1 — Les quatre couches TCP/IP

Bash Niveau 1 — Acquisition

Objectif : Ranger chaque élément dans les quatre couches du modèle TCP/IP : accès réseau, internet, transport, application.

Le script lit n lignes « objet couche » : couche vaut ac (accès réseau), in (internet), tr (transport) ou ap (application). Pour chaque ligne il affiche objet : acces-reseau, objet : internet, objet : transport ou objet : application. Il termine par transport : X/n.

Entrée du programme
4
ethernet ac
ip in
tcp tr
http ap
Sortie attendue
ethernet : acces-reseau
ip : internet
tcp : transport
http : application
transport : 1/4
Deux indices, rédigés en mots
  1. Un case à quatre codes : ac, in, tr, ap.
  2. Le compteur suit exactement les lignes « transport ».

Exercice 2 — Le three-way handshake

Bash Niveau 2 — Application

Objectif : Vérifier la séquence TCP : SYN, puis SYN-ACK, puis ACK — sinon la connexion échoue.

Le script lit n lignes « paquet etape » : etape vaut syn, synack ou ack. La connexion est correcte si les paquets arrivent dans l'ordre syn, puis synack, puis ack. Pour chaque ligne il affiche paquet : etape N (1, 2 ou 3) si le paquet est dans l'ordre, paquet : hors sequence sinon. Final : connexion : etablie si les trois étapes sont passées dans l'ordre, connexion : echouee sinon.

Entrée du programme
3
p1 syn
p2 synack
p3 ack
Sortie attendue
p1 : etape 1
p2 : etape 2
p3 : etape 3
connexion : etablie
Deux indices, rédigés en mots
  1. Trois étapes numérotées : syn avance à 1, synack avance à 2 (seulement si on est à 1), ack avance à 3.
  2. Un drapeau rompu : toute sortie d'ordre casse la connexion pour la suite.

Exercice 3 — TCP contre UDP

Bash Niveau 3 — Raisonnement

Objectif : Choisir entre TCP (fiable, accusés de réception, full-duplex) et UDP (rapide, sans accusé).

Le script lit n lignes « flux protocole » : protocole vaut tcp (transferts exigeant la fiabilité) ou udp (flux temps réel tolérant aux pertes). Pour chaque ligne il affiche flux : fiable (tcp) ou flux : rapide (udp). Il termine par fiables : X/n.

Entrée du programme
3
courriel tcp
dns udp
transfert tcp
Sortie attendue
courriel : fiable
dns : rapide
transfert : fiable
fiables : 2/3
Deux indices, rédigés en mots
  1. Un if sur le protocole suffit : tcp et udp sont les deux seules valeurs.
  2. Le compteur suit exactement les flux « fiable ».

4. QCM — niveau examen

Les couches du modèle TCP/IP sont…

AITA : accès réseau, internet, transport, application.

La couche internet de TCP/IP correspond à OSI…

La couche réseau d'OSI : IP, routage.

La première étape du handshake est…

SYN avec numéro de séquence aléatoire A.

Le SYN-ACK porte…

Acquittement A + 1, nouveau numéro de séquence B.

Après le handshake, la communication est…

Séquences définies dans les deux sens.

La voix sur IP utilise plutôt…

UDP : rapidité, tolérance aux pertes.

Un courriel voyage en…

Fiabilité exigée : TCP avec accusés.

L'Ethernet filaire (802.3) utilise…

CSMA/CD ; le Wi-Fi 802.11 utilise CSMA/CA.

5. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre les couches TCP/IP et OSI : 4 contre 7, les fusions se font en haut et en bas.
  • Démarrer un handshake par SYN-ACK : l'ordre est SYN, SYN-ACK, ACK.
  • Choisir TCP pour la voix : le retard de réémission dégrade l'appel.
  • Oublier que UDP sert aussi au DNS : rapide ne veut pas dire jouet.

6. Méthodologie de résolution

Méthode — choisir le transport en trois gestes
  1. Évaluer le coût d'une perte : contrat manquant (TCP) ou micro-coupure (UDP).
  2. Vérifier l'exigence de temps réel : flux vivant, UDP ; fichier exact, TCP.
  3. Dérouler le handshake si TCP : SYN (A), SYN-ACK (A+1, B), ACK (B+1).

7. Révision active

Résumé essentiel
  • Quatre couches : accès réseau, internet, transport, application.
  • IEEE 802.3 : Ethernet filaire CSMA/CD ; 802.11 : Wi-Fi CSMA/CA.
  • Handshake TCP : SYN (A), SYN-ACK (A+1, B), ACK (B+1) — full-duplex.
  • TCP = fiable (courriels, web) ; UDP = rapide (voix, DNS).

Checklist de maîtrise

  • Je sais ranger dix protocoles dans les quatre couches.
  • Je sais relier chaque couche TCP/IP à ses couches OSI.
  • Je sais dérouler le three-way handshake avec les numéros.
  • Je sais justifier TCP ou UDP pour cinq services donnés.

Les 8 notions à connaître absolument

  1. Accès réseau : physique + liaison — Ethernet, 802.3.
  2. Internet : couche réseau — IP, routage.
  3. Transport : TCP et UDP, ports.
  4. Application : HTTP, messagerie, FTP — fusion des couches 5-7.
  5. SYN : premier paquet, séquence aléatoire A.
  6. SYN-ACK : ACK = A + 1, séquence B.
  7. CSMA/CD : contrôle d'accès Ethernet filaire (802.3).
  8. CSMA/CA : contrôle d'accès Wi-Fi (802.11).
