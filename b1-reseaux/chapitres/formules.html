Mémo réseaux

Les règles du cours sur une page, dans l'ordre d'un dépannage. À garder ouvert pendant les exercices et l'atelier.

Classer un réseau

portee : PAN (une personne) / LAN (immeuble, campus) /

         WLAN (LAN sans fil, 802.11) / MAN (ville) / WAN (pays)

gestion: workgroup = chaque poste client ET serveur (max 10 postes)

         client-serveur = comptes centralises, cout du serveur



specialises : CAN (campus) / SAN (stockage en mode bloc)

Si le réseau tient dans des murs, c'est un LAN ; s'il emprunte des liaisons louées, c'est un WAN.

Topologies et supports

bus    : un seul cable, 10Base2, UNE coupure = tout tombe

anneau : jeton (Token Ring, 16 Mbit/s), 2 chemins,

         double anneau = bascule sur le secondaire

etoile : noeud central, coupure = 1 poste isole, beaucoup de cables



supports : UTP 100 m (cat 5 : 100 Mbit/s, cat 5e : 1 Gbit/s)

           STP blinde (interferences) / fibre (longue distance)

           Wi-Fi 802.11 / Bluetooth RFCOMM / CPL domestique

Retenez le comportement en panne : c'est lui que l'examen teste.

Le modèle OSI

1 physique       : cables, broches, tensions, radio

2 liaison        : trame, MAC/LLC, commutateurs

3 reseau         : IP, routage, routeurs

4 transport      : TCP/UDP, ports

5 session        : ouverture, coordination, terminaison du dialogue

6 presentation   : format, chiffrement, compression

7 application    : navigateur, messagerie, FTP



depannage : remonter depuis la couche 1 (cables, alimentation)

Commutateur = couche 2, routeur = couche 3 : l'inverse est le piège classique.

TCP/IP et le handshake

4 couches : acces reseau (OSI 1+2) / internet (OSI 3) /

            transport (OSI 4) / application (OSI 5+6+7)



802.3 Ethernet filaire : CSMA/CD     802.11 Wi-Fi : CSMA/CA



three-way handshake :

  1. SYN     client -> serveur, sequence aleatoire A

  2. SYN-ACK serveur -> client, ACK = A+1, sequence B

  3. ACK     client -> serveur, B+1   (full-duplex etabli)



TCP fiable : courriels, web, fichiers   UDP rapide : voix, DNS

Sans les trois étapes, pas de connexion TCP : SYN, SYN-ACK, ACK dans l'ordre.

Adressage : MAC, IP, classes

MAC   : 48 bits = 12 hexa ; 6 OUI fabricant + 6 serie ;

        couche 2, JAMAIS routee au-dela du LAN

IPv4  : 32 bits, 4 octets ; partie reseau + partie hote

IPv6  : 128 bits, 8 groupes hexa

ARP   : traduit IP en MAC sur le meme reseau



masque : bits a 1 = reseau, bits a 0 = hote

classes : A 1-126 /8    B 128-191 /16    C 192-223 /24

          D 224-239 multicast   E 240-254 experimental

          127 = boucle locale

L'IP dirige le paquet de réseau en réseau, la MAC de dispositif en dispositif.

Sous-réseautage : VLSM et CIDR

emprunt de bits (sur /24) :

  sous-reseaux = 2^emprunt        hotes valides = 2^restants - 2

  dernier octet du masque : 1 bit=128  2=192  3=224  4=240

  prefixe : /24 + emprunt   (3 bits empruntes -> /27)



VLSM : masques differents dans un meme reseau

       /30 = 2 hotes = liaison point-a-point

CIDR : notation /n, fin des classes A-B-C, standard actuel

Les hôtes valides retirent deux adresses : réseau et diffusion — 2^k - 2, jamais 2^k.

Erreurs fréquentes à éviter

  • Appeler WAN un Wi-Fi de campus : le WLAN reste un réseau local.
  • Promettre la continuité de service en bus : une coupure arrête tout.
  • Placer le routeur en couche 2 ou le commutateur en couche 3.
  • Chercher le chiffrement en couche 7 : il se fait en couche 6.
  • Router une adresse MAC : elle s'arrête au premier routeur.
  • Ranger 127 en classe B : c'est la boucle locale.
  • Démarrer un handshake par SYN-ACK : l'ordre est SYN, SYN-ACK, ACK.
  • Choisir TCP pour la voix : le retard de réémission dégrade l'appel.
  • Oublier de retirer 2 aux hôtes : réseau et diffusion ne sont pas attribuables.
  • Appliquer le même masque partout quand le VLSM est demandé.
