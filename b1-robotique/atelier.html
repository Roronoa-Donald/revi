Atelier de simulation

Un éditeur dans la page, un vrai interpréteur Python derrière. Programme le comportement du robot, exécute-le et lis ce qu’il affiche : c’est ici qu’une idée devient un programme.

Comment fonctionne l’atelier
  • Exécuter fait tourner votre code Python tel quel et affiche sa sortie, ses erreurs et son code de sortie.
  • Données du cas contient les paramètres soumis à l’étude.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Zone libre

Zone libre — régulateur de distance

Python

Objectif : expérimenter sans conséquence. Prends un comportement du robot (clignotement, seuil d’alerte, séquence de feux, chiffrement), programme-le et teste-le sur des cas limites.

Le script proposé lit une série de distances et déciderait la vitesse du robot. Modifie les seuils, change les états, ou remplace tout le script par le comportement que tu veux vérifier.

Sur la carte, ce sera digitalWrite et des capteurs réels : la structure du programme — lire, décider, agir — reste exactement la même.

De la simulation à la carte

La simulation texte a une limite assumée : rien ne clignote vraiment. Elle a une force : toute la logique se vérifie sans matériel. Quand le programme affiche les bonnes décisions sur tes cas limites, le portage vers MicroPython est mécanique : print devient digitalWrite, la lecture d’une ligne devient la lecture d’un capteur, et la boucle principale tourne dans while True.

Les trois erreurs que l’atelier révèle immédiatement
  • Ordre des lectures inversé : le programme lit le relevé avant le seuil alors que l’énoncé fixe l’ordre.
  • Seuil large au lieu de strict : la valeur exactement au seuil change de camp et le compte d’alertes glisse.
  • Bilan dans la boucle : le total s’affiche à chaque passage au lieu d’une seule fois, après.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices Python corrigés automatiquement dans la page. Une fois l’atelier apprivoisé, ils sont la meilleure façon de vérifier que le comportement programmé est vraiment acquis.
