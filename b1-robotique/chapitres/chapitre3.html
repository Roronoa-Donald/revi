Chapitre 3 — Conditions et fonctions

Module 3 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Le robot doit distinguer : ce capteur est-il activé ? Ce relevé dépasse-t-il le seuil ? Cette valeur est-elle acceptable ? La décision se code avec des conditions — et dès qu’une décision mérite d’être réutilisée, elle sort du programme principal pour devenir une fonction qui renvoie True ou False. Le TP du club demandait une fonction is_even : c’est exactement ce chapitre.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. écrire une fonction de test qui renvoie un booléen sans rien afficher ;
  2. compter les deux branches d’une condition sur une série ;
  3. implémenter un test de primalité qui s’arrête à la racine carrée ;
  4. classer des relevés par seuil strict et compter les alertes.

1. Une fonction qui répond vrai ou faux

Une fonction de test a un contrat précis : recevoir une valeur, renvoyer un booléen, ne rien afficher. C’est le programme qui décide quoi faire de la réponse.

\n
def est_pair(x):
    return x % 2 == 0

est_pair(4)   → True
est_pair(7)   → False
\n

La comparaison x % 2 == 0 est déjà un booléen : pas besoin d’écrire if ... : return True else: return False. Un return direct est plus court et dit la même chose.

\n
Piège — la fonction qui bavarde

Une fonction de test qui print son verdict est à moitié inutilisable : on ne peut ni compter avec, ni la recombiner. Une fonction calcule et renvoie ; l’affichage appartient au programme principal. Cette séparation est ce qui permet de tester une fonction toute seule.

2. Compter les deux branches

Sur une série, la condition s’applique valeur par valeur, et les deux issues se comptent.

\n
pairs = impairs = 0
for x in valeurs:
    if est_pair(x):
        pairs += 1
    else:
        impairs += 1
\n

Chaque passage incrémente un seul compteur : la somme des deux vaut forcément n à la sortie. C’est un contrôle gratuit — si pairs + impairs ne vaut pas n, le programme a un bug ailleurs.

\n
Mnémotechnique — « Un test, deux destins »

Dans un if / else, exactement une branche s’exécute par passage. Si un compteur double ou saute, c’est que le test n’est pas exclusif : relire l’opérateur de comparaison avant de soupçonner la boucle.

3. Tester la primalité

Un nombre premier possède exactement deux diviseurs : 1 et lui-même. 0 et 1 ne sont donc pas premiers. Tester tous les diviseurs jusqu’à x serait du gaspillage : il suffit d’aller jusqu’à la racine carrée de x.

\n
def est_premier(x):
    if x < 2:
        return False
    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1
    return True
\n

Pourquoi s’arrêter à la racine ? Si x = a × b avec a ≤ b, alors a ≤ √x. Un diviseur au-delà de la racine en entraîne donc un plus petit déjà testé. Pour 97, on essaie 2 à 9 au lieu de 2 à 96.

\n
Attention aux cas de bord

0, 1 et les nombres négatifs tombent dans le premier test x < 2. Sans lui, la boucle while ne tournerait pas mais renverrait True pour 1 — un résultat faux. Les cas de bord se traitent d’abord, explicitement.

4. Classer des relevés par seuil

Le capteur de distance du TP déclenche une alerte sous 10 cm. Le classement par seuil est la décision la plus fréquente en robotique.

\n
if d < seuil:      alerte
else:              tout va bien
\n

Strictement inférieur se traduit par < : une distance égale au seuil n’alerte pas. Avec un <=, la frontière changerait de camp — et les tests le remarquent, car ils incluent toujours le cas de la valeur exactement au seuil.

\n
Trois états avec elif
if t > 30:
    etat = "ALERTE CHALEUR"
elif t < 15:
    etat = "ALERTE FROID"
else:
    etat = "normale"
\n

Les trois branches sont mutuellement exclusives : le premier test vrai gagne, les autres ne sont même pas évalués. L’ordre des tests fait partie de la logique.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

Exercice 1 — Pairs et impairs

Python Niveau 1 — Acquisition

Objectif : Écrire une fonction de test, l’appliquer à une série et compter les deux cas.

Le programme lit n, puis n entiers. Pour chacun il affiche X pair ou X impair. La dernière ligne donne les deux comptes : pairs : P / impairs : I. Le test s’écrit dans une fonction est_pair(x) qui renvoie un booléen.

Entrée du programme
5
7
2
8
9
4
Sortie attendue
7 impair
2 pair
8 pair
9 impair
4 pair
pairs : 3 / impairs : 2

Cinq verdicts, puis le bilan.

Deux indices, rédigés en mots
  1. Le reste d’une division par 2 décide : x % 2 vaut 0 exactement quand x est pair.
  2. Deux compteurs, initialisés avant la boucle ; chaque if en incrémente un seul.

Exercice 2 — Test de primalité

Python Niveau 2 — Application

Objectif : Écrire une fonction qui renvoie un booléen après une recherche de diviseur, puis la rejouer sur une série.

Le programme lit n, puis n entiers. Pour chacun il affiche X : premier ou X : compose. La décision se prend dans une fonction est_premier(x) : un nombre est premier s’il a exactement deux diviseurs ; 0 et 1 sont composés ici. Le test des diviseurs s’arrête à la racine carrée de x.

Entrée du programme
4
2
9
11
15
Sortie attendue
2 : premier
9 : compose
11 : premier
15 : compose

9 = 3 × 3 et 15 = 3 × 5 : composés.

Deux indices, rédigés en mots
  1. Traiter d’abord les cas x < 2, puis boucler d de 2 à int(x ** 0.5) inclus : si x % d vaut 0, ce n’est pas premier.
  2. La fonction ne doit rien afficher : elle renvoie True ou False, et c’est la boucle qui affiche.

Exercice 3 — Contrôle de seuil d’un capteur

Python Niveau 3 — Raisonnement

Objectif : Comparer chaque relevé à un seuil fixé, décider d’une alerte et compter les alertes.

Le capteur de distance renvoie des relevés. Le programme lit d’abord le seuil s (une ligne), puis n, puis n distances entières. Pour chaque relevé d il affiche d cm : ALERTE si d est strictement inférieur au seuil, sinon d cm : OK. La dernière ligne compte les alertes : alertes : A.

Entrée du programme
30
4
12
45
8
30
Sortie attendue
12 cm : ALERTE
45 cm : OK
8 cm : ALERTE
30 cm : OK
alertes : 2

30 cm atteint le seuil : pas d’alerte.

Deux indices, rédigés en mots
  1. L’ordre des lectures est imposé : le seuil arrive avant le compteur de relevés.
  2. « Strictement inférieur » se traduit par < : une distance égale au seuil n’alerte pas.

6. QCM — niveau examen

Que doit faire une fonction de test ?

Elle renvoie True ou False ; l’affichage appartient au programme.

Que vaut est_pair(0) avec return x % 2 == 0 ?

0 % 2 vaut 0, donc 0 == 0 est True : zéro est pair.

Pourquoi tester la primalité jusqu’à √x seulement ?

Si x = a × b avec a ≤ b, alors a ≤ √x : suffisant pour trouver un diviseur.

Que vaut est_premier(1) ?

1 n’a qu’un seul diviseur : il n’est pas premier, le test x < 2 le renvoie en False.

d = seuil avec le test d < seuil : y a-t-il alerte ?

Strictement inférieur : la valeur égale au seuil n’alerte pas.

Dans une chaîne if / elif / else, combien de branches s’exécutent ?

Le premier test vrai gagne ; les suivants sont ignorés.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Fonction qui affiche au lieu de renvoyer : impossible de compter avec son résultat.
  • if ... : return True, else : return False : verbeux, mais surtout signe qu’on n’a pas vu que la comparaison est déjà un booléen.
  • est_premier(1) mal géré : sans le test x < 2, 1 sortirait « premier ».
  • <= au lieu de < : la valeur au seuil change de camp et le compte d’alertes glisse.
  • elif transformé en if séparés : un relevé peut alors être classé deux fois.

8. Méthodologie de résolution

Décider puis compter
  1. Isoler le critère dans une fonction de test qui renvoie un booléen.
  2. Traiter les cas de bord au début de la fonction (0, 1, négatifs).
  3. Comparer au seuil avec le bon opérateur : strict ou large, l’énoncé le dit.
  4. Compter chaque branche avec un compteur dédié initialisé avant la boucle.
  5. Contrôler que la somme des comptes redonne l’effectif total.

9. Révision active

Résumé essentiel
  • Une fonction de test renvoie un booléen et n’affiche rien ; le programme principal décide.
  • La comparaison est déjà un booléen : return x % 2 == 0 suffit.
  • Premiers : x ≥ 2 et aucun diviseur jusqu’à √x ; 0 et 1 sont exclus d’entrée.
  • Strict ou large au seuil : la frontière change de camp, les tests la vérifient toujours.
  • if / elif / else : une seule branche par passage, la première vraie gagne.

Checklist de maîtrise

  • J’écris une fonction de test qui renvoie True ou False sans afficher.
  • Je gère les cas de bord avant la boucle de test.
  • Je classe des relevés par seuil strict et je compte chaque catégorie.
  • Je vérifie que mes comptes additionnés redonnent le total.
