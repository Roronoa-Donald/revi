Chapitre 6 — Capteurs, seuils et régulation

Mise en situation

Le robot est équipé : afficheur 7 segments pour compter, capteur de distance pour freiner, capteur de température pour alerter. Le matériel se branche en une heure ; le programme qui le pilote demande trois qualités : une table de correspondance claire, des seuils stricts assumés, un bilan qui résume la série. C’est le chapitre où tout le cours se combine.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. associer chaque chiffre à ses segments via un dictionnaire ;
  2. classer des relevés par seuils stricts avec trois états ;
  3. réafficher des nombres sans zéros inutiles ;
  4. agréger une série en minimum et moyenne entière.

1. L’afficheur 7 segments comme table

Sept segments nommés de a à g. Chaque chiffre allume un sous-ensemble : le 0 allume tout sauf g, le 1 seulement b et c, le 8 tout. La correspondance est une donnée, pas un calcul : un dictionnaire la pose une fois pour toutes.

segments = {
    0: "a b c d e f",
    1: "b c",
    2: "a b d e g",
    ...
    8: "a b c d e f g"
}
print(segments[chiffre])

Le programme principal se réduit alors à une lecture et un affichage : toute la complexité est dans la table, lisible et vérifiable chiffre par chiffre. C’est le même réflexe qu’en électronique, où la table de vérité précède le câblage.

Mnémotechnique — « Le dictionnaire est un câblage »

Écrire 7: "a b c" dans un dictionnaire, c’est brancher les segments a, b, c du chiffre 7. Une table de correspondance est plus sûre qu’un calcul : elle ne peut pas se tromper de formule, seulement d’entrée — et ça se voit d’un coup d’œil.

2. Trois états, deux seuils

La station météo du TP classe chaque relevé : alerte chaleur au-dessus de 30, alerte froid en dessous de 15, normal entre les deux. Trois états, deux seuils, une chaîne if / elif / else.

if t > 30:      "ALERTE CHALEUR"
elif t < 15:    "ALERTE FROID"
else:           "normale"

Les seuils sont stricts : 30 exactement est normal, 15 exactement est normal. Les tests vérifient toujours la frontière — le relevé égal au seuil est le cas qui trahit un >= écrit par distraction.

Piège — le relevé à la frontière

Un >= au lieu de > déplace tout le compte d’alertes : 30.0 basculerait en alerte. L’énoncé fixe la frontière ; le code la respecte au caractère près. Si l’énoncé dit « strictement supérieur », le test est >.

3. Afficher sans zéros inutiles

Un relevé de 30.0 doit s’afficher « 30 », un relevé de 12.5 garde sa décimale. Le format :g fait exactement cela : il supprime les zéros de fin.

f"{t:g} C : normale"      →   "30 C : normale"
f"{t:g} C : normale"      →   "12.5 C : normale"
f"{t:.2f} C : normale"    →   "30.00 C : normale"   (à éviter ici)

Les trois formats à connaître : :g nettoie, :.2f arrondit à deux décimales, :<12 aligne à gauche. Choisir le mauvais n’est pas une erreur de style : c’est une sortie différente, et les tests la refusent.

4. Le bilan : minimum et moyenne entière

Après le classement, le régulateur résume la série : le relevé le plus petit (le plus urgent) et la moyenne.

minimum = min(distances)
moyenne = sum(distances) // n        # division entière

print(f"minimum : {minimum}")
print(f"moyenne : {moyenne}")

La division entière // est imposée par l’énoncé : 135 / 6 vaut 22,5 mais 135 // 6 vaut 22. Le min() d’une liste non vide ne plante jamais ; c’est une liste vide qui le ferait — et l’énoncé garantit n ≥ 1.

Suivre le minimum dans la boucle

Deux écoles : min() après coup, ou une variable suivie dans la boucle (« si d est plus petit, il devient le nouveau minimum »). Les deux sont justes ; la seconde est ce qu’on écrit sur une carte qui traite les relevés au fil de l’eau, sans les retenir tous.

5. Études de cas & applications pratiques

Ces trois études de cas se réalisent directement dans la page. Complétez chaque grille d’analyse à partir des données du cas, puis lancez la validation pour vérifier vos réponses critère par critère.

La validation compare vos réponses aux attendus des cas affichés ; elle ne vérifie pas votre capacité à traiter toutes les situations.

En cas d’hésitation, le bouton Obtenir une aide formative générale fournit un conseil identique pour toutes les grilles, sans transmettre de réponse attendue ni utiliser le tuteur IA.

Exercice 1 — L'afficheur de zone du robot d'inventaire

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Lire une table de correspondance chiffre-segments d'un afficheur 7 segments et comparer des configurations.

Énoncé. Le robot d'inventaire affiche le numéro de la zone en cours sur un afficheur 7 segments. Les sept segments sont nommés de a à g ; la correspondance de chaque chiffre est posée une fois pour toutes dans la table du programme :

Chiffre0123456789
Segments allumésa b c d e fb ca b d e ga b c d gb c f ga c d f ga c d e f ga b ca b c d e f ga b c d f g
  1. Combien de segments s'allument pour afficher le chiffre 8 ?
  2. Combien de segments s'allument pour afficher le chiffre 1 ?
  3. Pour combien de chiffres de la table le segment g reste-t-il éteint ?
  4. L'afficheur reçoit la commande « b c f g » : quel chiffre s'affiche ?
  5. Combien de segments le chiffre 4 et le chiffre 1 ont-ils en commun ?
  6. Pour passer de l'affichage de 8 à celui de 0, combien de segments s'éteignent ?

Répondez par des nombres ou un chiffre.

Cas d’exemple
Un afficheur réduit ne connaît que les chiffres 0, 7 et 9.

1) La commande « a b c » affiche le chiffre 7.
2) Le chiffre 9 allume 6 segments (a b c d f g).
3) Le chiffre 0 allume tout sauf g, donc 6 segments.
Trois indices, rédigés en mots
  1. La table de correspondance est une donnée : lisez-la ligne par ligne plutôt que de recalculer.
  2. Pour les segments communs à deux chiffres, listez les segments de chacun et repérez ceux présents dans les deux listes.
  3. Comparez les configurations des deux chiffres concernés : le passage d'un affichage à l'autre éteint les segments présents dans le premier et absents du second.

Exercice 2 — La station météo du club

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Classer des relevés de température par seuils stricts en trois états et compter chaque catégorie.

Énoncé. La station météo du club, montée autour d'une carte, classe chaque relevé de température en trois états : ALERTE CHALEUR au-dessus de 30 degrés, ALERTE FROID en dessous de 15 degrés, normale entre les deux. Les seuils sont stricts :

if t > 30:
    etat = "ALERTE CHALEUR"
elif t < 15:
    etat = "ALERTE FROID"
else:
    etat = "normale"

Relevés de la journée (en degrés Celsius) :

Relevé12345678
Température3130221415283319
  1. Quel est l'état du relevé t = 31 ?
  2. Quel est l'état du relevé t = 15 ?
  3. Combien de relevés passent en ALERTE CHALEUR ?
  4. Combien de relevés passent en ALERTE FROID ?
  5. Combien de relevés restent normaux ?
  6. Quel format de f-string affiche 30.0 sans zéros inutiles (écrivez :g, :.2f ou :<12) ?

Répondez aux questions 1 et 2 par le nom exact de l'état, et aux autres par des nombres ou le format demandé.

Cas d’exemple
Relevés d'essai de la sonde : 34 — 29 — 12 — 16 — 26.

1) 34 dépasse 30 : ALERTE CHALEUR.
2) 12 passe sous 15 : ALERTE FROID.
3) 29, 16 et 26 restent normaux.
4) Bilan : 1 chaleur, 1 froid, 3 normales — total 5.
Trois indices, rédigés en mots
  1. Les seuils sont stricts : 30 exactement et 15 exactement restent dans la zone normale.
  2. Classez chaque relevé l'un après l'autre : dans la chaîne if / elif / else, le premier test vrai gagne et un seul état s'applique par relevé.
  3. Contrôle final : la somme des trois catégories doit redonner l'effectif de la journée ; pour l'affichage, rappelez-vous quel format nettoie les zéros de fin.

Exercice 3 — Le régulateur de distance de l'aspirateur

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Agréger une série de relevés de capteur : minimum, moyenne entière, comptage par seuil et décision d'un capteur analogique.

Énoncé. En fin de tournée, le régulateur du robot aspirateur résume ses six relevés de distance (en cm), relevés dans cet ordre : 45 — 18 — 32 — 27 — 18 — 50. Le robot freine dès qu'un relevé passe strictement sous 20 cm. Sur la même carte, le capteur de poussière déclenche le mode turbo quand sa lecture dépasse strictement 700 ; ce matin, il lit 720. Le bilan du régulateur :

minimum = min(distances)
moyenne = sum(distances) // n
  1. Quel est le plus petit relevé de la série ?
  2. Combien de fois ce minimum apparaît-il dans la série ?
  3. Quelle est la somme des six relevés ?
  4. Quelle est la moyenne entière (somme // 6) ?
  5. Combien de relevés déclenchent le freinage (d < 20) ?
  6. Le capteur de poussière lit 720, le seuil est 700 : le mode turbo se déclenche-t-il (oui ou non) ?

Répondez par des nombres, sauf la question 6.

Cas d’exemple
Une tournée de 3 relevés : 40 — 12 — 25 (seuil de freinage 15 cm).

1) Minimum : 12.
2) Somme : 40 + 12 + 25 = 77 ; moyenne entière : 77 // 3 = 25.
3) Freinage : seul 12 est strictement sous 15, soit 1 relevé.
Trois indices, rédigés en mots
  1. Le minimum se lit en parcourant la série ; la moyenne entière s'obtient par somme // effectif, jamais par une division décimale.
  2. Pour le freinage, seul compte le test d inférieur strict à 20 : classez chaque relevé en « strictement sous 20 » ou « 20 et plus ».
  3. Contrôles : la moyenne entière vérifie 6 × moyenne ≤ somme ; et le turbo se déclenche dès que la lecture dépasse strictement le seuil.

6. QCM — niveau examen

Quels segments s’allument pour le chiffre 8 ?

Le chiffre 8 allume les sept segments a b c d e f g ; sans le g on obtiendrait 0, et b c seul afficherait 1.

t = 30 exactement avec le test t > 30 : quel état ?

Seuil strict : 30 n’est pas strictement supérieur à 30, il reste normal.

Que vaut 135 // 6 ?

La division entière tronque : 22. Le reste serait 3.

Que produit f"{12.5:g}" ?

:g affiche sans zéros inutiles : la décimale utile reste.

Dans if / elif / else, le relevé 20 des seuils 30 et 15 tombe dans…

Ni > 30 ni < 15 : c’est le else qui le classe normal.

min() sur une liste vide…

Il n’y a pas de minimum à une liste vide : l’énoncé garantit n ≥ 1.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Table incomplète : un chiffre absent du dictionnaire lève KeyError à l’affichage.
  • Seuil large au lieu de strict : 30 exactement compte en alerte et le total glisse.
  • :.2f au lieu de :g : « 30.00 » s’affiche là où « 30 » est attendu.
  • Moyenne vraie au lieu d’entière : 22.5 affiché là où // donne 22.
  • min() sur liste vide : impossible ici (n ≥ 1), mais le réflexe de garde reste bon.

8. Méthodologie de résolution

Piloter un capteur en simulation
  1. Poser les données fixes dans une table (dictionnaire) plutôt qu’en calculs ad hoc.
  2. Fixer les seuils et leur strictesse tels que l’énoncé les écrit.
  3. Choisir le format d’affichage : :g pour nettoyer, :.2f pour arrondir, alignement pour les colonnes.
  4. Agréger après la boucle : min, max, somme, moyenne — jamais dans le classement.
  5. Rejouer les frontières : une valeur exactement au seuil, une sous le seuil, une au-dessus.

9. Révision active

Résumé essentiel
  • Une correspondance chiffre → segments est une donnée : le dictionnaire la pose, l’affichage la lit.
  • Trois états, deux seuils : if / elif / else, une seule branche par relevé.
  • Seuils stricts : 30 et 15 exactement restent dans la zone normale.
  • :g affiche sans zéros inutiles ; :.2f arrondit ; le choix du format change la sortie.
  • Bilan : min() pour l’extrême, // pour la moyenne entière imposée par l’énoncé.

Checklist de maîtrise

  • Je construis un dictionnaire de correspondance complet et je le lis proprement.
  • Je classe des relevés avec des seuils stricts en trois états.
  • J’affiche des nombres sans zéros inutiles au bon format.
  • Je produis un bilan minimum et moyenne entière corrects.

Comment vous auto-évaluer

< 50 % — Complétez la table 7 segments pour tous les chiffres de 0 à 9.
