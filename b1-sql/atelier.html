Atelier et simulateur SQL

Deux espaces SQLite dans votre navigateur : la zone libre et le simulateur démarrent sur le même parc_auto (12 marques, 23 voitures), sans partager leurs modifications.

Comment fonctionne l’atelier
  • Dans la zone libre, chaque exécution repart d’une copie du parc. Pour commencer sur une base vide, effacez le script de préparation dans « Entrée du programme ».
  • Le moteur SQL fonctionne dans le navigateur ; la disponibilité du tuteur dépend de la configuration du service.
  • Dans le simulateur ci-dessous, Ctrl + Entrée lance les requêtes localement et votre script est conservé dans ce navigateur.

Simulateur SQL

Une base parc_auto complète est déjà chargée dans cette page : 12 marques, 23 voitures, le jeu de données du support. Écrivez vos requêtes, exécutez-les d’un clic, lisez le résultat en tableau — un vrai moteur SQL tourne dans votre navigateur, rien n’est envoyé nulle part.

Comment fonctionne le simulateur
  • Exécuter (ou Ctrl + Entrée) lance tout ce qui est écrit dans l’éditeur, requête par requête, et affiche le résultat de la dernière.
  • Réinitialiser reconstruit la base parc_auto à l’état initial — après un UPDATE ou un DELETE trop large, c’est le bouton magique.
  • Historique garde vos requêtes de la session ; Exporter copie le résultat en CSV.
  • Le moteur est SQLite (WebAssembly) : les exemples signalés MySQL, notamment CREATE USER, GRANT et MODIFY COLUMN, ne s’y exécutent pas.
  • Votre script est conservé dans ce navigateur ; aucune donnée ne quitte votre machine.

Une requête interrompue après quatre secondes entraîne la réinitialisation de la base : les modifications précédentes sont perdues. Les résultats sont limités à 2 000 lignes par instruction et à environ 1 Mo au total ; les allocations gérées par SQLite sont limitées à 32 Mio.

Le jeu de données : parc_auto

Deux tables, fidèles au support :

  • Marque (codemarque, nommarque, paysmarque) : 12 lignes, de TOYOTA à MG.
  • Voiture (immat, marque, codemarque, moteur, datecirc, km, pxachat, nbreplace) : 23 lignes, moteurs DIESEL/ESSENCE/HYBRIDE/ELECTRIQUE, prix de 6 à 50 millions, dates de 2000 à 2023.

Les clés primaires Marque.codemarque et Voiture.immat sont non nulles. La clé étrangère composée de Voiture vérifie ensemble son code et son nom contre Marque(codemarque, nommarque). Dans Voiture, seule datecirc accepte NULL ; les prix du jeu initial sont des entiers en francs. SQLite applique ici des affinités de type : INTEGER et TEXT ne valident pas à eux seuls toutes les valeurs. Les clés étrangères sont activées à l’initialisation de la connexion SQLite. Après une modification, Réinitialiser la base revient à l’état initial.

Missions guidées

Huit missions progressives sont proposées sous le tableau. Écrivez d’abord votre requête dans le simulateur : les résultats sont comparés aux tableaux de référence sur la base initiale. Une correspondance aide à vérifier votre réponse sans prouver qu’elle fonctionne sur tous les jeux de données.

Démarche conseillée
  1. Lisez la question et formulez-la en français : quelles colonnes, quelles lignes, quel ordre ?
  2. Écrivez le squelette (SELECT…FROM…WHERE…) puis complétez la condition.
  3. Exécutez et comparez au résultat de référence affiché sous le simulateur.
  4. Corrigez : comparez les valeurs, les filtres et l’ordre demandé.
  5. Réinitialisez la base entre deux essais de mission qui modifient les données.
