Atelier de scripts & simulateur SQL

Deux machines dans une page : un éditeur Bash dont chaque script est réellement exécuté côté serveur, et un vrai moteur SQL — base parc_auto du support déjà chargée (12 marques, 23 voitures). La logique des requêtes se programme en Bash, les requêtes s’essaient en réel : rien à installer.

Comment fonctionne l’atelier
  • Valider vérifie la conformité de vos réponses dans la grille d’analyse.
  • Données du cas contient les paramètres soumis à l’étude.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l’éditeur ; votre code est conservé dans ce navigateur.

Zone libre

Zone libre — contrôleur de privilèges

Bash

Objectif : expérimenter sans conséquence. Prenez une règle du cours (filtre WHERE, jointure, GROUP BY, privilèges GRANT et REVOKE), programmez-la en Bash et testez-la sur des cas limites.

Le script proposé rejoue la matrice des privilèges du chapitre 6 : lecture, écriture, administration. Transforme-le : ajoute un rôle, refuse grant à l’écriture, journalise chaque refus, ou remplace tout le script par la règle SQL que vous voulez vérifier.

Dans le vrai SGBD, ces décisions vivent dans GRANT et REVOKE : la structure du script — lire, décider, rapporter — reste exactement la même.

Le simulateur SQL plus bas exécute les requêtes elles-mêmes : utilisez-le pour voir le résultat réel d’un SELECT.

Simulateur SQL

Une base parc_auto complète est déjà chargée dans cette page : 12 marques, 23 voitures, le jeu de données du support. Écrivez vos requêtes, exécutez-les d’un clic, lisez le résultat en tableau — un vrai moteur SQL tourne dans votre navigateur, rien n’est envoyé nulle part.

Comment fonctionne le simulateur
  • Exécuter (ou Ctrl + Entrée) lance tout ce qui est écrit dans l’éditeur, requête par requête, et affiche le résultat de la dernière.
  • Réinitialiser reconstruit la base parc_auto à l’état initial — après un UPDATE ou un DELETE trop large, c’est le bouton magique.
  • Historique garde vos requêtes de la session ; Exporter copie le résultat en CSV.
  • Le moteur est SQLite (WebAssembly) : toutes les requêtes du cours y fonctionnent. Les commandes d’administration (CREATE USER, GRANT) restent du papier.
  • Votre script est conservé dans ce navigateur ; aucune donnée ne quitte votre machine.

Le jeu de données : parc_auto

Deux tables, fidèles au support :

  • Marque (codemarque, nommarque, paysmarque) : 12 lignes, de TOYOTA à MG.
  • Voiture (immat, marque, moteur, datecirc, km, pxachat, nbreplace) : 23 lignes, moteurs DIESEL/ESSENCE/HYBRIDE/ELECTRIQUE, prix de 6 à 50 millions, dates de 2000 à 2023.

Le lien entre les deux est la colonne marque de Voiture, qui porte le nommarque — c’est elle qu’utilisent les jointures du chapitre 4. Après une modification, Réinitialiser la base revient à l’état initial.

Missions guidées

Huit missions, de la lecture simple à l’analyse groupée : la validation se fait dans le simulateur, en comparant votre résultat au résultat de référence — chaque mission note le nombre de lignes et la première ligne attendue.

Démarche conseillée
  1. Lisez la question et formulez-la en français : quelles colonnes, quelles lignes, quel ordre ?
  2. Écrivez le squelette (SELECT…FROM…WHERE…) puis complétez la condition.
  3. Exécutez et comparez au résultat de référence affiché sous le simulateur.
  4. Corrige : nombre de lignes différent ? La condition WHERE ou le GROUP BY est en cause.
  5. Réinitialise la base entre deux essais de mission qui modifient les données.
