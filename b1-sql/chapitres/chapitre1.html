Chapitre 1 — Bases de données et SGBD

Module 1 ≈ 2 h de travail Accès libre
Mise en situation

Le club gère un parc de voitures : immatriculations, marques, moteurs, prix d’achat. Dans un classeur, retrouver « toutes les diesels mises en circulation avant 2015 » demande une heure de feuilletage ; dans une base de données, une requête d’une seconde. Ce premier chapitre nomme précisément les objets avant de les manipuler : une base de données n’est pas un tas de fichiers, et un SGBD n’est pas un tableur.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. définir une base de données et la distinguer d’un simple ensemble de fichiers ;
  2. citer les fonctions d’une base de données et les types de bases ;
  3. expliquer le rôle d’un SGBD et en donner des exemples réels ;
  4. décrire le modèle relationnel : table, ligne, colonne, clé primaire et étrangère ;
  5. interroger une table avec SELECT, DISTINCT et ORDER BY.

1. Qu’est-ce qu’une base de données ?

Définition. Une base de données (BDD) est un ensemble d’informations organisé pour être accessible, géré et mis à jour facilement par ses utilisateurs. Dans une base relationnelle, elles sont présentées en tables, lignes et colonnes ; d’autres modèles organisent les données autrement.

Un SGBD fournit notamment des outils pour :

  • décrire les données et les rendre accessibles à plusieurs programmes ;
  • les interroger par le contenu : par exemple, retrouver les produits à moins de 100 francs.

Une base peut être locale (une machine, un utilisateur) ou répartie (machines distantes accessibles par le réseau). Selon le SGBD et sa configuration, plusieurs utilisateurs peuvent y accéder et leurs opérations concurrentes sont coordonnées.

Piège — l’abus de langage

Un tableur peut aussi organiser, filtrer et partager des données. Distinguez les données, leur format de stockage et le logiciel utilisé : un SGBD fournit des fonctions de gestion adaptées à la base et aux besoins du projet.

2. Fonctions et types de bases de données

La structure d’une base répond à des fonctions fondamentales :

  • stocker l’information de façon fiable et la restituer à l’identique ;
  • traiter de grands volumes (massification) et rapidement (optimisation) ;
  • sécuriser les accès : autorisations selon les utilisateurs ;
  • contrôler la qualité : cohérence par rapport à un modèle préétabli ;
  • partager les données entre applications et métiers, y compris en réseau.

Historiquement, trois familles se sont succédé :

TypePrincipe
Hiérarchiquearborescence : chaque enregistrement dépend d’un niveau supérieur
Réseaurelations multiples entre données, par liens ou pointeurs
Orientée objetsdonnées stockées sous forme d’objets avec leurs attributs

Le modèle dominant aujourd’hui — celui du cours — est le modèle relationnel : les données vivent dans des tables à lignes et colonnes, reliées entre elles par des valeurs partagées.

Mnémotechnique — « FIQSCP »

Retenir les six fonctions par ce qu’elles donnent à l’utilisateur : Fiable, Important (volumes), Quick (rapide), Sûr (sécurité), Cohérent (qualité), Partagé. Ces objectifs dépendent de l’outil et de sa configuration ; ils ne sont pas garantis automatiquement.

3. Le SGBD

La base de données est le contenu ; le SGBD (système de gestion de base de données) est le logiciel qui la gère. Il permet d’insérer, de modifier et de rechercher efficacement des données dans une grande masse d’informations partagée par de multiples utilisateurs.

Un SGBD peut gérer les accès concurrents selon ses mécanismes de transactions et de verrouillage. Il décrit aussi les données (types, formats, contraintes) et permet de les interroger ou modifier. Les capacités et limites varient selon les systèmes et leur configuration.

SGBDParticularité
MySQL / MariaDBtrès répandu pour le web, gratuit, c’est celui du support
PostgreSQLpuissant et conforme aux normes, très utilisé en entreprise
Oracle Databasehistorique des grandes organisations, commercial
SQL Serverl’offre de Microsoft, intégrée à ses écosystèmes
SQLiteembarqué, sans serveur — c’est le moteur du simulateur de ce cours

Tous parlent SQL (Structured Query Language), le langage standard de l’interrogation. La syntaxe et les comportements peuvent différer selon les dialectes et les SGBD ; les exercices de ce chapitre utilisent SQLite.

Base, SGBD, SQL : trois rôles

La base est le garde-meuble (les données rangées), le SGBD est le gardien (il range, contrôle, arbitre), SQL est la langue qu’on lui parle pour demander quelque chose. Confondre les trois est la faute de vocabulaire la plus pénalisée à l’examen.

4. Le modèle relationnel

Dans le modèle relationnel, les données vivent dans des tables (le terme officiel est « relation ») : chaque ligne est un enregistrement, chaque colonne un attribut. Le support l’illustre avec un parc automobile :

Marque — extrait
codemarque | nommarque     | paysmarque
TOY        | TOYOTA        | JAPON
BMW        | BMW           | ALLEMAGNE
BNZ        | MERCEDES BENZ | ALLEMAGNE

Voiture — extrait de lignes et de colonnes
immat      | marque        | codemarque | moteur  | pxachat
TG-7854-Z  | MERCEDES BENZ | BNZ        | DIESEL  | 6000000
TG-3733-AC | TOYOTA        | TOY        | HYBRIDE | 20000000
TG-5420-AL | BMW           | BMW        | ESSENCE | 50000000

Deux clés structurent le tout :

  • la clé primaire identifie sans ambiguïté chaque ligne : une immatriculation désigne exactement une voiture, jamais deux ;
  • la clé étrangère relie une table à une autre : dans Voiture, le couple (codemarque, marque) doit correspondre au couple (codemarque, nommarque) d’une ligne de Marque. Le code sert aussi aux jointures du chapitre 4.

Le nom est répété dans Voiture pour faciliter les premières requêtes ; la clé étrangère composée vérifie qu’il correspond bien au code. Le schéma complet est au chapitre 2.

Piège — valeur manquante ≠ valeur nulle

Une date de mise en circulation inconnue peut être notée NULL dans datecirc. Les 23 voitures initiales ont une date ; l’exemple concerne une nouvelle voiture. L’immatriculation, clé primaire déclarée NOT NULL, ne peut pas être absente. Ne remplacez pas une donnée inconnue par zéro ou une chaîne vide : ce sont des valeurs distinctes qui peuvent fausser les calculs.

5. Poser une première question à la base : SELECT

Une base de données ne sert à rien si l’on ne peut pas l’interroger. SQL le fait avec des requêtes ; la plus courante commence par SELECT (« sélectionner »). Les exercices de ce chapitre n’utilisent que quatre idées, que voici sur la table Marque du parc automobile (colonnes codemarque, nommarque, paysmarque).

  • Tout afficher : SELECT * FROM Marque; — l’étoile * signifie « toutes les colonnes », FROM indique dans quelle table lire.
  • Choisir des colonnes (on dit une projection) : SELECT nommarque, paysmarque FROM Marque; — seules ces deux colonnes apparaissent, dans cet ordre.
  • Supprimer les doublons : si deux voitures ont le même moteur, SELECT moteur FROM Voiture; répète la valeur ; SELECT DISTINCT moteur FROM Voiture; ne l’affiche qu’une fois : le parc possède quatre types de moteurs. Sans ORDER BY, leur ordre n’est pas garanti.
  • Trier : SELECT * FROM Marque ORDER BY nommarque ASC; — ASC classe par ordre croissant (A→Z), DESC par ordre décroissant.

Voici les trois premières des 12 lignes du dernier résultat :

codemarque | nommarque | paysmarque
BMW        | BMW       | ALLEMAGNE
HYU        | HYUNDAI   | COREE DU SUD
KIA        | KIA       | COREE DU SUD
…
Lire une requête comme une phrase

SELECT dit quoi afficher, FROM dit où le prendre, ORDER BY dit dans quel ordre. Le point-virgule termine la requête. Une requête SELECT sert à interroger les données. Dans ces exemples simples, elle ne les modifie pas. Les chapitres 3 et 4 reprennent ces mots-clés et y ajoutent le filtrage (WHERE) et les jointures.

7. QCM — niveau examen

Quel est le rôle d’une base de données ?

Une base organise des informations ; elle ne remplace pas le matériel ni ne rend les fichiers illisibles.

Que signifie SGBD ?

Le logiciel qui gère la base : insertion, modification, recherche, partage.

Une clé primaire sert à…

Identification unique ; relier deux tables est le rôle de la clé étrangère.

Quel modèle utilise des relations représentées ici par des tables ?

Le modèle relationnel décrit les données par des relations, présentées ici sous forme de tables.

Que représente NULL dans une colonne ?

NULL n’est ni 0 ni vide : c’est l’absence de valeur, une information en soi.

Que peut faire un SGBD adapté au partage multiutilisateur ?

Le SGBD peut coordonner les opérations selon son mécanisme de transactions et de verrouillage ; les deux autres propositions ne sont pas des règles générales.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Base et logiciel confondus : un tableur peut aussi filtrer des données ; comparez les besoins et les fonctions disponibles.
  • SGBD confondu avec la base : le SGBD est le logiciel, la base est le contenu.
  • NULL remplacé par 0 ou chaîne vide : les moyennes et les comptages deviennent faux.
  • Clé primaire multi-usage : un numéro de téléphone n’identifie pas une personne de façon sûre.
  • Clé étrangère sans correspondance : une voiture dont la marque n’existe pas dans Marque casse la cohérence.

9. Méthodologie de résolution

Décrire une base avant d’écrire une requête
  1. Identifier les tables : quels objets du monde réel (marques, voitures, élèves) ?
  2. Choisir les clés primaires : ce qui identifie une ligne sans ambiguïté.
  3. Déclarer les clés étrangères : quelles tables pointent vers lesquelles ?
  4. Documenter les colonnes : type, présence possible de NULL.
  5. Vérifier la cohérence : une clé étrangère renseignée possède-t-elle la correspondance requise ? Une valeur NULL peut être permise selon le schéma.

10. Révision active

Résumé essentiel
  • Une base de données est interrogeable par le contenu et décrite séparément de son utilisation.
  • Six fonctions : fiable, massif, rapide, sûr, cohérent, partagé.
  • Le SGBD est le logiciel qui gère la base ; MySQL, PostgreSQL, Oracle, SQL Server et SQLite en sont des exemples.
  • Modèle relationnel : tables, lignes, colonnes ; clé primaire pour identifier, clé étrangère pour relier.
  • NULL signifie l’absence d’information : jamais 0, jamais chaîne vide.
  • Une première requête : SELECT choisit les colonnes, FROM la table, DISTINCT retire les doublons, ORDER BY trie.

  • J’explique ce que NULL représente et pourquoi on ne le remplace jamais.
