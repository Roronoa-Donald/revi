Chapitre 2 — Types de données et création de tables

Module 2 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

La base du parc auto ne se remplit pas à la main : on la décrit d’abord. Chaque colonne reçoit un type — un entier, une chaîne, une date — et ce choix engage tout : la place en mémoire, les comparaisons possibles, les erreurs évitées. Déclarer « prix » en texte n’affiche pas d’erreur aujourd’hui, mais interdit toute moyenne demain.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. choisir le type adapté pour une colonne : numérique, chaîne, temporel ;
  2. distinguer CHAR et VARCHAR et savoir quand préférer l’un ;
  3. écrire une instruction CREATE TABLE complète avec clés ;
  4. insérer des lignes avec INSERT et comprendre le rôle de NULL.

1. Les types numériques

Pour les entiers, MySQL propose une gamme de tailles croissantes :

\n
TypePlage (signé)Usage typique
TINYINT−128 à 127un âge, un petit compteur
SMALLINT≈ −32 700 à 32 700une année, une quantité
MEDIUMINT≈ −8,4 M à 8,4 Mun identifiant interne
INT≈ −2,1 Md à 2,1 Mdun prix en francs, un kilométrage
BIGINT≈ ±9,2 × 10¹⁸des identifiants mondiaux, des horodatages
\n

Deux précisions du support : la notation INT(x) ne change pas la capacité de stockage, seulement l’affichage (avec ZEROFILL, elle complète de zéros). Pour les décimaux, on utilise DECIMAL(p, s) — précision p, s décimales — pour l’argent, et FLOAT/DOUBLE pour les mesures scientifiques.

\n
Piège — l’argent en FLOAT

FLOAT et DOUBLE arrondissent par nature : une somme de prix peut y perdre un franc. Pour toute valeur monétaire, le type exact est DECIMAL — c’est le seul qui calcule en décimal exact, comme un humain pose l’addition.

2. CHAR et VARCHAR

Les chaînes de longueur fixe ou variable s’écrivent avec un paramètre de taille :

\n
StockéCHAR(5)VARCHAR(5)
« OK »« OK    » (complété d’espaces)« OK » (tel quel)
Mémoiretoujours 5 caractèresle contenu + 1 octet de longueur
\n

CHAR(x) réserve toujours x caractères et complète les plus courts d’espaces : il convient quand la longueur est constante — un code de marque sur trois lettres, un code postal. VARCHAR(x) stocke jusqu’à x caractères, sans remplissage : c’est le choix par défaut pour un nom, une adresse, un immatriculé.

\n

Le support cite aussi les grands textes (TEXT) et les binaires (BLOB) pour les contenus longs — un commentaire, une image stockée en base.

\n
Mnémotechnique — « Fixe = CHAR, variable = VARCHAR »

Un code de pays à trois lettres naît et meurt à trois lettres : CHAR(3). Un nom de famille va de une lettre à vingt : VARCHAR(20). Se tromper ne casse rien, mais gaspille — et un CHAR qui complète d’espaces surprend les comparaisons.

3. Les types temporels

Cinq types pour le temps en MySQL :

\n
TypeContenuFormat littéral
DATEune date'AAAA-MM-JJ'
TIMEune heure'HH:MM:SS'
DATETIMEdate et heure'AAAA-MM-JJ HH:MM:SS'
TIMESTAMPdate et heure (fuseau géré)idem DATETIME
YEARune année'AAAA' ou AAAA
\n

Le format littéral n’est pas décoratif : '2014-11-21' est compris partout, mais '21/11/2014' est rejeté ou mal interprété selon le SGBD. On écrit toujours les dates en SQL année, mois, jour.

\n

Le parc auto du support utilise DATETIME pour la mise en circulation — d’où des valeurs comme '2000-01-21 08:00:00' — et des comparaisons directes sont possibles : WHERE datecirc < '2015-01-01'.

4. CREATE TABLE et INSERT

La description d’une table passe par CREATE TABLE : chaque colonne reçoit un nom, un type, et des contraintes optionnelles (NOT NULL, PRIMARY KEY).

\n
CREATE TABLE IF NOT EXISTS Voiture (
    immat     VARCHAR(10) PRIMARY KEY,
    marque    VARCHAR(20) NOT NULL,
    moteur    VARCHAR(10) NOT NULL,
    datecirc  DATETIME,
    km        INT DEFAULT 0,
    pxachat   INT NOT NULL,
    nbreplace TINYINT NOT NULL
);
\n

Les lignes arrivent ensuite par INSERT INTO, en nommant les colonnes renseignées — celles qui manquent reçoivent NULL ou leur valeur par défaut :

\n
INSERT INTO Voiture (immat, marque, moteur, datecirc, km, pxachat, nbreplace)
VALUES ('TG-3733-AC', 'TOYOTA', 'HYBRIDE', '2010-01-21 18:00:00', 0, 20000000, 7);

-- plusieurs lignes d’un coup :
INSERT INTO Marque (codemarque, nommarque, paysmarque) VALUES
('TOY', 'TOYOTA', 'JAPON'),
('BMW', 'BMW', 'ALLEMAGNE');
\n

Exercice 2 — INSERT : ligne conforme ou rejetée ?

Bash Niveau 2 — Application

Objectif : Décider si une insertion respecte les contraintes NOT NULL et PRIMARY KEY.

Le script lit n lignes « immat marque moteur km pxachat nbreplace ». Contraintes de Voiture : immat (clé primaire), marque et moteur (NOT NULL) obligatoires — la valeur - signifie absent ; km, pxachat et nbreplace, entiers. Règles de refus : clé primaire absente, marque ou moteur absent, valeur non numérique dans km/pxachat/nbreplace. Pour chaque ligne il affiche immat : inseree ou immat : rejetee (raison) avec raison = cle, obligatoire ou type (dans cet ordre de priorité), puis insertions : X/n.

2

Deux indices, rédigés en mots

6. QCM — niveau examen

Quel type choisir pour un prix en francs ?

DECIMAL calcule en décimal exact ; FLOAT arrondit et fausse l’argent.

INT(2) limite-t-il la valeur à deux chiffres ?

INT(x) ne change pas le stockage, seulement l’affichage éventuel avec ZEROFILL.

Un code de marque sur 3 lettres : quel type ?

Longueur constante : CHAR(3), qui réserve exactement la place.

Comment s’écrit le 21 novembre 2014 en littéral SQL ?

Toujours année, mois, jour : AAAA-MM-JJ.

Dans INSERT INTO … (colonnes) VALUES (…), les colonnes non citées reçoivent…

C’est le sens du nommage explicite des colonnes.

Que fait IF NOT EXISTS dans CREATE TABLE ?

L’instruction devient sans effet (et sans erreur) si la table existe déjà.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Argent en FLOAT/DOUBLE : arrondis invisibles qui faussent totaux et moyennes.
  • Dates en format local : '21/11/2014' n’est pas un littéral SQL valide.
  • CHAR confondu avec VARCHAR : les espaces de complément surprennent les comparaisons.
  • Clé primaire oubliée : deux voitures avec la même immatriculation deviennent possibles.
  • INSERT sans colonnes nommées : tout repose sur l’ordre des colonnes, fragile au moindre changement.

8. Méthodologie de résolution

Déclarer une table proprement
  1. Lister les colonnes et leur contenu réel (est-ce un nombre, un texte, une date ?).
  2. Choisir les types : DECIMAL pour l’argent, CHAR pour le fixe, VARCHAR pour le variable.
  3. Poser la clé primaire et les contraintes NOT NULL indispensables.
  4. Insérer des lignes de test en nommant toujours les colonnes.
  5. Vérifier avec SELECT * que la structure et les NULL sont conformes.

9. Révision active

Résumé essentiel
  • Entiers : TINYINT à BIGINT selon la plage ; INT(x) ne change que l’affichage.
  • L’argent se stocke en DECIMAL, jamais en FLOAT.
  • CHAR pour la longueur fixe (complétée d’espaces), VARCHAR pour la longueur variable.
  • Dates au format 'AAAA-MM-JJ' ; DATETIME ajoute l’heure.
  • CREATE TABLE décrit colonnes, types et clés ; INSERT nomme les colonnes renseignées.

Checklist de maîtrise

  • Je choisis un type numérique adapté et je justifie DECIMAL pour l’argent.
  • Je distingue CHAR et VARCHAR avec un exemple de chaque.
  • J’écris un CREATE TABLE complet avec clé primaire.
  • J’insère des lignes en nommant les colonnes et je prévois les NULL.
