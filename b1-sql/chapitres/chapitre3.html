Chapitre 3 — Interroger : SELECT, WHERE, tri et restrictions

Module 3 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

La base du parc est en place : 23 voitures, 12 marques. Reste à poser les questions — combien de diesels ? lesquelles avant 2015 ? quelles marques distinctes ? Toute question s’écrit avec le même squelette SELECT…FROM…WHERE, et l’ordre des clauses n’est pas négociable : le SGBD le lit dans un ordre fixe, et une clause mal placée est rejetée.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. écrire une requête SELECT simple, sur des colonnes précises ou avec * ;
  2. filtrer les lignes avec WHERE et les opérateurs de comparaison et LIKE ;
  3. éliminer les doublons avec DISTINCT ;
  4. trier avec ORDER BY et restreindre le nombre de résultats avec LIMIT.

1. SELECT : afficher et sélectionner

SELECT est la commande qui sélectionne — et aussi qui affiche. Elle fonctionne sans table :

SELECT 'Nous sommes au COLLEGE DE PARIS SUPERIEUR';
SELECT 45 + 40 AS Effectif;

Mais son usage réel passe par FROM :

SELECT nommarque, paysmarque   -- les colonnes voulues, dans l’ordre voulu
FROM Marque;

SELECT *                       -- toutes les colonnes
FROM Voiture;

Le mot-clé AS renomme une colonne du résultat — pas la table : SELECT pxachat AS prix affiche « prix » en tête de colonne. Un alias de lisibilité, sans effet sur les données.

Les commentaires en SQL
-- ce commentaire tient sur une ligne
/* celui-ci
   en tient plusieurs */

Les doubles tirets commentent jusqu’à la fin de ligne ; le support les utilise pour expliquer chaque requête — un réflexe à garder.

2. Filtrer avec WHERE

La clause WHERE restreint les lignes du résultat selon une condition :

SELECT * FROM Voiture WHERE moteur = 'DIESEL';
SELECT * FROM Voiture WHERE pxachat >= 20000000;
SELECT * FROM Voiture WHERE marque = 'TOYOTA' AND moteur = 'DIESEL';
SELECT * FROM Voiture WHERE moteur = 'DIESEL' OR moteur = 'HYBRIDE';
OpérateurSens
= <> (ou !=)égal, différent
< <= > >=comparaisons (numériques ou alphabétiques)
BETWEEN a AND bdans l’intervalle inclus
IN (…)appartient à une liste
LIKEmotif : % = n’importe quoi, _ = un caractère
IS NULL / IS NOT NULLabsence d’information

Deux pièges de la clause : les chaînes se quotent avec des apostrophes simples ('DIESEL', jamais "DIESEL" en MySQL strict), et la comparaison avec NULL se fait uniquement par IS NULL — = NULL ne renvoie jamais vrai.

Piège — les immatriculations en AK

« Toutes les voitures immatriculées en AK » s’écrit WHERE immat LIKE '%AK' : le % remplace n’importe quel préfixe. Écrire = '%AK' chercherait une immatriculation qui s’appellerait littéralement « %AK » — et ne trouverait rien.

3. Doublons et tris

« Quelles marques possédons-nous ? » : SELECT marque FROM Voiture renvoie autant de lignes TOYOTA que de Toyota dans le parc. Le mot-clé DISTINCT, placé juste après SELECT, élimine les doublons :

SELECT DISTINCT marque FROM Voiture;      -- 12 lignes, une par marque
SELECT COUNT(DISTINCT marque) FROM Voiture;   -- directement le nombre

Un doublon disparaît seulement si toute la ligne sélectionnée est identique à une autre : avec deux colonnes, DISTINCT agit sur le couple, pas colonne par colonne.

Le tri passe par ORDER BY, placé après FROM/WHERE :

SELECT immat, marque, datecirc FROM Voiture ORDER BY datecirc;
SELECT immat FROM Voiture ORDER BY immat DESC;      -- décroissant
SELECT * FROM Voiture ORDER BY marque, datecirc;    -- tri à deux niveaux

Le second exemple trie par marque puis, à l’intérieur de chaque marque, par date : c’est la lecture des tris multi-colonnes. Sans précision, l’ordre est croissant (ASC).

4. LIMIT : restreindre le nombre de lignes

Une requête peut ramener des milliers de lignes quand on n’en veut que cinq. La clause LIMIT borne le résultat :

SELECT immat, pxachat FROM Voiture
ORDER BY pxachat DESC
LIMIT 3;                    -- les 3 voitures les plus chères

SELECT * FROM Voiture LIMIT 5 OFFSET 10;   -- 5 lignes à partir de la 11e

L’ordre complet d’une requête de lecture se mémorise une fois pour toutes :

SELECT   colonnes
FROM     tables
WHERE    condition sur les lignes
GROUP BY regroupement        (chapitre 5)
HAVING   condition sur les groupes  (chapitre 5)
ORDER BY tri
LIMIT    nombre de lignes
Mnémotechnique — « SFWGHOL »

La séquence Select From Where Group Having Order Limit se lit comme un mot. Les clauses sont optionnelles, leur ordre ne l’est jamais : un ORDER BY avant le WHERE est une erreur de syntaxe.

Exercice 1 — Filtrer les lignes avec WHERE

SQL Niveau 1 — Acquisition

Objectif : Sélectionner les enregistrements vérifiant une condition numérique avec WHERE.

La table notes(etudiant, matiere, note) contient les résultats du semestre. Écrivez une requête SQL affichant etudiant et note pour les lignes où note >= 12, triées par note décroissante puis etudiant croissant.

Entrée du programme
CREATE TABLE notes (etudiant TEXT, matiere TEXT, note INT); INSERT INTO notes VALUES ('Amina', 'SQL', 16), ('Koffi', 'SQL', 9), ('Yao', 'SQL', 14);
-- exemple
Sortie attendue
+----------+------+
| etudiant | note |
+----------+------+
| Amina    | 16   |
| Yao      | 14   |
+----------+------+
(2 lignes retournées)

Résultat de la requête SQL sur la base d’exemple.

Deux indices, rédigés en mots
  1. Ajoutez la clause WHERE note >= 12 après FROM notes.
  2. Triez avec ORDER BY note DESC, etudiant ASC.

Exercice 2 — Recherche par motif avec LIKE et intervalle BETWEEN

SQL Niveau 2 — Application

Objectif : Combiner les opérateurs BETWEEN et LIKE dans une clause WHERE.

Dans la table produits(id, nom, prix), sélectionnez nom et prix des produits dont le prix est compris entre 1000 et 50000 inclus (BETWEEN 1000 AND 50000) et dont le nom commence par 'Cable' (LIKE 'Cable%'), triés par prix croissant.

Entrée du programme
CREATE TABLE produits (id INT, nom TEXT, prix INT); INSERT INTO produits VALUES (1, 'Cable RJ45', 2500), (2, 'Cable HDMI', 5000), (3, 'Switch Pro', 15000), (4, 'Cable Fibre Bobine', 85000);
-- exemple
Sortie attendue
+------------+------+
| nom        | prix |
+------------+------+
| Cable RJ45 | 2500 |
| Cable HDMI | 5000 |
+------------+------+
(2 lignes retournées)

Résultat de la requête SQL sur la base d’exemple.

Deux indices, rédigés en mots
  1. Utilisez WHERE prix BETWEEN 1000 AND 50000 AND nom LIKE 'Cable%'.
  2. Terminez par ORDER BY prix ASC;

Exercice 3 — Valeurs absentes IS NULL et pagination LIMIT

SQL Niveau 3 — Raisonnement

Objectif : Identifier les enregistrements dont une colonne vaut NULL avec IS NULL.

Dans la table livraisons(id_commande, client, date_livraison), les commandes non encore livrées ont date_livraison à NULL. Affichez id_commande et client des commandes non livrées, triées par id_commande croissant.

Entrée du programme
CREATE TABLE livraisons (id_commande INT, client TEXT, date_livraison TEXT); INSERT INTO livraisons VALUES (101, 'Amina', '2026-03-01'), (102, 'Koffi', NULL), (103, 'Yao', NULL);
-- exemple
Sortie attendue
+-------------+--------+
| id_commande | client |
+-------------+--------+
| 102         | Koffi  |
| 103         | Yao    |
+-------------+--------+
(2 lignes retournées)

Résultat de la requête SQL sur la base d’exemple.

Deux indices, rédigés en mots
  1. En SQL, on teste l’absence de valeur avec IS NULL (et jamais avec = NULL).
  2. Ajoutez ORDER BY id_commande ASC.

6. QCM — niveau examen

Que fait SELECT DISTINCT marque FROM Voiture ?

DISTINCT élimine les lignes dupliquées du résultat.

Comment tester une valeur NULL dans WHERE ?

= NULL ne renvoie jamais vrai : seule la forme IS NULL fonctionne.

Dans LIKE '%AK', que remplace % ?

% = toute suite (même vide) ; _ remplace exactement un caractère.

ORDER BY marque, datecirc trie…

Les tris multi-colonnes s’appliquent de gauche à droite, par niveaux.

Où place-t-on LIMIT dans une requête ?

LIMIT clôt la requête : SELECT FROM WHERE (GROUP HAVING) ORDER LIMIT.

Comment quotent-on une chaîne en SQL ?

Apostrophes simples pour les valeurs textuelles.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Clause ORDER BY placée avant WHERE : l’ordre des clauses est imposé.
  • = NULL au lieu de IS NULL : le filtre ne renvoie rien, sans message d’erreur.
  • = '%AK' au lieu de LIKE '%AK' : le motif n’est interprété qu’avec LIKE.
  • DISTINCT espéré colonne par colonne : il agit sur la ligne entière sélectionnée.
  • Guillemets doubles autour des chaînes : selon le SGBD et le mode, c’est rejeté ou ambigu.

8. Méthodologie de résolution

Construire une requête de lecture
  1. Formuler la question en français : quelles colonnes, sur quelles lignes, dans quel ordre ?
  2. Écrire le squelette SELECT…FROM… dans l’ordre fixe des clauses.
  3. Filtrer avec WHERE, en citant les chaînes et en testant NULL avec IS NULL.
  4. Trier et borner avec ORDER BY puis LIMIT si la question demande un classement.
  5. Contrôler le résultat : nombre de lignes plausible, valeurs extrêmes cohérentes.

9. Révision active

Résumé essentiel
  • SELECT affiche (constant, calcul) et sélectionne (FROM), AS renomme une colonne du résultat.
  • WHERE filtre : comparaisons, AND/OR, BETWEEN, IN, LIKE avec % et _, IS NULL pour les absences.
  • DISTINCT élimine les doublons sur la ligne complète sélectionnée.
  • ORDER BY trie (ASC par défaut, DESC décroissant) par niveaux de gauche à droite.
  • LIMIT borne le nombre de lignes, OFFSET décale le départ ; l’ordre des clauses est fixe.

Checklist de maîtrise

  • J’écris une requête filtrée avec les bons opérateurs et les chaînes quotées.
  • J’élimine les doublons sur la bonne colonne (ou le bon couple).
  • Je trie sur deux colonnes et j’explique la hiérarchie.
  • Je place LIMIT et OFFSET conformément à l’ordre fixe des clauses.
