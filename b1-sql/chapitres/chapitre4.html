Chapitre 4 — Jointures : relier les tables

Module 4 ≈ 2 h 30 de travail Réservé B1 et plus
Mise en situation

Les marques vivent dans une table, les voitures dans une autre — et la question « combien de voitures japonaises dans le parc ? » traverse les deux. La jointure est l’opération qui combine leurs lignes autour de leur point de passage : le code de marque. Une fois le principe vu, les questions à deux tables ne coûtent pas plus cher que les autres.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. expliquer ce que produit une jointure : un résultat combinant les lignes ;
  2. écrire une jointure interne avec JOIN…ON et sans JOIN (virgules + WHERE) ;
  3. choisir entre INNER JOIN et LEFT JOIN selon la question ;
  4. utiliser des alias de tables pour écrire des requêtes lisibles.

1. Le principe : combiner les lignes

Une jointure combine les lignes de deux tables dans le résultat d’une requête, sans modifier les tables d’origine. Pour une jointure interne avec condition, imaginez toutes les combinaisons, puis gardez celles qui satisfont la condition. Le SGBD peut les calculer autrement.

Marque (un extrait)          Voiture (un extrait)
codemarque  nommarque        immat       codemarque
TOY         TOYOTA           TG-3733-AC  TOY
BMW         BMW              TG-5420-AL  BMW
REN         RENAULT          TG-2222-BC  REN

jointure sur Marque.codemarque = Voiture.codemarque
→ TG-3733-AC  TOYOTA   TOYOTA   JAPON
→ TG-5420-AL  BMW      BMW      ALLEMAGNE
→ TG-2222-BC  RENAULT  RENAULT  FRANCE

La condition de jointure se repère dans le schéma : quelle colonne d’une table désigne la même réalité qu’une colonne de l’autre ? Ici les deux colonnes codemarque désignent la même marque. La clé étrangère composée contrôle aussi la cohérence du nom.

Mnémotechnique — « Le pont a deux rives »

Pour relier les lignes correspondantes, vérifiez la condition : elle peut s’écrire avec ON, USING ou, pour une jointure interne, dans WHERE. Un produit cartésien associe volontairement chaque ligne à toutes les autres ; il est valide, mais souvent involontaire.

2. Jointure sans JOIN, puis INNER JOIN

La forme historique liste les tables séparées par des virgules et met la condition dans le WHERE :

SELECT V.immat, M.nommarque, M.paysmarque
FROM Voiture V, Marque M
WHERE V.codemarque = M.codemarque;

La forme moderne — celle du support et des normes — passe par JOIN…ON :

SELECT V.immat, M.nommarque, M.paysmarque
FROM Voiture V
INNER JOIN Marque M ON V.codemarque = M.codemarque;

-- les clauses habituelles restent en place :
SELECT V.immat, V.marque
FROM Voiture V
INNER JOIN Marque M ON V.codemarque = M.codemarque
WHERE M.paysmarque = 'JAPON'
ORDER BY V.immat;

INNER est facultatif — JOIN seul signifie déjà jointure interne. La jointure interne ne retient que les lignes ayant une correspondance des deux côtés : une marque sans voiture du parc disparaît du résultat.

Lorsque les deux tables portent le même nom de colonne, SQLite accepte aussi USING (codemarque). NATURAL JOIN utilise automatiquement tous les noms de colonnes communs : ici, seul codemarque est commun. Ajouter une colonne de même nom aux deux tables peut donc changer le résultat.

SELECT V.immat, M.nommarque
FROM Voiture V JOIN Marque M USING (codemarque)
ORDER BY V.immat LIMIT 3;
SELECT COUNT(*) AS voitures FROM Voiture NATURAL JOIN Marque;
SELECT COUNT(*) AS combinaisons FROM Voiture CROSS JOIN Marque;

Dans la base initiale, NATURAL JOIN donne 23 correspondances ; CROSS JOIN, sans condition ici, produit 23 × 12 = 276 combinaisons.

SELECT COUNT(*) FROM Voiture V CROSS JOIN Marque M ON V.codemarque = M.codemarque;

SQLite accepte aussi une condition ON ou USING sur CROSS JOIN : cette extension non portable ne conserve que les combinaisons correspondantes (23 ici). Pour obtenir un produit cartésien, écrivez CROSS JOIN sans condition.

Pourquoi la jointure interne « perd » des lignes

Si une marque n’a aucune voiture, aucune ligne de Voiture ne correspond : la ligne conjuguée n’existe pas, la marque disparaît. Ce n’est pas un bug — c’est la définition. Pour garder les marques sans voiture, il faut la jointure externe de la section suivante.

3. LEFT JOIN : garder la table de gauche

« Combien de voitures par marque ? » avec un INNER JOIN omettrait les marques sans voiture. La jointure externe gauche garde toutes les lignes de la table de gauche, complétées de NULL quand la droite manque :

SELECT M.nommarque, COUNT(V.immat) AS nb
FROM Marque M
LEFT JOIN Voiture V ON V.codemarque = M.codemarque
GROUP BY M.nommarque
ORDER BY nb DESC, M.nommarque;

Le détail qui compte : compter V.immat et non *. Pour une marque sans voiture, V.immat vaut NULL et n’est pas compté — le total est juste (0), là où COUNT(*) compterait 1 (la ligne conjuguée à NULL existe dans la jointure). Dans la base initiale, les 12 marques ont au moins une voiture : ajoutez une marque fictive sans voiture pour observer un zéro, puis réinitialisez la base.

TypeLignes retenues
INNER JOINuniquement les correspondances des deux côtés
LEFT JOINtoutes les lignes de gauche, NULL à droite si absence
RIGHT JOINsymétrique : toutes les lignes de droite

4. Relier plusieurs voitures et équipements

Une voiture peut avoir plusieurs équipements, et un même équipement peut équiper plusieurs voitures. La table VoitureEquipement enregistre chaque association par l’immatriculation et le code de l’équipement. Sa clé primaire composée interdit deux fois la même association ; ses deux clés étrangères désignent des lignes existantes.

SELECT V.immat, E.nomequipement
FROM Voiture V
INNER JOIN VoitureEquipement VE ON VE.immat = V.immat
INNER JOIN Equipement E ON E.codeequipement = VE.codeequipement
ORDER BY V.immat, E.nomequipement;

La première jointure retrouve les associations de chaque voiture ; la seconde retrouve le nom de chaque équipement. Dans ce parc fictif, supprimer une voiture ou un équipement supprime aussi ses associations grâce à ON DELETE CASCADE.

5. Les alias de tables

Écrire Marque.nommarque à chaque colonne fatigue vite. L’alias renomme la table le temps de la requête :

SELECT M.codemarque, M.nommarque, V.immat
FROM Marque M
INNER JOIN Voiture V ON M.codemarque = V.codemarque
WHERE V.immat LIKE '%AK';

Trois règles : l’alias se déclare dans le FROM (M, V), il remplace le nom de table partout dans la requête, et une fois aliasée la table ne peut plus être désignée par son nom complet. Le support l’écrit : les alias « permettent notamment de renommer les tables, et ainsi d’écrire moins de code ».

Piège — les colonnes ambiguës

Quand deux tables jointes portent une colonne de même nom (ici codemarque dans Marque et Voiture), écrire la colonne sans préfixe est une erreur : « ambiguous column ». Toujours préfixer par l’alias : M.codemarque, V.codemarque.

7. QCM — niveau examen

Que produit une jointure interne avec condition ?

La requête produit un résultat sans modifier les tables ; le moteur ne crée pas nécessairement une table temporaire.

Que retient une jointure interne ?

Sans correspondance, la ligne conjuguée n’existe pas.

Quelle jointure garde les marques sans voiture ?

LEFT JOIN garde toute la table de gauche, complétée de NULL.

Dans une LEFT JOIN, pourquoi COUNT(V.immat) plutôt que COUNT(*) ?

COUNT(colonne) ne compte que les non-NULL ; COUNT(*) compterait la ligne conjuguée.

Que vaut l’erreur « ambiguous column » ?

Il faut préfixer par l’alias : M.codemarque ou V.codemarque.

Une table aliasée en M peut encore s’écrire Marque dans la même requête ?

Une fois déclarée, seule la forme aliasée est valide.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Condition de jointure oubliée : produit cartésien, valide mais souvent non souhaité.
  • INNER JOIN quand la question demande les absents : les marques sans voiture disparaissent.
  • COUNT(*) sur une LEFT JOIN : les lignes conjuguées à NULL sont comptées à tort.
  • Colonnes non préfixées : « ambiguous column » dès que deux tables partagent un nom.
  • Alias déclarés mais non utilisés : la requête mélange les deux formes et se casse.

9. Méthodologie de résolution

Écrire une jointure
  1. Identifier le point de passage : quelle colonne désigne la même réalité des deux côtés ?
  2. Choisir la table de départ (FROM) selon ce qu’on ne veut jamais perdre.
  3. Écrire JOIN…ON avec la condition exacte, préfixée par les alias.
  4. Compléter WHERE, ORDER BY, LIMIT dans l’ordre fixe.
  5. Contrôler : le nombre de lignes correspond-il à la question (toutes, ou seulement les appariées) ?

10. Révision active

Résumé essentiel
  • Une jointure combine les lignes ; ON, USING et NATURAL sont des formes possibles, CROSS JOIN produit ici toutes les combinaisons.
  • INNER JOIN : correspondances des deux côtés ; LEFT JOIN : toute la table de gauche, NULL à droite.
  • COUNT(colonne) ignore les NULL : c’est lui qu’on compte sur une LEFT JOIN.
  • Les alias (M, V) raccourcissent la requête et remplacent le nom de table partout.
  • Deux tables jointes qui partagent un nom de colonne : toujours préfixer, sinon ambiguïté.

Checklist de maîtrise

  • J’écris une INNER JOIN avec la bonne condition ON.
  • Je choisis LEFT JOIN quand la question porte sur « même sans ».
  • Je compte avec COUNT(colonne) sur les jointures externes.
  • Je préfixe toutes les colonnes ambiguës par leurs alias.
