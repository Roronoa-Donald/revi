Chapitre 5 — Agrégation : compter, regrouper, filtrer les groupes

Module 5 ≈ 3 h de travail Réservé B1 et plus
Mise en situation

« Combien de voitures par marque ? Quel budget total du parc ? Quelle marque domine ? » — aucune de ces réponses n’est une ligne de la table : ce sont des calculs sur des groupes de lignes. Les fonctions d’agrégation réduisent des colonnes à une valeur, et GROUP BY découpe la table en groupes avant le calcul. C’est le cœur de l’analyse de données en SQL.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. calculer des totaux avec COUNT, MIN, MAX, SUM et AVG ;
  2. distinguer COUNT(*), COUNT(colonne) et COUNT(DISTINCT colonne) ;
  3. regrouper les lignes avec GROUP BY et lire le résultat ;
  4. filtrer les groupes avec HAVING, et le placer après WHERE.

1. Les cinq fonctions d’agrégation

Une fonction d’agrégation agit sur une colonne et renvoie une seule valeur pour toutes les lignes sélectionnées :

FonctionRésultatExemple sur le parc
COUNT(*)nombre de lignes23 voitures
COUNT(colonne)lignes où la colonne n’est pas NULLimmatriculées : 23
MIN / MAXplus petite / plus grande valeurprix de 6 M à 50 M
SUMsomme des valeursbudget total : 613,8 M
AVGmoyenne des valeurskilométrage moyen : 1 840,65

MIN et MAX ne sont pas réservés aux nombres : sur des chaînes ils renvoient la première et la dernière dans l’ordre alphabétique, sur des dates la plus ancienne et la plus récente — MIN(immat), MAX(datecirc) sont des requêtes légales.

Piège — COUNT(*) vs COUNT(colonne)

COUNT(*) compte toutes les lignes ; COUNT(colonne) saute celles où la colonne vaut NULL. Sur le support : « 25 voitures immatriculées sur 34 » — les 9 sans immatriculation existent dans COUNT(*) et disparaissent de COUNT(immat). Choisir l’un ou l’autre, c’est répondre à deux questions différentes.

2. GROUP BY : calculer par groupe

Pour savoir combien de Toyota, de BMW, de Kia en une seule requête, on regroupe les lignes par marque : GROUP BY réaménage le résultat en groupes où la colonne de regroupement a la même valeur, et l’agrégat se calcule pour chaque groupe.

SELECT marque, COUNT(*) AS nb
FROM Voiture
GROUP BY marque;

-- avec un filtre sur les lignes, avant le regroupement :
SELECT moteur, COUNT(*), AVG(pxachat)
FROM Voiture
WHERE marque = 'TOYOTA'
GROUP BY moteur;

Lecture du premier exemple : une ligne par marque présente dans le parc, avec son effectif — et rien d’autre. C’est la règle qui surprend : toute colonne du SELECT doit être dans le GROUP BY ou dans un agrégat. SELECT marque, immat … GROUP BY marque est rejeté : quelle immatriculation choisir pour le groupe ?

Mnémotechnique — « GROUP BY découpe, l’agrégat résume »

Chaque groupe devient une ligne du résultat. Si le résultat paraît étrange (trop de lignes, valeurs incohérentes), vérifier deux choses : la colonne de regroupement est-elle la bonne ? Chaque colonne affichée est-elle regroupée ou agrégée ?

3. HAVING : filtrer les groupes

« Quelles marques ont plus de deux voitures ? » : la condition porte sur le résultat du regroupement, pas sur les lignes. C’est le rôle de HAVING — l’équivalent de WHERE appliqué aux groupes :

SELECT marque, COUNT(*) AS nb
FROM Voiture
GROUP BY marque
HAVING COUNT(*) > 2;

-- WHERE filtre les lignes AVANT le regroupement,
-- HAVING filtre les groupes APRÈS :
SELECT moteur, COUNT(*)
FROM Voiture
WHERE marque = 'TOYOTA'
GROUP BY moteur
HAVING COUNT(*) >= 1;

HAVING ne peut exister qu’après un GROUP BY, et son critère porte sur une fonction d’agrégation. La séquence d’exécution du SGBD l’explique : lignes filtrées (WHERE), puis regroupées (GROUP BY), puis groupes filtrés (HAVING), puis tri (ORDER BY).

WHERE ou HAVING : la question à se poser

« Seulement les diesels » parle des lignes : WHERE. « Seulement les marques avec au moins 3 voitures » parle des groupes : HAVING. Une condition qui contient un agrégat (COUNT, AVG…) ne peut jamais vivre dans WHERE.

4. L’ordre complet, une dernière fois

Toutes les clauses du cours se combinent dans cet ordre — qui est aussi l’ordre d’exécution du SGBD :

SELECT   colonnes, agrégats
FROM     tables (jointures éventuelles)
WHERE    filtre les LIGNES
GROUP BY découpe en GROUPES
HAVING   filtre les GROUPES
ORDER BY trie le résultat
LIMIT    borne le nombre de lignes

Exemple récapitulatif du parc : « les deux moteurs les plus répandus parmi les voitures de moins de 30 millions, avec leur prix moyen » :

SELECT moteur, COUNT(*) AS nb, AVG(pxachat) AS prix_moyen
FROM Voiture
WHERE pxachat < 30000000
GROUP BY moteur
ORDER BY nb DESC
LIMIT 2;

Étude de cas Niveau 1 — Acquisition

Objectif : Associer chaque agrégat à son rôle.

Deux indices, rédigés en mots
  1. La clause GROUP BY regroupe les enregistrements partageant la même modalité.
  2. La clause HAVING filtre les groupes formés en évaluant une condition sur une fonction d’agrégation (SUM, AVG, COUNT).

6. QCM — niveau examen

Que renvoie une fonction d’agrégation ?

Elle résume une colonne : une valeur totale, ou une par groupe avec GROUP BY.

COUNT(immat) sur 34 lignes dont 9 immat NULL vaut…

COUNT(colonne) ignore les NULL : 34 − 9 = 25.

Que compte COUNT(DISTINCT marque) ?

DISTINCT élimine les doublons avant le comptage.

Dans SELECT marque, immat … GROUP BY marque, que se passe-t-il ?

Toute colonne du SELECT doit être dans le GROUP BY ou agrégée.

HAVING filtre…

WHERE filtre les lignes, HAVING filtre les groupes.

Une condition avec COUNT(*) peut-elle vivre dans WHERE ?

Les agrégats ne sont calculés qu’au regroupement : HAVING uniquement.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Colonne affichée hors GROUP BY : erreur immédiate du SGBD.
  • HAVING sans GROUP BY : la clause est rejetée.
  • COUNT(*) à la place de COUNT(colonne) : les NULL sont comptés à tort.
  • Filtre de groupe mis dans WHERE : « HAVING COUNT(*) > 2 » ne s’écrit pas « WHERE COUNT(*) > 2 ».
  • AVG sur une colonne textuelle : résultat sans sens — la moyenne d’un prix, oui ; d’une immatriculation, non.

8. Méthodologie de résolution

Analyser une table par groupes
  1. Traduire la question : quelle unité de compte (par marque, par moteur, par pays) ?
  2. Choisir l’agrégat : combien (COUNT), extrêmes (MIN/MAX), total (SUM), moyenne (AVG).
  3. Regrouper sur la colonne d’unité et n’afficher que regroupé ou agrégé.
  4. Filtrer au bon endroit : lignes dans WHERE, groupes dans HAVING.
  5. Présenter avec ORDER BY et LIMIT, puis contrôler les effectifs sur un cas connu.

9. Révision active

Résumé essentiel
  • Cinq agrégats : COUNT, MIN, MAX, SUM, AVG — une valeur par table ou par groupe.
  • COUNT(*) compte les lignes ; COUNT(colonne) ignore les NULL ; COUNT(DISTINCT …) dédoublonne.
  • GROUP BY découpe en groupes ; toute colonne affichée y figure ou est agrégée.
  • HAVING filtre les groupes (condition avec agrégat) ; WHERE filtre les lignes avant.
  • Ordre d’exécution : FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT.

Checklist de maîtrise

  • Je choisis le bon agrégat pour une question donnée.
  • Je distingue COUNT(*), COUNT(colonne) et COUNT(DISTINCT colonne).
  • J’écris un GROUP BY complet sans colonne hors regroupement.
  • Je place WHERE et HAVING conformément à ce qu’ils filtrent.
