Chapitre 5 — Agrégation : compter, regrouper, filtrer les groupes

Module 5 ≈ 3 h de travail Réservé B1 et plus
Mise en situation

« Combien de voitures par marque ? Quel budget total du parc ? Quelle marque domine ? » — aucune de ces réponses n’est une ligne de la table : ce sont des calculs sur des groupes de lignes. Les fonctions d’agrégation réduisent des colonnes à une valeur, et GROUP BY découpe la table en groupes avant le calcul. C’est le cœur de l’analyse de données en SQL.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. calculer des totaux avec COUNT, MIN, MAX, SUM et AVG ;
  2. distinguer COUNT(*), COUNT(colonne) et COUNT(DISTINCT colonne) ;
  3. regrouper les lignes avec GROUP BY et lire le résultat ;
  4. filtrer les groupes avec HAVING, et le placer après WHERE.

1. Les cinq fonctions d’agrégation

Une fonction d’agrégation agit sur une colonne et renvoie une seule valeur pour toutes les lignes sélectionnées :

FonctionRésultatExemple sur le parc
COUNT(*)nombre de lignes23 voitures
COUNT(colonne)lignes où la colonne n’est pas NULLdates connues : 23
MIN / MAXplus petite / plus grande valeurprix de 6 M à 50 M
SUMsomme des valeursbudget total : 613,8 M
AVGmoyenne des valeurskilométrage moyen : 1 840,65

MIN et MAX ne sont pas réservés aux nombres : sur des chaînes ils renvoient la première et la dernière dans l’ordre alphabétique, sur des dates la plus ancienne et la plus récente — SELECT MIN(immat), MAX(datecirc) FROM Voiture; est une requête légale.

Piège — COUNT(*) vs COUNT(colonne)

COUNT(*) compte toutes les lignes ; COUNT(colonne) saute celles où la colonne vaut NULL. Si, dans un autre jeu de 34 voitures, 9 dates étaient inconnues, COUNT(*) vaudrait 34 et COUNT(datecirc) vaudrait 25. Dans notre base initiale, les 23 dates sont connues ; l’immatriculation, elle, ne peut jamais être NULL.

2. GROUP BY : calculer par groupe

Pour savoir combien de Toyota, de BMW, de Kia en une seule requête, on regroupe les lignes par marque : GROUP BY réaménage le résultat en groupes où la colonne de regroupement a la même valeur, et l’agrégat se calcule pour chaque groupe.

SELECT marque, COUNT(*) AS nb
FROM Voiture
GROUP BY marque;

-- avec un filtre sur les lignes, avant le regroupement :
SELECT moteur, COUNT(*), AVG(pxachat)
FROM Voiture
WHERE marque = 'TOYOTA'
GROUP BY moteur;

Lecture du premier exemple : une ligne par marque présente dans le parc, avec son effectif — et rien d’autre. Pour obtenir un résultat portable et déterministe, affichez les colonnes de regroupement et les agrégats ; ne demandez pas une immatriculation arbitraire du groupe.

Différence de dialecte : colonne non agrégée

SQLite accepte aussi la requête suivante : il renvoie 12 groupes et choisit pour chaque groupe une immatriculation d’une de ses lignes, sans garantir laquelle. D’autres SGBD ou réglages peuvent refuser cette forme. Préférez la requête précédente, qui ne demande que la marque et son effectif.

SELECT marque, immat, COUNT(*) AS nb FROM Voiture GROUP BY marque;
Mnémotechnique — « GROUP BY découpe, l’agrégat résume »

Chaque groupe devient une ligne du résultat. Si le résultat paraît étrange (trop de lignes, valeurs incohérentes), vérifier deux choses : la colonne de regroupement est-elle la bonne ? Chaque colonne affichée est-elle regroupée ou agrégée ?

3. HAVING : filtrer les groupes

« Quelles marques ont plus de deux voitures ? » : la condition porte sur le résultat du regroupement, pas sur les lignes. C’est le rôle de HAVING — l’équivalent de WHERE appliqué aux groupes :

SELECT marque, COUNT(*) AS nb
FROM Voiture
GROUP BY marque
HAVING COUNT(*) > 2;

-- WHERE filtre les lignes AVANT le regroupement,
-- HAVING filtre les groupes APRÈS :
SELECT moteur, COUNT(*)
FROM Voiture
WHERE marque = 'TOYOTA'
GROUP BY moteur
HAVING COUNT(*) >= 1;

Dans SQLite, une requête agrégée sans GROUP BY forme aussi un groupe global ; HAVING peut le conserver ou l’écarter :

SELECT COUNT(*) AS nb FROM Voiture HAVING COUNT(*) > 0;

Sur la base initiale, cette requête renvoie une ligne contenant 23. Avec HAVING COUNT(*) > 23, elle ne renvoie aucune ligne. Les conditions acceptées par HAVING peuvent varier selon le dialecte.

WHERE ou HAVING : la question à se poser

« Seulement les diesels » parle des lignes : WHERE. « Seulement les marques avec au moins 3 voitures » parle des groupes : HAVING. On ne place pas directement dans WHERE un agrégat du même SELECT ; une sous-requête peut cependant y calculer un agrégat.

4. L’ordre complet, une dernière fois

Voici l’ordre d’écriture des clauses, lorsqu’elles sont présentes :

SELECT   colonnes, agrégats
FROM     tables (jointures éventuelles)
WHERE    filtre les LIGNES
GROUP BY découpe en GROUPES
HAVING   filtre les GROUPES
ORDER BY trie le résultat
LIMIT    borne le nombre de lignes

Pour comprendre le résultat, un ordre logique utile est FROM et jointures, WHERE, GROUP BY, HAVING, SELECT, puis ORDER BY et LIMIT. Ce n’est pas une promesse d’exécution physique : l’optimiseur choisit un plan équivalent.

Exemple récapitulatif du parc : « les deux moteurs les plus répandus parmi les voitures de moins de 30 millions, avec leur prix moyen » :

SELECT moteur, COUNT(*) AS nb, AVG(pxachat) AS prix_moyen
FROM Voiture
WHERE pxachat < 30000000
GROUP BY moteur
ORDER BY nb DESC
LIMIT 2;
Vérifier dans le simulateur

Chaque requête de ce chapitre s’exécute dans la page atelier — simulateur SQL : le jeu de données parc_auto y est chargé, et le résultat s’affiche en tableau. Une clause WHERE placée après GROUP BY provoque une erreur de syntaxe ; une colonne hors GROUP BY, en revanche, peut être acceptée par SQLite sans résultat déterministe.

6. QCM — niveau examen

Que renvoie une fonction d’agrégation ?

Elle résume une colonne : une valeur totale, ou une par groupe avec GROUP BY.

Dans un jeu hypothétique de 34 voitures dont 9 dates sont NULL, COUNT(datecirc) vaut…

COUNT(colonne) ignore les NULL : 34 − 9 = 25. Ce jeu hypothétique diffère des 23 voitures initiales.

Que compte COUNT(DISTINCT marque) ?

DISTINCT élimine les doublons avant le comptage.

En SQLite, que fait SELECT marque, immat, COUNT(*) FROM Voiture GROUP BY marque ?

SQLite accepte une colonne non regroupée et non agrégée ; sa valeur n’est pas déterministe. D’autres dialectes ou réglages peuvent la refuser.

HAVING filtre…

WHERE filtre les lignes, HAVING filtre les groupes.

Dans une même requête agrégée, où placer le filtre COUNT(*) > 2 ?

WHERE filtre les lignes avant le calcul de cet agrégat ; HAVING filtre les groupes après.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Colonne affichée hors GROUP BY : SQLite peut l’accepter mais sa valeur peut être arbitraire.
  • HAVING sans GROUP BY : en SQLite, il peut filtrer le groupe global d’une requête agrégée.
  • COUNT(*) à la place de COUNT(colonne) : les NULL sont comptés à tort.
  • Filtre de groupe mis dans WHERE : « HAVING COUNT(*) > 2 » ne s’écrit pas « WHERE COUNT(*) > 2 ».
  • AVG sur une colonne textuelle : résultat sans sens — la moyenne d’un prix, oui ; d’une immatriculation, non.

8. Méthodologie de résolution

Analyser une table par groupes
  1. Traduire la question : quelle unité de compte (par marque, par moteur, par pays) ?
  2. Choisir l’agrégat : combien (COUNT), extrêmes (MIN/MAX), total (SUM), moyenne (AVG).
  3. Regrouper sur la colonne d’unité et n’afficher que regroupé ou agrégé.
  4. Filtrer au bon endroit : lignes dans WHERE, groupes dans HAVING.
  5. Présenter avec ORDER BY et LIMIT, puis contrôler les effectifs sur un cas connu.

9. Révision active

Résumé essentiel
  • Cinq agrégats : COUNT, MIN, MAX, SUM, AVG — une valeur par table ou par groupe.
  • COUNT(*) compte les lignes ; COUNT(colonne) ignore les NULL ; COUNT(DISTINCT …) dédoublonne.
  • GROUP BY découpe en groupes ; pour un résultat déterministe, affichez les colonnes regroupées et les agrégats.
  • HAVING filtre les groupes, ou le groupe global d’une requête agrégée SQLite ; WHERE filtre les lignes avant.
  • Ordre logique : FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT ; le plan physique peut différer.

Checklist de maîtrise

  • Je choisis le bon agrégat pour une question donnée.
  • Je distingue COUNT(*), COUNT(colonne) et COUNT(DISTINCT colonne).
  • J’écris un GROUP BY complet sans colonne hors regroupement.
  • Je place WHERE et HAVING conformément à ce qu’ils filtrent.
