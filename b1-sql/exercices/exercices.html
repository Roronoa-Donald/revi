Exercices supplémentaires & cas pratiques SQL

De la pratique graduée pour consolider chaque module, puis un dossier de requêtage et d’optimisation relationnelle.

Entraînement rapide (acquisition)

Échauffement
  1. Sélectionner des colonnes spécifiques avec projection SELECT et filtrage simple WHERE.
  2. Éliminer les doublons dans les résultats avec le mot-clé DISTINCT.
  3. Trier les résultats avec ORDER BY (ASC / DESC) et limiter le nombre de lignes retournées avec LIMIT.
  4. Filtrer sur des intervalles (BETWEEN) ou des listes de valeurs (IN).
Requêtes SQL et explications détaillées

1. Projection : SELECT nom, email FROM clients WHERE ville = 'Paris';

2. Dédoublonnage : SELECT DISTINCT pays FROM fournisseurs;

3. Tri & pagination : SELECT * FROM commandes ORDER BY date_commande DESC LIMIT 10;

4. Intervalles : SELECT * FROM produits WHERE prix BETWEEN 20 AND 50;

Application

Application
  1. Effectuer des jointures internes (INNER JOIN) entre plusieurs tables reliées par clés primaires et étrangères.
  2. Utiliser les jointures externes (LEFT JOIN / RIGHT JOIN) pour conserver les enregistrements sans correspondance.
  3. Calculer des agrégats (COUNT, SUM, AVG, MIN, MAX) regroupés par catégories avec GROUP BY.
  4. Filtrer les résultats agrégés avec la clause HAVING.
Requêtes SQL et explications détaillées

1. Jointure interne : SELECT c.nom, cmd.id FROM clients c INNER JOIN commandes cmd ON c.id = cmd.client_id;

2. Jointure externe : SELECT c.nom, cmd.id FROM clients c LEFT JOIN commandes cmd ON c.id = cmd.client_id WHERE cmd.id IS NULL; (clients sans commande).

3. Agrégation : SELECT categorie, COUNT(*), AVG(prix) FROM produits GROUP BY categorie;

4. Filtrage d’agrégat : SELECT client_id, SUM(total) FROM commandes GROUP BY client_id HAVING SUM(total) > 1000;

Raisonnement

Raisonnement
  1. Écrire des sous-requêtes corrélées et imbriquées (IN, EXISTS, NOT EXISTS).
  2. Gérer les transactions ACID avec BEGIN, COMMIT et ROLLBACK.
  3. Créer et manipuler des vues (CREATE VIEW) pour sécuriser l’accès aux données.
  4. Analyser le plan d’exécution d’une requête avec EXPLAIN pour justifier la création d’un index (INDEX).
Requêtes SQL et explications détaillées

1. Sous-requête EXISTS : SELECT nom FROM clients c WHERE EXISTS (SELECT 1 FROM commandes cmd WHERE cmd.client_id = c.id AND cmd.total > 500);

2. Transaction : BEGIN; UPDATE comptes SET solde = solde - 100 WHERE id = 1; UPDATE comptes SET solde = solde + 100 WHERE id = 2; COMMIT;

3. Vue : CREATE VIEW v_ventes_mensuelles AS SELECT strftime('%Y-%m', date_commande) AS mois, SUM(total) AS ca FROM commandes GROUP BY mois;

4. Index : CREATE INDEX idx_cmd_client ON commandes(client_id); transforme un Seq Scan (parcours complet) en Index Scan immédiat.

Dossier de synthèse — Conception & Requêtage Relationnel

Cahier des charges du Dossier

Ce dossier d’ingénierie des bases de données consiste à concevoir le schéma relationnel, les contraintes d’intégrité référentielle et les requêtes analytiques de reporting d’une plateforme de commerce électronique.

Compétences SQL évaluées
  1. Modélisation DDL : Création des tables, clés primaires, clés étrangères avec clauses ON DELETE CASCADE.
  2. Requêtage complexe : Maîtrise des jointures multiples, sous-requêtes et fonctions d’agrégation.
  3. Intégrité transactionnelle : Préservation des propriétés ACID lors d’opérations concurrentes.
  4. Optimisation des performances : Analyse des coûts d’exécution et stratégie d’indexation.
