Exercices supplémentaires & cas pratiques SQL

De la pratique graduée sur le parc du simulateur, puis un dossier de conception indépendant. Réinitialisez le parc après les exemples qui modifient sa structure ou ses données.

Entraînement rapide (acquisition)

Échauffement
  1. Affichez les immatriculations et marques des voitures diesel.
  2. Listez les pays des marques sans doublon.
  3. Affichez les dix voitures les plus récentes avec ORDER BY et LIMIT.
  4. Affichez les voitures dont le prix est compris entre 20 et 30 millions de francs.
Requêtes SQL et explications détaillées

1. Projection : SELECT immat, marque FROM Voiture WHERE moteur = 'DIESEL';

2. Dédoublonnage : SELECT DISTINCT paysmarque FROM Marque;

3. Tri & pagination : SELECT * FROM Voiture ORDER BY datecirc DESC, immat ASC LIMIT 10;

4. Intervalle inclus : SELECT * FROM Voiture WHERE pxachat BETWEEN 20000000 AND 30000000;

Application

Application
  1. Associez chaque voiture à sa marque par INNER JOIN.
  2. Listez les marques sans voiture avec LEFT JOIN ; exprimez aussi la requête avec RIGHT JOIN.
  3. Calculez le nombre et le prix moyen des voitures par moteur.
  4. Listez les marques dont le budget total dépasse 100 millions de francs.
Requêtes SQL et explications détaillées

1. Jointure interne : SELECT V.immat, M.nommarque FROM Voiture V INNER JOIN Marque M ON V.codemarque = M.codemarque;

2. Jointure externe : SELECT M.nommarque FROM Marque M LEFT JOIN Voiture V ON V.codemarque = M.codemarque WHERE V.immat IS NULL; Forme symétrique : SELECT M.nommarque FROM Voiture V RIGHT JOIN Marque M ON V.codemarque = M.codemarque WHERE V.immat IS NULL; Dans le parc initial, ces requêtes renvoient zéro ligne ; ajoutez une marque sans voiture pour observer la différence.

3. Agrégation : SELECT moteur, COUNT(*), AVG(pxachat) FROM Voiture GROUP BY moteur;

4. Filtrage d’agrégat : SELECT marque, SUM(pxachat) FROM Voiture GROUP BY marque HAVING SUM(pxachat) > 100000000;

Raisonnement

Raisonnement
  1. Écrivez des sous-requêtes corrélées ou imbriquées avec IN, EXISTS et NOT EXISTS.
  2. Essayez BEGIN, COMMIT et ROLLBACK sur une modification du kilométrage.
  3. Créez une vue des achats mensuels et interrogez-la.
  4. Créez un index et consultez un plan avec EXPLAIN QUERY PLAN.
Requêtes SQL et explications détaillées

1. Sous-requêtes : SELECT M.nommarque FROM Marque M WHERE EXISTS (SELECT 1 FROM Voiture V WHERE V.codemarque = M.codemarque AND V.pxachat > 30000000); SELECT nommarque FROM Marque WHERE codemarque IN (SELECT codemarque FROM Voiture); SELECT M.nommarque FROM Marque M WHERE NOT EXISTS (SELECT 1 FROM Voiture V WHERE V.codemarque = M.codemarque);

2. Transaction : BEGIN; UPDATE Voiture SET km = km + 100 WHERE immat = 'TG-7854-Z'; SELECT km FROM Voiture WHERE immat = 'TG-7854-Z'; ROLLBACK; ROLLBACK annule la modification. Pour la conserver, terminez une nouvelle transaction par COMMIT : BEGIN; UPDATE Voiture SET km = km + 100 WHERE immat = 'TG-7854-Z'; COMMIT; Réinitialisez ensuite le parc.

3. Vue : CREATE VIEW v_achats_mensuels AS SELECT substr(datecirc, 1, 7) AS mois, SUM(pxachat) AS total FROM Voiture WHERE datecirc IS NOT NULL GROUP BY substr(datecirc, 1, 7); SELECT mois, total FROM v_achats_mensuels ORDER BY mois; Une vue nomme une requête. Dans un SGBD avec privilèges, elle peut aussi limiter les données exposées ; SQLite ne gère pas de privilèges par vue.

4. Index : CREATE INDEX idx_voiture_code ON Voiture(codemarque); EXPLAIN QUERY PLAN SELECT immat FROM Voiture WHERE codemarque = 'TOY'; Le plan indique le choix de l’optimiseur ; créer un index ne garantit pas qu’il sera utilisé.

Dossier de synthèse — Conception & Requêtage Relationnel

Cahier des charges du Dossier

Ce dossier d’ingénierie des bases de données consiste à concevoir le schéma relationnel, les contraintes d’intégrité référentielle et les requêtes analytiques de reporting d’une plateforme de commerce électronique.

Compétences SQL évaluées
  1. Modélisation DDL : Création des tables, clés primaires, clés étrangères avec clauses ON DELETE CASCADE.
  2. Requêtage complexe : Maîtrise des jointures multiples, sous-requêtes et fonctions d’agrégation.
  3. Intégrité transactionnelle : Préservation des propriétés ACID lors d’opérations concurrentes.
  4. Optimisation des performances : Analyse des coûts d’exécution et stratégie d’indexation.
