Chapitre 6 — Boîtes de dialogue (MsgBox, InputBox), Gestion des erreurs (On Error GoTo) et Formulaires (UserForm)

Mise en situation

Pour qu’un outil Excel devienne une véritable application métier utilisable par des collègues non informaticiens, il doit dialoguer clairement avec l’utilisateur (demander une confirmation, recueillir un paramètre, proposer un formulaire de saisie guidé UserForm) et ne jamais planter brutalement sur un message d’erreur technique incompréhensible.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. afficher des messages et récupérer le choix de l’utilisateur avec MsgBox (vbYesNo, vbInformation, vbYes, vbNo) et les arguments nommés (:=) ;
  2. recueillir une saisie utilisateur avec InputBox et contrôler les cas d’annulation ou de saisie vide ;
  3. mettre en place une gestion d’erreurs robuste avec On Error GoTo Etiquette, Exit Sub, On Error Resume Next et l’objet Err (Err.Number, Err.Description) ;
  4. concevoir un formulaire UserForm dans VBE avec ses contrôles (Label, TextBox, ComboBox/ListBox, CommandButton) ;
  5. coder les événements du formulaire (UserForm_Initialize, AddItem, CommandButton_Click) et maîtriser son cycle de vie (Load, Show, Hide vs Unload Me).

1. Les boîtes de dialogue natives : MsgBox et InputBox

La fonction MsgBox(prompt, [buttons], [title]) affiche une boîte de dialogue modale. Le support du Dr TCHAZINO Tchamiè distingue deux façons de l’appeler :

  • Comme simple instruction d’information (sans valeur de retour) : on n’utilise pas de parenthèses autour des arguments (sauf si l’on utilise Call). Ex. : MsgBox "Sauvegarde effectuée !", vbInformation, "Bilan".
  • Comme fonction (pour savoir sur quel bouton l’utilisateur a cliqué) : on place les arguments entre parenthèses et on affecte le retour à une variable entière. On combine le choix des boutons (vbOKOnly = 0, vbOKCancel = 1, vbYesNo = 4, vbYesNoCancel = 3) et l’icône (vbCritical = 16, vbQuestion = 32, vbExclamation = 48, vbInformation = 64) avec le signe +, puis on teste la réponse (vbOK = 1, vbCancel = 2, vbYes = 6, vbNo = 7).

On peut passer les arguments par position (dans l’ordre exact) ou par nom avec l’opérateur := (dans n’importe quel ordre, par ex. MsgBox Title:="Alerte", Prompt:="Vérifiez la ligne"). Pour demander à l’utilisateur de saisir une valeur, on utilise InputBox(prompt, [title], [default]), qui renvoie toujours une chaîne de caractères String (vide "" si l’utilisateur clique sur Annuler) :

Dim nomClient As String, rep As Integer
nomClient = InputBox("Entrez le nom du client :", "Nouveau dossier", "SARL Togo")
If nomClient = "" Then Exit Sub  ' Annulation ou saisie vide

rep = MsgBox("Créer la fiche de " & nomClient & " ?", vbYesNo + vbQuestion, "Confirmation")
If rep = vbYes Then
    Range("A2").Value = nomClient
End If

2. La gestion des erreurs d’exécution : On Error GoTo et l’objet Err

Une erreur d’exécution survient lorsqu’une instruction valide syntaxiquement échoue face aux données réelles : division par zéro (erreur 11), feuille ou classeur introuvable dans une collection (erreur 9 Indice en dehors de la plage / Subscript out of range), texte saisi au lieu d’un nombre (erreur 13 Incompatibilité de type / Type mismatch), ou action interdite sur une feuille protégée (erreur 1004).

Pour éviter l’arrêt brutal d’Excel, on place en début de procédure une instruction On Error :

  • On Error GoTo GestionErreur : dès qu’une erreur survient, VBA saute immédiatement à l’étiquette GestionErreur: placée en fin de procédure. Il faut impérativement placer Exit Sub (ou Exit Function) juste avant l’étiquette pour que l’exécution normale ne tombe pas dans le bloc d’erreur !
  • On Error Resume Next : ignore l’erreur et passe à la ligne suivante (utile pour tenter une opération optionnelle puis tester If Err.Number <> 0 Then).
  • On Error GoTo 0 : désactive le gestionnaire courant et rétablit le comportement standard de VBA.
Sub ActiverFeuilleClient(nomFeuille As String)
    On Error GoTo FeuilleAbsente
    Worksheets(nomFeuille).Select
    Exit Sub  ' Sortie normale avant le gestionnaire !

FeuilleAbsente:
    MsgBox "Erreur " & Err.Number & " : la feuille [" & nomFeuille & "] n'existe pas." & _
           vbCrLf & "Détail : " & Err.Description, vbCritical, "Feuille introuvable"
End Sub

3. Les formulaires personnalisés (UserForm) : contrôles, initialisation et cycle de vie

Lorsque InputBox ne suffit plus (saisie simultanée d’un nom, d’une catégorie dans une liste déroulante et d’un montant), on crée un formulaire personnalisé (UserForm) dans VBE via Insertion → UserForm. À l’aide de la Boîte à outils Contrôles, on y dépose :

  • Intitulé (Label) : étiquette de texte fixe (propriété Caption).
  • Zone de texte (TextBox) : champ de saisie libre (propriété Value ou Text).
  • Zone de liste modifiable (ComboBox) / Zone de liste (ListBox) : liste déroulante alimentée soit par la propriété RowSource (ex. Feuil1!A2:A10), soit par programmation avec la méthode .AddItem dans l’événement UserForm_Initialize().
  • Case à cocher (CheckBox), Bouton d’option (OptionButton) et Cadre (Frame).
  • Bouton de commande (CommandButton) : bouton Valider ou Annuler (propriétés Caption, Default = True pour la touche Entrée, Cancel = True pour Échap).

Le support insiste sur le cycle de vie du UserForm et la différence cruciale entre Hide et Unload :

  • MonForm.Show : charge (en déclenchant Private Sub UserForm_Initialize()) et affiche le formulaire à l’écran.
  • MonForm.Hide (ou Me.Hide) : masque visuellement le formulaire mais le conserve en mémoire vive, ce qui permet à la macro appelante de lire encore le contenu de MonForm.TextBoxNom.Value.
  • Unload MonForm (ou Unload Me) : ferme le formulaire et le décharge complètement de la mémoire (toutes les valeurs saisies dans les contrôles sont effacées).
' Dans le module de code du UserForm (FrmSaisie) :
Private Sub UserForm_Initialize()
    ComboBoxService.AddItem "Comptabilité"
    ComboBoxService.AddItem "Logistique"
    ComboBoxService.AddItem "Direction"
End Sub

Private Sub ButtonOK_Click()
    If TextBoxNom.Value = "" Then
        MsgBox "Veuillez saisir un nom.", vbExclamation, "Champ requis"
        Exit Sub
    End If
    Range("A2").Value = TextBoxNom.Value
    Range("B2").Value = ComboBoxService.Value
    Unload Me
End Sub
Ouverture d’autres applications Office depuis VBA (Automation)

Comme le montre la fin du support de cours, VBA peut aussi piloter Word ou un navigateur depuis Excel grâce à CreateObject("Word.Application") (automation COM/OLE) ou ouvrir un document/site avec ActiveWorkbook.FollowHyperlink.

Exercice 1 — Dialogue utilisateur avec InputBox et MsgBox

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Maîtriser les constantes de boutons et de retour de MsgBox, le comportement d’InputBox et les arguments nommés (:=).

Énoncé. Avant d’archiver les factures du mois, la macro interroge l’utilisateur :

Dim mois As String, reponse As Integer
mois = InputBox(Prompt:="Mois à clôturer :", Title:="Clôture")
If mois = "" Then Exit Sub

reponse = MsgBox("Archiver le mois de " & mois & " ?", vbYesNo + vbQuestion, "Confirmation")
If reponse = vbYes Then
    Call ArchiverFactures(mois)
End If
  1. Quelle fonction VBA ouvre une boîte de dialogue permettant à l’utilisateur de saisir un texte au clavier ?
  2. Que renvoie InputBox si l’utilisateur clique sur le bouton Annuler : "" (chaîne vide) ou 0 ?
  3. Quel opérateur de deux caractères (utilisé après Prompt et Title) permet de passer un argument par son nom ?
  4. Quelle constante VBA passée à MsgBox affiche les deux boutons Oui et Non ?
  5. Quelle constante VBA renvoyée dans reponse indique que l’utilisateur a cliqué sur le bouton Oui ?
Cas d’exemple
Si l'utilisateur clique sur Non dans MsgBox(..., vbYesNo) :
- reponse reçoit la constante vbNo (valeur 7)
- Le test If reponse = vbYes est faux : ArchiverFactures n'est pas appelée.
Trois indices, rédigés en mots
  1. InputBox saisit une entrée (Input) et MsgBox affiche un message (Message).
  2. Pour les arguments nommés, regardez les deux caractères collés entre Prompt et "Mois à clôturer :".
  3. Étapes : citer InputBox ; répondre "" (chaîne vide) en cas d’annulation ; noter l’opérateur := ; relever vbYesNo pour afficher Oui/Non et vbYes pour tester la réponse Oui.

Exercice 2 — Gestion des erreurs d’exécution avec On Error GoTo et l’objet Err

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Structurer un gestionnaire d’erreur On Error GoTo et identifier les propriétés de l’objet Err ainsi que les codes d’erreur classiques.

Énoncé. Pour éviter qu’une erreur d’exécution n’interrompe brutalement le travail de l’utilisateur, Kofi protège sa procédure avec un gestionnaire d’erreur :

Sub CalculerRatio( nomFeuille As String )
    On Error GoTo GestionErreur
    Worksheets(nomFeuille).Activate
    Range("D2").Value = Range("B2").Value / Range("C2").Value
    Exit Sub

GestionErreur:
    MsgBox "Erreur n° " & Err.Number & " : " & Err.Description, vbCritical, "Anomalie"
End Sub
  1. Quelle instruction de trois mots en début de procédure branche l’exécution vers l’étiquette GestionErreur en cas d’anomalie ?
  2. Quelle instruction de deux mots placée juste avant GestionErreur: est indispensable pour que la procédure s’arrête normalement quand aucune erreur ne survient ?
  3. Quel est le nom de l’objet VBA qui stocke les informations sur l’erreur qui vient de se produire ?
  4. Quelle propriété de cet objet renvoie le code numérique de l’erreur (par ex. 9 ou 11) ?
  5. Si Range("C2").Value vaut 0, quel est le numéro de l’erreur VBA « Division par zéro » (9 ou 11) ?
Cas d’exemple
Codes d'erreur classiques en VBA Excel :
- Erreur 9 : Indice en dehors de la plage (ex. Worksheets("Inconnue"))
- Erreur 11 : Division par zéro
- Erreur 13 : Incompatibilité de type (Type mismatch)
Trois indices, rédigés en mots
  1. Lisez les deux premières lignes et la ligne située juste au-dessus de l’étiquette GestionErreur:.
  2. Dans le MsgBox final, l’objet d’erreur expose deux propriétés : son numéro (Number) et son texte (Description).
  3. Étapes : relever On Error GoTo ; noter Exit Sub avant l’étiquette ; citer l’objet Err ; indiquer la propriété Number (Err.Number) ; retenir le code 11 pour la division par zéro (9 étant l’indice en dehors de la plage).

Exercice 3 — Concevoir et piloter un formulaire UserForm de saisie client

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Identifier les contrôles d’un UserForm, initialiser une ComboBox avec AddItem et distinguer Show, Hide et Unload Me.

Énoncé. Conformément au dernier chapitre du support du Dr TCHAZINO Tchamiè, vous créez un formulaire personnalisé FrmClient contenant une zone de texte TextBoxNom, une liste déroulante ComboBoxVille et un bouton ButtonOK :

Private Sub UserForm_Initialize()
    ComboBoxVille.AddItem "Lomé"
    ComboBoxVille.AddItem "Kara"
    ComboBoxVille.AddItem "Sokodé"
End Sub

Private Sub ButtonOK_Click()
    Range("A2").Value = TextBoxNom.Value
    Range("B2").Value = ComboBoxVille.Value
    Unload Me
End Sub
  1. Quelle méthode appliquée à FrmClient (ex. FrmClient.______) permet d’afficher le formulaire à l’écran depuis un module standard ?
  2. Dans l’événement UserForm_Initialize(), quelle méthode permet d’ajouter chacune des villes à la liste déroulante ComboBoxVille ?
  3. Quel type de contrôle de la Boîte à outils (en anglais : Label ou TextBox) permet à l’utilisateur de saisir librement son nom au clavier ?
  4. Quelle méthode (Hide ou Unload) masque visuellement le formulaire tout en conservant ses valeurs en mémoire vive ?
  5. Que fait l’instruction finale Unload Me : conserve-t-elle le formulaire en mémoire ou le décharge-t-elle complètement de la mémoire ? (répondez decharge ou conserve)
Cas d’exemple
Cycle de vie d'un UserForm :
1) FrmClient.Show -> déclenche UserForm_Initialize() et affiche la fenêtre
2) Saisie par l'utilisateur puis clic sur ButtonOK -> copie dans Range("A2:B2")
3) Unload Me -> ferme la fenêtre et libère la mémoire.
Trois indices, rédigés en mots
  1. En anglais, afficher se dit Show et masquer se dit Hide.
  2. Dans UserForm_Initialize, regardez la méthode appelée après ComboBoxVille. pour insérer "Lomé", "Kara" et "Sokodé".
  3. Étapes : noter Show pour afficher le formulaire ; relever AddItem pour remplir la ComboBox ; choisir TextBox pour la zone de saisie ; indiquer Hide pour masquer en mémoire ; répondre decharge pour Unload Me.

5. QCM — niveau examen

Quelle constante VBA faut-il passer au paramètre buttons de MsgBox pour afficher les boutons Oui et Non, et quelle constante teste le clic sur Oui ?

vbYesNo (valeur 4) affiche les boutons Oui et Non ; lorsque l’utilisateur clique sur Oui, la fonction MsgBox renvoie la constante vbYes (valeur 6, et vbNo = 7 pour Non).

Dans une procédure utilisant On Error GoTo GestionErreur, pourquoi faut-il placer Exit Sub juste avant l’étiquette GestionErreur: ?

Une étiquette (GestionErreur:) n’arrête pas le flux séquentiel du programme : sans Exit Sub juste au-dessus, la macro exécuterait le code d’erreur même quand tout s’est bien passé.

Dans un formulaire UserForm, quel événement s’exécute automatiquement au chargement du formulaire et permet de remplir une ComboBox avec .AddItem ?

L’événement Private Sub UserForm_Initialize() se déclenche lors du chargement en mémoire du formulaire (Load ou Show) avant son affichage : c’est l’endroit idéal pour initialiser les listes avec .AddItem.

Quelle est la différence fondamentale entre Me.Hide et Unload Me dans le code d’un UserForm ?

Hide masque simplement la fenêtre (les valeurs des TextBox et ComboBox restent lisibles en mémoire), tandis que Unload décharge complètement l’objet de la mémoire vive.

Que renvoie la fonction standard InputBox("Votre âge ?") si l’utilisateur clique sur le bouton Annuler ?

La fonction VBA InputBox renvoie toujours une chaîne String : si l’utilisateur clique sur Annuler, elle renvoie la chaîne vide "".

Quel opérateur permet de passer des arguments par leur nom (par exemple Prompt:="Bonjour", Title:="Info") lors de l’appel d’une procédure ou de MsgBox ?

En VBA, le passage d’arguments nommés utilise l’opérateur := (deux-points suivi de égal), ce qui permet de fournir les arguments dans n’importe quel ordre.

Quel objet VBA contient le numéro (Number) et le texte explicatif (Description) de la dernière erreur d’exécution interceptée ?

L’objet intrinsèque Err stocke les informations de la dernière erreur d’exécution : Err.Number donne son code numérique (ex. 9, 11, 13, 1004) et Err.Description son libellé.

Quelle méthode d’un contrôle ComboBox permet d’ajouter par programmation un choix supplémentaire dans sa liste déroulante ?

La méthode .AddItem (par ex. ComboBox1.AddItem "Lomé") ajoute un nouvel élément à la liste d’un contrôle ComboBox ou ListBox.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Mettre des parenthèses à MsgBox("Bonjour", vbInformation) sans récupérer la valeur de retour ni utiliser Call : VBE génère une erreur de syntaxe.
  • Oublier Exit Sub juste avant l’étiquette du gestionnaire d’erreur On Error GoTo.
  • Décharger un formulaire avec Unload Me avant d’avoir copié les valeurs de ses TextBox dans la feuille Excel.
  • Oublier de vérifier si InputBox a renvoyé "" (clic sur Annuler) avant de convertir la saisie en nombre.

7. Méthodologie de résolution

Méthode — construire une interface utilisateur fiable sous Excel
  1. Pour une simple question Oui/Non ou une saisie unique, utiliser MsgBox(..., vbYesNo + vbQuestion) et InputBox en testant le cas d’annulation ("").
  2. Pour une saisie multi-champs, créer un UserForm, remplir ses ComboBox dans UserForm_Initialize() avec .AddItem et valider les champs dans CommandButtonOK_Click().
  3. Transférer les valeurs des contrôles (TextBox.Value, ComboBox.Value) vers les cellules de la feuille avant d’appeler Unload Me.
  4. Protéger les opérations sensibles (ouverture de fichier, sélection de feuille, division) par On Error GoTo Etiquette précédé de Exit Sub.

8. Révision active

Résumé essentiel
  • MsgBox affiche un message ou pose une question (vbYesNo, retour vbYes/vbNo) ; InputBox recueille une chaîne String.
  • Les arguments nommés s’écrivent avec := (Prompt:="...", Title:="...").
  • On Error GoTo Etiquette (avec Exit Sub avant l’étiquette) et l’objet Err (Err.Number, Err.Description) interceptent proprement les erreurs.
  • Un UserForm réunit Label, TextBox, ComboBox (.AddItem dans UserForm_Initialize) et CommandButton ; Show l’affiche, Hide le masque en mémoire et Unload Me le décharge.

Checklist de maîtrise

  • Je sais utiliser MsgBox en instruction simple et en fonction avec vbYesNo / vbYes.
  • Je sais structurer un gestionnaire d’erreur complet avec On Error GoTo, Exit Sub et Err.Number.
  • Je sais initialiser une ComboBox avec .AddItem dans UserForm_Initialize().
  • Je sais expliquer la différence entre Me.Hide et Unload Me.

Les 8 notions à connaître absolument

  1. MsgBox : boîte de message modale (constantes vbYesNo, vbInformation, retours vbYes, vbNo).
  2. InputBox : boîte de saisie renvoyant la chaîne entrée par l’utilisateur (ou "" sur Annuler).
  3. Arguments nommés (:=) : syntaxe permettant de passer les paramètres d’une procédure par leur nom.
  4. On Error GoTo / Resume Next : instructions de branchement ou de poursuite en cas d’erreur d’exécution.
  5. Objet Err : porte le code (Err.Number) et le message (Err.Description) de l’erreur active.
  6. UserForm : boîte de dialogue personnalisée dotée de contrôles graphiques (Label, TextBox, ComboBox, CommandButton).
  7. UserForm_Initialize() & .AddItem : événement de chargement du formulaire et méthode d’ajout dans une liste.
  8. Show, Hide vs Unload Me : afficher, masquer en gardant les données en mémoire, ou décharger complètement de la mémoire.
