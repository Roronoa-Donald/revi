Atelier d’analyse & Bac à sable

Un éditeur dans la page, un vrai interpréteur Bash derrière. Écris un script, exécute-le et lis ce qu’il affiche : c’est ici qu’une règle de l’histoire devient un contrôle automatisé.

Comment fonctionne l’atelier
  • Valider vérifie la conformité de vos réponses dans la grille d’analyse.
  • Données du cas contient les paramètres soumis à l’étude.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Zone libre — jauge du serveur fainéant

Bash

Objectif : expérimenter sans conséquence. Prends une règle de l’histoire (seuil des 48 minutes, allocation mémoire/disque, saturation, symptômes de surcharge), programme-la et teste-la sur des cas limites.

Le script proposé rejoue le constat : 80 % d’une heure = 48 minutes creuses, l’heure est perdue. Transforme-le : fais-le dire le taux d’inactivité global en pourcentage, distingue les heures à 100 % de repos, ou remplace tout le script par la règle que tu veux vérifier.

Dans un vrai parc, ce contrôle tourne en continu sur les métriques du matériel : la structure du script — lire, décider, rapporter — reste exactement la même.

Du script à la vraie console

La simulation a une limite assumée : aucune machine virtuelle ne démarre ici et aucun hyperviseur n’est installé — le serveur reste du texte structuré. Elle a une force : toute la logique se vérifie sans risque — on peut rejouer une allocation, une saturation ou un plan de consolidation autant de fois que nécessaire. Quand le script reproduit les bons réflexes — lire, décider, rapporter — le passage à un vrai hyperviseur est mécanique.

Les trois erreurs que l’atelier révèle immédiatement
  • Case incomplet : une valeur imprévue tombe dans le défaut silencieux et produit une sortie vide.
  • Compteur dans la boucle : le bilan s’affiche à chaque ligne au lieu d’une seule fois, après.
  • Ordre des lectures inversé : le script lit la seconde valeur avant la première, et tout décale.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.
