Chapitre 6

Algorithmes de Tri

Ordonner des données : tri par sélection, tri à bulles, tri par insertion. Comparaison et complexité.

Objectifs du chapitre

  • Implémenter les tris par sélection, insertion et bulles
  • Comparer les complexités O(n²) et O(n) au meilleur cas
  • Identifier un tri stable vs instable

6.1 — Pourquoi trier ?

📚
Analogie — La bibliothèque : Imagine une bibliothèque où les livres sont rangés au hasard. Trouver un livre prendrait des heures ! Si tout est trié par ordre alphabétique, c'est instantané. Trier = faciliter la recherche.
ℹ️
Un tableau est trié en ordre croissant si pour tout i : T[i] ≤ T[i+1]. En ordre décroissant : T[i] ≥ T[i+1].
🧠
Mnémo — S.B.I. : Les 3 tris de B1 = Sélection, Bulles, Insertion. Comme un bus SBI !

6.2 — Tri par sélection

🎯 Principe

À chaque étape, on sélectionne le plus petit élément restant et on le place à sa position définitive.

🃏
Analogie — Les cartes : Tu as un tas de cartes en désordre. Tu cherches la plus petite, tu la mets en 1ère position. Puis la plus petite parmi les restantes → 2ème position. Etc.
Pour i de 1 à N-1 Faire posMin ← i Pour j de i+1 à N Faire Si T[j] < T[posMin] Alors posMin ← j FinSi FinPour // Échange T[i] et T[posMin] temp ← T[i] T[i] ← T[posMin] T[posMin] ← temp FinPour
💡
Échange : Toujours utiliser une variable temp ! Rappel du chapitre 1 : l'échange des 3 verres.
Complexité : O(n²) comparaisons dans tous les cas

6.3 — Tri à bulles

🫧 Principe

On compare chaque paire d'éléments voisins et on les échange s'ils sont dans le mauvais ordre. On répète jusqu'à ce qu'aucun échange ne soit nécessaire.

🫧
Analogie — Les bulles : Comme des bulles de savon : les éléments les plus légers (petits) remontent petit à petit vers le haut (début), les plus lourds descendent vers le fond (fin).
Répéter échange ← FAUX Pour i de 1 à N-1 Faire Si T[i] > T[i+1] Alors // Échange temp ← T[i] T[i] ← T[i+1] T[i+1] ← temp échange ← VRAI FinSi FinPour Jusqu'à échange = FAUX
ℹ️
Avantage : Si le tableau est déjà trié, une seule passe suffit (aucun échange) → s'arrête plus vite que la sélection.
Complexité : O(n²) pire cas, O(n) meilleur cas (déjà trié)

6.4 — Tri par insertion

📥 Principe

On prend les éléments un par un et on les insère à la bonne position dans la partie déjà triée.

🃏
Analogie — Le jeu de cartes : Quand tu reçois tes cartes une par une, tu insères chacune à sa place dans ta main déjà triée. C'est exactement le tri par insertion !
Pour i de 2 à N Faire clé ← T[i] j ← i - 1 TantQue (j ≥ 1) ET (T[j] > clé) Faire T[j+1] ← T[j] // Décaler vers la droite j ← j - 1 FinTantQue T[j+1] ← clé // Insérer FinPour
🧠
Mnémo — Qui décale quoi ?
🔍 Sélection = cherche le min, échange → « le chasseur »
🫧 Bulles = voisins qui s'échangent → « les secousses »
📥 Insertion = prend et insère → « le joueur de cartes »
Complexité : O(n²) pire cas, O(n) meilleur cas (déjà trié)

6.5 — Comparaison des 3 tris

TriMeilleur casPire casStable ?Avantage
SélectionO(n²)O(n²)NonSimple, peu d'échanges
BullesO(n)O(n²)OuiDétecte si déjà trié
InsertionO(n)O(n²)OuiEfficace sur petits tableaux
ℹ️
Tri stable : Un tri est stable s'il conserve l'ordre relatif des éléments égaux. Bulles et Insertion sont stables, Sélection ne l'est pas.

Exercices guidés — Algorithmes de Tri

🎯 Tri par sélection — Pas à pas

Énoncé : Trier T = [29, 10, 14, 37, 13] par sélection croissante.

Principe : À chaque tour, trouver le minimum et le placer en bonne position
PasseMin trouvéÉchangeTableau
Init——[29, 10, 14, 37, 13]
1 (i=0)10 (pos 1)T[0] ↔ T[1][10, 29, 14, 37, 13]
2 (i=1)13 (pos 4)T[1] ↔ T[4][10, 13, 14, 37, 29]
3 (i=2)14 (pos 2)Déjà en place[10, 13, 14, 37, 29]
4 (i=3)29 (pos 4)T[3] ↔ T[4][10, 13, 14, 29, 37]
 
→ Résultat : [10, 13, 14, 29, 37] ✓
Nombre de comparaisons : 4+3+2+1 = 10 = n(n-1)/2

🎯 Tri à bulles — Pas à pas

Énoncé : Trier T = [5, 1, 4, 2] avec le tri à bulles.

Principe : Comparer les éléments adjacents et échanger si mal ordonnés

Passe 1 :

[5, 1, 4, 2]  → 5>1 ? Oui → échange → [1, 5, 4, 2]
[1, 5, 4, 2]  → 5>4 ? Oui → échange → [1, 4, 5, 2]
[1, 4, 5, 2]  → 5>2 ? Oui → échange → [1, 4, 2, 5]  ← 5 est en place

Passe 2 :

[1, 4, 2, 5]  → 1>4 ? Non
[1, 4, 2, 5]  → 4>2 ? Oui → échange → [1, 2, 4, 5]  ← 4 est en place

Passe 3 :

[1, 2, 4, 5]  → 1>2 ? Non  → Aucun échange → STOP
→ Résultat : [1, 2, 4, 5] ✓ (trié en 3 passes)

6.6 — Résumé

🎯 Aide-mémoire

  • S.B.I. = Sélection, Bulles, Insertion
  • Sélection : cherche le min → échange → O(n²) toujours
  • Bulles : échange voisins → O(n) si déjà trié
  • Insertion : insère à la bonne place → O(n) si déjà trié
  • Tous en O(n²) dans le pire cas
  • Échange = toujours avec variable temp

Pièges classiques à l'examen

⚠️ Piège n°1 — Complexité du tri sélection : Le tri par sélection est toujours O(n²), même si le tableau est déjà trié. Contrairement au tri à bulles ou par insertion qui peuvent être O(n) dans le meilleur cas.
⚠️ Piège n°2 — Oublier la variable temporaire : Pour échanger deux valeurs, il faut obligatoirement une variable temp. Écrire a ← b ; b ← a sans temp écrase la première valeur !
⚠️ Piège n°3 — Stabilité des tris : Un tri est stable s'il préserve l'ordre relatif des éléments égaux. Le tri par sélection n'est pas stable, mais insertion et bulles le sont.
