Chapitre 8

La Récursivité

Une fonction qui s'appelle elle-même : cas de base, pile d'appels, factorielle, Fibonacci et pièges classiques.

Objectifs du chapitre

  • Comprendre le principe de la récursivité
  • Identifier le cas de base et le cas récursif
  • Tracer l'exécution d'un appel récursif (pile d'appels)

8.1 — Le principe de la récursivité

🔄 Définition

Une fonction est récursive si elle s'appelle elle-même dans sa définition. Chaque appel résout un sous-problème plus petit, jusqu'à atteindre un cas de base (arrêt).

🪆
Analogie — Les poupées russes : Tu ouvres une matriochka et tu trouves une plus petite dedans. Tu l'ouvres aussi, et encore une plus petite… jusqu'à la dernière (la plus petite = cas de base). Puis tu refermes tout dans l'ordre inverse.
🧠
Mnémo — Les 2 règles d'or :
🛑 Règle 1 — CAS DE BASE : Il doit y avoir un point d'arrêt (sinon boucle infinie !)
📉 Règle 2 — PROGRESSION : Chaque appel doit se rapprocher du cas de base
Résumé : « Base + Progression = récursion saine »

8.2 — Exemple : la factorielle

n! = n × (n-1) × (n-2) × … × 1. Par définition : 0! = 1.

ℹ️
Formule récursive : fact(n) = n × fact(n-1) avec fact(0) = 1 (cas de base)
Fonction Factorielle(n : Entier) : Entier Début Si n = 0 Alors // Cas de base Retourner 1 Sinon Retourner n * Factorielle(n - 1) // Appel récursif FinSi Fin
function Factorielle(n: integer): integer; begin if n = 0 then Factorielle := 1 else Factorielle := n * Factorielle(n - 1); end;

Trace de Factorielle(4)

Factorielle(4) = 4 × Factorielle(3) Factorielle(3) = 3 × Factorielle(2) Factorielle(2) = 2 × Factorielle(1) Factorielle(1) = 1 × Factorielle(0) Factorielle(0) = 1 ← cas de base = 1 × 1 = 1 = 2 × 1 = 2 = 3 × 2 = 6 = 4 × 6 = 24

8.3 — La pile d'appels

📚 Définition

Chaque appel récursif est empilé sur la pile d'appels (call stack). Quand le cas de base est atteint, les appels sont dépilés dans l'ordre inverse.

🥞
Analogie — La pile de crêpes : Chaque appel récursif = une crêpe posée sur la pile. On ne peut manger (résoudre) que la crêpe du dessus. Le cas de base = la dernière crêpe posée (la première mangée). C'est le principe LIFO (Last In, First Out).
⚠️
Stack Overflow ! Si la récursion est trop profonde (pas de cas de base ou progression insuffisante), la pile déborde → erreur Stack Overflow. C'est l'équivalent de la boucle infinie pour les boucles.

8.4 — Fibonacci

Suite : 0, 1, 1, 2, 3, 5, 8, 13, 21… Chaque terme = somme des 2 précédents.

Fonction Fibo(n : Entier) : Entier Début Si n = 0 Alors Retourner 0 // Cas de base 1 SinonSi n = 1 Alors Retourner 1 // Cas de base 2 Sinon Retourner Fibo(n-1) + Fibo(n-2) // Deux appels récursifs ! FinSi Fin
⚠️
Attention : La version récursive de Fibonacci est très lente car elle recalcule les mêmes valeurs des millions de fois ! Fibo(5) appelle Fibo(3) deux fois, Fibo(2) trois fois… Complexité exponentielle O(2ⁿ). En pratique, on préfère la version itérative.

8.5 — Récursif vs Itératif

CritèreRécursifItératif
LisibilitéSouvent plus élégantPlus explicite
MémoirePile d'appels (coûteux)Variables en boucle
PerformancePeut être lent (Fibonacci)Généralement plus rapide
RisqueStack OverflowBoucle infinie
🧠
Mnémo : Tout algorithme récursif peut être réécrit en itératif (et vice-versa). La récursivité est un outil, pas une obligation. Utilise-la quand le problème est naturellement récursif (arbres, fractales, diviser pour régner).

Exercices guidés — La Récursivité

🎯 Fibonacci récursif — Arbre d'appels

Énoncé : Calculer fib(5) et tracer l'arbre des appels récursifs.

Étape 1 — La fonction
FONCTION fib(n : ENTIER) : ENTIER
    SI n ≤ 1 ALORS
        RETOURNER n           // Cas de base
    SINON
        RETOURNER fib(n-1) + fib(n-2)  // Appel récursif
    FIN SI
FIN FONCTION
Étape 2 — Arbre d'appels pour fib(5)
                fib(5)
              /                  fib(4)        fib(3)
         /     \        /           fib(3)  fib(2)  fib(2)  fib(1)
      /   \    /  \    /  \      |
  fib(2) fib(1) fib(1) fib(0) fib(1) fib(0) → 1
   / \     |      |      |      |
fib(1) fib(0)  → 1    → 1    → 0    → 1
  |      |
→ 1    → 0
Étape 3 — Remonter les résultats
fib(0) = 0, fib(1) = 1
fib(2) = fib(1) + fib(0) = 1 + 0 = 1
fib(3) = fib(2) + fib(1) = 1 + 1 = 2
fib(4) = fib(3) + fib(2) = 2 + 1 = 3
fib(5) = fib(4) + fib(3) = 3 + 2 = 5 ✓

⚠️ Problème : fib(2) est calculé 3 fois ! La complexité est O(2ⁿ). Solution : mémoïsation ou version itérative.

🎯 Puissance récursive rapide

Énoncé : Calculer 3⁸ avec l'exponentiation rapide (diviser l'exposant par 2).

Algorithme
FONCTION puissance(x, n : ENTIER) : ENTIER
    SI n = 0 ALORS RETOURNER 1
    SI n est pair ALORS
        demi ← puissance(x, n/2)
        RETOURNER demi × demi
    SINON
        RETOURNER x × puissance(x, n-1)
    FIN SI
FIN FONCTION

8.6 — Résumé

🎯 Aide-mémoire

  • Récursif = une fonction qui s'appelle elle-même
  • 2 règles d'or : Base + Progression
  • Factorielle : fact(0)=1, fact(n)=n×fact(n-1)
  • Fibonacci : fibo(0)=0, fibo(1)=1, fibo(n)=fibo(n-1)+fibo(n-2)
  • Pile d'appels : LIFO (crêpes)
  • Stack Overflow : quand il manque le cas de base

Méthode : Écrire une Fonction Récursive

Étape 1 : Identifier le cas de base (condition d'arrêt)

  • Quel est le cas le plus simple ? Ex: n = 0, tableau vide, chaîne vide
  • Quelle valeur retourner ? Ex: fact(0) = 1, fib(0) = 0

Étape 2 : Identifier la réduction du problème

  • Comment le problème de taille n se ramène à un problème de taille n−1 ?
  • Ex: fact(n) = n × fact(n−1), fib(n) = fib(n−1) + fib(n−2)

Étape 3 : Vérifier la terminaison

  • Chaque appel récursif doit se rapprocher du cas de base
  • Si n diminue à chaque appel → terminaison garantie ✅
  • Sinon → boucle infinie (Stack Overflow) ⚠️

Étape 4 : Tracer à la main avec n petit

  • Dépiler les appels pour vérifier le résultat
  • Ex: fact(3) → 3×fact(2) → 3×2×fact(1) → 3×2×1×fact(0) → 3×2×1×1 = 6 ✅

Checklist mnémotechnique : B.R.T.

  • Base — Le cas d'arrêt est défini
  • Réduction — Chaque appel réduit le problème
  • Test — Vérifier à la main avec un petit exemple
