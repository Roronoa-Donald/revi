Chapitre 2

σ Algèbre relationnelle

Sélection, projection, jointure, union… — les opérations théoriques avant le SQL.

Objectifs du chapitre

  • Maîtriser les opérations de l'algèbre relationnelle
  • Appliquer sélection, projection et jointure
  • Combiner union, intersection et différence

Pourquoi l'algèbre relationnelle ?

🔧 Analogie AutoBot : L'algèbre relationnelle, c'est la recette de cuisine que suit le SGBD. Le SQL est la commande au restaurant, l'algèbre est ce que le chef fait en cuisine pour préparer le plat.

L'algèbre relationnelle est le langage théorique qui décrit les opérations sur les tables. Le SQL est sa traduction pratique. Comprendre l'algèbre aide à prédire le résultat d'une requête SQL complexe.

Opérations unaires (1 table)

🧠 Mnémonique S.P.R.

Sélection (σ) — Projection (π) — Renommage (ρ)

Les 3 opérations qui s'appliquent à UNE seule table.

σ — Sélection (sigma)

Filtre les lignes selon une condition. Garde les tuples qui satisfont le critère.

Sélection
σ_age>20 (ETUDIANTS)
→ Garde uniquement les étudiants de plus de 20 ans

En SQL : SELECT * FROM ETUDIANTS WHERE age > 20;
💡 Moyen mnémotechnique : σ = Sigma = Sélection = on Sépare les lignes qui passent le filtre.

π — Projection (pi)

Sélectionne des colonnes. Ne garde que les attributs demandés.

Projection
π_nom,prenom (ETUDIANTS)
→ Garde uniquement les colonnes nom et prenom

En SQL : SELECT nom, prenom FROM ETUDIANTS;
🔧 Analogie : σ = filtre horizontal (lignes). π = filtre vertical (colonnes). Ensemble, ils découpent la table comme un cutter dans les deux directions.

ρ — Renommage (rho)

Change le nom d'une relation ou d'un attribut.

Renommage
ρ_E (ETUDIANTS)      → la table s'appelle maintenant E
ρ_surname/nom (E)    → l'attribut nom s'appelle surname

En SQL : SELECT nom AS surname FROM ETUDIANTS E;

Opérations ensemblistes (2 tables)

🧠 Mnémonique U.I.D.P.

Union (∪) — Intersection (∩) — Différence (−) — Produit cartésien (×)

⚠️ Condition de compatibilité : Pour Union, Intersection et Différence, les deux tables doivent avoir le même schéma (mêmes attributs, mêmes types).

Les 4 opérations

OpérationSymboleRésultatSQL
Union∪Toutes les lignes de R1 + R2 (sans doublons)UNION
Intersection∩Lignes communes à R1 et R2INTERSECT
Différence−Lignes de R1 absentes de R2EXCEPT
Produit cartésien×Toutes les combinaisons (R1 × R2)CROSS JOIN
Exemples
ETUDIANTS_PARIS ∪ ETUDIANTS_LYON    → tous les étudiants
ETUDIANTS_PARIS ∩ ETUDIANTS_LYON    → étudiants inscrits aux deux
ETUDIANTS_PARIS − ETUDIANTS_LYON    → étudiants SEULEMENT à Paris

Si R1 a 3 lignes et R2 a 4 lignes :
R1 × R2 → 3 × 4 = 12 lignes (toutes les combinaisons)
⚠️ Attention : Le produit cartésien seul est rarement utile — il « explose » le nombre de lignes. On l'utilise TOUJOURS avec une sélection (→ jointure).

Les jointures

La jointure combine deux tables en utilisant une condition de liaison (généralement PK = FK).

🔧 Analogie : Imagine deux listes Excel — ETUDIANTS et NOTES. Tu veux voir les notes avec le nom de l'étudiant. La jointure « colle » les deux listes en faisant correspondre l'id_etudiant.

Types de jointures

TypeSymboleDescription
Theta-jointure⋈_θProduit cartésien + sélection sur condition θ
Equi-jointure⋈=Theta-jointure où θ est une égalité (=)
Jointure naturelle⋈Equi-jointure sur TOUS les attributs communs (même nom)
Jointure — Algèbre vs SQL
Algèbre :  ETUDIANTS ⋈ (id_etu = id_etudiant) NOTES
SQL     :  SELECT * FROM ETUDIANTS
            JOIN NOTES ON ETUDIANTS.id_etu = NOTES.id_etudiant;

Jointure naturelle :
Algèbre :  ETUDIANTS ⋈ NOTES  (si même nom d'attribut)
SQL     :  SELECT * FROM ETUDIANTS NATURAL JOIN NOTES;
🧠 Formule de la jointure

R1 ⋈_θ R2 = σ_θ (R1 × R2)

Jointure = Produit cartésien + Sélection. C'est du « filtrage après combinaison » !

La division (÷)

Opération la plus complexe : R1 ÷ R2 retourne les tuples de R1 associés à TOUS les tuples de R2.

🔧 Analogie : « Quels étudiants sont inscrits à TOUS les cours ? » — La division répond à cette question du « pour tout ».
Exemple
INSCRIPTIONS(id_etu, id_cours)    ÷    COURS(id_cours)
= Les étudiants inscrits à TOUS les cours

SQL (pas de mot-clé direct, on passe par NOT EXISTS) :
SELECT id_etu FROM INSCRIPTIONS I
WHERE NOT EXISTS (
    SELECT id_cours FROM COURS C
    WHERE NOT EXISTS (
        SELECT 1 FROM INSCRIPTIONS I2
        WHERE I2.id_etu = I.id_etu AND I2.id_cours = C.id_cours
    )
);

Arbre algébrique

On représente une requête complexe sous forme d'arbre :

  • Feuilles = relations (tables sources)
  • Nœuds internes = opérations (σ, π, ⋈, ∪…)
  • Racine = résultat final
Exemple : π_nom (σ_note>15 (ETUDIANTS ⋈ NOTES))
        π_nom
          │
      σ_note>15
          │
          ⋈
         / \
   ETUDIANTS  NOTES

Lecture bottom-up :
1. Tables sources → ETUDIANTS et NOTES
2. Jointure → combine les deux
3. Sélection → filtre note > 15
4. Projection → ne garde que le nom
💡 Optimisation : Descendre les σ (sélections) le plus bas possible dans l'arbre réduit le volume de données traitées → requête plus rapide !

Exercices guidés

Enchaîner sélection, projection et jointure

Tables :

EMPLOYE(NumEmp, Nom, Salaire, NumDept)
| 1   | Dupont  | 2800 | 10 |
| 2   | Martin  | 3200 | 20 |
| 3   | Durand  | 2500 | 10 |
| 4   | Petit   | 3500 | 30 |

DEPARTEMENT(NumDept, NomDept, Ville)
| 10 | Compta  | Paris |
| 20 | Info    | Lyon  |
| 30 | RH      | Paris |

Question : Trouver les noms des employés parisiens gagnant plus de 2700 €.

Étape 1 — Jointure
R1 = EMPLOYE ⋈ DEPARTEMENT (sur NumDept)
→ Combine chaque employé avec son département
Étape 2 — Sélection (σ)
R2 = σ(Ville='Paris' ET Salaire > 2700)(R1)
→ Garde : Dupont (2800, Compta/Paris) et Petit (3500, RH/Paris)
→ Élimine : Martin (Lyon), Durand (2500 < 2700)
Étape 3 — Projection (π)
R3 = π(Nom)(R2)
→ Résultat : { Dupont, Petit } ✓

Différence et division relationnelles

Question : Quels étudiants ont validé TOUS les modules ?

VALIDATION(NumEtu, CodeModule)
| E1 | M1 |    MODULE(CodeModule)
| E1 | M2 |    | M1 |
| E1 | M3 |    | M2 |
| E2 | M1 |    | M3 |
| E2 | M3 |
| E3 | M1 |
Division : VALIDATION ÷ MODULE
Pour chaque étudiant, vérifier s'il a TOUS les modules :
  E1 : {M1, M2, M3} ⊇ {M1, M2, M3} ? OUI ✓
  E2 : {M1, M3}     ⊇ {M1, M2, M3} ? NON (M2 manque)
  E3 : {M1}         ⊇ {M1, M2, M3} ? NON (M2, M3 manquent)

→ Résultat : { E1 } ✓
