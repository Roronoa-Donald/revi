Les Jointures en SQL

🔧 Analogie AutoBot : Imagine deux feuilles de calcul : ETUDIANTS et NOTES. La jointure, c'est le ruban adhésif qui colle les deux feuilles côte à côte en faisant correspondre l'identifiant étudiant.
🧠 Mnémonique I.L.R.F.C.

INNER — LEFT — RIGHT — FULL — CROSS

Les 5 types de JOIN en SQL.

INNER JOIN (jointure interne)

Retourne uniquement les lignes qui ont une correspondance dans les DEUX tables.

INNER JOIN
SELECT e.nom, e.prenom, n.matiere, n.note
FROM etudiants e
INNER JOIN notes n ON e.id = n.id_etudiant;

-- Résultat : seuls les étudiants ayant des notes apparaissent

LEFT JOIN (jointure gauche)

Toutes les lignes de la table gauche + les correspondances à droite (NULL si pas de match).

LEFT JOIN
SELECT e.nom, n.note
FROM etudiants e
LEFT JOIN notes n ON e.id = n.id_etudiant;

-- Les étudiants SANS notes apparaissent aussi (note = NULL)

RIGHT JOIN, FULL JOIN, CROSS JOIN

TypeGardeUsage
INNER JOINCorrespondances uniquementLe plus courant (90%)
LEFT JOINTout à gauche + correspondancesVoir les lignes « orphelines »
RIGHT JOINTout à droite + correspondancesRare (inverser l'ordre suffit)
FULL JOINTout des deux côtésVoir toutes les données
CROSS JOINProduit cartésienRarement utile tel quel
💡 Astuce : En cas de doute, commence toujours par un INNER JOIN. Si tu veux voir les lignes sans correspondance, passe au LEFT JOIN.

Fonctions d'agrégation

🧠 Mnémonique C.S.A.M.M.

COUNT — SUM — AVG — MAX — MIN

Les 5 fonctions d'agrégation principales.

Fonctions d'agrégation
SELECT COUNT(*) FROM etudiants;              -- nombre total de lignes
SELECT COUNT(email) FROM etudiants;           -- nb de emails non-NULL
SELECT SUM(prix) FROM commandes;              -- somme des prix
SELECT AVG(note) FROM notes;                  -- moyenne des notes
SELECT MAX(age), MIN(age) FROM etudiants;     -- plus vieux et plus jeune
⚠️ COUNT(*) vs COUNT(col) : COUNT(*) compte toutes les lignes y compris NULL. COUNT(col) ne compte que les lignes où col n'est PAS NULL.

GROUP BY & HAVING

🔧 Analogie : GROUP BY = trier des billes par couleur puis compter chaque tas. HAVING = ne garder que les tas de plus de 5 billes.
GROUP BY + HAVING
-- Nombre d'étudiants par ville
SELECT ville, COUNT(*) AS nb
FROM etudiants
GROUP BY ville;

-- Moyenne des notes par matière, seulement si moyenne > 12
SELECT matiere, AVG(note) AS moy
FROM notes
GROUP BY matiere
HAVING AVG(note) > 12;

-- Combiné : combien de commandes par client, ceux avec plus de 3
SELECT id_client, COUNT(*) AS nb_cmd, SUM(montant) AS total
FROM commandes
GROUP BY id_client
HAVING COUNT(*) > 3
ORDER BY total DESC;
🧠 WHERE vs HAVING

WHERE filtre les lignes individuelles AVANT le regroupement.
HAVING filtre les groupes APRÈS le regroupement.

Retiens : Where → aVant | Having → aPrès

Sous-requêtes

Une sous-requête (ou requête imbriquée) est un SELECT à l'intérieur d'un autre SELECT.

Sous-requêtes
-- Dans WHERE : étudiants plus vieux que la moyenne
SELECT nom, age FROM etudiants
WHERE age > (SELECT AVG(age) FROM etudiants);

-- Avec IN : étudiants ayant au moins une note
SELECT nom FROM etudiants
WHERE id IN (SELECT DISTINCT id_etudiant FROM notes);

-- Avec EXISTS : étudiants qui ont des commandes
SELECT nom FROM etudiants e
WHERE EXISTS (SELECT 1 FROM commandes c WHERE c.id_client = e.id);

-- Dans FROM (table dérivée)
SELECT ville, moy FROM (
    SELECT ville, AVG(age) AS moy FROM etudiants GROUP BY ville
) AS stats
WHERE moy > 20;

IN vs EXISTS

OpérateurUsagePerformance
INPetite liste de valeursBon pour sous-requêtes courtes
EXISTSVérifier l'existenceMeilleur pour grandes tables
NOT IN⚠️ Piège avec NULL !Préférer NOT EXISTS
⚠️ Piège NOT IN : Si la sous-requête retourne un NULL parmi les résultats, NOT IN ne retourne RIEN. Utiliser NOT EXISTS à la place.

Exercices guidés

JOIN + GROUP BY + HAVING

Tables : COMMANDE(id, date, id_client) et LIGNE_CMD(id_cmd, id_prod, qte, prix_unit)

Question : Quels clients ont dépensé plus de 500 € au total ?

Étape 1 — Jointure
SELECT c.id_client, SUM(l.qte * l.prix_unit) AS total
FROM COMMANDE c
JOIN LIGNE_CMD l ON c.id = l.id_cmd
Étape 2 — Grouper par client
GROUP BY c.id_client
Étape 3 — Filtrer les groupes
HAVING SUM(l.qte * l.prix_unit) > 500;
Requête complète et résultat
SELECT c.id_client, SUM(l.qte * l.prix_unit) AS total
FROM COMMANDE c
JOIN LIGNE_CMD l ON c.id = l.id_cmd
GROUP BY c.id_client
HAVING total > 500
ORDER BY total DESC;

-- | id_client | total  |
-- | C003      | 1250.00|
-- | C001      |  780.50|
WHERE vs HAVING : WHERE filtre les lignes AVANT le GROUP BY, HAVING filtre les groupes APRÈS.

Sous-requêtes imbriquées

Question : Trouver les employés qui gagnent plus que la moyenne de leur département.

SELECT e.nom, e.salaire, e.num_dept
FROM EMPLOYE e
WHERE e.salaire > (
    SELECT AVG(e2.salaire)
    FROM EMPLOYE e2
    WHERE e2.num_dept = e.num_dept
);

-- Explication pas à pas :
-- 1. Pour chaque employé, la sous-requête calcule
--    la moyenne du département correspondant
-- 2. Dept 10 : moyenne = (2800+2500)/2 = 2650
--    → Dupont (2800) > 2650 ✓
--    → Durand (2500) < 2650 ✗
-- 3. Dept 20 : moyenne = 3200/1 = 3200
--    → Martin (3200) = 3200 ✗ (pas strictement >)
