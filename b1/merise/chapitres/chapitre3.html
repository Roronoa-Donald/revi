Module 3

Modèle Logique de Données (MLD)

Du MCD au MLD : traduire le modèle conceptuel en tables relationnelles avec clés primaires et clés étrangères.

Objectifs du chapitre

  • Appliquer les règles de passage MCD → MLD
  • Transformer les associations selon leur cardinalité
  • Vérifier la cohérence du MLD obtenu

I. Qu'est-ce que le MLD ?

Définition

Le Modèle Logique de Données (MLD) est la traduction du MCD en un ensemble de tables relationnelles. Il se situe au niveau logique de MERISE, entre le MCD (niveau conceptuel) et le MPD (niveau physique). Le MLD prépare l'implémentation concrète dans un SGBD relationnel (MySQL, PostgreSQL, Oracle…).

Vocabulaire MCD ↔ MLD

Niveau Conceptuel (MCD)Niveau Logique (MLD)
EntitéTable (ou Relation)
PropriétéAttribut (ou Colonne)
IdentifiantClé primaire (PK)
Occurrencen-uplet (ligne / enregistrement)

🏗️ Analogie : MCD = vision de l'architecte, MLD = plan de construction

Imaginez la construction d'une maison :

  • Le MCD = le dessin de l'architecte. Il montre les pièces (entités), les portes entre elles (associations), sans se soucier des matériaux.
  • Le MLD = le plan technique du maçon. Il traduit la vision en tables, colonnes, clés étrangères — des éléments concrets qu'un SGBD peut construire.
  • Le MPD = la maison terminée. C'est le MLD adapté à un SGBD précis (MySQL, PostgreSQL…) avec les types de données, index, etc.

On ne construit jamais une maison sans plan. On ne crée jamais une base de données sans MCD → MLD ! 📐

II. Clé Primaire et Clé Étrangère

Clé primaire (PK — Primary Key)

La clé primaire est l'attribut (ou combinaison d'attributs) qui identifie de manière unique chaque enregistrement d'une table. Elle correspond à l'identifiant de l'entité dans le MCD. Elle est obligatoire (non nulle) et unique.

Clé étrangère (FK — Foreign Key)

La clé étrangère est un attribut d'une table qui fait référence à la clé primaire d'une autre table. Elle matérialise le lien entre deux tables et garantit l'intégrité référentielle (toute valeur de FK doit exister dans la table référencée).

Notation du MLD : 
COMMANDE (Num_cmd, Date_cmd, #Code_client)
Num_cmd est la clé primaire (soulignée).
#Code_client est la clé étrangère (précédée de #), référençant CLIENT.

III. Les 3 Règles de Passage MCD → MLD

La transformation du MCD en MLD obéit à 3 règles qui dépendent des cardinalités des associations.

Règle 1 — Association (x,1) – (x,n)

Cas : L'une des entités a une cardinalité maximale de 1 (soit 0,1 soit 1,1).

→ Chaque entité devient une table. La clé primaire de l'entité côté n migre comme clé étrangère dans la table côté 1.

Exemple — MCD

MLD résultant

SERVICE (Num_serv, Nom_serv)

Astuce : La FK va toujours du côté 1 vers le côté n. Pensez : « Employé a cardinalité (1,1) → c'est lui qui reçoit la FK du Service. »

Règle 2 — Association (x,n) – (x,n)

Cas : Les deux entités ont une cardinalité maximale de n.

→ Chaque entité devient une table. L'association devient une table supplémentaire dont la clé primaire est la concaténation des clés primaires des entités participantes. Les propriétés portées par l'association deviennent des attributs de cette table.

Exemple — MCD

MLD résultant

COMMANDE (Num_cmd, Date_cmd)
PRODUIT (Code_produit, Désignation, Prix_HT)
CONCERNER (#Num_cmd, #Code_produit, Quantité)
La table CONCERNER a une clé primaire composée formée des deux clés étrangères. « Quantité » est un attribut normal de cette table d'association.

Règle 3 — Association (1,1) – (1,1)

Cas : Les deux entités ont une cardinalité exactement (1,1).

→ On fusionne les deux entités en une seule table, ou on envoie la FK dans la table la plus logique (souvent la table « dépendante »). Ce cas est rare en pratique.
Attention : Une association (1,1)–(1,1) signifie souvent que les deux entités pourraient en être une seule. Revoir les règles de gestion avant de conclure !

IV. Récapitulatif des Règles

Cardinalité maxTransformationClé étrangère ?
x,1 — x,n FK côté 1 Oui, la PK du côté n va dans la table côté 1
x,n — x,n Table d'association Oui, la PK = concaténation des deux FK
1,1 — 1,1 Fusion ou FK Selon le contexte métier

V. Exemple Complet — MCD vers MLD

Énoncé

Une entreprise gère ses formations internes.
RG1 : Un formateur anime plusieurs sessions. Chaque session est animée par un seul formateur.
RG2 : Une session concerne exactement une formation. Une formation peut avoir plusieurs sessions.
RG3 : Un employé participe à plusieurs sessions. Une session accueille plusieurs employés (avec une note d'évaluation).

MLD final

Vérification : SESSION reçoit 2 clés étrangères (ANIMER et PORTER_SUR = deux fois règle 1). PARTICIPER est une table d'association avec clé composée + attribut Note_eval (règle 2).
🧠 Mnémotechnique — MCD → MLD : les 3 règles d'or
« Règle 1-2-3 : Chaque cardinalité max dit ce qu'il faut faire »
  • Règle 1 (x,1 — x,n) → La clé du côté « n » migre comme clé étrangère vers le côté « 1 »
  • Règle 2 (x,n — x,n) → L'association devient une table d'association avec clé composée
  • Règle 3 (0,1 — 1,1) → On peut fusionner les deux entités en une seule table

« Le n envoie sa clé vers le 1. Si c'est n-n, on crée une table pont. »

Exercice guidé

Transformer un MCD en MLD — Règles de passage

MCD donné :

ÉTUDIANT ——(1,n)—— INSCRIPTION ——(0,n)—— MODULE
   |                  |Date, Note|
   NumEtu             CodeModule
   Nom                Libelle
   Prenom             Coeff
Règle 1 — Entités → Tables
ÉTUDIANT(NumEtu, Nom, Prenom)    → clé primaire : NumEtu
MODULE(CodeModule, Libelle, Coeff) → clé primaire : CodeModule
Règle 2 — Association N:M → Table de jonction
Cardinalités : (1,n) côté ÉTUDIANT, (0,n) côté MODULE
→ C'est du N:M → créer une table de jonction

INSCRIPTION(NumEtu#, CodeModule#, Date, Note)
  Clé primaire : (NumEtu, CodeModule)
  NumEtu# → réf. ÉTUDIANT
  CodeModule# → réf. MODULE
Règle 3 — Association 1:N → Migration de clé
Si on avait eu une cardinalité (1,1):
  ÉTUDIANT ——(1,1)—— INSCRIRE ——(1,n)—— CLASSE
  → La clé migre côté (1,1) :
  ÉTUDIANT(NumEtu, Nom, Prenom, NumClasse#)

Résumé des règles :
  1:1 → fusionner ou migrer au choix
  1:N → clé étrangère côté "1" (ou "1,1")
  N:M → table de jonction avec clé composite
