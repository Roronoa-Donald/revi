Chapitre 1

🌐 Modèle OSI & Introduction

Comprendre les 7 couches du modèle OSI — la base de tout réseau.

Objectifs du chapitre

  • Identifier les types de réseaux (LAN, WAN, MAN)
  • Comprendre les topologies physiques et logiques
  • Connaître les couches du modèle OSI et TCP/IP

Qu'est-ce qu'un réseau ?

🏘️ Analogie du quartier

Un réseau informatique c'est comme un quartier de maisons reliées par des routes. Chaque maison (ordinateur) a une adresse. Les routes (câbles/Wi-Fi) permettent d'envoyer des colis (données). La poste (protocoles) s'assure que le bon colis arrive à la bonne maison.

ℹ️ Types de réseaux :
  • LAN (Local Area Network) — réseau local (école, bureau)
  • WAN (Wide Area Network) — réseau étendu (Internet)
  • MAN (Metropolitan Area Network) — échelle ville

Le modèle OSI — 7 couches

🧠 Mnémonique « Pour Le Réseau, Tout Se Passe Automatiquement »

De la couche 7 (haut) à la couche 1 (bas) :
Physique · Liaison · Réseau · Transport · Session · Présentation · Application
(ou de bas en haut : P-L-R-T-S-P-A)

Encapsulation

📦 Analogie des poupées russes

Quand un ordinateur envoie des données, chaque couche emballe les données dans une enveloppe (en-tête). C'est comme des poupées russes : les données sont au centre, et chaque couche ajoute sa propre enveloppe autour.

Le processus d'encapsulation
Application     → Données
Transport       → [En-tête TCP] + Données = Segment
Réseau          → [En-tête IP] + Segment = Paquet
Liaison         → [En-tête MAC] + Paquet + [FCS] = Trame
Physique        → Bits sur le câble (010110...)
💡 Astuce : À la réception, c'est l'inverse = désencapsulation. Chaque couche enlève son en-tête et passe au-dessus.

Zoom sur les couches essentielles

Couche 1 — Physique 🔌

Les « routes » du réseau : câbles RJ45 (cuivre), fibre optique (lumière), ondes Wi-Fi. Elle transforme les bits en signaux électriques/lumineux.

Couche 2 — Liaison 🔗

Utilise les adresses MAC (uniques pour chaque carte réseau). Le switch travaille à cette couche. Format MAC : AA:BB:CC:DD:EE:FF (6 octets en hexadécimal).

Couche 3 — Réseau 🗺️

Utilise les adresses IP pour le routage. Le routeur travaille à cette couche. Il choisit le meilleur chemin pour les paquets.

Couche 4 — Transport 🚛

TCP (fiable, lent) vs UDP (rapide, non fiable). Utilise les numéros de port (ex: HTTP = 80, HTTPS = 443).

Noms des PDU par couche

Chaque couche manipule une unité de données (PDU – Protocol Data Unit) portant un nom spécifique. Connaître ces noms est incontournable en examen.

PDU à chaque couche OSI
Couche 7 – Application   → Données  (Data)
Couche 6 – Présentation  → Données  (Data)
Couche 5 – Session        → Données  (Data)
Couche 4 – Transport      → Segment  (TCP) / Datagramme (UDP)
Couche 3 – Réseau         → Paquet   (Packet)
Couche 2 – Liaison        → Trame    (Frame)
Couche 1 – Physique       → Bits     (0 et 1)

🧠 Mnémonique « Des Singes Tapent Pas Très Bien »

Données → Segment → Trame… Non ! Attention à l'ordre :
Données (L7-L5) → Segment (L4) → Paquet (L3) → Trame (L2) → Bits (L1)
Retenir : D – S – P – T – B = « Des Singes Pas Très Beaux »

Couches 5, 6 et 7 en détail

CoucheRôleExemples concrets
7 – ApplicationInterface entre l'utilisateur et le réseauHTTP, FTP, SMTP, DNS, DHCP
6 – PrésentationTraduction, chiffrement, compressionSSL/TLS, JPEG, ASCII ↔ Unicode
5 – SessionOuverture/fermeture/synchronisation des sessionsNetBIOS, RPC, sessions web (cookies)
💡 Astuce examen : En pratique, le modèle TCP/IP fusionne L5+L6+L7 en une seule couche « Application ». Mais en QCM sur l'OSI, chaque couche compte !

Pièges classiques

⚠️ Piège 1 – Confondre Trame et Paquet : Une trame (L2) contient des adresses MAC. Un paquet (L3) contient des adresses IP. En examen, si on vous dit « Ethernet », c'est de la couche 2 (trame). Si on dit « routage », c'est couche 3 (paquet).
⚠️ Piège 2 – L'ordre des couches : La couche 1 est en bas (physique, câbles). La couche 7 est en haut (l'application). L'envoi descend de 7→1, la réception remonte de 1→7.
⚠️ Piège 3 – « 7 couches OSI » ≠ « 4 couches TCP/IP » : Ne pas mélanger les deux modèles ! OSI = théorique (7 couches). TCP/IP = pratique (4 couches). Un QCM peut tester les deux.

Encapsulation : suivre une requête web

Scénario : Un navigateur envoie une requête HTTP à google.com. Décrire l'encapsulation.

Couche 7 (Application) : Données HTTP
  → Le navigateur crée la requête "GET / HTTP/1.1"

Couche 4 (Transport) : Segment TCP
  → Ajout : port source (49152) + port dest (80)
  → En-tête TCP + Données HTTP

Couche 3 (Réseau) : Paquet IP
  → Ajout : IP source (192.168.1.10) + IP dest (142.250.74.46)
  → En-tête IP + Segment TCP

Couche 2 (Liaison) : Trame Ethernet
  → Ajout : MAC source + MAC dest (gateway) + FCS
  → En-tête Ethernet + Paquet IP + Trailer

Couche 1 (Physique) : Bits
  → La trame est convertie en signaux électriques/optiques
  → Transmission sur le câble !

Récapitulatif

📝 L'essentiel du Chapitre 1

  • Un réseau = machines connectées qui communiquent
  • LAN (local), WAN (étendu), MAN (métropolitain)
  • OSI = 7 couches : P-L-R-T-S-P-A
  • Encapsulation = chaque couche ajoute un en-tête
  • Couche 2 = MAC + switch · Couche 3 = IP + routeur
  • Couche 4 = TCP (fiable) / UDP (rapide)
