Chapitre 2

🌐 TCP/IP & Modèle Internet

Le modèle pratique qui fait tourner Internet : 4 couches, TCP vs UDP, ports.

Objectifs du chapitre

  • Comprendre les supports de transmission (cuivre, fibre, sans fil)
  • Connaître les normes Ethernet et le câblage structuré
  • Identifier débits, bande passante et atténuation

OSI vs TCP/IP

📚 Analogie : Théorie vs Pratique

OSI = le modèle théorique (7 couches, parfait sur papier). TCP/IP = le modèle pratique (4 couches, utilisé en vrai sur Internet). TCP/IP fusionne les couches 5-6-7 d'OSI en une seule couche « Application ».

OSI (7 couches)TCP/IP (4 couches)Protocoles
7. Application
6. Présentation
5. Session		ApplicationHTTP, FTP, DNS, SMTP
4. TransportTransportTCP, UDP
3. RéseauInternetIP, ICMP, ARP
2. Liaison
1. Physique		Accès réseauEthernet, Wi-Fi

🧠 Mnémonique A.T.I.A.

Application · Transport · Internet · Accès réseau — les 4 couches TCP/IP de haut en bas.

TCP vs UDP

📬 Analogie du courrier

TCP = lettre recommandée avec accusé de réception : on sait qu'elle est arrivée, mais c'est plus lent.
UDP = carte postale : rapide et simple, mais aucune garantie d'arrivée.

CritèreTCPUDP
Fiabilité✅ Fiable (ACK)❌ Non fiable
ConnexionConnecté (3-way handshake)Non connecté
OrdreGarantiNon garanti
VitessePlus lentPlus rapide
UsageWeb, email, FTPStreaming, jeux, DNS

Le 3-Way Handshake (TCP)

Ouverture de connexion TCP
Client → Serveur :  SYN        (« Je veux parler »)
Serveur → Client :  SYN-ACK    (« OK, moi aussi »)
Client → Serveur :  ACK        (« C'est parti ! »)

🤝 Après ces 3 étapes, la connexion est établie !
💡 Astuce : Pensez à un coup de fil : « Allô ? — Oui allô ! — Parfait, parlons ! » = SYN, SYN-ACK, ACK.

Les ports

🏢 Analogie de l'immeuble

L'adresse IP = le bâtiment. Le port = le numéro d'appartement. Un serveur peut héberger plusieurs services (web, email, FTP) sur la même IP, chacun sur un port différent.

PortProtocoleService
80HTTPWeb (non sécurisé)
443HTTPSWeb (sécurisé)
22SSHConnexion distante sécurisée
53DNSRésolution de noms
25SMTPEnvoi d'email
21FTPTransfert de fichiers
67/68DHCPAttribution d'IP auto
⚠️ Plages de ports : 0-1023 = ports « bien connus » (réservés) · 1024-49151 = enregistrés · 49152-65535 = dynamiques/privés

Les flags TCP en détail

L'en-tête TCP contient 6 flags (drapeaux) qui contrôlent l'état de la connexion :

FlagNom completRôle
SYNSynchronizeInitier une connexion
ACKAcknowledgeConfirmer la réception
FINFinishTerminer proprement la connexion
RSTResetForcer la fermeture (erreur ou refus)
PSHPushEnvoyer immédiatement sans attendre le buffer
URGUrgentDonnées prioritaires à traiter en premier
Fermeture de connexion TCP (4-Way Teardown)
Client → Serveur :  FIN        (« J'ai fini d'envoyer »)
Serveur → Client :  ACK        (« Bien reçu »)
Serveur → Client :  FIN        (« Moi aussi j'ai fini »)
Client → Serveur :  ACK        (« OK, connexion fermée »)

🔚 La connexion est proprement fermée des deux côtés !
💡 Ouverture = 3 étapes (SYN, SYN-ACK, ACK). Fermeture = 4 étapes (FIN, ACK, FIN, ACK). C'est asymétrique car chaque côté ferme indépendamment.

Le concept de Socket

🔌 Qu'est-ce qu'un socket ?

Un socket = une combinaison unique Adresse IP + Port. C'est le « point de rencontre » entre deux machines pour communiquer.

Exemple de connexion par sockets
Votre navigateur :  192.168.1.50:54321  (IP locale + port dynamique)
        ↕
Serveur web :       93.184.216.34:443   (IP serveur + port HTTPS)

Socket client = 192.168.1.50:54321
Socket serveur = 93.184.216.34:443

→ La paire de sockets identifie UNIQUEMENT cette connexion !
ℹ️ Un serveur peut avoir des milliers de sockets ouverts simultanément, tous sur le même port (ex: 443) mais avec des clients différents.

Pièges classiques

⚠️ Piège 1 – TCP vs UDP : TCP = fiable, connexion, accusés de réception (web, email, fichiers). UDP = rapide, sans connexion, pas de garantie (streaming, DNS, jeux en ligne). Un QCM peut demander « quel protocole pour le streaming ? » → UDP !
⚠️ Piège 2 – « TCP/IP a 4 couches, pas 5 » : Certains manuels montrent 5 couches (en séparant Liaison et Physique). Le modèle TCP/IP officiel en a 4 : Accès réseau, Internet, Transport, Application.
⚠️ Piège 3 – Port ≠ Protocole : Le port 80 est associé à HTTP mais n'est pas HTTP. On peut faire tourner un serveur web sur le port 8080 ou n'importe quel port.

Exercices guidés

TCP vs UDP — Choisir le bon protocole

Énoncé : Pour chaque application, quel protocole de transport utiliser ?

ApplicationProtocoleJustification
Navigation web (HTTP)TCPLes pages doivent arriver complètes et dans l'ordre
Streaming vidéo en directUDPVitesse prioritaire, perte d'une image acceptable
Envoi d'email (SMTP)TCPLe message doit arriver intégralement
Jeu en ligne (FPS)UDPLatence minimale, un paquet perdu = 1 frame
DNS (résolution de nom)UDPRequête courte, réponse courte, pas besoin de connexion
Transfert de fichiers (FTP)TCPIntégrité du fichier essentielle
Règle simple : Si perdre un paquet = problème grave → TCP. Si la vitesse prime et qu'une perte est tolérable → UDP.

Le handshake TCP en 3 étapes

Scénario : Un client (192.168.1.10) se connecte au serveur web (10.0.0.1:80).

Étape 1 — SYN (Client → Serveur)
  Client envoie : SYN, Seq=100
  "Je veux me connecter, mon numéro de séquence est 100"

Étape 2 — SYN-ACK (Serveur → Client)
  Serveur répond : SYN-ACK, Seq=300, Ack=101
  "D'accord, mon numéro est 300, j'attends ton paquet 101"

Étape 3 — ACK (Client → Serveur)
  Client confirme : ACK, Seq=101, Ack=301
  "Reçu ! J'envoie 101, j'attends ton 301"

→ Connexion établie ! Échange de données possible ✓
Déconnexion (4 étapes) :
  Client → FIN → Serveur
  Serveur → ACK → Client
  Serveur → FIN → Client
  Client → ACK → Serveur → Connexion fermée

Récapitulatif

📝 L'essentiel du Chapitre 2

  • TCP/IP = 4 couches : A.T.I.A. (Application, Transport, Internet, Accès)
  • TCP = fiable + lent · UDP = rapide + non fiable
  • 3-way handshake : SYN → SYN-ACK → ACK
  • Ports = n° d'appartement (80=HTTP, 443=HTTPS, 22=SSH, 53=DNS)
