Chapitre 5

🌐 Protocoles courants

HTTP, DNS, DHCP, ARP, ICMP — les protocoles qui font tourner Internet.

Objectifs du chapitre

  • Découper un réseau en sous-réseaux (VLSM, CIDR)
  • Calculer plage d'adresses, broadcast et nombre d'hôtes
  • Optimiser un plan d'adressage

HTTP / HTTPS — Le Web

🌐 Analogie du serveur au restaurant

Vous (le client/navigateur) passez une commande (requête HTTP) au serveur. Il prépare le plat (la page web) et vous le sert (réponse HTTP). HTTPS = le même restaurant mais avec un rideau (chiffrement TLS) pour que personne n'espionne votre commande.

Requête / Réponse HTTP
Client → Serveur :  GET /index.html HTTP/1.1
                    Host: www.example.com

Serveur → Client :  HTTP/1.1 200 OK
                    Content-Type: text/html
                    <html>...</html>

Codes de statut :
  200 = OK          301 = Redirection
  404 = Not Found   500 = Erreur serveur

DNS — Le GPS d'Internet

📱 Analogie du répertoire téléphonique

Vous ne retenez pas les numéros de téléphone, vous cherchez « Alice » dans vos contacts. Le DNS fait pareil : il traduit les noms (google.com) en adresses IP (142.250.75.14). Sans DNS, il faudrait taper des IP partout !

Résolution DNS
1. Vous tapez "www.google.com" dans le navigateur
2. Le PC demande au serveur DNS : "Quelle IP pour google.com ?"
3. Le DNS répond : "142.250.75.14"
4. Le navigateur contacte 142.250.75.14

Types d'enregistrements DNS :
  A     → nom → IPv4
  AAAA  → nom → IPv6
  CNAME → alias vers un autre nom
  MX    → serveur mail du domaine
  NS    → serveur DNS du domaine
💡 Port : DNS utilise le port 53 (UDP pour les requêtes courantes, TCP pour les transferts de zone).

DHCP — IP automatique

🏨 Analogie de l'hôtel

Quand vous arrivez à l'hôtel, la réception vous attribue un numéro de chambre. Le DHCP fait pareil : il attribue automatiquement une adresse IP à chaque appareil qui se connecte au réseau.

🧠 Mnémonique D.O.R.A. (processus DHCP)

Discover → Offer → Request → Ack
Le client cherche, le serveur propose, le client demande, le serveur confirme.

ARP — Trouver l'adresse MAC

📢 Analogie du « Qui habite ici ? »

Vous connaissez l'adresse (IP) mais pas le nom du résident (MAC). ARP crie dans le réseau : « Qui a l'IP 192.168.1.5 ? ». L'appareil concerné répond : « C'est moi ! Mon MAC est AA:BB:CC:DD:EE:FF ».

ℹ️ ARP travaille entre couche 2 et 3. Il traduit une adresse IP → adresse MAC. Les résultats sont stockés dans la table ARP (cache) pour ne pas redemander à chaque fois.

ICMP — Diagnostic réseau

ICMP en pratique
# ping — tester la connectivité
ping 8.8.8.8          # Teste si Google DNS est joignable
ping www.google.com   # Teste DNS + connectivité

# traceroute — voir le chemin
tracert www.google.com   # (Windows)
traceroute www.google.com # (Linux/Mac)
→ Affiche chaque routeur traversé

Protocoles de messagerie en détail

L'email utilise 3 protocoles qu'il ne faut pas confondre :

ProtocolePortDirectionRôle
SMTP25 / 587Envoi →Envoyer un email (client → serveur, serveur → serveur)
POP3110 / 995← RéceptionTélécharge les mails puis les supprime du serveur
IMAP143 / 993← RéceptionSynchronise les mails, les garde sur le serveur

📮 Analogie postale

SMTP = le facteur qui dépose la lettre au bureau de poste.
POP3 = vous allez chercher la lettre et la ramenez chez vous (le bureau ne la garde plus).
IMAP = vous lisez la lettre au bureau de poste, elle reste là pour être relue depuis d'autres endroits.

💡 IMAP vs POP3 : Aujourd'hui, IMAP est le standard (Gmail, Outlook…) car on consulte ses mails sur plusieurs appareils. POP3 est utile si on veut une copie locale unique.

La hiérarchie DNS

Le DNS fonctionne comme un annuaire distribué organisé en arbre hiérarchique :

Résolution DNS pas à pas : www.google.com
1. Votre PC vérifie son cache DNS local
2. Si pas en cache → demande au serveur DNS récursif (FAI)
3. Récursif interroge un serveur racine (".")  → "Allez voir .com"
4. Récursif interroge le serveur TLD .com       → "Allez voir ns.google.com"
5. Récursif interroge le serveur autoritaire de google.com
   → "www.google.com = 142.250.179.68"
6. Réponse renvoyée au PC + mise en cache (TTL)

Hiérarchie :
  . (racine)  →  .com / .fr / .org (TLD)  →  google.com (domaine)  →  www (sous-domaine)
ℹ️ Il existe 13 serveurs racine (de A à M), répartis mondialement via Anycast. Ils sont le point de départ de toute résolution DNS non mise en cache.

Pièges classiques

⚠️ Piège 1 – SMTP ≠ réception : SMTP sert à envoyer. Pour recevoir, c'est POP3 ou IMAP. Un QCM avec « quel protocole pour relever ses mails ? » → jamais SMTP !
⚠️ Piège 2 – FTP utilise 2 ports : Le port 21 (commandes) ET le port 20 (données en mode actif). Ne pas oublier le port 20 en examen !
⚠️ Piège 3 – DHCP utilise UDP, pas TCP : DHCP fonctionne en broadcast (le client n'a pas encore d'IP !). Il utilise UDP sur les ports 67 (serveur) et 68 (client).

Résolution DNS pas à pas

Scénario : L'utilisateur tape www.example.com dans son navigateur.

1. Cache local → "www.example.com" trouvé ? NON

2. Fichier hosts (/etc/hosts ou C:\Windows\...\hosts)
   → Entrée trouvée ? NON

3. Requête au serveur DNS configuré (ex: 8.8.8.8)

4. DNS récursif : le serveur interroge la hiérarchie
   a) Serveur racine (.) → "Demandez à .com"
   b) Serveur TLD (.com) → "Demandez au NS de example.com"
   c) Serveur autoritaire (example.com) → "IP = 93.184.216.34"

5. Réponse : www.example.com = 93.184.216.34
   → Mise en cache (TTL = 3600s = 1h)

6. Le navigateur contacte 93.184.216.34 sur le port 443 (HTTPS)
