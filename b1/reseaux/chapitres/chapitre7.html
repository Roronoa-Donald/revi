Chapitre 7

🌐 Sécurité réseau

Pare-feu, VPN, chiffrement, et les attaques les plus courantes.

Objectifs du chapitre

  • Comprendre la triade C.I.D. (Confidentialité, Intégrité, Disponibilité)
  • Différencier chiffrement symétrique et asymétrique
  • Connaître pare-feu, VPN, IDS/IPS et les attaques courantes

La triade C.I.D.

🧠 Mnémonique C.I.D. — les 3 piliers de la sécurité

Confidentialité — seules les personnes autorisées accèdent aux données
Intégrité — les données ne sont pas modifiées en transit
Disponibilité — les services restent accessibles

Chiffrement

🔐 Analogie du coffre-fort

Chiffrement symétrique = un coffre avec une seule clé (même clé pour chiffrer et déchiffrer). Rapide mais il faut partager la clé.
Chiffrement asymétrique = deux clés : une publique (cadenas ouvert) et une privée (la clé du cadenas). Plus sûr pour l'échange de clés.

TypeClésVitesseExemples
Symétrique1 clé partagéeRapideAES, DES, 3DES
Asymétrique2 clés (pub/priv)LentRSA, ECC
💡 HTTPS combine les deux : asymétrique pour échanger la clé, puis symétrique (AES) pour chiffrer les données — le meilleur des deux mondes !

Hachage (Hashing)

🔒 Empreinte digitale des données

Le hachage transforme des données de n'importe quelle taille en une empreinte fixe (hash). C'est irréversible : on ne peut pas retrouver les données depuis le hash.

Algorithmes de hachage
MD5     → 128 bits (32 hex) — obsolète, vulnérable aux collisions
SHA-1   → 160 bits (40 hex) — obsolète depuis 2017
SHA-256 → 256 bits (64 hex) — standard actuel ✓
SHA-512 → 512 bits (128 hex)

Exemple SHA-256 :
"bonjour" → 2c89d40cb16b6c0db5c35bc35cf75b98...
"Bonjour" → 6e340b9cffb37a989ca544e6bb780a2c...
↑ Un seul caractère change → hash complètement différent !
UsageExplication
Stockage de mots de passeOn stocke le hash, jamais le mot de passe en clair
Intégrité des fichiersVérifier qu'un fichier n'a pas été modifié (checksum)
Signatures numériquesProuver l'authenticité d'un message
Certificats SSL/TLSVérifier l'identité d'un site web

SSL/TLS et certificats

🤝 Le handshake HTTPS simplifié

Quand vous visitez un site HTTPS, voici ce qui se passe :

  1. Le navigateur demande le certificat du serveur
  2. Le certificat contient la clé publique du serveur (signée par une autorité de confiance CA)
  3. Le navigateur vérifie le certificat auprès du CA
  4. Échange de clé symétrique via chiffrement asymétrique
  5. Communication chiffrée en AES (symétrique, rapide)
ℹ️ CA (Certificate Authority) : Autorité de confiance qui signe les certificats (Let's Encrypt, DigiCert, Verisign). Le cadenas dans le navigateur = certificat valide.

Pare-feu et ACL

Règles de pare-feu (exemples)
ACL = Access Control List (liste de règles ordonnées)

Règle    Action    Protocole    Source          Dest Port    Description
1        ALLOW     TCP          192.168.1.0/24  80,443       Web (HTTP/HTTPS)
2        ALLOW     TCP          192.168.1.0/24  22           SSH admin
3        ALLOW     UDP          Any             53           DNS
4        DENY      TCP          Any             23           Bloquer Telnet
5        DENY      ALL          Any             Any          Tout le reste bloqué

→ Les règles sont évaluées dans l'ordre : première correspondance gagne.
→ Toujours terminer par un DENY ALL implicite.
💡 Principe du moindre privilège : Bloquer tout par défaut, puis ouvrir uniquement ce qui est nécessaire. C'est la philosophie « deny by default, allow by exception ».

DMZ (Zone démilitarisée)

🏰 Architecture de sécurité

La DMZ est une zone réseau entre Internet et le réseau interne, protégée par deux pare-feu :

  • Internet → [Pare-feu 1] → DMZ (serveurs web, mail) → [Pare-feu 2] → Réseau interne

Si un serveur DMZ est compromis, l'attaquant ne peut pas atteindre le réseau interne grâce au 2e pare-feu.

IDS vs IPS

SystèmeRôleAction
IDS (Intrusion Detection)Détecte les activités suspectesAlerte l'administrateur (passif)
IPS (Intrusion Prevention)Détecte ET bloque les attaquesBloque automatiquement (actif)
ℹ️ Analogie : IDS = caméra de surveillance (observe et alerte). IPS = gardien (observe et intervient).

VPN — Le tunnel sécurisé

🚇 Analogie du tunnel

Un VPN crée un tunnel chiffré entre votre appareil et un serveur distant. Toutes vos données passent par ce tunnel : personne ne peut les lire, même sur un Wi-Fi public.

ℹ️ Protocoles VPN : IPSec (couche 3), OpenVPN (SSL/TLS), WireGuard (moderne, rapide). Le VPN d'entreprise permet de travailler depuis chez soi comme si on était au bureau.

Attaques courantes

AttaqueDescriptionProtection
PhishingFaux emails/sites pour voler des identifiantsVigilance, 2FA
DDoSSubmerger un serveur de requêtesCDN, pare-feu, rate limiting
Man-in-the-MiddleIntercepter les communicationsHTTPS, VPN
ARP SpoofingFausser les tables ARP pour intercepterARP statique, VLAN
Brute ForceTester toutes les combinaisons de mots de passeMots de passe forts, verrouillage
DNS PoisoningRediriger vers un faux site via DNSDNSSEC, DNS sécurisé

Pièges classiques à l'examen

⚠️ Piège n°1 — IDS vs IPS : L'IDS (Intrusion Detection System) détecte et alerte seulement — il est passif. L'IPS (Intrusion Prevention System) bloque activement le trafic malveillant. Ne les confondez pas !
⚠️ Piège n°2 — Symétrique vs Asymétrique : Symétrique = 1 seule clé (rapide, pour chiffrer les données). Asymétrique = 2 clés publique/privée (lent, pour l'échange de clés et les signatures). TLS utilise les deux !
⚠️ Piège n°3 — Ordre des ACL : Les règles d'un pare-feu sont évaluées dans l'ordre, première correspondance gagne. Si un « deny all » est en première position, tout est bloqué même si des « permit » suivent.

Configurer les règles d'un pare-feu

Scénario : Protéger un serveur web (192.168.1.10) en autorisant seulement HTTP/HTTPS et SSH.

Règle 1 : AUTORISER TCP entrant vers port 80  (HTTP)
Règle 2 : AUTORISER TCP entrant vers port 443 (HTTPS)
Règle 3 : AUTORISER TCP entrant vers port 22  (SSH)
           source : 10.0.0.0/24 uniquement (admin)
Règle 4 : BLOQUER tout le reste (deny all)

Ordre important ! Les règles sont évaluées de haut en bas.
La règle "deny all" doit être en DERNIER.
En notation iptables (Linux) :
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT
iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 22 -j ACCEPT
iptables -A INPUT -j DROP
