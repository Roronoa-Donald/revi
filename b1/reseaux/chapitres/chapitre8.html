Le Wi-Fi — Réseau sans fil

📡 Analogie de la radio

Le Wi-Fi fonctionne comme une radio : le routeur est l'émetteur et vos appareils sont les récepteurs. Les données voyagent par ondes radio au lieu de câbles.

ℹ️ IEEE 802.11 est le standard qui définit le Wi-Fi. Chaque lettre (a, b, g, n, ac, ax) est une version avec des améliorations.

📻 2.4 GHz vs 5 GHz

2.4 GHz = longue portée mais plus lent et encombré (micro-ondes, Bluetooth…)
5 GHz = courte portée mais plus rapide et moins d'interférences
Analogie : 2.4 GHz = autoroute large mais embouteillée, 5 GHz = voie rapide moins encombrée.

Commandes réseau essentielles

🧠 Mnémonique PINTA — Les 5 commandes à retenir

Ping — Ipconfig — Nslookup — Tracert — Arp

1. ipconfig / ifconfig

# Windows
ipconfig
ipconfig /all         # détails complets
ipconfig /release     # libérer l'IP DHCP
ipconfig /renew       # renouveler l'IP DHCP
ipconfig /flushdns    # vider le cache DNS

# Linux/Mac
ifconfig
ip addr show          # version moderne

2. ping

# Tester la connectivité (envoi de paquets ICMP)
ping google.com
ping 192.168.1.1      # tester la passerelle
ping 127.0.0.1        # tester la carte réseau locale (loopback)
💡 Diagnostic rapide : ping 127.0.0.1 OK → carte réseau OK. ping passerelle OK → réseau local OK. ping google.com OK → Internet OK.

3. tracert / traceroute

# Voir tous les routeurs traversés pour atteindre une destination
tracert google.com       # Windows
traceroute google.com    # Linux/Mac

4. nslookup / dig

# Résoudre un nom de domaine en IP (interrogation DNS)
nslookup google.com
nslookup -type=MX google.com    # serveurs mail

# Linux alternative
dig google.com

5. netstat / ss

# Voir les connexions réseau actives et les ports ouverts
netstat -an              # Windows
netstat -tulpn           # Linux (TCP/UDP, ports, processus)
ss -tulpn                # Linux moderne

6. arp

# Afficher la table ARP (correspondance IP ↔ MAC)
arp -a

Diagnostic réseau — méthode pas à pas

🔍 La méthode « de bas en haut » (bottom-up)

Quand Internet ne marche pas, on teste couche par couche :

  1. Couche 1 (Physique) — Le câble est branché ? Le Wi-Fi est activé ?
  2. Couche 2 (Liaison) — ipconfig montre-t-il une adresse IP ?
  3. Couche 3 (Réseau) — ping 127.0.0.1 puis ping passerelle
  4. Couche 4+ (Transport) — ping 8.8.8.8 puis ping google.com

Si ping 8.8.8.8 OK mais ping google.com échoue → problème DNS !

💡 Le réflexe universel : Quand rien ne marche, testez ping 8.8.8.8 — c'est le serveur DNS de Google, toujours accessible. S'il répond, Internet fonctionne mais c'est peut-être un problème DNS.

Scénario de diagnostic complet

Un utilisateur se plaint : « Je n'arrive pas à accéder à un site web ». Voici la démarche systématique :

Diagnostic en 5 étapes
Étape 1 : Vérifier la couche physique
  → Le câble est branché ? Le Wi-Fi est activé ?
  → ipconfig (Windows) / ip addr (Linux) → IP obtenue ?

Étape 2 : Tester la connectivité locale
  → ping 127.0.0.1      (loopback = pile TCP/IP OK ?)
  → ping [ma passerelle] (ex: 192.168.1.1 = routeur joignable ?)

Étape 3 : Tester la connectivité Internet
  → ping 8.8.8.8         (serveur Google = Internet OK ?)

Étape 4 : Tester la résolution DNS
  → ping google.com      (si échec mais 8.8.8.8 OK = problème DNS)
  → nslookup google.com  (vérifier quel serveur DNS répond)

Étape 5 : Tester le service
  → tracert google.com   (où le paquet se bloque-t-il ?)
  → Vérifier pare-feu, proxy, port bloqué

🧠 Mnémonique « De Bas en Haut »

Toujours diagnostiquer de la couche 1 vers la couche 7 :
Câble → IP → Passerelle → Internet → DNS → Application
Comme un médecin : on vérifie d'abord le pouls avant de faire une radio !

Pièges classiques

⚠️ Piège 1 – « Pas d'Internet » ≠ « Pas de réseau » : Si ping vers la passerelle fonctionne mais pas vers 8.8.8.8, le réseau local est OK. Le problème est en amont (routeur, FAI).
⚠️ Piège 2 – SSID caché ≠ sécurisé : Masquer le nom du Wi-Fi n'empêche personne de le détecter (des outils le voient quand même). La vraie sécurité = WPA3 + mot de passe fort.
⚠️ Piège 3 – 2.4 GHz vs 5 GHz : Si un QCM demande « quelle fréquence pour traverser les murs ? » → 2.4 GHz (meilleure portée). Pour le débit max → 5 GHz. Wi-Fi 6E ajoute le 6 GHz (débit++, portée--).

Exercices guidés

Diagnostiquer un problème réseau

Scénario : Un PC ne peut pas accéder à www.google.com. Diagnostic méthodique.

Étape 1 — Vérifier la configuration IP
> ipconfig (Windows) / ip addr (Linux)
→ IP : 192.168.1.50  ✓ (pas d'APIPA 169.254.x.x)
→ Masque : 255.255.255.0  ✓
→ Passerelle : 192.168.1.1  ✓
→ DNS : 8.8.8.8  ✓
Étape 2 — Tester la connectivité locale
> ping 192.168.1.1   (passerelle)
→ Réponse OK ✓ → Le réseau local fonctionne
Étape 3 — Tester la connectivité Internet
> ping 8.8.8.8   (serveur Google DNS)
→ Réponse OK ✓ → Internet fonctionne !
Étape 4 — Tester la résolution DNS
> ping www.google.com
→ "Impossible de résoudre le nom" ❌
→ Problème = DNS !
Solution
> nslookup www.google.com 8.8.8.8
→ Fonctionne avec 8.8.8.8 mais pas avec le DNS local

Solution : changer le serveur DNS
ou vider le cache : ipconfig /flushdns
