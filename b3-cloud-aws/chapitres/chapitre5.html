Chapitre 5 — Stockage & Données — Amazon S3, EFS, RDS & NoSQL DynamoDB

Module 5 ≈ 2 h 45 Réservé B3 et plus
Mise en situation

L'architecture de votre plateforme web doit traiter des téraoctets de données non structurées, assurer la persistance partagée de médias, et gérer simultanément des transactions financières relationnelles critiques et un catalogue produit à très faible latence. Vous devez concevoir la stratégie de stockage hybride : compartiments Amazon S3 sécurisés avec règles de cycle de vie et Block Public Access, système de fichiers partagé Amazon EFS, cluster Amazon RDS PostgreSQL Multi-AZ avec répliques de lecture, et table Amazon DynamoDB dimensionnée en RCU/WCU.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. Maîtriser le stockage objet Amazon S3 : classes de stockage (Standard, IA, Glacier Deep Archive), règles de cycle de vie et durabilité de 99.999999999%.
  2. Sécuriser les données S3 avec S3 Block Public Access, le versioning, les Bucket Policies et le chiffrement au repos AWS KMS.
  3. Distinguer le stockage bloc (EBS), le stockage fichier partagé (EFS) et le stockage objet (S3) selon leurs cas d'usage.
  4. Concevoir des bases de données relationnelles Amazon RDS / Aurora (Multi-AZ vs Read Replicas) et dimensionner des tables NoSQL DynamoDB (RCU, WCU, modes de cohérence).

1. Amazon S3 : Stockage Objet & Classes de Stockage

Amazon Simple Storage Service (S3) est le service de stockage objet distribué d'AWS, conçu pour offrir une durabilité de 99.999999999% (11 neuf) en répliquant automatiquement les objets sur plusieurs centres de données physiques d'une région :

Concepts Fondamentaux d'Amazon S3

  • Buckets (Compartiments) : conteneurs logiques racines de niveau mondial dont le nom doit être unique à l'échelle planétaire.
  • Objets & Clés : un fichier est un objet constitué d'une clé (chemin complet ex: images/logo.png), de données brutes (jusqu'à 5 To par objet) et de métadonnées.
  • Échelle illimitée : aucun provisionnement de capacité requis, volume total illimité avec paiement au gigaoctet réel.

La Hiérarchie des Classes de Stockage

  • S3 Standard : haute disponibilité (99.99%), accès ultra-rapide (ms) pour données fréquemment consultées.
  • S3 Intelligent-Tiering : déplace automatiquement les objets entre tiers d'accès fréquent et rare sans frais d'extraction.
  • S3 Standard-IA : coût de stockage réduit de 50%, facturation des frais d'accès/extraction pour sauvegardes à consultation rare.
  • S3 Glacier Flexible Retrieval : archivage à bas coût, récupération en quelques minutes ou 3 à 5 heures.
  • S3 Glacier Deep Archive : classe la plus économique d'AWS (~1 $/To/mois), récupération en 12 à 48 heures pour archivage légal long terme.

2. Sécurité S3 : Block Public Access, Versioning & Chiffrement KMS

Amazon S3 intègre de multiples verrous pour prévenir la fuite accidentelle de données d'entreprise :

S3 Block Public Access

Garde-fou centralisé activé par défaut au niveau du compte et des buckets.

Bloque et ignore immédiatement toute ACL ou politique de compartiment (Bucket Policy) qui tenterait d'accorder un accès anonyme ou public aux objets.

Versioning & MFA Delete

Conserve l'historique complet de toutes les versions d'un objet (créations, modifications, marqueurs de suppression).

Protège contre les suppressions accidentelles et les attaques de ransomwares. MFA Delete exige un code d'authentification physique pour supprimer définitivement une version.

Chiffrement au Repos (SSE)

Tout nouvel objet dans S3 est obligatoirement chiffré au repos :

  • SSE-S3 : clés gérées par S3 (AES-256), gratuit et transparent.
  • SSE-KMS : clés gérées par AWS Key Management Service (audit CloudTrail et contrôle d'accès granulaire).

3. Système de Fichiers Partagé Amazon EFS (Elastic File System)

Amazon EFS fournit un système de fichiers élastique sans serveur basé sur le protocole standard NFS v4 :

  • Accès concurrent multi-instances : contrairement à EBS qui est lié à une seule VM dans une seule AZ, EFS peut être monté simultanément sur des centaines d'instances EC2 et conteneurs ECS/Fargate répartis sur plusieurs AZs.
  • Croissance et décroissance automatique : s'étend et se rétracte automatiquement à mesure que des fichiers sont ajoutés ou supprimés sans interruption.
  • Cas d'usage types : répertoires de médias partagés pour CMS (WordPress, Drupal), systèmes de gestion de contenu d'entreprise et répertoires personnels de serveurs Linux.

4. Bases Relationnelles Amazon RDS & Amazon Aurora

Amazon Relational Database Service (RDS) automatise l'administration des moteurs relationnels (PostgreSQL, MySQL, MariaDB, Oracle, SQL Server) :

Déploiement Multi-AZ (Haute Disponibilité)

  • Réplication synchrone vers une instance Standby passive située dans une Availability Zone distincte.
  • En cas de défaillance matérielle ou de panne d'AZ primaire, AWS bascule automatiquement (Failover) le point de terminaison DNS vers le Standby en 60 à 120 secondes sans perte de données.
  • L'instance Standby ne traite aucune requête client (dédiée exclusivement à la reprise).

Read Replicas (Montée en Charge Lecture)

  • Réplication asynchrone vers jusqu'à 15 instances de lecture dédiées (pouvant être situées dans d'autres AZs ou d'autres régions).
  • Déleste l'instance primaire des requêtes de consultation lourdes (reporting, requêtes de recherche) pour préserver les performances d'écriture.

Amazon Aurora : moteur relationnel propriétaire AWS compatible MySQL et PostgreSQL, offrant jusqu'à 5 fois les performances de MySQL standard. Il s'appuie sur un système de stockage cloud natif qui réplique automatiquement 6 copies des données sur 3 Availability Zones avec basculement ultra-rapide (< 30 secondes).

5. Bases NoSQL Managées : Amazon DynamoDB & Capacité RCU/WCU

Amazon DynamoDB est une base de données NoSQL clé-valeur et document entièrement gérée, offrant des temps de réponse inférieurs à 10 millisecondes à n'importe quelle échelle :

Structure de Données & Clés

  • Partition Key (Clé de hachage) : détermine la partition physique où l'élément est stocké.
  • Sort Key (Clé de tri) : facultative, permet d'indexer plusieurs éléments sous une même clé de partition (clé composite).
  • Schéma flexible : chaque élément peut posséder des attributs différents, sans contrainte de schéma rigide.

Dimensionnement RCU & WCU

  • RCU (Read Capacity Unit) : 1 RCU = 1 lecture fortement cohérente par seconde pour un item jusqu'à 4 KB (ou 2 lectures éventuellement cohérentes).
  • WCU (Write Capacity Unit) : 1 WCU = 1 écriture standard par seconde pour un item jusqu'à 1 KB.
  • Mode On-Demand : allocation et facturation automatique à la requête sans aucun provisionnement préalable, idéal pour les charges imprévisibles.

Exercice 1 — Calculateur de Coûts & Cycle de Vie Amazon S3 (Standard vs Glacier)

Étude de cas Niveau 1 — Acquisition

Objectif : Calculer les coûts de stockage mensuels d'un volume de données selon la classe de stockage S3 choisie.

Amazon S3 propose plusieurs classes de stockage avec un compromis entre coût au Go et frais d'accès :

Tarifs indicatifs de stockage par GiB et par mois :
- STANDARD : 0.023 $ / GiB (accès instantané, aucun frais de récupération).
- STANDARD_IA (Infrequent Access) : 0.0125 $ / GiB + 0.01 $ / GiB récupéré.
- GLACIER_FLEXIBLE : 0.0036 $ / GiB + 0.03 $ / GiB récupéré (restauration en quelques minutes à plusieurs heures).
- DEEP_ARCHIVE : 0.00099 $ / GiB + 0.05 $ / GiB récupéré (restauration en 12 à 48 heures).

Entrée STDIN :
S3_COST SIZE_GIB=<g> CLASS=<CLASSE> RETRIEVE_GIB=<r>.

Sortie :
S3_BILL: class=<cls> storage_cost=<sc:.2f>$ retrieval_cost=<rc:.2f>$ total_cost=<tot:.2f>$.

Cas d’exemple
S3_COST SIZE_GIB=1000 CLASS=STANDARD RETRIEVE_GIB=500
Résolution attendue
S3_BILL: class=STANDARD storage_cost=23.00$ retrieval_cost=0.00$ total_cost=23.00$

Cas d'usage nominal.

Exercice 2 — Validateur de Nom de Bucket S3 & Détecteur de Risques Publics

Étude de cas Niveau 2 — Application

Objectif : Vérifier la conformité syntaxique globale d'un nom de bucket S3 et auditer les paramètres S3 Block Public Access.

Les règles de nommage universelles d'Amazon S3 imposent des contraintes strictes :

1. Règles de nom de bucket :
- Longueur comprise entre 3 et 63 caractères inclus.
- Uniquement lettres minuscules, chiffres, points . et tirets -.
- Doit obligatoirement commencer et se terminer par une lettre ou un chiffre.
- Ne doit pas ressembler à une adresse IP décimale à 4 octets (ex: 192.168.1.1).
- Ne doit pas comporter deux points adjacents (..) ni de points et tirets contigus (.- ou -.).

2. Audit de sécurité (S3 Block Public Access) :
Les 4 paramètres doivent être à true : BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets.
Si l'un d'eux est à false -> statut de risque EXPOSED, sinon SECURE.

Entrée STDIN :
S3_AUDIT BUCKET=<nom> BPA=<bpa1,bpa2,bpa3,bpa4>.

Sortie :
Si nom valide : BUCKET_AUDIT: bucket=<nom> name_status=VALID security_status=<SECURE|EXPOSED>.
Si nom invalide : BUCKET_AUDIT: bucket=<nom> name_status=INVALID reason=<BAD_LENGTH|BAD_CHARS|BAD_EDGES|IP_FORMAT|BAD_DOT_DASH>.

Cas d’exemple
S3_AUDIT BUCKET=mon-bucket-prod-2026 BPA=true,true,true,true
Résolution attendue
BUCKET_AUDIT: bucket=mon-bucket-prod-2026 name_status=VALID security_status=SECURE

Exercice 3 — Calculateur de Capacité Provisionnée Amazon DynamoDB (RCU & WCU)

Étude de cas Niveau 3 — Raisonnement

Objectif : Calculer précisément les unités de capacité de lecture (RCU) et d'écriture (WCU) requises pour une table DynamoDB.

Dans Amazon DynamoDB, la capacité provisionnée se calcule selon la taille d'élément et le mode de cohérence :

1. Calcul des Read Capacity Units (RCU) :
- Unité de base : blocs de 4 KB arrondis au supérieur : Blocs_R = math.ceil(Item_Size_KB / 4.0) (ou 1 si size <= 4).
- Mode EVENTUAL (Éventuellement cohérent) : 0.5 RCU par lecture par seconde :
RCU = Blocs_R * Reads_Sec * 0.5.
- Mode STRONG (Fortement cohérent) : 1 RCU par lecture par seconde :
RCU = Blocs_R * Reads_Sec * 1.0.
- Mode TRANSACTIONAL (Lectures transactionnelles) : 2 RCU par lecture par seconde :
RCU = Blocs_R * Reads_Sec * 2.0.
Arrondir le RCU final à l'entier supérieur : math.ceil(RCU).

2. Calcul des Write Capacity Units (WCU) :
- Unité de base : blocs de 1 KB arrondis au supérieur : Blocs_W = math.ceil(Item_Size_KB / 1.0).
- Mode STANDARD : 1 WCU par écriture par seconde :
WCU = Blocs_W * Writes_Sec * 1.0.
- Mode TRANSACTIONAL : 2 WCU par écriture par seconde :
WCU = Blocs_W * Writes_Sec * 2.0.

Entrée STDIN :
DYNAMO_CAP SIZE_KB=<k> READS_SEC=<r> WRITES_SEC=<w> READ_MODE=<EVENTUAL|STRONG|TRANSACTIONAL> WRITE_MODE=<STANDARD|TRANSACTIONAL>.

Sortie : DYNAMO_SIZING: size=<k>KB rcu=<rcu> wcu=<wcu>.

Cas d’exemple
DYNAMO_CAP SIZE_KB=3.5 READS_SEC=100 WRITES_SEC=50 READ_MODE=EVENTUAL WRITE_MODE=STANDARD
Résolution attendue
DYNAMO_SIZING: size=3.5KB rcu=50 wcu=200

7. QCM — niveau examen

Quelle durabilité théorique des données Amazon S3 garantit-il en répliquant automatiquement chaque objet sur au moins 3 Availability Zones ?

Amazon S3 Standard est conçu pour offrir une durabilité de 99.999999999% (11 neuf) sur un an en distribuant les copies d'objets sur plusieurs centres de données indépendants.

Quelle classe de stockage Amazon S3 offre le tarif au Go le plus bas pour des archives légales à long terme nécessitant un délai de récupération de 12 à 48 heures ?

S3 Glacier Deep Archive est la classe de stockage la plus économique du cloud (~0.00099 $/Go/mois), idéale pour la conformité et la rétention réglementaire sur 7 à 10 ans.

Quelle technologie de stockage AWS permet à des dizaines d'instances EC2 réparties dans plusieurs Availability Zones d'accéder simultanément au même système de fichiers partagé en NFS v4 ?

Amazon EFS est un système de fichiers partagé basé sur le protocole NFS v4 qui peut être monté simultanément sur des centaines d'instances réparties sur plusieurs AZs.

Dans une architecture de base de données Amazon RDS PostgreSQL, quelle est la fonction principale d'un déploiement Multi-AZ ?

Le déploiement Multi-AZ assure la haute disponibilité en maintenant une réplique synchrone passive dans une autre zone. En cas de panne de l'instance primaire, le basculement est automatique.

Combien de Read Capacity Units (RCU) sont nécessaires dans Amazon DynamoDB pour réaliser 100 lectures fortement cohérentes (Strongly Consistent) par seconde sur des éléments de 3.5 KB ?

Un élément de 3.5 KB tient dans un bloc de 4 KB (math.ceil(3.5/4) = 1). Pour une lecture fortement cohérente, 1 lecture = 1 RCU. Donc 100 lectures/sec * 1 RCU = 100 RCU.

Quel mécanisme de sécurité Amazon S3 neutralise formellement toute tentative de rendre un bucket ou des objets publics, même si une politique permissive est appliquée ?

S3 Block Public Access fournit des paramètres centralisés appliqués au niveau du compte ou du bucket qui écrasent et ignorent toute règle permissive publique (ACL ou Bucket Policy).

Quelle caractéristique distingue Amazon Aurora par rapport aux moteurs de bases de données RDS traditionnels (MySQL standard) ?

Amazon Aurora est un moteur cloud natif qui sépare le calcul et le stockage. Son système de stockage distribué réplique 6 copies des blocs sur 3 AZs avec un basculement ultra-rapide.

Pour protéger les objets S3 contre les suppressions accidentelles et les ransomwares en conservant l'historique des modifications, quelle fonctionnalité doit être activée ?

Le versioning S3 conserve toutes les variantes d'un objet (création, écrasement, suppression). Une suppression place simplement un Delete Marker, permettant de restaurer la version antérieure.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Créer un compartiment S3 avec un nom contenant des majuscules ou des underscores (le nom doit respecter strictement le format DNS minuscule).
  • Penser qu'un Standby RDS Multi-AZ peut être utilisé pour accélérer les requêtes de lecture de l'application (seules les Read Replicas traitent des lectures).
  • Sous-estimer les frais de récupération (retrieval fees) des classes S3 Standard-IA et Glacier lors de restaurations massives fréquentes.
  • Oublier de provisionner suffisamment de WCU sur DynamoDB, entraînant des erreurs de dépassement de quota de débit (ProvisionedThroughputExceededException).

9. Méthodologie de résolution

Démarche de Sélection & Dimensionnement des Données
  1. Classification des données : séparer les objets non structurés (fichiers, images, logs vers S3), le stockage bloc attaché (OS et I/O intensives vers EBS), les fichiers partagés (EFS) et les données structurées (RDS ou DynamoDB).
  2. Définition des règles de cycle de vie S3 : configurer des transitions automatiques vers S3 Standard-IA après 30 jours, vers Glacier Flexible après 90 jours et suppression des anciennes versions après 365 jours.
  3. Activation des protections de conformité : verrouiller l'ensemble des compartiments avec S3 Block Public Access et exiger le chiffrement systématique par clé KMS managée.
  4. Arbitrage relationnel vs NoSQL : opter pour RDS Multi-AZ / Aurora si des requêtes SQL complexes et jointures ACID sont requises, ou pour DynamoDB pour des charges de microservices à volumétrie massive et latence sub-milliseconde.

10. Révision active

Résumé essentiel
  • Amazon S3 fournit un stockage objet mondial hautement durable (99.999999999%), organisé en compartiments et objets avec hiérarchie de classes économiques (Standard, IA, Glacier).
  • La sécurité S3 repose sur S3 Block Public Access, le versioning d'objets contre les ransomwares et le chiffrement transparent SSE-S3 / SSE-KMS.
  • Amazon EFS offre un système de fichiers partagé NFS v4 montable simultanément par des centaines d'instances et conteneurs sur plusieurs zones de disponibilité.
  • Amazon RDS garantit la haute disponibilité via la réplication synchrone Multi-AZ (basculement automatique) et la scalabilité des lectures via Read Replicas asynchrones.
  • Amazon DynamoDB est une base NoSQL serverless ultra-rapide dimensionnée par unités de capacité de lecture (RCU) et d'écriture (WCU) ou en mode On-Demand.

Checklist de maîtrise

  • Savez-vous choisir la classe de stockage S3 optimale selon la fréquence d'accès et les contraintes budgétaires ?
  • Comprenez-vous le rôle des 4 options de S3 Block Public Access pour empêcher les fuites de données ?
  • Distinguez-vous parfaitement les cas d'usage d'Amazon EBS (mono-AZ/bloc), Amazon EFS (multi-AZ/NFS) et Amazon S3 (régional/objet) ?
  • Pouvez-vous expliquer la différence entre un déploiement RDS Multi-AZ et une réplique en lecture (Read Replica) ?
  • Savez-vous calculer les RCU et WCU nécessaires pour une table DynamoDB selon la taille des éléments et le mode de cohérence ?

Les 8 notions à connaître absolument

  1. Amazon S3 : Simple Storage Service : service de stockage objet distribué mondial à durabilité extrême (11 neuf).
  2. Durabilité 11 neuf (99.999999999%) : Probabilité théorique de ne perdre qu'un seul objet sur 10 millions stockés sur une période de 10 000 ans.
  3. S3 Block Public Access : Mécanisme centralisé neutralisant toute politique ou ACL rendant un compartiment ou objet S3 accessible publiquement.
  4. Amazon EFS : Elastic File System : système de fichiers partagé NFS v4 multi-AZ pour instances Linux et conteneurs.
  5. RDS Multi-AZ : Déploiement haute disponibilité avec réplication synchrone vers une instance passive Standby avec failover automatique.
  6. Read Replica : Copie en lecture seule alimentée par réplication asynchrone pour délester l'instance primaire des requêtes de consultation.
  7. Amazon Aurora : Base de données relationnelle cloud native répliquant 6 copies sur 3 AZs avec jusqu'à 5x les performances de MySQL.
  8. Amazon DynamoDB : Base de données NoSQL gérée offrant des performances sub-millisecondes et un modèle de dimensionnement RCU/WCU.
