Examens Blancs & Épreuves Corrigées — Services Cloud AWS B3

Deux épreuves académiques complètes d’architecture et d’ingénierie Cloud conformes au cursus Bachelor 3 (L3-ASI) et aux certifications professionnelles Amazon Web Services (AWS Certified Cloud Practitioner CLF-C02 & Solutions Architect Associate SAA-C03) : gouvernance, IAM, EC2, VPC, S3, RDS, DynamoDB, Lambda, SQS et Well-Architected Framework.

Épreuve 1 : Contrôle Continu (CC) — Durée 1 h 30 (Barème sur 20 points)

Sujet du Contrôle Continu — Infrastructure Globale, IAM & Calcul EC2

Partie 1 : Infrastructure Mondiale & Modèle de Responsabilité Partagée (6 points)

  1. Définissez les notions de Région AWS, d'Availability Zone (AZ) et d'Edge Location. Pourquoi une région AWS comprend-elle toujours au minimum 3 AZs isolées ? (3 pts)
  2. Dans le modèle de responsabilité partagée, qui d'AWS ou du Client est responsable des opérations suivantes : (a) le remplacement d'une barrette de RAM défaillante dans un centre de données, (b) l'application des correctifs de sécurité de l'OS d'une instance EC2 Linux, (c) la configuration des règles de pare-feu d'un Security Group, (d) les correctifs de l'OS sous-jacent d'une base de données Amazon RDS ? Justifiez chaque réponse. (3 pts)

Partie 2 : Sécurité IAM, Rôles & Politiques JSON (7 points)

  1. Expliquez la différence fondamentale entre un utilisateur IAM (User), un groupe IAM et un rôle IAM (Role). Dans quelle situation un rôle IAM doit-il obligatoirement être utilisé à la place de clés d'accès statiques ? (4 pts)
  2. Décrivez l'ordre d'évaluation des politiques IAM par le moteur d'autorisation d'AWS. Que se passe-t-il si un utilisateur possède une politique avec Effect: Allow sur s3:* et une autre avec Effect: Deny sur s3:DeleteBucket ? (3 pts)

Partie 3 : Calcul Élastique & Stockage Bloc avec EC2 et EBS (7 points)

  1. Comparez les 3 principaux modèles d'achat d'instances EC2 : On-Demand, Reserved Instances / Savings Plans et Spot Instances. Quelle stratégie d'achat recommandez-vous pour un site e-commerce ayant un trafic plancher continu de 4 instances et des pics de 10 instances pendant les soldes ? (4 pts)
  2. Présentez les différences entre les volumes EBS de type gp3 (General Purpose SSD) et io2 (Provisioned IOPS SSD). Pourquoi la séparation du volume de données et de l'instance EC2 permet-elle une haute résilience ? (3 pts)

Corrigé Partie 1 (6 points)

  • Infrastructure Globale (3 pts) : - Région : Zone géographique autonome mondiale (ex: eu-west-3 à Paris) hébergeant des centres de données. - Availability Zone (AZ) : Ensemble d'un ou plusieurs centres de données discrets équipés d'alimentations, de refroidissements et de connexions physiques redondantes. Trois AZs au minimum garantissent qu'un sinistre majeur (inondation, panne d'alimentation) dans une zone ne bloque pas la disponibilité globale de l'application via le basculement multi-AZ. - Edge Locations : Points de présence mondiaux ultra-distribués pour le cache de contenu CDN CloudFront et la résolution DNS Route 53 à très faible latence.
  • Modèle de Responsabilité Partagée (3 pts) : - (a) Remplacement RAM physique : AWS (Sécurité DU Cloud, matériel sous-jacent). - (b) Patchs OS invité EC2 : CLIENT (Sécurité DANS le Cloud, l'instance IaaS est sous contrôle exclusif de l'administrateur). - (c) Configuration Security Group : CLIENT (Filtrage réseau applicatif configuré par l'administrateur). - (d) Patchs OS RDS : AWS (Service PaaS géré, AWS maintient le système d'exploitation de l'hôte de base de données).

Corrigé Partie 2 (7 points)

  • Composants IAM & Rôles (4 pts) : - Utilisateur : Identité permanente pour une personne ou un système spécifique avec identifiants propres (mot de passe ou Access Keys). - Groupe : Collection d'utilisateurs simplifiant l'attribution collective de politiques. - Rôle : Identité sans identifiant permanent, endossable temporairement par des utilisateurs, des applications ou des services AWS (Instance Profile sur EC2, rôle d'exécution Lambda). L'utilisation d'un rôle évite de stocker des clés d'accès statiques dans le code ou les fichiers de configuration, éliminant le risque de fuite d'identifiants sur GitHub.
  • Évaluation des Politiques IAM (3 pts) : L'évaluation commence par un Default Deny. Si un Explicit Deny correspond à la requête, celle-ci est immédiatement et irrévocablement rejetée. Ici, la déclaration Deny: s3:DeleteBucket l'emporte sur Allow: s3:* : l'utilisateur peut effectuer toutes les opérations S3 sauf la suppression de buckets.

Corrigé Partie 3 (7 points)

  • Modèles d'Achat EC2 & Stratégie (4 pts) : - On-Demand : Paiement à la seconde sans engagement, idéal pour charges imprévisibles à court terme. - Reserved / Savings Plans : Engagement 1 ou 3 ans avec remises massives (jusqu'à 72%), optimal pour charge stable. - Spot Instances : Surplus de calcul vendu aux enchères jusqu'à 90% moins cher, interruptible avec préavis de 2 minutes. Stratégie recommandée : 4 instances de base en Reserved Instances (1 ou 3 ans) pour minimiser les coûts prévisibles, complétées pendant les soldes par des instances On-Demand (pour le panier d'achat critique) ou Spot (pour la consultation de catalogue tolérante aux pannes) pilotées par un Auto Scaling Group.
  • Volumes EBS gp3 vs io2 (3 pts) : - gp3 offre un excellent rapport performance/prix avec 3 000 IOPS et 125 MB/s de base gratuits, modulables indépendamment du stockage. - io2 est conçu pour les charges de bases de données critiques avec une durabilité de 99.999% et jusqu'à 256 000 IOPS. La persistance EBS est découplée du cycle de vie de l'instance : si l'instance tombe en panne, le volume peut être rattaché immédiatement à une nouvelle VM sans perte de données.

Épreuve 2 : Examen Final d'Ingénierie — Durée 2 h 00 (Barème sur 20 points)

Sujet de l'Examen Final — Architecture Web Résiliente Multi-Tiers dans un Amazon VPC

Mise en Situation d'Architecture

Vous êtes Ingénieur Cloud Architect pour une plateforme SaaS bancaire. Vous devez concevoir l'infrastructure AWS dans la région Paris (eu-west-3) pour héberger une application web critique à fort trafic.

Partie 1 : Conception du Réseau Amazon VPC (6 points)

  1. Définissez le plan d'adressage CIDR pour un VPC 10.0.0.0/16 réparti sur 2 Availability Zones (eu-west-3a et eu-west-3b). Vous devez créer : (a) un sous-réseau public par zone (/24), (b) un sous-réseau applicatif privé par zone (/24) et (c) un sous-réseau base de données isolé par zone (/24). Donnez les plages d'adresses précises et indiquez le nombre d'adresses IP assignables dans chaque sous-réseau. (3 pts)
  2. Décrivez la configuration des tables de routage pour que les serveurs applicatifs privés puissent télécharger des mises à jour logicielles sur Internet sans jamais être directement joignables depuis l'extérieur. Expliquez le rôle de la NAT Gateway et de l'Internet Gateway. (3 pts)

Partie 2 : Sécurité Périmétrique & Pare-feux (5 points)

  1. Concevez les règles de Security Groups pour une architecture 3-tiers (ALB public, Serveurs applicatifs EC2, Base de données RDS PostgreSQL). Comment configure-t-on les règles de sécurité pour que les instances EC2 n'acceptent du trafic HTTP (port 8080) QUE depuis l'ALB sans exposer d'adresses IP statiques ? (3 pts)
  2. Expliquez pourquoi une Network ACL (NACL) nécessite d'autoriser les ports éphémères (1024-65535) en sortie pour permettre aux requêtes clientes de recevoir les réponses du serveur web, contrairement à un Security Group. (2 pts)

Partie 3 : Stockage S3, Bases de Données RDS & Découplage Serverless (9 points)

  1. Comment garantit-on la haute disponibilité et la tolérance aux pannes d'une base de données Amazon RDS PostgreSQL ? Comparez un déploiement Multi-AZ (réplication synchrone) avec des Read Replicas (réplication asynchrone). (3 pts)
  2. Les relevés bancaires mensuels PDF sont stockés dans un bucket S3. Définissez une politique de cycle de vie (Lifecycle Policy) optimisée pour conserver les fichiers 90 jours en S3 Standard, les basculer en Glacier Flexible pendant 1 an, puis en Glacier Deep Archive pendant 7 ans avant suppression. Quel paramètre S3 empêche formellement toute fuite publique accidentelle de ces relevés ? (3 pts)
  3. Pour absorber les pics de dépôts de transactions sans saturer la base de données relationnelle, vous insérez une file d'attente Amazon SQS entre les microservices et un pool de fonctions AWS Lambda. Comment fonctionne le mécanisme de Dead-Letter Queue (DLQ) en cas de transaction malformée provoquant une erreur continue ? (3 pts)

Corrigé type & Barème détaillé de l'Examen Final

Corrigé Partie 1 : Réseau VPC (6 points)

  • Plan d'adressage CIDR (3 pts) : - AZ eu-west-3a : Public Subnet 1 = 10.0.1.0/24 ; App Subnet 1 = 10.0.2.0/24 ; DB Subnet 1 = 10.0.3.0/24. - AZ eu-west-3b : Public Subnet 2 = 10.0.11.0/24 ; App Subnet 2 = 10.0.12.0/24 ; DB Subnet 2 = 10.0.13.0/24. Pour chaque sous-réseau /24, le nombre total d'IP est 2^(32-24) = 256. AWS réservant obligatoirement 5 adresses (.0 réseau, .1 routeur VPC, .2 DNS AWS, .3 réservé futur, .255 broadcast), il y a exactement 251 adresses IP assignables par sous-réseau.
  • Routage Egress & NAT (3 pts) : - Sous-réseaux publics : Route Table avec 0.0.0.0/0 → igw-xxxx (Internet Gateway). - Sous-réseaux applicatifs privés : Route Table avec 0.0.0.0/0 → nat-xxxx (NAT Gateway managée déployée dans un sous-réseau public). La NAT Gateway effectue une translation d'adresses source (SNAT) permettant aux requêtes sortantes des VMs privées d'accéder à Internet tout en bloquant toute tentative de connexion initiée depuis l'extérieur. - Sous-réseaux bases de données : Table de routage locale isolée (aucune route vers 0.0.0.0/0).

Corrigé Partie 2 : Sécurité Pare-feux (5 points)

  • Chaining de Security Groups (3 pts) : Au lieu de filtrer par plage d'adresses IP CIDR, AWS permet de référencer l'identifiant d'un autre Security Group dans le champ Source : 1. SG-ALB : Inbound 443 depuis 0.0.0.0/0. 2. SG-App : Inbound 8080 avec Source = sg-alb-xxxx. Seul le trafic provenant d'instances rattachées au groupe de l'ALB est autorisé. 3. SG-DB : Inbound 5432 avec Source = sg-app-xxxx. Seuls les serveurs applicatifs autorisés peuvent contacter la base de données.
  • Stateless NACL vs Stateful SG (2 pts) : Les Security Groups sont Stateful : si le paquet entrant sur le port 443 est accepté, le paquet réponse sortant vers le port éphémère du client est automatiquement autorisé. Les Network ACLs sont Stateless : elles évaluent chaque paquet isolément. Pour qu'un client TCP reçoive la réponse HTML, la NACL sortante doit explicitement comporter une règle Allow sur les ports éphémères clients (1024-65535).

Corrigé Partie 3 : Données & Découplage (9 points)

  • RDS Multi-AZ vs Read Replicas (3 pts) : - Multi-AZ : Réplication synchrone vers une instance Standby dans une autre zone. Utilisé pour la haute disponibilité et reprise après sinistre (basculement automatique en cas de panne de l'AZ primaire). La réplique passive ne traite aucune requête de lecture. - Read Replicas : Réplication asynchrone vers jusqu'à 15 instances de lecture. Utilisé pour la montée en charge des performances de lecture (Read scaling).
  • Cycle de Vie S3 & Block Public Access (3 pts) : Politique S3 Lifecycle : Transition vers GLACIER_FLEXIBLE à J+90, puis vers DEEP_ARCHIVE à J+365, et Expiration (suppression définitive) à J+2920 (8 ans). Le paramètre S3 Block Public Access (activé au niveau du compte ou du bucket avec ses 4 verrous activés) neutralise formellement toute tentative de rendre le bucket ou un objet public via des ACLs ou des politiques permissives.
  • Découplage SQS & Dead-Letter Queue (3 pts) : Lorsqu'une fonction Lambda échoue à traiter un message, celui-ci redevient visible dans la file SQS après expiration du VisibilityTimeout. Le compteur ReceiveCount du message est incrémenté. Dès que ReceiveCount ≥ maxReceiveCount (ex: 3 tentatives infructueuses), le message est automatiquement évincé vers la Dead-Letter Queue (DLQ). Cela isole le message toxique (« poison pill »), empêche le blocage de la file d'attente et permet aux ingénieurs d'analyser l'erreur ultérieurement.
