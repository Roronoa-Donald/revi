2. Structure Canonique d'un ARN (Amazon Resource Name)

L'ARN identifie de manière univoque toute ressource à travers les régions et les comptes :

arn:partition:service:region:account-id:resource-id
arn:partition:service:region:account-id:resourcetype/resource-id
arn:partition:service:region:account-id:resourcetype:resource-id
  • partition : aws (commercial mondial), aws-cn (Chine), aws-us-gov (Gouvernement US).
  • service : identifiant minuscule (s3, ec2, iam, lambda, dynamodb).
  • region : vide pour les services globaux (S3, IAM, Route 53, CloudFront) ou code géographique (eu-west-3 pour Paris, us-east-1 pour N. Virginia).
  • account-id : exactement 12 chiffres décimaux (ou vide pour S3).

3. Structure d'une Politique IAM JSON & Ordre d'Évaluation

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3ReadSpecificBucket",
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::mon-bucket-prod",
        "arn:aws:s3:::mon-bucket-prod/*"
      ]
    },
    {
      "Sid": "DenySensitiveBucketDelete",
      "Effect": "Deny",
      "Action": "s3:DeleteBucket",
      "Resource": "*"
    }
  ]
}

Règle d'or : Default Deny → Explicit Deny (priorité absolue immuable) → Explicit Allow (si aucun Deny) → Default Deny final.

Offset IPRôle & Affectation AWSExemple (/24 : 10.0.1.0/24)

7. Les 6 Piliers du AWS Well-Architected Framework

  1. Excellence opérationnelle : exécuter et surveiller les systèmes, automatiser les changements via l'IaC et tirer les enseignements des incidents.
  2. Sécurité : protéger les données, les systèmes et les actifs via le principe du moindre privilège, le chiffrement généralisé et l'audit continu.
  3. Fiabilité : prévenir et récupérer automatiquement des défaillances via la redondance Multi-AZ, l'auto-scaling et les tests de panne réguliers.
  4. Efficacité des performances : sélectionner les types d'instances adaptés (Compute/Memory/Storage), employer des architectures serverless et monitorer les métriques.
  5. Optimisation des coûts : éliminer les dépenses inutiles via les instances Spot/Reserved, le dimensionnement adapté (Rightsizing) et les politiques de cycle de vie S3.
  6. Durabilité (Sustainability) : minimiser l'impact environnemental de l'infrastructure en maximisant le taux d'utilisation des ressources physiques sous-jacentes.
