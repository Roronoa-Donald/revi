Cartes de Révision & Mémorisation Active — Git & GitHub B3

36 fiches synthétiques pour ancrer les concepts fondamentaux : Modèle objet DAG & SHA, Stratégies de fusion & Rebase interactif, Reflog & Diagnostic bisect, Gouvernance & Protection de branches, GitHub Actions CI/CD, Gestion LFS, Hooks & Purge d’historique.

Module 1 — Modèle Objet & Plomberie Git

QuestionQu’est-ce qu’un système de fichiers adressable par contenu (CAS) dans Git ?
RéponseUn système où chaque élément est stocké et retrouvé non par son nom arbitraire, mais par la valeur de hachage cryptographique (SHA-1 ou SHA-256) de son contenu et de son en-tête.
QuestionQuelle est la différence fondamentale entre un objet blob et un objet tree ?
RéponseLe blob stocke le contenu pur du fichier sans nom ni permissions ; le tree représente un répertoire en associant des noms de fichiers, des permissions Unix et des hashes d’objets cibles.
QuestionQuel est le format exact de l’en-tête injecté par Git avant de calculer l’empreinte SHA ?
Réponse \0 (ex: "blob 25\0", où \0 est l’octet nul terminateur).
QuestionQue signifie l’expression « Detached HEAD » (tête détachée) ?
RéponseLa référence HEAD contient directement le hash d’un commit au lieu de pointer symboliquement vers une branche (ex: ref: refs/heads/main).
QuestionPourquoi l’attaque SHAttered a-t-elle poussé Git à préparer la transition vers SHA-256 ?
RéponseCar SHAttered a démontré qu’une collision pratique sur SHA-1 était réalisable (deux contenus différents produisant le même hash), menaçant l’intégrité du graphe Git.
QuestionÀ quoi sert la commande « git rev-parse » ?
RéponseÀ résoudre et convertir n’importe quel spécificateur de révision symbolique ou relatif (HEAD, main, HEAD~2) en son identifiant de commit SHA-1/SHA-256 canonique.

Module 2 — Fusions Avancées & Rebase

QuestionQu’est-ce qu’une fusion Fast-Forward dans Git ?
RéponseUn déplacement direct du pointeur de branche sans création de nouveau commit, possible uniquement lorsque l’historique entre les deux branches est strictement linéaire.
QuestionQu’est-ce que le LCA (Lowest Common Ancestor) ?
RéponseLe dernier ancêtre commun le plus proche partagé par deux branches dans le graphe DAG, servant de point de base pour le 3-Way Merge.
QuestionQuelle est la différence fondamentale entre squash et fixup lors d’un rebase interactif ?
RéponseSquash fond le commit dans le précédent en concaténant les messages ; fixup fond le commit en supprimant purement et simplement son message de commit.
QuestionPourquoi le moteur de fusion ORT surpasse-t-il l’ancien moteur recursive ?
RéponseORT opère massivement en mémoire sans écritures disque superflues et résout avec une très haute fidélité les conflits complexes liés aux renommages et déplacements de fichiers.
QuestionQue fait la commande « git merge --abort » ?
RéponseElle interrompt une fusion en cours de résolution de conflit et restaure la copie de travail à l’état exact précédant l’appel de git merge.
QuestionQuelle est la règle d’or du rebase Git ?
RéponseNe jamais rebaser une branche publique partagée avec d’autres collaborateurs, sous peine de modifier tous les identifiants SHA et de corrompre leur historique.

Module 3 — Reflog & Diagnostic Bisect

QuestionQuelle est la différence fondamentale entre git log et git reflog ?
Réponsegit log parcourt l’historique des commits reliés à la branche courante ; git reflog consigne chronologiquement tous les mouvements du pointeur HEAD sur la machine locale.
QuestionQu’est-ce qu’un « dangling commit » (commit orphelin) ?
RéponseUn commit existant physiquement dans la base d’objets .git/objects/ mais vers lequel aucune branche ni tag ne pointe directement ou indirectement.
QuestionQuelle est la complexité algorithmique de git bisect ?
RéponseO(log2 N), car il applique une recherche binaire (dichotomique) en divisant par deux le nombre de commits à inspecter à chaque étape.
QuestionQue fait la commande « git bisect reset » ?
RéponseElle met fin à la session de recherche dichotomique et replace la copie de travail sur la branche et le commit où se trouvait le développeur avant de lancer bisect.
QuestionPourquoi le reflog ne peut-il pas être partagé lors d’un git push ?
RéponseCar le reflog est un journal strictement local retraçant les actions propres à la session de travail de chaque développeur sur son poste de travail.
QuestionQuelle est la structure de données utilisée par git stash ?
RéponseUne pile LIFO (Last In, First Out) où la remise la plus récente est référencée à l’indice 0 sous le nom stash@{0}.

Module 4 — Gouvernance & Workflows

QuestionQuel est le principe fondamental du Trunk-Based Development ?
RéponseTous les développeurs travaillent sur une branche unique partagée (le tronc main), intégrant fréquemment de petits commits via des branches de courte durée (< 2 jours).
QuestionÀ quoi servent les Feature Flags en développement logiciel moderne ?
RéponseÀ découpler le déploiement du code en production de l’activation effective de la fonctionnalité pour les utilisateurs finaux.
QuestionQuelles sont les 4 règles de protection de branche majeures sur GitHub ?
RéponseRevue de code obligatoire (PR reviews), passage des statuts CI requis, commits signés obligatoires (GPG/SSH) et historique linéaire strict.
QuestionQuel est le format standard d’un commit Conventional Commits 1.0.0 ?
Réponse[scope optionnel][!]: (avec deux-points suivi impérativement d’un espace).
QuestionComment un « Breaking Change » est-il formellement indiqué dans un commit sémantique ?
RéponsePar un point d’exclamation avant le deux-points (ex: feat!:) ou par la mention BREAKING CHANGE: dans le corps/pied de page.
QuestionQuel est le rôle du fichier .github/CODEOWNERS ?
RéponseIl associe des dossiers et fichiers du dépôt à des équipes ou experts désignés, qui sont automatiquement sollicités pour valider les Pull Requests concernées.

Module 5 — CI/CD & GitHub Actions

QuestionDans quel dossier doit résider un workflow GitHub Actions ?
RéponseDans le répertoire masqué .github/workflows/ à la racine du dépôt, sous forme de fichier YAML (.yml ou .yaml).
QuestionQue fait la directive strategy.matrix dans un job ?
RéponseElle génère un produit cartésien de variables (ex: OS, versions de runtime) pour instancier automatiquement plusieurs jobs de test en parallèle.
QuestionPourquoi l’injection d’expressions ${{ ... }} directement dans run: est-elle dangereuse ?
RéponseParce que GitHub remplace le texte avant l’exécution : des métacaractères insérés par un attaquant dans un titre d’issue ou de branche peuvent détourner le script shell (Command Injection).
QuestionComment immuniser un script shell contre l’injection de contexte GitHub ?
RéponseEn passant la valeur dynamique via le bloc env: du step, puis en utilisant la variable d’environnement ($MA_VAR) dans le script.
QuestionÀ quoi sert la directive permissions: en tête de workflow ?
RéponseÀ appliquer le principe du moindre privilège en limitant strictement les droits accordés au GITHUB_TOKEN généré pour le job.
QuestionQue fait la directive fail-fast: false ?
RéponseElle ordonne à GitHub Actions de ne pas annuler les autres jobs d’une matrice si l’un d’entre eux échoue.

Module 6 — Administration, LFS & Purge

QuestionQuel problème fondamental résout Git LFS ?
RéponseL’explosion de la taille du dossier .git lors du suivi de gros fichiers binaires, en remplaçant les binaires par de micro-pointeurs textuels légers.
QuestionQuels champs composent un pointeur textuel Git LFS v1 ?
RéponseLa version de la spécification (version https://...), le hash SHA-256 du binaire (oid sha256:...) et sa taille en octets (size ...).
QuestionQuelle est la différence entre un hook pre-commit et un hook pre-receive ?
Réponsepre-commit s’exécute localement sur le poste du développeur avant la création du commit ; pre-receive s’exécute sur le serveur distant lors d’un push pour valider ou rejeter l’envoi.
QuestionPourquoi « git rm » ne suffit-il pas pour effacer un secret commité par erreur ?
RéponseCar git rm crée un nouveau commit de suppression, mais le secret demeure intact et lisible dans tous les commits antérieurs de l’historique.
QuestionQuel outil remplace officiellement l’ancien et obsolète « git filter-branch » ?
Réponsegit-filter-repo, un outil en Python infiniment plus rapide, fiable et simple pour réécrire le graphe DAG.
QuestionQuelle mesure d’urgence absolue prime sur le nettoyage de Git en cas de fuite de secret ?
RéponseLa révocation immédiate de la clé auprès de la plateforme tierce (AWS, Stripe, etc.) afin de désactiver tout accès frauduleux.
