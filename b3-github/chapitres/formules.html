Mémento Technique & Aide-Mémoire — Git & GitHub

Guide de référence opérationnelle pour ingénieurs logiciels et DevOps : modèle objet DAG, commandes de plomberie, résolution de conflits, reflog, workflows GitHub Actions et sécurité des dépôts.

1. Modèle Objet Interne & Commandes de Plomberie Git

Type d’Objet GitStructure du StockageRôle & Métadonnées AssociéesCommande d’Inspection
blobblob <taille>\0<contenu>Stocke le contenu brut d’un fichier sans nom ni permissions.git cat-file -p <hash>
treetree <taille>\0[mode nom\0hash...]Représente un répertoire, associe noms de fichiers et hashes.git ls-tree -r <tree-ish>
commitcommit <taille>\0tree, parent, author, committer, msgCapture un état instantané de l’arborescence avec ancêtres.git cat-file -p HEAD
tagtag <taille>\0object, type, tag, tagger, msgÉtiquette annotée immuable pointant vers un commit précis.git cat-file -p v1.0.0

2. Stratégies de Fusion & Réécriture d’Historique

Opération GitMécanique TopologiqueModifie les SHA-1 ?Cas d’Usage Recommandé
Fast-ForwardDéplace simplement le pointeur de branche cible vers l’amont.NonBranches de travail strictement linéaires sans divergence.
3-Way Merge (ORT)Calcule le LCA (Lowest Common Ancestor) et crée un commit à 2 parents.Non (nouveau commit créé)Fusion de branches de fonctionnalités (Feature Branches).
Rebase InteractifRejoue les commits un par un sur une nouvelle base (LCA modifié).Oui (nouveaux hashes)Nettoyage d’historique local avant soumission de Pull Request.
Squash & MergeCondense tous les commits d’une PR en un seul commit linéaire.Oui (nouvel historique)Maintien d’une branche principale compacte et lisible.

3. Sauvetage de Données, Reflog & Diagnostic d’Anomalies

Commande de DiagnosticDescription & Action OpérationnelleSyntaxe Typique
git reflogAffiche l’historique des mouvements du pointeur HEAD (même après reset dur).git reflog show HEAD
Sauvetage d’un commit perduRecrée une branche pointant sur le commit orphelin repéré dans le reflog.git checkout -b rescue HEAD@{3}
git bisectEffectue une recherche binaire dans l’historique pour identifier un commit fautif.git bisect start HEAD v1.2.0
git stashEmpile les modifications non validées pour nettoyer temporairement la copie de travail.git stash push -m "wip" && git stash pop
git fsckVérifie l’intégrité de la base d’objets et liste les objets inaccessibles (dangling).git fsck --lost-found

4. Spécification Conventional Commits 1.0.0 & SemVer

Préfixe de CommitSignification SémantiqueImpact SemVer (X.Y.Z)Exemple Conforme
feat:Nouvelle fonctionnalité pour l’utilisateur.MINOR (+0.1.0)feat(auth): ajout support OAuth2 GitHub
fix:Correction d’un bogue en production.PATCH (+0.0.1)fix(api): resolution fuite memoire sur stream
docs:, chore:, test:Documentation, maintenance ou tests sans code applicatif.Aucun incrémentdocs: mise a jour du guide de deploiement
feat!: ou BREAKING CHANGERupture de compatibilité ascendante dans l’API publique.MAJOR (+1.0.0)feat(v2)!: suppression endpoints depreciees

5. GitHub Actions : Syntaxe de Workflow & Bonnes Pratiques de Sécurité

Élément de WorkflowRôle & SyntaxeRecommandation de Sécurité
on: [push, pull_request]Événements déclencheurs du pipeline CI/CD.Filtrer par branches cibles précises (ex: main).
permissions:Droit accordé au token GITHUB_TOKEN du job.Toujours appliquer le principe du moindre privilège (ex: contents: read).
strategy.matrix:Exécute le job sur plusieurs versions/OS en parallèle.Définir fail-fast: false pour observer toutes les plateformes.
steps.env:Injection de variables d’environnement.Ne JAMAIS injecter ${{ github.event... }} directement dans run: bash !
