Chapitre 5 — Exploitation Système, Escalade de Privilèges & Pivoting (Gaining Access)

Module 5 ≈ 2 h 45 de travail Réservé B3 et plus
Mise en situation

L'obtention d'un shell initial non privilégié (par exemple sous l'identité www-data sur un serveur web) ne constitue qu'une étape intermédiaire dans un test d'intrusion. L'auditeur doit élever ses privilèges pour atteindre les droits suprêmes (root sous Linux, SYSTEM sous Windows) afin de démontrer l'accès aux données sensibles et pivoter vers les réseaux internes isolés non routables directement depuis Internet. En tant que pentesteur B3, vous devez maîtriser les techniques d'audit des configurations locales, exploiter méthodiquement les faiblesses d'assignation de droits et établir des passerelles de rebond sécurisées.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. comprendre la structure mémoire d'un processus et la mécanique d'un Stack Buffer Overflow (x86/x64) ;
  2. identifier et contourner les mécanismes de protection mémoire fondamentaux (ASLR, DEP/NX, Stack Canaries) ;
  3. exploiter Metasploit Framework, manipuler des payloads stagés vs inline et opérer une session Meterpreter ;
  4. auditer et exploiter les vecteurs d'escalade de privilèges Linux : binaires SUID (GTFOBins) et règles sudoers ;
  5. maîtriser l'élévation de privilèges Windows : chemins de services non quotés et abus de jetons (SeImpersonate) ;
  6. mettre en œuvre des tunnels de pivoting réseau (SSH port forwarding local/distant/dynamique SOCKS et Chisel).

1. Architecture Mémoire & Dépassement de Tampon (Stack Buffer Overflow)

Dans les programmes compilés en C ou C++ sans vérification stricte des limites de tableaux (fonctions dangereuses comme strcpy, gets, sprintf), un Buffer Overflow permet de détourner le flux d'exécution :

Organisation de la Pile (Stack)

La pile croît des adresses hautes vers les adresses basses. Lors d'un appel de fonction :

  1. Empilement des arguments de fonction.
  2. Empilement de l'adresse de retour (Saved Return Pointer : EIP en x86, RIP en x64).
  3. Sauvegarde du Frame Pointer (EBP/RBP).
  4. Allocation des variables locales dans le tampon mémoire (Buffer).

Mécanique de l'Exploit

En injectant plus de données que la taille allouée du tampon :

  • Les données débordent et écrasent EBP puis le pointeur de retour (EIP/RIP).
  • L'attaquant remplace l'adresse de retour par l'adresse de son code malveillant injecté (Shellcode).
  • Un NOP Sled (suite d'instructions \x90 No Operation) précède le shellcode pour sécuriser l'atterrissage de l'exécution.
Les Mécanismes de Protection Moderne de la Mémoire

Les systèmes d'exploitation contemporains intègrent des défenses matérielles et logicielles :

  • DEP / NX (Data Execution Prevention / No-Execute) : marque les zones de données (pile et tas) comme non exécutables. Tout saut direct vers du shellcode sur la pile déclenche un crash (contourné par la technique Return-Oriented Programming - ROP).
  • ASLR (Address Space Layout Randomization) : aléatorise les adresses mémoire de la pile, du tas et des bibliothèques à chaque exécution du programme.
  • Stack Canaries : valeur aléatoire secrète placée sur la pile juste avant l'adresse de retour. Si la valeur est modifiée lors du retour de fonction, le programme s'arrête immédiatement (Stack Smashing Detected).

2. Exploitation avec Metasploit Framework & Sessions Meterpreter

Metasploit Framework (MSF) est la plateforme modulaire d'automatisation d'exploits la plus répandue :

ComposantRôle dans le FrameworkExemple d'Utilisation
ExploitModule exploitant une vulnérabilité logicielle pour injecter la chargeuse exploit/windows/smb/ms17_010_eternalblue
Payload (Charge Utile)Code exécuté sur la cible une fois l'accès obtenu (Reverse Shell, Meterpreter)set PAYLOAD windows/x64/meterpreter/reverse_tcp
AuxiliaryModules de scan, d'énumération ou de déni de service sans charge utileuse auxiliary/scanner/smb/smb_version
PostModules d'énumération locale, extraction de hashes ou escalade après compromissionuse post/windows/gather/smart_hashdump
Différence entre Payloads Stagés et Non-Stagés (Inline)

Dans Metasploit, la convention de nommage distingue deux types d'architectures de charge utile :

  • Payload Stagé (avec un slash intermédiaire, ex: meterpreter/reverse_tcp) : un premier petit code injecté (Stager) se connecte au serveur de l'attaquant pour télécharger en mémoire la charge utile complète plus volumineuse. Indispensable lorsque l'espace mémoire pour l'exploit initial est restreint.
  • Payload Inline / Non-stagé (avec un tiret du bas, ex: meterpreter_reverse_tcp) : la charge utile entière est envoyée d'un seul bloc dans l'exploit. Plus stable face aux coupures réseau ou aux inspections proxies.

3. Élévation de Privilèges Linux : SUID, GTFOBins & Sudoers

Sous Linux, l'élévation de privilèges vers le compte root repose majoritairement sur les mauvaises configurations d'administration :

Binaires SUID & GTFOBins

La recherche de fichiers avec le bit SUID (chmod u+s) appartenant à root est systématique :

$ find / -perm -4000 -type f 2>/dev/null

Le projet GTFOBins répertorie les binaires légitimes qui permettent d'obtenir un shell administrateur :

  • /usr/bin/find : find . -exec /bin/sh -p \; -quit
  • /usr/bin/vim : vim -c ':!/bin/sh'
  • /usr/bin/awk : awk 'BEGIN {system("/bin/sh")}'

Droits Sudoers Permissifs (sudo -l)

La commande sudo -l liste les commandes autorisées pour l'utilisateur courant :

Si la directive NOPASSWD: est attribuée sur un binaire permettant l'échappement (ex: (ALL) NOPASSWD: /usr/bin/less /var/log/syslog), l'attaquant lance la commande et tape !/bin/sh dans l'interface pour obtenir un shell root instantané.

4. Élévation de Privilèges Windows : Unquoted Service Paths & SeImpersonate

Sous Windows, l'élévation vers le compte NT AUTHORITY\SYSTEM exploite deux grandes familles de failles :

Chemins de Services Non Quotés (Unquoted Service Paths)

Si le chemin d'un service Windows contient des espaces et n'est pas entouré de guillemets doubles (ex: C:\Program Files\Mon Service\service.exe) :

Le gestionnaire de services tente d'exécuter séquentiellement :

  1. C:\Program.exe
  2. C:\Program Files\Mon.exe
  3. C:\Program Files\Mon Service\service.exe

Si un utilisateur sans privilège a le droit d'écriture dans C:\, il y dépose un binaire malveillant Program.exe qui sera exécuté avec les droits SYSTEM au redémarrage du service.

Abus de Privilèges de Jetons (SeImpersonatePrivilege)

Les comptes de services Windows (comme LOCAL SERVICE ou NETWORK SERVICE sous IIS) possèdent le privilège SeImpersonatePrivilege (visible via whoami /priv).

Ce droit autorise un processus à usurper le jeton de sécurité de n'importe quel client qui se connecte à lui via un tube nommé (Named Pipe).

Des exploits automatisés (PrintSpoofer, SweetPotato) forcent le service Spooler local (SYSTEM) à s'authentifier sur un tube contrôlé pour dupliquer son jeton et spawner un shell SYSTEM.

5. Mouvement Latéral et Pivoting Réseau (SSH & Chisel)

Le pivoting consiste à utiliser une machine compromise comme passerelle de rebond pour attaquer des réseaux internes isolés :

Tunnel SSH Local (-L)

Redirige un port de la machine de l'auditeur vers un service interne accessible par la machine pivot :

ssh -L 8080:10.0.0.5:80 user@pivot

Accès à l'intranet interne sur http://localhost:8080.

Tunnel Dynamique SOCKS (-D)

Transforme la connexion SSH en proxy SOCKS complet :

ssh -D 1080 user@pivot

Combiné avec proxychains, toutes les commandes Nmap, curl ou navigateurs transitent par le pivot.

Tunneling HTTP Chisel

Outil écrit en Go encapsulant un proxy SOCKS chiffré au travers d'une connexion HTTP/Websocket standard :

Idéal pour traverser les pare-feux stricts n'autorisant que les flux web sortants (port 80/443).

Exercice 1 — Auditeur de Permissions Linux et Détection de Binaires SUID Anormaux

Étude de cas Niveau 1 — Acquisition

Objectif : Analyser les permissions octales de fichiers système pour détecter les binaires SUID exploitables (GTFOBins).

Le bit SUID (Set User ID) permet d'exécuter un binaire avec les privilèges de son propriétaire (généralement root).

Binaires connus du catalogue GTFOBins permettant une évasion directe vers un shell root :
bash, find, vim, nano, cp, awk, python, nmap, pkexec.

Règles d'évaluation :
1. Vérifier si le mode octal comporte le bit SUID (chiffre des milliers >= 4, ex: 4755, 4750) :
- Si le bit SUID est absent : exploit=NO_SUID_BIT, risk=NONE.
2. Si le bit SUID est présent et owner == 'root' :
- Si le nom du binaire est dans GTFOBins : exploit=GTFOBINS_PRIVILEGE_ESCALATION, risk=CRITICAL.
- Sinon (binaire standard comme passwd, ping) : exploit=STANDARD_SYSTEM_BINARY, risk=LOW.
3. Si le bit SUID est présent mais owner != 'root' :
- exploit=NON_ROOT_SUID, risk=MEDIUM.

Données du cas : SUID_CHECK path=<chemin> owner=<user> mode=<octal>.
Résultat d’analyse attendu : SUID_AUDIT: binary=<nom> owner=<user> mode=<octal> exploit=<exploit> risk=<risk>.

Cas d’exemple
SUID_CHECK path=/usr/bin/find owner=root mode=4755
Résolution attendue
SUID_AUDIT: binary=find owner=root mode=4755 exploit=GTFOBINS_PRIVILEGE_ESCALATION risk=CRITICAL

Binaire find SUID root exploitable directement via la commande find . -exec /bin/sh -p ;

Trois indices, rédigés en mots
  1. Extrayez le nom de base du fichier (ex: /usr/bin/find -> find).
  2. Vérifiez si le premier chiffre du mode octal (mode >= 4000) active le bit SUID.
  3. Comparez avec la liste GTFOBins si owner == root.

Exercice 2 — Analyseur de Fichier Sudoers et Détection de Droits Dangereux (NOPASSWD)

Étude de cas Niveau 2 — Application

Objectif : Analyser une directive sudoers pour détecter des privilèges excessifs permettant l'élévation directe vers root.

Une mauvaise configuration dans /etc/sudoers constitue le vecteur d'élévation de privilèges le plus fréquent en environnement Linux.

Commandes dangereuses permettant l'échappement vers un shell (Shell Escape) :
ALL, find, vim, vi, less, more, bash, sh, python, perl, awk.

Règles d'analyse :
1. Déterminer si NOPASSWD: est présent dans la règle :
- Si absent : nopasswd=FALSE, vector=PASSWORD_PROTECTED, risk=LOW.
2. Si NOPASSWD: est présent (nopasswd=TRUE) :
- Extraire la commande autorisée située après NOPASSWD: (ex: /usr/bin/find).
- Extraire le nom du binaire de base.
- Si le binaire est ALL ou appartient à la liste de shell escape :
vector=INSTANT_ROOT_SHELL, risk=CRITICAL.
- Sinon (binaire d'administration restreint, ex: systemctl restart nginx) :
vector=RESTRICTED_SUDO_EXECUTION, risk=MEDIUM.

Données du cas : SUDO_PARSE rule=<texte_complet_de_la_regle_sudoers>.
Résultat d’analyse attendu : SUDO_AUDIT: user=<user> nopasswd=<TRUE|FALSE> command=<cmd_name> vector=<vector> risk=<risk>.

Cas d’exemple
SUDO_PARSE rule=developer ALL=(ALL) NOPASSWD: /usr/bin/find
Résolution attendue
SUDO_AUDIT: user=developer nopasswd=TRUE command=find vector=INSTANT_ROOT_SHELL risk=CRITICAL

find exécutable sans mot de passe permettant l'échappement shell immédiat.

Trois indices, rédigés en mots
  1. Isolez le texte de la règle avec l’extraction des champs[1].
  2. Le premier mot de la règle correspond à l'utilisateur ou au groupe.
  3. Vérifiez la présence de NOPASSWD: et extrayez la commande qui suit.

Exercice 3 — Calculateur d'Offset de Buffer Overflow et Agencement de Payload

Étude de cas Niveau 3 — Raisonnement

Objectif : Calculer la structure et la taille globale d'un exploit de dépassement de tampon de pile (Stack Buffer Overflow).

Dans l'exploitation de binaires compilés (x86/x64 sans canary), un dépassement de tampon permet de réécrire le pointeur d'instruction de retour (EIP/RIP).

Structure du payload dans la pile :
1. PADDING : offset octets (remplissage jusqu'au pointeur de retour).
2. RET_ADDR : taille de l'adresse de retour (4 octets en x86, 8 octets en x64).
3. NOP_SLED : sled_len octets de NOP (\x90).
4. SHELLCODE : shellcode_len octets du code exécutable injecté.

Calcul de la taille totale du payload :
total_size = offset + ret_bytes + sled_len + shellcode_len.

Données du cas : BOF_LAYOUT arch=<x86|x64> offset=<N> sled_len=<S> shellcode_len=<L>.
Résultat d’analyse attendu : PAYLOAD_LAYOUT: arch=<arch> offset=<N> ret_bytes=<4|8> sled=<S> shellcode=<L> total_size=<total> status=READY_FOR_INJECTION.

Cas d’exemple
BOF_LAYOUT arch=x86 offset=112 sled_len=32 shellcode_len=44
Résolution attendue
PAYLOAD_LAYOUT: arch=x86 offset=112 ret_bytes=4 sled=32 shellcode=44 total_size=192 status=READY_FOR_INJECTION

Payload x86 standard avec 112 octets de padding et 32 octets de NOP sled.

Trois indices, rédigés en mots
  1. Identifiez ret_bytes : 4 octets pour x86 et 8 octets pour x64.
  2. Sommez offset + ret_bytes + sled_len + shellcode_len.
  3. Affichez la disposition du payload selon le format demandé.

7. QCM — niveau examen

Dans une attaque par dépassement de tampon sur la pile (Stack Buffer Overflow x86), quel registre de processeur l'attaquant cherche-t-il à écraser pour contrôler le flux d'exécution ?

EIP contient l'adresse de la prochaine instruction processeur à exécuter. En écrasant l'adresse de retour sauvegardée sur la pile, EIP est forcé de pointer vers le shellcode de l'attaquant.

Quel est le rôle d'un "NOP Sled" (suite d'instructions 0x90) placé avant le shellcode dans un exploit Buffer Overflow ?

Le NOP sled (No Operation) permet de compenser les légères imprécisions d'adressage mémoire : le processeur exécute les NOP séquentiellement jusqu'à atteindre le début du shellcode.

Quel mécanisme de sécurité de l'OS empêche l'exécution de code injecté directement dans la mémoire de la pile (Stack) ?

DEP/NX marque les pages de pile et de tas comme non exécutables : toute tentative du processeur d'exécuter des instructions situées sur la pile déclenche une exception matérielle immédiate.

Dans Metasploit, quelle est la particularité d'un payload de type "Stagé" (ex: windows/x64/meterpreter/reverse_tcp) ?

Les payloads stagés résolvent le problème des petits tampons mémoire : le stager est minuscule, établit la connexion réseau, puis télécharge en RAM le reste du binaire Meterpreter volumineux.

Sur un système Linux, pourquoi le binaire /usr/bin/find avec le bit SUID root (mode 4755) représente-t-il une élévation de privilèges immédiate (GTFOBins) ?

L'option -exec de find lance une commande sous l'identité effective du propriétaire du binaire (root grâce au bit SUID), ce qui permet d'obtenir un shell root avec le drapeau -p.

Quelle mauvaise configuration dans Windows permet l'attaque par "Unquoted Service Path" ?

Sous Windows, un chemin avec espaces sans guillemets force le gestionnaire de services à tenter d'exécuter chaque mot précédant un espace (ex: C:\Program.exe avant C:\Program Files\...).

Quel privilège Windows, souvent détenu par les comptes de services applicatifs (IIS/SQL), permet d'usurper l'identité de jetons locaux et d'obtenir les droits SYSTEM via l'exploit PrintSpoofer ?

SeImpersonatePrivilege autorise un compte de service à usurper le jeton de sécurité de n'importe quel client local se connectant à lui, permettant des attaques comme RottenPotato ou PrintSpoofer.

Quelle commande SSH permet de créer un tunnel proxy dynamique SOCKS sur le port local 1080 au travers d'une machine pivot ?

L'option "-D" de SSH ouvre un proxy SOCKS dynamique local qui route le trafic de n'importe quel outil (via proxychains ou navigateur) à travers la machine pivot distante.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier d'ajouter le drapeau -p lors de l'exécution d'un shell via un binaire SUID (l'OS rétrograde sinon l'euid au compte réel).
  • Confondre un payload Metasploit stagé (avec slash) et non-stagé inline (avec tiret bas).
  • Modifier directement des fichiers système critiques sans vérifier les sauvegardes lors d'une élévation de privilèges.
  • Négliger les règles sudoers comportant la directive NOPASSWD: sur des binaires d'édition comme vim ou less.

9. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Énumérer l'environnement local après premier accès : OS, kernel, utilisateurs, groupes et privilèges (whoami, id).
  2. Rechercher les binaires SUID mal configurés sous Linux et croiser avec GTFOBins.
  3. Auditer les autorisations accordées par le fichier sudoers (sudo -l).
  4. Sous Windows, inspecter les privilèges de jetons (whoami /priv) et les services non quotés.
  5. Mettre en place un tunnel de pivoting (SSH -D ou Chisel) pour router les attaques vers le réseau interne.

10. Révision active

Résumé essentiel
  • L'exploitation de buffer overflows détourne EIP/RIP mais se heurte aux protections modernes ASLR, DEP/NX et Canaries.
  • Metasploit structure l'attaque en exploits, payloads, modules auxiliaires et sessions de post-exploitation Meterpreter.
  • Sous Linux, les binaires SUID non nécessaires et les règles sudoers NOPASSWD sont les vecteurs d'escalade les plus courants.
  • Sous Windows, les privilèges de jetons applicatifs (SeImpersonate) permettent d'obtenir les droits SYSTEM via PrintSpoofer.
  • Le pivoting réseau étend la portée de l'intrusion en transformant une machine compromise en passerelle de rebond.

Checklist de maîtrise

  • Je comprends la structure d'un payload Buffer Overflow avec offset, adresse de retour, NOP sled et shellcode.
  • Je sais identifier et exploiter les binaires SUID répertoriés dans GTFOBins.
  • Je maîtrise l'analyse des failles sudoers NOPASSWD et l'échappement de shell.
  • Je sais monter un tunnel de rebond SSH ou Chisel pour pivoter vers un segment interne.

Les 8 notions à connaître absolument

  1. Stack Buffer Overflow : Écrasement de la mémoire de pile permettant de remplacer le pointeur d'instruction EIP/RIP par l'adresse d'un shellcode.
  2. GTFOBins : Catalogue de référence des binaires Unix légitimes détournables pour échapper à un shell restreint ou élever ses privilèges.
  3. NOP Sled : Suite d'octets 0x90 créant une zone tampon d'atterrissage sécurisée précédant le shellcode lors d'un buffer overflow.
  4. Unquoted Service Path : Chemin d'exécutable de service Windows contenant des espaces sans guillemets permettant l'injection de binaire.
  5. SeImpersonatePrivilege : Privilège Windows autorisant l'usurpation de jetons de sécurité clients pour obtenir les droits NT AUTHORITY\SYSTEM.
  6. L'exploitation de buffer overflows détourne EIP/RIP mais se heurte aux protections modernes ASLR, DEP/NX et Canaries.
  7. Metasploit structure l'attaque en exploits, payloads, modules auxiliaires et sessions de post-exploitation Meterpreter.
  8. Sous Linux, les binaires SUID non nécessaires et les règles sudoers NOPASSWD sont les vecteurs d'escalade les plus courants.
