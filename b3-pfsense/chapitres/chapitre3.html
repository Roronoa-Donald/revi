Chapitre 3 — Translation d’Adresses (NAT), Redirections & Routage Multi-WAN

Module 3 ≈ 2 h 45 de travail Réservé B3 et plus
Mise en situation

Dans un réseau professionnel, les adresses IPv4 publiques sont une ressource rare et coûteuse. Le pare-feu pfSense doit donc traduire les adresses privées internes (RFC 1918) pour leur permettre d’accéder à l’Internet public (SNAT) et permettre l’hébergement sécurisé de services internes via la redirection de ports (DNAT). De plus, pour garantir une haute disponibilité sans interruption de service face aux pannes des fournisseurs d’accès, l’infrastructure d’entreprise s’appuie sur le routage Multi-WAN : agrégation de liens en répartition de charge (Load Balancing) et basculement automatique instantané (Failover) orchestré par le démon de surveillance dpinger.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. configurer les règles de redirection de ports (Port Forwarding / DNAT) et comprendre leur liaison avec les règles de filtrage WAN ;
  2. déployer le NAT 1:1 pour associer des adresses IP publiques dédiées à des serveurs critiques ;
  3. maîtriser le NAT sortant (Outbound NAT) dans ses modes Automatique et Hybride ;
  4. créer des adresses IP Virtuelles (Virtual IPs : IP Alias, CARP, Proxy ARP) sur les interfaces réseau ;
  5. configurer des passerelles multiples et les agréger au sein de Gateway Groups avec gestion des Tiers ;
  6. développer en Python 3 des simulateurs de DNAT, des moteurs de NAT sortant hybride et des ordonnanceurs Multi-WAN.

1. Translation d’Adresses Entrante : Port Forwarding (DNAT) & NAT 1:1

Le Port Forwarding (DNAT - Destination NAT) permet d’exposer un serveur hébergé sur une adresse IP privée interne (LAN ou DMZ) derrière l’adresse IP publique unique de l’interface WAN du pare-feu.

1. Mécanisme du Port Forwarding

Lorsqu’un paquet externe frappe l’interface WAN sur un port donné (ex: port 8080) :

  1. La table NAT réécrit l’en-tête IP : dst_ip: WAN_IP → 192.168.1.50 et dst_port: 8080 → 80.
  2. La règle de filtrage WAN associée : La translation d’adresse ne dispense pas du filtrage ! Par défaut, pfSense crée automatiquement la règle de pare-feu correspondante sur l’interface WAN autorisant ce flux vers l’hôte interne (option Filter rule association).
  3. NAT Reflection : Mécanisme permettant à un poste du réseau local d’accéder au serveur interne en utilisant son nom de domaine ou son IP publique sans quitter le pare-feu.

2. Le NAT 1:1 (One-to-One)

Le NAT 1:1 établit une correspondance bidirectionnelle statique complète entre une adresse IP publique dédiée et une adresse IP privée interne :

  • Tous les ports entrants non mappés spécifiquement sont acheminés vers ce serveur interne unique.
  • Tout le trafic sortant émis par ce serveur utilise systématiquement cette adresse IP publique dédiée comme IP source.
  • Idéal pour les serveurs de messagerie (SMTP), passerelles VPN tierces ou serveurs applicatifs dédiés possédant leur propre bloc public (/29 ou /28).

2. NAT Sortant (Outbound NAT) : Modes Automatique, Hybride & IP Virtuelles

L’Outbound NAT (SNAT - Source NAT) réécrit l’adresse IP source des paquets générés par les postes internes lorsqu’ils sortent vers Internet, remplaçant l’adresse privée par l’IP publique du WAN (Masquerading / PAT - Port Address Translation).

Mode Automatique (Automatic)

pfSense génère dynamiquement des règles de translation pour toutes les interfaces internes déclarées vers l’adresse IP principale du WAN. Simple et sans maintenance, mais totalement rigide.

Mode Hybride (Hybrid)

Le mode recommandé en production. Il conserve toutes les règles automatiques tout en permettant à l’administrateur d’insérer au sommet des règles manuelles prioritaires pour des cas d’usage spécifiques.

Mode Manuel Avancé (Manual)

pfSense désactive la génération automatique : l’administrateur doit déclarer explicitement chaque règle de sortie. Offre un contrôle total mais exige une rigueur absolue lors de l’ajout d’interfaces.

Les Types d’Adresses IP Virtuelles (Virtual IPs - VIPs)

Pour utiliser des adresses IP publiques additionnelles fournies par le FAI sur une interface WAN, pfSense propose plusieurs types de VIPs :

3. Architecture Multi-WAN : Groupes de Passerelles, Tiers & PBR

Lorsque le pare-feu dispose de plusieurs connexions Internet (ex: WAN1 Fibre Optique et WAN2 4G/5G de secours), pfSense orchestre les flux à travers des Gateway Groups :

1. Notion de Tiers dans les Gateway Groups

Chaque passerelle membre du groupe se voit assigner un niveau de priorité (Tier) :

  • Load Balancing (Répartition de charge) : Les deux passerelles sont configurées sur le même Tier (ex: WAN1 = Tier 1, WAN2 = Tier 1). Les connexions sont distribuées selon le poids (Weight) de chaque liaison.
  • Failover (Basculement automatique) : Les passerelles sont sur des Tiers différents (ex: WAN1 = Tier 1, WAN2 = Tier 2). Tout le trafic emprunte WAN1 ; si WAN1 tombe en panne, WAN2 prend immédiatement le relais.

Le démon de surveillance dpinger envoie des sondes ICMP périodiques vers l’IP de monitoring (ex: 8.8.8.8 ou la passerelle du FAI) pour mesurer la latence RTT et le taux de perte de paquets.

2. Routage par Politique (Policy-Based Routing - PBR)

Dans pfSense, le choix de la passerelle de sortie peut être forcé directement dans les règles de filtrage (champ Gateway sous les options avancées) :

Cas concret : Forcer le trafic vidéo ou les postes invités à sortir exclusivement par le lien 4G secondaire pour préserver la bande passante de la fibre optique principale.

Règle d’or : Toujours placer une règle autorisant le trafic inter-VLANs local (sans passerelle forcée) au-dessus des règles utilisant un Gateway Group pour ne pas casser la communication interne !

Exercice 1 — Simulateur de redirection de ports (Port Forwarding / DNAT)

Python Niveau 1 — Acquisition

Objectif : Appliquer les règles de NAT entrant (Port Forwarding) pour rediriger les flux externes vers les serveurs internes.

Dans pfSense, le Port Forwarding (DNAT) permet d'exposer un service interne hébergé sur une IP privée derrière l'adresse IP publique de l'interface WAN.

Le script lit sur l'entrée standard d'abord les règles de redirection :
NAT_RULE ext_port=<int> int_ip=<ip> int_port=<int>.
Puis des paquets entrants sur le WAN :
INCOMING_PKT id=<nom> ext_dst_ip=<wan_ip> ext_dst_port=<int>.

Règles :
- Si ext_dst_port correspond à une NAT_RULE :
status=REDIRECTED new_dst={int_ip}:{int_port}.
- Sinon :
status=DROPPED new_dst=NONE.

Pour chaque paquet, afficher :
DNAT_REPORT id={id} ext_port={ext_dst_port} status={status} target={new_dst}

Entrée du programme
NAT_RULE ext_port=8080 int_ip=192.168.1.50 int_port=80
INCOMING_PKT id=PKT1 ext_dst_ip=203.0.113.1 ext_dst_port=8080
INCOMING_PKT id=PKT2 ext_dst_ip=203.0.113.1 ext_dst_port=22
Sortie attendue
DNAT_REPORT id=PKT1 ext_port=8080 status=REDIRECTED target=192.168.1.50:80
DNAT_REPORT id=PKT2 ext_port=22 status=DROPPED target=NONE

Port 8080 redirigé vers 192.168.1.50:80 ; port 22 non mappé rejeté.

Deux indices, rédigés en mots
  1. Gérer un dictionnaire associant ext_port à (int_ip, int_port).
  2. Vérifier si ext_dst_port existe dans les règles.

Exercice 2 — Moteur d’Outbound NAT (SNAT) : Masquerade vs Adresses Virtuelles (VIP)

Python Niveau 2 — Application

Objectif : Translater les adresses sources privées des paquets sortants vers l’IP WAN principale ou une IP Virtuelle CARP/Statique.

pfSense propose 4 modes d'Outbound NAT (Automatique, Hybride, Manuel, Désactivé). Lorsqu'un paquet quitte le WAN, sa source privée est remplacée (SNAT / Masquerade).

Le script lit sur l'entrée standard d'abord les règles d'Outbound NAT :
OUTBOUND_DEF src_subnet=<cidr> nat_ip=<WAN_INTERFACE|ip>.
Puis des paquets sortants :
OUT_PKT id=<nom> src_ip=<ip> wan_ip=<ip>.

Règles :
- Vérifier si src_ip appartient à un src_subnet déclaré.
- Si oui :
- Si nat_ip == 'WAN_INTERFACE' : translater vers wan_ip.
- Sinon : translater vers nat_ip.
status=SNAT_APPLIED new_src={ip_translatée}.
- Si non :
status=NO_NAT new_src={src_ip}.

Pour chaque paquet, afficher :
SNAT_REPORT id={id} original_src={src_ip} status={status} nat_src={new_src}

Entrée du programme
OUTBOUND_DEF src_subnet=192.168.1.0/24 nat_ip=WAN_INTERFACE
OUT_PKT id=P1 src_ip=192.168.1.15 wan_ip=203.0.113.100
OUT_PKT id=P2 src_ip=10.0.0.5 wan_ip=203.0.113.100
Sortie attendue
SNAT_REPORT id=P1 original_src=192.168.1.15 status=SNAT_APPLIED nat_src=203.0.113.100
SNAT_REPORT id=P2 original_src=10.0.0.5 status=NO_NAT nat_src=10.0.0.5

192.168.1.15 translaté vers l’IP WAN 203.0.113.100 ; 10.0.0.5 non couvert conservé sans NAT.

Deux indices, rédigés en mots
  1. Stocker les réseaux avec ipaddress.ip_network(subnet).
  2. Tester src_ip in net_obj pour appliquer la règle correspondante.

Exercice 3 — Évaluateur de Gateway Groups Multi-WAN (Load Balancing vs Failover)

Python Niveau 3 — Raisonnement

Objectif : Aiguiller les paquets selon l’état de santé des passerelles WAN et la hiérarchie de niveaux (Tiers) dans un groupe pfSense.

pfSense gère les connexions Internet multiples via les Gateway Groups :
- Deux passerelles dans le même Tier (ex: Tier 1) : Load Balancing (répartition de charge Round-Robin).
- Des passerelles dans des Tiers différents : Failover (basculement). Le Tier 1 est utilisé en priorité ; s'il tombe (état DOWN), le Tier 2 prend automatiquement le relais.

Le script lit sur l'entrée standard des déclarations de passerelles au format :
GW_STATUS name=<nom> tier=<1..3> state=<ONLINE|DOWN>.

Règles d'élection de la passerelle active :
1. Trouver le plus petit niveau tier possédant au moins une passerelle ONLINE.
2. S'il existe plusieurs passerelles ONLINE dans ce meilleur tier, le mode est LOAD_BALANCING et la liste des passerelles actives est affichée triée par ordre alphabétique séparée par une virgule.
3. S'il n'y a qu'une seule passerelle ONLINE dans ce tier :
- Si tier == 1 : mode=PRIMARY_ACTIVE.
- Si tier > 1 : mode=FAILOVER_ACTIVE.
4. Si aucune passerelle n'est ONLINE : mode=TOTAL_OUTAGE selected=NONE.

Afficher :
MULTIWAN_DECISION tier={meilleur_tier} mode={mode} selected={passerelles}

Entrée du programme
GW_STATUS name=WAN_FIBRE tier=1 state=DOWN
GW_STATUS name=WAN_4G tier=2 state=ONLINE
Sortie attendue
MULTIWAN_DECISION tier=2 mode=FAILOVER_ACTIVE selected=WAN_4G

Tier 1 en panne : basculement automatique vers le Tier 2 (WAN_4G).

Deux indices, rédigés en mots
  1. Grouper les passerelles ONLINE par tier.
  2. Prendre le plus petit tier non vide (1, 2, ou 3).
  3. Si plusieurs passerelles dans ce tier, trier leurs noms par ordre alphabétique.

5. QCM — niveau examen

Quel type de NAT est utilisé pour exposer un serveur Web interne (port 80) sur l’IP publique du WAN ?

Le Port Forwarding (Destination NAT) redirige les requêtes externes vers l’adresse IP privée et le port interne du serveur hébergé.

Pourquoi une règle de filtrage WAN est-elle nécessaire lors de la création d’une redirection de port (DNAT) ?

Le NAT modifie les adresses mais n’autorise pas le passage : le moteur de filtrage exige une règle explicite autorisant le trafic vers l’hôte interne.

Quel mode d’Outbound NAT est officiellement recommandé en environnement de production sous pfSense ?

Le mode Hybride conserve la génération automatique pour les réseaux standards tout en autorisant l’ajout de règles manuelles prioritaires.

Quel type d’adresse IP Virtuelle (VIP) est utilisé lorsqu’un bloc public doit être partagé entre deux nœuds en cluster haute disponibilité ?

Les VIPs de type CARP disposent d’une adresse MAC virtuelle et synchronisent l’état actif/passif entre deux pare-feux redondants.

Dans un Gateway Group pfSense, quelle configuration permet d’obtenir un équilibrage de charge (Load Balancing) entre deux liaisons WAN ?

Lorsque deux ou plusieurs passerelles sont affectées au même Tier dans un Gateway Group, pfSense répartit les connexions en Round-Robin pondéré.

Quel démon système sous pfSense est responsable de mesurer la latence et les pertes de paquets sur les passerelles WAN ?

dpinger est le démon officiel de surveillance sous FreeBSD/pfSense qui teste périodiquement les passerelles et déclenche le basculement si les seuils sont dépassés.

Qu’est-ce que le NAT Reflection ?

Le NAT Reflection permet aux postes internes de joindre les serveurs locaux en utilisant le nom de domaine externe pointant vers l’IP WAN publique.

Pourquoi doit-on exclure le trafic inter-VLANs local avant d’appliquer une règle de Policy-Based Routing (PBR) vers un Gateway Group ?

Si la règle de PBR envoie tout le trafic vers la passerelle WAN par défaut, les paquets locaux destinés à une autre interface interne sortiront vers le FAI et seront perdus.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Créer une règle de Port Forwarding sans autoriser le trafic dans les règles de filtrage WAN.
  • Appliquer une passerelle PBR WAN sur une règle LAN sans exclure le trafic local RFC 1918, brisant les flux inter-VLANs.
  • Configurer le même Tier dans un Gateway Group en croyant faire du Failover (cela fait du Load Balancing).
  • Utiliser comme IP de monitoring dpinger une adresse qui ne répond pas aux pings ICMP, provoquant un basculement erroné.

7. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Étape 1 : Cartographier les flux exposés (DNAT) et les blocs d’adresses IP publiques additionnelles disponibles.
  2. Étape 2 : Configurer les règles de Port Forwarding en activant l’association automatique de la règle de filtrage WAN.
  3. Étape 3 : Basculer l’Outbound NAT en mode Hybride et déclarer les règles manuelles utilisant les VIPs dédiées.
  4. Étape 4 : Déclarer les passerelles WAN dans System > Routing et renseigner les IP de monitoring pour dpinger.
  5. Étape 5 : Créer le Gateway Group en assignant les Tiers selon la politique choisie (Failover vs Load Balancing).
  6. Étape 6 : Appliquer le Gateway Group via une règle de PBR en prenant soin d’exclure les sous-réseaux locaux RFC 1918.

8. Révision active

Résumé essentiel
  • Le Port Forwarding (DNAT) redirige les ports externes du WAN vers les adresses IP et ports privés internes.
  • Toute règle DNAT exige une règle de filtrage autorisant explicitement le passage des paquets sur le WAN.
  • Le NAT 1:1 associe de manière bidirectionnelle et statique une adresse IP publique à un serveur interne unique.
  • Le mode Hybrid Outbound NAT permet de concilier la simplicité des règles automatiques et la flexibilité de règles manuelles.
  • Les Gateway Groups organisent la redondance Multi-WAN : mêmes Tiers pour le Load Balancing, Tiers différents pour le Failover.
  • Le Policy-Based Routing (PBR) permet de router des flux applicatifs spécifiques sur des passerelles choisies.

Checklist de maîtrise

  • Je sais créer une redirection de port DNAT et vérifier la règle de filtrage WAN associée.
  • Je comprends la différence d’usage entre Port Forwarding et NAT 1:1.
  • Je sais pourquoi le mode Hybrid Outbound NAT est recommandé en entreprise.
  • Je sais configurer une adresse IP Virtuelle (VIP) de type IP Alias.
  • Je maîtrise l’attribution des Tiers dans un Gateway Group pour réaliser du Failover ou du Load Balancing.
  • Je sais pourquoi il faut exclure le trafic inter-VLANs avant d’appliquer une passerelle PBR.
