Chapitre 5 — Sécurité de la Couche d’Accès (Port Security, DHCP Snooping & DAI)

Module 5 ≈ 2 h 45 de travail Réservé B1 et plus
Mise en situation

La couche d’accès d’un réseau local d’entreprise est le périmètre le plus vulnérable aux menaces internes et aux compromissions physiques. Tout collaborateur, prestataire ou intrus branchant une machine sur une prise murale RJ-45 ou une borne Wi-Fi peut tenter de saturer la table CAM du commutateur (MAC Flooding) pour transformer le switch en concentrateur (hub) passif et intercepter le trafic, déployer un serveur DHCP pirate (Rogue DHCP) pour détourner la passerelle par défaut des utilisateurs, ou émettre des réponses ARP falsifiées (ARP Poisoning) pour réaliser une attaque d’homme du milieu (Man-In-The-Middle - MITM). L’ingénieur réseau et cybersécurité de niveau Bachelor 3 doit maîtriser l’arsenal complet de durcissement de niveau 2 : configurer Port Security avec apprentissage dynamique Sticky MAC, activer DHCP Snooping avec ségrégation stricte des ports de confiance, et corréler l’inspection dynamique ARP (DAI) avec IP Source Guard pour neutraliser toute tentative d’usurpation.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. comprendre les vecteurs d’attaques majeures de niveau 2 (MAC Flooding, Rogue DHCP, ARP Spoofing) ;
  2. configurer et auditer la fonctionnalité Port Security et ses modes de violation (protect, restrict, shutdown) ;
  3. déployer le mécanisme Sticky MAC pour l’apprentissage persistant des adresses d’accès autorisées ;
  4. mettre en œuvre DHCP Snooping avec distinction rigoureuse des ports trusted et untrusted ;
  5. analyser la base de données DHCP Snooping Binding Table et son exploitation par Dynamic ARP Inspection (DAI) ;
  6. développer en Python 3 des simulateurs de violation de sécurité, des inspecteurs DHCP Snooping et des filtres DAI.

1. Attaques Fondamentales de Niveau 2 : Saturation CAM & Serveurs DHCP Pirates

Historiquement conçu sans préoccupation de sécurité cryptographique, le standard Ethernet considère que tout port physique connecté est légitime. Les attaquants exploitent cette confiance aveugle par deux techniques offensives classiques :

1. Saturation de Table CAM (MAC Address Flooding)

La table de commutation (Content Addressable Memory - CAM) possède une mémoire finie (typiquement 8 000 à 32 000 entrées). Un outil offensif (ex: macof) injecte des dizaines de milliers de trames Ethernet forgées avec des adresses MAC sources aléatoires par seconde :

  • La table CAM sature en quelques fractions de seconde.
  • Incapable d’apprendre les adresses légitimes, le commutateur passe en mode fail-open (Unicast Flooding) : il diffuse chaque trame reçue sur tous ses ports comme un simple hub.
  • L’attaquant positionné sur son port capture l’intégralité des flux du VLAN en clair.

2. Serveur DHCP Pirate (Rogue DHCP Server)

Lorsqu’un poste client démarre, il émet une diffusion DHCPDISCOVER. Un attaquant déployant un serveur DHCP pirate répond plus rapidement que le serveur officiel (DHCPOFFER) :

  • Il fournit une adresse IP valide au client.
  • Il positionne sa propre machine comme passerelle par défaut et serveur DNS.
  • Tout le trafic sortant du poste client est intercepté, analysé et modifié avant d’être relayé.

2. Port Security : Contrôle d’Accès Matériel & Modes de Violation

La fonctionnalité Port Security permet de restreindre le nombre d’adresses MAC autorisées à émettre sur une interface d’accès et d’associer des adresses MAC matérielles spécifiques :

Apprentissage et Types d'Adresses MAC

  • Statique : Configurée manuellement par l’administrateur (switchport port-security mac-address <mac>).
  • Dynamique : Apprise au vol par le commutateur et oubliée au redémarrage.
  • Sticky MAC : Apprise dynamiquement sur la première trame reçue et automatiquement inscrite dans la configuration courante (running-config) pour persister après redémarrage.

Les Trois Modes de Violation

ModeTrafic InconnuNotification Syslog / SNMPÉtat du Port
protectDétruit (Drop)Non (silencieux)Reste Up
restrictDétruit (Drop)Oui (compteur incrémenté)Reste Up
shutdownDétruit (Drop)Oui (alerte critique)err-disable (désactivé)
Rétablissement d'un Port en état err-disable

Lorsqu’un port passe en état err-disable suite à une violation en mode shutdown, il ne se réactive pas automatiquement par défaut. L’administrateur doit intervenir manuellement (shutdown puis no shutdown), ou activer le redémarrage temporisé automatique : errdisable recovery cause psecure-violation avec un intervalle configuré (ex: 300 secondes).

3. DHCP Snooping & Dynamic ARP Inspection (DAI)

Pour contrer les attaques de type Rogue DHCP et Man-In-The-Middle par usurpation ARP (ARP Poisoning), les commutateurs combinent deux technologies complémentaires de filtrage dynamique :

1. DHCP Snooping

Agit comme un pare-feu applicatif de niveau 2 pour les messages DHCP :

  • Ports de Confiance (Trusted) : Reliés aux serveurs DHCP légitimes et liaisons montantes (uplinks). Les messages serveurs (DHCPOFFER, DHCPACK) y sont autorisés.
  • Ports Non Approuvés (Untrusted) : Reliés aux utilisateurs. Tout message serveur émis depuis ces ports est immédiatement bloqué.
  • DHCP Snooping Binding Table : Construit une table dynamique liant : Adresse MAC, Adresse IP attribuée, Durée du bail, VLAN et Port physique.

2. Dynamic ARP Inspection (DAI) & IP Source Guard

Exploite directement la base construite par le DHCP Snooping :

  • Dynamic ARP Inspection (DAI) : Intercepte toutes les requêtes et réponses ARP sur les ports untrusted. Si le couple IP/MAC ne figure pas dans la table DHCP Snooping, la trame ARP est détruite, neutralisant totalement l’usurpation de passerelle.
  • IP Source Guard (IPSG) : Filtre tous les paquets IP au niveau matériel : si un utilisateur change manuellement son adresse IP sans passer par le DHCP légitime, le commutateur bloque immédiatement ses paquets.

Exercice 1 — Contrôleur de Port Security et détection de violation (Protect, Restrict, Shutdown)

Python Niveau 1 — Acquisition

Objectif : Simuler le mécanisme Cisco Port Security et les modes de réaction face aux adresses MAC non autorisées.

La fonctionnalité Port Security sur les commutateurs de niveau 2 restreint l'accès d'un port aux seules adresses MAC approuvées (statiques ou apprises dynamiquement jusqu'à un quota max_mac).

Modes de violation lorsqu'une adresse MAC non autorisée émet une trame :
- protect : Détruit silencieusement la trame sans générer de log ni incrémenter de compteur ; le port reste opérationnel pour les MACs légitimes (→ action=DROP_SILENT state=UP).
- restrict : Détruit la trame, incrémente le compteur de violations et émet un piège SNMP / log syslog ; le port reste UP (→ action=DROP_ALERT state=UP).
- shutdown : Désactive immédiatement le port physique qui passe en état d'erreur irrécupérable ERR_DISABLE (→ action=PORT_SHUTDOWN state=ERR_DISABLE). Toutes les trames suivantes reçues sur ce port sont rejetées (→ action=DROP state=ERR_DISABLE).

Le script lit sur l'entrée standard :
- La configuration du port :
PORT_SEC port=<nom> max_mac=<int> mode=<protect|restrict|shutdown> sticky_macs=<mac1,mac2,...|NONE>
- Les trames arrivant sur le port :
FRAME id=<nom> src_mac=<mac>

Pour chaque trame, afficher :
PORT_SEC_REPORT id={id} port={port} mac={src_mac} status={PERMIT|VIOLATION|PORT_DOWN} action={action} state={state}

Entrée du programme
PORT_SEC port=Fa0/1 max_mac=1 mode=shutdown sticky_macs=00:11:22:33:44:01
FRAME id=F1 src_mac=00:11:22:33:44:01
FRAME id=F2 src_mac=00:aa:bb:cc:dd:02
FRAME id=F3 src_mac=00:11:22:33:44:01
Sortie attendue
PORT_SEC_REPORT id=F1 port=Fa0/1 mac=00:11:22:33:44:01 status=PERMIT action=FORWARD state=UP
PORT_SEC_REPORT id=F2 port=Fa0/1 mac=00:aa:bb:cc:dd:02 status=VIOLATION action=PORT_SHUTDOWN state=ERR_DISABLE
PORT_SEC_REPORT id=F3 port=Fa0/1 mac=00:11:22:33:44:01 status=PORT_DOWN action=DROP state=ERR_DISABLE

F1 est autorisée ; F2 déclenche le shutdown du port ; F3 arrive sur un port désactivé.

Deux indices, rédigés en mots
  1. Stocker les MACs connues dans une liste ordonnée ou un set.
  2. Si le port est déjà en ERR_DISABLE, rejeter toute nouvelle trame (PORT_DOWN).
  3. Si une nouvelle MAC arrive alors que len(known) < max_mac, l'ajouter sans violation.

Exercice 2 — Validateur de base de données de liaison DHCP Snooping

Python Niveau 2 — Application

Objectif : Filtrer les messages DHCP selon le statut de confiance des ports et alimenter la base de liaison (Binding DB).

L'attaque par serveur DHCP pirate (Rogue DHCP Server) permet à un attaquant de distribuer de fausses passerelles et de faux serveurs DNS aux postes du réseau. La parade DHCP Snooping classe les ports du commutateur en deux catégories :
- Ports de confiance (TRUSTED) : Reliés aux serveurs DHCP légitimes ou aux uplinks de distribution. Tous les messages DHCP y sont autorisés.
- Ports non fiables (UNTRUSTED) : Reliés aux utilisateurs finals. Seules les requêtes clients (DISCOVER, REQUEST) y sont autorisées. Si une réponse serveur (OFFER ou ACK) y est détectée, elle est immédiatement détruite et signalée comme attaque Rogue DHCP.

Le script lit sur l'entrée standard :
- La configuration de confiance des ports :
PORT_TRUST name=<nom> trust=<TRUSTED|UNTRUSTED>
- Les paquets DHCP interceptés :
DHCP_MSG id=<nom> port=<nom> type=<DISCOVER|OFFER|REQUEST|ACK> client_mac=<mac> assigned_ip=<ip> vlan=<int>

Règles de traitement :
1. Si port.trust == 'UNTRUSTED' et type in ['OFFER', 'ACK'] :
status=SECURITY_VIOLATION action=DROP reason=ROGUE_DHCP_SERVER.
2. Si port.trust == 'UNTRUSTED' et type in ['DISCOVER', 'REQUEST'] :
status=PERMIT action=FORWARD reason=LEGIT_CLIENT_REQUEST.
3. Si port.trust == 'TRUSTED' :
status=PERMIT action=FORWARD reason=TRUSTED_PORT_TRAFFIC.
(Si de plus type == 'ACK' et assigned_ip != '0.0.0.0', la liaison est insérée dans la base de données Snooping).

Pour chaque message, afficher :
DHCP_SNOOP_REPORT id={id} port={port} type={type} status={status} action={action} reason={reason}

Entrée du programme
PORT_TRUST name=Gi0/1 trust=UNTRUSTED
PORT_TRUST name=Gi0/24 trust=TRUSTED
DHCP_MSG id=M1 port=Gi0/1 type=DISCOVER client_mac=00:11:22:33:44:01 assigned_ip=0.0.0.0 vlan=10
DHCP_MSG id=M2 port=Gi0/1 type=OFFER client_mac=00:11:22:33:44:01 assigned_ip=192.168.10.50 vlan=10
DHCP_MSG id=M3 port=Gi0/24 type=ACK client_mac=00:11:22:33:44:01 assigned_ip=192.168.10.50 vlan=10
Sortie attendue
DHCP_SNOOP_REPORT id=M1 port=Gi0/1 type=DISCOVER status=PERMIT action=FORWARD reason=LEGIT_CLIENT_REQUEST
DHCP_SNOOP_REPORT id=M2 port=Gi0/1 type=OFFER status=SECURITY_VIOLATION action=DROP reason=ROGUE_DHCP_SERVER
DHCP_SNOOP_REPORT id=M3 port=Gi0/24 type=ACK status=PERMIT action=FORWARD reason=TRUSTED_PORT_TRAFFIC

M1 est un Discover client normal ; M2 est une tentative d'usurpation DHCP serveur sur port non fiable ; M3 est la réponse légitime du serveur.

Deux indices, rédigés en mots
  1. Mémoriser le statut de chaque port (TRUSTED ou UNTRUSTED).
  2. Identifier les réponses serveur OFFER et ACK arrivant sur port UNTRUSTED.

Exercice 3 — Filtre anti-usurpation Dynamic ARP Inspection (DAI)

Python Niveau 3 — Raisonnement

Objectif : Valider les trames ARP en croisant les couples (IP, MAC) avec la base de données DHCP Snooping.

L'attaque par empoisonnement de cache ARP (ARP Poisoning / ARP Spoofing) permet à un pirate d'intercepter tout le trafic d'un sous-réseau en s'interposant entre les postes et la passerelle (Man-in-the-Middle).
Le mécanisme Dynamic ARP Inspection (DAI) intercepte toutes les requêtes et réponses ARP sur les ports non fiables et valide la cohérence du couple (sender_ip, sender_mac) par rapport à la base de liaison DHCP Snooping Binding Database.

Le script lit sur l'entrée standard :
- Les liaisons valides enregistrées dans la base Snooping :
BINDING mac=<mac> ip=<ip> vlan=<int>
- Les paquets ARP circulant sur le réseau :
ARP_FRAME id=<nom> vlan=<int> sender_mac=<mac> sender_ip=<ip> target_ip=<ip>

Règles d'inspection DAI :
Pour chaque paquet ARP :
1. Si le couple (sender_mac, sender_ip, vlan) correspond exactement à une entrée de la base BINDING :
status=PERMIT action=FORWARD reason=BINDING_MATCH.
2. Si sender_ip existe dans la base pour ce vlan mais avec une mac différente (usurpation d'IP avérée) :
status=DENY action=DROP_ALERT reason=ARP_SPOOFING_DETECTED.
3. Si sender_ip n'existe pas du tout dans la base de données :
status=DENY action=DROP reason=UNKNOWN_HOST_BINDING.

Pour chaque paquet ARP, afficher :
DAI_AUDIT id={id} vlan={vlan} sender_ip={sender_ip} sender_mac={sender_mac} status={status} action={action} reason={reason}

Entrée du programme
BINDING mac=00:11:22:33:44:01 ip=192.168.1.10 vlan=10
BINDING mac=00:11:22:33:44:02 ip=192.168.1.20 vlan=10
ARP_FRAME id=ARP1 vlan=10 sender_mac=00:11:22:33:44:01 sender_ip=192.168.1.10 target_ip=192.168.1.1
ARP_FRAME id=ARP2 vlan=10 sender_mac=00:aa:bb:cc:dd:ee sender_ip=192.168.1.10 target_ip=192.168.1.20
ARP_FRAME id=ARP3 vlan=10 sender_mac=00:11:22:33:44:99 sender_ip=192.168.1.99 target_ip=192.168.1.1
Sortie attendue
DAI_AUDIT id=ARP1 vlan=10 sender_ip=192.168.1.10 sender_mac=00:11:22:33:44:01 status=PERMIT action=FORWARD reason=BINDING_MATCH
DAI_AUDIT id=ARP2 vlan=10 sender_ip=192.168.1.10 sender_mac=00:aa:bb:cc:dd:ee status=DENY action=DROP_ALERT reason=ARP_SPOOFING_DETECTED
DAI_AUDIT id=ARP3 vlan=10 sender_ip=192.168.1.99 sender_mac=00:11:22:33:44:99 status=DENY action=DROP reason=UNKNOWN_HOST_BINDING

ARP1 est légitime ; ARP2 usurpe l'IP 192.168.1.10 avec une fausse MAC ; ARP3 est inconnu dans le bail DHCP.

Deux indices, rédigés en mots
  1. Normaliser les adresses MAC en minuscules.
  2. Gérer un dictionnaire indexé par (vlan, sender_ip) renvoyant la MAC légitime.

5. QCM — niveau examen

Quel est l’objectif d’une attaque par saturation de table CAM (MAC Flooding) menée contre un commutateur ?

En saturant la table CAM, le switch ne peut plus associer les MACs aux ports et diffuse chaque trame sur tous les ports du VLAN comme un hub.

Quel mode de violation de Port Security désactive immédiatement le port physique et le place en état « err-disable » ?

Le mode shutdown coupe administrativement le port (err-disable), incrémente le compteur de violation et émet une alerte syslog/SNMP.

Quel est le rôle de l’option « sticky » dans la commande « switchport port-security mac-address sticky » ?

L’apprentissage sticky convertit dynamiquement la première adresse MAC active apprise en entrée statique inscrite dans la configuration courante.

Dans une architecture protégée par DHCP Snooping, sur quel type de port les réponses DHCPOFFER d’un serveur DHCP légitime doivent-elles transiter ?

Seuls les ports marqués comme Trusted sont autorisés à recevoir et relayer des messages DHCP émis par un serveur (DHCPOFFER, DHCPACK).

Quelles informations sont consignées dans la base de données dynamique DHCP Snooping Binding Table ?

La table de liaison associe pour chaque poste : adresse MAC, adresse IP reçue par DHCP, durée du bail, VLAN d’appartenance et numéro de port physique.

Comment la technologie Dynamic ARP Inspection (DAI) neutralise-t-elle les attaques d’usurpation de passerelle (ARP Poisoning) ?

DAI intercepte chaque trame ARP sur les ports untrusted : si l’adresse IP ou l’adresse MAC ne correspond pas à l’entrée validée dans la base DHCP Snooping, la trame est détruite.

Quelle technologie de niveau 2 empêche un utilisateur d’utiliser une adresse IP statique configurée manuellement non attribuée par le DHCP ?

IP Source Guard applique un filtre matériel strict au niveau du port : seuls les paquets dont l’adresse IP source figure dans la table DHCP Snooping sont autorisés.

Que se passe-t-il par défaut sous Cisco IOS lorsqu’un commutateur reçoit un paquet DHCP sur un port untrusted contenant l’option 82 alors qu’il n’est pas configuré comme relais de confiance ?

Par défaut, un commutateur avec DHCP Snooping actif rejette les paquets DHCP contenant l’option 82 (relay agent information) arrivant sur un port untrusted.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de configurer « ip dhcp snooping trust » sur la liaison montante vers le serveur DHCP, bloquant l’attribution de baux pour tous les clients du switch.
  • Activer Dynamic ARP Inspection (DAI) sur un VLAN sans avoir préalablement peuplé la base DHCP Snooping (ou sans ACL ARP statique pour les serveurs en IP fixe), bloquant l’ensemble du trafic légitime.
  • Choisir le mode « protect » au lieu de « shutdown » dans un environnement critique, laissant l’attaquant persister sans aucune alerte générée.
  • Ne pas limiter le taux de requêtes ARP (ip arp inspection limit rate) sur les ports utilisateurs, exposant le CPU du commutateur à un déni de service.

7. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Étape 1 : Activer Port Security sur l’ensemble des ports d’accès utilisateurs en fixant la limite maximale à 1 ou 2 adresses MAC.
  2. Étape 2 : Configurer le mode de violation shutdown et activer l’apprentissage sticky pour pérenniser les affectations physiques.
  3. Étape 3 : Activer globalement la surveillance DHCP Snooping sur le commutateur et pour les VLANs utilisateurs concernés.
  4. Étape 4 : Déclarer explicitement les liaisons montantes (Trunks vers le cœur de réseau) et ports de serveurs en mode trusted (ip dhcp snooping trust).
  5. Étape 5 : Activer l’inspection dynamique ARP (ip arp inspection vlan <id>) sur les VLANs protégés par DHCP Snooping.
  6. Étape 6 : Activer IP Source Guard sur les ports d’accès pour interdire l’usurpation d’adresses IP statiques non autorisées.

8. Révision active

Résumé essentiel
  • Le MAC Flooding vise à saturer la mémoire CAM du commutateur pour forcer la diffusion de toutes les trames en clair (hub).
  • Port Security limite le nombre d’adresses MAC par port ; le mode shutdown désactive le port en état err-disable en cas d’infraction.
  • Le mécanisme Sticky MAC enregistre automatiquement l’adresse apprise dans la configuration courante du commutateur.
  • DHCP Snooping sépare les ports de confiance (trusted) des ports utilisateurs (untrusted) pour neutraliser les serveurs pirates.
  • La base de données DHCP Snooping Binding associe l’adresse MAC, l’IP attribuée, le VLAN et le port physique du client.
  • DAI inspecte les paquets ARP entrants sur les ports untrusted et bloque les réponses non validées par la base DHCP Snooping.

Checklist de maîtrise

  • Je comprends comment une attaque par MAC Flooding transforme un commutateur en concentrateur.
  • Je connais la différence entre les trois modes de violation de Port Security (protect, restrict, shutdown).
  • Je sais expliquer le fonctionnement et l’intérêt du mot-clé sticky dans la commande port-security mac-address.
  • Je maîtrise la configuration de DHCP Snooping et la déclaration indispensable des ports de confiance (trusted).
  • Je comprends pourquoi Dynamic ARP Inspection (DAI) dépend directement de la base DHCP Snooping Binding Table.
  • Je sais comment IP Source Guard bloque les tentatives de configuration d’IP statique illégitime sur un port utilisateur.
