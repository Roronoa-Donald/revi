Chapitre 5 — Sécurité de la Couche d’Accès (Port Security, DHCP Snooping & DAI)

Module 5 ≈ 2 h 45 de travail Réservé B3 et plus
Mise en situation

La couche d’accès d’un réseau local d’entreprise est exposée aux menaces internes et aux compromissions physiques. Tout collaborateur, prestataire ou intrus branchant une machine sur une prise murale RJ-45 ou une borne Wi-Fi peut tenter de saturer la table CAM du commutateur (MAC Flooding) pour provoquer la diffusion de certaines trames unicast vers des destinations inconnues et les intercepter dans leur VLAN, déployer un serveur DHCP pirate (Rogue DHCP) pour détourner la passerelle par défaut des utilisateurs, ou émettre des réponses ARP falsifiées (ARP Poisoning) pour réaliser une attaque d’homme du milieu (Man-In-The-Middle - MITM). L’ingénieur réseau et cybersécurité de niveau Bachelor 3 doit maîtriser les outils de durcissement de niveau 2 : configurer Port Security avec apprentissage dynamique Sticky MAC, activer DHCP Snooping avec ségrégation des ports de confiance, et associer l’inspection dynamique ARP (DAI) à IP Source Guard pour réduire les risques d’usurpation selon le contexte et la configuration.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. comprendre les vecteurs d’attaques majeures de niveau 2 (MAC Flooding, Rogue DHCP, ARP Spoofing) ;
  2. configurer et auditer la fonctionnalité Port Security et ses modes de violation (protect, restrict, shutdown) ;
  3. déployer le mécanisme Sticky MAC pour l’apprentissage persistant des adresses d’accès autorisées ;
  4. mettre en œuvre DHCP Snooping avec distinction rigoureuse des ports trusted et untrusted ;
  5. analyser la base de données DHCP Snooping Binding Table et son exploitation par Dynamic ARP Inspection (DAI) ;
  6. analyser et résoudre méthodologiquement des simulateurs de violation de sécurité, des inspecteurs DHCP Snooping et des filtres DAI.

1. Attaques Fondamentales de Niveau 2 : Saturation CAM & Serveurs DHCP Pirates

Historiquement conçu sans préoccupation de sécurité cryptographique, le standard Ethernet considère que tout port physique connecté est légitime. Les attaquants exploitent cette confiance aveugle par deux techniques offensives classiques :

1. Saturation de Table CAM (MAC Address Flooding)

La table de commutation (Content Addressable Memory - CAM) possède une capacité finie, qui dépend du matériel. Un outil offensif (ex: macof) peut injecter de nombreuses trames Ethernet avec des adresses MAC sources forgées :

  • La table CAM peut atteindre sa capacité ; le délai dépend du trafic, du matériel et des protections activées.
  • Si le commutateur ne peut plus apprendre de nouvelles adresses sources, les destinations correspondantes restent inconnues ; des destinations déjà apprises peuvent aussi le devenir lorsque leur entrée expire sans être réapprise.
  • Selon le matériel et sa configuration, les trames unicast vers ces destinations peuvent être diffusées sur les ports autorisés du même VLAN, sauf le port d’entrée. Les destinations encore connues restent généralement commutées vers leur port.
  • Port Security, correctement configuré, peut limiter le nombre d’adresses MAC autorisées par port et bloquer des trames provenant d’adresses non autorisées ou désactiver le port en violation. D’autres contrôles peuvent limiter la diffusion.
  • Si son port est autorisé dans le VLAN et reçoit ces copies, l’attaquant peut capturer certaines trames ; cela ne garantit ni l’accès à tous les flux ni leur lecture en clair. Un chiffrement correctement configuré, par exemple TLS, protège le contenu applicatif d’une simple capture ; certaines métadonnées restent visibles.

2. Serveur DHCP Pirate (Rogue DHCP Server)

Lorsqu’un poste client démarre, il émet une diffusion DHCPDISCOVER. Un attaquant déployant un serveur DHCP pirate répond plus rapidement que le serveur officiel (DHCPOFFER) :

  • Il fournit une adresse IP valide au client.
  • Il positionne sa propre machine comme passerelle par défaut et serveur DNS.
  • Le trafic passant par cette passerelle peut être intercepté ou modifié. Un chiffrement correctement authentifié, tel que TLS, protège le contenu applicatif sans masquer nécessairement toutes les métadonnées.

2. Port Security : Contrôle d’Accès Matériel & Modes de Violation

La fonctionnalité Port Security permet de restreindre le nombre d’adresses MAC autorisées à émettre sur une interface d’accès et d’associer des adresses MAC matérielles spécifiques :

Apprentissage et Types d'Adresses MAC

  • Statique : Configurée manuellement par l’administrateur (switchport port-security mac-address <mac>).
  • Dynamique : Apprise au vol par le commutateur et oubliée au redémarrage.
  • Sticky MAC : Apprise dynamiquement et inscrite dans la configuration courante (running-config). Pour la conserver après redémarrage, sauvegarder cette configuration dans la startup-config, selon la plateforme.

Les Trois Modes de Violation

Rétablissement d'un Port en état err-disable

Lorsqu’un port passe en état err-disable suite à une violation en mode shutdown, diagnostiquer et corriger la cause avant réactivation. Selon la plateforme et sa configuration, l’administrateur peut intervenir manuellement (shutdown puis no shutdown) ou configurer la récupération temporisée, par exemple errdisable recovery cause psecure-violation avec un intervalle adapté.

3. DHCP Snooping & Dynamic ARP Inspection (DAI)

Pour contrer les attaques de type Rogue DHCP et Man-In-The-Middle par usurpation ARP (ARP Poisoning), les commutateurs combinent deux technologies complémentaires de filtrage dynamique :

1. DHCP Snooping

Agit comme un pare-feu applicatif de niveau 2 pour les messages DHCP :

  • Ports de Confiance (Trusted) : Reliés aux serveurs DHCP légitimes et liaisons montantes (uplinks). Les messages serveurs (DHCPOFFER, DHCPACK) y sont autorisés.
  • Ports Non Approuvés (Untrusted) : Reliés aux utilisateurs. Tout message serveur émis depuis ces ports est immédiatement bloqué.
  • DHCP Snooping Binding Table : Construit une table dynamique liant : Adresse MAC, Adresse IP attribuée, Durée du bail, VLAN et Port physique.

2. Dynamic ARP Inspection (DAI) & IP Source Guard

Ces fonctions peuvent utiliser les liaisons DHCP Snooping et, selon leur configuration, des règles statiques :

  • Dynamic ARP Inspection (DAI) : Sur les ports non approuvés, vérifie les messages ARP à partir des liaisons DHCP Snooping ou d’une ACL ARP configurée pour les adresses statiques. Les messages refusés sont éliminés ; cette vérification réduit certains risques d’usurpation sans les supprimer tous.
  • IP Source Guard (IPSG) : Sur une interface où il est activé, filtre les paquets selon les liaisons DHCP ou les liaisons statiques configurées. Une adresse source non autorisée peut être bloquée ; une adresse statique explicitement autorisée reste possible.

Exercice 1 — Contrôleur de Port Security et détection de violation (Protect, Restrict, Shutdown)

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Simuler le mécanisme Cisco Port Security et les modes de réaction face aux adresses MAC non autorisées.

La fonctionnalité Port Security limite les adresses MAC autorisées sur un port à celles qui sont configurées ou apprises, jusqu'au quota max_mac.

Pour une trame non autorisée, ce modèle distingue trois modes :
- protect : la trame est détruite sans alerte ni incrément de compteur ; le port reste UP (action=DROP_SILENT).
- restrict : la trame est détruite, le compteur et l'alerte sont activés ; le port reste UP (action=DROP_ALERT).
- shutdown : le port passe en ERR_DISABLE (action=PORT_SHUTDOWN). Dans ce scénario sans rétablissement, les trames suivantes sont rejetées avec action=DROP state=ERR_DISABLE.

En pratique, après diagnostic et correction de la cause, une réactivation manuelle (shutdown puis no shutdown) ou une récupération automatique configurée peut être possible selon la plateforme.

Chaque cas commence par PORT_SEC port=<port> max_mac=<quota> mode=<protect|restrict|shutdown> sticky_macs=<adresses|NONE>, suivi des trames FRAME id=<nom> src_mac=<mac>.
Pour chaque trame, afficher :
PORT_SEC_REPORT id={id} port={port} mac={src_mac} status={PERMIT|VIOLATION|PORT_DOWN} action={action} state={state}

Cas d’exemple
PORT_SEC port=Fa0/1 max_mac=1 mode=shutdown sticky_macs=00:11:22:33:44:01
FRAME id=F1 src_mac=00:11:22:33:44:01
FRAME id=F2 src_mac=00:aa:bb:cc:dd:02
FRAME id=F3 src_mac=00:11:22:33:44:01
Deux indices, rédigés en mots
  1. Le mécanisme de sécurité Port Security surveille le nombre d’adresses MAC distinctes autorisées sur un port de commutateur.
  2. Si une adresse inconnue dépasse le quota, seul le mode shutdown du scénario place le port en err-disable.

Exercice 2 — Validateur de base de données de liaison DHCP Snooping

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Filtrer les messages DHCP selon le statut de confiance des ports et alimenter la base de liaison (Binding DB).

L'attaque par serveur DHCP pirate (Rogue DHCP Server) permet à un attaquant de distribuer de fausses passerelles et de faux serveurs DNS aux postes du réseau. La parade DHCP Snooping classe les ports du commutateur en deux catégories :
- Ports de confiance (TRUSTED) : Reliés aux serveurs DHCP légitimes ou aux uplinks de distribution. Tous les messages DHCP y sont autorisés.
- Ports non fiables (UNTRUSTED) : Reliés aux utilisateurs finals. Seules les requêtes clients (DISCOVER, REQUEST) y sont autorisées. Si une réponse serveur (OFFER ou ACK) y est détectée, elle est immédiatement détruite et signalée comme attaque Rogue DHCP.

Analysez les paramètres du problème pour chaque cas. Si port.trust == 'UNTRUSTED' et type in ['OFFER', 'ACK'] :
status=SECURITY_VIOLATION action=DROP reason=ROGUE_DHCP_SERVER.
2. Si port.trust == 'UNTRUSTED' et type in ['DISCOVER', 'REQUEST'] :
status=PERMIT action=FORWARD reason=LEGIT_CLIENT_REQUEST.
3. Si port.trust == 'TRUSTED' :
status=PERMIT action=FORWARD reason=TRUSTED_PORT_TRAFFIC.
(Si de plus type == 'ACK' et assigned_ip != '0.0.0.0', la liaison est insérée dans la base de données Snooping).

Pour chaque message, afficher :
DHCP_SNOOP_REPORT id={id} port={port} type={type} status={status} action={action} reason={reason}

Cas d’exemple
PORT_TRUST name=Gi0/1 trust=UNTRUSTED
PORT_TRUST name=Gi0/24 trust=TRUSTED
DHCP_MSG id=M1 port=Gi0/1 type=DISCOVER client_mac=00:11:22:33:44:01 assigned_ip=0.0.0.0 vlan=10
DHCP_MSG id=M2 port=Gi0/1 type=OFFER client_mac=00:11:22:33:44:01 assigned_ip=192.168.10.50 vlan=10
DHCP_MSG id=M3 port=Gi0/24 type=ACK client_mac=00:11:22:33:44:01 assigned_ip=192.168.10.50 vlan=10
Deux indices, rédigés en mots
  1. Mémoriser le statut de chaque port (TRUSTED ou UNTRUSTED).
  2. Identifier les réponses serveur OFFER et ACK arrivant sur port UNTRUSTED.

Exercice 3 — Filtre anti-usurpation Dynamic ARP Inspection (DAI)

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Analyser des trames ARP en les comparant à des liaisons fournies, sans conclure à une attaque sur ce seul indice.

Un empoisonnement de cache ARP peut détourner certaines communications si un attaquant parvient à faire accepter une fausse liaison. Dynamic ARP Inspection (DAI) vérifie les messages ARP sur les ports non fiables selon les liaisons DHCP ou les ACL ARP configurées.

Dans cette grille simplifiée, tous les messages proviennent de ports non fiables et seules les liaisons BINDING fournies sont utilisées ; aucune ACL ARP n'est modélisée. Une différence de liaison ne prouve pas une attaque : elle peut aussi résulter d'une configuration erronée ou périmée. Les actions et alertes ci-dessous sont celles du modèle, pas une garantie sur chaque commutateur.

1. Si (sender_mac, sender_ip, vlan) correspond à une liaison : status=PERMIT action=FORWARD reason=BINDING_MATCH.
2. Si sender_ip est enregistré pour ce VLAN avec une autre MAC : status=DENY action=DROP_ALERT reason=BINDING_MISMATCH.
3. Si sender_ip n'est pas enregistré pour ce VLAN : status=DENY action=DROP reason=UNKNOWN_HOST_BINDING.

Pour chaque message, indiquez : DAI_AUDIT id={id} vlan={vlan} sender_ip={sender_ip} sender_mac={sender_mac} status={status} action={action} reason={reason}.

Cas d’exemple
BINDING mac=00:11:22:33:44:01 ip=192.168.1.10 vlan=10
BINDING mac=00:11:22:33:44:02 ip=192.168.1.20 vlan=10
ARP_FRAME id=ARP1 vlan=10 sender_mac=00:11:22:33:44:01 sender_ip=192.168.1.10 target_ip=192.168.1.1
ARP_FRAME id=ARP2 vlan=10 sender_mac=00:aa:bb:cc:dd:ee sender_ip=192.168.1.10 target_ip=192.168.1.20
ARP_FRAME id=ARP3 vlan=10 sender_mac=00:11:22:33:44:99 sender_ip=192.168.1.99 target_ip=192.168.1.1
Deux indices, rédigés en mots
  1. Normalisez les adresses MAC en minuscules.
  2. Comparez chaque couple (vlan, sender_ip) à la MAC enregistrée dans les liaisons fournies.

5. QCM — niveau examen

Quel est l’objectif d’une attaque par saturation de table CAM (MAC Flooding) menée contre un commutateur ?

La saturation peut empêcher l’apprentissage de nouvelles adresses ; de nouvelles destinations restent alors inconnues, comme celles dont les entrées expirent sans être réapprises. Selon le commutateur et ses protections, leurs trames unicast peuvent être diffusées sur les ports autorisés du même VLAN. Les destinations encore connues restent généralement acheminées vers leur port et un chiffrement adapté protège le contenu d’une simple capture.

Quel mode de violation de Port Security désactive immédiatement le port physique et le place en état « err-disable » ?

Le mode shutdown coupe administrativement le port (err-disable), incrémente le compteur de violation et émet une alerte syslog/SNMP.

Quel est le rôle de l’option « sticky » dans la commande « switchport port-security mac-address sticky » ?

L’apprentissage sticky convertit dynamiquement la première adresse MAC active apprise en entrée statique inscrite dans la configuration courante.

Dans une architecture protégée par DHCP Snooping, sur quel type de port les réponses DHCPOFFER d’un serveur DHCP légitime doivent-elles transiter ?

Seuls les ports marqués comme Trusted sont autorisés à recevoir et relayer des messages DHCP émis par un serveur (DHCPOFFER, DHCPACK).

Quelles informations sont consignées dans la base de données dynamique DHCP Snooping Binding Table ?

La table de liaison associe pour chaque poste : adresse MAC, adresse IP reçue par DHCP, durée du bail, VLAN d’appartenance et numéro de port physique.

Comment la technologie Dynamic ARP Inspection (DAI) contribue-t-elle à réduire les risques d’usurpation ARP ?

DAI vérifie les messages ARP reçus sur les ports untrusted selon les liaisons DHCP et les ACL ARP configurées. Les messages non autorisés sont rejetés, mais cela ne supprime pas tous les risques.

Quelle technologie permet de filtrer l’adresse IP source d’un port selon les liaisons autorisées ?

IP Source Guard filtre les paquets selon les liaisons DHCP ou les liaisons statiques configurées sur le port ; une adresse statique explicitement autorisée peut donc être utilisée.

Que se passe-t-il par défaut sous Cisco IOS lorsqu’un commutateur reçoit un paquet DHCP sur un port untrusted contenant l’option 82 alors qu’il n’est pas configuré comme relais de confiance ?

Par défaut, un commutateur avec DHCP Snooping actif rejette les paquets DHCP contenant l’option 82 (relay agent information) arrivant sur un port untrusted.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de configurer « ip dhcp snooping trust » sur la liaison montante vers le serveur DHCP, bloquant l’attribution de baux pour tous les clients du switch.
  • Activer Dynamic ARP Inspection (DAI) sans prévoir les liaisons DHCP ou les ACL ARP nécessaires : des messages ARP légitimes peuvent être rejetés et perturber certains hôtes.
  • Choisir le mode « protect » au lieu de « shutdown » dans un environnement critique, laissant l’attaquant persister sans aucune alerte générée.
  • Ne pas limiter le taux de requêtes ARP (ip arp inspection limit rate) sur les ports utilisateurs, exposant le CPU du commutateur à un déni de service.

7. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Étape 1 : Activer Port Security sur l’ensemble des ports d’accès utilisateurs en fixant la limite maximale à 1 ou 2 adresses MAC.
  2. Étape 2 : Configurer le mode de violation shutdown et activer l’apprentissage sticky pour pérenniser les affectations physiques.
  3. Étape 3 : Activer globalement la surveillance DHCP Snooping sur le commutateur et pour les VLANs utilisateurs concernés.
  4. Étape 4 : Déclarer explicitement les liaisons montantes (Trunks vers le cœur de réseau) et ports de serveurs en mode trusted (ip dhcp snooping trust).
  5. Étape 5 : Activer l’inspection dynamique ARP (ip arp inspection vlan <id>) sur les VLANs protégés par DHCP Snooping.
  6. Étape 6 : Activer IP Source Guard sur les ports d’accès pour interdire l’usurpation d’adresses IP statiques non autorisées.

8. Révision active

Résumé essentiel
  • Le MAC Flooding tente de saturer la table CAM ; des trames unicast vers des destinations devenues inconnues peuvent être diffusées dans leur VLAN si les protections le permettent. Leur contenu n’est pas forcément lisible lorsqu’il est chiffré.
  • Port Security limite le nombre d’adresses MAC par port ; le mode shutdown désactive le port en état err-disable en cas d’infraction.
  • Le mécanisme Sticky MAC enregistre automatiquement l’adresse apprise dans la configuration courante du commutateur.
  • DHCP Snooping sépare les ports de confiance (trusted) des ports utilisateurs (untrusted) pour neutraliser les serveurs pirates.
  • La base de données DHCP Snooping Binding associe l’adresse MAC, l’IP attribuée, le VLAN et le port physique du client.
  • DAI inspecte les messages ARP entrants sur les ports untrusted et peut utiliser les liaisons DHCP ou une ACL ARP applicable pour les valider.

Checklist de maîtrise

  • Je sais expliquer pourquoi le MAC Flooding peut diffuser certaines trames unicast, mais ne rend pas tout le trafic lisible.
  • Je connais la différence entre les trois modes de violation de Port Security (protect, restrict, shutdown).
  • Je sais expliquer le fonctionnement et l’intérêt du mot-clé sticky dans la commande port-security mac-address.
  • Je maîtrise la configuration de DHCP Snooping et la déclaration indispensable des ports de confiance (trusted).
  • Je comprends comment Dynamic ARP Inspection (DAI) utilise les liaisons DHCP et, pour des hôtes statiques, une ACL ARP adaptée.
  • Je sais comment IP Source Guard filtre les adresses sources selon les liaisons DHCP ou statiques autorisées.
