Chapitre 1 — Architecture Système, Services d’Infrastructure Réseau & Modèle de Licence par Cœur

Module 1 ≈ 2 h 45 de travail Accès libre
Mise en situation

Dans une infrastructure informatique d’entreprise moderne, les serveurs Windows constituent le socle régalien sur lequel reposent l’authentification centralisée, l’adressage IP dynamique et la résolution de noms. Un déploiement anarchique ou mal calibré engendre des pannes en cascade : conflits d’adresses IP paralysant les postes clients, zones DNS désynchronisées empêchant la découverte des contrôleurs de domaine, ou non-conformité contractuelle majeure lors d’un audit de licences Microsoft. Pour un ingénieur système de niveau Bachelor 3, l’administration d’infrastructure commence par la compréhension rigoureuse du noyau Windows (Kernel NT, HAL, séparation stricte des espaces mémoires), le choix raisonné entre l’édition Server Core (sécurisée et allégée) et l’interface graphique, la conception étanche des services DHCP et DNS, et la maîtrise du modèle mathématique de licences par cœur physique.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. maîtriser l’architecture interne du système d’exploitation Windows Server (Kernel NT, HAL, pilotes d’anneau 0 vs sous-systèmes Win32 d’anneau 3) ;
  2. comparer les éditions Windows Server (Standard, Datacenter, Essentials) et justifier le déploiement en Server Core en environnement de production ;
  3. concevoir, dimensionner et sécuriser une étendue DHCP (Scope) avec plages d’exclusion et réservations MAC statiques sans conflit d’adressage ;
  4. administrer une zone DNS d’infrastructure avec synchronisation stricte des enregistrements directs (A/AAAA), inverses (PTR) et de service (SRV) ;
  5. appliquer les règles officielles Microsoft de licences par cœur physique (min 8 par socket, min 16 par hôte, packs de 2 cœurs) et arbitrer le coût de virtualisation ;
  6. implémenter en Python 3 des validateurs d’étendues DHCP, des auditeurs de zones DNS et des calculateurs de licences serveur.

1. Architecture Interne du Système d’Exploitation Windows Server

L’architecture de Windows Server repose sur une séparation matérielle et logicielle stricte héritée de la lignée Windows NT, garantissant la stabilité et la protection mémoire de l’infrastructure :

Les Deux Anneaux d’Exécution Privilégiée

  • Mode Noyau (Ring 0 / Kernel Mode) : accès direct au processeur et aux ressources physiques. Comprend la couche d’abstraction matérielle (HAL - Hardware Abstraction Layer), le micro-noyau NT (Executive Kernel), le gestionnaire de mémoire virtuelle (VMM), le gestionnaire d’I/O et les pilotes de périphériques noyau (.sys). Un crash en Ring 0 déclenche un arrêt d’urgence système (BugCheck / BSoD).
  • Mode Utilisateur (Ring 3 / User Mode) : espace mémoire isolé et protégé. Héberge les sous-systèmes d’environnement (Win32 / Windows Subsystem), les applications d’entreprise et les processus système critiques (lsass.exe pour la sécurité, services.exe pour le gestionnaire de services, smss.exe). Une défaillance en Ring 3 n’entraîne pas le crash du serveur.

2. Services Réseau Fondamentaux : DHCP & Résolution DNS d’Infrastructure

Tout contrôleur de domaine et toute station de travail dépendent d’une configuration IP sans faille et d’une résolution de noms déterministe fournie par les rôles DHCP et DNS :

Architecture et Rôle du Serveur DHCP

Le protocole DHCP (Dynamic Host Configuration Protocol) automatise l’attribution des baux IP à travers la transaction DORA (Discover, Offer, Request, Acknowledge) :

  • Étendue (Scope) : plage consécutive d’adresses IPv4 distribuables sur un sous-réseau avec masque, passerelle par défaut (Option 003) et serveurs DNS (Option 006).
  • Plages d’exclusion : sous-ensembles d’adresses réservés aux équipements statiques (serveurs, imprimantes, passerelles) qui ne doivent jamais être alloués dynamiquement.
  • Réservations statiques : baux permanents assignés à une adresse MAC spécifique pour garantir l’attribution immuable de la même IP.
  • DHCP Failover : haute disponibilité entre deux serveurs DHCP en mode Load Balancing (50/50 ou 80/20) ou Hot Standby.

Zones DNS & Enregistrements SRV Active Directory

Le DNS Windows Server est intégré à Active Directory (Active Directory-Integrated Zones) et stocke ses données dans la partition d’annuaire :

  • Zone Directe (Forward Lookup) : résout un FQDN en adresse IP (enregistrements A en IPv4 et AAAA en IPv6).
  • Zone Inverse (Reverse Lookup) : résout une IP en FQDN (enregistrements PTR dans le domaine in-addr.arpa). La réciprocité A/PTR est indispensable pour Kerberos et la conformité des audits.
  • Enregistrements de service SRV : permettent aux clients du domaine de localiser les contrôleurs de domaine (DC). Exemple : _ldap._tcp.dc._msdcs.domaine.lan (port 389) et _kerberos._tcp.dc._msdcs.domaine.lan (port 88).

3. Modèle Officiel Microsoft de Licences par Cœur Physique

Depuis Windows Server 2016, Microsoft applique un modèle de licence basé sur le nombre de cœurs physiques des processeurs hôtes, avec des règles d’évaluation minimales strictes :

Règles de Calcul par Cœur Physique

  • Règle du Socket : Chaque processeur physique (socket) doit être licencié pour un minimum de 8 cœurs. Si un socket n’a que 4 ou 6 cœurs, compter obligatoirement 8.
  • Règle du Serveur : Chaque serveur physique complet doit être licencié pour un minimum de 16 cœurs au total.
  • Conditionnement commercial : Les licences sont commercialisées sous forme de packs de 2 cœurs : $\text{Packs de base} = \lceil \text{Total cœurs} / 2 \rceil$.

Droits de Virtualisation : Standard vs Datacenter

  • Édition Standard : Une licence couvrant l’ensemble des cœurs physiques de l’hôte accorde le droit d’exécuter 2 machines virtuelles (OSEs) Windows Server. Pour chaque palier de 2 VMs supplémentaires, l’intégralité des cœurs physiques de l’hôte doit être relicenciée.
  • Édition Datacenter : Une licence couvrant tous les cœurs physiques accorde le droit d’exécuter un nombre illimité de machines virtuelles sur cet hôte physique.
  • Seuil d’arbitrage : En pratique, lorsque la densité de virtualisation dépasse 10 à 12 VMs par hôte, l’édition Datacenter devient financièrement plus avantageuse que le cumul de licences Standard.

Exercice 1 — Validateur d’étendue DHCP, exclusions et conflits de réservation MAC

Python Niveau 1 — Acquisition

Objectif : Calculer la liste des adresses IP distribuables d’une étendue DHCP après déduction des exclusions et détecter les conflits de réservation.

Dans l’administration d’un serveur DHCP Windows Server, une étendue (Scope) distribue dynamiquement des adresses IP IPv4 : - `SCOPE net= start= end=` : définit la plage complète d’adresses `PREFIX.N` (ex: net=192.168.1. start=10 end=30). - `EXCLUDE start= end=` : plage d’hôtes exclus de la distribution dynamique (inclusifs). - `RESERVATION mac= ip=` : association statique MAC / IP. Règles de validation : - Une réservation est en conflit (`CONFLIT`) si l’IP est hors de la plage `[start, end]`, ou si deux réservations ont la même IP avec des MAC différentes, ou si la même MAC a plusieurs IP différentes. Sinon elle est `VALIDE`. - Une adresse IP est distribuable dynamiquement si son numéro d’hôte est dans `[start, end]`, n’est couvert par aucune plage d’exclusion `EXCLUDE`, et n’est assigné à aucune réservation valide. Entrée : `SCOPE net= start= end=` `EXCLUDE start= end=` (0 ou plusieurs) `RESERVATION mac= ip=` (0 ou plusieurs) Sortie : - Ligne de statut des réservations : `RESERVATIONS valides= conflits=` - Ligne du pool d’adresses dynamiques : `POOL_DYNAMIC total_disponibles= first_ip= last_ip=` (si total > 0, sinon `POOL_DYNAMIC total_disponibles=0 first_ip=NONE last_ip=NONE`) - Bilan : `SUMMARY statut= pool_pct=%` (où pool_pct = round((total_disponibles / total_scope) * 100, 1) ; statut=OK si conflits=0, sinon AVERTISSEMENT)
Entrée du programme
SCOPE net=192.168.1. start=10 end=20
EXCLUDE start=12 end=14
RESERVATION mac=00:11:22:33:44:01 ip=192.168.1.15
RESERVATION mac=00:11:22:33:44:02 ip=192.168.1.18
Sortie attendue
RESERVATIONS valides=2 conflits=0
POOL_DYNAMIC total_disponibles=6 first_ip=192.168.1.10 last_ip=192.168.1.20
SUMMARY statut=OK pool_pct=54.5%

Étendue de 11 adresses (10 à 20). 3 exclues (12, 13, 14), 2 réservées (15, 18). Reste : 10, 11, 16, 17, 19, 20 (6 adresses, 6/11 = 54.5%).

Deux indices, rédigés en mots
  1. Stocker les entiers d’hôtes exclus dans un ensemble (set).
  2. Vérifier les doublons de MAC et d’IP pour les réservations avec des dictionnaires.
  3. Calculer les adresses disponibles en soustrayant exclusions et réservations valides.

Exercice 2 — Validateur de cohérence de zone DNS d’infrastructure (A, PTR, SRV)

Python Niveau 2 — Application

Objectif : Vérifier la réciprocité des enregistrements A et PTR et la présence des enregistrements de service SRV indispensables à Active Directory.

Dans une infrastructure Windows Server avec Active Directory, le DNS assure la résolution de noms et la découverte des contrôleurs de domaine (DC) : - `RECORD_A fqdn= ip=` : résolution directe. - `RECORD_PTR ip= fqdn=` : résolution inverse (Reverse Lookup). - `RECORD_SRV service= proto= port= target=` : localisation de services AD (ex: _ldap, _kerberos). Règles d’audit de zone : 1. Réciprocité A / PTR : chaque `RECORD_A` doit avoir son `RECORD_PTR` exact (même IP et même FQDN). Si le PTR manque ou pointe vers un autre nom, émettre `ANOMALIE_PTR fqdn= ip=`. 2. Résolution de cible SRV : la cible `target` d’un `RECORD_SRV` doit impérativement posséder un enregistrement direct `RECORD_A`. Si absent, émettre `ANOMALIE_SRV target= service=`. Sortie : - Anomalies triées par FQDN / target alphabétique croissant : `ANOMALIE_PTR fqdn= ip=` ou `ANOMALIE_SRV target= service=` - Bilan : `SUMMARY total_records= anomalies= statut=`
Entrée du programme
RECORD_A fqdn=dc01.corp.lan ip=192.168.1.10
RECORD_PTR ip=192.168.1.10 fqdn=dc01.corp.lan
RECORD_SRV service=_ldap proto=_tcp port=389 target=dc01.corp.lan
Sortie attendue
SUMMARY total_records=3 anomalies=0 statut=CONFORME

Enregistrement direct et inverse synchronisés, cible SRV résolue.

Deux indices, rédigés en mots
  1. Indexer les enregistrements A sous forme {fqdn: ip} et l’inverse {ip: fqdn}.
  2. Comparer les enregistrements PTR à l’index des A.
  3. Vérifier que chaque target de SRV existe dans les clés de l’index A.

Exercice 3 — Simulateur de dimensionnement de licences Windows Server (Cœurs physiques vs VMs)

Python Niveau 3 — Raisonnement

Objectif : Calculer le nombre de packs de licences cœurs requis et déterminer l’édition financièrement optimale (Standard vs Datacenter).

Les règles officielles de licences par cœur Microsoft Windows Server imposent : - Règle 1 : minimum 8 cœurs physiques par socket CPU (si < 8, compter 8). - Règle 2 : minimum 16 cœurs physiques par serveur physique au total. - Licences vendues par packs de 2 cœurs : `packs_base = ceil(total_coeurs / 2)`. Règles de virtualisation Windows Server : - `Édition Standard` (120 € / pack 2 cœurs) : chaque licence complète de l’hôte accorde 2 VMs. Pour $V$ machines virtuelles, multiplier les packs de base par `max(1, ceil(V / 2))`. - `Édition Datacenter` (750 € / pack 2 cœurs) : une seule licence complète de l’hôte accorde un nombre illimité de VMs (`packs_base` invariants). Entrée : `SERVER nom= sockets= cores_per_socket= vms=` Sortie : - Profil hôte : `SERVER_PROFILE nom= base_cores= packs_base=` - Coûts par édition : `EDITION_STANDARD packs= cout=EUR` `EDITION_DATACENTER packs= cout=EUR` - Recommandation finale (Standard si cout_std <= cout_dc, sinon Datacenter) : `RECOMMENDATION nom= edition_recommandee= economie=EUR`
Entrée du programme
SERVER nom=HOTE-PROD-01 sockets=2 cores_per_socket=8 vms=4
Sortie attendue
SERVER_PROFILE nom=HOTE-PROD-01 base_cores=16 packs_base=8
EDITION_STANDARD packs=16 cout=1920EUR
EDITION_DATACENTER packs=8 cout=6000EUR
RECOMMENDATION nom=HOTE-PROD-01 edition_recommandee=STANDARD economie=4080EUR

16 cœurs = 8 packs. 4 VMs = 2 passages de licence Standard (16 packs = 1920€). Datacenter = 8 packs (6000€). Standard est plus économique de 4080€.

Deux indices, rédigés en mots
  1. Appliquer max(8, cores) par socket, puis max(16, total).
  2. Calculer les packs Standard en multipliant packs_base par math.ceil(vms / 2) si vms > 0.
  3. Comparer les coûts totaux (120€ vs 750€ par pack).

5. QCM — niveau examen

Dans quelle couche d’exécution le micro-noyau NT et les pilotes matériels opèrent-ils ?

Le noyau NT, la HAL et les pilotes .sys s’exécutent en mode noyau (Ring 0) avec accès matériel direct et mémoire protégée.

Quel est l’avantage premier du déploiement en Server Core pour un contrôleur de domaine ?

L’absence de sous-système graphique réduit massivement le code exécuté, diminuant les failles exploitables et les besoins en redémarrages de patchs.

Selon les règles officielles Microsoft, quel est le minimum de cœurs à licencier par serveur physique ?

Chaque serveur physique doit être licencié pour un minimum absolu de 16 cœurs, même s’il n’en contient que 4 ou 8.

Combien de machines virtuelles Windows Server une licence complète Standard permet-elle d’exécuter ?

L’édition Standard octroie le droit d’exécuter 2 VMs Windows Server par couverture complète des cœurs physiques de l’hôte.

À quoi sert une plage d’exclusion dans une étendue DHCP ?

L’exclusion protège les adresses IP assignées en fixe aux serveurs et routeurs pour que le DHCP ne les distribue jamais à des postes clients.

Quel type d’enregistrement DNS permet aux clients Active Directory de localiser les contrôleurs de domaine ?

Les enregistrements SRV (Service Records) indiquent le protocole, le port et le FQDN des services vitaux comme LDAP (389) et Kerberos (88).

Quel est le résultat d’une requête DNS inverse (Reverse Lookup) ?

La résolution inverse interroge la zone in-addr.arpa pour convertir une adresse IP en nom FQDN grâce à l’enregistrement PTR.

Que se passe-t-il lorsqu’un serveur physique doté de 2 CPU à 4 cœurs chacun est licencié ?

Chaque processeur physique requiert un plancher de 8 cœurs : 2 sockets x 8 cœurs = 16 cœurs de base (soit 8 packs de 2 cœurs).

7. Méthodologie de résolution

Démarche d’ingénierie pas à pas
  1. Identifier précisément les besoins du serveur pour opter dès l’installation pour Server Core sauf impératif d’interface graphique avéré.
  2. Configurer systématiquement une adresse IP statique et documentée avant toute installation de rôle d’infrastructure réseau (AD DS, DHCP, DNS).
  3. Définir une plage d’exclusion DHCP pour tous les serveurs et équipements de routage avant d’activer une nouvelle étendue dynamique.
  4. Vérifier la création automatique des enregistrements PTR correspondants lors de l’ajout d’enregistrements directs A dans la zone DNS.
  5. Contrôler la présence et la résolubilité des enregistrements SRV (_ldap, _kerberos) sur tous les contrôleurs de domaine promus.
  6. Appliquer les règles de licence Microsoft (min 8 cœurs/socket, min 16 cœurs/serveur) pour calculer le nombre exact de packs de 2 cœurs requis.

8. Révision active

Résumé essentiel
  • L’architecture Windows Server isole strictement l’espace noyau Ring 0 (HAL, Executive, pilotes) de l’espace utilisateur Ring 3 pour prévenir les pannes matérielles globales.
  • Server Core offre une surface d’attaque réduite, une consommation mémoire minime et une diminution drastique des redémarrages de maintenance en production.
  • Le rôle DHCP alloue les baux dynamiques mais exige des plages d’exclusion étanches et des réservations MAC vérifiées pour bannir les conflits IP.
  • Le DNS Windows Server stocke les zones intégrées à Active Directory et gère la réciprocité A/PTR ainsi que les enregistrements de découverte de service SRV.
  • Le modèle de licences Microsoft par cœur impose 8 cœurs minimum par socket processeur et 16 cœurs minimum par serveur physique.
  • L’édition Standard couvre 2 VMs par licence complète d’hôte, tandis que l’édition Datacenter offre des droits de virtualisation illimités.

Checklist de maîtrise

  • L’hôte physique dispose-t-il d’une configuration réseau statique validée via ipconfig et test de ping local ?
  • L’étendue DHCP dispose-t-elle de plages d’exclusion excluant les adresses de passerelle et de serveurs critiques ?
  • Chaque enregistrement direct A possède-t-il un enregistrement inverse PTR synchronisé dans la zone Reverse Lookup ?
  • Les enregistrements SRV essentiels (_ldap, _kerberos) pointent-ils vers un contrôleur de domaine pleinement opérationnel ?
  • Le calcul de licence par cœur intègre-t-il bien les planchers de 8 cœurs par socket et 16 cœurs par serveur ?
  • Le choix entre Standard et Datacenter a-t-il été validé en comparant le coût total selon le nombre de VMs hébergées ?

Les 8 notions à connaître absolument

  1. : Option d’installation minimale de Windows Server sans interface graphique ni explorateur, administrée exclusivement en ligne de commande ou à distance.
  2. : Composant logiciel noyau de bas niveau masquant les spécificités des cartes mères et processeurs pour fournir une interface standardisée au système.
  3. : Ensemble configuré d’adresses IP consécutives attribuables dynamiquement aux clients d’un même réseau local avec options de configuration.
  4. : Association statique et permanente entre une adresse physique MAC et une adresse IP au sein d’une étendue dynamique.
  5. : Enregistrement DNS spécifiant l’emplacement (hôte et port de communication) d’un service réseau, indispensable à Active Directory.
  6. : Zone DNS spécialisée dans la résolution d’adresses IP en noms d’hôtes FQDN via des enregistrements de type PTR.
  7. : Unité commerciale standard de vente des licences Microsoft Windows Server calculée à partir du nombre total de cœurs physiques du serveur.
  8. : Édition haut de gamme de Windows Server accordant des droits de virtualisation illimités sur l’hôte physique licencié.
