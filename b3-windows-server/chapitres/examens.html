Examens Blancs & Épreuves Corrigées — Windows Server B3

Deux épreuves d’évaluation complètes conformes aux exigences académiques et professionnelles de niveau Bachelor 3 en ingénierie des systèmes Windows, gouvernance d’annuaire Active Directory, stratégies de groupe, virtualisation Hyper-V et haute disponibilité.

Épreuve 1 : Contrôle Continu (CC) — Durée 1 h 30 (Barème sur 20 points)

Sujet du Contrôle Continu — Architecture Système, Active Directory DS & GPO

Partie 1 : Architecture Système, Services Réseau DHCP/DNS & Licences (6 points)

  1. Détaillez la différence architecturale fondamentale entre l’installation Server Core et l’installation avec Expérience Utilisateur (Desktop Experience). Quels sont les trois avantages opérationnels majeurs de Server Core en environnement de production ? (3 pts)
  2. Un serveur physique dispose de 2 processeurs de 6 cœurs chacun et doit héberger 8 machines virtuelles Windows Server. Calculez le nombre de cœurs à licencier selon les règles Microsoft et comparez le coût entre les éditions Standard (120 € / pack 2 cœurs) et Datacenter (750 € / pack 2 cœurs). Quelle édition recommandez-vous ? (3 pts)

Partie 2 : Active Directory DS, Rôles FSMO & Modèle AGDLP (7 points)

  1. Citez les 5 rôles FSMO (Flexible Single Master Operations). Précisez pour chacun son niveau d’action (Forêt ou Domaine) et la conséquence immédiate sur le système d’information si le contrôleur détenteur du rôle subit une panne prolongée. (4 pts)
  2. Expliquez en détail le modèle AGDLP recommandé par Microsoft pour la gestion des droits d’accès. Pourquoi est-il formellement proscrit d’ajouter directement un compte utilisateur dans un groupe Local de Domaine (DL) ou sur une liste de contrôle d’accès (ACL) ? (3 pts)

Partie 3 : Stratégies de Groupe (GPO) & Résolution de Conflits (7 points)

  1. Décrivez le cycle de traitement et l’ordre d’application strict des stratégies de groupe (modèle LSDOU). Quelle stratégie gagne en cas de conflit sur un même paramètre entre le niveau Domaine et le niveau Unité Organisationnelle (OU) ? (3 pts)
  2. Une OU active l’option « Bloquer l’héritage » (Block Inheritance). Une GPO de niveau Domaine liée avec l’option « Appliquée » (Enforced) est-elle bloquée par cette OU ? Justifiez en explicitant la règle de primauté absolue de Microsoft. (4 pts)

Corrigé Partie 1 (6 points)

  • Server Core vs Desktop Experience (3 pts) : Server Core installe uniquement le noyau, les sous-systèmes d’exécution et les services en ligne de commande (PowerShell / cmd) sans interface graphique (GUI) ni explorateur de fichiers. Les 3 avantages majeurs sont : 1. Surface d’attaque considérablement réduite (moins de code et de binaires exposés, réduction drastique des vulnérabilités) ; 2. Consommation de ressources minime (empreinte RAM et CPU réduite, permettant de densifier les machines virtuelles) ; 3. Maintenance allégée (beaucoup moins de correctifs de sécurité mensuels et de redémarrages serveur requis).
  • Calcul de licences (3 pts) : Règle socket : min 8 cœurs par socket (2 sockets de 6 cœurs -> comptés comme $2 \times 8 = 16$ cœurs de base). Règle serveur : min 16 cœurs physiques (respecté). Packs de base = $16 / 2 = 8$ packs de 2 cœurs. Pour 8 VMs en édition Standard : facteur de couverture $= \lceil 8 / 2 \rceil = 4$. Total packs Standard $= 8 \times 4 = 32$ packs. Coût $= 32 \times 120 = 3\,840$ €. En édition Datacenter : 1 seule couverture $= 8$ packs. Coût $= 8 \times 750 = 6\,000$ €. Recommandation : Édition Standard recommandée (économie de $2\,160$ €). À partir de 12 VMs, Datacenter devient plus rentable.

Corrigé Partie 2 (7 points)

  • Les 5 rôles FSMO (4 pts) : 1. Schema Master (Forêt) : gère la structure de l’annuaire. Panne : blocage des extensions de schéma (ex. Exchange, mises à jour majeures), impact nul sur les opérations courantes. 2. Domain Naming Master (Forêt) : ajout/suppression de domaines. Panne : impossibilité de modifier l’arborescence des domaines. 3. PDC Emulator (Domaine) : référence de temps NTP, verrouillage de comptes, compatibilité NTLM. Panne critique : désynchronisation horaire de Kerberos, retards de verrouillage de mots de passe erronés. 4. RID Master (Domaine) : alloue des blocs de RID aux contrôleurs. Panne : si le pool local d’un DC s’épuise, impossibilité de créer de nouveaux comptes utilisateurs/ordinateurs. 5. Infrastructure Master (Domaine) : met à jour les références inter-domaines. Panne : impact sur les traductions de noms d’objets dans les forêts multi-domaines.
  • Modèle AGDLP (3 pts) : Accounts -> Global Groups -> Domain Local Groups -> Permissions. Interdiction de rattacher un compte directement à un groupe DL ou une ACL : cela provoque une rupture de traçabilité, rend l’audit des privilèges impossible, démultiplie la taille des jetons d’accès et empêche la réutilisation modulaire des rôles lors de migrations ou d’évolutions organisationnelles.

Corrigé Partie 3 (7 points)

  • Ordre LSDOU (3 pts) : Les GPOs sont traitées dans l’ordre : 1. Local, 2. Site, 3. Domaine, 4. Unité Organisationnelle (OU). En cas de conflit sur un paramètre identique sans option spéciale, c’est la règle de la dernière stratégie appliquée qui prévaut (« Last Writer Wins ») : la GPO de niveau OU écrase la valeur définie au niveau Domaine.
  • Enforced vs Block Inheritance (4 pts) : Non, la GPO Enforced n’est pas bloquée. Dans l’architecture de sécurité Active Directory, l’option Enforced (anciennement « No Override ») dispose d’une priorité hiérarchique absolue : elle traverse obligatoirement tous les blocages d’héritage configurés sur les OUs enfants, et ses paramètres ne peuvent être écrasés par aucune stratégie descendante. Cette règle garantit que les politiques de sécurité régaliennes de l’entreprise (ex. complexité de mot de passe, chiffrement BitLocker) s’appliquent à l’ensemble du parc sans exception.

Épreuve 2 : Examen Terminal (ET) — Durée 2 h 00 (Barème sur 20 points)

Sujet de l’Examen Terminal — Permissions Réseau, Virtualisation Hyper-V & Quorum

Dossier 1 : Sécurité des Services de Fichiers, Partage SMB & NTFS (6 points)

  1. Un dossier réseau \\SRV01\Comptabilite est partagé avec l’autorisation SMB « Change » pour le groupe Tout le monde. Sur le système de fichiers local NTFS, le sous-dossier Factures accorde « Full Control » au groupe DL_Factures_Modif et « Read » au groupe DL_Factures_Lecture. Déterminez les droits d’accès réseau effectifs pour un utilisateur membre de ces deux groupes accédant au partage à distance. Expliquez la règle du plus restrictif. (3 pts)
  2. Sur un fichier confidentiel, l’utilisateur Bob hérite de la permission « Modify » via son groupe métier, mais possède une entrée directe « Explicit Deny » sur la permission « Write ». Bob peut-il enregistrer des modifications dans ce fichier ? Détaillez la hiérarchie des ACEs NTFS (Explicit Deny, Explicit Allow, Inherited Deny, Inherited Allow). (3 pts)

Dossier 2 : Virtualisation d’Entreprise Hyper-V & Commutateurs Virtuels (7 points)

  1. Comparez les trois types de commutateurs virtuels Hyper-V : External vSwitch, Internal vSwitch et Private vSwitch. Pour une architecture DMZ isolée hébergeant des serveurs web frontaux et une base de données interne, quelle topologie de vSwitchs recommandez-vous ? (3 pts)
  2. Expliquez le fonctionnement de la mémoire dynamique (Dynamic Memory) sous Hyper-V. Comment l’hyperviseur gère-t-il la mémoire tampon (Memory Buffer) et quelles sont les conséquences si la demande globale dépasse la mémoire physique de l’hôte hôte ? (4 pts)

Dossier 3 : Automatisation PowerShell, Sauvegardes VSS & Quorum de Cluster (7 points)

  1. Un cluster de basculement Windows Server (WSFC) est constitué de 4 nœuds physiques et d’un témoin Cloud (Cloud Witness). Combien de voix au total composent le quorum ? Combien de nœuds peuvent tomber en panne simultanément sans provoquer l’arrêt du cluster ? Expliquez le phénomène de Split-Brain que le quorum permet d’éviter. (4 pts)
  2. Décrivez le fonctionnement des clichés instantanés VSS (Volume Shadow Copy Service) lors d’une sauvegarde de serveur en production. Pourquoi cette technologie permet-elle de sauvegarder des bases de données Active Directory ou SQL Server actives sans interrompre les services utilisateurs ? (3 pts)

Corrigé type & Barème détaillé de l’Examen Terminal

Corrigé Dossier 1 (6 points)

  • Permissions effectives SMB vs NTFS (3 pts) : La permission réseau effective est l’intersection la plus restrictive entre les autorisations de partage SMB et les permissions NTFS. Au niveau du partage SMB : autorisation Change (qui inclut Read, Write, Delete mais exclut le changement d’ACLs et la prise de possession). Au niveau NTFS : l’utilisateur cumule Full Control et Read, ce qui donne Full Control en local. Résultat effectif à travers le réseau : Modify / Change. L’utilisateur peut lire, créer, modifier et supprimer des fichiers, mais ne peut pas modifier les permissions NTFS du dossier car le partage SMB (Change) bloque les droits d’administration Full Control.
  • Hiérarchie des ACEs NTFS (3 pts) : Non, Bob ne peut pas modifier le fichier. L’ordre d’évaluation strict des ACEs dans la DACL NTFS est : 1. Explicit Deny (priorité 1 absolue) ; 2. Explicit Allow ; 3. Inherited Deny ; 4. Inherited Allow. L’Explicit Deny sur Write posé directement sur le fichier prend le pas sur n’importe quelle permission Allow héritée du groupe.

Corrigé Dossier 2 (7 points)

  • Commutateurs Hyper-V (3 pts) : External : lié à une carte physique, permet la communication entre VMs, avec l’hôte (optionnel) et le réseau physique extérieur. Internal : permet la communication entre les VMs et l’hôte uniquement (aucun accès réseau physique). Private : strictement réservé à la communication inter-VMs sur le même hôte (aucun accès hôte ni extérieur). Topologie DMZ recommandée : les serveurs web frontaux sont rattachés à un External vSwitch (avec carte réseau physique dédiée à la DMZ, allow_host=FALSE), tandis que le lien entre le frontal web et la base de données interne transite par un vSwitch Private ou un réseau interne filtré par un pare-feu virtuel.
  • Mémoire dynamique Hyper-V (4 pts) : Chaque VM démarre avec sa RAM de démarrage (Startup RAM), puis le pilote VMBus (Dynamic Memory Service) mesure la pression mémoire de l’OS invité. La formule cible est : $\text{Target} = \text{Demand} \times (1 + \text{Buffer}\%)$. L’hyperviseur ajuste la RAM allouée entre Minimum RAM et Maximum RAM. En cas de surallocation (RAM physique hôte saturée), Hyper-V priorise les VMs selon leur poids (Memory Weight). Si la saturation persiste, les VMs utilisent le Smart Paging sur disque pour démarrer, ce qui entraîne une dégradation temporaire des performances I/O.

Corrigé Dossier 3 (7 points)

  • Quorum de cluster WSFC (4 pts) : Total des voix = 4 nœuds + 1 témoin Cloud = 5 voix. Majorité absolue requise = $\lfloor 5 / 2 \rfloor + 1 = \mathbf{3}$ voix actives. Tolérance de panne : le cluster tolère la perte de 2 voix (ex. 2 nœuds physiques, ou 1 nœud et le témoin Cloud). Le phénomène de Split-Brain survient lorsqu’une coupure réseau scinde le cluster en deux sous-groupes isolés : si chaque sous-groupe continuait d’écrire simultanément sur le stockage partagé, cela provoquerait une corruption irréversible des données. Le mécanisme de quorum garantit que seul le sous-groupe possédant la majorité stricte des voix reste actif, tandis que l’autre s’arrête immédiatement.
  • Technologie VSS (Volume Shadow Copy Service) (3 pts) : VSS coordonne trois composants : le VSS Requestor (logiciel de sauvegarde wbadmin), le VSS Writer (composant applicatif AD DS ou SQL Server) et le VSS Provider (moteur de stockage NTFS). Lors de la sauvegarde, le Writer suspend brièvement les écritures en mémoire (freeze de quelques millisecondes), le Provider fige un cliché instantané différentiel (Copy-on-Write), puis les écritures applicatives reprennent immédiatement. La sauvegarde s’effectue sur le cliché statique sans verrouiller les bases de données en production.
