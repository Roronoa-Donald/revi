Chapitre 3 — Commutation Ethernet L2, Tables CAM & Spanning Tree (STP)

Module 3 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Lors d’une extension de câblage dans un campus universitaire, deux techniciens relient deux commutateurs par un second câble pour faire du secours. En quelques secondes, l’ensemble du réseau s’effondre : tous les voyants clignotent frénétiquement, les processeurs des switches montent à 100% et aucune machine ne parvient plus à communiquer. Une tempête de diffusion (broadcast storm) a paralysé l’infrastructure. L’équipe réseau doit analyser le fonctionnement de la table CAM, comprendre pourquoi les trames tournent en boucle indéfiniment sans TTL au niveau 2, et maîtriser le fonctionnement du protocole Spanning Tree (STP) pour calculer l’élection du Root Bridge et l’attribution des rôles de ports (RP, DP, BLK). Ce troisième module décortique le cœur de la commutation locale Ethernet.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. comprendre le fonctionnement d’un commutateur de niveau 2 (Switch L2) et le rôle de la table CAM (MAC Address Table) ;
  2. analyser le processus d’apprentissage dynamique (Learning), de vieillissement (Aging) et de transmission (Forwarding/Flooding) ;
  3. distinguer les domaines de collision (par port de switch) des domaines de diffusion (par VLAN) ;
  4. identifier les dangers mortels des boucles de niveau 2 : tempête de diffusion, instabilité de table CAM et copies multiples de trames ;
  5. décortiquer le protocole Spanning Tree (STP 802.1D / 802.1w RSTP) : élection du Root Bridge par Bridge ID (Priorité + MAC) ;
  6. calculer les coûts de chemin et déterminer les rôles de ports (Root Port, Designated Port, Blocking Port).

1. Fonctionnement d’un Switch L2 & Table CAM

Contrairement à un concentrateur (Hub) qui répète bêtement chaque signal électrique sur tous ses ports, un commutateur Ethernet (Switch L2) est un équipement intelligent qui opère au niveau de la couche 2 (Liaison de données). Il maintient en mémoire une table de correspondance appelée Table CAM (Content Addressable Memory) ou MAC Address Table associant chaque adresse MAC apprise au numéro de port physique sur lequel elle est connectée.

1. Apprentissage Dynamique (Learning)

Chaque fois qu’une trame entre par un port, le commutateur examine son adresse MAC source :

  • Si la MAC source est inconnue, il crée une entrée MAC_SRC -> Port avec un compteur d’inactivité (Aging timer, défaut 300 s).
  • Si la MAC est déjà présente sur un autre port (déplacement d’hôte), il met à jour le port immédiatement.

2. Décision de Transmission (Forwarding)

Le commutateur examine ensuite l’adresse MAC destination de la trame :

  • Unicast connue : Commutation directe vers le port de sortie enregistré (Forwarding).
  • Unicast inconnue : Inondation sur tous les autres ports actifs (Unknown Unicast Flooding).
  • Broadcast / Multicast : Inondation sur l’ensemble des ports sauf le port d’arrivée (Flooding).

2. Domaines de Collision vs Domaines de Diffusion

Une distinction fondamentale du programme CCNA concerne la segmentation des domaines :

ConceptDéfinitionÉquipement de Segmentation
Domaine de Collision Zone du réseau où deux équipements émettant simultanément provoquent une collision de signaux. En Full Duplex moderne sur switch, chaque port constitue son propre domaine de collision isolé (zéro collision). Commutateur (Switch) : chaque port est un domaine de collision distinct.
Domaine de Diffusion (Broadcast Domain) Zone du réseau où une trame de diffusion (MAC FF:FF:FF:FF:FF:FF) émise par une machine est reçue par toutes les autres. Routeur (L3) ou VLAN : les commutateurs propagent le broadcast, les routeurs l’arrêtent.

3. Le Péril des Boucles de Niveau 2 & Tempêtes de Diffusion

Pour assurer la haute disponibilité, les ingénieurs réseau installent des liens physiques redondants entre commutateurs. Cependant, sans protocole de contrôle, ces boucles physiques entraînent des catastrophes instantanées :

  • Absence de TTL en Couche 2 : L’en-tête Ethernet ne contient aucun champ Time-To-Live (contrairement au paquet IP). Une trame en boucle circule donc éternellement jusqu’à saturation des liens.
  • Tempête de diffusion (Broadcast Storm) : Une simple requête ARP en broadcast est dupliquée et rebouclée indéfiniment par les switches, saturant la bande passante et figeant les équipements.
  • Instabilité de la table CAM (MAC Flapping) : La même MAC source arrivant alternativement par plusieurs ports, le switch réécrit sans cesse sa table CAM, épuisant son processeur.
  • Copies multiples de trames : Les machines clientes reçoivent des dizaines de copies de la même trame, causant des plantages applicatifs.

4. Le Protocole Spanning Tree (STP 802.1D & 802.1w RSTP)

Le protocole STP (Spanning Tree Protocol) résout ce dilemme : il permet d’avoir des câbles physiques redondants tout en bloquant logiquement certains ports pour créer une topologie arborescente sans boucle (Tree). En cas de coupure d’un lien actif, le port bloqué s’ouvre automatiquement pour rétablir la communication.

L’algorithme STP (STA) procède en 3 étapes d’élection :

  1. Élection du Root Bridge (Commutateur Racine) :
    Chaque switch possède un Bridge ID (BID) composé de :
    Priorité (2 octets, multiple de 4096, défaut 32768) + MAC de base (6 octets).
    Le commutateur ayant le plus petit Bridge ID est élu Root Bridge. En cas d’égalité de priorité, l’adresse MAC la plus basse l’emporte.
  2. Élection des Root Ports (RP) sur les commutateurs non-racines :
    Chaque switch non-racine élit exactement un seul Root Port : le port physique qui présente le plus faible coût cumulé vers la racine (Root Path Cost).
  3. Élection des Designated Ports (DP) par segment :
    Sur chaque segment réseau reliant deux switches, un seul port est élu Designated Port (celui du switch ayant le plus faible coût vers la racine). Tous les ports du Root Bridge sont automatiquement DP.
  4. Blocage des ports restants (Blocking / Alternate) :
    Tous les ports qui ne sont ni Root Port (RP) ni Designated Port (DP) sont placés en état Blocking (BLK). Ils n’émettent ni ne relaient aucune trame de données, mais continuent d’écouter les trames BPDU (Bridge Protocol Data Units) pour détecter les pannes.
Coûts de liens standard STP 802.1D vs RSTP

Plus le lien est rapide, plus son coût est faible :

  • 10 Mbps : Coût 100 (STP) / 2 000 000 (RSTP)
  • 100 Mbps (FastEthernet) : Coût 19 (STP) / 200 000 (RSTP)
  • 1 Gbps (GigabitEthernet) : Coût 4 (STP) / 20 000 (RSTP)
  • 10 Gbps (TenGigabit) : Coût 2 (STP) / 2 000 (RSTP)

Exercice 1 — Simulateur de table CAM de commutateur L2

Étude de cas Niveau 1 — Acquisition

Objectif : Modéliser l'apprentissage dynamique d'adresses MAC sur les ports d'un switch et la décision de commutation (forwarding vs inondation/flooding).

Le commutateur possède N ports (ex: Fa0/1 à Fa0/24). La table CAM est initialement vide.
Analysez les paramètres du problème pour chaque cas.
Puis il prend sa décision :
1. Si MAC_DST == ff:ff:ff:ff:ff:ff ou si MAC_DST n'est pas dans la table : afficher ACTION: FLOOD (ports sauf <PORT_RECU>).
2. Si MAC_DST est connue sur le port P_DST : si P_DST == PORT_RECU, afficher ACTION: FILTRE (meme port), sinon afficher ACTION: FORWARD vers <P_DST>.
- CAM : Indiquez les entrées apprises triées par adresse MAC au format :
<MAC> -> <PORT>. Si la table est vide, afficher TABLE CAM VIDE.

Cas d’exemple
FRAME Fa0/1 00:11:22:33:44:01 00:11:22:33:44:02
FRAME Fa0/2 00:11:22:33:44:02 00:11:22:33:44:01
CAM
Résolution attendue

Première trame inondée car destination inconnue, deuxième commutée directement.

Trois indices, rédigés en mots
  1. L'apprentissage se fait sur la MAC source.
  2. La décision d'acheminement se fait sur la MAC destination.
  3. Si la destination est sur le même port d'entrée (ex: hub connecté au port), le switch filtre la trame.

Exercice 2 — Émulateur d'élection de Root Bridge STP 802.1D

Étude de cas Niveau 2 — Application

Objectif : Simuler l'élection du commutateur racine (Root Bridge) selon les Bridge IDs (Priority + MAC).

Dans Spanning Tree Protocol (STP 802.1D / RSTP 802.1w), le commutateur racine est celui qui possède le plus petit Bridge ID (BID).
Le Bridge ID est composé de :
<Bridge Priority> (entier multiple de 4096 sous Cisco PVST+, défaut 32768) + <MAC de base>.
Analysez les paramètres du problème pour chaque cas.
Le script doit :
1. Afficher pour chaque switch son Bridge ID calculé sous la forme :
<NOM>: BID=<PRIORITE>.<MAC>
2. Déterminer et afficher le Root Bridge élu :
ROOT BRIDGE ELU: <NOM> (Raison: <PLUS_FAIBLE_PRIORITE|DEPARTAGE_MAC>)
Si un switch a une priorité strictement inférieure à tous les autres : PLUS_FAIBLE_PRIORITE ; si la priorité minimale est partagée par 2 switches ou plus et que le choix s'est fait sur la MAC : DEPARTAGE_MAC.

Cas d’exemple
SW1 32768 00:0a:00:11:22:33
SW2 4096 00:0b:00:44:55:66
SW3 32768 00:0c:00:77:88:99
Résolution attendue
SW1: BID=32768.00:0a:00:11:22:33
SW2: BID=4096.00:0b:00:44:55:66
SW3: BID=32768.00:0c:00:77:88:99
ROOT BRIDGE ELU: SW2 (Raison: PLUS_FAIBLE_PRIORITE)

SW2 a la plus faible priorité configurée (4096 contre 32768).

Deux indices, rédigés en mots
  1. Le BID se compare d'abord sur la priorité numérique, puis alphabétiquement/numériquement sur l'adresse MAC.
  2. La plus petite valeur l'emporte toujours.

Exercice 3 — Déterminateur des rôles de ports STP (RP, DP, BLK)

Étude de cas Niveau 3 — Raisonnement

Objectif : Déterminer les rôles et états des ports STP : Root Port (RP), Designated Port (DP) et Alternate/Blocking (BLK).

Analysez les données fournies pour chaque cas.
Les lignes suivantes décrivent les liens bidirectionnels du réseau :
LIEN <SW_A>:<PORT_A> <SW_B>:<PORT_B> <COUT> (ex: LIEN SW1:Fa0/1 SW2:Fa0/1 19).
Règles Spanning Tree :
1. Sur le Root Bridge, tous les ports connectés sont DP (Designated Port, état Forwarding).
2. Pour chaque switch non-racine : le port ayant le plus faible coût cumulé vers la racine (Root Path Cost) est élu RP (Root Port).
3. Sur chaque lien entre deux switches non-racines : le switch ayant le plus faible Root Path Cost obtient le DP sur son port. L'autre port du lien devient BLK (Alternate/Blocking).
Indiquez pour chaque commutateur (trié alphabétiquement), puis pour chaque port de ce commutateur (trié) :
<SWITCH> <PORT> -> <RP|DP|BLK> (Cout-Racine: <C>)

Cas d’exemple
ROOT: SW1
LIEN SW1:Fa0/1 SW2:Fa0/1 19
LIEN SW1:Fa0/2 SW3:Fa0/1 19
LIEN SW2:Fa0/2 SW3:Fa0/2 19
Résolution attendue
SW1 Fa0/1 -> DP (Cout-Racine: 0)
SW1 Fa0/2 -> DP (Cout-Racine: 0)
SW2 Fa0/1 -> RP (Cout-Racine: 19)
SW2 Fa0/2 -> DP (Cout-Racine: 19)
SW3 Fa0/1 -> RP (Cout-Racine: 19)
SW3 Fa0/2 -> BLK (Cout-Racine: 19)

Triangle classique : SW3:Fa0/2 est bloqué (départage arbitraire alphabétique SW2 < SW3).

Trois indices, rédigés en mots
  1. Utiliser l'algorithme de Dijkstra ou une exploration en largeur pour trouver le coût minimum vers le Root Bridge pour chaque switch.
  2. Le port qui offre ce chemin minimal est le Root Port (RP).
  3. Sur un segment partagé entre non-racines, le côté le plus proche de la racine est Designated (DP), l'autre est Alternate/Blocking (BLK).

6. QCM — niveau examen

Sur quelle adresse figurant dans une trame Ethernet un commutateur s’appuie-t-il pour enrichir sa table CAM ?

Le commutateur apprend la localisation des machines uniquement en observant l’adresse MAC source de chaque trame arrivant sur un port physique. L’adresse destination sert uniquement à décider où envoyer la trame.

Quelle action immédiate réalise un commutateur lorsqu’il reçoit une trame unicast dont l’adresse MAC destination ne figure pas dans sa table CAM ?

C’est le mécanisme d’Unknown Unicast Flooding : ne sachant pas sur quel port se trouve le destinataire, le commutateur duplique la trame sur l’ensemble des autres ports du même VLAN pour que l’hôte visé puisse la recevoir.

Quel critère prioritaire départage deux commutateurs lors de l’élection du Root Bridge dans le protocole STP ?

Le Root Bridge est le commutateur possédant le plus petit Bridge ID. Le premier élément comparé est la Bridge Priority (défaut 32768). En cas d’égalité stricte de priorité, l’adresse MAC la plus basse sert de départage.

Sur un commutateur non-racine, combien de ports peuvent obtenir le rôle de Root Port (RP) pour une instance STP donnée ?

Par définition de l’arbre couvrant Spanning Tree, chaque commutateur non-racine possède exactement un seul Root Port (RP), qui est le port offrant le plus faible coût de chemin cumulé vers le Root Bridge.

Quel est le coût Spanning Tree standard (802.1D) associé à un lien Gigabit Ethernet (1000 Mbps) ?

Selon la norme STP 802.1D, un lien 10 Mbps a un coût de 100, un lien Fast Ethernet (100 Mbps) a un coût de 19, un lien Gigabit Ethernet a un coût de 4, et un lien 10 Gigabit a un coût de 2.

Pourquoi une boucle physique sur un réseau de commutation L2 provoque-t-elle une tempête de diffusion alors qu’une boucle sur réseau IP L3 finit par s’arrêter ?

Le paquet IP contient un champ TTL (Time-To-Live) décrémenté par chaque routeur jusqu’à destruction du paquet à TTL=0. La trame Ethernet ne possède aucun TTL : sans STP, une trame Ethernet tourne indéfiniment en boucle.

Quel est le rôle d’un port STP placé en état Blocking (Alternate) ?

Un port bloqué n’apprend pas les adresses MAC et ne transmet aucune trame utilisateur (rompant ainsi la boucle), mais il écoute en permanence les trames BPDU. Si la racine devient injoignable, il transite vers l’état Forwarding.

Quels rôles de ports trouve-t-on sur le commutateur élu Root Bridge ?

Puisque le Root Bridge est la racine absolue de la topologie, son coût vers lui-même est 0. Sur chaque segment auquel il est connecté, il offre donc le meilleur chemin : tous ses ports actifs sont Designated Ports (DP).

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Croire que le commutateur apprend l’adresse MAC destination : l’apprentissage se fait UNIQUEMENT sur la MAC source entrante.
  • Oublier que les trames Ethernet n’ont pas de champ TTL, ce qui rend les boucles L2 infinies et destructrices.
  • Penser que le Root Bridge possède un port bloqué : tous les ports actifs du Root Bridge sont Designated (DP).
  • Confondre un port Root Port (RP, présent sur switch non-racine vers la racine) avec un Designated Port (DP, présent sur chaque segment).
  • Négliger les trames BPDU : même un port bloqué (BLK) continue de recevoir les BPDU pour surveiller l’état du réseau.

8. Méthodologie de résolution

Méthodologie de Calcul Manuel d’une Topologie Spanning Tree
  1. Étape 1 — Identifier le Root Bridge : Comparer les Bridge IDs (Priorité puis MAC). Le commutateur avec le plus petit BID est la racine.
  2. Étape 2 — Activer les DP de la racine : Marquer tous les ports connectés du Root Bridge comme Designated Ports (DP, état Forwarding).
  3. Étape 3 — Élire les Root Ports (RP) : Pour chaque switch non-racine, additionner les coûts de liens vers la racine. Le port au coût minimal devient RP.
  4. Étape 4 — Élire les Designated Ports (DP) par segment : Sur chaque câble reliant deux non-racines, le port du switch le plus proche de la racine devient DP.
  5. Étape 5 — Bloquer les boucles : Placer tous les ports restants en état Alternate/Blocking (BLK). Vérifier que le graphe forme un arbre parfait.

9. Révision active

Résumé essentiel
  • Le commutateur L2 apprend dynamiquement les adresses MAC sources entrantes et alimente sa table CAM.
  • Le switch commute (forward) en unicast connu, et inonde (flood) en broadcast ou unicast inconnu.
  • Chaque port d’un commutateur constitue un domaine de collision distinct en mode Full Duplex.
  • L’absence de champ TTL dans la trame Ethernet transforme toute boucle physique L2 en tempête de diffusion paralysante.
  • Le protocole STP 802.1D élit un Root Bridge (plus petit Bridge ID) et bloque logiquement les ports redondants.
  • Sur chaque switch non-racine, le meilleur port vers la racine est le Root Port (RP) ; sur chaque câble, le port actif est le Designated Port (DP).

Checklist de maîtrise

  • Je comprends parfaitement la différence entre apprentissage (source) et décision de commutation (destination).
  • Je sais distinguer un domaine de collision d’un domaine de diffusion sur un schéma réseau.
  • Je connais la composition d’un Bridge ID (Priorité de pont + adresse MAC de base).
  • Je sais déterminer quel commutateur est élu Root Bridge sur une topologie donnée.
  • Je sais attribuer avec certitude les rôles de ports STP (RP, DP, BLK) sur un réseau maillé.

Les 8 notions à connaître absolument
