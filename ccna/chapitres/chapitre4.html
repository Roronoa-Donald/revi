Chapitre 4 — Configuration des Équipements sous Cisco IOS & Sécurisation

Mise en situation

Un audit de cybersécurité externe classe au niveau « Critique » le parc de commutateurs et routeurs d’une banque régionale. Des mots de passe circulent en clair sur le réseau via Telnet, les bannières d’avertissement sont absentes et les accès d’administration par console ne sont pas verrouillés. Les ingénieurs réseau doivent reprendre le contrôle de la flotte d’équipements sous Cisco IOS, maîtriser la hiérarchie des modes d’accès de la CLI, appliquer les 5 règles d’or du durcissement Cisco (protection des secrets locaux, secret privilégié adapté à la plateforme, SSH version 2 sur les lignes VTY) et interpréter instantanément les sorties de commandes show pour diagnostiquer les incidents matériels et logiques. Ce quatrième module forme à la pratique opérationnelle quotidienne de l’administration réseau Cisco.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. naviguer avec aisance entre les différents modes d’exécution de la CLI Cisco IOS (User EXEC, Privileged EXEC, Global Config, Interface Config) ;
  2. appliquer la configuration de base d’un équipement (hostname, description d’interfaces, bannières MOTD) ;
  3. distinguer et manipuler la mémoire vive running-config (RAM) et la mémoire non volatile startup-config (NVRAM) ;
  4. distinguer les types de secrets Cisco et les limites de service password-encryption pour protéger les accès ;
  5. configurer l’accès à distance sécurisé SSH v2 (nom de domaine, clés RSA 2048 bits, désactivation de Telnet sur les lignes VTY) ;
  6. analyser la commande de diagnostic clé « show ip interface brief » pour distinguer les pannes L1 des erreurs d’encapsulation L2.

1. Hiérarchie des Modes d’Exécution Cisco IOS

L’interface en ligne de commande (CLI) des routeurs et commutateurs Cisco IOS est structurée selon une arborescence stricte de modes de commande, chacun reconnaissable à son invite (prompt) spécifique :

Mode d’ExécutionInvite (Prompt)Commande de TransitionPrivilèges & Usages
Mode Utilisateur (User EXEC) Router> ou Switch> Connexion initiale Consultation basique (ping, traceroute simple). Aucune modification de configuration permise.
Mode Privilégié (Privileged EXEC) Router# ou Switch# enable Toutes les commandes de supervision approfondie (show, debug, sauvegarde, redémarrage).
Mode Configuration Globale Router(config)# configure terminal (depuis Privilégié) Paramètres affectant l’équipement dans son ensemble (hostname, bannières, services globaux, routage).
Sous-mode Interface / Ligne Router(config-if)# ou (config-line)# interface g0/0 ou line vty 0 4 Paramétrage spécifique à un port physique, une sous-interface ou une ligne de console/terminal virtuel.

Commandes de navigation :

  • exit : remonte d’un cran dans l’arborescence (ex: de (config-if)# vers (config)#).
  • end ou Ctrl + Z : quitte immédiatement tous les sous-modes pour revenir directement au mode Privilégié Router#.
  • disable : repasse du mode Privilégié au mode Utilisateur Router>.

2. Gestion des Fichiers de Configuration : RAM vs NVRAM

Un équipement Cisco gère deux fichiers de configuration distincts :

1. running-config (Mémoire RAM)

La configuration actuellement en cours d’exécution par le système. Toute commande tapée dans la CLI s’applique instantanément dans la running-config. En contrepartie, la RAM étant volatile, toute modification non sauvegardée est définitivement perdue en cas de coupure de courant ou de redémarrage.

Commande : show running-config

2. startup-config (Mémoire NVRAM)

Le fichier de configuration de démarrage, stocké en mémoire non volatile (NVRAM). Il est chargé en RAM lors du boot de l’équipement. Il conserve les réglages de manière permanente.

Sauvegarde : copy running-config startup-config (ou write memory).

Suppression : erase startup-config.

3. Les 5 Règles d’Or du Durcissement de Sécurité Cisco IOS

Tout équipement déployé en production doit impérativement respecter les règles de durcissement recommandées par Cisco et l’ANSSI :

  1. Masquage de certains mots de passe dans la configuration :
    Router(config)# service password-encryption
    Le type 7 est un masquage réversible et faible : il ne protège pas un secret contre une personne qui obtient la configuration.
  2. Protection du mode Privilégié avec enable secret :
    Router(config)# enable secret <MotDePasseRobuste>
    Le type 5 utilise MD5 et est faible pour les mots de passe ; le type 8 utilise PBKDF2 avec SHA-256 et le type 9 utilise scrypt. Choisir un type adapté à la politique de sécurité, à la version et à la compatibilité de l’équipement ; la seule présence de enable secret ne prouve pas le type utilisé.
  3. Configuration d’une bannière d’avertissement :
    Router(config)# banner motd #ACCES INTERDIT AU PERSONNEL NON AUTORISE#
    La bannière avertit de la restriction d’accès ; ses éventuelles exigences juridiques dépendent du contexte et doivent être vérifiées localement.
  4. Authentification locale sur console physique :
    Router(config)# line console 0
    Router(config-line)# login local
    Router(config-line)# logging synchronous     (évite que les messages système ne tronquent la ligne de commande).
  5. Accès distant sécurisé SSH v2 exclusif :
    Telnet transmet les identifiants et commandes en clair sur le réseau. Il doit être banni au profit de SSH version 2 chiffré.
Procédure complète de déploiement de SSH v2 sur Cisco IOS
Router(config)# hostname R1
R1(config)# ip domain-name entreprise.local
R1(config)# crypto key generate rsa modulus 2048
R1(config)# ip ssh version 2
R1(config)# username admin privilege 15 secret AdminPass2026!
R1(config)# line vty 0 4
R1(config-line)# transport input ssh
R1(config-line)# login local
R1(config-line)# exit

4. Diagnostic d’État des Interfaces (show ip interface brief)

La commande show ip interface brief est l’outil de diagnostic le plus puissant de la CLI Cisco. Elle affiche une ligne synthétique par interface avec deux colonnes d’état capitales : Status (couche 1) et Protocol (couche 2) :

Status (L1)Protocol (L2)Diagnostic OpérationnelAction Corrective
up up Opérationnel : signal physique présent et protocole de liaison synchronisé. Interface fonctionnelle pour le trafic IP.
administratively down down Désactivée administrativement : l’interface est verrouillée par commande. Taper no shutdown dans le sous-mode interface.
down down Panne physique (L1) : aucun signal détecté. Câble débranché ou équipement distant éteint. Contrôler le cordon RJ45/SFP, vérifier que l’équipement en vis-à-vis est allumé.
up down Panne de liaison (L2) : câble branché mais problème d’encapsulation ou d’horloge. Vérifier l’encapsulation (ex: mismatch HDLC/PPP) ou l’attribution de la vitesse/duplex.

Exercice 1 — Parseur et validateur de hiérarchie de modes Cisco IOS

Étude de cas Formative Niveau 1 — Acquisition

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Simuler la navigation entre les modes CLI Cisco IOS (User EXEC, Privileged EXEC, Global Config, Interface Config) et vérifier la validité des commandes.

Le script simule une session interactive Cisco IOS sur un équipement nommé Router.
Modes possibles et leurs invites :
- USER : Router>
- PRIVILEGED : Router#
- CONFIG : Router(config)#
- CONFIG_IF : Router(config-if)#
Transitions valides :
- Depuis USER : enable -> PRIVILEGED
- Depuis PRIVILEGED : disable -> USER, configure terminal -> CONFIG
- Depuis CONFIG : interface <nom> -> CONFIG_IF, exit -> PRIVILEGED, end -> PRIVILEGED
- Depuis CONFIG_IF : exit -> CONFIG, end -> PRIVILEGED
Toute autre commande est considérée comme exécutée dans le mode courant (afficher OK: <cmd>), sauf si une commande de mode restreint est appelée dans un mode insuffisant (ex: configure terminal appelé en mode USER -> afficher ERREUR: Commande non autorisee en mode USER).
Pour chaque commande du scénario, indiquer l'invite courante suivie de la commande, puis le résultat ou l'erreur, et enfin la nouvelle invite.

Cas d’exemple
enable
configure terminal
interface g0/0
exit
end
disable
Deux indices, rédigés en mots
  1. Utiliser une variable mode ("USER", "PRIV", "CONF", "IF") et mettre à jour l'invite après chaque transition.
  2. Les commandes "exit" et "end" permettent de remonter dans la hiérarchie.

Exercice 2 — Audit et durcissement de configuration Cisco IOS

Étude de cas Formative Niveau 2 — Application

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Relever la présence de cinq commandes dans un modèle simplifié de configuration Cisco.

Dans ce modèle simplifié, vérifiez uniquement la présence des commandes suivantes pour chaque cas :
1. PASSWORD_ENCRYPTION : service password-encryption.
2. ENABLE_SECRET : enable secret <mot_de_passe> ; enable password ne compte pas.
3. SSH_ONLY : transport input ssh dans le bloc line vty indiqué.
4. BANNER_MOTD : banner motd.
5. LOGIN_LOCAL : login local sur la console ou les lignes VTY indiquées.
Pour chaque critère, utilisez [VALIDE] <NOM_REGLE> : Commande presente ou [ECHEC] <NOM_REGLE> : Commande absente.
Terminez par SCORE DE PRESENCE: <X>/5 -> CRITERES_REUNIS si les cinq commandes sont présentes, sinon CRITERES_INCOMPLETS.
Ce contrôle ne permet pas de déterminer le type de secret, la conformité juridique ou la sécurité globale de l'équipement.

Cas d’exemple
service password-encryption
enable secret Cisc0$ecr3t
banner motd #ACCES INTERDIT#
line con 0
 login local
line vty 0 4
 transport input ssh
 login local
Deux indices, rédigés en mots
  1. Le type 7 est un masquage faible et réversible ; la présence de enable secret ne révèle pas son type.
  2. Analyser le contexte de bloc "line vty 0 4" pour vérifier le transport SSH.

Exercice 3 — Parseur d'état d'interfaces Cisco (show ip interface brief)

Étude de cas Formative Niveau 3 — Raisonnement

Cette vérification est une aide à l’apprentissage : elle ne donne pas de note et ne valide pas les acquis.

Objectif : Analyser la sortie de la commande Cisco « show ip interface brief » pour diagnostiquer les incidents de couche 1 et couche 2.

Analysez les paramètres du problème pour chaque cas.
Chaque ligne comporte les colonnes :
Interface | IP-Address | OK? | Method | Status | Protocol
Pour chaque interface active ou inactive, le script détermine le diagnostic :
- Si Status == "up" et Protocol == "up" : OPERATIONNEL (L1 Up / L2 Up)
- Si Status == "up" et Protocol == "down" : ERREUR_LIAISON (L1 Up / L2 Down - Probleme encapsulation ou clock-rate)
- Si Status == "down" et Protocol == "down" : NON_CONNECTE (L1 Down / L2 Down - Cable debranche)
- Si Status == "administratively down" : DESACTIVE_ADMIN (Interface sous shutdown)
Format de sortie :
<INTERFACE> (<IP>) -> <DIAGNOSTIC>

Cas d’exemple
Interface IP-Address OK? Method Status Protocol
GigabitEthernet0/0 192.168.1.1 YES manual up up
GigabitEthernet0/1 unassigned YES unset administratively down down
Deux indices, rédigés en mots
  1. Ignorer la ligne d'en-tête contenant "Interface IP-Address OK? Method Status Protocol".
  2. Le statut "administratively down" compte pour deux mots lors du découpage.

6. QCM — niveau examen

Quelle commande permet de passer du mode Utilisateur (Router>) au mode Privilégié (Router#) ?

La commande enable permet d’accéder au mode Privilégié (Privileged EXEC mode). Elle est généralement protégée par le mot de passe configuré via enable secret.

Dans quelle mémoire réside le fichier de configuration actuellement actif et en cours d’exécution par le processeur ?

La running-config est chargée et exécutée en mémoire vive (RAM). Elle est volatile et sera effacée en cas de coupure de courant si elle n’est pas copiée en NVRAM (startup-config).

Quelle commande Cisco IOS enregistre de manière permanente les modifications de configuration pour le prochain démarrage ?

La commande officielle est « copy running-config startup-config » (ou la commande historique équivalente « write memory »).

Pourquoi est-il impératif d’utiliser « enable secret » plutôt que « enable password » ?

Le type 5 fondé sur MD5 est faible ; les types 8 (PBKDF2-SHA-256) et 9 (scrypt) sont à privilégier lorsqu’ils sont compatibles avec la plateforme et sa politique de sécurité. Le type 7 est réversible.

Quelle instruction interdit formellement les connexions Telnet non chiffrées sur les terminaux virtuels (lignes VTY) ?

Dans le sous-mode line vty 0 4, la commande « transport input ssh » n’autorise que les sessions SSH chiffrées et rejette automatiquement toutes les tentatives de connexion Telnet en clair.

Quelle taille de clé minimale est préconisée par Cisco pour la génération des clés RSA destinées à SSH version 2 ?

Une clé RSA de 2048 bits est le standard recommandé moderne. Une clé inférieure à 768 bits interdit le passage en SSH v2 sous Cisco IOS.

Dans la sortie de « show ip interface brief », que signifie l’état « Status: administratively down / Protocol: down » ?

Status « administratively down » indique que la commande shutdown est active sur l’interface. Pour la rendre opérationnelle, l’administrateur doit entrer dans l’interface et taper « no shutdown ».

Que réalise la commande globale « service password-encryption » ?

Elle masque certains mots de passe dans la configuration au moyen du type 7, réversible et faible : ce masquage ne protège pas les secrets si la configuration est divulguée.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de taper « no shutdown » sur une interface de routeur Cisco (les ports de routeur sont désactivés par défaut).
  • Redémarrer un équipement sans avoir exécuté « copy running-config startup-config », perdant ainsi tout le travail effectué.
  • Utiliser la commande obsolète « enable password » à la place de « enable secret » (vulnérabilité critique).
  • Oublier de configurer « ip domain-name » avant de lancer « crypto key generate rsa », ce qui provoque une erreur de commande.
  • Laisser Telnet activé sur les lignes VTY (« transport input all » ou « transport input telnet »), exposant les mots de passe sur le réseau.

8. Méthodologie de résolution

Méthodologie de Configuration & Recette d’un Équipement Cisco
  1. Étape 1 — Nommage & Accès : Se connecter sur console, attribuer un hostname explicite et configurer logging synchronous.
  2. Étape 2 — Sécurisation : Configurer enable secret avec un type adapté à la version, connaître les limites de service password-encryption et déclarer une banner motd.
  3. Étape 3 — Accès distant : Déclarer le nom de domaine, générer la clé RSA 2048 bits, créer un utilisateur local et forcer transport input ssh sur VTY.
  4. Étape 4 — Adressage d’interfaces : Configurer l’IP et le masque sur les ports requis, ajouter une description explicite et activer avec no shutdown.
  5. Étape 5 — Recette : Exécuter show ip interface brief et sauvegarder la configuration avec copy running-config startup-config.

9. Révision active

Résumé essentiel
  • La CLI Cisco IOS s’organise en 4 modes principaux : User EXEC (>), Privileged EXEC (#), Global Config (config)# et Interface (config-if)#.
  • La running-config vit en mémoire vive RAM (volatile) ; la startup-config est sauvegardée en NVRAM permanente.
  • La commande copy running-config startup-config sauvegarde les modifications de manière persistante.
  • Le type 5 de enable secret est faible ; privilégier un type 8 ou 9 compatible et ne pas confondre le masquage réversible de type 7 avec une protection forte.
  • Telnet transmettant les données en clair, il doit être formellement banni en production via transport input ssh.
  • show ip interface brief permet de diagnostiquer en un coup d’œil l’état physique L1 (Status) et protocolaire L2 (Protocol) de chaque port.

Checklist de maîtrise

  • Je connais la syntaxe de transition entre les 4 modes de la CLI Cisco IOS.
  • Je comprends la différence fondamentale entre la running-config et la startup-config.
  • Je sais appliquer les 5 commandes de durcissement de sécurité recommandées par Cisco.
  • Je maîtrise l’ensemble de la procédure pour activer SSH v2 sur les lignes VTY.
  • Je sais interpréter un statut « administratively down », « down/down » ou « up/down » dans show ip interface brief.

Les 8 notions à connaître absolument

  1. Modes d’exécution CLI Cisco IOS
  2. Mémoire RAM (running-config) vs NVRAM (startup-config)
  3. Sauvegarde (copy running-config startup-config)
  4. Chiffrement (service password-encryption)
  5. Mot de passe privilégié (enable secret)
  6. Bannière d’avertissement (banner motd)
  7. Configuration SSH v2 et clés RSA 2048 bits
  8. Diagnostic L1/L2 avec show ip interface brief
