Chapitre 5 — Routage IPv4, Tables de Routage & Routes Statiques

Module 5 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Un fournisseur de services héberge plusieurs filiales interconnectées par des liaisons télécoms louées et un accès Internet fibre. Lors d’un incident de coupure de fibre optique principale, le trafic vers le siège ne bascule pas sur le lien 4G de secours, et certains paquets destinés à des serveurs internes empruntent par erreur la passerelle Internet publique avant d’être détruits. Les ingénieurs réseau doivent décortiquer l’algorithme décisionnel de la table de routage Cisco, comprendre la suprématie absolue du Longest Prefix Match (LPM) sur la Distance Administrative, configurer des routes statiques précises, des routes de dernier recours (0.0.0.0/0) et déployer des routes statiques flottantes pour garantir la résilience des liens. Ce cinquième module aborde le cœur névralgique de l’acheminement des paquets IP.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. comprendre le rôle fondamental d’un routeur L3 et le cycle de vie d’un paquet IP traversant plusieurs sous-réseaux ;
  2. interpréter avec précision la table de routage Cisco IOS issue de la commande « show ip route » (codes C, L, S, O, D) ;
  3. maîtriser l’algorithme Longest Prefix Match (LPM) pour prédire quelle route sera choisie face à des préfixes concurrents ;
  4. différencier la Distance Administrative (fiabilité de la source) de la métrique (coût du chemin) ;
  5. configurer des routes statiques complètes (via adresse de prochain saut ou interface de sortie) et des routes par défaut (0.0.0.0/0) ;
  6. concevoir une route statique flottante (Floating Static Route) avec Distance Administrative élevée pour le secours automatique ;
  7. agréger plusieurs sous-réseaux contigus en un unique préfixe résumé (Supernetting / Route Summarization).

1. Principes du Routage L3 & Lecture de « show ip route »

Un routeur est un équipement de niveau 3 (Réseau) dont la mission est d’acheminer les paquets IP entre des réseaux logiques distincts. Pour chaque paquet reçu, il consulte sa table de routage (RIB / FIB) afin de déterminer l’interface de sortie et l’adresse du prochain saut (Next-Hop).

La commande show ip route affiche les routes apprises, précédées d’un code identifiant leur origine :

CDirectement connectée0C 192.168.1.0/24 is directly connected, GigabitEthernet0/0
LHôte local (Local host)0L 192.168.1.254/32 is directly connected, GigabitEthernet0/0

Structure de l’entrée [AD/Métrique] : Le premier nombre entre crochets représente la Distance Administrative (plus elle est petite, plus la source est jugée fiable). Le second nombre est la Métrique (coût calculé par le protocole pour atteindre la cible).

2. L’Algorithme Décisionnel : Longest Prefix Match (LPM)

L’une des règles les plus importantes de la certification CCNA est l’ordre de priorité appliqué par le routeur lors du routage :

  1. Règle n°1 — Longest Prefix Match (LPM) :
    Le routeur recherche toutes les routes dont le réseau englobe l’adresse IP destination du paquet. Parmi les routes candidates, la route ayant le préfixe le plus long (le masque le plus spécifique) est OBLIGATOIREMENT choisie. Cette règle l’emporte toujours, indépendamment de la Distance Administrative ou de la métrique !
  2. Règle n°2 — Distance Administrative (AD) :
    Si deux routes candidates ont exactement la même longueur de préfixe (ex: deux routes vers 10.0.0.0/24), le routeur installe dans sa table de routage celle qui possède la plus petite Distance Administrative.
  3. Règle n°3 — Métrique la plus faible :
    Si les deux routes proviennent du même protocole (même préfixe et même AD), la route ayant la plus petite métrique est préférée.
Exemple Piège Classique de Concours & Certification

Soit la table suivante :
1. S 10.0.0.0/16 [1/0] via 192.168.1.1 (Route statique, AD=1)
2. O 10.0.1.0/24 [110/20] via 192.168.2.1 (Route OSPF, AD=110)

Un paquet arrive pour 10.0.1.50. Quelle route est empruntée ?
Réponse : La route OSPF (/24) ! Même si son AD est de 110 contre 1 pour la statique, son masque de 24 bits est plus long que le masque de 16 bits. Le Longest Prefix Match a toujours la priorité absolue.

3. Configuration des Routes Statiques & Route par Défaut

Une route statique est configurée manuellement par l’administrateur avec la syntaxe globale :
Router(config)# ip route <reseau_destination> <masque> <next_hop_ip | interface_sortie>

  • Route vers prochain saut (Next-Hop IP) :
    R1(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2
    Recommandé sur les interfaces multi-accès Ethernet (évite les résolutions ARP abusives).
  • Route directement connectée (Interface de sortie) :
    R1(config)# ip route 192.168.20.0 255.255.255.0 Serial0/0/0
    Adapté aux liaisons point-à-point série.
  • Route entièrement spécifiée (Fully Specified Route) :
    R1(config)# ip route 192.168.20.0 255.255.255.0 GigabitEthernet0/1 10.0.0.2
  • Route par défaut (Passerelle de dernier recours) :
    R1(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.254
    Représentée par 0.0.0.0/0, elle matche tous les paquets qui n’ont aucune route spécifique dans la table. C’est la passerelle vers Internet.

4. Routes Statiques Flottantes & Supernetting

Routes Statiques Flottantes (Secours)

Une route statique flottante est configurée avec une Distance Administrative manuellement rehaussée pour être supérieure à celle de la liaison principale :

! Lien principal fibre (AD 1 par defaut)
ip route 10.0.0.0 255.0.0.0 172.16.1.1
! Lien 4G secours (AD forcee a 10)
ip route 10.0.0.0 255.0.0.0 172.16.2.1 10

La route AD 10 reste dormante hors de la table de routage tant que le lien primaire fonctionne. En cas de coupure du lien primaire, elle s’injecte instantanément dans la table.

Supernetting (Résumé de Routes)

Le supernetting permet d’agréger plusieurs sous-réseaux contigus en un unique préfixe résumé CIDR pour alléger la table :

Exemple : 4 réseaux /24 contigus :
192.168.0.0/24, 192.168.1.0/24, 192.168.2.0/24, 192.168.3.0/24
Tous partagent les 22 premiers bits binaires identiques.
Leur résumé optimal est : 192.168.0.0/22 (masque 255.255.252.0).

Exercice 1 — Parseur de table de routage Cisco (show ip route)

Étude de cas Niveau 1 — Acquisition

Objectif : Analyser les entrées d'une table de routage Cisco IOS pour identifier la source (code), le préfixe, la distance administrative et le next-hop.

Analysez les paramètres du problème pour chaque cas.168.1.0/24 is directly connected, GigabitEthernet0/0
- L 192.168.1.1/32 is directly connected, GigabitEthernet0/0
- S 10.0.0.0/8 [1/0] via 192.168.1.254
- O 172.16.0.0/16 [110/20] via 10.1.1.2, GigabitEthernet0/1
- S* 0.0.0.0/0 [1/0] via 192.168.1.254
Pour chaque route, il Indiquez :
[<PROTO>] <RESEAU> | AD=<AD> | Metrique=<MET> | Sortie=<VIA_OU_INTERFACE>
avec les correspondances de protocoles :
C -> Directement Connecte (AD=0, Metrique=0)
L -> Hote Local (AD=0, Metrique=0)
S ou S* -> Statique (AD et métrique extraits de [AD/Metrique], par défaut AD=1, Met=0 si non précisé)
O -> OSPF (AD=110)
D -> EIGRP (AD=90)
B -> BGP (AD=20 si eBGP, 200 si iBGP)

Cas d’exemple
C 192.168.1.0/24 is directly connected, GigabitEthernet0/0
S 10.0.0.0/8 [1/0] via 192.168.1.254
Résolution attendue
[Directement Connecte] 192.168.1.0/24 | AD=0 | Metrique=0 | Sortie=GigabitEthernet0/0
[Statique] 10.0.0.0/8 | AD=1 | Metrique=0 | Sortie=via 192.168.1.254

Extraction de route connectée et route statique standard.

Deux indices, rédigés en mots
  1. Le premier token indique le code protocole (C, L, S, S*, O, D, B).
  2. Le bloc entre crochets [AD/Metrique] fournit la Distance Administrative et le coût.

Exercice 2 — Moteur de décision Longest Prefix Match (LPM)

Étude de cas Niveau 2 — Application

Objectif : Déterminer la route exacte empruntée par un paquet IP en appliquant la règle CCNA du préfixe le plus spécifique.

Analysez les données fournies pour chaque cas.168.1.135).
Les lignes suivantes décrivent les routes candidates dans la table de routage au format :
ROUTE <PREFIXE/CIDR> <NEXT_HOP> <AD> (ex: ROUTE 192.168.1.128/28 10.0.0.1 110).
Règles d'arbitrage Cisco :
1. Filtrer les routes qui englobent l'IP de destination (l'IP doit appartenir au sous-réseau).
2. Choisir la route ayant le masque le plus long (CIDR le plus élevé) : Longest Prefix Match.
3. En cas d'égalité parfaite de longueur de préfixe, départager par la plus petite Distance Administrative (AD).
Afficher :
ROUTE RETENUE: <PREFIXE/CIDR> via <NEXT_HOP> (Masque /<n>, AD=<ad>)
Si aucune route ne correspond, afficher PAQUET REJETE: Pas de route par defaut.

Cas d’exemple
PAQUET: 192.168.1.135
ROUTE 192.168.0.0/16 10.1.1.1 1
ROUTE 192.168.1.0/24 10.2.2.1 110
ROUTE 192.168.1.128/28 10.3.3.1 110
ROUTE 0.0.0.0/0 10.0.0.254 1
Résolution attendue
ROUTE RETENUE: 192.168.1.128/28 via 10.3.3.1 (Masque /28, AD=110)

Le préfixe /28 est le plus spécifique bien que son AD (110) soit plus forte que /16 (AD 1).

Deux indices, rédigés en mots
  1. Vérifier l'appartenance à un sous-réseau : (ip & mask) == network.
  2. Le tri principal est sur le CIDR décroissant, le tri secondaire sur l'AD croissante.

Exercice 3 — Calculateur de résumé de routes (Supernetting CIDR)

Étude de cas Niveau 3 — Raisonnement

Objectif : Agréger un ensemble de sous-réseaux IPv4 contigus en un unique préfixe résumé optimal pour optimiser la table de routage.

Analysez les paramètres du problème pour chaque cas.168.0.0/24, 192.168.1.0/24, 192.168.2.0/24, 192.168.3.0/24).
L'objectif est de déterminer le plus petit préfixe englobant (Supernet) qui couvre l'ensemble des réseaux donnés :
1. Convertir chaque réseau en binaire 32 bits.
2. Trouver le nombre de bits communs de poids fort partagés par TOUS les réseaux.
3. Calculer l'adresse réseau résultante avec ce nouveau CIDR.
Afficher :
RESUME OPTIMAL: <RESEAU_RESUME>/<CIDR_COMMUN>
Masque: <MASQUE_DECIMAL>
Sous-reseaux englobes: <N>

Cas d’exemple
192.168.0.0/24
192.168.1.0/24
192.168.2.0/24
192.168.3.0/24
Résolution attendue
RESUME OPTIMAL: 192.168.0.0/22
Masque: 255.255.252.0
Sous-reseaux englobes: 4

4 blocs /24 contigus résumés en 1 bloc /22.

Deux indices, rédigés en mots
  1. Comparer les représentations binaires des adresses réseau minimale et maximale du lot.
  2. Le premier bit divergent détermine la fin du préfixe commun.

6. QCM — niveau examen

Dans la sortie de « show ip route », que représente le premier chiffre entre crochets dans l’expression « [110/35] » ?

Dans l’affichage [110/35], 110 est la Distance Administrative (ici OSPF) et 35 est la métrique (coût du lien).

Soit deux routes dans la table : 192.168.1.0/24 via 10.0.0.1 (AD 1) et 192.168.1.128/25 via 10.0.0.2 (AD 110). Vers quelle adresse IP un paquet destiné à 192.168.1.150 est-il acheminé ?

L’algorithme Longest Prefix Match s’applique en premier : /25 est plus long que /24. La Distance Administrative ne sert qu’à départager des routes de même longueur de masque.

Quelle est la syntaxe correcte pour configurer une route par défaut vers la passerelle 203.0.113.1 sous Cisco IOS ?

La route par défaut sous Cisco IOS est définie par le préfixe 0.0.0.0 avec le masque 0.0.0.0, soit la commande « ip route 0.0.0.0 0.0.0.0 203.0.113.1 ».

Quelle est la valeur de la Distance Administrative par défaut attribuée à une route directement connectée (C) ?

Une route directement connectée a une Distance Administrative de 0, ce qui en fait la source d’information la plus fiable possible.

Comment qualifie-t-on une route statique configurée avec une Distance Administrative de 150 pour servir de secours à une route OSPF (AD 110) ?

C’est une route statique flottante (Floating Static Route). Son AD supérieure à 110 la maintient inactive tant qu’OSPF fonctionne, et lui permet de s’injecter en cas de panne d’OSPF.

Quel préfixe CIDR agrégé (Supernetting) résume au plus juste les deux sous-réseaux contigus 172.16.10.0/24 et 172.16.11.0/24 ?

En binaire, 10 vaut 00001010 et 11 vaut 00001011. Les 7 premiers bits du troisième octet sont identiques, ce qui donne 16 + 7 = 23 bits communs. Le résumé optimal est donc 172.16.10.0/23.

Que se passe-t-il si un routeur reçoit un paquet destiné à une adresse IP pour laquelle aucune route spécifique n’existe et qu’aucune route par défaut n’est configurée ?

Sans route correspondante ni route par défaut (0.0.0.0/0), le paquet est silencieusement détruit et le routeur émet un message ICMP type 3 code 0 (Network Unreachable) vers l’adresse IP source.

Quelle Distance Administrative possède une route apprise via le protocole EIGRP interne ?

EIGRP interne possède une Distance Administrative par défaut de 90. (OSPF est à 110, RIP à 120 et eBGP à 20).

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Penser que la Distance Administrative a la priorité sur la longueur du préfixe : le Longest Prefix Match l’emporte toujours.
  • Oublier que le routage est bidirectionnel : envoyer un paquet avec succès ne sert à rien si le routeur de destination ne sait pas répondre.
  • Utiliser uniquement l’interface de sortie sur un lien Ethernet multi-accès (provoque une tempête de requêtes ARP proxy).
  • Configurer une route flottante avec une AD inférieure ou égale à la route principale, écrasant ainsi la route normale.
  • Résumer des sous-réseaux non contigus ou inclure des réseaux tiers par erreur dans un calcul de supernetting.

8. Méthodologie de résolution

Méthodologie d’Ingénierie & Troubleshooting du Routage IP
  1. Étape 1 — Inspection de la table : Lancer « show ip route » et vérifier la présence des réseaux directement connectés (C/L) et statiques (S).
  2. Étape 2 — Test LPM : Identifier le préfixe englobant le plus long pour l’adresse IP ciblée afin de connaître le prochain saut retenu.
  3. Étape 3 — Vérification du prochain saut : S’assurer que l’adresse IP du next-hop est bien joignable sur le lien local (vérifier « show ip arp »).
  4. Étape 4 — Contrôle de la route retour : S’assurer que le routeur distant dispose lui aussi d’une route valide pour retourner les paquets (routage bidirectionnel).
  5. Étape 5 — Validation de secours : Débrancher temporairement le lien primaire pour attester que la route statique flottante prend bien le relais.

9. Révision active

Résumé essentiel
  • Le routeur L3 achemine les paquets IP en consultant sa table de routage (RIB/FIB).
  • Chaque entrée de table comprend un code source (C, L, S, O, D), un préfixe et le couple [Distance Administrative / Métrique].
  • L’algorithme Longest Prefix Match (LPM) donne la priorité absolue à la route ayant le masque le plus long (le plus spécifique).
  • La Distance Administrative mesure la fiabilité de la source (Directe 0, Statique 1, EIGRP 90, OSPF 110, RIP 120).
  • La route par défaut 0.0.0.0 0.0.0.0 permet d’acheminer tous les paquets vers Internet en l’absence de route plus spécifique.
  • Une route statique flottante possède une AD supérieure à la route normale pour s’activer uniquement en cas de panne.
  • Le supernetting agrège plusieurs sous-réseaux contigus en un préfixe résumé optimal pour réduire la taille des tables de routage.

Checklist de maîtrise

  • Je sais lire et expliquer chaque champ d’une sortie « show ip route » sous Cisco IOS.
  • J’applique sans hésitation l’algorithme Longest Prefix Match pour déterminer la route gagnante.
  • Je connais par cœur les distances administratives des principales sources de routage (0, 1, 90, 110, 120).
  • Je sais rédiger la commande exacte d’une route statique, d’une route par défaut et d’une route flottante.
  • Je sais calculer le masque agrégé d’un ensemble de sous-réseaux contigus (Supernetting).
