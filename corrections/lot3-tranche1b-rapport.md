## Constats et corrections

### Recherche opérationnelle B2

- Les titres des cas ne donnent plus le résultat des grilles 1 à 3. La grille 4 ne fournit plus les équations à recopier dans le texte de départ ; la grille 5 demande un champ de réponse structuré. Les indices ne révèlent plus la résolution particulière d’un cas. Sources : `server/exercises/RD-RO.js` et page générée `RD-RO/chapitres/chapitre1.html`.
- La question sur la réalisabilité pouvait aussi admettre un plan optimal ou dégénéré : elle demande désormais ce qui est nécessairement vrai. La question sur les variables binaires ne prétend plus qu’un domaine binaire est toujours non convexe ; les questions sur la non-négativité et l’objectif économique sont limitées au modèle étudié. Plusieurs explications ont été précisées : `server/content/RD-RO/chapitre1.js`.
- Les objectifs de deux grilles ont été recentrés sur ce qui est demandé aux apprenants. La relecture complète de l’enchaînement des prérequis, des exercices et du reste du chapitre reste à faire ; le cours reste « pas prêt ».

### Cybersécurité B2

- Les grilles de classification et de mot de passe distinguent le format de réponse des valeurs à déduire. Les situations d’incident précisent les faits observés ; l’absence d’information ne permet pas d’inférer une atteinte. Sources : `server/exercises/cyber-securite-b2/chapitre1.js` et `Cyber securite B2/chapitres/chapitre1.html`.
- La formule de score et ses seuils sont présentés comme un modèle pédagogique, et non comme une formule standard ISO ; la question correspondante le précise. Les explications des cinq QCM explicitent les distracteurs. La carte de révision a été régénérée.
- Les règles de longueur, de liste de refus, de points de code Unicode et d’absence de composition imposée ont été contrôlées dans la source primaire NIST SP 800-63B-4, section 3.1.1, consultée le 31 octobre 2026 : https://pages.nist.gov/800-63-4/sp800-63b.html. Cela ne valide pas tout le chapitre. La page ISO https://www.iso.org/standard/80585.html a renvoyé HTTP 403 à cette date : la norme complète n’a pas été consultée et son détail reste à vérifier.

### Formats et limites

Les anciens brouillons doivent être adaptés pour `ro2-c1-e3`, `ro2-c1-e5`, `cs2-c1-e2` et `cs2-c1-e3` : leurs formats de réponse ont changé. Les cas et le moteur de comparaison sont conservés. Une banque de mots ou une règle générale peut être nécessaire pour expliquer le format ; l’absence d’une chaîne complète dans un brief ne prouve pas l’absence d’indice donnant la réponse par déduction.

Les six alertes restantes sont `erp2-c1-e2`, `ib2-c1-e3`, `az3-c1-e1`, `cr3-c1-e1`, `cr3-c1-e2` et `cr3-c1-e3`. Elles résultent d’une comparaison mécanique et ne sont pas toutes des défauts confirmés ; les autres champs et les liens entre questions et réponses demandent aussi une lecture humaine. L’inventaire, ses limites et les empreintes des pages figurent dans `resultats/lot3-chapitre1-inventaire-tranche1b.json` ; celui de la tranche 1A est conservé séparément.

## Vérifications et limites

- `tests/grilles-chapitre1-lot3b.test.js` contrôle les champs transmis par `toClient()`, les attendus littéraux dans les briefs, starters et indices, ainsi que les 30 cas : corrigé accepté et deux sorties volontairement fausses rejetées. Ces sorties triviales ne démontrent ni la pertinence du barème ni la résistance à des erreurs plausibles.
- `tests/cyber-b2-lot2.test.js`, `tests/pedagogical-ro-chapitre1.test.js` et le nouveau test : 17 tests ciblés réussis. Le comparateur GitHub et la visibilité mobile/ordinateur des fiches suspendues ont été rejoués séparément : deux tests réussis ; cette visibilité navigateur ne couvre pas chaque exercice.
- `npm run courses:check` : 832 pages synchronisées, 64 cours générés. `npm run labs:check` : 1 250 ateliers synchronisés, 68 cours. Le vérificateur des preuves pré-lot 3 produit un inventaire identique pour les 289 fiches ; il ne constitue pas une nouvelle preuve pour les autres fiches.
- Suite isolée : 8 657 tests, 8 654 réussis, aucun échec, trois omissions liées à des sondes de confinement imbriqué. Build isolé : 1 446 fichiers, 936 pages avec injection ; le `dist/` local n’a pas été reconstruit. Journaux : `resultats/lot3-tranche1b-suite.txt.gz`, `resultats/lot3-tranche1b-build.txt.gz`.
- Les audits SQL et intégrité ne sont pas rejoués dans cette tranche : leur dernier résultat enregistré reste rouge (voir `lot3-tranche1a-rapport.md`). Les occurrences SQL brutes et fiches non évaluées ne sont pas assimilées à des défauts prouvés ; les faux positifs documentés restent séparés. Le défaut établi de généralisation du banc GitHub n’est pas corrigé ici.
- Pour `gh3-c1-e2`, le comparateur du site retire par défaut les espaces en fin de ligne ; les tests en mode `exact` font exception et conservent la distinction. Le test `tests/comparateur-github-lot3.test.js` confirme cette différence localement, pas le comportement d’un fournisseur distant.
- La piste de mutations et d’entrées aléatoires reste celle documentée dans la tranche 1A : trois fiches Python B1 couvertes, pas les 227 fiches à reprendre ; aucun changement de politique de notation dans cette tranche. Les 354 fiches de code précédemment suspendues restent suspendues dans les vérifications automatiques.
