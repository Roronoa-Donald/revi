Chapitre 1 — Fondamentaux C# et Écosystème .NET

Module 1 ≈ 2 h 45 de travail Accès libre
Mise en situation

Une équipe de développement refond le moteur d’un système bancaire haute fréquence sous .NET 8. Dans la version précédente, des millions de conversions implicites entre types primitifs et objets ont saturé le Garbage Collector, provoquant des micro-pauses inacceptables en production. L’équipe doit comprendre l’anatomie exacte de la mémoire CLR, distinguer la pile (Stack) du tas (Heap), éradiquer le boxing/unboxing inutile, maîtriser le passage d’arguments par référence (ref, out, in) et adopter le pattern matching moderne introduit dans les dernières versions du langage C#. Ce premier module pose les bases indispensables de l’ingénierie logicielle C# professionnelle.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. comprendre le cycle de compilation C# (Roslyn, CIL/MSIL, CLR et compilation JIT) ;
  2. distinguer la pile (Stack) du tas managé (Heap) et maîtriser les types valeur (struct) vs types référence (class) ;
  3. identifier et prévenir les opérations coûteuses de boxing et unboxing ;
  4. manipuler les modificateurs de paramètres de méthode : passage par valeur, ref, out et in ;
  5. exploiter le pattern matching moderne dans les expressions switch avec gardes conditionnels when.

1. L’Écosystème .NET & Le Common Language Runtime (CLR)

Le langage C# est compilé en deux étapes distinctes :

  1. Compilation statique (Roslyn) : Le code source C# est transformé par le compilateur Roslyn en un langage intermédiaire standardisé appelé CIL (Common Intermediate Language, anciennement MSIL), encapsulé dans un assemblage (binaire portable .dll ou .exe) accompagné de métadonnées riches.
  2. Exécution & Compilation JIT (CLR) : Lors de l’exécution, le Common Language Runtime (CLR) charge l’assemblage. Le compilateur JIT (Just-In-Time) traduit le code CIL à la volée en instructions machine natives adaptées à l’architecture matérielle cible (x86_64, ARM64).

Responsabilités de la CLR

  • Gestion de la mémoire : Allocation automatique et ramasse-miettes (Garbage Collector).
  • Sécurité des types : Vérification stricte des conversions et prévention des dépassements de mémoire tampon.
  • Gestion des exceptions : Routage structuré des erreurs à travers les blocs managés.
  • Orchestration des threads : ThreadPool managé pour la concurrence légère.

Avantages du modèle managé

  • Portabilité multiplateforme : Le même CIL s’exécute sur Linux, macOS et Windows sans recompilation.
  • Optimisations JIT dynamiques : Profiling en cours d’exécution (Tiered Compilation) et vectorisation SIMD native.

2. Système de Types : Pile (Stack) vs Tas (Heap)

En C#, tout type dérive directement ou indirectement de System.Object. Cependant, la gestion mémoire divise le système de types en deux familles fondamentales :

CaractéristiqueTypes Valeur (Value Types)Types Référence (Reference Types)
Définition C#struct, enum, primitifs (int, double, bool, char)class, interface, delegate, record, string, tableaux
Emplacement mémoireDirectement sur la Pile (Stack) (ou encapsulé dans un objet hôte)Sur le Tas managé (Heap) ; seule la référence (adresse) est sur la pile
Sémantique d’assignationCopie par valeur : la valeur brute est clonée bit à bitCopie par référence : seul le pointeur mémoire est dupliqué vers le même objet
Cycle de vieDétruit immédiatement à la sortie du scope d’exécution (désempilement ultra-rapide)Géré par le Garbage Collector (GC) selon les générations d’objets (Gen 0, 1, 2)
Support de nullNon nullable par défaut (sauf Nullable<T> ou int?)Nullable par défaut (supporte null)
Le piège de performance du Boxing / Unboxing

Le boxing se produit lorsqu’un type valeur est converti implicitement ou explicitement en un type référence (notamment object ou une interface). La CLR doit allouer un nouvel objet sur le tas, copier la valeur de la pile vers cet objet et renvoyer une référence.
L’unboxing extrait la valeur contenue dans cet objet vers la pile via un cast explicite (ex: (int)obj).
Règle d’or : Bannissez le boxing dans les boucles critiques en exploitant systématiquement les collections génériques typées (List<int> plutôt que ArrayList).

3. Passage d’Arguments de Méthode : val, ref, out & in

Par défaut, C# passe tous les arguments par valeur : une copie de la variable locale est transmise à la méthode. C# propose trois modificateurs avancés :

Le mot-clé ref

Passe une référence directe vers la variable de l’appelant. La variable doit être initialisée avant l’appel. Toute modification au sein de la méthode altère la variable d’origine.

void Incrementer(ref int x) {
    x += 1;
}

Le mot-clé out

Utilisé pour renvoyer des valeurs calculées. La variable n’a pas besoin d’être initialisée avant l’appel, mais la méthode a l’obligation absolue d’assigner une valeur avant de terminer.

bool Diviser(int a, int b, out int q) {
    if (b == 0) { q = 0; return false; }
    q = a / b;
    return true;
}

Le mot-clé in

Passe une référence en lecture seule. Idéal pour passer de grosses structures (struct volumineuses) sans le coût de copie, tout en interdisant toute mutation par la méthode.

double Distance(in Point3D p1, in Point3D p2) {
    // p1 et p2 ne peuvent pas être modifiés
}

4. Pattern Matching & Switch Expressions Modernes

Depuis C# 8, les instructions switch peuvent être exprimées sous forme d’expressions switch concises combinées avec un puissant moteur de filtrage par motif (pattern matching) :

string resultat = forme switch {
    Circle c when c.Radius > 10 => $"Grand cercle ({c.Radius})",
    Circle c => $"Petit cercle ({c.Radius})",
    Rectangle r when r.Width == r.Height => $"Carré de côté {r.Width}",
    Rectangle r => $"Rectangle {r.Width}x{r.Height}",
    _ => "Forme inconnue" // Discard par défaut
};

Cette syntaxe garantit :

  • L’exhaustivité des cas vérifiée par le compilateur (avertissement si une branche est omise) ;
  • L’intégration de conditions booléennes arbitraires via la clause when ;
  • L’extraction automatique (déconstruction) des variables typées sans cast manuel intermédiaire.

Exercice 1 — Détecteur de Boxing/Unboxing et allocation Stack vs Heap

Python Niveau 1 — Acquisition

Objectif : Analyser une suite d'instructions C# pour détecter les opérations de boxing/unboxing et localiser les données en mémoire.

Le script lit sur l'entrée standard une suite d'instructions C# séparées par des points-virgules de la forme Type variable = expression;.
Pour chaque affectation, il détermine : - Le nom de la variable et son type CLR ; - L'emplacement mémoire : Stack (types valeur : int, double, bool, char, float, long) ou Heap (types référence : string, object) ; - L'opération effectuée : ALLOCATION, BOXING (type valeur encapsulé dans object), UNBOXING (cast explicite d'object vers type valeur), ou COPIE_VALEUR / COPIE_REF.

Format de sortie :
<variable>: Type=<type> | Mem=<Stack|Heap> | Op=<Operation>

Entrée du programme
int a = 42; object o = a; int b = (int)o; string s = "test";
Sortie attendue
a: Type=int | Mem=Stack | Op=ALLOCATION
o: Type=object | Mem=Heap | Op=BOXING
b: Type=int | Mem=Stack | Op=UNBOXING
s: Type=string | Mem=Heap | Op=ALLOCATION

Allocation primitive, puis boxing vers object, unboxing vers int, et chaîne sur le Heap.

Deux indices, rédigés en mots
  1. Un cast de type (int)obj vers un type valeur constitue un UNBOXING.
  2. L'assignation d'une variable de type valeur à une variable de type object déclenche un BOXING.
  3. Les types valeur (int, double, bool...) vivent sur la pile (Stack), tandis que les objets et chaînes vivent sur le tas (Heap).

Exercice 2 — Passage d'arguments par valeur, référence (ref) et sortie (out)

Python Niveau 2 — Application

Objectif : Simuler l'exécution d'une méthode C# recevant des paramètres par valeur, ref et out.

Le script lit sur l'entrée standard 4 lignes décrivant l'appel d'une méthode C# :
- INIT <var1>=<val1>, <var2>=<val2>... : état initial des variables de l'appelant.
- METHOD <Nom>(<mod1> <p1>, <mod2> <p2>...) : signature (modificateurs : val, ref ou out).
- BODY <instr1>; <instr2>... : corps de la méthode (affectations arithmétiques).
- CALL <Nom>(<arg1>, [ref|out] <arg2>...) : instruction d'appel.
Le script doit simuler l'exécution et afficher l'état initial, la méthode exécutée et l'état final des variables après retour de la méthode (les variables passées par ref ou out voient leurs modifications propagées à l'appelant, contrairement au passage par valeur).

Format de sortie :
ETAT_INITIAL: a=<val>, b=<val>...
METHODE: <Nom>
ETAT_FINAL: a=<val>, b=<val>... (variables triées par ordre alphabétique)

Entrée du programme
INIT a=10, b=20, c=0
METHOD Modifier(val x, ref y, out z)
BODY x=x*2; y=y+50; z=x+y
CALL Modifier(a, ref b, out c)
Sortie attendue
ETAT_INITIAL: a=10, b=20, c=0
METHODE: Modifier
ETAT_FINAL: a=10, b=70, c=90

x reste local (a inchangé), b est modifié par ref, et c reçoit la valeur de sortie z.

Deux indices, rédigés en mots
  1. Les paramètres "val" reçoivent une copie locale qui ne modifie pas l'appelant.
  2. Les paramètres "ref" et "out" pointent vers la variable de l'appelant : toute modification locale doit être répercutée.
  3. Affiche les variables triées par ordre alphabétique sous le format nom=valeur.

Exercice 3 — Moteur de Pattern Matching et Switch Expressions C#

Python Niveau 3 — Raisonnement

Objectif : Évaluer une suite d'objets géométriques via une switch expression C# avec filtres conditionnels when.

Le script lit sur l'entrée standard une liste d'objets géométriques (une forme par ligne), par exemple Circle Radius=12 ou Rectangle Width=5 Height=5.
Il doit simuler l'évaluation d'une expression switch C# moderne :
- Circle c when c.Radius > 10 => GrandCercle (Aire = 3.14 * r * r) ;
- Circle c => PetitCercle (Aire = 3.14 * r * r) ;
- Rectangle r when r.Width == r.Height => Carre (Aire = w * h) ;
- Rectangle r => Rectangle (Aire = w * h) ;
- Discard _ => FormeNonSupportee (Aire = 0.00).

Format de sortie :
<DescriptionInitiale> => <Categorie> | Aire=<Valeur2Dec>

Entrée du programme
Circle Radius=12
Circle Radius=4
Rectangle Width=5 Height=5
Rectangle Width=8 Height=3
Triangle Base=4 Height=6
Sortie attendue
Circle (r=12) => GrandCercle | Aire=452.16
Circle (r=4) => PetitCercle | Aire=50.24
Rectangle (5x5) => Carre | Aire=25.00
Rectangle (8x3) => Rectangle | Aire=24.00
Triangle => FormeNonSupportee | Aire=0.00

Switch pattern matching avec filtre conditionnel when sur le rayon et égalité largeur/hauteur.

Deux indices, rédigés en mots
  1. Extrais le type et les propriétés clés-valeurs de chaque forme.
  2. Dans une switch expression C#, l'ordre des branches est crucial : les gardes "when" plus spécifiques doivent précéder les cas généraux.
  3. Formate les aires avec 2 décimales via :.2f.

6. QCM — niveau examen

Où est stockée en mémoire une variable déclarée comme "int x = 42;" à l’intérieur d’une méthode locale C# ?

Les types valeur primitifs (comme int) déclarés localement dans une méthode sont alloués directement sur la pile (Stack) et libérés immédiatement au désempilement du frame de la méthode.

Quelle instruction C# provoque une opération de Boxing ?

Le boxing a lieu lorsqu’une variable de type valeur (comme int) est affectée à un type référence comme object ou une interface. Une boîte objet est alors allouée sur le tas.

Quelle est l’obligation imposée par le compilateur C# pour un paramètre de méthode déclaré avec le mot-clé out ?

Avec le modificateur out, l’appelant n’a pas besoin d’initialiser la variable, mais la méthode appelée a l’obligation stricte de lui affecter une valeur avant de retourner (erreur CS0177 sinon).

Dans une switch expression C#, que représente le symbole de soulignement _ ?

Le symbole _ (discard pattern) fait office de branche par défaut dans une switch expression C#, équivalent au bloc default: d’une instruction switch classique.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre types valeur et types référence lors de l’assignation : copier une struct duplique ses données, copier une classe partage l’instance.
  • Provoquer du boxing involontaire en passant une variable primitive (int, bool) à une méthode attendant un object ou dans une concaténation non typée.
  • Oublier d’assigner tous les paramètres marqués out dans tous les chemins de code d’une méthode (erreur de compilation CS0177).
  • Ordonner incorrectement les branches d’une switch expression en plaçant un motif général avant un motif spécialisé avec clause when (code mort inatteignable).

8. Méthodologie de résolution

Protocole en 4 étapes pour optimiser la mémoire et les flux d’arguments en C#
  1. Classifier les types nécessaires : struct sur la pile pour les petits agrégats immuables (<= 16 octets), class pour les entités métier.
  2. Traquer et supprimer le boxing en privilégiant les types génériques et les conversions explicites typées.
  3. Choisir le modificateur de paramètre approprié : par valeur pour isoler, ref pour muter l’appelant, out pour renvoyer des résultats, in pour la lecture seule sans copie.
  4. Structurer la logique conditionnelle complexe avec des switch expressions et du pattern matching exhaustif avec gardes when.

9. Révision active

Résumé essentiel
  • Le code C# est compilé en CIL (Roslyn) puis exécuté et traduit en code machine natif par le JIT de la CLR.
  • Les types valeur (struct) résident sur la pile (Stack) ; les types référence (class) résident sur le tas (Heap).
  • Le boxing encapsule un type valeur dans un objet sur le tas ; l’unboxing extrait la valeur par cast explicite.
  • Les modificateurs ref et out permettent le passage par référence directe vers la variable de l’appelant.
  • Les expressions switch C# modernes permettent le filtrage par type, déconstruction et gardes conditionnels when.
