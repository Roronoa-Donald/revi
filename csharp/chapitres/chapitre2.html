Chapitre 2 — Encapsulation & Programmation Orientée Objet Moderne en C#

Module 2 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Une plateforme de commerce électronique souffre d’incohérences de données critiques en production : des soldes de clients deviennent négatifs suite à des accès directs aux champs de classe, et des objets partagés entre plusieurs threads sont mutés de façon imprévisible, corrompant les paniers d’achat. L’architecte logiciel exige une refactorisation immédiate vers les standards modernes de C# : encapsulation hermétique via des propriétés auto-implémentées validées, utilisation d’accesseurs init-only, harmonisation des constructeurs avec chaînage explicite, et adoption de records immuables manipulés par mutabilité non destructive (with). Ce module détaille la conception orientée objet robuste selon les idiomes .NET contemporains.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. concevoir des classes hermétiques respectant le principe d’encapsulation avec champs privés et accesseurs de propriété ;
  2. exploiter les propriétés auto-implémentées avec accesseurs différenciés (get public, set ou init privé) ;
  3. chaîner les constructeurs surchargés via l’initialiseur : this() pour éliminer la duplication de code d’initialisation ;
  4. comprendre les constructeurs primaires introduits dans les versions modernes de C# ;
  5. maîtriser les records C#, l’égalité structurelle par valeur et le clonage non destructif avec l’expression with.

1. Encapsulation & Propriétés C# Auto-implémentées

L’encapsulation est le pilier fondamental de la POO qui consiste à masquer l’état interne d’un objet et à n’exposer que des interfaces de contrôle strictes. En C#, on ne déclare jamais de champs publics (fields) : on expose des propriétés (properties).

Propriété classique avec champ de soutien (Backing Field)

public class Compte {
    private decimal _solde;
    public decimal Solde {
        get => _solde;
        set {
            if (value < 0) throw new ArgumentOutOfRangeException("Solde négatif refusé");
            _solde = value;
        }
    }
}

Propriété auto-implémentée moderne

public class Utilisateur {
    // Le compilateur génère le champ privé en coulisses
    public string Id { get; init; }
    public string Nom { get; set; }
    public decimal Score { get; private set; } = 100m;
}
L’accesseur init (C# 9+)

L’accesseur init autorise la modification de la propriété uniquement lors de l’instanciation de l’objet (dans le constructeur ou via un initialiseur d’objet new Utilisateur { Id = "U1" }). Une fois l’objet créé, la propriété devient strictement en lecture seule, garantissant une immuabilité absolue sans boilerplate.

2. Constructeurs, Chaînage : this() & Constructeurs Primaires

Lorsqu’une classe offre plusieurs constructeurs pour s’adapter à différents scénarios d’initialisation, la duplication de logique doit être évitée en déléguant au constructeur le plus complet grâce à l’instruction : this(...) :

public class Produit {
    public string Reference { get; }
    public string Libelle { get; }
    public decimal Prix { get; }

    // Constructeur 1 : référence seule
    public Produit(string reference) : this(reference, "Non renseigné", 0.0m) {}

    // Constructeur 2 : référence et libellé
    public Produit(string reference, string libelle) : this(reference, libelle, 0.0m) {}

    // Constructeur principal : logique d’assignation unique
    public Produit(string reference, string libelle, decimal prix) {
        Reference = reference ?? throw new ArgumentNullException(nameof(reference));
        Libelle = libelle;
        Prix = prix;
    }
}

Depuis C# 12, les constructeurs primaires (Primary Constructors) permettent de déclarer les paramètres d’initialisation directement sur la ligne de déclaration de la classe :

public class ServiceClient(string apiUrl, int timeoutSecondes = 30) {
    public void Appeler() => Console.WriteLine($"Appel {apiUrl} avec timeout {timeoutSecondes}s");
}

3. Records C# & Mutabilité Non Destructive (with)

Introduits en C# 9, les records (record class ou record struct) sont des types conçus spécifiquement pour encapsuler des données immuables. Ils se distinguent des classes classiques par deux caractéristiques majeures :

1. Égalité structurelle par valeur

Deux instances d’un record possédant les mêmes valeurs pour toutes leurs propriétés sont considérées comme égales (Equals et opérateur == renvoient true), même si elles occupent deux adresses mémoires distinctes sur le tas.

2. Clonage non destructif avec with

L’expression with crée une copie superficielle (shallow copy) de l’instance tout en modifiant de façon ciblée une ou plusieurs propriétés spécifiées, préservant ainsi l’objet d’origine.

// Déclaration positionnelle ultra-concise
public record Commande(string Id, string Client, decimal Montant, string Statut);

var c1 = new Commande("CMD-01", "Alice", 120.0m, "EnAttente");
// Clonage non destructif : c1 reste inchangé, c2 reçoit le nouveau statut
var c2 = c1 with { Statut = "Expédiée" };

var c3 = new Commande("CMD-01", "Alice", 120.0m, "EnAttente");
Console.WriteLine(c1 == c3); // Affiche "True" (égalité par valeur native)

Exercice 3 — Records C# 9+ et mutabilité non destructive (with)

C# Niveau 3 — Raisonnement

Objectif : Simuler le comportement des records immuables C# et la création de copies via l'expression with.

Votre programme C# lit les données sur l’entrée standard (Console.In)... : création d'un record immuable ;
- WITH <nouveau_nom> FROM <nom_source> <propModif>=<valModif>... : clonage non destructif avec l'expression C# with { ... } ;
- COMPARE <record1> <record2> : comparaison d'égalité structurelle (value-based equality native des records C#).
Le script Indiquez la création, la copie non destructive et le résultat des comparaisons.

Format de sortie :
CREATE: <nom> => Record { <k1> = <v1>, ... }
WITH: <nom> => Record { <k1> = <v1>, ... }
EQUALS: <r1> == <r2> => True|False [ (Egalite structurelle)]

Entrée du programme
RECORD u1 Id=U101 Email=alice@corp.com Role=Lecteur
WITH u2 FROM u1 Role=Admin
RECORD u3 Id=U101 Email=alice@corp.com Role=Lecteur
COMPARE u1 u2
COMPARE u1 u3
Sortie attendue
CREATE: u1 => Record { Id = U101, Email = alice@corp.com, Role = Lecteur }
WITH: u2 => Record { Id = U101, Email = alice@corp.com, Role = Admin }
CREATE: u3 => Record { Id = U101, Email = alice@corp.com, Role = Lecteur }
EQUALS: u1 == u2 => False
EQUALS: u1 == u3 => True (Egalite structurelle)

Clonage avec with préservant l'immuabilité et égalité structurelle entre u1 et u3.

Trois indices, rédigés en mots
  1. Un record C# possède une égalité par valeur automatique (égalité structurelle de toutes les propriétés).
  2. L'expression with copie toutes les propriétés du record source puis écrase celles spécifiées.
  3. Affichez "(Egalite structurelle)" lorsque deux records distincts possèdent les mêmes valeurs.

5. QCM — niveau examen

Quel est l’effet de l’accesseur "init" sur une propriété C# ?

L’accesseur init (C# 9) permet la mutation lors de la phase d’initialisation (constructeur ou syntaxes d’initialiseur new T { Prop = val }), puis verrouille la propriété en lecture seule.

Comment appelle-t-on un constructeur frère au sein de la même classe en C# ?

En C#, le chaînage vers un autre constructeur de la même classe s’effectue via la clause d’initialisation : this(arguments) placée entre la signature et le corps du constructeur.

Quelle est la différence fondamentale entre deux instances de class et deux instances de record ayant des propriétés identiques ?

Les records C# implémentent automatiquement l’égalité structurelle basée sur la valeur de leurs propriétés, tandis que les classes ordinaires appliquent l’égalité de référence (identité mémoire).

À quoi sert l’expression "with" appliquée sur un record C# ?

L’expression with réalise un clonage non destructif : elle produit une nouvelle instance du record avec les mêmes valeurs que l’original, sauf pour les propriétés expressément réassignées dans le bloc with.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Exposer des champs publics directs (public string Nom;) au lieu de propriétés (public string Nom { get; set; }), empêchant tout contrôle futur sur les mutations.
  • Tenter de modifier une propriété possédant un accesseur init après la fin du bloc d’initialisation (erreur de compilation CS8852).
  • Créer des boucles infinies de chaînage de constructeurs (ctor A appelle ctor B qui rappelle ctor A).
  • Confondre l’égalité de référence (classes standard où deux new donnent deux objets différents) et l’égalité de valeur des records C#.

7. Méthodologie de résolution

Protocole en 4 étapes pour concevoir une classe ou un record C# robuste
  1. Masquer totalement l’état interne de la classe en interdisant les champs publics.
  2. Définir des propriétés auto-implémentées avec les accesseurs les plus restreints possibles (private set ou init).
  3. Centraliser l’initialisation dans un constructeur principal et chaîner les surcharges via : this().
  4. Utiliser des records (record class ou record struct) pour les conteneurs de données immuables et le clonage avec with.

8. Révision active

Résumé essentiel
  • L’encapsulation protège l’état interne des objets en exposant uniquement des propriétés contrôlées.
  • L’accesseur init (C# 9+) verrouille la propriété en lecture seule immédiatement après l’instanciation.
  • Le chaînage de constructeurs : this(...) élimine la duplication de code d’initialisation entre surcharges.
  • Les constructeurs primaires (C# 12) simplifient la déclaration des dépendances directement sur la classe.
  • Les records C# fournissent l’égalité structurelle par valeur native et le clonage non destructif via l’expression with.
