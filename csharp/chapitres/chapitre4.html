Chapitre 4 — Collections Génériques & Gestion Avancée des Exceptions

Module 4 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Un service de microservices bancaires rencontre de multiples incidents d’interruption de service en production : des exceptions non interceptées provoquent l’effondrement de processus entiers suite à des recherches sur des clés absentes dans des tables de hachage, des ressources mémoire restent verrouillées à cause de blocs finally manquants, et des conteneurs non typés obligent à des conversions de types hasardeuses sources de plantages au runtime. L’équipe doit standardiser l’usage des collections génériques de haute performance (List<T>, Dictionary<TKey, TValue>, HashSet<T>), sécuriser les accès aux dictionnaires via TryGetValue, structurer un pipeline de traitement d’exceptions infaillible avec filtres conditionnels when et bloc finally, et verrouiller les types avec des contraintes génériques strictes (where T). Ce chapitre dote les développeurs d’outils fondamentaux de résilience logicielle.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. choisir la collection générique optimale (List, Dictionary, HashSet) selon les complexités algorithmiques O(1) vs O(n) ;
  2. sécuriser les accès aux dictionnaires via la méthode TryGetValue pour éliminer les KeyNotFoundException ;
  3. structurer des blocs try/catch/finally garantissant la libération des ressources critiques ;
  4. filtrer sélectivement les exceptions à la volée grâce aux clauses catch when ;
  5. déclarer des classes et méthodes génériques contraintes par la clause where T (class, struct, new(), interfaces).

1. Collections Génériques : List<T>, Dictionary<TKey, TValue> & HashSet<T>

L’introduction des génériques dans le framework .NET a révolutionné la manipulation de données en apportant un typage strict à la compilation, éliminant tout coût de boxing pour les types valeur et prévenant les erreurs de cast au runtime :

CollectionStructure sous-jacenteRecherche par clé/valeurUsage recommandé
List<T>Tableau dynamique indexéO(1) par index, O(n) par valeurListes séquentielles ordonnées avec accès par position
Dictionary<TKey, TValue>Table de hachage associativeO(1) en moyenne par cléAssociations clé-valeur avec recherche ultra-rapide
HashSet<T>Table de hachage d’éléments uniquesO(1) en moyenne (Contains)Ensembles mathématiques, déduplication et tests d’appartenance
Sécurisation des accès aux dictionnaires : TryGetValue

L’accès direct par indexeur dict[cle] est une cause majeure de plantage d’application : si la clé est absente, la CLR lève immédiatement une KeyNotFoundException.
La méthode TryGetValue(cle, out var valeur) teste l’existence et extrait la valeur en une seule opération de hachage sans jamais lever d’exception :

if (dictionnaire.TryGetValue("ServeurBD", out int port)) {
    Console.WriteLine($"Port trouvé : {port}");
} else {
    Console.WriteLine("Clé absente : valeur par défaut 0 assignée sans crash.");
}

2. Gestion Robuste des Exceptions & Filtres catch ... when

La gestion des erreurs en C# repose sur la hiérarchie System.Exception. Depuis C# 6, les blocs catch peuvent être filtrés avec une clause conditionnelle when :

try {
    EffectuerRequeteReseau();
} catch (HttpException ex) when (ex.StatusCode == 404) {
    // Ne capture QUE les erreurs HTTP 404 (Ressource introuvable)
    JournaliserAlerte("Ressource manquante", ex);
} catch (HttpException ex) when (ex.StatusCode >= 500) {
    // Capture sélectivement les pannes d’infrastructure serveur
    DeclencherBasculementSecours();
} catch (Exception ex) {
    // Filet de capture générique final
    JournaliserCrashInattendu(ex);
} finally {
    // Exécuté dans TOUS les cas (succès ou échec)
    FermerConnexionsActives();
}

Avantage déterminant de la clause when : contrairement à un if placé à l’intérieur du bloc catch, la clause when évalue la condition sans dépiler la pile d’appels (Stack Unwinding). Les informations de débogage restent intactes si l’exception est propagée plus haut.

3. Contraintes de Généricité : La Clause where T

Par défaut, un paramètre de type générique T est totalement libre (équivalent à object). Les contraintes de généricité permettent de restreindre les capacités de T pour lui appliquer des règles spécifiques :

ContrainteSignificationExemple d’utilisation
where T : classT doit obligatoirement être un type référenceGestionnaires d’entités, caches d’objets
where T : structT doit obligatoirement être un type valeurCalculateurs mathématiques sans allocation tas
where T : new()T doit posséder un constructeur public sans argumentFabriques d’objets génériques (new T())
where T : IComparable<T>T doit implémenter l’interface de comparaisonAlgorithmes de tri et arbres binaires
where T : BaseClassT doit dériver obligatoirement de la classe spécifiéeRéférentiels d’accès aux données d’entités

Exercice 1 — Collections génériques C# et recherche sécurisée TryGetValue

Étude de cas Niveau 1 — Acquisition

Objectif : Manipuler un Dictionary<TKey, TValue> C# et comparer l'indexeur direct avec la méthode TryGetValue.

Le script gère un dictionnaire générique C# Dictionary<string, int>.
Il lit dans l’énoncé du cas des instructions :
- ADD <Cle> <Valeur> : insère ou met à jour la valeur et Indiquez la nouvelle taille ;
- GET <Cle> : accès par indexeur direct dict[cle]. Si la clé existe, Indiquez sa valeur ; sinon, lève une exception CRASH KeyNotFoundException (Cle absente du dictionnaire) ;
- TRYGET <Cle> : accès sécurisé via dict.TryGetValue(cle, out int val). Indiquez Trouve: <val> ou NonTrouve (out val=0) sans lever d'exception.

Format de sortie :
ADD: <Cle> => <Valeur> (Taille=<N>)
GET: <Cle> => <Valeur> ou GET: <Cle> => CRASH KeyNotFoundException (Cle absente du dictionnaire)
TRYGET: <Cle> => Trouve: <Valeur> ou TRYGET: <Cle> => NonTrouve (out val=0)

Cas d’exemple
ADD ServeurWeb 80
ADD ServeurSSH 22
GET ServeurWeb
TRYGET ServeurBD
GET ServeurBD
Résolution attendue
ADD: ServeurWeb => 80 (Taille=1)
ADD: ServeurSSH => 22 (Taille=2)
GET: ServeurWeb => 80
TRYGET: ServeurBD => NonTrouve (out val=0)
GET: ServeurBD => CRASH KeyNotFoundException (Cle absente du dictionnaire)

Démonstration de TryGetValue qui protège contre le crash de l'indexeur sur une clé absente.

Deux indices, rédigés en mots
  1. L'indexeur C# dictionnaire[cle] lève KeyNotFoundException si la clé est absente.
  2. La méthode TryGetValue renvoie false et initialise la variable out à sa valeur par défaut (0 pour int).
  3. ADD met à jour la valeur si la clé existe déjà, tout en incrémentant la taille seulement si c'est une nouvelle clé.

Exercice 2 — Gestion des exceptions avec filtres catch ... when

Étude de cas Niveau 2 — Application

Objectif : Simuler le routage d'exceptions C# grâce aux filtres de clause catch when et garantir l'exécution de finally.

En C# 6+, les blocs catch peuvent être filtrés avec une clause when (condition) :
1. catch (HttpException ex) when (ex.StatusCode == 404) => [ClientError] ;
2. catch (HttpException ex) when (ex.StatusCode >= 500) => [ServerError] ;
3. catch (TimeoutException) => [DelaiDepasse] ;
4. catch (Exception) => [FallbackGlobal].
Dans tous les cas, le bloc finally est inconditionnellement exécuté (| FINALLY execute).

Format de sortie :
Exception: <Type> (<Code>) => Intercepte par: <ClauseCatch> <Tag> | FINALLY execute

Cas d’exemple
THROW HttpException StatusCode=404
THROW HttpException StatusCode=503
THROW TimeoutException StatusCode=408
THROW HttpException StatusCode=401
Résolution attendue
Exception: HttpException (404) => Intercepte par: catch when (StatusCode == 404) [ClientError] | FINALLY execute
Exception: HttpException (503) => Intercepte par: catch when (StatusCode >= 500) [ServerError] | FINALLY execute
Exception: TimeoutException (408) => Intercepte par: catch (TimeoutException) [DelaiDepasse] | FINALLY execute

Démonstration du routage conditionnel d'exceptions en C# via when.

Deux indices, rédigés en mots
  1. Évalue les conditions dans l'ordre d'apparition des blocs catch.
  2. Les clauses when permettent de capturer sélectivement selon l'état interne de l'exception (ex: StatusCode).
  3. Le bloc finally s'exécute toujours, que l'exception ait été levée, interceptée ou non.

Exercice 3 — Validateur de contraintes génériques (where T : ...)

Étude de cas Niveau 3 — Raisonnement

Objectif : Vérifier la conformité de types candidats aux contraintes génériques d'une classe ou méthode C#.

En C#, les contraintes génériques (where T : ...) restreignent les types pouvant instancier une classe ou méthode :
- class : le type doit être un type référence (IsClass=True) ;
- struct : le type doit être un type valeur non nullable (IsClass=False) ;
- new() : le type doit avoir un constructeur public sans paramètre (HasDefaultCtor=True) ;
- IComparable : le type doit implémenter l'interface de comparaison (ImplementsComparable=True).

Il doit évaluer chaque type et afficher sa validation ou la liste des violations constatées.

Format de sortie :

Type <Nom>: REJETE [Violation: <Motif1>, ...]

Cas d’exemple

Candidate Nom=Client IsClass=True HasDefaultCtor=True ImplementsComparable=True
Candidate Nom=Int32 IsClass=False HasDefaultCtor=True ImplementsComparable=True

5. QCM — niveau examen

Pourquoi la méthode dict.TryGetValue(cle, out var val) est-elle préférée à l’indexeur direct dict[cle] ?

TryGetValue évite le coût élevé de la levée d’exception KeyNotFoundException sur les clés absentes et évite le double hachage qu’imposerait un if (dict.ContainsKey(k)) { v = dict[k]; }.

Quel est l’intérêt de la clause catch (Exception ex) when (condition) introduite en C# 6 ?

La clause when permet de n’intercepter l’exception que si la condition est vérifiée, préservant la stack trace intacte si l’exception doit être traitée par un bloc englobant supérieur.

Que garantit la contrainte générique "where T : new()" sur une classe Repository ?

La contrainte new() indique au compilateur que le type T dispose d’un constructeur public par défaut sans argument, autorisant le code interne à créer des instances avec new T().

Dans un bloc try/catch/finally, quand le bloc finally est-il exécuté ?

Le bloc finally est garanti d’être exécuté systématiquement, qu’une exception ait été levée, interceptée, propagée, ou qu’un return anticipe la fin de la méthode.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Utiliser l’indexeur direct dict[cle] sans certitude préalable de l’existence de la clé, provoquant des KeyNotFoundException intempestives.
  • Capturer System.Exception sans la relancer (catch vide) et étouffer silencieusement des erreurs critiques d’exécution.
  • Faire "throw ex;" au lieu de "throw;" dans un bloc catch, ce qui détruit la trace de pile d’origine (stack trace) et complique le diagnostic.
  • Omettre le bloc finally ou l’instruction using sur des flux ouverts, provoquant des fuites de descripteurs de fichiers sous charge.

7. Méthodologie de résolution

Protocole en 4 étapes pour sécuriser les collections et le flux d’exceptions
  1. Choisir la collection générique adaptée à la complexité visée : Dictionary pour O(1) par clé, List pour la séquence, HashSet pour l’unicité.
  2. Remplacer systématiquement les indexeurs directs à risque par dict.TryGetValue(cle, out var val).
  3. Capturer sélectivement les exceptions applicatives avec des clauses catch when filtrant sur l’état interne de l’erreur.
  4. Sécuriser systématiquement la fermeture des fichiers et connexions dans un bloc finally inconditionnel.

8. Révision active

Résumé essentiel
  • Les collections génériques System.Collections.Generic garantissent le typage fort sans boxing.
  • TryGetValue est la méthode idiomatique pour interroger un Dictionary sans risque de KeyNotFoundException.
