Chapitre 5 — LINQ, Délégués & Système Événementiel

Module 5 ≈ 2 h 45 de travail Réservé B2 et plus
Mise en situation

Une application de gestion logistique traite des flux volumineux de bordereaux de livraison avec des boucles imbriquées manuelles (for et foreach). Le code est illisible, sujet à des erreurs de bornes et recalcule les mêmes filtres à chaque itération. De plus, les notifications d’état de livraison sont couplées de façon rigide aux composants d’interface utilisateur. L’équipe doit moderniser son socle : exploiter la programmation fonctionnelle en C# grâce aux délégués (Func, Action) et lambdas, migrer le filtrage et l’agrégation de collections vers la puissance déclarative de LINQ tout en comprenant l’exécution différée, et découpler l’architecture logicielle grâce aux événements multicast C# (events avec += et -=). Ce module transforme la manipulation des collections en un modèle élégant, expressif et découplé.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. maîtriser les types délégués prédéfinis du framework : Action (sans retour), Func (avec retour) et Predicate (booléen) ;
  2. écrire des expressions lambdas concises et comprendre la capture de variables locales (fermetures ou closures) ;
  3. chaîner les opérateurs LINQ Fluent API (Where, Select, OrderByDescending, GroupBy, Sum, Average) ;
  4. distinguer l’évaluation différée (Deferred Execution) de l’évaluation terminale immédiate (ToList, ToArray, Count) ;
  5. implémenter le patron Observateur via le mot-clé event avec inscription (+=) et désinscription (-=).

1. Délégués Prédéfinis & Expressions Lambdas

Un délégué (delegate) en C# est un pointeur de fonction managé, sécurisé et typé. Plutôt que de déclarer des types délégués personnalisés, le framework .NET fournit trois familles génériques universelles :

DéléguéSignatureType de retourUsage typique
Action<T1, T2, ...>Prend de 0 à 16 paramètresvoid (aucun retour)Journalisation, notifications, effets de bord
Func<T1, ..., TResult>Prend de 0 à 16 paramètresTResult (dernier type spécifié)Transformations, projections de données, calculs
Predicate<T>Prend exactement 1 paramètre de type TboolConditions de filtrage et critères de sélection

Les expressions lambdas fournissent une syntaxe concise pour instancier ces délégués :

// Délégué Func prenant un entier et renvoyant son carré
Func<int, int> carre = x => x * x;

// Délégué Action affichant un message formaté
Action<string, decimal> afficherPrix = (produit, prix) => Console.WriteLine($"{produit} : {prix:F2} €");

// Predicate testant si un nombre est pair
Predicate<int> estPair = n => n % 2 == 0;

2. LINQ Fluent API & Le Principe d’Exécution Différée

LINQ (Language Integrated Query) unifie les requêtes sur les collections en mémoire (LINQ to Objects), les bases de données (LINQ to Entities) et les flux XML/JSON. Il s’appuie sur des méthodes d’extension opérant sur IEnumerable<T> :

Opérateurs d’évaluation différée (Lazy)

Ne calculent rien lors de la déclaration ! La requête est simplement une recette d’exécution qui ne s’évalue qu’à l’itération (ex: foreach) :

  • .Where(p => p.Actif) : filtre les éléments
  • .Select(p => p.Nom) : projette et transforme
  • .OrderByDescending(p => p.Prix) : trie
  • .GroupBy(p => p.Categorie) : regroupe

Opérateurs terminaux (Immédiats)

Provoquent immédiatement l’exécution complète de la requête et matérialisent le résultat en mémoire :

  • .ToList() / .ToArray() : produit une collection
  • .First() / .FirstOrDefault() : extrait un élément
  • .Count(), .Sum(), .Average() : agrège
  • .Any() / .All() : quantificateurs booléens
Le piège de la multiple énumération

Si vous itérez deux fois sur une requête LINQ différée sans avoir appelé ToList(), l’intégralité de la chaîne d’opérations (et potentiellement la requête SQL en base de données) est exécutée deux fois ! Matérialisez toujours avec ToList() si le résultat doit être consommé plusieurs fois.

3. Système Événementiel C# : Le Mot-clé event & Délégués Multicast

Le mot-clé event encapsule un délégué en appliquant le patron de conception Observateur. Il garantit que les consommateurs extérieurs peuvent uniquement s’abonner (+=) ou se désabonner (-=), sans jamais pouvoir écraser la liste des abonnés ni déclencher l’événement à la place de l’émetteur :

public class MoniteurServeur {
    // Déclaration de l'événement basé sur Action
    public event Action<string>? AlerteDeclenchee;

    public void EmettreAlerte(string message) {
        // Invocation sécurisée avec l'opérateur null-conditionnel (?.)
        AlerteDeclenchee?.Invoke(message);
    }
}

var moniteur = new MoniteurServeur();
// Abonnement via +=
moniteur.AlerteDeclenchee += msg => Console.WriteLine($"[Audit] {msg}");
moniteur.AlerteDeclenchee += msg => Console.WriteLine($"[SMS] Notification {msg}");

moniteur.EmettreAlerte("Surchauffe processeur 85°C");
// Les deux abonnés sont appelés successivement dans l'ordre d'inscription.

Exercice 1 — Moteur LINQ de base : Where, Select, OrderBy et exécution différée

Python Niveau 1 — Acquisition

Objectif : Simuler une requête LINQ avec Where, OrderBy, Select et matérialisation terminale ToList().

En C#, les requêtes LINQ bénéficient de l'exécution différée (Deferred Execution) : aucun calcul n'a lieu avant l'appel d'un opérateur terminal tel que ToList().
Le script lit une première ligne spécifiant le seuil de filtrage (ex: FILTER Prix >= 20.0) suivi d'articles sous la forme Article Nom=<Nom> Prix=<Prix>.
Le script simule l'évaluation du pipeline LINQ suivant :
1. .Where(a => a.Prix >= seuil) ;
2. .OrderByDescending(a => a.Prix) ;
3. .Select(a => $"{a.Nom} - {a.Prix:F2}").
Il affiche la matérialisation terminale et chaque élément sélectionné.

Format de sortie :
LINQ: Declenchement ToList() (Evaluation differee terminee)
Resultat: <Nom> - <Prix2Dec>
TOTAL_ELEMENTS: <N>

Entrée du programme
FILTER Prix >= 20.0
Article Nom=Clavier Prix=45.0
Article Nom=Souris Prix=15.0
Article Nom=Ecran Prix=180.0
Article Nom=Tapis Prix=10.0
Sortie attendue
LINQ: Declenchement ToList() (Evaluation differee terminee)
Resultat: Ecran - 180.00
Resultat: Clavier - 45.00
TOTAL_ELEMENTS: 2

Seuls Ecran et Clavier dépassent le seuil de 20.0 et sont triés par ordre décroissant.

Deux indices, rédigés en mots
  1. Extrais le seuil de prix de la première ligne.
  2. Filtre les articles dont le prix est supérieur ou égal au seuil.
  3. Trie les articles filtrés par ordre décroissant de prix avant l'affichage.

Exercice 2 — Pipeline LINQ de regroupement GroupBy et agrégations

Python Niveau 2 — Application

Objectif : Regrouper un jeu de données avec LINQ GroupBy et calculer le total et la moyenne par groupe.

Le script lit sur l'entrée standard une liste d'achats au format <Client> <Categorie> <Montant>.
Il doit simuler l'opérateur LINQ GroupBy(a => a.Categorie) et calculer pour chaque catégorie : - Le nombre total d'achats (Count()) ; - La somme totale dépensée (Sum(a => a.Montant)) ; - La moyenne par achat (Average(a => a.Montant)).
Les catégories doivent être présentées par ordre alphabétique croissant.

Format de sortie :
Groupe: <Categorie> | NbAchats: <N> | Total: <Total2Dec> | Moyenne: <Moyenne2Dec>

Entrée du programme
Alice Informatique 120.0
Bob Mobilier 300.0
Alice Informatique 80.0
Charlie Informatique 50.0
Bob Mobilier 150.0
Sortie attendue
Groupe: Informatique | NbAchats: 3 | Total: 250.00 | Moyenne: 83.33
Groupe: Mobilier | NbAchats: 2 | Total: 450.00 | Moyenne: 225.00

Regroupement en deux catégories avec calculs d'agrégation exacts.

Deux indices, rédigés en mots
  1. Stocke les montants dans une liste associée à chaque catégorie.
  2. Calcule la somme et divise par le nombre d'éléments pour obtenir la moyenne.
  3. Trie les noms de catégories par ordre alphabétique croissant.

Exercice 3 — Système Événementiel C# (event Action<string>, +=, -= multicast)

Python Niveau 3 — Raisonnement

Objectif : Simuler un délégué multicast C# avec inscription +=, désinscription -= et diffusion d'événement.

En C#, un événement public event Action<string> OnNotification; permet à plusieurs gestionnaires de s'abonner avec l'opérateur += et de se désabonner avec -=.
Le script lit sur l'entrée standard des instructions séquentielles :
- SUBSCRIBE <NomAbonne> : ajoute l'abonné à la liste des récepteurs actifs ;
- UNSUBSCRIBE <NomAbonne> : retire l'abonné s'il est présent ;
- EMIT "<Message>" : diffuse l'événement à tous les abonnés enregistrés à cet instant, dans l'ordre d'abonnement.

Format de sortie pour chaque émission :
EVENT "<Message>" => <NomAbonne> recoit la notification

Entrée du programme
SUBSCRIBE Logger
SUBSCRIBE EmailService
EMIT "Incident Detecte"
UNSUBSCRIBE EmailService
SUBSCRIBE SmsAlerte
EMIT "Serveur Redemarre"
Sortie attendue
EVENT "Incident Detecte" => Logger recoit la notification
EVENT "Incident Detecte" => EmailService recoit la notification
EVENT "Serveur Redemarre" => Logger recoit la notification
EVENT "Serveur Redemarre" => SmsAlerte recoit la notification

EmailService reçoit la première alerte mais pas la seconde après désinscription.

Deux indices, rédigés en mots
  1. Maintiens une liste d'abonnés actifs dans l'ordre d'ajout.
  2. Lors d'un UNSUBSCRIBE, supprime le nom de la liste.
  3. Lors d'un EMIT, itère sur tous les abonnés actifs pour afficher la notification.

5. QCM — niveau examen

Quelle est la signature du délégué Func ?

Dans un délégué Func, le dernier argument de type spécifié correspond toujours au type de retour. Ainsi, Func prend une string et un int et renvoie un booléen.

Que signifie le concept d’exécution différée (Deferred Execution) dans une requête LINQ ?

En LINQ, les opérateurs de transformation comme Where et Select construisent un itérateur différé : aucun traitement n’a lieu tant qu’un consommateur n’itère pas sur la séquence (via foreach, ToList, etc.).

Quelle méthode LINQ force la matérialisation immédiate en mémoire d’une séquence différée ?

.ToList() est un opérateur terminal qui parcourt immédiatement l’intégralité de la séquence et stocke tous les éléments dans une nouvelle instance de List en mémoire.

Pourquoi le mot-clé event est-il préférable à un délégué public simple pour notifier des abonnés ?

Le mot-clé event restreint l’accès extérieur aux seuls opérateurs d’abonnement (+=) et désabonnement (-=). Seule la classe déclarante a le droit d’invoquer ou de réassigner le délégué sous-jacent.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre Func (prend un int et renvoie une string) avec Action (prend un int et une string sans rien renvoyer).
  • Réévaluer involontairement une requête LINQ lourde plusieurs fois en oubliant de la matérialiser avec ToList().
  • Déclencher un événement sans vérifier s’il possède des abonnés, provoquant une NullReferenceException (utiliser systématiquement monEvent?.Invoke(...)).
  • Oublier de se désabonner d’un événement avec -= lors de la destruction d’un composant, provoquant des fuites mémoire car l’émetteur conserve une référence forte vers l’abonné.

7. Méthodologie de résolution

Protocole en 4 étapes pour manipuler les données avec LINQ et les événements
  1. Définir le flux avec les délégués standard : Func pour transformer, Predicate pour filtrer, Action pour notifier.
  2. Chaîner les méthodes d’extension LINQ de façon déclarative (Where, Select, OrderBy, GroupBy).
  3. Identifier précisément le point de matérialisation terminale avec ToList() pour éviter les ré-énumérations multiples.
  4. Encapsuler les notifications dans un mot-clé event et invoquer avec l’opérateur null-conditionnel (?.).

8. Révision active

Résumé essentiel
  • Action (void) et Func (retour typé) éliminent le besoin de déclarer des délégués personnalisés.
  • LINQ s’appuie sur des méthodes d’extension appliquées sur IEnumerable.
  • L’exécution différée (Deferred Execution) retarde le calcul jusqu’à l’itération effective.
  • Les opérateurs terminaux (ToList, ToArray, Count) forcent l’évaluation immédiate en mémoire.
  • Le mot-clé event protège le délégué contre les écrasements et applique le pattern Observateur avec += et -=.
