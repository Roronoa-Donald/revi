Mémento des Commandes, Architectures & Directives Docker

Guide de référence rapide : primitives noyau Linux, cycle de vie des conteneurs, directives Dockerfile clés, syntaxe Compose et bonnes pratiques de sécurité en production.

1. Primitives d’Isolation du Noyau Linux

MécanismeType de primitiveRôle et Périmètre isolé
PID NamespaceNamespaceIsole l’arborescence des processus : le conteneur dispose de son propre PID 1 sans voir l’hôte.
NET NamespaceNamespaceIsole les interfaces réseau (eth0), tables de routage et ports d’écoute.
MNT NamespaceNamespaceIsole les points de montage et la racine du système de fichiers (chroot avancé).
IPC NamespaceNamespaceIsole les communications inter-processus (mémoire partagée POSIX, sémaphores).
UTS NamespaceNamespaceIsole le nom d’hôte (hostname) et le nom de domaine NIS du conteneur.
USER NamespaceNamespaceMappe l’UID 0 (root dans le conteneur) vers un UID standard non-privilégié sur la machine hôte.
Cgroups (v1/v2)Control GroupsLimite et comptabilise la consommation des ressources matérielles (CPU, RAM, E/S disques).

2. Commandes Essentielles du Cycle de Vie

Commande CLIAction effectuéeImpact sur le conteneur
docker run -d -p 80:80 --name web nginxCrée et démarre un conteneur en arrière-planPasse de l’état Absent à Running directement.
docker exec -it web shExécute une commande dans un conteneur actifOuvre un shell interactif sans redémarrer le conteneur.
docker stop webArrêt propre du conteneurEnvoie SIGTERM (délai 10s) puis SIGKILL si nécessaire.
docker rm -f webSuppression forcéeStoppe et détruit le conteneur et sa couche Writable.
docker logs -f --tail 100 webConsultation des flux stdout/stderrAffiche et suit les 100 dernières lignes de journalisation.
docker inspect webAffichage des métadonnées bas niveauRetourne la configuration complète en JSON (IP, volumes, cgroups).

3. Directives Dockerfile & Multi-Stage Build

DirectiveUsage recommandéRègle d’optimisation / Sécurité
FROM image:tag [AS stage]Déclare l’image parente de basePréférer des tags précis (ex: node:20-alpine) à latest.
WORKDIR /cheminDéfinit le répertoire courant d’exécutionToujours utiliser des chemins absolus (crée le dossier si absent).
COPY src destCopie des fichiers locaux de l’hôtePrivilégier COPY à ADD pour les fichiers simples (meilleure transparence).
RUN commande && nettoyageExécute une commande et crée un layerChaîner avec && et supprimer les caches apt/pip dans le même layer.
USER nonrootBascule vers un utilisateur non-privilégiéObligatoire en production pour éliminer le risque d’exécution root.
COPY --from=stage binaire destMulti-stage : extrait l’artefact compiléIsole les compilateurs lourds hors de l’image finale de production.
CMD ["exec", "arg"]Commande ou arguments par défautUtiliser la forme JSON exec form pour recevoir correctement les signaux UNIX.

4. Stockage, Réseau & Docker Compose

Pilotes de Stockage & Persistance

  • Volumes nommés : Gérés par Docker dans /var/lib/docker/volumes/. Recommandés pour les bases de données (persistance garantie).
  • Bind Mounts : Liés directement à un chemin de l’hôte (ex: ./src:/app). Idéaux en développement pour le rechargement à chaud (Hot Reload).
  • Tmpfs Mounts : Stockés en RAM pure. Données volatiles et ultra-rapides (clés éphémères, jetons).

Réseaux & Docker Compose

  • Bridge Network : Réseau privé virtuel par défaut. Dans un réseau personnalisé, résolution DNS automatique par nom de service.
  • Host Network : Supprime l’isolation réseau : le conteneur partage directement la pile réseau de l’hôte.
  • depends_on : Définit l’ordre d’instanciation sans garantir que l’application applicative interne est prête (utiliser healthcheck).
