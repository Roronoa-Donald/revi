Mémo synthétique Ingénierie du besoin

Toutes les normes, formules d’échantillonnage, canevas de User Stories, équations WSJF et critères de contrôle qualité réunis sur une seule page de référence.

1. Normes & Cycle de vie RE (ISO/IEC/IEEE 29148)

// Les 4 macro-activités itératives de l’ingénierie des exigences
1. Élicitation (Recueil)   : entretiens, observation terrain (shadowing), ateliers JAD, sondages
2. Analyse & Négociation   : arbitrage des conflits, détection d’ambiguïtés, priorisation
3. Spécification           : rédaction SRS normée, codification immuable, User Stories
4. Validation & Gestion    : revues formelles Fagan, matrice RTM, Change Requests (CR), Baselines

// Matrice Pouvoir / Intérêt de Mendelow
Pouvoir Fort  + Intérêt Fort   -> Gérer de près (Manage Closely)
Pouvoir Fort  + Intérêt Faible -> Garder satisfait (Keep Satisfied)
Pouvoir Faible + Intérêt Fort  -> Garder informé (Keep Informed)
Pouvoir Faible + Intérêt Faible-> Surveiller avec effort minimal (Monitor)

2. Classification FURPS+ & Qualité ISO 29148

// Taxonomie FURPS+
F (Functionality) : services métier, fonctionnalités, sécurité, calculs
U (Usability)     : ergonomie, accessibilité, temps d’apprentissage (< 3 clics)
R (Reliability)   : disponibilité (ex. 99,9 %), MTBF, tolérance aux pannes
P (Performance)   : latence (< 500 ms à 95 %), débit (transactions/s)
S (Supportability): maintenabilité, modularité, couverture de tests, portabilité
+ (Contraintes)   : contraintes techniques d’environnement, d’interface et légales (RGPD)

// Règle d’or de rédaction
Bannir les termes subjectifs : « rapide », « intuitif », « facile », « moderne », « si possible ».
Utiliser le verbe normatif obligatoire : « Le système doit... » (Shall).

3. Dimensionnement d’échantillon d’enquête (Taro Yamane)

// Formule de Taro Yamane pour population finie N et marge d’erreur e
n = N / (1 + N * e^2)

// Exemples types (avec e = 0,05 soit 5 % d’erreur tolérée) :
Pour N = 500   -> n = 500   / (1 + 500   * 0,0025) = 500   / 2,25 ≈ 222 répondants
Pour N = 2 000 -> n = 2 000 / (1 + 2 000 * 0,0025) = 2 000 / 6,00 ≈ 334 répondants
Pour N = 10 000-> n = 10 000/ (1 + 10 000* 0,0025) = 10 000/ 26,0 ≈ 385 répondants

4. Modélisation Agile & Arbitrage MoSCoW

// Canevas Connextra
En tant que <rôle / persona>,
Je veux <action ou capacité souhaitée>,
Afin de <bénéfice métier mesurable / valeur ajoutée>.

// Règle budgétaire MoSCoW 60 / 20 / 20
Must have   : ≤ 60 % de l’effort total (vital, non négociable)
Should have : ≈ 20 % de l’effort total (important, contournement possible)
Could have  : ≈ 20 % de l’effort total (confort, variable d’ajustement)
Won’t have  : exclu de l’itération courante (gardé en backlog pour plus tard)

5. Priorisation économique WSJF (SAFe)

// Algorithme Weighted Shortest Job First
WSJF = Cost_of_Delay / Job_Duration

// Composantes du Coût du Retard (Cost of Delay)
Cost_of_Delay = User_Business_Value + Time_Criticality + Risk_Reduction_Opportunity_Enablement

// Règle d’ordonnancement
L’élément avec le score WSJF le plus élevé est traité en priorité absolue (High Value / Short Duration).

6. Traçabilité RTM, BDD & Grille INVEST

// Codification formelle ISO
[PROJET]-[MODULE]-[TYPE]-[NUMÉRO]  -> Ex. MEDI-RDV-FR-001

// Matrice de Traçabilité RTM
Traçabilité Amont (Forward)  : Besoin Client -> Exigence SRS -> Code -> Test (Évite les oublis)
Traçabilité Aval (Backward)  : Test / Code -> Exigence SRS -> Besoin Client (Évite le Gold Plating)

// Syntaxe Gherkin BDD
Étant donné que (Given) [contexte initial]
Quand (When)            [action déclenchante]
Alors (Then)            [résultat observable attendu]

// Grille INVEST pour User Stories
I = Independent  | N = Negotiable | V = Valuable
E = Estimable    | S = Small      | T = Testable
