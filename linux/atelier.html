Atelier de scripts

Un éditeur dans la page, un vrai interpréteur Bash derrière. Écris un script, exécute-le et lis ce qu’il affiche : c’est ici qu’une règle d’administration devient un contrôle automatisé.

Comment fonctionne l’atelier
  • Exécuter fait tourner votre script Bash tel quel et affiche sa sortie, ses erreurs et son code de sortie.
  • Entrée du programme contient ce que read lira, une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Bash

Objectif : expérimenter sans conséquence. Prends un mécanisme d’administration (conversion octal, validation IPv4, filtre de journal, état de service), programme-le et teste-le sur des cas limites.

Le script proposé lit l’état d’une liste de services et décide de l’action. Modifie la règle, ajoute un décompte par état, ou remplace tout le script par le mécanisme que tu veux vérifier — un audit de droits, un classement de tâches cron, une validation d’adresse.

Dans un vrai terminal, ce sera systemctl, ps, cron : la structure du script — lire, décider, rapporter — reste exactement la même.

De la page au vrai serveur

La simulation a une limite assumée : rien n’est vraiment écrit sur disque. Elle a une force : toute la logique se vérifie sans machine. Quand le script affiche les bons rapports sur tes cas limites, le portage vers un serveur est mécanique : read lit la même entrée, case décide du même arbre, et le bilan s’affiche pareil.

Les trois erreurs que l’atelier révèle immédiatement
  • Ordre des lectures inversé : le script lit un nom avant n, ou le seuil après les valeurs.
  • Dernière ligne non lue : sans retour à la ligne final sur l’entrée, le dernier read renvoie un échec.
  • Bilan dans la boucle : le total s’affiche à chaque passage au lieu d’une seule fois, après.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices Bash corrigés automatiquement dans la page. Une fois l’atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme est vraiment acquis.
