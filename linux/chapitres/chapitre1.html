Chapitre 1 — Commandes de base et arborescence

Module 1 ≈ 2 h de travail Accès libre
Mise en situation

Un serveur n’a ni souris ni fenêtres : tout passe par un terminal et une ligne de commande. Avant d’administrer quoi que ce soit, il faut savoir se déplacer dans l’arborescence, reconnaître un chemin absolu d’un chemin relatif et créer les fichiers et dossiers dont on a besoin.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. distinguer une commande, ses options et ses arguments ;
  2. parcourir l’arborescence FHS et nommer le rôle de chaque répertoire ;
  3. reconnaître un chemin absolu et un chemin relatif ;
  4. créer, copier, déplacer et supprimer fichiers et dossiers sans erreur.

1. La ligne de commande

Une commande se lit toujours COMMANDE OPTIONS ARGUMENTS. Les options commencent par un tiret (ls -l) et les arguments désignent sur quoi elle agit (ls -l /home). Le shell (bash) lit la ligne, la découpe puis demande au noyau d’exécuter le programme.

Trois commandes suffisent à s’orienter : pwd affiche le répertoire courant, ls liste son contenu, cd change de répertoire. cd sans argument ramène dans la maison de l’utilisateur ; cd .. remonte d’un niveau ; cd / va à la racine.

pwd                 # où suis-je ?
ls -a               # tout, y compris les fichiers cachés (commençant par un point)
ls -l               # format long : droits, propriétaire, taille, date
cd /var/log         # chemin absolu
cd ../etc           # chemin relatif
Le prompt vous parle

Le prompt utilisateur@machine:dossier$ résume la situation : qui vous êtes, sur quelle machine, dans quel dossier. Le $ final signifie utilisateur normal ; un # signifie que vous êtes root — chaque commande est alors irréversible et dangereuse.

2. L’arborescence FHS

Sur Linux, tout part de la racine / : il n’y a ni lettre de lecteur ni séparateur en forme de barre oblique inversée. La norme FHS (Filesystem Hierarchy Standard) fixe le rôle de chaque répertoire :

/        racine, origine de tout chemin absolu
/etc     configuration du système (à sauvegarder en priorité)
/var     données variables : journaux, spools, bases
/home    répertoires personnels des utilisateurs
/root    maison du super-utilisateur (différent de /)
/tmp     temporaires, effacés à chaque redémarrage
/usr     programmes et bibliothèques partagés
/bin /sbin  binaires essentiels (sbin : réservés à root)
/dev     fichiers de périphériques ; /proc : arborescence virtuelle du noyau
Rien ne se perd, tout est fichier

Sous Linux, « tout est fichier » : un disque, un terminal, une socket réseau apparaissent comme des fichiers dans /dev. Retenir trois pièges : / n’est pas /root, les configurations vont dans /etc et non dans le répertoire du programme, et les journaux vont dans /var.

3. Chemins absolus et relatifs

Un chemin absolu commence par / et décrit la position depuis la racine : /etc/hosts. Un chemin relatif part du répertoire courant : hosts, ./hosts, ../etc/hosts. Les symboles spéciaux sont . (répertoire courant) et .. (répertoire parent).

Un chemin se construit en joignant un répertoire et un nom. Le piège classique est le double séparateur : /var/ plus log donne /var/log, pas /var//log. C’est exactement la logique que code l’exercice 3 de ce chapitre.

Piège — le chemin relatif dépend d’où l’on est

La même commande cat notes.txt réussit ou échoue selon le répertoire courant. Dans un script lancé par une tâche planifiée, le répertoire courant n’est pas celui de l’utilisateur : préférez toujours les chemins absolus dans les scripts.

4. Créer, copier, déplacer, supprimer

touch rapport.txt          # créer un fichier vide
mkdir -p /srv/site/html   # créer un dossier et ses parents
cp source cible           # copier (-r pour un dossier)
mv source cible           # déplacer ou renommer
rm fichier                # supprimer (-r pour un dossier)
echo "texte" > f          # écrire (écrase)
echo "texte" >> f         # ajouter (conserve)

cp duplique, mv déplace ou renomme : renommer n’est qu’un déplacement dans le même dossier. rm est définitif — il n’y a pas de corbeille pour root — et rm -rf est la commande la plus dangereuse du système.

Piège — un seul chevron écrase

> écrase le contenu existant, >> l’ajoute à la fin. Confondre les deux sur un fichier de configuration revient à détruire la configuration du service.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Reconnaître un chemin absolu

Bash Niveau 1 — Acquisition

Objectif : Classer chaque chemin en absolu ou relatif, puis compter les absolus.

Le script lit n lignes, chacune un chemin. Un chemin est absolu s’il commence par / ; sinon il est relatif. Pour chaque chemin, le script affiche chemin : absolu ou chemin : relatif, puis à la fin absolus : X.

Entrée du programme
2
/etc/hosts
home/rd
Sortie attendue
/etc/hosts : absolu
home/rd : relatif
absolus : 1
Deux indices, rédigés en mots
  1. Le motif `/*` en début de case correspond à tout chemin commençant par un slash.
  2. Le bilan sort une seule fois, après la boucle.

Exercice 2 — Compter les entrées par type

Bash Niveau 1 — Acquisition

Objectif : Dresser le bilan d’un répertoire : fichiers, répertoires et liens.

Le script lit n lignes « nom type » où type vaut fichier, repertoire ou lien. Il affiche trois compteurs, dans cet ordre : fichiers : X, repertoires : Y, liens : Z.

Entrée du programme
3
etc repertoire
bashrc lien
notes fichier
Sortie attendue
fichiers : 1
repertoires : 1
liens : 1
Deux indices, rédigés en mots
  1. Un case sur le type : fichier, repertoire, lien.
  2. Les trois lignes de bilan sortent dans l’ordre fichiers, repertoires, liens.

Exercice 3 — Assembler un chemin

Bash Niveau 1 — Acquisition

Objectif : Joindre un répertoire et un nom de fichier sans doubler le séparateur.

Le script lit n lignes « repertoire nom ». Il affiche le chemin assemblé : repertoire/nom, sauf si le répertoire se termine déjà par /, auquel cas la barre n’est pas répétée. Une seule ligne par entrée.

Entrée du programme
2
/etc hosts
/var/ log
Sortie attendue
/etc/hosts
/var/log
Deux indices, rédigés en mots
  1. Le motif `*/` en début de case repère un répertoire terminé par un slash.
  2. Ne pas oublier le cas simple, sans slash final, dans la branche par défaut.

6. QCM — niveau examen

Quelle commande affiche le répertoire courant ?

pwd (print working directory) affiche le chemin absolu du répertoire courant.

Un chemin qui commence par / est…

Tout chemin partant de la racine est absolu ; sinon il est relatif au répertoire courant.

Où se trouvent les fichiers de configuration ?

/etc contient la configuration du système : le sauvegarder, c’est sauvegarder la machine.

Que devient /tmp au redémarrage ?

/tmp ne survit pas au reboot : il ne contient que des fichiers temporaires.

Différence entre / et /root ?

/ est l’origine de l’arborescence ; /root est le répertoire personnel du super-utilisateur.

Que fait echo "x" >> f ?

Deux chevrons ajoutent à la fin ; un seul chevron écrase tout le fichier.

mkdir -p a/b/c sert à…

L’option -p crée toute la chaîne de répertoires intermédiaires.

Quelle commande renomme un fichier ?

mv déplace et, dans le même dossier, renomme : mv ancien nouveau.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre / (racine) et /root (maison du super-utilisateur).
  • Écrire des journaux ou des données variables dans /etc au lieu de /var.
  • Utiliser > au lieu de >> et écraser un fichier de configuration.
  • Oublier que rm est définitif pour root — aucune corbeille.
  • Lancer un script avec des chemins relatifs dont le répertoire courant n’est pas celui attendu.

8. Méthodologie de résolution

Explorer un système inconnu
  1. Se repérer : pwd puis ls -a avant toute action.
  2. Nommer les répertoires : parcourir /etc, /var, /home et énoncer le rôle de chacun.
  3. Qualifier les chemins : absolu ou relatif, avant d’écrire une commande.
  4. Créer proprement : mkdir -p, touch, puis vérifier avec ls -l.
  5. Relire les redirections : un chevron ou deux ? écrase ou ajoute ?

9. Révision active

Résumé essentiel
  • Une commande se lit COMMANDE OPTIONS ARGUMENTS ; bash interprète la ligne et dialogue avec le noyau.
  • Tout part de / ; la norme FHS fixe le rôle de /etc, /var, /home, /tmp, /usr, /dev.
  • Absolu = commence par / ; relatif = part du répertoire courant (. et ..).
  • mv déplace ou renomme, cp duplique, rm supprime définitivement.
  • > écrase, >> ajoute : un chevron de trop détruit un fichier.

Checklist de maîtrise

  • Je me repère avec pwd, ls et cd sans hésiter.
  • Je nomme le rôle de /etc, /var, /home, /tmp, /root.
  • Je reconnais un chemin absolu et un chemin relatif.
  • Je crée, copie, déplace et supprime sans confondre > et >>.
