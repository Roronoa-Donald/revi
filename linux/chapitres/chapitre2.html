Chapitre 2 — Manipulation de fichiers et recherche

Module 2 ≈ 2 h de travail Réservé B2 et plus
Mise en situation

Un serveur en production produit des gigaoctets de fichiers et de journaux. L’administrateur doit retrouver un fichier précis, repérer les liens cassés, et extraire d’un journal la seule ligne qui explique la panne.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. copier, déplacer et supprimer sans perdre de données ;
  2. distinguer un lien symbolique d’un lien dur ;
  3. chercher par nom, type et taille avec find ;
  4. filtres un journal avec grep pour y compter les erreurs.

1. Copier, déplacer, supprimer proprement

cp et mv acceptent l’option -i (demander confirmation avant d’écraser) et -r (récursif, pour un dossier). Le réflexe d’administration est de prévisualiser une suppression avec ls avant de lancer rm.

cp -r /etc/nginx /root/nginx.bak   # sauvegarder un dossier
mv rapport.txt /var/backups/       # déplacer
rm -i ancien.log                   # demander confirmation
find /tmp -type f -delete          # supprimer les fichiers (pas les dossiers)
Sauvegarder avant de modifier

La règle d’or : avant de modifier un fichier de configuration, on en fait une copie horodatée. En cas d’erreur, restaurer la copie prend deux secondes ; sans elle, la machine peut être inaccessible.

2. Liens durs et liens symboliques

Un lien dur (ln source lien) est un second nom pour le même fichier : les deux noms partagent les mêmes données et le même numéro d’inode. Un lien symbolique (ln -s source lien) est un simple raccourci : il pointe vers un chemin, et si la cible disparaît, le lien devient cassé.

ln fichier second_nom       # lien dur : même contenu, même inode
ln -s /etc/hosts raccourci  # lien symbolique : un raccourci vers un chemin
ls -l raccourci             # l -> indique la cible du lien symbolique
Piège — le lien dur ne traverse pas les systèmes de fichiers

Un lien dur ne peut pas franchir les frontières d’un système de fichiers ni pointer vers un dossier. Le lien symbolique, lui, accepte tout — y compris une cible absente, ce qui produit un lien cassé que find signale.

3. find : chercher par critère

find parcourt une arborescence et applique des critères. Il se lit find répertoire critères :

find /tmp -name "fich*"      # par motif de nom
find /tmp -type f            # fichier (f) ou dossier (d)
find /var -size +10M         # plus de 10 mégaoctets
find /etc -user root         # appartenant à root
find / -perm -4000 -type f   # fichiers setuid (audit de sécurité)
find est le couteau suisse

On combine les critères sans limite : find /home -type f -name "*.ssh*" retrouve les clés, find /var/log -mtime +7 les journaux vieux de plus de sept jours. Le motif de nom doit être entre guillemets, sinon le shell l’interprète avant find.

4. grep et les journaux

Les journaux de /var/log sont des fichiers texte : on les filtre avec grep. grep -c compte les lignes, grep -i ignore la casse, grep -v inverse la sélection.

grep "ERROR" /var/log/syslog      # lignes contenant ERROR
grep -c "ERROR" /var/log/syslog   # combien de lignes
grep -i "failed" /var/log/auth.log
jourctl -p err -b                 # même idée avec journalctl (systemd)
Lire un journal en trois temps

1) repérer le fichier concerné (/var/log/syslog, auth.log) ; 2) filtrer par niveau (ERROR) ; 3) compter avec grep -c pour décider si l’incident est isolé ou répété.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Copier ou déplacer

Bash Niveau 2 — Application

Objectif : Consigner les opérations de fichiers et en dresser le bilan.

Le script lit n lignes « op source cible » où op vaut cp ou mv. Il affiche pour chaque ligne copie source vers cible (pour cp) ou deplacement source vers cible (pour mv). Il termine par copies : C puis deplacements : D.

Entrée du programme
2
cp a.txt b.txt
mv b.txt c.txt
Sortie attendue
copie a.txt vers b.txt
deplacement b.txt vers c.txt
copies : 1
deplacements : 1
Deux indices, rédigés en mots
  1. Un case sur op : cp pour une copie, mv pour un déplacement.
  2. Les deux compteurs s’affichent dans l’ordre copies puis deplacements.

Exercice 2 — Rechercher par extension

Bash Niveau 2 — Application

Objectif : Filtrer une liste de fichiers et ne garder que les scripts shell.

Le script lit n lignes, chacune un nom de fichier. Il n’affiche que ceux qui se terminent par .sh, dans leur ordre d’apparition, puis termine par scripts : X.

Entrée du programme
3
install.sh
notes.txt
backup.sh
Sortie attendue
install.sh
backup.sh
scripts : 2
Deux indices, rédigés en mots
  1. Le motif `*.sh` correspond à tout nom se terminant par .sh.
  2. Si aucun fichier ne correspond, seul le bilan s’affiche, avec 0.

Exercice 3 — Compter les erreurs d’un journal

Bash Niveau 2 — Application

Objectif : Parcourir un journal ligne par ligne et compter les entrées critiques.

Le script lit n lignes « niveau message » où niveau vaut INFO, WARN ou ERROR. Il compte les lignes de niveau ERROR et affiche à la fin erreurs : X.

Entrée du programme
3
INFO demarrage
ERROR disque plein
WARN memoire faible
Sortie attendue
erreurs : 1
Deux indices, rédigés en mots
  1. `read -r niveau message` laisse le reste de la ligne dans message.
  2. La comparaison se fait sur le niveau seul, avec [ "$niveau" = "ERROR" ].

6. QCM — niveau examen

Quelle option de cp copie un dossier entier ?

-r rend la copie récursive : dossier, sous-dossiers et fichiers.

Un lien dur partage…

Le lien dur est un second nom pour le même fichier (même inode).

Que crée ln -s source lien ?

-s crée un lien symbolique, un simple raccourci de chemin.

Un lien symbolique vers une cible supprimée devient…

Le symbole pointe vers un chemin absent : le lien est cassé.

find /var -size +10M cherche…

Le signe + signifie « supérieur à » ; -10M serait « inférieur ».

grep -c compte…

-c affiche le nombre de lignes qui correspondent au motif.

Où lire les traces d’une connexion en échec ?

Les authentifications et échecs de connexion sont journalisés dans auth.log.

Pourquoi entourer le motif de find de guillemets ?

Sans guillemets, le shell développe le motif (fich*) avant de lancer find.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre lien dur (même inode) et lien symbolique (raccourci de chemin).
  • Oublier -r et croire qu’un dossier a été copié alors que cp a échoué.
  • Négliger les motifs de find sans guillemets, développés par le shell.
  • Chercher un mot sans -i et manquer les lignes en casse mixte.
  • Modifier un fichier de configuration sans en avoir fait une copie de sauvegarde.

8. Méthodologie de résolution

Retrouver une information dans un parc
  1. Préciser la cible : nom exact, motif, extension ou taille ?
  2. Choisir l’outil : find pour les fichiers, grep pour les contenus.
  3. Restreindre la portée : partir d’un répertoire précis plutôt que de la racine.
  4. Vérifier le motif : guillemets autour de "fich*".
  5. Rapporter : compter avec grep -c ou find | wc -l.

9. Révision active

Résumé essentiel
  • cp duplique (-r pour un dossier), mv déplace ou renomme, rm supprime définitivement.
  • Lien dur = même inode ; lien symbolique = raccourci de chemin, cassable.
  • find cherche par nom (-name), type (-type), taille (-size), propriétaire (-user).
  • grep filtre les journaux : -c compte, -i ignore la casse, -v inverse.
  • Les journaux vivent dans /var/log ; auth.log trace les connexions.

Checklist de maîtrise

  • Je sauvegarde avant de modifier un fichier de configuration.
  • Je distingue un lien dur d’un lien symbolique.
  • J’écris une commande find avec un motif entre guillemets.
  • Je compte les erreurs d’un journal avec grep -c.
