Chapitre 3 — Droits, permissions, utilisateurs et groupes

Module 3 ≈ 2 h 30 de travail Réservé B2 et plus
Mise en situation

Sur un serveur partagé, chacun doit pouvoir travailler sans marcher sur le travail des autres. Les droits Unix décident qui peut lire, écrire et exécuter ; les comptes et les groupes décident qui est qui. Un droit mal posé ouvre une faille, un compte mal géré laisse une porte ouverte.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. lire une ligne de droits et la traduire en octal ;
  2. modifier les droits en notation symbolique et octale ;
  3. changer propriétaire et groupe d’un fichier ;
  4. lire /etc/passwd, /etc/shadow et /etc/group ;
  5. créer, modifier et supprimer comptes et groupes.

1. Lire les permissions

ls -l affiche une chaîne de dix caractères. Le premier est le type (- fichier, d dossier, l lien) ; les neuf suivants sont trois trios : u (propriétaire), g (groupe), o (autres). Dans chaque trio, r lit, w écrit, x exécute.

-rwxr-x--- 1 rd it 4096 mai 12 10:00 script.sh
 ^^^       ^^ ^^
 u g o     own grp
u=rwx  g=r-x  o=---
La valeur des lettres

r = 4, w = 2, x = 1. Un trio se lit donc rwx=7, r-x=5, rw-=6, r--=4, ---=0. On additionne dans chaque trio, jamais entre les trios : rwxr-x--- = 750, pas 12.

2. chmod : modifier les droits

Deux notations équivalentes. Octale : trois chiffres, un par trio. Symbolique : on nomme la classe (u, g, o, a = tous) et l’opération (+ ajoute, - retire, = fixe exactement).

chmod 755 script.sh        # rwxr-xr-x
chmod 640 secret.conf      # rw-r-----
chmod u+x script.sh        # ajoute l’exécution au propriétaire
chmod o-rw secret.conf     # retire lecture et écriture aux autres
chmod ug=rwx dossier       # fixe u et g exactement, o inchangé
chmod -R 750 /srv/site     # récursif sur tout le dossier
Piège — 777 n’est jamais une solution

Donner 777 « pour que ça marche » ouvre le fichier au monde entier. Le bon réflexe est de chercher la classe qui manque (souvent le groupe) et de lui accorder le droit nécessaire, pas de tout ouvrir.

3. chown et chgrp

chown change le propriétaire, chgrp le groupe. chown sait faire les deux d’un coup avec utilisateur:groupe, et l’option -R rend le changement récursif.

chown rd rapport.txt            # propriétaire = rd
chgrp it rapport.txt            # groupe = it
chown rd:it rapport.txt         # les deux à la fois
chown -R www-data:www-data /var/www  # rendre un site au serveur web
Après un déploiement

Copier des fichiers avec cp en root n’est pas suffisant : les nouveaux fichiers appartiennent à root. Un site web servi par www-data doit lui être restitué, sinon le serveur ne lira pas ses propres fichiers.

4. Comptes et groupes

Trois fichiers font foi. /etc/passwd décrit les comptes (lisible par tous), /etc/shadow contient les mots de passe chiffrés (root seul), /etc/group les groupes.

caroline:x:1002:1000:Caroline TP:/home/caroline:/bin/bash
  ^      ^  ^    ^     ^             ^            ^
 login mdp UID GID  info          maison       shell
/etc/shadow : login:empreinte:dates… (root uniquement)
/etc/group  : groupe:*:GID:utilisateurs

root a l’UID 0 ; les comptes système sont sous 1000 ; les comptes humains commencent à 1000. Dans /etc/passwd, x ou ! renvoient au shadow ; * interdit l’authentification ; !! désactive le compte.

Menus de gestion des comptes

useradd crée, usermod modifie, userdel -r supprime (avec la maison), groupadd/groupdel gèrent les groupes, passwd change le mot de passe, id affiche les appartenances.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Décoder une permission

Bash Niveau 2 — Application

Objectif : Convertir une permission symbolique en notation octale.

Le script lit n lignes, chacune une permission symbolique de neuf caractères (ex. rwxr-xr-x). Pour chaque trio, r vaut 4, w vaut 2 et x vaut 1. Il affiche permission : octal, par exemple permission : 755.

Entrée du programme
1
rwxr-xr-x
Sortie attendue
permission : 755
Deux indices, rédigés en mots
  1. Trois trios : les caractères 1-3, 4-6 puis 7-9 de la permission.
  2. Un case sur le trio : *r* ajoute 4, *w* ajoute 2, *x* ajoute 1.

Exercice 2 — Interroger une permission

Bash Niveau 3 — Raisonnement

Objectif : Vérifier si le propriétaire possède le droit demandé.

Le script lit n lignes « permission action » où action vaut lire, ecrire ou executer. Il considère uniquement le premier trio (le propriétaire) : si le droit demandé est présent, il affiche droit : oui, sinon droit : non.

Entrée du programme
2
rw-r--r-- lire
rw-r--r-- executer
Sortie attendue
droit : oui
droit : non
Deux indices, rédigés en mots
  1. Le premier trio correspond aux caractères 1 à 3 de la permission.
  2. Lire cherche r, ecrire cherche w, executer cherche x.

Exercice 3 — Vérifier une appartenance

Bash Niveau 3 — Raisonnement

Objectif : Contrôler le groupe de chaque utilisateur contre l’annuaire du service.

L’annuaire du service associe un groupe à chaque compte : rd appartient à it, sam à dev, ada à admin. Le script lit n lignes « utilisateur groupe » et affiche utilisateur : membre si le groupe est le bon, utilisateur : non membre sinon.

Entrée du programme
2
rd it
sam admin
Sortie attendue
rd : membre
sam : non membre
Deux indices, rédigés en mots
  1. Un case sur user : rd → it, sam → dev, ada → admin.
  2. La comparaison se fait ensuite avec [ "$groupe" = "$attendu" ].

6. QCM — niveau examen

rwxr-x--- vaut en octal…

rwx=7, r-x=5, ---=0 : 750, trio par trio.

Que fait chmod o-r secret ?

o désigne les autres, - retire : la lecture leur est enlevée.

Ug=rwx…

= fixe exactement les classes visées ; les autres ne bougent pas.

Quel fichier contient les mots de passe chiffrés ?

/etc/shadow, lisible par root uniquement, contient les empreintes.

Un UID ≥ 1000 correspond à…

Les comptes humains commencent à 1000 ; en dessous, ce sont des comptes système.

Que fait userdel -r ?

-r retire aussi le répertoire personnel et la boîte aux lettres.

chgrp agit sur…

chgrp change le groupe propriétaire ; chown le propriétaire.

groupdel échoue quand le groupe…

On ne supprime pas un groupe qui est le groupe principal d’un compte.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre / et /root dans un contexte de droits.
  • Additionner les trios entre eux (750, pas 12).
  • Ouvrir en 777 au lieu d’accorder le droit à la bonne classe.
  • Oublier -R sur chown après un déploiement.
  • Confondre chown (propriétaire) et chgrp (groupe).

8. Méthodologie de résolution

Poser des droits justes
  1. Lire la ligne de droits et la découper en trois trios.
  2. Convertir chaque trio en chiffre (r=4, w=2, x=1).
  3. Décider de la classe qui a besoin du droit : u, g ou o.
  4. Appliquer avec la notation la plus lisible (773 ou ug=rx).
  5. Vérifier avec ls -l et id utilisateur.

9. Révision active

Résumé essentiel
  • Dix caractères : type + u + g + o ; r=4, w=2, x=1 par trio.
  • chmod en octal (755) ou symbolique (u+x, o-rw, ug=rwx) ; -R pour récursif.
  • chown change le propriétaire (ou utilisateur:groupe) ; chgrp le groupe.
  • /etc/passwd décrit les comptes, /etc/shadow les mots de passe, /etc/group les groupes.
  • UID 0 = root, < 1000 = système, ≥ 1000 = humain ; useradd, usermod, userdel -r.

Checklist de maîtrise

  • Je convertis une ligne de droits en octal sans erreur.
  • Je choisis entre notation octale et symbolique selon le besoin.
  • Je restitue un dossier au bon propriétaire et groupe après déploiement.
  • Je lis une ligne de /etc/passwd champ par champ.
