Atelier de code

Un éditeur dans la page, un vrai interpréteur PHP derrière. Écrivez une classe, exécutez-la et lisez ce qu’elle affiche : c’est ici qu’une règle d’objet devient un programme qui tourne.

Comment fonctionne l’atelier
  • Exécuter fait tourner votre programme PHP tel quel et affiche sa sortie, ses erreurs et son code de sortie.
  • Entrée du programme contient ce que fgets(STDIN) lira, une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le programme sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

PHP

Objectif : expérimenter sans conséquence. Prenez un mécanisme du cours (encapsulation, héritage, exception, PDO en mémoire), programmez-le et testez-le sur des cas limites.

Le programme proposé construit un objet à partir de l’entrée et l’affiche. Modifiez la classe, ajoute une validation, un second contact, ou remplace tout le programme par le mécanisme que vous voulez vérifier — un setter qui refuse une valeur, une exception personnalisée, une requête préparée.

Dans une vraie application, ce sera un contrôleur, un dépôt, une base : la structure du programme — lire, construire, afficher — reste exactement la même.

De la page à la vraie application

La simulation a une limite assumée : rien n’est envoyé ni stocké durablement. Elle a une force : toute la logique se vérifie sans serveur. Quand le programme affiche les bons résultats sur vos cas limites, le portage est mécanique : la même classe, le même setter, la même requête préparée.

Les trois erreurs que l’atelier révèle immédiatement
  • Point au lieu de flèche : $this.x au lieu de $this->x.
  • Entrée mal lue : oublier trim() et comparer une chaîne avec un saut de ligne.
  • Exception non attrapée : le programme s’arrête net avec une erreur fatale.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices PHP corrigés automatiquement dans la page. Une fois l’atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme est vraiment acquis.
