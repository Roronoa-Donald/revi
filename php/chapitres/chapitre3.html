Chapitre 3 — Héritage, classes abstraites et interfaces

Module 3 ≈ 2 h 30 de travail Réservé B2 et plus
Mise en situation

Plusieurs objets partagent des comportements : un cercle et un carré ont tous deux une aire et un périmètre. Plutôt que de recopier, on factorise dans une classe mère, et on impose un contrat commun à toutes les formes avec une interface. C’est ce qui permet d’écrire du code qui traite « n’importe quelle forme » sans connaître les détails.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. étendre une classe et réutiliser son code avec extends ;
  2. appeler le constructeur parent avec parent::__construct() ;
  3. déclarer une classe abstraite et des méthodes abstraites ;
  4. imposer un contrat avec une interface et l’implémenter.

1. Hériter d’une classe

Le mot-clé extends fait hériter une classe (la fille) d’une autre (la mère). La fille reçoit les propriétés et méthodes accessibles du parent, et peut les redéfinir pour les spécialiser.

class Animal {
    protected $nom;

    public function __construct(string $nom) {
        $this->nom = $nom;
    }

    public function crier(): string {
        return $this->nom . " fait un bruit";
    }
}

class Chien extends Animal {
    public function crier(): string {
        return $this->nom . " aboie";
    }
}

La visibilité protected est faite pour cela : la propriété $nom est accessible depuis la classe et ses filles, mais reste fermée à l’extérieur.

2. Redéfinir et appeler le parent

Quand la fille a besoin du comportement du parent, elle l’appelle avec parent::. Typiquement, la fille appelle parent::__construct() pour ne pas réécrire l’initialisation.

class Chat extends Animal {
    public function __construct(string $nom) {
        parent::__construct($nom);   // hérite de l’initialisation
    }
}
Piège — oublier le constructeur parent

Si la fille définit son propre __construct() sans appeler parent::__construct(), le parent n’est plus jamais initialisé : les propriétés du parent restent vides. On appelle explicitement le parent quand on veut son travail.

3. Classes abstraites

Une classe abstraite (abstract) ne s’instancie pas : elle sert de base commune. Elle peut déclarer des méthodes abstraites — sans corps — que chaque fille devra obligatoirement implémenter.

abstract class Forme {
    abstract public function aire(): float;

    public function decrire(): string {
        return "forme d’aire " . $this->aire();
    }
}

Impossible de faire new Forme() : une classe abstraite est un squelette. En revanche, elle peut déjà coder les méthodes communes, comme decrire().

4. Polymorphisme et interfaces

Le polymorphisme est la conséquence de l’abstraction : on appelle aire() sur un objet dont on ne connaît que le type de base, et chaque classe exécute sa version. Une interface pousse l’idée plus loin : elle ne décrit qu’un contrat de méthodes, sans aucun code, et une classe peut en implémenter plusieurs.

interface Affichable {
    public function afficher(): string;
}

class Cercle extends Forme implements Affichable {
    public function aire(): float { return 3.14 * $this->r * $this->r; }
    public function afficher(): string { return "cercle"; }
}
Interface contre classe abstraite

Une classe abstraite peut contenir du code et n’en hérite qu’une seule (héritage simple). Une interface ne contient que des signatures et on peut en implémenter autant qu’on veut : elle sert à décrire une capacité (« est affichable », « est comparable »).

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Héritage et classe abstraite

PHP Niveau 2 — Application

Objectif : Implémenter une méthode abstraite dans une classe fille.

Le programme reçoit le côté d’un carré (entier). Écris une classe abstraite Forme déclarant aire(), puis Carre qui hérite de Forme et calcule côté × côté. Affiche aire : X.

Entrée du programme
4
Sortie attendue
aire : 16

4 × 4 = 16.

Deux indices, rédigés en mots
  1. Une méthode abstraite s’écrit abstract public function aire(): int; sans corps.
  2. La classe fille doit définir aire() avec la même signature, sinon PHP refuse.

Exercice 2 — Polymorphisme

PHP Niveau 3 — Raisonnement

Objectif : Traiter des objets de types différents derrière une même méthode.

Le programme reçoit n, puis n lignes « type a [b] » : carre a ou rectangle l h. Écris Forme (abstraite), Carre et Rectangle, puis calcule la somme des aires. Affiche total : X.

Entrée du programme
3
carre 3
rectangle 2 5
carre 2
Sortie attendue
total : 23

9 + 10 + 4 = 23.

Deux indices, rédigés en mots
  1. Découpe chaque ligne avec explode(' ', trim(fgets(STDIN))).
  2. Les deux classes exposent aire() : la somme s’écrit sans connaître leur type.

Exercice 3 — Implémenter une interface

PHP Niveau 2 — Application

Objectif : Garantir un contrat commun avec une interface.

Le programme reçoit un nom d’article puis son prix (entier). Écris une interface Affichable déclarant afficher(): string, puis Produit qui l’implémente et renvoie nom (prix EUR). Affiche le résultat.

Entrée du programme
Clavier
29
Sortie attendue
Clavier (29 EUR)

Nom et prix mis en forme.

Deux indices, rédigés en mots
  1. Une interface déclare des signatures ; une classe l’implémente avec implements.
  2. La chaîne attendue se construit par concaténation : nom . ' (' . prix . ' EUR)'.

6. QCM — niveau examen

Quel mot-clé fait hériter une classe ?

extends établit l’héritage simple entre deux classes.

Comment appelle-t-on le constructeur du parent ?

parent::__construct() exécute le constructeur de la classe mère.

Une classe abstraite…

abstract interdit new : elle sert de base à des filles concrètes.

Une méthode abstraite…

Elle déclare la signature ; chaque fille doit la définir.

protected est visible…

protected ouvre l’accès à la classe et à ses descendantes.

Combien d’interfaces peut implémenter une classe ?

On peut implémenter plusieurs interfaces, séparées par des virgules.

Une interface contient…

L’interface n’est qu’un contrat : des signatures sans implémentation.

Le polymorphisme permet…

Chaque objet répond à la même méthode selon sa propre implémentation.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Redéfinir __construct() sans appeler parent::__construct().
  • Vouloir instancier une classe abstract ou une interface.
  • Oublier d’implémenter une méthode abstraite ou une méthode d’interface.
  • Mettre du code dans une interface : elle ne porte que des signatures.
  • Confondre héritage (« est un ») et simple factorisation de code.

8. Méthodologie de résolution

Factoriser sans se tromper
  1. Identifier ce qui est commun : propriétés et méthodes partagées.
  2. Remonter le commun dans une classe mère (concrète ou abstraite).
  3. Déclarer abstrait ce que chaque fille doit absolument fournir.
  4. Choisir le contrat : interface pour une capacité, classe abstraite pour un squelette.
  5. Appeler parent quand la fille a besoin du comportement hérité.

9. Révision active

Résumé essentiel
  • extends établit l’héritage simple ; la fille redéfinit ce qu’elle spécialise.
  • parent::__construct() réutilise l’initialisation du parent.
  • Une classe abstract ne s’instancie pas et peut imposer des méthodes abstraites.
  • Le polymorphisme : une méthode appelée s’exécute selon le type réel de l’objet.
  • Une interface est un contrat de signatures ; une classe peut en implémenter plusieurs.

Checklist de maîtrise

  • Je fais hériter une classe et je redéfinis une méthode.
  • J’appelle parent::__construct() quand la fille a son propre constructeur.
  • Je déclare et implémente une méthode abstraite.
  • Je distingue interface (contrat) et classe abstraite (squelette).
