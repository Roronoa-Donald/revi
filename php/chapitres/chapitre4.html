Chapitre 4 — Traits, namespaces et chargement des classes

Module 4 ≈ 2 h de travail Réservé B2 et plus
Mise en situation

Deux classes sans lien de parenté ont besoin de la même méthode : l’héritage ne convient pas. Et quand un projet grossit, deux développeurs finissent par nommer une classe Utilisateur — impossible de les distinguer. Traits et namespaces répondent à ces deux problèmes d’organisation.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. factoriser des méthodes réutilisables dans un trait ;
  2. résoudre un conflit de méthodes entre deux traits ;
  3. déclarer et utiliser des namespaces ;
  4. importer une classe avec use et comprendre l’autoloading.

1. Les traits : réutiliser sans hériter

Un trait est un paquet de méthodes qu’une classe peut importer avec use. Ce n’est ni une classe ni une interface : il ne s’instancie pas, mais son code devient celui de la classe qui l’utilise.

trait Salutation {
    public function saluer(string $nom): string {
        return "Bonjour " . $nom;
    }
}

class Accueil {
    use Salutation;
}

Ici Accueil possède saluer() comme si elle l’avait écrite elle-même. Le trait évite de dupliquer du code entre des classes qui n’ont aucun lien de parenté.

2. Résoudre un conflit de traits

Si deux traits apportent la même méthode, use refuse de choisir et PHP lève une erreur fatale. On lève l’ambiguïté avec insteadof pour désigner celui qui gagne, et as pour renommer l’autre.

class Service {
    use A, B {
        A::demarrer insteadof B;
        B::demarrer as demarrerB;
    }
}
Piège — le silence du conflit

Un conflit de méthodes entre deux traits n’est pas une commodité : c’est une erreur. Il faut le dire explicitement, sinon la classe ne compile pas. C’est une protection : PHP refuse de décider à notre place quand le choix a un sens.

3. Les namespaces

Un namespace est un espace de noms : il préfixe les classes pour éviter les collisions. La déclaration namespace App; se place tout en haut du fichier, juste après <?php.

<?php
namespace App;

class Utilisateur {
    // App\Utilisateur, distinct d’un autre Utilisateur
}

Sans namespace, deux bibliothèques définissant Utilisateur entreraient en conflit. Avec, les noms complets App\Utilisateur et Auth\Utilisateur coexistent.

4. Importer et charger les classes

Pour ne pas écrire le chemin complet à chaque fois, on importe la classe avec use. On peut la renommer avec as. À l’échelle d’un projet, on ne fait plus require à la main : un autoloader (spl_autoload_register, ou Composer) charge la classe au moment où on en a besoin.

<?php
namespace App;

use Core\Calcul as Calc;

$c = new Calc();   // Core\Calcul
Le chargeur automatique

On enregistre une fonction auprès de spl_autoload_register(). Quand PHP rencontre une classe inconnue, il appelle cette fonction avec son nom : à elle de retrouver le fichier et de le require. C’est exactement ce que fait Composer en mappant les namespaces aux dossiers.

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

Exercice 1 — Réutiliser du code avec un trait

PHP Niveau 2 — Application

Objectif : Composer une méthode réutilisable via un trait.

Le programme reçoit un prénom. Écrivez un trait Salutation qui fournit saluer(string $nom): string renvoyant Bonjour nom, puis une classe Accueil qui l’utilise. Affichez le message.

Entrée du programme
Ada
Sortie attendue
Bonjour Ada

Le prénom est inséré dans le message.

Deux indices, rédigés en mots
  1. Un trait se déclare comme une classe (trait Salutation { … }) et s’importe avec use à l’intérieur de la classe.
  2. Les méthodes du trait se comportent comme des méthodes de la classe.

Exercice 2 — Ranger ses classes dans un namespace

PHP Niveau 2 — Application

Objectif : Déclarer un namespace et instancier la classe qu’il contient.

Le programme reçoit un login. Déclare un namespace App contenant une classe Utilisateur (propriété privée $nom, méthode nom()), puis instancie-la et affiche utilisateur : login.

Entrée du programme
sam
Sortie attendue
utilisateur : sam

Login mis en forme.

Deux indices, rédigés en mots
  1. La déclaration namespace App; se place tout en haut, juste après <?php.
  2. À l’intérieur du namespace, la classe s’instancie directement : new Utilisateur($nom).

Exercice 3 — Importer une classe avec un alias

PHP Niveau 3 — Raisonnement

Objectif : Déclarer une classe dans un namespace et l’importer avec use … as.

Le programme reçoit un entier n. Déclare une classe Calcul dans le namespace App (méthode doubler(int $n): int renvoyant le double), importe-la sous l’alias Calc et affiche double : 2n.

Entrée du programme
21
Sortie attendue
double : 42

Classe importée sous un autre nom.

Deux indices, rédigés en mots
  1. Un import use App\Calcul as Calc; se place en haut du bloc namespace, avant le code.
  2. On instancie ensuite via l’alias : (new Calc())->doubler($n).

6. QCM — niveau examen

Qu’est-ce qu’un trait ?

Un trait fournit des méthodes qu’on importer avec use dans une classe.

Comment importer un trait dans une classe ?

À l’intérieur de la classe : use NomDuTrait;.

Que fait insteadof ?

insteadof désigne le trait dont la méthode l’emporte.

À quoi sert un namespace ?

Le namespace préfixe les classes pour les distinguer.

Où se place la déclaration namespace ?

Tout en haut du fichier, avant tout autre code.

Que fait use App\Utilisateur as U; ?

use importe la classe sous l’alias U.

À quoi sert spl_autoload_register ?

PHP appelle l’autoloader quand il rencontre une classe non encore chargée.

Deux traits définissent la méthode demarrer. Que fait PHP ?

Le conflit doit être levé explicitement avec insteadof / as.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre trait et interface : le trait contient du code, l’interface seulement des signatures.
  • Laisser un conflit de traits sans insteadof ni as.
  • Placer namespace après du code ou après un affichage.
  • Écrire le nom complet Core\Calcul partout au lieu d’importer une fois.
  • Oublier que le namespace fait partie du nom complet de la classe.

8. Méthodologie de résolution

Organiser un projet PHP
  1. Regrouper en trait les méthodes partagées hors héritage.
  2. Lever les conflits avec insteadof, renommer avec as.
  3. Préfixer chaque domaine par un namespace (App, Core, Auth…).
  4. Importer une seule fois en haut avec use … as.
  5. Automatiser le chargement (autoloader ou Composer) plutôt que des require à la main.

9. Révision active

Résumé essentiel
  • Un trait est un paquet de méthodes importé par use à l’intérieur d’une classe.
  • insteadof tranche un conflit de méthodes ; as renomme.
  • Un namespace préfixe les classes et évite les collisions de noms.
  • use importe une classe, éventuellement sous un alias (as).
  • Un autoloader charge une classe au moment où on l’utilise.

Checklist de maîtrise

  • Je déclare un trait et je l’utilise dans une classe.
  • Je résous un conflit de traits avec insteadof/as.
  • Je place et nomme mes classes dans un namespace.
  • J’importe une classe avec use et j’explique l’autoloading.
