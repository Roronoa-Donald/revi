Chapitre 5 — Erreurs et exceptions

Module 5 ≈ 2 h de travail Réservé B2 et plus
Mise en situation

Un programme qui plante au premier cas imprévu n’est pas fiable. Une exception transporte un message au lieu de stopper net : le code qui sait quoi faire l’attrape, celui qui ne sait pas la laisse remonter. C’est ainsi qu’une application reste debout même quand l’entrée est mauvaise.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. distinguer une erreur PHP d’une exception ;
  2. lancer une exception avec throw et l’intercepter avec try/catch ;
  3. créer une exception personnalisée qui étend Exception ;
  4. utiliser finally et attraper plusieurs types dans un même catch.

1. Erreur et exception

Une erreur (Warning, Notice, Fatal error) signale un problème dans le code : division par zéro, appel d’une méthode inexistante, type inattendu. Une exception est un objet qu’on choisit de lancer pour signaler une situation anormale et la laisser à un autre niveau décider quoi en faire.

La différence est le contrôle : l’erreur est subie, l’exception se déclenche avec throw et peut être capturée avec try/catch.

Exception est un objet

Une exception possède un message (getMessage()), un code, le fichier et la ligne. La lancer ne l’affiche pas : tant que personne ne l’attrape, PHP termine le script avec un message d’erreur non capturé.

2. Lancer et attraper

On protège le code risqué dans un bloc try et on prévoit la suite dans un bloc catch. throw déclenche l’exception ; le premier catch compatible la reçoit.

function diviser(int $a, int $b): int {
    if ($b === 0) {
        throw new Exception("division par zéro");
    }
    return intdiv($a, $b);
}

try {
    echo diviser(10, 0);
} catch (Exception $e) {
    echo "erreur : " . $e->getMessage();
}

Le code du catch n’est exécuté que si une exception est lancée ; jamais deux fois, et jamais sans throw.

3. Exceptions personnalisées

Une exception personnalisée est une classe qui étend Exception. On peut l’attraper précisément : un catch (SoldeInsuffisant $e) ne réagit qu’à ce type.

class SoldeInsuffisant extends Exception {}

function retirer(float $solde, float $montant): float {
    if ($montant > $solde) {
        throw new SoldeInsuffisant("solde insuffisant");
    }
    return $solde - $montant;
}
Piège — attraper trop large

catch (Exception $e) attrape tout, y compris des erreurs qu’on ne savait pas prévoir. Préférer des types précis permet de distinguer un problème métier (« solde insuffisant ») d’un problème technique inattendu.

4. finally et multi-catch

Plusieurs types peuvent être regroupés dans un seul catch avec le tube (|). Le bloc finally, enfin, s’exécute dans tous les cas — succès ou exception — ce qui le rend idéal pour fermer une ressource.

try {
    verifier($saisie);
} catch (InvalidArgumentException | RangeException $e) {
    echo "saisie invalide";
} finally {
    echo "controle termine";
}

L’ordre compte : PHP teste les catch dans l’ordre écrit. Un type fils doit donc être attrapé avant un type parent, sinon il est masqué.

Exercice 1 — Attraper une exception

PHP Niveau 2 — Application

Objectif : Protéger un calcul risqué par un bloc try/catch.

Le programme reçoit deux entiers a puis b. Écris une fonction diviser(int $a, int $b): int qui lève une Exception de message division par zéro quand b vaut 0. Affiche resultat : X au succès, ou erreur : division par zéro si l’exception est attrapée.

Entrée du programme
10
2
Sortie attendue
resultat : 5

Cas nominal.

Deux indices, rédigés en mots
  1. On lève une erreur avec throw new Exception('division par zéro');.
  2. Le résultat se calcule avec intdiv($a, $b) ; le bloc catch (Exception $e) récupère le message via $e->getMessage().

Exercice 2 — Exception personnalisée

PHP Niveau 2 — Application

Objectif : Étendre Exception et intercepter précisément son type.

Déclare une exception SoldeInsuffisant qui étend Exception. Le programme reçoit un solde puis un montant (entiers). La fonction retirer renvoie le solde restant ou lève SoldeInsuffisant. Affiche reste : X ou erreur : solde insuffisant.

Entrée du programme
100
30
Sortie attendue
reste : 70

Retrait autorisé.

Deux indices, rédigés en mots
  1. Une exception personnalisée est une classe qui hérite : class SoldeInsuffisant extends Exception {}.
  2. On peut lancer une instance avec throw new SoldeInsuffisant('solde insuffisant');.

Exercice 3 — Attraper plusieurs types et conclure

PHP Niveau 3 — Raisonnement

Objectif : Regrouper plusieurs exceptions dans un catch et exécuter un finally.

Le programme reçoit une saisie. Si elle n’est pas numérique, lève une InvalidArgumentException ; si elle est négative, une RangeException. Attrape les deux types dans un même catch et affiche saisie invalide. Sinon affiche valeur : X. Un bloc finally ajoute toujours controle termine.

Entrée du programme
7
Sortie attendue
valeur : 7
controle termine

Saisie valide suivie du finally.

Deux indices, rédigés en mots
  1. Plusieurs types se regroupent avec un tube : catch (InvalidArgumentException | RangeException $e).
  2. Le bloc finally s’exécute dans tous les cas, après le try ou le catch.

6. QCM — niveau examen

Comment lance-t-on une exception ?

On lance avec throw new Exception(…).

Que fait un bloc catch ?

catch intercepte une exception du type indiqué.

Une exception personnalisée…

Elle hérite d’Exception pour être attrapable précisément.

Quand s’exécute finally ?

finally s’exécute après le try ou le catch, quoi qu’il arrive.

Que fait `catch (A | B $e)` ?

Le tube regroupe plusieurs types dans un même catch.

Comment lire le message d’une exception ?

On appelle la méthode getMessage() de l’objet exception.

Attraper (Exception $e) attrape…

Exception est la racine : elle attrape très large, parfois trop.

Que fait une exception non attrapée ?

Sans catch, PHP affiche une erreur fatale "Uncaught".

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre erreur (subie) et exception (lancée volontairement).
  • Utiliser catch (Exception $e) là où un type précis serait plus sûr.
  • Oublier $e->getMessage() et tenter $e->message.
  • Placer un catch parent avant un fils : le fils devient inatteignable.
  • Croire que finally ne s’exécute qu’en cas d’exception.

8. Méthodologie de résolution

Rendre un programme robuste
  1. Repérer le point où une situation invalide doit être signalée.
  2. Lancer une exception typée avec un message clair (le plus précis possible).
  3. Protéger l’appel dans un try et prévoir les types attendus dans les catch.
  4. Réagir : corriger, journaliser, ou laisser remonter selon le niveau.
  5. Nettoyer dans finally (fermeture de ressource, remise en état).

9. Révision active

Résumé essentiel
  • Une erreur est subie ; une exception se lance avec throw et s’attrape avec catch.
  • Une exception est un objet : message via getMessage(), plus code, fichier et ligne.
  • Une exception personnalisée étend Exception pour être attrapée précisément.
  • catch (A | B $e) regroupe plusieurs types ; l’ordre des catch importe.
  • finally s’exécute dans tous les cas, succès comme échec.

Checklist de maîtrise

  • Je sais quand lancer une exception plutôt que retourner un code d’erreur.
  • J’écris un try/catch qui lit le message de l’exception.
  • Je crée une exception personnalisée et l’attrape précisément.
  • J’utilise finally et le multi-catch à bon escient.
