Chapitre 6 — PDO, dépôt de données et architecture

Module 6 ≈ 3 h de travail Réservé B2 et plus
Mise en situation

Une application objet finit toujours par parler à une base de données. Le faire proprement, c’est séparer le code qui décrit les données (les objets) de celui qui les range (le dépôt), et ne jamais concaténer une entrée utilisateur dans une requête SQL. Ce dernier point sépare une application sûre d’une faille béante.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. ouvrir une connexion PDO avec un DSN et le mode erreur par exception ;
  2. écrire une requête préparée et lier ses paramètres ;
  3. isoler l’accès aux données dans une classe de dépôt ;
  4. assembler un petit service (liste de tâches) en couches.

1. Se connecter avec PDO

PDO (PHP Data Objects) est une couche d’accès unique pour MySQL, PostgreSQL, SQLite… On ouvre une connexion avec un DSN (Data Source Name) qui décrit le driver et la cible.

$pdo = new PDO("sqlite::memory:");
$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

Le mode ERRMODE_EXCEPTION est essentiel : sans lui, une requête qui échoue renvoie simplement false et l’erreur passe inaperçue. Avec, chaque incident lève une PDOException qu’on peut intercepter.

Le DSN, mode d’emploi

Le DSN a la forme driver:paramètres — par exemple mysql:host=localhost;dbname=app ou sqlite:ma-base.sqlite. Le même code PHP fonctionne avec plusieurs bases en changeant seulement le DSN.

2. Requêtes préparées contre l’injection SQL

Ne jamais concaténer une entrée dans le SQL : une apostrophe bien placée suffit à détourner la requête (injection SQL). Une requête préparée sépare le modèle SQL des valeurs, liées ensuite comme paramètres.

$stmt = $pdo->prepare("INSERT INTO contacts (nom) VALUES (:nom)");
$stmt->execute([":nom" => $nom]);

Le pilote traite la valeur $nom comme une donnée, jamais comme du SQL. C’est la protection de référence, et ce n’est pas plus compliqué à écrire.

Piège — l’injection par concaténation

"SELECT * FROM users WHERE nom = '" . $nom . "'" est une porte ouverte : si $nom vaut a' OR '1'='1, la condition devient toujours vraie. La requête préparée ferme cette porte.

3. Le patron dépôt (repository)

Un dépôt est une classe dont le seul métier est l’accès aux données d’un type d’entité : ajouter, lister, compter, retrouver. Le reste de l’application parle au dépôt, pas à PDO.

class ContactDepot {
    private $pdo;

    public function __construct(PDO $pdo) {
        $this->pdo = $pdo;
    }

    public function ajouter(string $nom): void {
        $stmt = $this->pdo->prepare("INSERT INTO contacts (nom) VALUES (:nom)");
        $stmt->execute([":nom" => $nom]);
    }
}

Avantage : le jour où la base change ou où l’on passe à des données en mémoire, seul le dépôt bouge. Le reste du code ne connaît pas PDO.

4. Architecture en couches et projet

Une application se découpe en couches : les entités (les objets métier), le dépôt (les données), le service (les règles) et l’affichage. Chaque couche ne connaît que la suivante. Le mini-projet ToDo List de ce chapitre assemble exactement cela : une entité tâche, une liste qui la gère, et un rendu numéroté.

class TodoList {
    private $taches = [];

    public function ajouter(string $tache): void {
        $this->taches[] = $tache;
    }

    public function lister(): array {
        return $this->taches;
    }
}
Cahier des charges du projet

Le projet lit un nombre de tâches puis les tâches elles-mêmes, les range dans une liste et les affiche numérotées de 1 à n. Il exerce la lecture d’entrée, l’encapsulation d’un tableau dans une classe, et la mise en forme — les trois gestes d’une application en couches.

Exercice 1 — Insérer avec une requête préparée

PHP Niveau 2 — Application

Objectif : Ouvrir une base sqlite en mémoire, créer une table et insérer sans concaténation.

Le programme reçoit un nom. Ouvrez une connexion sqlite::memory: (mode erreur par exception), crée la table contacts(id, nom), insère le nom avec une requête préparée, puis relis-le et affiche contact : nom.

Entrée du programme
Ada
Sortie attendue
contact : Ada

Nom stocké puis relu.

Deux indices, rédigés en mots
  1. On prépare le modèle une fois : $stmt = $pdo->prepare('INSERT INTO contacts (nom) VALUES (:nom)'); puis $stmt->execute([':nom' => $nom]);.
  2. La lecture se fait simplement : $pdo->query('SELECT nom FROM contacts LIMIT 1')->fetchColumn().

Exercice 2 — Un dépôt en mémoire

PHP Niveau 2 — Application

Objectif : Isoler l’accès aux données dans une classe de dépôt.

La première ligne donne un entier n, puis n lignes donnent des entiers. Écrivez une classe Depot qui expose ajouter(int $valeur): void et somme(): int. Range les valeurs reçues puis affiche somme : total.

Entrée du programme
3
1
2
3
Sortie attendue
somme : 6

Trois valeurs additionnées.

Deux indices, rédigés en mots
  1. ajouter() empile dans le tableau privé : $this->valeurs[] = $valeur;.
  2. somme() peut utiliser array_sum($this->valeurs).

Exercice 3 — Mini projet : liste de tâches

PHP Niveau 3 — Raisonnement

Objectif : Assembler une classe de service et une mise en forme numérotée.

Mini application ToDo : la première ligne donne un entier n, puis n lignes donnent des tâches. Écrivez une classe TodoList exposant ajouter(string $tache): void et lister(): array. Affichez chaque tâche numérotée à partir de 1, au format 1. tâche.

Entrée du programme
1
Faire les courses
Sortie attendue
1. Faire les courses

Une seule tâche.

Deux indices, rédigés en mots
  1. Pour numéroter, parcours le tableau avec foreach ($todo->lister() as $i => $tache) et affiche ($i + 1) . '. ' . $tache.
  2. La concaténation se termine par un retour à la ligne pour éviter que tout s’affiche sur une seule ligne.

6. QCM — niveau examen

Que signifie PDO ?

PDO est la couche d’accès aux bases de données de PHP.

Qu’est-ce qu’un DSN ?

Le DSN décrit le driver et la cible de la connexion.

Pourquoi ERRORMODE_EXCEPTION ?

Sans ce mode, une requête échouée renvoie false en silence.

Que protège une requête préparée ?

Elle sépare le SQL des valeurs, empêchant l’injection.

Comment lie-t-on un paramètre nommé ?

On passe un tableau associatif à execute().

À quoi sert un dépôt (repository) ?

Il centralise les accès à la base pour un type d’entité.

Que reçoit un dépôt à sa construction ?

On lui injecte la connexion PDO, qu’il utilise en interne.

Combien de couches distingue-t-on ici ?

Chaque couche ne connaît que la suivante : entités, dépôt, service, affichage.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Concaténer une entrée utilisateur dans une requête SQL (injection).
  • Oublier ERRMODE_EXCEPTION et ignorer les échecs silencieux.
  • Mélanger requêtes SQL et logique métier dans la même classe.
  • Laisser PDO se propager dans tout le code au lieu de l’isoler dans un dépôt.
  • Oublier d’échapper le nom d’un paramètre (:nom) dans execute().

8. Méthodologie de résolution

Construire une application en couches
  1. Modéliser l’entité métier en premier (une classe, pas une table).
  2. Ouvrir une connexion PDO en mode exception, avec un DSN clair.
  3. Préparer chaque requête et lier les valeurs (jamais de concaténation).
  4. Enfermer les accès dans un dépôt qui expose des méthodes métier.
  5. Assembler le service et l’affichage, puis tester avec des cas limites.

9. Révision active

Résumé essentiel
  • PDO connecte PHP à la base via un DSN ; le mode exception rend les erreurs visibles.
  • Une requête préparée sépare le SQL des valeurs : c’est la protection contre l’injection.
  • Un dépôt isole l’accès aux données d’une entité derrière des méthodes claires.
  • Une application se découpe en couches : entités, dépôt, service, affichage.
  • Le projet ToDo List assemble liste, ajout et rendu numéroté.

Checklist de maîtrise

  • J’ouvre une connexion PDO avec un DSN et le mode exception.
  • J’écris une requête préparée avec un paramètre nommé.
  • Je sais pourquoi la concaténation SQL est dangereuse.
  • J’organise mon code en couches autour d’un dépôt.
