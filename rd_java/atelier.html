Atelier de code

Un éditeur dans la page, un vrai compilateur Java derrière. Écris une classe, exécute-la et lis ce qu’elle affiche : c’est ici qu’une règle du langage devient un programme qui tourne.

Comment fonctionne l’atelier
  • Exécuter fait compiler et tourner votre programme Java tel quel, et affiche sa sortie, ses erreurs et son code de sortie.
  • Entrée du programme contient ce que Scanner lira, une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le programme sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Objectif : expérimenter sans conséquence. Reprends un mécanisme du cours (boucle, tableau, classe, exception) et programme-le sur des cas limites.

Le programme proposé calcule le carré d’un entier lu en entrée. Modifie-le, ajoute une boucle, une méthode, une classe personnalisée, ou remplace tout le programme par le mécanisme que tu veux vérifier — une ArrayList triée, un héritage, un try/catch.

Dans un vrai projet, ce sera une classe métier, un service, un point d’entrée : la structure du programme — lire, traiter, afficher — reste exactement la même.

De la page au vrai projet

La simulation a une limite assumée : rien n’est envoyé ni stocké durablement. Elle a une force : toute la logique se vérifie sans projet local. Quand le programme affiche les bons résultats sur tes cas limites, le portage est mécanique : la même classe, la même boucle, la même exception.

Les trois erreurs que l’atelier révèle immédiatement
  • Point-virgule oublié : la compilation s’arrête avant même l’exécution.
  • Division entière : 7 / 2 donne 3, pas 3.5.
  • Exception non attrapée : le programme s’arrête net sur une trace.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service de compilation et d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices Java corrigés automatiquement dans la page. Une fois l’atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme est vraiment acquis.
