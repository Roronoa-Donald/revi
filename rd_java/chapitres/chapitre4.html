Chapitre 4 — Classes, objets et encapsulation

Module 4 ≈ 3 h de travail Réservé B2 et plus
Mise en situation

Un tableau transporte des valeurs, mais rien ne garantit leur cohérence. La classe décrit la forme d’une donnée ; l’objet en est une instance. L’encapsulation protège l’état derrière des méthodes qui le contrôlent.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. déclarer une classe avec ses attributs et son constructeur ;
  2. créer des objets avec new et appeler leurs méthodes ;
  3. protéger l’état avec private et des getters/setters ;
  4. redéfinir toString() pour afficher un objet.

1. Classe, objet et constructeur

Une classe décrit les attributs (l’état) et les méthodes (les comportements) d’un type. Le constructeur porte le nom de la classe et initialise l’objet.

class Rectangle {
    private final int largeur;
    private final int hauteur;

    Rectangle(int largeur, int hauteur) {
        this.largeur = largeur;
        this.hauteur = hauteur;
    }

    int aire() {
        return largeur * hauteur;
    }
}

On crée un objet avec new : Rectangle r = new Rectangle(4, 5);. this désigne l’objet courant, notamment pour distinguer un attribut d’un paramètre de même nom.

2. Encapsulation et visibilité

Les mots-clés de visibilité décident qui accède à un membre : public (tout le monde), private (la classe seule), protected (la classe et ses filles). L’encapsulation met les attributs en private et n’ouvre que des méthodes contrôlées.

private int solde;

public int getSolde() {
    return solde;
}

public void setSolde(int solde) {
    if (solde < 0) {
        throw new IllegalArgumentException("solde négatif");
    }
    this.solde = solde;
}
Piège — l’attribut public

Un attribut public se modifie de n’importe où, sans contrôle : un solde négatif peut entrer par la porte de service. Le setter, lui, refuse la valeur avant de l’affecter.

3. Affichage d’un objet

Par défaut, afficher un objet montre son type et son adresse, illisibles. On redéfinit toString() avec l’annotation @Override pour lui donner un sens.

@Override
public String toString() {
    return "(" + x + ", " + y + ")";
}

System.out.println(unPoint) appelle alors automatiquement cette méthode.

4. Construire un objet complet

Une bonne classe garantit qu’un objet ne peut pas exister dans un état invalide. Le constructeur range les valeurs obligatoires ; les setters valident celles qui changent.

class Personne {
    private final String nom;
    private int age;

    Personne(String nom, int age) {
        this.nom = nom;
        this.age = age;
    }

    String getNom() { return nom; }
    int getAge() { return age; }
}
Un objet, un contrat

Une classe bien faite répond à une question : « qu’est-ce qu’une Personne valide ? ». En verrouillant les propriétés qui ne changent pas (final) et en validant les autres, elle rend les bugs d’état impossibles plutôt que difficiles à trouver.

6. QCM — niveau examen

Qu’est-ce qu’une classe ?

La classe décrit attributs et méthodes ; new produit des instances.

Comment s’appelle le constructeur ?

Le constructeur porte le nom de la classe.

Que fait new ?

new instancie et appelle le constructeur.

Que désigne this ?

this référence l’instance en cours.

Que fait private ?

private n’est accessible que depuis la classe elle-même.

À quoi sert un setter ?

Le setter contrôle la valeur avant de l’affecter.

Que fait @Override sur toString ?

println appelle alors cette version de toString.

Que signifie final sur un attribut ?

final fige la valeur une fois le constructeur passé.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier this. dans le constructeur quand le paramètre a le même nom.
  • Laisser un attribut public alors qu’il devrait être contrôlé.
  • Affecter avant de valider dans un setter.
  • Afficher un objet sans toString() et lire une adresse illisible.
  • Réaffecter un attribut final.

8. Méthodologie de résolution

Écrire une classe propre
  1. Nommer l’entité métier, pas la table de données.
  2. Lister les attributs qui décrivent un objet complet.
  3. Écrire le constructeur qui range les valeurs reçues.
  4. Fermer les attributs en private et ouvrir getters/setters utiles.
  5. Redéfinir toString() pour un affichage lisible.

9. Révision active

Résumé essentiel
  • Une classe décrit état (attributs) et comportements (méthodes).
  • Le constructeur initialise ; new crée l’objet.
  • this désigne l’objet courant.
  • public/private/protected décident de la visibilité ; private protège l’état.
  • Un setter valide avant d’affecter ; toString() rend l’affichage lisible.

Checklist de maîtrise

  • Je protège mes attributs en private.
