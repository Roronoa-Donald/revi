Chapitre 5 — Collections, héritage et polymorphisme

Module 5 ≈ 3 h de travail Réservé B2 et plus
Mise en situation

Les applications manipulent des ensembles de données et des familles d’objets qui partagent un comportement commun. Les collections rangent les données ; l’héritage factorise le code entre types proches, et le polymorphisme laisse chaque type répondre à sa manière.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. choisir entre List, Set et Map selon le besoin ;
  2. factoriser par héritage avec extends et super ;
  3. redéfinir une méthode et en tirer du polymorphisme ;
  4. écrire une classe abstraite comme contrat partiel.

1. List, Set et Map

Le framework Collections propose trois familles. List garde l’ordre et autorise les doublons ; Set élimine les doublons ; Map associe chaque clé à une valeur.

import java.util.*;

List<String> liste = new ArrayList<>();
Set<Integer> ensemble = new HashSet<>();
Map<String, Integer> ages = new HashMap<>();
ages.put("Ada", 36);

Pour compter des valeurs distinctes, un Set est l’outil direct : ensemble.size() après avoir ajouté les éléments.

2. Héritage : extends et super

Une classe fille hérite d’une classe mère avec extends. Elle récupère ses attributs et méthodes, et appelle son constructeur avec super(...).

class Animal {
    protected final String nom;

    Animal(String nom) {
        this.nom = nom;
    }
}

class Chien extends Animal {
    Chien(String nom) {
        super(nom);
    }
}
Piège — super oublié

Si la classe mère n’a pas de constructeur vide, la classe fille doit appeler super(...) en première ligne de son propre constructeur. L’oublier casse la compilation.

3. Redéfinition et polymorphisme

Une fille peut redéfinir une méthode héritée avec @Override. Une variable de type mère peut alors référencer un objet fille : c’est le polymorphisme, la version exécutée étant celle du type réel de l’objet.

class Chien extends Animal {
    @Override
    String crier() {
        return "Wouf";
    }
}

Animal a = new Chien("Rex");
a.crier();   // "Wouf", la version de Chien

C’est ce mécanisme qui permet de traiter une collection d’animaux différents avec un seul appel.

4. Classes abstraites

Une classe abstraite décrit un squelette incomplet : elle peut déclarer des méthodes abstraites que les filles devront implémenter. On ne peut pas l’instancier directement.

abstract class Forme {
    abstract double aire();
}

class Carre extends Forme {
    private final double cote;
    Carre(double cote) { this.cote = cote; }
    double aire() { return cote * cote; }
}
Un contrat, pas un code

Une classe abstraite dit « toute forme sait calculer son aire », sans dire comment. Chaque fille fournit sa formule. L’appelant, lui, n’a besoin que de connaître Forme.

Exercice 1 — Mots distincts

Java Niveau 2 — Application

Objectif : Utiliser une collection pour éliminer les doublons.

Le programme reçoit un entier n, puis n mots. Affichez mots distincts : X où X est le nombre de mots différents.

Entrée du programme
4
a
b
a
c
Sortie attendue
mots distincts : 3

a, b et c : trois mots différents.

Deux indices, rédigés en mots
  1. Un Set ne garde qu’une copie de chaque valeur : vus.add(sc.next()) suffit.
  2. La taille de l’ensemble (vus.size()) est exactement le nombre de mots distincts.

Exercice 2 — Formes et polymorphisme

Java Niveau 3 — Raisonnement

Objectif : Définir une classe abstraite et faire varier le comportement par héritage.

Le programme reçoit un type (carre ou cercle) puis un nombre décimal. Écrivez une classe abstraite Forme avec une méthode aire(), puis Carre (côté) et Cercle (rayon, aire = π·r²). Affichez aire : X.XX avec deux décimales (séparateur point).

Entrée du programme
carre
4
Sortie attendue
aire : 16.00

Un carré de côté 4.

Deux indices, rédigés en mots
  1. Une classe abstraite déclare abstract double aire(); chaque fille l’implémente.
  2. Choisissez avec type.equals("carre") ? new Carre(valeur) : new Cercle(valeur), puis formate avec Locale.US.

Exercice 3 — Héritage : Animal et Chien

Java Niveau 2 — Application

Objectif : Utiliser extends, super et la redéfinition de méthode.

Le programme reçoit un prénom. Écrivez une classe Animal avec un attribut nom et une méthode crier() renvoyant ..., puis une classe Chien extends Animal qui redéfinit crier() pour renvoyer Wouf. Affichez nom dit Wouf en utilisant la méthode sePresente() de Animal.

Entrée du programme
Rex
Sortie attendue
Rex dit Wouf

L’animal Rex est un chien.

Deux indices, rédigés en mots
  1. La redéfinition utilise @Override String crier() { return "Wouf"; }.
  2. Le polymorphisme joue son rôle : animal.sePresente() appelle la version de Chien pour crier().

6. QCM — niveau examen

Quelle collection élimine les doublons ?

Un Set ne garde qu’une copie de chaque valeur.

Quelle collection associe clés et valeurs ?

Map associe chaque clé à une valeur.

Que fait extends ?

extends établit la relation classe fille → classe mère.

À quoi sert super(...) ?

super transmet l’initialisation à la classe mère.

Que fait @Override ?

Il redéfinit la version de la classe mère.

Le polymorphisme permet…

La méthode exécutée est celle du type réel de l’objet.

Peut-on instancier une classe abstraite ?

Une classe abstraite ne peut pas être instanciée directement.

Que doit fournir une classe fille d’une méthode abstraite ?

La fille doit implémenter toute méthode abstraite.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre List (ordonné, doublons) et Set (pas de doublons).
  • Oublier super(...) dans le constructeur d’une classe fille.
  • Redéfinir une méthode sans l’annotation @Override et se tromper de signature.
  • Tenter new sur une classe abstraite.
  • Comparer deux chaînes avec == au lieu de .equals().

8. Méthodologie de résolution

Structurer entre collections et héritage
  1. Choisir la collection : List, Set ou Map.
  2. Identifier le comportement commun à factoriser.
  3. Écrire la classe mère (ou abstraite) et ses méthodes.
  4. Redéfinir dans les filles avec @Override.
  5. Programmer contre le type mère pour bénéficier du polymorphisme.

9. Révision active

Résumé essentiel
  • List garde l’ordre et les doublons ; Set les élimine ; Map associe clé et valeur.
  • extends hérite ; super(...) appelle le constructeur de la mère.
  • Une fille redéfinit une méthode avec @Override.
  • Le polymorphisme exécute la version du type réel de l’objet.
  • Une classe abstraite ne s’instancie pas : elle fixe un contrat.

Checklist de maîtrise

  • Je choisis la collection adaptée au besoin.
  • J’écris une relation d’héritage correcte avec super.
  • Je redéfinis une méthode et je m’appuie sur le polymorphisme.
  • Je déclare une classe abstraite quand elle a des méthodes à implémenter.
