Atelier de code

Un éditeur dans la page, un vrai interpréteur PowerShell derrière. Écris un script d’administration, exécute-le et lis ce qu’il affiche : c’est ici qu’une règle du cours devient un script qui tourne.

Comment fonctionne l’atelier
  • Exécuter fait tourner votre script PowerShell tel quel, et affiche sa sortie, ses erreurs et son code de sortie.
  • Entrée du programme contient ce que lira [Console]::In.ReadLine(), une valeur par ligne.
  • Expliquer mon erreur demande au tuteur, quand il y a une erreur, pourquoi elle survient et par où chercher. Il explique en mots : il n’écrit jamais de code à votre place.
  • Le raccourci Ctrl + Entrée exécute le script sans quitter l’éditeur.
  • Votre code est conservé dans ce navigateur, par exercice et par cours.

Objectif : expérimenter sans conséquence. Reprends un mécanisme du cours (condition, boucle, switch) et programme-le sur des cas limites.

Le script proposé totalise des tailles de sauvegarde lues en entrée. Modifie-le, ajoute une condition, un switch, remplace tout le script par le mécanisme que tu veux vérifier — un test de quorum, un seuil de température, un mode réseau.

Dans un vrai serveur, ce sera un script d’administration planifié : la structure — lire, traiter, afficher — reste exactement la même.

De la page au vrai serveur

La simulation a une limite assumée : rien n’est envoyé ni stocké durablement. Elle a une force : toute la logique se vérifie sans machine Windows. Quand le script affiche les bons résultats sur tes cas limites, le portage est mécanique : les mêmes variables, la même boucle, le même test.

Les trois erreurs que l’atelier révèle immédiatement
  • Comparaison avec == : PowerShell compare les chaînes avec -eq, pas ==.
  • Boucle infinie : un $i jamais incrémenté fait tourner le script sans fin.
  • Type d’entrée : sans [int], une valeur lue reste du texte.
Ce que fait l’atelier, côté technique
  • Votre code est envoyé à ce serveur, qui le transmet à un service d’exécution isolé : rien ne tourne sur votre machine, et aucun accès au système n’est possible.
  • La clé du service reste sur le serveur ; le navigateur ne la voit jamais.
  • Le nombre d’exécutions est limité par jour, pour tout le monde. L’atelier n’exécute donc que sur un clic.

Ensuite

Les 6 chapitres contiennent chacun trois exercices corrigés dans la page. Une fois l’atelier apprivoisé, ils sont la meilleure façon de vérifier que le mécanisme est vraiment acquis.
