Chapitre 5 — Virtualisation & VMware

Module 5 ≈ 2 h 30 de travail Réservé B2 et plus
Mise en situation

Plutôt que d’installer un serveur par machine, on exécute plusieurs machines virtuelles sur un même hôte. Comprendre l’hyperviseur, les réseaux virtuels et l’allocation de ressources est la base de toute infrastructure moderne.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. distinguer hyperviseur de type 1 et de type 2 ;
  2. situer ESXi, vCenter et vSphere Client ;
  3. comparer les modes réseau NAT, Bridge et Host-Only ;
  4. interpréter vCPU, CPU Ready Time et thin provisioning.

1. Hyperviseur de type 1 et de type 2

Un hyperviseur est un logiciel qui crée et gère des machines virtuelles (VM). On en distingue deux familles :

TypeDescriptionExemples
Type 1 (bare-metal)Virtualise directement sur le matériel, sans OS intermédiaireVMware ESXi
Type 2 (hébergé)S’installe sur un OS existant (Windows, Linux, macOS)VMware Workstation, VirtualBox

Dans un environnement VMware professionnel : ESXi est l’hyperviseur qui héberge les VM, vCenter gère centralement plusieurs hôtes et les clusters, vSphere Client est l’interface web d’administration.

Un exemple concret

Max ouvre vSphere Client, choisit un hôte ESXi, alloue 2 vCPU, 8 Go de RAM et 100 Go de stockage, puis crée une VM Ubuntu Server. Tout le provisionnement passe par l’interface web ; ESXi exécute, vCenter orchestre.

2. Les réseaux virtuels

Une VM se connecte au réseau selon trois modes principaux :

  • NAT : la VM sort via l’adresse de l’hôte, qui sert de passerelle. Accès Internet sécurisé, mais la VM n’est pas joignable depuis le réseau local.
  • Bridge (pont) : la VM se comporte comme une machine physique du réseau, avec sa propre adresse obtenue par DHCP. Elle est accessible partout.
  • Host-Only : réseau privé entre l’hôte et les VM, sans Internet par défaut. Idéal pour des environnements de test isolés.

3. Images disque

Une image disque est un fichier qui représente tout le contenu d’un disque dur ou d’un support optique.

  • ISO : image d’un disque optique (CD/DVD), copie secteur par secteur. Sert à installer un système dans une VM.
  • VMDK : format principalement utilisé par VMware ; peut être thick (espace réservé d’avance) ou thin (alloué dynamiquement).
  • VHD / VHDX : format Microsoft, utilisé surtout avec Hyper-V. VHDX est la version améliorée, plus tolérante aux erreurs.
Thin provisioning

Le thin provisioning n’alloue que l’espace réellement utilisé : la VM s’agrandit au fil du temps. Le thick réserve tout de suite l’espace complet. Le premier économise le stockage, le second garantit l’espace.

4. vCPU, CPU Ready Time et surallocation

Un vCPU est un processeur virtuel alloué à une VM ; il correspond à un cœur (ou un thread) du processeur de l’hôte. Une VM peut en recevoir plusieurs.

Le CPU Ready Time mesure le temps qu’une VM attend pour obtenir du temps processeur : c’est l’indicateur clé de contention CPU dans VMware.

La surallocation (overcommit) survient quand le total de vCPU alloués dépasse le nombre de cœurs physiques. Conséquence principale : le CPU Ready Time s’allonge et les performances se dégradent.

Allouer plus n’est pas mieux

Donner 8 vCPU à une VM qui n’en utilise que 2 ne la rend pas plus rapide : cela crée de l’attente pour tout le monde. On dimensionne les ressources, on ne les empile pas.

6. QCM — niveau examen

Qu’est-ce qu’un hyperviseur ?

Il crée et exécute des machines virtuelles.

L’hyperviseur de type 1 s’installe…

C’est un hyperviseur bare-metal.

Exemple d’hyperviseur de type 1 ?

ESXi s’exécute directement sur le serveur.

Rôle de vCenter ?

Il administre plusieurs hôtes et les clusters.

En NAT, la VM est-elle accessible depuis le LAN ?

Elle sort via l’hôte mais n’est pas joignable de l’extérieur.

Quel mode met la VM sur le même réseau que l’hôte ?

Le pont intègre la VM au réseau physique.

Quel format pour VMware ?

VMDK est le format de disque de VMware.

Que mesure le CPU Ready Time ?

Il indique la contention CPU.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Confondre hyperviseur de type 1 (bare-metal) et de type 2 (hébergé).
  • Attendre qu’une VM en NAT soit joignable depuis le réseau local.
  • Confondre VMDK (VMware) et VHDX (Microsoft).
  • Surallouer les vCPU et dégrader le CPU Ready Time de tous.
  • Croire que thin provisioning réserve l’espace à l’avance.

8. Méthodologie de résolution

Provisionner et connecter une VM
  1. Choisir l’hyperviseur : type 1 en production, type 2 pour le poste de travail.
  2. Gérer l’infrastructure avec vCenter et vSphere Client.
  3. Connecter la VM selon le besoin : NAT, Bridge ou Host-Only.
  4. Sélectionner le format d’image adapté (ISO, VMDK, VHDX).
  5. Dimensionner les vCPU sans surallocation excessive.

9. Révision active
