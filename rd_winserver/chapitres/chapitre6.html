Chapitre 6 — Windows Server Backup (wbadmin, VSS), FSRM, WSUS, Surveillance & Snapshots VM

Mise en situation

En production sous Windows Server B2, la continuité opérationnelle repose sur des outils natifs incontournables : sauvegarder l’état du système et le serveur nu avec Windows Server Backup (wbadmin) et les clichés instantanés VSS, maîtriser la volumétrie et bloquer les extensions dangereuses avec le Gestionnaire de ressources du serveur de fichiers (FSRM), orchestrer les correctifs via WSUS, corréler les événements et compteurs de performance, et encadrer les snapshots et migrations de VM.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. mettre en œuvre Windows Server Backup (wbadmin, System State, Bare-Metal Recovery et clichés instantanés VSS) ;
  2. configurer le Gestionnaire de ressources du serveur de fichiers (FSRM : quotas stricts/souples et filtrage de fichiers actif/passif) ;
  3. administrer le déploiement de correctifs avec WSUS et surveiller les événements (Event Viewer / Get-WinEvent) et performances (Performance Monitor) ;
  4. définir un snapshot (checkpoint Hyper-V standard vs production) et le distinguer d’une sauvegarde ;
  5. comparer clone complet et clone lié, expliquer l’usage d’un template et situer vMotion, le cluster HA et la sauvegarde Veeam.

1. Sauvegarde et restauration Windows Server Backup (wbadmin, Bare-Metal Recovery et clichés instantanés VSS)

La fonctionnalité native Windows Server Backup (installée via Install-WindowsFeature Windows-Server-Backup) s’appuie sur le service VSS (Volume Shadow Copy Service) pour réaliser des sauvegardes à chaud cohérentes sans interrompre Active Directory ni les bases de données :

  • Architecture des clichés instantanés VSS : le VSS Requestor (wbadmin ou agent tiers) interroge les VSS Writers applicatifs (NTDS pour Active Directory, SQL Server, Hyper-V) afin de purger les tampons en mémoire et de geler brièvement les écritures pendant que le VSS Provider prend un cliché instantané (Shadow Copy) en lecture seule du volume. Sur les partages de fichiers, les clichés VSS permettent aussi aux utilisateurs de restaurer leurs Versions précédentes (Previous Versions) en autonomie.
  • Sauvegarde System State (État du système) : wbadmin start systemstatebackup -backupTarget:E: -quiet sauvegarde la base Active Directory (ntds.dit), le dossier SYSVOL, le Registre, les fichiers système protégés et la base de certificats AD CS. En cas de suppression accidentelle d’une OU, on redémarre en mode DSRM (Directory Services Restore Mode) pour exécuter une restauration non-autoritative suivie d’un marquage autoritatif via ntdsutil.
  • Bare-Metal Recovery (BMR — Restauration sur matériel vierge) : wbadmin start backup -backupTarget:\\nas\backups -allCritical -systemState -vssFull -quiet capture l’intégralité des volumes critiques, la partition EFI/boot et l’état système pour reconstruire le serveur à l’identique sur un nouveau serveur physique ou virtuel depuis l’environnement de récupération Windows RE.
Commandes clés wbadmin et vssadmin en production

Lister les sauvegardes disponibles : wbadmin get versions ; consulter les éléments d’un jeu : wbadmin get items -version:11/15/2026-02:00 ; inspecter les clichés instantanés VSS actifs : vssadmin list shadows et redimensionner l’espace réservé aux clichés : vssadmin resize shadowstorage /for=D: /on=D: /maxsize=20%.

3. Le snapshot

Un snapshot (instantané) permet un retour à un état antérieur de la VM, mais son contenu dépend du produit et du type choisi. Dans Hyper-V, un checkpoint standard capture aussi la mémoire ; un checkpoint de production est créé sans capture de la mémoire, avec VSS ou le gel du système de fichiers invité.

Source : documentation Microsoft des checkpoints Hyper-V, consultée le 30 octobre 2026.

Deux précautions : les snapshots consomment de l’espace disque au fil du temps, et il ne faut pas les conserver longtemps en production.

CritèreSnapshotSauvegarde
ConservationTemporaire (court terme)Long terme
UtilitéRevenir avant/après un changementRestaurer après une perte
Espace disqueConsomme de plus en plusPlanifié
Snapshot n’est pas sauvegarde

Un snapshot vit sur le même stockage que la VM : si le stockage disparaît, le snapshot aussi. Il ne remplace jamais une sauvegarde hors site.

4. Clones complet et lié

Un clone est une copie d’une VM existante. Deux variantes :

  • Clone complet : copie indépendante (fichiers disque et configuration). Il fonctionne même si la VM d’origine est supprimée.
  • Clone lié (linked clone) : la nouvelle VM partage une partie de ses fichiers disque avec l’originale. Moins gourmand en espace, mais dépendant de la source : si elle est supprimée, le clone lié ne fonctionne plus.

IndépendanceTotaleDépend de la source
Espace disquePlus volumineuxMoins gourmand
Si la source est suppriméeContinue de fonctionnerNe fonctionne plus

5. Templates et vMotion

Un template est une VM préconfigurée et souvent figée en lecture seule : système installé, outils de base, paramètres réseau et sécurité prédéfinis. Il sert de modèle pour créer de nouvelles VM, ce qui standardise les déploiements, fait gagner du temps et garantit la cohérence.

vMotion migre une VM en cours d’exécution d’un hôte physique vers un autre en cherchant à limiter l’interruption. Une courte pause de bascule subsiste et peut perturber certaines applications sensibles ; le résultat dépend de la charge, du réseau et de la configuration.

Un template, des déploiements

Un template bien tenu contient les mises à jour et les bases de sécurité à jour. Chaque VM créée en hérite : le déploiement devient reproductible plutôt qu’artisanal.

6. Cluster HA et sauvegarde Veeam

La fonctionnalité essentielle pour la haute disponibilité des VM est le cluster de virtualisation. Avec un cluster HA, les VM redémarrent automatiquement sur un autre hôte disponible en cas de panne, ce qui minimise l’impact des défaillances matérielles.

Veeam est un outil de sauvegarde automatique des VM. Il configure des sauvegardes quotidiennes et permet de restaurer rapidement une VM supprimée par erreur.

Bonnes pratiques : documenter chaque action, surveiller les performances avec vCenter, prendre un snapshot avant chaque mise à jour majeure, configurer des sauvegardes automatiques et activer la HA.

Plusieurs filets, pas un seul

Snapshot pour un retour immédiat, sauvegarde Veeam pour la perte durable, cluster HA pour la panne matérielle : trois protections pour trois menaces différentes. En cumuler plusieurs, c’est couvrir tous les scénarios.

8. QCM — niveau examen

Que capture un checkpoint Hyper-V de production ?

La capture de mémoire caractérise le checkpoint standard, pas le checkpoint de production.

Durée de conservation d’un snapshot ?

Il ne doit pas rester longtemps en production.

Que fait un clone complet ?

Il fonctionne même si la source est supprimée.

Faiblesse d’un clone lié ?

Si la source est supprimée, il cesse de fonctionner.

À quoi sert un template ?

Un template est un modèle de VM préconfigurée : il standardise les déploiements et garantit des machines identiques. Il ne sauvegarde rien et ne migre rien à chaud.

Que fait vMotion ?

vMotion déplace la VM vers un autre hôte en limitant l’interruption — une courte pause de bascule, sans extinction d’hôte ni clonage.

En cas de panne, que fait un cluster HA ?

Les VM redémarrent automatiquement ailleurs.

Que permet Veeam ?

Veeam sauvegarde automatiquement les VM et restaure rapidement — restauration instantanée incluse. Il ne compile aucun code et ne crée aucun réseau.

Quel service Windows Server coordonne les Writers applicatifs (AD DS, SQL) pour capturer une sauvegarde wbadmin cohérente à chaud ?

Le service VSS (Volume Shadow Copy Service) orchestre les Writers applicatifs pour geler proprement les écritures et créer un cliché instantané cohérent.

Dans FSRM, quelle est la différence entre un quota strict (Hard) et un quota souple (Soft) ?

Dans FSRM, un quota strict (Hard Quota) empêche immédiatement d’écrire au-delà de la limite, tandis qu’un quota souple (Soft Quota) laisse l’écriture aboutir mais génère des alertes et événements.

9. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier d’inclure l’état du système (System State) et l’option Bare-Metal Recovery dans la sauvegarde wbadmin des contrôleurs de domaine.
  • Appliquer un filtrage de fichiers FSRM actif en production sans l’avoir d’abord validé en mode passif (audit).
  • Confondre snapshot et sauvegarde : le snapshot ne protège pas d’une perte du stockage.
  • Conserver des snapshots pendant des semaines en production.
  • Supprimer la VM source d’un clone lié, qui cesse alors de fonctionner.

10. Méthodologie de résolution

Sauvegarder, gouverner les ressources (FSRM / WSUS) et protéger les VM
  1. Sauvegarder l’état du système et le serveur nu avec Windows Server Backup (wbadmin) et les clichés instantanés VSS.
  2. Encadrer les partages SMB via FSRM (quotas stricts/souples et filtrage d’extensions actif/passif) et piloter les correctifs par anneaux dans WSUS.
  3. Surveiller proactivement les journaux Event Viewer (Get-WinEvent) et les compteurs Performance Monitor (Get-Counter).
  4. Prendre un snapshot court terme avant tout changement critique, puis le purger après validation.
  5. Protéger durablement les machines virtuelles par les templates, le cluster HA et la sauvegarde Veeam.
