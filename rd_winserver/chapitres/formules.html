Mémo WinServer

Sauvegarde, haute disponibilité, clusters, maintenance, virtualisation et gestion des VM sur une page. À garder ouvert pendant les exercices et l’atelier.

Sauvegarde

  • Complète : tout, restauration simple, lente et volumineuse.
  • Incrémentielle : depuis la dernière sauvegarde, restauration en chaîne.
  • Différentielle : depuis la dernière complète, restauration = complète + dernière diff.
  • 3-2-1 : 3 copies, 2 supports, 1 hors site. Toujours tester la restauration.
  • PCA : continuité sans interruption ; PRA : reprise rapide.

Haute disponibilité

  • Trois piliers : redondance, failover, supervision.
  • SLA : 99 % ≈ 3 j 15 h ; 99,9 % ≈ 8 h 45 ; 99,99 % ≈ 52 min ; 99,999 % ≈ 5 min.
  • Load balancer : répartit la charge, mais à redonder lui aussi.

Clustering

  • Active-passive : un nœud actif, les autres en veille.
  • Active-active : tous actifs, synchronisation complexe.
  • Load balancing : répartition des requêtes.
  • Failover : stockage partagé, reprise automatique des services.
  • Grid : calcul intensif distribué. Quorum = majorité des nœuds.

Maintenance

  • Préventive : éviter les pannes (mises à jour, surveillance, sécurité, matériel).
  • Corrective : réparer après une panne (Restart-Service, ping, tracert, nslookup).
  • Évolutive : moderniser, migrer (2012 R2 → 2016 → 2019 → 2022).
  • Outils : Task Manager, Performance Monitor, Event Viewer, netstat, Wireshark.
  • Température CPU : normal 30-60 °C, danger > 85 °C, critique > 95 °C.

Virtualisation & VMware

  • Type 1 (bare-metal : ESXi) / Type 2 (hébergé : Workstation, VirtualBox).
  • ESXi héberge, vCenter gère, vSphere Client administre.
  • Réseaux : NAT (Internet oui, LAN non), Bridge (oui/oui), Host-Only (non/non).
  • Images : ISO (optique), VMDK (VMware), VHD/VHDX (Microsoft).
  • vCPU, CPU Ready Time (attente CPU), surallocation, thin provisioning.

Snapshots, clones & templates

  • Snapshot : mémoire + CPU + disques, temporaire ; ne remplace pas une sauvegarde.
  • Clone complet : indépendant ; clone lié : dépend de la source.
  • Template : VM préconfigurée, modèle de déploiement standardisé.
  • vMotion : migration à chaud sans interruption.
  • Cluster HA : redémarrage automatique des VM ; Veeam : sauvegarde des VM.

Erreurs fréquentes à éviter

  • Confondre incrémentielle (depuis la dernière) et différentielle (depuis la complète).
  • Prendre un snapshot pour une sauvegarde durable.
  • Laisser un point unique de défaillance (load balancer, alimentation).
  • Supprimer la VM source d’un clone lié.
  • Surallouer les vCPU et dégrader le CPU Ready Time.
  • Conserver des snapshots pendant des semaines.
