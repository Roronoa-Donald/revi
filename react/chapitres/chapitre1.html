Chapitre 1 — Penser en composants & l’écosystème JSX / Vite

Module 1 ≈ 2 h 30 de travail Accès libre
Mise en situation

Face aux interfaces web modernes riches en données et en interactions, manipuler le DOM à la main devient rapidement ingérable et source de bugs. React introduit un modèle déclaratif fondé sur des composants réutilisables orchestrés par un outillage ultra-rapide (Vite).

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. comprendre le paradigme déclaratif par opposition à l’impératif ;
  2. décomposer une interface graphique en une arborescence de composants autonomes ;
  3. maîtriser l’outillage Vite et la structure d’un projet frontend moderne ;
  4. écrire du code JSX valide (Fragments, balises auto-fermantes, className) ;
  5. comprendre le rôle de React.createElement et de createRoot (react-dom).

1. Prérequis intégré : Rappels JavaScript ES6+ indispensables pour React

Les 5 constructions modernes de JavaScript (ES6+) utilisées dans chaque composant React
  • Modules (import / export) : import { useState } from "react" importe une fonction, et export default App expose un composant ;
  • Fonctions fléchées (Arrow Functions) : const doubler = (x) => x * 2 est l’écriture courte de function(x) { return x * 2; } ;
  • Déstructuration (Destructuring) : const { nom, age } = utilisateur (ou function Carte({ titre })) extrait directement les propriétés d’un objet, et const [compteur, setCompteur] = useState(0) extrait les éléments d’un tableau ;
  • Méthodes de tableaux .map() et .filter() : liste.map(item => <li key={item.id}>{item.nom}</li>) transforme chaque donnée en élément JSX sans modifier le tableau d’origine ;
  • Appels asynchrones (fetch & async/await) : permettent d’interroger une API JSON sans bloquer l’interface.

2. Le paradigme déclaratif et le modèle mental de React

Dans le développement web classique (impératif avec JavaScript pur), le développeur indique au navigateur comment modifier l’interface pas à pas : sélectionner un élément avec document.querySelector, changer sa classe, ajouter un écouteur, modifier son texte. Dès que l’application grandit, maintenir la cohérence entre l’état des données et l’affichage devient complexe.

React adopte une approche déclarative : on décrit à quoi l’interface doit ressembler pour un état de données donné (ce que l’on veut). Lorsque les données changent, React recalcule le rendu et met à jour efficacement le DOM réel grâce à son algorithme de réconciliation.

L’interface comme fonction de l’état

La formule fondamentale de React est : UI = f(state). L’interface est le reflet direct et prédictible des données en mémoire à un instant T.

3. L’outillage moderne avec Vite

Pour développer en React, les navigateurs ne comprenant pas directement le JSX, un environnement de compilation est nécessaire. Autrefois dominé par Create React App et Webpack, l’écosystème moderne utilise Vite.

Vite tire parti des modules ES natifs (ESM) du navigateur en phase de développement et du bundler Rollup / esbuild pour offrir un rechargement à chaud (Hot Module Replacement - HMR) quasi instantané.

npm create vite@latest mon-app -- --template react
cd mon-app
npm install
npm run dev
Structure d’un projet Vite + React
  • index.html : point d’entrée HTML contenant la balise <div id="root"></div>.
  • src/main.jsx : point d’entrée JavaScript qui instancie createRoot et monte <App />.
  • src/App.jsx : composant racine de l’application.
  • package.json : dépendances (react, react-dom) et scripts.

4. La syntaxe JSX (JavaScript XML)

Le JSX est une extension syntaxique de JavaScript qui permet d’écrire une structure semblable à du HTML directement dans le code JavaScript des composants.

Sous le capot, le compilateur (Babel ou SWC) transforme chaque balise JSX en un appel à React.createElement(type, props, ...children). Par exemple :

// Ce que vous écrivez en JSX :
const bouton = <button className="btn">Valider</button>;

// Ce qui est exécuté sous le capot :
const bouton = React.createElement('button', { className: 'btn' }, 'Valider');
Les 3 règles strictes du JSX
  1. Une seule racine : un composant doit renvoyer un élément parent unique, ou un Fragment <>...</>.
  2. Fermer toutes les balises : les balises orphelines doivent se terminer par /> (ex. <img />, <input />).
  3. Attributs en camelCase : class devient className, for devient htmlFor, tabindex devient tabIndex.

5. Montage dans le DOM : createRoot

Depuis React 18, le montage d’une application s’effectue avec l’API concurrente de react-dom/client :

import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);

Le mode strict (React.StrictMode) aide à détecter les effets secondaires indésirables en exécutant deux fois certains cycles en mode développement.

6. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Créer un React Element (createElement)

JavaScript Niveau 1 — Acquisition

Objectif : Simuler React.createElement en produisant l'objet virtuel correspondant à une balise et son texte.

En React, React.createElement(type, props, children) génère un objet décrivant un nœud virtuel. Le programme lit une ligne au format type texte (ex. button Valider). Produisez et affichez l'objet JSON correspondant sous la forme {"type":"button","props":{"children":"Valider"}}.

Entrée du programme
button Valider
Sortie attendue
{"type":"button","props":{"children":"Valider"}}

Objet élément simple avec balise button.

Deux indices, rédigés en mots
  1. Utilisez un objet littéral avec la clé type et un sous-objet props contenant children.
  2. Affichez l'objet converti en chaîne avec JSON.stringify(element).

Exercice 2 — Rendu conditionnel JSX

JavaScript Niveau 1 — Acquisition

Objectif : Générer la représentation JSX d'une vue selon l'état de connexion de l'utilisateur.

Dans une application React, une interface s'adapte à l'état. Le script reçoit une ligne : statut identifiant où statut vaut 1 (connecté) ou 0 (anonyme). Si connecté, affichez <Dashboard user="identifiant" /> ; sinon, affichez <LoginForm redirect="/login" />.

Entrée du programme
1 Alice
Sortie attendue
<Dashboard user="Alice" />

Utilisateur connecté avec son prénom.

Deux indices, rédigés en mots
  1. Testez si statut === "1" avec une condition if/else.
  2. Utilisez un template literal avec backticks pour injecter l'identifiant dans la prop user.

Exercice 3 — Décomposition en arbre de composants

JavaScript Niveau 2 — Application

Objectif : Décomposer une maquette en une hiérarchie de composants App, Header, Content et Footer.

Penser en React consiste à découper l'UI en composants indépendants. Le programme lit 3 lignes : le titre (ligne 1), le message (ligne 2) et l'auteur (ligne 3). Affichez l'arborescence textuelle suivante avec 2 espaces d'indentation par niveau :
<App>
  <Header title="TITRE" />
  <Content message="MESSAGE" />
  <Footer author="AUTEUR" />
</App>

Entrée du programme
Accueil
Bienvenue en B2
Equipe Peda
Sortie attendue
<App>
  <Header title="Accueil" />
  <Content message="Bienvenue en B2" />
  <Footer author="Equipe Peda" />
</App>

Arbre complet avec 3 sous-composants.

Deux indices, rédigés en mots
  1. Chaque sous-composant est indenté de deux espaces à l'intérieur de <App> ... </App>.
  2. Veillez à bien respecter les guillemets et les noms exacts des props : title, message, author.

8. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier de fermer une balise orpheline (<img /> ou <input />).
  • Écrire class="..." au lieu de className="...".
  • Renvoyer deux balises sœurs sans Fragment (<>...</>) au niveau racine.
  • Tenter de manipuler le DOM avec querySelector au lieu de laisser React gérer le rendu.
  • Confondre un composant React (PascalCase) avec une balise HTML native (minuscule).

9. Méthodologie de résolution

Décomposer une interface en composants React
  1. Observer la maquette graphique et identifier les blocs fonctionnels répétés.
  2. Nommer chaque composant avec une majuscule (Header, Card, SearchBar).
  3. Définir la hiérarchie parent-enfant et l’arbre de composants.
  4. Traduire le gabarit HTML en JSX valide (className, fermeture des balises).
  5. Monter le composant racine dans createRoot pour valider l’affichage.

10. Révision active

Résumé essentiel
  • React est une bibliothèque déclarative : l’UI est une fonction directe de l’état (UI = f(state)).
  • Vite est l’environnement de développement moderne recommandé (rapide, ESM natif).
  • Le JSX combine la puissance de JavaScript et la clarté du HTML sous forme d’arborescence.
  • Chaque balise JSX est compilée sous le capot en un appel à React.createElement.
  • createRoot permet de monter l’application React sur un élément racine du DOM.

Checklist de maîtrise

  • Je comprends la différence entre programmation déclarative et impérative.
  • Je sais initialiser un projet React avec Vite.
  • Je respecte les 3 règles de syntaxe du JSX (racine unique, fermeture, camelCase).
  • Je sais utiliser les Fragments (<>...</>).
  • Je sais comment l’application est ancrée dans le DOM réel via createRoot.
