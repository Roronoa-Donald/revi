Chapitre 3 — État local (useState) & formulaires contrôlés

Module 3 ≈ 3 h 00 de travail Réservé B2 et plus
Mise en situation

Une interface statique ne suffit pas : un utilisateur clique sur des boutons, remplit des formulaires et modifie l’affichage. Pour mémoriser ces changements et déclencher des réactualisations visuelles, React fournit la notion d’état local avec le Hook useState.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. comprendre pourquoi une variable JavaScript standard ne déclenche pas de nouveau rendu ;
  2. utiliser le Hook useState pour stocker et modifier des données réactives ;
  3. manipuler les événements synthétiques (onClick, onChange, onSubmit) ;
  4. concevoir des formulaires contrôlés avec validation en temps réel ;
  5. respecter strictement l’immutabilité des objets et tableaux d’état.

1. Le Hook useState et le cycle de rendu

Contrairement à une variable ordinaire qui est réinitialisée à chaque exécution de fonction, le state est une mémoire persistée par React entre les rendus d’un composant.

import { useState } from 'react';

function Compteur() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Valeur courante : {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Incrémenter
      </button>
    </div>
  );
}
Comment React réagit à setState ?

L’appel à la fonction modifie la valeur en mémoire et planifie un nouveau rendu du composant. React réexécute la fonction, calcule la différence avec l’ancien Virtual DOM et met à jour uniquement les nœuds modifiés.

2. Mises à jour basées sur l’état précédent

Les mises à jour d’état en React sont regroupées par lot (batching). Si une nouvelle valeur dépend directement de l’ancienne valeur (par exemple lors de plusieurs incrémentations rapides), il faut passer une fonction de rappel :

// À privilégier pour éviter les états obsolètes :
setCount(prevCount => prevCount + 1);

3. Gestion des événements et formulaires contrôlés

React enveloppe les événements natifs du navigateur dans des événements synthétiques (SyntheticEvent) assurant une compatibilité cross-browser parfaite. On utilise le camelCase : onClick, onChange, onSubmit.

Dans un composant contrôlé, l’élément de formulaire HTML (<input>, <textarea>, <select>) ne gère pas son propre état interne : c’est le state React qui devient la source unique de vérité.

function FormulaireContact() {
  const [email, setEmail] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault(); // Bloque le rechargement de page natif
    console.log('Envoi pour :', email);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="votre.email@exemple.fr"
      />
      <button type="submit">Valider</button>
    </form>
  );
}

4. Règle d’or : l’immutabilité de l’état

On ne doit jamais muter directement un objet ou un tableau stocké dans le state (ex. tableau.push(...) ou objet.propriete = ...). React compare les références des objets pour savoir s’il doit re-rendre : sans nouvelle référence, le composant ne se met pas à jour.

Opérations immuables courantes
  • Ajout dans un tableau : setItems(prev => [...prev, nouvelItem]) (opérateur spread).
  • Suppression d’un élément : setItems(prev => prev.filter(item => item.id !== idCible)).
  • Modification d’un objet : setUser(prev => ({ ...prev, role: 'admin' })).

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute votre code sur un service distant, puis la validation fait tourner des tests que vous ne voyez pas : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire de code à votre place — c’est le principe de l’exercice.

Exercice 1 — Simulateur du Hook useState

JavaScript Niveau 1 — Acquisition

Objectif : Gérer l'évolution d'un état numérique à travers une succession d'actions INC, DEC et RESET.

Un composant React conserve son état avec useState. Le programme lit la valeur initiale sur la ligne 1, puis une série d'actions séparées par des espaces sur la ligne 2. Les actions possibles sont INC (+1), DEC (-1) et RESET (revient à 0). Affichez Etat final : VALEUR.

Entrée du programme
5
INC INC DEC
Sortie attendue
Etat final : 6

5 + 1 + 1 - 1 = 6

Deux indices, rédigés en mots
  1. Bouclez sur les actions en vérifiant act === "INC", "DEC" ou "RESET".
  2. Nettoyez les entrées vides avec filter(Boolean).

Exercice 2 — Validation d'input contrôlé (onChange)

JavaScript Niveau 1 — Acquisition

Objectif : Valider en direct la valeur saisie dans un champ de formulaire React.

Dans un formulaire contrôlé, la fonction de rappel onChange valide la saisie à chaque frappe. Le programme lit une chaîne représentant un mot de passe. Il est valide s'il mesure au moins 8 caractères ET contient au moins un chiffre. Affichez Statut : VALIDE ou Statut : INVALIDE.

Entrée du programme
React2026
Sortie attendue
Statut : VALIDE

9 caractères dont 4 chiffres.

Deux indices, rédigés en mots
  1. Vérifiez saisie.length >= 8 pour le critère de taille.
  2. Utilisez l'expression régulière /[0-9]/.test(saisie) pour vérifier la présence d'un chiffre.

Exercice 3 — Mise à jour immuable d'un tableau d'état

JavaScript Niveau 2 — Application

Objectif : Modifier une liste d'éléments sans muter l'état précédent (immutabilité React).

En React, on ne doit jamais modifier directement un tableau d'état (ex. push ou splice interdits). Le script lit sur la ligne 1 une liste d'articles séparés par des virgules, et sur la ligne 2 une commande : soit AJOUTER nom, soit SUPPRIMER nom. Affichez la nouvelle liste avec les éléments séparés par une virgule (ou (vide) si vide).

Entrée du programme
pomme,banane
AJOUTER orange
Sortie attendue
pomme,banane,orange

Ajout en fin de tableau par décomposition.

Deux indices, rédigés en mots
  1. Pour ajouter sans muter : [...articles, cible].
  2. Pour supprimer sans muter : articles.filter(item => item !== cible).

6. QCM — niveau examen

L’appel à useState(initial) retourne…

useState renvoie un tuple déstructuré avec la valeur et la fonction de mise à jour.

Pourquoi variable = 10 ne provoque aucun re-rendu ?

Seul le setter de useState informe le réconciliateur de planifier un rendu.

À quoi sert e.preventDefault() dans onSubmit ?

Dans une SPA, on bloque le comportement par défaut pour traiter la soumission en JS.

Comment ajouter un élément à un tableau d’état de façon immuable ?

L’opérateur spread crée un nouveau tableau avec une nouvelle référence mémoire.

Dans un input contrôlé, d’où provient la valeur affichée ?

L’état React constitue la source unique de vérité de l’input.

Pour calculer un nouvel état à partir de l’ancien en toute sécurité, on écrit…

La fonction de rappel garantit de manipuler l’état le plus récent malgré le batching.

Quel événement React capture la modification d’un champ texte ?

onChange en React se déclenche à chaque frappe de touche dans le champ.

Que se passe-t-il si l’on mute un objet d’état sans changer sa référence ?

La comparaison par référence superficielle (shallow comparison) ne voit pas la mutation interne.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Muter directement un tableau avec push(), pop() ou splice().
  • Modifier une propriété d’objet sans créer une copie via l’opérateur spread (...).
  • Oublier e.preventDefault() dans la gestion d’un formulaire.
  • Associer la prop value d’un input sans fournir de gestionnaire onChange (input bloqué en lecture seule).
  • Compter sur la mise à jour immédiate et synchrone d’un state juste après l’appel du setter.

8. Méthodologie de résolution

Gérer un formulaire contrôlé avec validation en direct
  1. Déclarer une variable d’état avec useState pour chaque champ ou un objet d’état unique.
  2. Lier la prop value du champ HTML à la variable d’état correspondante.
  3. Écouter l’événement onChange pour appeler le setter avec e.target.value.
  4. Valider la saisie à la volée (longueur, caractères, expressions régulières).
  5. Intercepter la soumission avec onSubmit et bloquer le rechargement via e.preventDefault().

9. Révision active

Résumé essentiel
  • useState permet de mémoriser des données réactives entre les cycles de rendu.
  • Chaque appel au setter planifie un recalcul du Virtual DOM et une mise à jour ciblée.
  • Les événements synthétiques React normalisent les interactions utilisateur (onClick, onChange).
  • Un formulaire contrôlé fait du state React la source unique de vérité de chaque champ.
  • L’immutabilité stricte des objets et tableaux est indispensable pour la détection des changements.

Checklist de maîtrise

  • Je sais initialiser et mettre à jour un état avec useState.
  • J’utilise la forme fonctionnelle setX(prev => ...) pour les mises à jour dépendantes de l’ancien état.
  • Je conçois des inputs contrôlés avec value et onChange.
  • Je neutralise le rechargement natif de page avec e.preventDefault().
  • Je respecte l’immutabilité en utilisant l’opérateur spread (...).
