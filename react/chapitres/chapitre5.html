Chapitre 5 — Effets de bord (useEffect) & requêtes asynchrones

Module 5 ≈ 3 h 00 de travail Réservé B2 et plus
Mise en situation

Un composant React doit rester pur lors de son rendu : il ne doit pas déclencher d’appels réseau ni d’abonnements pendant le calcul du JSX. Pour synchroniser le composant avec le monde extérieur (APIs REST, timers, stockage local), React propose le Hook useEffect.

Objectifs pédagogiques

À la fin de ce chapitre, vous serez capable de :

  1. définir la notion d’effet de bord (side effect) dans une application frontend ;
  2. maîtriser la syntaxe et le fonctionnement du Hook useEffect ;
  3. comprendre le rôle critique du tableau de dépendances et la règle d’exhaustivité ;
  4. implémenter des fonctions de nettoyage (cleanup) pour éviter les fuites mémoire ;
  5. gérer le cycle complet d’un appel API (états loading, data et error).

1. Qu’est-ce qu’un effet de bord en React ?

Un effet de bord (ou side effect) désigne toute opération qui interagit avec l’extérieur du composant ou modifie un état hors de son cycle de calcul pur :

  • Effectuer une requête HTTP vers une API backend (fetch, Axios) ;
  • Démarrer ou arrêter une minuterie (setTimeout, setInterval) ;
  • Écouter un événement global du navigateur (window.addEventListener) ;
  • Modifier directement le titre de la page (document.title = ...).
Séparer le calcul du rendu et les effets

Le corps d’un composant sert exclusivement à calculer la représentation visuelle (JSX). Tous les effets secondaires doivent être différés dans useEffect, qui s’exécute après que le navigateur a mis à jour l’écran.

2. Le Hook useEffect et son tableau de dépendances

Le Hook useEffect accepte deux arguments : une fonction d’effet et un tableau optionnel de dépendances :

import { useState, useEffect } from 'react';

useEffect(() => {
  // Code exécuté après le rendu
}, [dependance1, dependance2]);
Les 3 modes du tableau de dépendances
  1. Aucun tableau fourni : l’effet s’exécute après absolument chaque rendu du composant (à éviter pour les requêtes réseau).
  2. Tableau vide [] : l’effet ne s’exécute qu’une seule fois, au montage initial du composant.
  3. Tableau garni [a, b] : l’effet s’exécute au montage, puis se réexécute si et seulement si a ou b change de valeur.

3. La fonction de nettoyage (Cleanup function)

Certains effets nécessitent d’être annulés pour libérer des ressources lorsque le composant est retiré de l’écran (démontage) ou avant que le prochain effet ne s’applique. Pour cela, la fonction d’effet renvoie une fonction de nettoyage :

useEffect(() => {
  const intervalId = setInterval(() => {
    console.log('Battement d’horloge');
  }, 1000);

  // Fonction de nettoyage appelée au démontage :
  return () => {
    clearInterval(intervalId);
    console.log('Minuterie nettoyée !');
  };
}, []);

4. Appels API et gestion des états asynchrones

La fonction passée à useEffect ne peut pas être marquée directement comme async car elle doit renvoyer soit rien, soit une fonction de nettoyage (et non une Promesse). On déclare donc une fonction asynchrone interne :

function ProfilUtilisateur({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let actif = true;
    setLoading(true);

    async function chargerDonnees() {
      try {
        const res = await fetch(`https://api.exemple.fr/users/${userId}`);
        if (!res.ok) throw new Error('Erreur HTTP ' + res.status);
        const data = await res.json();
        if (actif) setUser(data);
      } catch (err) {
        if (actif) setError(err.message);
      } finally {
        if (actif) setLoading(false);
      }
    }

    chargerDonnees();
    return () => { actif = false; }; // Évite les courses de requêtes
  }, [userId]);

  if (loading) return <p>Chargement...</p>;
  if (error) return <p className="erreur">Erreur : {error}</p>;
  return <h1>{user?.nom}</h1>;
}

5. Exercices de code

Ces trois exercices se font dans la page. L’éditeur du navigateur exécute le code et la validation fait tourner des jeux de tests indépendants : réussir l’exemple affiché ne suffit donc pas, il faut traiter le cas général.

En cas d’erreur, le bouton Expliquer mon erreur interroge le tuteur : il décrit ce qui s’est passé et par où chercher, sans jamais écrire le code de la solution — c’est le principe de l’exercice.

Exercice 1 — Détection de changement de dépendances (useEffect)

JavaScript Niveau 1 — Acquisition

Objectif : Déterminer si un effet doit s'exécuter en comparant les dépendances de deux rendus successifs.

React compare chaque valeur du tableau de dépendances de useEffect par égalité stricte (Object.is). Le script lit deux lignes : les valeurs des dépendances au rendu 1 (ligne 1), puis au rendu 2 (ligne 2), séparées par des espaces. Si au moins une valeur a changé, affichez EFFET DECLENCHE ; sinon, affichez EFFET IGNORE.

Entrée du programme
10 Paris
10 Lyon
Sortie attendue
EFFET DECLENCHE

La seconde dépendance a changé (Paris -> Lyon).

Deux indices, rédigés en mots
  1. Comparez chaque paire dep1[i] et dep2[i] avec Object.is ou ===.
  2. Dès qu'une différence apparaît, l'effet doit s'exécuter.

Exercice 2 — Machine d'états d'une requête API

JavaScript Niveau 1 — Acquisition

Objectif : Afficher le composant adapté au statut du chargement : en attente, succès ou échec.

Lors d'un appel API asynchrone dans un useEffect, l'UI gère trois états : chargement, succès et erreur. Le script lit une ligne etat donnee où etat vaut LOADING, SUCCESS ou ERROR. Affichez :
- <Spinner label="Chargement en cours..." /> pour LOADING
- <DataView result="DONNEE" /> pour SUCCESS
- <AlertError message="DONNEE" /> pour ERROR

Entrée du programme
SUCCESS 42_utilisateurs
Sortie attendue
<DataView result="42_utilisateurs" />

Requête réussie avec affichage des données.

Deux indices, rédigés en mots
  1. Gérez les trois branches avec if / else if.
  2. Pour LOADING, le composant Spinner n'utilise pas la donnée restante.

Exercice 3 — Nettoyage d'effet (Cleanup function)

JavaScript Niveau 2 — Application

Objectif : Simuler la fonction de retour de useEffect pour éviter les fuites de mémoire (timer / écouteur).

La fonction retournée par useEffect nettoie les abonnements ou timers lors du démontage ou avant le prochain effet. Le script lit une suite d'événements séparés par des virgules (ex. MOUNT,TICK,TICK,UNMOUNT). Affichez chaque étape :
- MOUNT → Timer demarre
- TICK → Tick horloge
- UNMOUNT → Timer nettoye

Entrée du programme
MOUNT,TICK,UNMOUNT
Sortie attendue
Timer demarre
Tick horloge
Timer nettoye

Cycle complet avec un battement.

Deux indices, rédigés en mots
  1. Bouclez sur chaque événement découpé et nettoyé par trim().
  2. Associez chaque mot-clé à sa chaîne de journalisation exacte.

6. QCM — niveau examen

Le callback passé à useEffect s’exécute…

useEffect s’exécute de manière asynchrone après l’affichage pour ne pas bloquer l’écran.

Si aucun tableau de dépendances n’est fourni, l’effet s’exécute…

Sans tableau, l’effet se relance à chaque actualisation.

Un tableau de dépendances vide ([]) signifie que l’effet s’exécute…

[] indique à React que l’effet ne dépend d’aucune valeur réactive.

La fonction renvoyée par le callback de useEffect sert à…

La cleanup function prévient les fuites de mémoire lors du démontage ou ré-exécution.

Pourquoi ne peut-on pas passer directement une fonction async à useEffect ?

React attend une fonction de nettoyage ou undefined, pas une promesse.

Comment éviter les courses de requêtes (race conditions) dans useEffect ?

Annuler ou ignorer la requête précédente évite d’écraser des données récentes avec d’anciennes réponses.

Quels sont les trois états fondamentaux d’une requête asynchrone ?

Gérer ces trois états garantit une interface claire à chaque instant.

Si useEffect dépend de [userId], quand se re-déclenche-t-il ?

React compare l’ancienne et la nouvelle valeur de userId pour décider de l’exécution.

7. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Oublier le tableau de dépendances et créer une boucle infinie de requêtes et de re-rendus.
  • Déclarer useEffect(async () => ...) directement.
  • Oublier de nettoyer les timers (setInterval) ou écouteurs (addEventListener).
  • Omettre des variables d’état ou props utilisées à l’intérieur de l’effet dans le tableau de dépendances.
  • Mettre à jour l’état dans le corps de l’effet sans condition ni dépendance appropriée.

8. Méthodologie de résolution

Intégrer une requête asynchrone dans un composant React
  1. Définir trois variables d’état : les données (null), le statut de chargement (true) et l’erreur (null).
  2. Déclarer un useEffect avec les dépendances dont l’appel a besoin (ex. id de ressource).
  3. Écrire une fonction asynchrone interne avec bloc try / catch / finally.
  4. Gérer le nettoyage avec un marqueur d’annulation (AbortController ou variable booléenne).
  5. Rendre conditionnellement l’état correspondant : spinner, message d’erreur ou vue de données.

9. Révision active

Résumé essentiel
  • useEffect synchronise un composant React avec des systèmes extérieurs (APIs, timers, DOM).
  • Le tableau de dépendances contrôle rigoureusement les moments d’exécution de l’effet.
  • Un tableau vide [] correspond à une exécution unique au montage du composant.
  • La fonction de nettoyage (cleanup) prévient les fuites de mémoire et les effets résiduels.
  • Les requêtes HTTP requièrent une fonction async interne et la gestion des états loading/data/error.

Checklist de maîtrise

  • Je comprends la différence entre le rendu pur et les effets de bord.
  • Je sais choisir entre aucun tableau, un tableau vide [] et un tableau garni [deps].
  • J’écris systématiquement une fonction de nettoyage pour mes timers et écouteurs.
  • Je n’écris jamais useEffect(async () => ...).
  • Je gère les trois états visuels (chargement, succès, échec) lors d’un appel API.
