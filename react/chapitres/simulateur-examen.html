Conseils pour l’épreuve

Examen blanc n°1 : Composants, JSX, Props & State

Sujet théorique et pratique : modèle mental, syntaxe JSX, communication par props et formulaires contrôlés.

Exercice 1 /5 : JSX & Composants

Énoncé : Quelles sont les trois règles strictes de syntaxe à respecter impérativement en JSX ? Expliquez pourquoi un nom de composant doit commencer par une majuscule.

Voir le corrigé type
Les 3 règles : (1) Un seul élément racine ou un Fragment <>...</> ; (2) Fermeture obligatoire de toutes les balises, y compris orphelines (<img />) ; (3) Attributs en camelCase (className, htmlFor). Une majuscule initiale indique à React qu’il s’agit d’un composant personnalisé ; en minuscule, React le transmet au navigateur comme balise HTML native.
Exercice 2 /5 : Props & Children

Énoncé : Définissez la nature des props en React. Comment concevoir un composant conteneur réutilisable (ex. Modal ou Card) sans connaître à l’avance son contenu textuel ?

Voir le corrigé type
Les props sont en lecture seule (immuables) : un composant ne doit jamais modifier ses props reçues. Pour concevoir un conteneur générique, on utilise la prop spéciale réservée props.children, qui capture et injecte le JSX imbriqué entre les balises ouvrante et fermante du composant.
Exercice 3 /5 : Hook useState

Énoncé : Pourquoi l’affectation directe variable = valeur ne met-elle pas à jour l’interface ? Quelle fonction de mise à jour devez-vous utiliser si l’état suivant dépend du précédent ?

Voir le corrigé type
Une variable JavaScript locale n’informe pas React d’un changement en mémoire. Seul le setter renvoyé par useState planifie un nouveau rendu et déclenche le réconciliateur. Si le nouvel état dépend de l’ancien, on passe une fonction de rappel : setCount(prev => prev + 1) pour éviter les incohérences liées au regroupement par lot (batching).
Exercice 4 /5 : Formulaire contrôlé

Énoncé : Expliquez le fonctionnement d’un champ de saisie contrôlé. Pourquoi est-il indispensable d’appeler e.preventDefault() lors de la soumission ?

Voir le corrigé type
Dans un input contrôlé, la prop value est liée à une variable d’état et l’événement onChange met à jour cet état : React est la source unique de vérité. e.preventDefault() neutralise le comportement natif du navigateur qui rechargerait la page entière, ce qui détruirait l’état en mémoire dans une SPA.

Examen blanc n°2 : Listes, Cycle de vie & Architecture SPA

Sujet d’approfondissement : réconciliation, synchronisation d’effets de bord et routage multipage.

Exercice 1 /5 : Listes & Key

Énoncé : Pourquoi est-il crucial de fournir une prop key lors du rendu d’un tableau avec map() ? Pourquoi l’index de boucle (key={index}) est-il vivement déconseillé sur une liste dynamique ?

Voir le corrigé type
La prop key fournit une identité stable à chaque élément pour que l’algorithme de réconciliation identifie les ajouts, déplacements et suppressions dans le DOM sans tout redessiner. L’index de boucle est lié à la position et non à l’élément : si la liste est triée ou qu’un élément est inséré au début, les index changent et créent des bugs visuels d’état chez les composants enfants.
Exercice 2 /5 : Hook useEffect

Énoncé : Distinguez le comportement de useEffect selon que son tableau de dépendances est : (a) absent ; (b) vide [] ; (c) garni [id, role]. À quoi sert la fonction renvoyée par le callback ?

Voir le corrigé type
(a) Absent : s’exécute après chaque rendu. (b) Vide [] : s’exécute une seule fois au montage initial. (c) Garni [id, role] : s’exécute au montage puis dès que id ou role change. La fonction renvoyée est la cleanup function, exécutée au démontage ou avant le prochain effet pour détruire les timers ou abonnements résiduels.
Exercice 3 /5 : Requête asynchrone

Énoncé : Décrivez l’architecture recommandée pour effectuer un appel fetch dans un composant sans provoquer de boucle infinie et en gérant les états de chargement.

Voir le corrigé type
On déclare trois variables d’état (data, loading, error). On place l’appel dans un useEffect avec un tableau de dépendances adapté (ex. [userId]). On déclare une fonction async interne, avec bloc try/catch/finally. Un booléen d’annulation (ou AbortController) dans le cleanup évite les courses de requêtes (race conditions).
Exercice 4 /5 : Routage & Architecture

Énoncé : Comment fonctionne la navigation sans rechargement dans React Router ? Citez les rôles respectifs de BrowserRouter, Link, useParams et useReducer.

Voir le corrigé type
React Router utilise l’API History (pushState) du navigateur pour changer l’URL et monte conditionnellement les composants associés sans recharger le HTML. BrowserRouter synchronise le contexte d’URL ; Link intercepte le clic ; useParams extrait les paramètres dynamiques (ex. :id) ; useReducer centralise la gestion d’états complexes via des actions et une fonction pure.
