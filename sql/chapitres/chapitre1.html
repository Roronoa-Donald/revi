Chapitre 1 — Modélisation Relationnelle, DDL & Contraintes d’Intégrité

Module 1 ≈ 2 h 45 de travail Accès libre
Mise en situation

Une jeune pousse de la FinTech lance une application de gestion de portefeuilles financiers. Lors de la phase de test initiale, des ordres d’achat sont enregistrés sans identifiant client valide, des transactions orphelines subsistent après la suppression d’un compte et des montants négatifs sont injectés par erreur. Ces défaillances critiques proviennent d’un schéma SQL mal contraint et de l’absence de règles d’intégrité référentielle strictes au niveau du SGBD. Comment concevoir un schéma robuste avec CREATE TABLE, verrouiller les domaines avec des contraintes CHECK et UNIQUE, et garantir la cohérence mathématique des relations avec les clés primaires composites et les clés étrangères ? Ce premier module établit les fondations du Data Definition Language (DDL) en SQL professionnel.

Objectifs pédagogiques

À la fin de ce chapitre, tu seras capable de :

  1. traduire un modèle conceptuel entité-association en un schéma relationnel normalisé (3NF) ;
  2. sélectionner les types de données SQL optimaux (INT, BIGINT, VARCHAR, TEXT, DECIMAL, TIMESTAMP, BOOLEAN) selon les contraintes de stockage et de précision ;
  3. déclarer des clés primaires simples ou composites et des contraintes d’unicité (UNIQUE) ;
  4. configurer l’intégrité référentielle (FOREIGN KEY) et maîtriser les comportements ON DELETE / ON UPDATE (RESTRICT, CASCADE, SET NULL) ;
  5. implémenter des règles de validation métier directes grâce à la contrainte CHECK.

1. Le Modèle Relationnel & Typage Strict des Données SQL

Introduit par Edgar F. Codd en 1970, le modèle relationnel organise l’information sous forme de tables (relations mathématiques) composées de lignes (tuples ou enregistrements) et de colonnes (attributs). Chaque attribut appartient à un domaine de définition strict déterminé par son type SQL.

Types numériques & Monétaires

  • INT / BIGINT : Entiers signés 32 bits (jusqu’à 2 milliards) ou 64 bits (pour les identifiants à fort volume).
  • DECIMAL(p, s) / NUMERIC(p, s) : Nombre à virgule fixe exact (p chiffres au total, s après la virgule). Indispensable pour les valeurs monétaires afin de bannir les erreurs d’arrondi inhérentes aux types flottants (FLOAT/DOUBLE).

Types textuels & Temporels

  • CHAR(n) vs VARCHAR(n) : CHAR réserve une longueur fixe complétée par des espaces (ex: code ISO pays à 2 lettres). VARCHAR n’occupe que la taille réelle du texte plus un préfixe de longueur.
  • TIMESTAMP WITH TIME ZONE : Horodatage universel stocké en UTC et restitué selon le fuseau du client.

2. Langage de Définition de Données (DDL) : CREATE, ALTER & DROP

Le sous-ensemble DDL (Data Definition Language) de SQL permet de créer, modifier et supprimer les structures de la base de données. Contrairement aux requêtes de consultation (DQL), les commandes DDL appliquent des verrous exclusifs de schéma.

CREATE TABLE Commandes ( id_cmd BIGINT GENERATED ALWAYS AS IDENTITY, ref_commande VARCHAR(32) NOT NULL, client_id INT NOT NULL, montant_ht DECIMAL(12,2) NOT NULL, taux_tva DECIMAL(4,2) DEFAULT 20.00 NOT NULL, cree_le TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL, PRIMARY KEY (id_cmd), CONSTRAINT uq_ref_commande UNIQUE (ref_commande), CONSTRAINT ck_montant_positif CHECK (montant_ht ≥ 0), CONSTRAINT fk_cmd_client FOREIGN KEY (client_id) REFERENCES Clients(id_client) ON DELETE RESTRICT ON UPDATE CASCADE );
  • DROP TABLE t; détruit complètement la structure, les index, les contraintes et les données de la table dans le dictionnaire du SGBD.
  • TRUNCATE TABLE t; vide instantanément toutes les lignes de la table en désallouant les blocs de données sur disque. C’est une commande DDL très rapide, non journalisée ligne par ligne, qui réinitialise les compteurs d’auto-incrément.
  • DELETE FROM t; est une commande DML qui supprime les lignes une à une dans le journal des transactions (WAL), permettant un ROLLBACK et activant les déclencheurs (triggers).

3. Clés Primaires Composites & Intégrité Référentielle

L’intégrité des données d’une application repose sur deux règles immuables :

1. Intégrité d’Entité (PRIMARY KEY)

Chaque ligne d’une relation doit être identifiable de façon unique et non nulle. Dans une table d’association (ex: ligne de facture ou inscription à un cours), la clé primaire est dite composite car elle associe plusieurs colonnes :

PRIMARY KEY (commande_id, produit_id)

Cette déclaration garantit à elle seule qu’un même produit ne peut pas figurer deux fois dans la même commande.

2. Intégrité Référentielle (FOREIGN KEY)

Une clé étrangère garantit que la valeur d’une colonne fait référence à une clé primaire existante dans la table parent :

  • ON DELETE RESTRICT (défaut) : Empêche la suppression du parent tant que des enfants y sont rattachés.
  • ON DELETE CASCADE : Supprime automatiquement tous les enregistrements enfants dépendants lors de la suppression du parent.
  • ON DELETE SET NULL : Affecte la valeur NULL à la clé étrangère des enfants si la colonne est nullable.

Exercice 1 — Analyseur syntaxique de commande DDL CREATE TABLE

Python Niveau 1 — Acquisition

Objectif : Analyser une instruction DDL CREATE TABLE pour extraire le nom de la table, les colonnes et la clé primaire.

Le script lit une commande DDL CREATE TABLE sur une seule ligne. Il doit extraire : - Le nom de la table ; - Le nombre de colonnes définies ; - Le nom de la colonne clé primaire (identifiée par la mention PRIMARY KEY inline ou comme contrainte PRIMARY KEY (col)). Format de sortie : Table: <Nom> | Colonnes: <Nb> | PK: <NomColonnePK> (ou PK: AUCUNE si absente).

Entrée du programme
CREATE TABLE clients ( id INT PRIMARY KEY, nom VARCHAR(50), email VARCHAR(100) );
Sortie attendue
Table: clients | Colonnes: 3 | PK: id

Table clients avec 3 colonnes et id comme PK.

Deux indices, rédigés en mots
  1. Utilise une expression régulière pour extraire le nom de la table après CREATE TABLE.
  2. Extrais le contenu entre les parenthèses principales et découpe par les virgules de niveau supérieur.
  3. Repère PRIMARY KEY inline ou en contrainte séparée.

Exercice 2 — Vérificateur d’intégrité référentielle parent-enfant

Python Niveau 2 — Application

Objectif : Détecter les enregistrements enfants dont la clé étrangère pointe vers un parent inexistant (clés orphelines).

Une contrainte de clé étrangère (FOREIGN KEY) impose que toute valeur non nulle de la colonne fille référence une clé primaire existante dans la table parent.

Entrée : - Ligne 1 : Liste ordonnée d’IDs de la table parent séparés par des virgules (ex: 10,20,30). - Ligne 2 : Liste de couples enfant id_enfant:parent_id séparés par des virgules (ex: 1:10,2:99,3:20). Sortie : Valides: <N> | Orphelins: <id1,id2,...> (ou Orphelins: AUCUN si tout est valide).

Entrée du programme
10,20,30
1:10,2:99,3:20,4:50
Sortie attendue
Valides: 2 | Orphelins: 2,4

Les enfants 2 (parent 99) et 4 (parent 50) sont orphelins.

Deux indices, rédigés en mots
  1. Convertis les identifiants parents en un ensemble set() pour des tests d appartenance rapides.
  2. Sépare chaque couple enfant par deux-points id_enfant:parent_id.
  3. Gère le cas où aucun orphelin n est détecté en affichant AUCUN.

Exercice 3 — Émulateur d’action de clé étrangère ON DELETE (CASCADE vs RESTRICT)

Python Niveau 3 — Raisonnement

Objectif : Simuler la politique de suppression ON DELETE CASCADE ou ON DELETE RESTRICT lors de la suppression d’un enregistrement parent.

Lorsqu’un enregistrement parent est supprimé : - RESTRICT : La suppression est immédiatement rejetée si au moins un enfant dépend de ce parent. - CASCADE : La suppression du parent est acceptée et entraîne automatiquement la suppression de tous ses enregistrements enfants.

Entrée : - Ligne 1 : ACTION,ID_PARENT_A_SUPPRIMER (ex: CASCADE,10 ou RESTRICT,20). - Ligne 2 : Liste des enfants au format id_enfant:parent_id séparés par des virgules. Sortie : - Si RESTRICT rejeté : ERREUR: Suppression interdite (enfants presents: <id1,id2>) - Si RESTRICT accepté (aucun enfant) : SUCCES: Parent <ID> supprime | Enfants restants: <liste> - Si CASCADE : SUCCES: Parent <ID> supprime | Enfants supprimes: <Nb> | Enfants restants: <liste>

Entrée du programme
RESTRICT,10
1:10,2:20,3:10,4:30
Sortie attendue
ERREUR: Suppression interdite (enfants presents: 1,3)

La suppression du parent 10 est bloquée par RESTRICT car les enfants 1 et 3 y sont rattachés.

Deux indices, rédigés en mots
  1. Sépare l action (RESTRICT ou CASCADE) et l ID parent sur la première ligne.
  2. Identifie tous les enfants qui ont ce parent_id.
  3. Pour CASCADE, filtre les enfants pour ne garder que ceux dont le parent_id est différent.

5. QCM — niveau examen

Pour stocker des montants monétaires dans une base de données de production, quel type SQL garantit l’absence totale d’erreurs d’arrondi binaire ?

Les types flottants (FLOAT, DOUBLE) utilisent une représentation binaire IEEE 754 qui engendre des erreurs d’arrondi sur les fractions décimales. DECIMAL/NUMERIC stocke les nombres en base 10 exacte et est le standard obligatoire en finance.

Quelle action se produit lors de la suppression d’une ligne parente si la clé étrangère est configurée avec ON DELETE CASCADE ?

ON DELETE CASCADE propage automatiquement la suppression de la ligne parente à l’ensemble des lignes dépendantes dans la table enfant.

Quelle est la différence majeure entre les instructions TRUNCATE TABLE et DELETE FROM sans clause WHERE ?

TRUNCATE est une instruction DDL qui vide la table instantanément en libérant les pages de disque sans enregistrer chaque suppression dans le journal des transactions (WAL), ce qui la rend considérablement plus rapide que DELETE.

Dans une table d’association modélisant les lignes d’une commande, comment interdire qu’un même produit soit présent plusieurs fois dans une même commande ?

La clé primaire composite PRIMARY KEY (id_commande, id_produit) impose l’unicité stricte du couple (id_commande, id_produit) au niveau du moteur relationnel.

Quelle contrainte SQL permet de s’assurer qu’une colonne numérique stocke exclusivement des valeurs strictement positives (> 0) ?

La contrainte CHECK évalue une expression booléenne sur chaque ligne insérée ou modifiée et rejette l’opération si l’expression vaut FALSE.

6. Erreurs classiques — récapitulatif

À reconnaître en examen
  • Utiliser le type FLOAT pour des montants monétaires au lieu de DECIMAL, entraînant des décalages de centimes inacceptables.
  • Oublier de déclarer une contrainte FOREIGN KEY explicite entre deux tables, laissant l’application créer des enregistrements orphelins incohérents.
  • Configurer systématiquement ON DELETE CASCADE sans discernement, risquant d’effacer par inadvertance des pans entiers de la base de données.
  • Confondre CHAR(10) (qui remplit systématiquement avec des espaces jusqu’à 10 caractères) et VARCHAR(10) (qui s’adapte à la longueur réelle).
  • Exécuter un TRUNCATE TABLE sur un environnement de production en pensant pouvoir le restaurer par un simple ROLLBACK dans tous les SGBD.

7. Méthodologie de résolution

Protocole en 4 étapes pour créer une table conforme aux normes professionnelles
  1. Identifier l’identifiant unique et déclarer la clé primaire (clé synthétique auto-incrémentée BIGINT ou clé composite naturelle).
  2. Choisir le type de données le plus précis et le plus économique pour chaque colonne (DECIMAL pour les prix, VARCHAR calibré, TIMESTAMP UTC).
  3. Poser les contraintes d’intégrité structurelle : NOT NULL sur tous les attributs obligatoires et UNIQUE sur les identifiants alternatifs (email, référence).
  4. Définir les clés étrangères avec leurs règles d’intégrité référentielle explicites (RESTRICT par défaut, CASCADE pour les dépendances strictes compositionnelles).

8. Révision active

Résumé essentiel
  • Le modèle relationnel s’appuie sur des relations mathématiques (tables), des tuples (lignes) et des attributs typés.
  • Les types à virgule fixe DECIMAL(p, s) sont obligatoires pour toutes les valeurs comptables et financières.
  • Les commandes DDL (CREATE, ALTER, DROP, TRUNCATE) définissent et modifient la structure physique de la base.
  • L’intégrité référentielle (FOREIGN KEY) empêche l’apparition de données orphelines et orchestre les suppressions (CASCADE, RESTRICT).
  • Les contraintes CHECK et UNIQUE déportent les règles de cohérence au cœur du SGBD, garantissant une protection indépendante du code applicatif.
