Examens Blancs & Épreuves Corrigées de SQL B2

Deux sujets d’entraînement intensif conformes aux épreuves de licence informatique B2, accompagnés de leurs corrigés types et grilles d’évaluation détaillées.

Épreuve 1 : Contrôle Continu (CC) — Durée 1 h 30 (Barème sur 20 points)

Sujet du Contrôle Continu — Modélisation Relationnelle, DDL & Jointures Avancées

Partie 1 : Questions de cours & Algèbre relationnelle (6 points)

  1. Définissez les concepts d’intégrité référentielle et de clé primaire composite. Quelle est la différence entre ON DELETE CASCADE et ON DELETE RESTRICT ? (3 pts)
  2. Expliquez pourquoi l’expression conditionnelle WHERE date_naissance = NULL est une erreur en SQL et comment tester correctement l’absence de valeur (3 pts).

Partie 2 : Requêtes SQL complexes (8 points)

Soit le schéma relationnel suivant d’une plateforme e-commerce :

  • Clients(id_client, nom, ville, email)
  • Commandes(id_cmd, date_cmd, id_client, montant_total)
  • LignesCommande(id_cmd, ref_produit, quantite, prix_unitaire)
  1. Écrivez la requête listant tous les clients qui n’ont JAMAIS passé la moindre commande (utiliser une sous-requête avec NOT EXISTS ou un LEFT JOIN) (4 pts).
  2. Écrivez la requête affichant le total des dépenses par client pour l’année 2025, en ne conservant que les clients ayant dépensé au moins 1 000 €, triés par montant décroissant (4 pts).

Partie 3 : Normalisation & Contraintes DDL (6 points)

Écrivez l’instruction CREATE TABLE complète pour LignesCommande garantissant que la combinaison (id_cmd, ref_produit) est unique, que la quantité est strictement positive (> 0) et que la suppression d’une commande entraîne la suppression automatique de ses lignes (6 pts).

Corrigé type & Barème détaillé du Contrôle Continu

Corrigé Partie 1 (6 points)

  • Intégrité référentielle (3 pts) : Garantit qu’une clé étrangère dans une table enfant référence une clé primaire existante et valide dans la table parente. CASCADE propage automatiquement la suppression du parent à ses enfants, tandis que RESTRICT bloque la suppression tant qu’au moins un enfant est rattaché.
  • Valeurs NULL (3 pts) : En logique tri-valuée SQL, toute comparaison avec NULL via l’opérateur = produit UNKNOWN et est donc fausse dans un WHERE. Il faut impérativement employer le prédicat IS NULL (ou IS NOT NULL).

Corrigé Partie 2 (8 points)

  • Clients sans commande (4 pts) :
    SELECT c.id_client, c.nom FROM Clients c WHERE NOT EXISTS (SELECT 1 FROM Commandes cmd WHERE cmd.id_client = c.id_client);
  • Total annuel avec seuil (4 pts) :
    SELECT c.id_client, c.nom, SUM(cmd.montant_total) AS total_depenses
    FROM Clients c JOIN Commandes cmd ON c.id_client = cmd.id_client
    WHERE cmd.date_cmd BETWEEN '2025-01-01' AND '2025-12-31'
    GROUP BY c.id_client, c.nom
    HAVING SUM(cmd.montant_total) >= 1000
    ORDER BY total_depenses DESC;

Corrigé Partie 3 (6 points)

CREATE TABLE LignesCommande ( id_cmd INT, ref_produit VARCHAR(30), quantite INT NOT NULL CHECK (quantite > 0), prix_unitaire DECIMAL(10,2) NOT NULL CHECK (prix_unitaire ≥ 0), PRIMARY KEY (id_cmd, ref_produit), FOREIGN KEY (id_cmd) REFERENCES Commandes(id_cmd) ON DELETE CASCADE );

Épreuve 2 : Examen Final (EF) — Durée 2 h 00 (Barème sur 20 points)

Sujet de l’Examen Final — Transactions ACID, Fonctions Analytiques & Triggers

Partie 1 : Transactions ACID & Verrous (7 points)

  1. Détaillez les quatre propriétés ACID d’un SGBD transactionnel (3,5 pts).
  2. Décrivez les trois anomalies de concurrence classiques (lecture sale, lecture non répétable, lecture fantôme) et le niveau d’isolation minimal requis pour neutraliser chacune d’elles (3,5 pts).

Partie 2 : Fonctions de fenêtrage (Window Functions) (6 points)

À partir de la table Ventes(vendeur_id, region, montant, date_vente), écrivez une requête affichant pour chaque vente : le nom du vendeur, sa région, le montant, son rang de vente au sein de sa région (ROW_NUMBER()) ainsi que le montant de la vente précédente effectuée dans la même région (LAG()) (6 pts).

Partie 3 : Déclencheurs (Triggers) & Optimisation (7 points)

  1. Écrivez un déclencheur BEFORE UPDATE sur la table ComptesBancaires(id, solde, decouvert_max) interdisant la mise à jour si le nouveau solde est inférieur au découvert autorisé (déclencher une erreur SQL) (4 pts).
  2. Expliquez la différence de coût d’exécution entre un Seq Scan et un Index Scan sur une table de 10 millions de lignes. Dans quelle situation le planificateur préférera-t-il un parcours séquentiel même si un index existe ? (3 pts)
Corrigé type & Barème détaillé de l’Examen Final

Corrigé Partie 1 (7 points)

  • Propriétés ACID (3,5 pts) : Atomicité (tout ou rien), Cohérence (respect des règles d’intégrité), Isolation (les transactions simultanées ne se perturbent pas), Durabilité (persistance sur disque après COMMIT).
  • Anomalies & Niveaux (3,5 pts) : Lecture sale (résolue par Read Committed), Lecture non répétable (résolue par Repeatable Read), Lecture fantôme (résolue par Serializable ou verrous de plage de clés).

Corrigé Partie 2 (6 points)

SELECT vendeur_id, region, montant, ROW_NUMBER() OVER (PARTITION BY region ORDER BY montant DESC) AS rang_region, LAG(montant, 1) OVER (PARTITION BY region ORDER BY date_vente ASC) AS montant_precedent FROM Ventes;

Corrigé Partie 3 (7 points)

  • Trigger (4 pts) :
    CREATE TRIGGER check_solde_before_update BEFORE UPDATE ON ComptesBancaires FOR EACH ROW BEGIN IF NEW.solde < -NEW.decouvert_max THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Depassement de decouvert interdit'; END IF; END;
  • Optimisation (3 pts) : Le Seq Scan lit séquentiellement les 10 millions de blocs (coût O(N)). L’Index Scan parcourt un arbre B-Tree de profondeur 3 ou 4 (coût O(log N)). Le planificateur choisit le Seq Scan si la condition de filtrage sélectionne une large fraction de la table (ex: > 20-30 % des lignes), car les lectures aléatoires de l’index deviendraient plus coûteuses qu’une lecture séquentielle continue.
