Chapitre 1 — Bases de données et SGBD

Découvrez la mécanique interne qui alimente le web moderne. Comprenez pourquoi le simple tableur s'effondre sous la charge et comment le modèle relationnel et les SGBD garantissent intégrité, concurrence et rapidité grâce au standard SQL.

psychology

Mise en situation — Pourquoi un simple fichier texte ou tableur ne suffit plus

Imaginez un service e-commerce lors du Black Friday : 10 000 utilisateurs tentent d'acheter simultanément le dernier stock d'un produit. Avec un tableur Excel ou un fichier CSV partagé sur un disque réseau, deux requêtes en écriture s’écraseraient mutuellement (race condition), corrompant le fichier. Une base de données pilotée par un SGBD résout ce dilemme fondamental grâce à la sérialisation, aux verrous transactionnels et à la persistence ACID.

01. Qu’est-ce qu’une base de données ?

Une base de données (BDD ou Database) est un ensemble structuré et organisé d'informations stockées de façon persistante sur un support non volatile (disque dur, SSD). L'objectif est double : permettre une restitution ultrarapide et garantir qu'aucune donnée ne disparaisse même en cas de coupure de courant subite.

lightbulb Intuition pédagogique : Bibliothèque vs Fiche volante

Un simple fichier texte ressemble à un tas de post-it non indexés : pour trouver un mot, il faut relire chaque feuille du début à la fin (parcours séquentiel $O(n)$). Une base de données fonctionne comme une bibliothèque centrale informatisée pourvue d'index alphabétiques et thématiques, permettant d'accéder à la référence en un clin d'œil ($O(\log n)$).

02. Fonctions et types de bases de données

Depuis les années 1960, plusieurs modèles de structuration se sont succédé pour répondre aux exigences grandissantes d'interrogation et de volumétrie.

Modèle Principe architectural Point fort Limite historique
Hiérarchique Arborescence stricte parent-enfant (1:N) type dossiers racine. Parcours rapide si l'arborescence est connue. Rigidité totale ; impossible de modéliser du N:M sans duplication.
Réseau Graphe orienté : un enregistrement peut avoir plusieurs parents. Modélisation N:M possible. Requêtes manuelles très complexes par pointeurs physiques.
star Relationnel (Codd, 1970) Tables bidimensionnelles reliées par des clés logiques indépendantes du stockage. Standard universel SQL, intégrité mathématique, algèbre relationnelle. Scalabilité horizontale distribuée plus délicate.
NoSQL (Moderne) Clé-valeur, documents JSON, colonnes larges ou graphes. Élasticité horizontale massive, schémas flexibles. Garanties relationnelles ACID souvent assouplies (BASE).

03. Le SGBD (Système de Gestion de Base de Données)

Une base de données n'est qu'un ensemble de fichiers passifs. Le SGBD (ou DBMS en anglais) est le logiciel actif — le moteur intelligent — qui assure la sécurité, optimise les calculs et sérialise les accès simultanés.

Moteur SGBD Architecture Particularité clé Usage idéal
SQLite 3 Embarqué (In-process) Pas de démon serveur ; base entière contenue dans un fichier unique sur disque. Smartphones (iOS/Android), navigateurs (WASM), tests locaux.
PostgreSQL Client-Serveur Respect des standards ANSI SQL le plus rigoureux, types avancés (JSONB, géospatial). Applications critiques d'entreprise, finances, systèmes complexes.
MySQL / MariaDB Client-Serveur Moteur par défaut du web LAMP/LNMP, optimisations poussées en lecture. Sites web à fort trafic, CMS (WordPress, Drupal), e-commerce standard.
A Atomicité

Tout s'exécute ou rien n'est écrit (rollback automatique).

C Cohérence

Respect strict de toutes les contraintes de domaine et clés.

I Isolation

Les transactions parallèles ne se parasitent pas.

D Durabilité

Les commits sont gravés et résistent aux pannes secteur.

04. Le modèle relationnel

Le modèle proposé par Edgar F. Codd repose sur des concepts mathématiques de théorie des ensembles :

Concept 1

Table (Relation)

Tableau à deux dimensions. Elle porte un nom unique et représente une entité métier (ex. Voiture, Client).

Concept 2

Ligne (Tuple / Enregistrement)

Une occurrence unique de l'entité. Chaque ligne d'une table possède exactement la même structure.

Concept 3

Colonne (Attribut)

Une propriété nommée de l'entité (ex. immatriculation, kilometrage) rattachée à un type précis.

key Clés Primaires (PK) & Clés Étrangères (FK)

PRIMARY KEY (PK)

Attribut (ou groupe d'attributs) garantissant que chaque ligne est rigoureusement unique.

Ex: id_client = 14829 (Jamais NULL, toujours unique)
FOREIGN KEY (FK)

Attribut qui fait référence à la clé primaire d'une autre table pour lier les informations.

Ex: Voiture.marque_id → pointe sur Marque.id

05. Poser une première question à la base : SELECT

Le langage SQL (Structured Query Language) est un langage déclaratif : vous décrivez ce que vous voulez obtenir, et le compilateur/planificateur du SGBD décide de l'algorithme physique d'exécution.

// Syntaxe minimale de consultation
SELECT <liste_colonnes ou *>
FROM <nom_de_la_table>;

lightbulb_circle La clause SELECT DISTINCT

Par défaut, SQL préserve les doublons de valeurs si vous ne projetez que certains champs. Pour obliger le SGBD à dédoublonner le résultat final, on insère le mot-clé DISTINCT immédiatement après le SELECT.

warning 8. Erreurs classiques — récapitulatif

Confusion NULL vs 0 vs ''

0 est un entier. '' est un texte vide. NULL est un état spécial (inconnu). Tester WHERE champ = NULL renvoie toujours faux ! On doit écrire IS NULL.

Absence de Clé Primaire

Créer une table sans clé primaire rend les suppressions et mises à jour incertaines : vous risquez d'altérer des lignes clonées involontairement.

Ordre des clauses SELECT

SQL impose un ordre syntaxique strict : SELECT, puis FROM, puis WHERE. Oublier la virgule entre les attributs est l'erreur numéro 1 des débutants.
