L'ordre d'évaluation des clauses SQL

Le langage SQL est déclaratif : vous décrivez ce que vous voulez plutôt que la séquence impérative d'instructions. Cependant, le compilateur SQL interne traite votre requête selon un flux logique très strict qui diffère fondamentalement de l'ordre d'écriture.

Étape Ordre Écrit (Syntaxique) Ordre d'Évaluation (Moteur SQL) Action réalisée par le SGBD
1. SELECT col1, col2 AS alias FROM table Charge le jeu de données relationnel initial en mémoire tampon.
2. FROM table WHERE condition Filtre ligne par ligne selon les prédicats booléens.
3. WHERE condition SELECT projection Extrait uniquement les colonnes demandées et calcule les alias.
4. ORDER BY col1 ASC ORDER BY expression Trie l'ensemble projeté résultant.
5. LIMIT n OFFSET m LIMIT / OFFSET Tronque la liste pour ne renvoyer que la fenêtre demandée.
warning

Pourquoi un alias de SELECT est-il inconnu dans la clause WHERE ?

Puisque la clause WHERE est évaluée avant la clause SELECT, le moteur n'a pas encore calculé vos alias de projection ! Écrire WHERE prix_ttc > 100 provoquera l'erreur « column "prix_ttc" does not exist » si cet alias a été créé dans le SELECT.

2

Les opérateurs du WHERE et gestion de la logique ternaire

Le filtrage s'exécute à l'aide d'opérateurs de comparaison et d'opérateurs booléens. En SQL, les conditions n'évaluent pas seulement à TRUE ou FALSE, mais à un troisième état : UNKNOWN (logique à trois valeurs de Kleene).

Opérateurs relationnels classiques

Opérateur Signification Exemple
=Égalité strictekm = 0
!= ou <>Différentmarque <> 'Audi'
< , <=Inférieur / Inférieur ou égalprix <= 15000
> , >=Supérieur / Supérieur ou égalannee > 2020
IS NULLVérifie l'absence de valeuroptions IS NULL
IS NOT NULLVérifie la présence d'une valeurprix IS NOT NULL

cancel Le piège absolu : '= NULL' renvoie toujours UNKNOWN

En SQL standard, NULL = NULL ne renvoie pas TRUE, mais UNKNOWN. Comme le WHERE ne garde que les lignes strictement évaluées à TRUE, la requête WHERE remise = NULL retournera toujours 0 ligne, même si la colonne est vide !

psychology Priorité booléenne : AND prime sur OR

L'opérateur AND agit comme une multiplication logique, et OR comme une addition. Sans parenthèses, le moteur regroupe d'abord les membres avec AND.

-- Mauvais : WHERE marque = 'Renault' OR annee > 2022 AND prix < 10000
-- Correct : WHERE (marque = 'Renault' OR annee > 2022) AND prix < 10000
3

Prédicats avancés : IN, BETWEEN et filtrage de texte LIKE

IN (...)

Appartenance ensembliste

Remplace élégamment une suite fastidieuse de disjonctions OR. Permet aussi d'accueillir des sous-requêtes.

SELECT * FROM Voiture
WHERE marque IN ('BMW', 'Audi', 'Tesla');
BETWEEN a AND b

Intervalle inclusif

Équivaut exactement à val >= a AND val <= b. Les bornes extrêmes sont obligatoirement incluses dans le résultat.

SELECT * FROM Voiture
WHERE prix BETWEEN 10000 AND 25000;
LIKE 'pattern'

Motif textuel (Jokers)

% : 0, 1 ou plusieurs caractères.
_ : Exactement 1 seul caractère arbitraire.

-- Ex: '208', '308', '508'
WHERE modele LIKE '_08';
4

Tri des données avec ORDER BY

Dans le modèle relationnel pur, une table est un ensemble non ordonné de tuples. Si vous ne spécifiez pas de clause ORDER BY, l'ordre de retour est purement aléatoire et dépend des optimisations physiques du moteur (pages disque, partitions, parallélisme).

Direction du tri et multi-critères

  • • ASC : Ordre croissant (valeur par défaut, optionnelle).
  • • DESC : Ordre décroissant (du plus grand au plus petit).
  • • Tri multi-colonnes : séparer les colonnes par des virgules. Le tri s'effectue de gauche à droite en cascade.
ORDER BY marque ASC, prix DESC;

→ Trie par marque alphabétique, et départage les doublons par prix le plus élevé d'abord.

Gestion des valeurs NULL dans le tri

Selon les SGBD (PostgreSQL, SQLite, MySQL), les NULL sont soit placés en tout premier soit en tout dernier. Le standard SQL permet de forcer leur position :

ORDER BY prix DESC NULLS LAST;
✓ Garantit que les véhicules au prix inconnu ne pollueront pas le haut de page.
5

Pagination industrielle avec LIMIT et OFFSET

Pour découper de volumineux catalogues en pages web navigables (ex. 10 ou 20 articles par vue), on restreint l'extraction avec LIMIT (taille de page) et OFFSET (nombre de lignes sautées).

-- Formule de pagination universelle :
LIMIT :taille_page OFFSET (:numero_page - 1) * :taille_page

Cas pratique : Pour extraire la page 3 avec 10 véhicules par page, le décalage est de (3 - 1) * 10 = 20. La requête saute les 20 premières lignes et extrait les 10 suivantes.

verified_user Règle d'or de Pagination

NE JAMAIS exécuter de LIMIT sans clause ORDER BY déterministe.

Sans tri explicite (ex. sur la clé primaire immat), des lignes peuvent apparaître en double sur deux pages distinctes ou disparaître purement entre deux requêtes !

8. Erreurs classiques de l'étudiant B1 à proscrire

1. Utilisation de '= NULL'

Ne jamais écrire WHERE col = NULL. Employer obligatoirement IS NULL.

2. Oubli de parenthèses (AND vs OR)

La priorité de l'opérateur AND casse la logique attendue dès que vous mélangez les conjonctions sans parenthèses explicites.

3. Alias de SELECT dans le WHERE

Le WHERE est calculé avant la projection SELECT : répétez l'expression complète au lieu d'appeler l'alias.

4. Pagination sans ORDER BY

Utiliser un LIMIT / OFFSET sans ordre strict conduit à une pagination instable et non reproductible.

9. Méthodologie d'extraction SQL en 4 étapes

1

Identifier le FROM

Déterminez la ou les tables sources indispensables contenant les données brutes.

2

Filtrer avec le WHERE

Isolez les enregistrements cibles à la source à l'aide de prédicats indexables.

3

Projeter via SELECT

Ne conservez que les colonnes nécessaires (évitez SELECT * en production).

4

Ordonner et Paginer

Structurez le rendu avec ORDER BY puis tronquez la vue via LIMIT / OFFSET.
