02

Clauses fondamentales & Filtrage unitaire

Précision des sélections scalaires, prédicats de restriction et découpage.

SELECT Projection

Choisit les colonnes, applique des fonctions, supprime les doublons avec DISTINCT et renomme avec AS.

SELECT DISTINCT prenom,
  nom AS patronyme,
  note * 2 AS note_sur_40
FROM Source

Indique la ou les tables sources. Pratique recommandée : attribuer un alias court (ex: e pour etudiants).

FROM etudiants AS e
// AS est optionnel : FROM etudiants e
WHERE (Opérateurs) Prédicats

Filtre sur chaque ligne individuellement. Évalué avant toute fonction de regroupement.

age >= 18 AND statut != 'archive'
ville IN ('Paris', 'Lyon', 'Lille')
score BETWEEN 10 AND 20
email LIKE '%@univ-%.fr'
date_naissance IS NOT NULL
ORDER BY Tri séquentiel

Ordonne selon un ou plusieurs critères. ASC (croissant par défaut) ou DESC (décroissant).

ORDER BY filiere ASC, moyenne DESC
-- SQLite : NULLS FIRST / NULLS LAST
LIMIT & OFFSET Pagination

Restreint le volume de lignes retournées. Règle d'or : Toujours associer à un ORDER BY déterministe.

ORDER BY id_etudiant
LIMIT 20 OFFSET 40;
-- Lignes 41 à 60 (Page 3)
LIKE : Motifs & Caractères Wildcards

Filtrage textuel insensible à la casse par défaut dans SQLite (sur caractères ASCII).

% : zéro, un ou plusieurs carac.
_ : exactement 1 caractère unique
// 'B_1%' trouve 'B12', 'BA_test', etc.
03

Jointures relationnelles (INNER & OUTER JOINS)

Correspondance entre tables selon la théorie des ensembles et algèbre relationnelle.

hub Relation Clé primaire (PK) → Clé étrangère (FK)
INNER JOIN Intersection

Conserve uniquement les lignes qui satisfont la condition ON dans les deux tables.

FROM etudiants e
INNER JOIN inscriptions i
  ON e.id = i.etudiant_id
LEFT JOIN Gauche + Correspondances

Prend toutes les lignes de la table gauche. Si pas de correspondance à droite, remplit avec des NULL.

FROM etudiants e
LEFT JOIN clubs c
  ON e.club_id = c.id
RIGHT / FULL JOIN Portabilité
RIGHT JOIN swap_horiz Inverser tables LEFT

SQLite 3.39+ : supporte RIGHT & FULL. Pour versions antérieures : inverser les tables dans un LEFT JOIN ou faire l'union d'un LEFT JOIN.

-- Équivalent universel :
FROM B LEFT JOIN A
  ON B.x = A.x
CROSS JOIN N x M

Produit cartésien complet : chaque ligne de la table A est combinée avec chaque ligne de la table B sans condition ON.

SELECT *
FROM tailless
CROSS JOIN couleurs;
priority_high

Piège Redoutable : Filtrage ON vs WHERE sur un LEFT JOIN

Si vous placez un filtre sur la table de droite dans la clause WHERE b.statut = 'actif', toute ligne sans correspondance (où b.statut IS NULL) sera éliminée, ce qui transforme accidentellement votre LEFT JOIN en INNER JOIN !

✓ CORRECT (Condition préservant le LEFT) :
FROM a LEFT JOIN b ON a.id = b.a_id AND b.statut = 'actif'
✗ INCORRECT (Détruit les lignes orphelines) :
FROM a LEFT JOIN b ON a.id = b.a_id WHERE b.statut = 'actif'
04

Fonctions d'agrégation & Regroupement (GROUP BY & HAVING)

Compression de volumes de lignes en métriques synthétiques par compartiments.

Fonction Traitement des NULL Description synthétique Exemple d'invocation
COUNT(*) Compte tout Nombre total absolu de lignes retournées dans le groupe COUNT(*) AS nb_inscrits
COUNT(colonne) Ignore les NULL Nombre de valeurs non nulles pour cette colonne spécifique COUNT(email) AS nb_avec_mail
SUM(colonne) Ignore les NULL Somme arithmétique de toutes les valeurs numériques SUM(montant) AS ca_total
AVG(colonne) Ignore les NULL Moyenne pondérée uniquement sur les lignes non-nulles ROUND(AVG(note), 2) AS moyenne
MIN(col) / MAX(col) Ignore les NULL Valeur minimale / maximale (fonctionne aussi sur chaînes & dates) MIN(date_creation), MAX(prix)

layers Règle stricte du GROUP BY

Toute colonne présente dans le SELECT qui n'est pas enveloppée dans une fonction d'agrégation doit obligatoirement figurer dans la liste du GROUP BY.

SELECT promo, filiere, AVG(note)
FROM etudiants
GROUP BY promo, filiere;

filter_alt HAVING : Le WHERE des groupes

Le mot-clé WHERE ne peut jamais tester une fonction d'agrégat. Utilisez HAVING pour filtrer après regroupement.

SELECT filiere, COUNT(*) AS nb
FROM etudiants
WHERE actif = 1 -- pré-filtrage lignes
GROUP BY filiere
HAVING COUNT(*) >= 30; -- post-filtrage

Définition des données (DDL) & Contraintes d'intégrité

Création, typage, altération et préservation de la cohérence relationnelle.

Structure canonique CREATE TABLE SQLite 3
CREATE TABLE IF NOT EXISTS etudiants (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  matricule TEXT NOT NULL UNIQUE,
  nom TEXT NOT NULL,
  filiere_id INTEGER NOT NULL,
  moyenne REAL DEFAULT 0.0,
  date_inscription TEXT DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (filiere_id)
    REFERENCES filieres (id)
    ON DELETE CASCADE
);
Actions ALTER & DROP : ALTER TABLE etudiants ADD COLUMN email TEXT; ALTER TABLE t RENAME TO t_archive; DROP TABLE IF EXISTS t;

verified_user Les 5 Contraintes Clés

  • PRIMARY KEY : Identifiant unique, non nul et immuable.
  • NOT NULL : Interdit formellement la valeur indéfinie NULL.
  • UNIQUE : Empêche les duplications sur toute la colonne.
  • DEFAULT : Valeur de substitution automatique lors d'INSERT.
  • FOREIGN KEY : Garantit l'existence de l'entité référencée.

dataset Types de stockage SQLite 3

INTEGER : Entier signé
REAL : Nombre flottant
TEXT : Chaîne UTF-8
BLOB : Binaire brut

* Note : SQLite stocke les dates au format TEXT ISO 8601 ('YYYY-MM-DD HH:MM:SS').

Manipulation des données (DML) : INSERT, UPDATE, DELETE

Opérations d'écriture transactionnelles dans le magasin de données.

INSERT INTO Création

Ajoute une ou plusieurs nouvelles lignes. Spécifiez toujours explicitement les colonnes cibles.

INSERT INTO etudiants
  (nom, promo, note)
VALUES
  ('Alice', 'B1', 17.5),

Met à jour les colonnes désignées pour les lignes satisfaisant le critère.

    statut = 'admis'

Les 5 Pièges Éliminatoires à l'Examen B1

Erreurs fréquentes entraînant une perte immédiate de points.

1 Confusion WHERE vs HAVING

Interdit formel d'écrire WHERE COUNT(*) > 5. L'agrégat n'est pas encore calculé au moment du WHERE. Utilisez toujours HAVING COUNT(*) > 5.

2 Écrire = NULL au lieu de IS NULL

En logique ternaire SQL, val = NULL vaut toujours UNKNOWN (faux), jamais vrai. Utilisez toujours IS NULL ou IS NOT NULL.

3 Omission de ORDER BY avant LIMIT

Sans ORDER BY, les bases relationnelles retournent les lignes dans un ordre arbitraire non garanti. Un LIMIT 5 sans tri peut renvoyer un jeu de données différent à chaque exécution.

4 Guillemets simples vs doubles

Les guillemets simples 'valeur' délimitent les chaînes de caractères littérales. Les guillemets doubles "colonne" sont réservés aux identifiants d'objets ou mots réservés.

5 La division entière implicite dans SQLite

Si deux opérandes sont de type entier, SQLite tronque les décimales : 5 / 2 donnera 2 et non 2.5 ! Forcez le mode flottant : 5 * 1.0 / 2 ou CAST(5 AS REAL) / 2.
